# 把 playbook 写成一篇论文

类型：计划；所有者：接手本仓的 agent；意图与验收，不是结果。
写于 2026-10-19。

## 为什么要写

仓里已经有七条定律，每条都带数字、带适用边界，且大部分是**在别人会说"这应该有用"的地方测出无用或有害**（K 路径集成增益恰为 0、形态税 96% 归因于改主干本体、深度集成失败）。这些约束目前只存在于 `docs/playbook.md` 和一个私有仓里。

它们的价值不在"我们做了什么架构"，而在**给改架构的人一张代价表**：动主干本体要交多少、动旁路是否免费、什么时候组合会拮抗。这个表目前没有被写成可引用的形式，也不在任何人能检索到的地方。

## 一句话 claim

在 13M 与 100M 两个规模、固定 token 预算下，**架构改动的代价由"是否触碰主干本体"决定**：改形态的形态税为 `+0.44 bpc` 且 96% 归因于形态本身，而所有不碰主干的旁路设计（probe 早退、判断头）在测量精度内免费；同时，确定性路径上的 K 路集成增益恰为 0，只有训练进去的多样性才有效。

## 现有材料（不需新实验）

- 七条定律与边界：`docs/playbook.md:9-74`，逐条在 `FINDINGS.md` §一
- 形态税：`+0.4563` 跨引擎 / `+0.4362` 同引擎，96% 归因（`.scratch/24-depth-ar-100m/evidence/SUMMARY.md` §2.1、`.scratch/25-tax-attribution/evidence/SUMMARY.md` §0、`docs/methodology.md:76-77`）
- 负例三条（2.2.2 / 2.2.3 被否证、retry 矩阵排序整体撤回）：`FINDINGS.md` §四
- 七条定律的"什么时候不成立"已逐条写明，这是论文最该保留的部分

## 缺什么

1. **一页方法**：13M/100M 两个规模、bpc 口径、seed 散布（0.0103）、`Δ<0.014` 不可排序带的定义——现在散在 methodology 与各轴目录里。
2. **一张总表**：七条定律 × 规模 × 是否触碰主干 × 代价 × 边界，读者要能一眼看完。
3. **可复现声明**：哪些 run 的权重/日志还在、哪些只剩汇总（论文必须写清能复跑到什么程度，不能含糊）。
4. **外推边界的显式化**：char 级 enwik8、1.1-epoch 快照、两个规模。这三条限制要在正文出现，不在脚注。

## 结构（8–10 页）

1. 问题：小规模架构实验里，什么代价是可以预判的
2. 方法：两个规模、固定预算、同引擎对照、不可排序带
3. 主结果：形态税与 96% 归因
4. 旁路免费：四个独立设计 × 两个规模
5. K 路集成增益为 0，以及它与 beam search 的区别
6. 组合的选择性
7. 一张代价表（本文的可复用产物）
8. 限制：规模、语料、epoch 口径

## 验收

- 七条定律每条在正文有数字与边界，与 `FINDINGS.md` 不冲突
- 代价表可被第三方直接拿去用（列：改动类型 / 是否触主干 / 观测代价 / 适用边界）
- 撤回记录保留在正文或附录，不移除
- Zenodo DOI + 仓 tag
- 不声称跨规模外推成立；不把 `−0.007` 说成改善

## 不做

不追加新规模、不训练更大模型、不比较公开 checkpoint。要更多规模是另一件事。
