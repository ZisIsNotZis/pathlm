# 树分诊：46 个研究项按「能否改变判断」排序

> 本文件是**推进里程碑第一步的当前事实**：研究优先级与排序判据只有这一个家。
> 里程碑状态、工作包状态与测试计数在 `docs/plan.md`；每格的结论文本在它自己的 `axes/<轴>/<格子>/project.yaml`；
> 已有代价事实在 `docs/cost-table.md`（生成物）；定律正文与边界在 `docs/playbook.md`。本文件只排序，不改判词、不新增读数。

## 0 人话摘要（先说人话，再上表）

**下一步该做哪几格，按什么排。** 结论是第一批两件：把「大 `head_dim` 下 fp8 与 int8 谁更省」这一点补完（9 min 训练 + 4 min CPU 评测）；把已经写好契约、单测和一个臂都没跑过的「只激活部分通道」四臂跑出来（3 支新臂 24 min）。两件合计 **37 分钟**（训练 33 min + CPU 评测 4 min；`3.1.5` 自带评测的分钟数契约未单列），都不需要新写引擎代码，只需要一次干净的 GPU 时间窗口。

**为什么「按内容挑 vs 按最近的位置挑」没进第一批。** 那一格自己列了三项缺口（同 k 的位置窗口对照、长 T ≥2048 且 n≥2、真稀疏核），而它 `milestone.output` 要覆盖 T∈{256,512,1024,2048} 与长程召回、含 n≥2：按 §1.1 的 U 档，这是「要做 2–3 条实验才定论」⇒ **U=2**，分 3×2/2 = **3.0**，档位落在「补一条最小实验（次批）」而不是派活线。它不是不做：20 min 是 3.0 组里最便宜的一件，排在次批首位。

**为什么不是先做那些完全空白的格。** MoE 三格（`4.1`–`4.3`）确实是零覆盖，但它们的成本最高（要新写专家前向、路由与均衡，属改共享引擎那一档），而且 `4.1`–`4.3` 已有「本阶段不在 13M 上花算力做 MoE 判决」的裁决、`4.2` 的前提探针还显示 13M 上朴素 top-1 根本不自发坍缩（判据没有对象）。**在统一判据下，「已经备好仪器、只差 GPU 分钟」的格赢过「全空白、要新造仪器」的格**——这不是偏好，是成本项算出来的。

**为什么不是去做那些已经有很多实验的格。** `1.1.4.1`（30 个实验）与 `6.2`（19 个）剩下的缺口都是「归因再拆一条」或「补一个尺度点」，最便宜的那几条（0 训练 token 的再分析）排在第三、四名，值得做但不占第一批 GPU。

## 1 排序判据

### 1.1 三个量各是什么

排序要回答的原始问题只有一个：**这一格做出来，是否可能改变我们对「某种算力路径值不值」的判断**。它被拆成三个可逐项核对的量。

**D 判决增量（1–3；已定论为 0）** —— 这一格做出来后，它能给出「采纳 / 不采纳 / 本尺度无信号」三态中的哪一种，以及幅度。

| D | 判据 |
|---|---|
| 3 | 会新开一条**代价事实**：产出能直接落成一条 `cost_rows` 行，且落在现有代价表**没有的对照维度**上（新的字节水平 / 可见键数水平 / 同预算对照 / 整条没覆盖的轴） |
| 2 | 会**改判已有结论**：把「不可排序 / 边缘判定」压成「可排序」，或把某条已有代价事实的**归属**拆开（原来算在 A 头上，可能其实是 B） |
| 1 | 只把已有代价事实做稳：补 seed、补窗口、加一条对照臂，方向不变 |
| 0 | 已有判词（已完成 / 被否证），或按本仓标准不可能改变判断 |

**U 未测缺口紧迫度（1–3；无缺口为 0）** —— 该格自己的 `gaps`（必要时并读 `analysis.md` 的残余缺口节）里，有没有「补上就能定论」的那一条。

| U | 判据 |
|---|---|
| 3 | `gaps` 明写了一条「补上就能定论」的**单一**动作：做完它，该格即可从 进行中 → 已完成 / 被否证，或闭掉 milestone 的最后一项 |
| 2 | 要把 2–3 条实验做完才定论，或那条关键实验需要新代码 / 新开关 / 新实现 |
| 1 | 缺口是多条加和（补样本、加窗口、往外推），不存在单点定论 |
| 0 | 无未测缺口 |

**C 成本（1 / 2 / 4 / 8；除数，越大越贵）** —— 等效算力与时间，以及是否要新写代码。

单位换算（**本文件唯一的成本口径，标为换算、未实测**）：1 支 13M / 12k 步 / 98.3M token 臂 ≈ **10 min GPU**，锚点是 `axes/1-time/1.1.1-hard-window/experiments/2662-hard-window-anchor-13m/results.json` 落盘的四臂 `train_wall_minutes`（`::liveness`）与 `2631-spec-three-arms/smoke/steptime.md` 的实测步时。放大到 53.9M（≈4× 参数）按 **×2.5 GPU 时间**换算——步时读数 40.1 → 100.3 ms/step，即参数 ×4 换来时间 ×2.5，**不是** ×4；所以本表的「更大规模点」都用 ×2.5。

| C | 判据 |
|---|---|
| 1 | ≤20 min GPU，或 0 训练 token（纯推理 / 纯再分析），且 0 新代码 |
| 2 | 20–45 min GPU（2–4 支 13M 臂），且新代码 ≤ 1 个实验内开关 |
| 4 | 45–120 min GPU，或新代码 > 1 个开关 / 需实验内新写前向 |
| 8 | >120 min GPU（放大到 53.9M 的多臂判决就落在这里：3 臂 ××2.5 已约 75 min、再多一档就过线），或需改共享引擎 `pathlm/**` |

### 1.2 公式与阈值

**分 = D × U ÷ C**（满分 9.0）。打分按该行**「建议动作」列的那一条动作**算，不按整格算——所以同一格换一条动作就会换一个分，这是有意的：分诊要排的是「现在做哪一件」，不是「这格值多少」。

| 分 | 建议动作 |
|---|---|
| ≥ 4.5 | **派活**（本轮第一批，按分排序取前三） |
| 4.0 – 4.4 | **补一条最小实验**（排第一批之后；多为 0 GPU 的再分析） |
| 2.0 – 3.9 | **补一条最小实验**（次批，等 GPU 窗口）或 **观察**（有前置在跑） |
| 0.5 – 1.9 | **观察**：不派活，等更便宜的前置条件（多为要新实现或要放大规模） |
| < 0.5 | **观察**（维持 Backlog） |
| 0 | **无需再做**（已完成 / 被否证） |

**同分怎么破**：(a) 估算 GPU 分钟少的在前；(b) 仍同分时，`gaps` 条数少的在前（离「可交付」更近）。

### 1.3 三个格的打分演示（照做就能复现）

**`5.5` fp8 / 大 head_dim → 3×3/1 = 9.0。** D=3：它的 WP2 会产出一条今天没有的代价事实——`head_dim`=64 时「每值字节 → 每位置部署字节 → clean bpc」这个字节水平上 fp8 与 int8+块标尺谁占优；`docs/cost-table.md` 现有的 fp8 行只有 `head_dim`=32 一个字节水平。U=3：`gaps` 第一条自己写着「本项唯一未闭的 milestone 验收项」，就是 `head_dim`=64 的实测腿。C=1：训练 1 支 13M 臂 ≈ 9 min GPU + 三臂 CPU 评测 ≈ 4 min（那个 status 文件自报的估算），`--heads 4` 是现成 flag（`engine_change_required=false`），**0 新代码**。9 ÷ 1 = 9.0。

**`3.1.5` 通道极化 → 3×3/2 = 4.5。** D=3：「总参数不变、每 token 只算一部分 FFN 通道」若成立，会新开一条「激活通道数 → 质量」的代价事实，而代价表里没有任何条件计算的字节/算力行；它还顺带替整条 MoE 线（4.1–4.3 已降 Backlog）在 13M 上打一个便宜的代理前哨。U=3：`gaps` 就是「四臂最小判决一个都没跑」，契约、实现、等值门单测都已落盘 ⇒ 跑完即出本地判决。C=2：3 支臂 ≈ 24 min GPU（该契约自报的 GPU 预算是 ≤30 min），0 新代码。9 ÷ 2 = 4.5。

**`4.1` 稀疏激活专家 → 3×2/8 = 0.75。** D=3（它确实会新开整条专家轴的代价事实，是树里唯一零覆盖的大轴），但 U 只有 2（判据要「等 FLOPs / 等参数双对照」外加两个兄弟项的边界整合），C=8（要 MoE 专家前向 + 路由，属改共享引擎那一档，而且 13M 上 MoE 的「变化空间」要先自证）。6 ÷ 8 = 0.75 ⇒ 观察。**这一格演示的是判据真的会压掉「看起来最空白所以最该做」的直觉**。

## 3 工作包草案（第一批两件 + 次批首选一件）

三件都能在「不新增代码」或「新增 ≤ 1 个开关」的前提下执行；判据一律沿用该格已预登记的契约，本文件不重写判据线。**只有分 ≥ 4.5 的两件进第一批**（`5.5` 9.0、`3.1.5` 4.5）；`1.2.3` 按 U=2 落到 3.0，草案留在本节当次批首选，不改它已预登记的判据线。

### 3.1 派活 #1 · `5.5` 的 WP2：`head_dim`=64 的字节-质量实测腿

- **要闭掉什么**：`gaps` 第一条、也是它自己写着「本项唯一未闭的 milestone 验收项」的那条——大 `head_dim` 下标尺摊薄只有解析、没有实测。
- **预登记判据**（取自 `axes/5-quant/5.5-fp8-head-dim/project.yaml` 的 `objective_criteria`）：**该跌** = 每位置部署字节（`head_dim`=64、G=64 时标尺摊得更薄 ⇒ 省幅应比 32 时更大）；**该不跌 / 可排序** = clean bpc（fp8 E4M3 相对 int8 块标尺须越 0.014 配对带才算差异，不越即「不可分辨」）；**必须不变** = 严格前缀不变性两条、非量化臂逐位不变；**必须报** = fp8 是否免掉标尺、实测字节与解析是否一致。
- **对照臂**：`fp16`（基线）、`int8` + 块标尺 G=64、`fp8 E4M3` 三臂，同一 checkpoint、同一 CPU 评测口径、同一批窗口。
- **指标口径**：解析每位置部署字节（含标尺）+ clean bpc 的 5 窗口配对 Δ；**墙钟不进判据**。
- **验收**：实测每位置字节与解析对账一致（解析值写在该 status 文件里，不在本文件重算），差异有解释；三臂同字节轴可比；前缀不变性两条为 True。落盘 `results.json` + `analysis.md`，`project.yaml` 的 `status` 由 `summary.py --check` 接受。
- **预计算力与墙钟**：训练 1 支 13M / 12k 步 ≈ 9 min GPU（命令见 `axes/5-quant/5.5-fp8-head-dim/experiments/2653-fp8-vs-int8-13m/wp2_hd64_status.json`）+ 三臂 CPU 评测 ≈ 4 min；需一个 GPU 锁窗口，取放按 `SCHEMA.md` §20。
- **它会新产生哪一条代价事实**：一条新的 `cost_rows`——`head_dim`=64 水平上「每值 / 每位置字节 → clean bpc」的 fp8 对 int8 二选一（今天 `docs/cost-table.md` 只有 `head_dim`=32 那一档）。
- **不需要新代码**：`--heads 4` 让 `d//heads`=64，能力面已核 `engine_change_required=false`。

### 3.2 派活 #2 · `3.1.5` 的四臂最小判决

- **要闭掉什么**：`gaps` 第一条「四臂一个都没跑」——契约、实验内实现与等值门单测都已落盘，只差 GPU 时间；顺带替 Backlog 中的整条 MoE 线在 13M 上打一个便宜代理前哨。
- **预登记判据**（取自 `axes/3-width/3.1.5-channel-sparsity/experiments/2644-channel-sparsity-13m/README.md` §1）：**H1 备择** = 按内容条件选一半通道（`K50`）相对固定前缀常开一半（`F50`）可排序更优（|Δbpc| ≥ 0.014）⇒「保参数、条件选通道」是独立的前沿维度；**H0 零假设** = 两者不可排序（|Δbpc| < 0.014）⇒ 本尺度上条件性本身没有独立收益；**必须不变** = 总参数逐臂相同（完整 FFN 权重都在账上）、掩码全 1 时前向与 stock 逐位相同。
- **对照臂**：`D`（dense 锚，复用已训 `U4-s0`）、`K50`、`K25`、`F50`（无条件对照），同 seed、同构造路径。
- **指标口径**：matched-step 的 clean bpc 配对 Δ（0.014 带为主判）+ 每 token FFN 实际算的通道数。**判读必须落在「质量-代价前沿的位置」上**：契约里 `K50` 与 `F50` 的实现口径 MACs 并不相等（`K50` 更高，见那份 README 的臂表），只报 Δbpc 会把算力差读成机制差——验收里要同时给出两臂的实际算量列。
- **验收**：四臂读数齐备、活性列（每臂实际激活通道占比）有落盘；H0 / H1 二选一明确；等值门与变异门仍绿；`project.yaml` 从 `进行中` 走到 `已完成` 或 `被否证`。
- **预计算力与墙钟**：3 支新臂 ≈ 24 min GPU + 评测（该契约自报的 GPU 预算是 ≤30 min，见 `axes/3-width/3.1.5-channel-sparsity/experiments/2644-channel-sparsity-13m/README.md` 的 `budget` 字段）；`D` 锚复用已训 checkpoint。
- **它会新产生哪一条代价事实**：一条新 `cost_rows`——「同总参数下每 token 激活通道数 → clean bpc」的条件计算前沿点（今天代价表里没有任何条件计算的行）。
- **不需要新代码**：实现、单测与等值门已落在 `axes/3-width/3.1.5-channel-sparsity/experiments/2644-channel-sparsity-13m/`，不改引擎。

### 3.3 次批首选（3.0） · `1.2.3` 的 WP2：同 k 下「按内容选」对「按位置窗口」

- **要闭掉什么**：`gaps` 第二条「与『按位置取最近 k』的同预算正面对照未做」——这是全树引用最多的一处缺口（`1.1.3` 也把它写成「若要真正独立收口上限本身」的唯一做法）。
- **为什么是次批而不是派活**：这一条只闭 `gaps` 第二条（同 k 的位置窗口对照），而该格 `milestone.output` 还要覆盖 T∈{256,512,1024,2048} 与 n≥2、长程召回——那要另做 WP1（长 T 回本）与真稀疏核，属「2–3 条实验才定论」⇒ U=2、分 3×2/2 = 3.0，按 §1.2 的档位是「补一条最小实验（次批）」。本草案只改排序，不改判据。
- **预登记判据**（取自 `axes/1-time/1.2.3-content-topk/project.yaml`）：**该跌** = 每 token 等效注意力 FLOPs 与每位置缓存字节（须真降，不能只纸面降）；**该涨 / 该不变** = clean bpc 不得越噪声带；**必须不变** = 因果性、可见键数对齐、参数量相等。二选一明确：内容选择相对位置窗口**可排序占优** 或 **无增量**。
- **对照臂**：`full`（全因果）、`win32`、`win64`（新跑，按位置取最近 k）对复用 `topk32`、`topk64`（同可见键数）。对齐口径 = 每行保留键数逐行相等（含自身与否两臂用同一约定，起跑前写死）。
- **指标口径**：matched-step / 同 token 预算的 clean bpc 配对 Δ；率类指标走配对 bootstrap / Wilson 95% CI，不跨量纲借用 0.014 带；禁墙钟。
- **验收**：两臂可见键数逐行相等有落盘列；「内容 vs 位置」二选一明确且不超过「本 n 下可判 / 不可判」的措辞；`project.yaml` 的 `conclusion` 与 `status` 可被 `summary.py --check` 接受。
- **预计算力与墙钟**：2 支 13M / 12k 臂 ≈ 20 min GPU（复用 `axes/1-time/1.2.3-content-topk/experiments/2614-topk-sparse-attn-13m/` 的配方与配对评测脚本）。
- **它会新产生哪一条代价事实**：一条新 `cost_rows`——「同每行可见键数下，按位置选 vs 按内容选」的 bpc 差（今天代价表里只有内容 top-k 对全因果的单点，没有位置对照）。
- **新增代码 ≤ 1 个开关**：在 2614 的实验内臂表加一条窗口臂，掩码复用共享底座的 `window_anchor_keep_mask`（`pathlm/depth_ar.py`），**不碰** `pathlm/**`。
