# 方法学（天平）——所有研究线共享的测量纪律

这份文件是唯一的「天平」。**线可以各自独立，天平必须唯一**——否则
「这个设计是否比本体更好」这句话无法回答。

## 1. 三列账本（每个机制都要记三列）

| 列 | 内容 | 例 |
|---|---|---|
| **税** | 对基线 clean bpc 的 Δ | skip **+0.175** |
| **收益** | 该机制自己的货币下的收益 | 早退 1.45× tok/s |
| **裁决** | 采纳 / 证伪 / 未测 | 距离惩罚：未观察到超带损伤（**不称改善**） |

**受益域先于测量**：先写清「这个机制在什么条件下该有用」，再去量。
否则测到的是「它在没有收益条件的地方没用」。

## 2. 方差界（先看方差，再排序）

- nondeterminism **0.0019**；种子散布 **≤0.0138** ⇒ **Δ < 0.014 不可排序**。
- 曾据此**撤回整个 retry 矩阵的排序结论**（6 个 cell 跨度 0.011 < 0.0138）。
- **n=1 的负结果必须复现后入账**（13M「prob0 生成段反向」系单 prompt 假象，
  n=6 复刻未复现）。
- **n=1 的正结论默认不可采信**：只有「效应远超噪声带」且「有机制性证据（含毁源对照）」
  才站得住；跨种子复现是关键格的前置条件。
- **0.014 是 bpc 口径的方差带，不得直接当准确率的 1.4pp 界。**「准确率」与「bpc」是
  两个不同随机变量的方差；「0.014 bpc 带」从未在准确率口径上被测量过，因此文档中的
  「1.4pp 方差带」是一个**预登记的实用阈值**（为提前定下可排序线而写），**不是已测方差**。
  准确率的可排序性应用**二项 / Wilson 95% CI**。

## 3. 口径必须标注（否则数字不可比）

| 口径 | 含义 | 例 |
|---|---|---|
| 1.1-epoch 快照 | 训练早期；**所有早期公布的税都是它的上界** | +0.364@1k → +0.122@24k |
| 4.4-epoch 渐近 | 收敛附近 | 回环族税 +0.126 → +0.082 |
| matched-step | 同训练步数对照 | 形态真税 @12k = +0.3295 |
| 墙钟 | 部署真实收益 | spec k=2 1.15–1.29× @100M |
| FLOPs（等价 width-1） | 计算量口径 | spec 每 token `R=(1+γ)/(1+τ)` ≈ 1.07–1.27 |

**双货币必须双报**：同一机制在两口径下结论会分歧（spec：forwards 口径占优
〔2.4 tok/fwd〕、FLOPs 口径**净亏**〔R>1〕、墙钟口径随规模从 13M 1.68–1.90× 塌到 @100M 约 1.0–1.35×）。
只报一种货币 = 不可比。

**算力（FLOPs）口径的兑换率必须用解析量，不得用墙钟前向比**：一次前向送出
`1+γ` 个位置、产出 `1+τ` 个 token ⇒ 每 token 算力 `R=(1+γ)/(1+τ)`（以 native
逐 token 的 1 次 width-1 前向为单位）。`c_wall`（实测 width-(1+γ)/width-1 **墙钟**比，
与宽度 `1+γ` 配对）只描述墙钟，含核回退/启动开销/外部占用，代入算力会得到随环境漂移的假结论。

**记账货币清单（原研究格 `G2-currency` 的纪律，非可证伪命题）**：

- 货币 = `forwards`（每 token 前向次数）/ `FLOPs`（等价 width-1 单位）/ `墙钟` / `内存` / `延迟分位`；
  同一机制在不同货币下可能给出**相反**结论，因此**多货币并报并解释分歧**是硬纪律。
- 本地实例：spec 的 forwards 口径 = 2.37–2.40 tok/fwd；FLOPs 口径 `R=(1+γ)/(1+τ)` =
  1.07–1.27（**两规模都 >1，净亏**）；墙钟口径 13M k=2 1.68–1.90×、@100M 约 1.0–1.35×
  （外部占用下不可稳定复现）；深度自适应 C 配方按 FLOPs 口径 122.8 vs 112.9 tok/s。
  证据：`.scratch/15-slider-rung3/evidence`、`.scratch/20-spec-scale/evidence`、`.scratch/25-tax-attribution/evidence`、
  `axes/6-predict/6.2-speculative-decoding/experiments/2520-spec-at-scale/analysis.md @c3cf43c`。
- 反例（不得犯）：「逐位相等」只在 13M 成立，@100M fp 平局会翻转（enwik8 k=2 首错位 169、
  级联 68 token、gap 0.0079，两轮运行复现）⇒ 规模性质不得当跨规模结论。

## 4. 对照必须同引擎、同配方、同 token 预算

跨引擎对照会让归属不可分。正确做法：**三列拆混杂**（形态 / 引擎 / 配方）。
范例：某实验用两臂（等权臂 + 同引擎 dense）把 +0.4563 拆成
**形态 +0.44（96%）+ 引擎 +0.02（4%）+ 配方 ≈0**。

## 5. 冒烟 + 变异测试（每个新开关）

1. 先 **20 步冒烟 + 全电池**，再全跑；
2. 每个语义开关都有一个**可失败单测**；
3. 关键开关做**变异验证**：故意破坏实现，必须抓红（例：切片忽略、调度退化、
   掩码维错位、丢筛选、回落 fill）。

反例（真实教训）：needle v1 构造使每 batch 只有 1 个监督 token → 信号饥饿，
全桶测到 0.0，是**假失败**；修测量后才可判机制。

## 6. 三种可复用的审计模板

1. **撤回型**：格间跨度 < 种子散布 ⇒ 排序无效。例：retry 矩阵。
2. **拆混杂型**：效应拆成形态/引擎/配方三列归属。例：深度自适应 100M。
3. **干预-恢复型**：四格判读表（干预是否收回代价），并给反证方向。例：税归因。

## 7. 稳定性与数值纪律

- bf16 autocast 下的 **negative / reward 类损失必须 float32 + pre-step
  grad-norm gate**；读出用 fp32 头。
- 梯度范数监控（max/mean/skip 计数）是常规项。
- 相对/绝对：生成段监测的参考水平必须**相对化**（greedy 全局偏低）。

## 8. 证据可回溯纪律

- 每个结论必须能回溯到 **run 目录 + resolved config + commit**。
- 权重是派生物，**不入库**（`*.pt` gitignored）；证据 json/log/md 入库。
- 失败结论与成功结论**同等入账**：写清「试了什么 → 为什么失败 → 排除了什么」。

## 9. 单因素铁律（含唯一的例外）

> 我们绝不做多因素实验，永远只考虑单因素。但如果**单因素本身不可能发挥效用**、
> 必须加入别的因素才能生效，则加入「目前最主流、最 SOTA 的、有帮助的**非标准**因素」。
> 其他情况下，永远在**主流标准 Decoder-Only Transformer** 上改。

- **默认基底 = 主流标准 decoder-only transformer**（RAP 保留的三条必要 shared-substrate
  偏离见 `docs/design.md` §2——它们是「传统设计根本不够用」的部分）。
- **必要性例外必须写明**：为什么单因素无法独立生效、引入了哪个非标准因素、
  它对结论的影响是什么（否则违反拆混杂纪律）。
- **禁止**为了好看而叠加第二个机制；**deps 字段只记录依赖，不构成组合实验授权**。

## 10. 规模纪律

单卡 4090 共享卡的规模与预算要求见 `SCHEMA.md` §7（规模）与 §8（成本预算的唯一数字）；
锁协议见 `SCHEMA.md` §20。

## 11. 指标必须是多维的、可量化的

一个设计 = 一个哲学；它的**用途可以有很多种**，因此指标必须分开记、分开报：

| 维度 | 问题 | 典型量 |
|---|---|---|
| **它解决什么问题** | 对应哪个痛点（长上下文 / 吞吐 / 内存 / 可控性 / 保留） | 命题陈述 |
| **代价** | 同尺寸同 token 预算下的税 | Δ clean bpc / ppl |
| **有效性** | 相对同尺寸或同标的基线，有效 / 无效 / 反向 | Δ vs 对照（带方差界） |
| **收益与用法** | 每种用法各自的收益（可能有多种） | 墙钟 tok/s · FLOPs 等效 · 内存 · 保留召回 · 校准 ECE |
| **可控性** | 旋钮是否可预测、可调度 | 成本预测误差 · 开火率 split gap |
| **副产品** | 意外得到的能力（例：出口资产） | 独立指标 |

- **每个指标单独分析**，不合并成单一分数（单货币记账会给出相反结论）。
- 指标必须与**同尺寸或同标的**的对照比（不是与更大的模型比）。

## 12. 数据、脚本与可复现资产（必收集）

每个实验目录必须留下：数据集（名称/来源/规模/切分/下载或生成命令，**用小数据集**）、
入口脚本 + resolved config（含 seed、超参、路径）、原始产出（`results.json` / 日志 / 探针 json
入库；权重不入库、写 `MODEL.md` 哈希）、判读（`analysis.md` 逐指标表格，含失败）。
目录与契约字段的规范见 `SCHEMA.md` §3 / §6。

## 13. Scope 可控与「立竿见影」

启动实验前必须回答四个问题，写进契约：

1. 这个实验**最小可判定版本**是什么？（能砍到多少成本）
2. 结果**多快**能出来？（≤ 一小时为佳；超过则拆成先导实验）
3. 判据线是多少？（预先写下，不许事后调整）
4. 如果无效，**下一步怎么走**？

## 14. 失败处理决策树（结果不好时先分清是谁的错）

| 症状 | 诊断 | 处置 |
|---|---|---|
| 税 ≈ 0、收益 ≈ 0 | 机制在此规模**无头寸**（headroom） | 换判据或换尺度；不要加第二个机制 |
| 收益为负、且实现可疑 | **实现 bug** | 先做变异验证 + 单测；bug 未排除前不判机制 |
| 收益为负、实现正确 | **设计在该设定下无效** | 记录为否证，写清「在什么条件下它才会有效」 |
| 指标互相矛盾 | **口径/判据问题** | 双报口径；检查是不是假失败（构造/评测泄漏） |
| 结果不可重复 | **方差** | 按 §2 方差界；n=1 负结果必须复现 |

**原则**：先排除「测量问题」与「实现问题」，再排除「规模问题」，最后才归因「设计问题」。

## 15. 组织方式

主 Agent 只编排、sub-agent 执行；**一个 cwd 同一时刻只允许一个写入者**；GPU 任务**串行**提交。
sub-agent 的产出必须落成实验目录内的规定文件，**口头汇报不算交付**。
编排职责与派发纪律见 `AGENTS.md` §3 与 `SCHEMA.md` §22 / §14b。

## 16. 判据取向

**与自循环比，不与 oracle 比**——oracle 只是上界，对手必须同成本或更低成本。详见 `SCHEMA.md` §11。

## 17. 防自欺三件套（每份报告必过）

1. **对账**（`SCHEMA.md` §12）：算术上下界、任务同一性、口径一致性；
2. **可比**（`SCHEMA.md` §13）：对照臂三要素（输入分布 / 预测什么 / 部署对应）；
3. **复核**（`SCHEMA.md` §14）：fresh-context 只读复核者独立检查，fail 不计入状态灯。

主 Agent 的义务：**宁可报「数字可疑、待重测」，也不报一个漂亮的假数字。**

## 18. 长时自主运行的纪律

用户长期不在时，主 Agent 全权推进，但必须：

- 每个实验**预登记判据 + 事后复核**，判据线一律不得事后调整；
- 每个结论写进对应研究项的 `project.yaml`（`axes/**/project.yaml`，见 `docs/research-schema.md`）时**带口径与证据锚点**；
- 每批结束写 ticket 的 `evidence/SUMMARY.md`（第一段人话摘要）；
- 遇到「契约有缺陷 / 数字可疑 / 干预是死的」→ **停下记录并改用保守解释**，
  绝不为了推进而放宽判据；
- 每批结束向用户留一份可离线阅读的汇报（提交信息 + ticket SUMMARY 即为其载体）。
