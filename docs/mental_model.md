# PathLM 实用化思路模型（mental model）

> 2026-09-16。本文回答：理想的 PathLM 是什么、怎么用、怎么在 4090 上一步步验证。
> 重点不是模型的常规推理能力，而是**灵活性 + 概率可审计性带来的算力精细分配能力**。

## 1. 目标定义

- **输入**：算力预算 b（每 token 的前向次数 × 深度），或目标 (速度 s\*, 质量 q\*)
- **输出**：在 b 下达到可达的最优质量；或达到 (s\*, q\*) 的最小算力
- **硬件**：RTX 4090（24GB）。训练包络：13M≈5min/6000 步、29M≈10min、100M≈1–2h/6000 步。推理单流 ~100–200 tok/s
- **对照物**：常规单路径 LLM 是**一个点**（每 token 固定算力）；beam search 是一条昂贵的线；外部草稿模型是"命中或 miss"的概率。PathLM 的声明是**一条连续、可审计、可控的质量-算力前沿曲线**——它穿过常规点，并向两侧延伸（更便宜-略差 / 更贵-更好）

## 2. 核心抽象：从"固定函数"到"分配策略"

常规 LLM 推理 = 固定函数：每个 token 全层一次前向，自由度只有采样参数。
PathLM 推理 = **分配策略 π(状态) → (深度 d, 精炼轮数 r, 草稿宽度 k)**，输入是模型
自己的已校准概率，输出是该 token 的算力分配。

三个杠杆（全部已实测）：

| 杠杆 | 方向 | 实测效果 | 门槛信号 |
|---|---|---|---|
| 深度（早退） | 省 | 1.45× tok/s；质量损失需 dense-exit 训练控制（税 +0.067） | 深度 d 的置信 |
| 精炼（retry） | 花 | 门控 15%：C1M **+0.128 bpc @1.15×**（均匀 −0.019 = 净有害） | prob0 |
| 宽度（spec） | 摊销 | **1.68–1.90×** tok/s（k=2，批量验证） | node-k 概率 |

**审计性**：prob0 校准（ECE 0.002–0.011）⇒ 每个阈值的开火率可预测、每个决策可
回溯、在线质量可用平均置信代理。这就是"概率可审计性带来的算力精细分配"。

## 3. Slider 的定义与实现

两级参数：

- **规模参数**（部署时定）：模型大小、最大深度、n_mtp——决定前沿曲线的**形状**
- **Slider**（运行时调）：θ = (τ_retry, k)——在前沿曲线上**移动**

Slider 实现（**Rung 3 已建成并验证，ticket 15**，`pathlm/slider.py` + 根探针
`slider.py`；证据 `.scratch/15-slider-rung3/evidence/`）：
1. ✅ **校准**：gate_probe 在校准集测 P(prob0<τ) 曲线（clean/corrupt 双 profile）
   → 每个 τ 的开火率可预测；split gap ≤ 0.004
2. ✅ **成本模型**：双货币（forwards = 每 token 前向次数，§1 口径；flop = 等价
   width-1 单位）。**a2 部署口径校准后全线预测误差 ≤ ±13%**（k=0 −2.7~−7.6%，
   k=1 −4.6~−12.8%；TF 估 a2 低估部署接受率 → 保守）。**两口径结论会分歧，
   必须双报**（spec 在 forwards 口径 0.55–0.70、flop 口径 ≥1.23）
3. ✅ **求解器**：给定 b 在前沿插值上选 (k,τ)（预算/质量两模式，货币可选）；
   验证解码实测成本与预测对账
4. ✅/**⚠** **在线质量代理**：prob0 ≈ P(当前 token 正确)，TF 窗口 ECE 0.0011–0.0079
   ——**有真值对齐的读出上成立**；**自由生成段失败**（负结果，见 §7）

**草稿的三种模式**：

- (a) **免费验证**：k=1 时下一 forward 反正要算 t+2 → 验证免费，总是验证
- (b) **批量验证**：k≥2 一次 forward 验证全部（实测 1.68–1.90×；批量 forward
  成本仅 1.28× 单位置）
- (c) **免验证提交**：草稿概率 > 高阈值时直接提交、不验证——质量风险换速度的
  旋钮。**这是常规 LLM 完全没有的自由度**

## 4. 组合地图

| 组合 | 状态 | 结果 |
|---|---|---|
| retry × 损坏 | ✅ 次可加 | 共享修复机制（IX1 +0.087 < 0.277） |
| exit × 驱逐 | ✅ +0.004 | X3 |
| retry(门控) × 损坏 | ✅ **翻正** | 均匀 −0.019 → 门控 +0.021（INT2）/ +0.128（C1M） |
| **dense-exit × retry** | ❌ 拮抗 | ALLOC 各桶全负 → 深度头需改 probe 式 |
| 逐位置门控（状态掩码） | ❌ 需稀疏计算 | gather/scatter 未建；选择性价值已证（+0.04~+0.07） |
| retry(门控) × spec | ✅ **复合成立且严格占优** | INT2 损坏输入：plain 42.7 tok/s @2.040 bpc → spec+门控 50.8 tok/s @2.031（**又快又好**）；门控收益在 spec 下保持 |
| spec × 损坏 | ✅ | INT2 上 k=1 spec 1.31×（驱逐向量化后） |
| **exit × spec** | ❌ 本引擎不可组合 | 批量验证必须全深度（逐位置深度会使缓存失步）；exit 单独实测 2.4×（103-105 tok/s）但质量需 dense-exit 训练校准，而它与 retry 冲突 → 见 §4 的 probe 式深度头解法 |

**已知设计冲突——已定案（ticket 18）**：整形与 retry 是同一梯度的两面，**两全被
证伪**。probe 式头（trunk stop-grad）确实解掉引擎拮抗（retry 活，−0.0098 优于
参照）；但 exit 质量轴需要 trunk 塑形——dense 0.2 温和整形仍杀 retry（+0.0146）
而 exit 轴好（depth 6 +0.199 vs probe 的 +0.93），dense 0.2 还顺带改善 clean/
corrupt（aux 正则）。**双边前沿以两个 profile 成立**：质量 profile（EX2：1.0 flop
1.54 → 0.5 flop 1.74）+ 自适应 profile（probe/无 dense：retry+spec+门控活）。
conf 逐深度校准在训练分布上极好；阈值跨 profile 需重校准（Slider 校准框架职责）。

## 5. 验证阶梯（4090 包络内）

- **Rung 1 ✅** 单机制（12 个验证，6 存活：MTP/prob0、早退、retry、损坏、驱逐、距离惩罚）
- **Rung 2 ✅** 成对组合全部测毕（retry×损坏 ✓ 次可加、exit×驱逐 ✓、retry门控×spec ✓ 严格占优、dense-exit×retry ✗、spec×损坏 ✓ 1.31×、exit×spec ❌ 引擎不支持）
- **Rung 3 ✅** 完整分配器（Slider 端到端，ticket 15）：校准→双货币成本模型→
  求解器→验证解码→在线代理；严格占优点在新权重复现（corrupt：k=1 τ=0.98
  比 plain **少 37% forwards 且 bpc 更好**）；单轮重试 mixture==overwrite
  （设计保证，引擎无损失）
- **Rung 4 ✅（实质完成；exit 双 profile 定案见 §4）** 规模（ticket 16/17）：100M 2 seeds 定案——税首次不增
  （+0.126）、能力溢价持续（≥1.54 bpc）、prob0 校准存活；Slider 分配器在 100M
  闭环自洽（spec 占优复现；门控重试质量杠杆随规模自衰减 ≤0.001）。
  更远：node-3+ 接受率随规模、exit 校准（probe 式深度头）、4.4-epoch 渐近口径。

## 6. 质量的角色（诚实地）

TTS 探针已证 "nothing beats B0"——**这套东西不卖质量，卖可控性**。前沿曲线的
质量轴只需要不劣于常规点（等算力下）；曲线的价值在"可以任选成本点 + 全程可审计 +
可在线调整"。质量是**约束**，不是卖点。
