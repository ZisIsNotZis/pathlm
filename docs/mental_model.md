# PathLM 实用化思路模型（mental model）

> 2026-09-16。本文回答：理想的 PathLM 是什么、怎么用、怎么在 4090 上一步步验证。
> 重点不是模型的常规推理能力，而是**灵活性 + 概率可审计性带来的算力精细分配能力**。

## 1. 目标定义

- **输入**：算力预算 b（每 token 的前向次数 × 深度），或目标 (速度 s\*, 质量 q\*)
- **输出**：在 b 下达到可达的最优质量；或达到 (s\*, q\*) 的最小算力
- **硬件**：RTX 4090（24GB）。训练包络：13M≈5min/6000 步、29M≈10min、100M≈1–2h/6000 步。推理单流 ~100–200 tok/s
- **对照物**：常规单路径 LLM 是**一个点**（每 token 固定算力）；beam search 是一条昂贵的线；外部草稿模型是"命中或 miss"的概率。PathLM 的声明是**一条连续、可审计、可控的质量-算力前沿曲线**——它穿过常规点，并向两侧延伸（更便宜-略差 / 更贵-更好）

## 2. 核心抽象：从"固定函数"到"分配策略"

常规 LLM 推理 = 固定函数：每个 token 全层一次前向，自由度只有采样参数。
PathLM 推理 = **分配策略 π(状态) → (深度 d, 精炼轮数 r, 草稿宽度 k)**，输入是模型
自己的已校准概率，输出是该 token 的算力分配。

三个杠杆（全部已实测）：

| 杠杆 | 方向 | 实测效果 | 门槛信号 |
|---|---|---|---|
| 深度（早退） | 省 | 1.45× tok/s；质量损失需 dense-exit 训练控制（税 +0.067） | 深度 d 的置信 |
| 精炼（retry） | 花 | 门控 15%：C1M **+0.128 bpc @1.15×**（均匀 −0.019 = 净有害） | prob0 |
| 宽度（spec） | 摊销 | **1.68–1.90×** tok/s（k=2，批量验证） | node-k 概率 |

**审计性**：prob0 校准（ECE 0.002–0.011）⇒ 每个阈值的开火率可预测、每个决策可
回溯、在线质量可用平均置信代理。这就是"概率可审计性带来的算力精细分配"。

## 3. Slider 的定义与实现

两级参数：

- **规模参数**（部署时定）：模型大小、最大深度、n_mtp——决定前沿曲线的**形状**
- **Slider**（运行时调）：θ = (τ_exit, τ_retry, k)——在前沿曲线上**移动**

Slider 实现：
1. 校准集测 P(prob0 < τ) 曲线 → 每个 τ 的开火率（成本可预测）
2. 前沿曲线上质量(τ) 插值 → 质量可预测
3. 给定 b：二分 θ 使 E[cost](θ) = b；给定 (s\*, q\*)：找可行 θ
4. 在线质量代理 = 生成窗口的平均 prob0（ECE 校准 ⇒ 平均置信 ≈ 准确率）

**草稿的三种模式**：

- (a) **免费验证**：k=1 时下一 forward 反正要算 t+2 → 验证免费，总是验证
- (b) **批量验证**：k≥2 一次 forward 验证全部（实测 1.68–1.90×；批量 forward
  成本仅 1.28× 单位置）
- (c) **免验证提交**：草稿概率 > 高阈值时直接提交、不验证——质量风险换速度的
  旋钮。**这是常规 LLM 完全没有的自由度**

## 4. 组合地图

| 组合 | 状态 | 结果 |
|---|---|---|
| retry × 损坏 | ✅ 次可加 | 共享修复机制（IX1 +0.087 < 0.277） |
| exit × 驱逐 | ✅ +0.004 | X3 |
| retry(门控) × 损坏 | ✅ **翻正** | 均匀 −0.019 → 门控 +0.021（INT2）/ +0.128（C1M） |
| **dense-exit × retry** | ❌ 拮抗 | ALLOC 各桶全负 → 深度头需改 probe 式 |
| 逐位置门控（状态掩码） | ❌ 需稀疏计算 | gather/scatter 未建；选择性价值已证（+0.04~+0.07） |
| **exit × spec / retry × spec** | ⬜ 本轮测 | 预期近乘法（省深度 × 摊销宽度正交） |
| spec × 损坏 | ⬜ | 草稿在损坏输入上的接受率 |

**已知设计冲突与解法**：dense-exit 的深度监督梯度会重塑 trunk、破坏 retry 精炼
（ALLOC 各置信桶全负）。解法：深度置信头改为 **probe 式**（对 trunk stop-grad，
只训头本身）——深度头是"读出探针"而非"训练信号"。未测，是 exit×retry 共存的
前提。

## 5. 验证阶梯（4090 包络内）

- **Rung 1 ✅** 单机制（12 个验证，6 存活：MTP/prob0、早退、retry、损坏、驱逐、距离惩罚）
- **Rung 2 ⬜** 成对组合（retry×损坏 ✓、exit×驱逐 ✓、dense-exit×retry ✗、
  exit×spec ⬜、retry×spec ⬜、spec×损坏 ⬜）
- **Rung 3 ⬜** 完整分配器（Slider 端到端，13M，4090 可行）
- **Rung 4 ⬜** 规模（100M+；训练 1–2h/6000 步，可行但慢）

## 6. 质量的角色（诚实地）

TTS 探针已证 "nothing beats B0"——**这套东西不卖质量，卖可控性**。前沿曲线的
质量轴只需要不劣于常规点（等算力下）；曲线的价值在"可以任选成本点 + 全程可审计 +
可在线调整"。质量是**约束**，不是卖点。
