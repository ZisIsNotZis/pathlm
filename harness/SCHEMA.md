## 6. 实验契约的必需字段（`experiments/<name>/README.md`）

除 `docs/methodology.md` 的一般纪律外，每个实验契约必须包含以下小节（缺一不可）：

1. **命题**：一句话、可证伪。
2. **单因素声明**：干预只改一个因素；基底是主流标准 decoder-only transformer
   （或 RAP 的三条共享底座，见 `docs/design.md` §2）。**若单因素无法独立生效**：写明为什么、
   引入了哪个「主流 SOTA 的非标准因素」、它对结论的影响（必要性例外，须显式记账）。
3. **指标表**（多维，逐项分析）：它解决什么问题 / 代价 / 有效性（vs 同尺寸或同标的对照）/
   收益与用法（每种用法一行）/ 可控性 / 副产品。
4. **判据线**：预先写下，不许事后调整。
5. **对照与方差**：对照臂、seed 数、方差界（界值与口径见 `docs/methodology.md` §2）。
6. **成本**：显存预算（4090 共享卡）/ 预计墙钟（按 2–3× 折扣估）/ 可中断性 / 冒烟计划。
7. **数据与脚本清单**：数据集（名称/来源/规模/切分/生成命令）、入口脚本、resolved config、落盘文件。
8. **失败决策树**：无效时的处置路径（测量 / 实现 / 规模 / 设计，按此顺序排除）。
9. **产出**：`results.json` / 日志 / `analysis.md` / `MODEL.md`（权重哈希，不入库）。

## 7. 规模纪律（写进每个契约的 §6）

- 硬件 = 单卡 RTX 4090（24GB）且**被多个任务共享**：GPU 任务串行提交，批大小保守。
- 只做小规模实验验证**原理与 scaling 趋势**；外推靠**公式**，必要时多档次小实验拟合，
  **不做大实验**。

## 8. 成本预算的唯一性

**契约里只能有一个 GPU 墙钟预算数字**，且必须与任务下发时的预算一致。

- 错误范式：契约 §6 写「全跑 25 min」而任务写「GPU 预算 ≤20 min」——子代理无法同时满足，
  只能停下裁决，浪费一轮往返。
- 正确范式：契约 §6 用一行写死 `gpu_wall_budget: <N> min`（含冒烟+全跑+评测的总和），
  并在 §13（scope）里写清「预算不够时砍什么」（砍步数 / 砍对照 / 砍指标，**不砍判据线**）。
- **冲突处理规则**：若执行中发现预算与判据不可兼得，**停下向主 Agent 裁决**；
  **禁止自行修改判据线或事后调整判据**。裁决必须给出「预算内最小可判定版本」的取舍。
- 预算数字一律按**共享卡 2× 折扣**估（4090 24GB，通常已被占用 8–12GB）。

## 9. 对照复用规则

复用历史 run 作对照**只能节省算力，不能节省证据**。复用必须同时满足：

1. **实现层 equality**：有可失败单测证明新实现关闭开关时与历史实现逐位一致；
2. **配置层 equality**：把历史 run 的 resolved config 与本次对照配置**逐字段列表对照**
   （d/layers/heads/seq/batch/steps/**seed**/数据切分/fill/退火/优化器），不等字段必须显式列出；
3. **口径标注**：在 `analysis.md` 标注「历史同配置对照 + 等值性证明 + 已知口径」；
4. 任一字段不等 → **回退到自包含双跑**（宁可多花 10 分钟，不可引入跨 run 混杂）。

## 10. 干预活性判据

**任何参数化干预都必须报告它是否真的被激活**，否则可能交付一个「死的干预」
却把它当成机制结论。

- `results.json` 必须落 `intervention:` 块，至少含：
  `{params_added, w_fro, w_absmax, nonzero_frac}`（或等价的活性量：门开度、路由选择率、
  稀疏激活率、实际使用的通道数）。
- `analysis.md` 必须用一句话说明「干预是否活着」，并把它列为**多维指标表的一行**。
- **恒等初始化 ≠ 零初始化**：为了「起步严格等价于基线」，容易写成零初始化，
  但若损失对参数的梯度在零点也同时为零（鞍点），学习会永久停住。
  正确做法 = **单边零**（只把输出侧置零，输入侧随机初始化），
  既严格恒等起步又保留非零梯度。实测（W4）：`W1~N(0,0.02), W2=0`
  起步恒等且 200 步内 |W1|=5.34 / |W2|=1.33（已逃逸）；`W1=W2=0` 200 步仍全零。
- 每个语义开关同样要有「活性」测试：断言开关打开时参数/通路的统计量发生变化，
  否则测试无法区分「开关无效」与「机制无效」。

## 11. 判据取向：与「自循环」比，不与 oracle 比

> 用户原话要点：不应该和 oracle 比，应该和两次前向比，因为 oracle 是作弊的。
> 假如两次前向能拿 50 分，跳跃能拿接近 50 分，就比較成功。更严谨的指标是草稿接受率
> ——接受率里也没有作弊，本质上也是在和自回归比。

- **oracle 类基线（喂入真值中间结果）一律只是「上界参考」，不得作为判据。**
- 判据必须是**同成本或更低成本的诚实对手**：
  - 多步预测 → **自回归跑两次**（用自己生成的中间 token，且只替换紧邻位置）；
  - 草稿/推测解码 → **草稿接受率 = P(草稿 argmax == 主干自身输出 argmax)**（对照物是主干，不是真值）。
- 与真值比较的命中率可以报，但要标注它是「质量口径」，**不是**草稿用途的判据。
- 这两个量（vs 真值 / vs 主干）**必须分开报**，不得混用。

## 12. 有利数字的对账义务

任何**支持假设**的数字，写进结论前必须过三道对账：

1. **算术对账**：算清该指标的理论上下界，把边界与实测对一下。
   （实例：已知两个边际命中率 P(t+1)=a、P(t+2)=b 时，其交集 P(A∩B) 只有
   Fréchet–Hoeffding 界 `max(0, a+b−1) ≤ P(A∩B) ≤ min(a,b)`；取 a=0.6934、b=0.6953
   ⇒ 下界 `max(0, 0.3887)=` **0.3887**、上界 `min(a,b)=` **0.6934**。
   **两个边际相乘只在两者独立时才是下界**，不能当界；仅凭边际也推不出条件命中率，
   更不能用「实测值越过某数」证明实现正确。）
2. **任务对账**：这个对照臂测的是不是同一件事？输入分布是否可比？
   （实例：把整段上下文替换为自预测再用真值打分 = 「假上下文猜真值」，不是 AR。）
3. **口径对账**：快照/渐近/matched-step/墙钟/FLOPs 是否与主臂一致。

对账不过 ⇒ **撤回该结论**：把 `analysis.md`（及退役前的 `catalog.yaml`，见顶部迁移通告 /
`docs/structure.md` §15）改成**当前正确状态**
（不要留 ERRATA 叠加）。不利于假设的数字同样必须报（但只要求如实体量，不强制对账）。

## 13. 对照臂可比性

- 对照臂必须与主臂在**同一任务定义、同一输入分布、同一位置集**下打分。
- **禁止「假上下文 + 真目标」式对照**（它量的是不可能任务，会给主臂制造虚假优势）。
- 每个对照臂必须写明三件事：输入是什么分布、要预测什么、在部署中对应什么。

## 14. 独立复核（每个实验完成后强制）

- 每个研究实验完成后，**另派一个 fresh-context 的只读复核者**（agent: reviewer）
  独立检查，不复用执行者上下文。
- 复核清单（缺一即不合格）：
  1. **判据线是否被改过**（对照契约原文；改过即不合格）；
  2. **对账**：§12 三道对账是否做了、是否通过；
  3. **对照臂可比性**：§13 三要素是否写明、是否同一任务定义；
  4. **干预活性**：§10 活性量是否非零、是否与训练日志一致；
  5. **证据可回溯**：`results.json` 的文件是否与 `analysis.md` 的数字逐一对应；
  6. **口径标注**：是否注明快照/渐近等口径；
  7. **回归**：`pytest` 是否全绿、既有实验是否被破坏。
- 复核结论（pass / fail + 具体条目）由主 Agent 汇总；**fail 的结论不得计入状态灯**。

## 14b. 复核必须排在执行之后（依赖屏障，不得同波启动）

**规则**：

- 复核者（§14）必须在被复核对象**全部完成并落盘之后**再启动（不同波，或同波但显式依赖屏障）；
- 正确做法：执行波 → 等完成 → **另派 fresh-context 复核者**（新 run，不复用执行者上下文）；
- 若确实要同波启动（为了省时间），必须在任务里写明「先等待 X/Y/Z 的产物出现（轮询到文件存在）
  再开始复核」，并给出产物路径清单；否则视为编排缺陷；
- 同波启动导致的 no-op 复核**不计入**「已复核」，也不计入状态灯门禁。

## 15. 增益归因必须过「等参数对照」

任何声称**来自结构改动**的增益（非线性、跨层连接、门控、路由、新算子），
必须同时给出一个**参数量完全相同、但去掉该结构**的对照臂：

- 若两者差异 < 方差界（0.014）⇒ 归因于**容量/重参数化**，**不得**归因于该结构。
- 实例：gated 读出 Δ=−0.0812 vs 等参数纯线性对照 Δ=−0.0888，差 0.0076 < 0.014 ⇒
  「非线性」无额外贡献，增益来自读出重参数化 + 2·d² 参数。
- 例外：结构改动**减少**参数（剪枝类）时，改与「同 FLOPs 的稀疏/稠密对照」比。

## 16. 快照增益必须做收敛对账

短训练（如 12k 步）的增益可能是**收敛加速**而非**最终质量**。凡报增益，必须附：

1. 对照臂与主臂的**同方法** loss 斜率（同一窗口、同一算法，不得一臂用 25% 窗、另一臂用 50% 窗）；
2. 至少一个更长训练点（如 2×）的 Δ，并说明 Δ 是保持、缩小还是消失。

实例：读出重参数化 Δ 12k −0.0812 → 24k **−0.0463（缩 43%）**，两臂仍未收敛
⇒ 只能作快照结论，且必须标注「疑为收敛加速」。

## 17. 契约模板易错点（写契约前先读这一节）

以下均来自实际返工/返修，逐条记录以免重复：

1. **不要把「需要深度监督才存在的指标」写进 stock dense 实验的判据。**
   实例：某契约的并列判据 `tf@4 ≥ 0.95`——普通模型只监督最终深度，实测 tf@4 = 0.44，
   四臂全部不可达 ⇒ 零区分度（执行者如实报，未改判据线）。
2. **门控 + 初始化约束可能互相矛盾，必须先做可满足性检查。**
   实例：某契约同时要求「sigmoid 门」「单边零初始化」「起步等价 direct 或 composed」，
   但 σ(0)=0.5 ⇒ 不可能。写契约时必须先验算：起步状态是否真的存在？
3. **Δ 的符号方向必须在契约里定义一次并全篇一致。**
   实例：某契约同时出现「Δbpc ≥0.014 可迁移」与「Δ ≥ +0.014 负迁移」⇒ 执行者只能自行统一。
   规范：一律写 `Δ = bpc_对照 − bpc_实验`（正 = 改善），并在判据三条线上复用同一符号。
4. **活性量要周期性落盘，不能只存终值。** 否则复核者无法与训练日志逐点交叉核对。
   规范：活性量每 200 步写入训练日志的同一行。
5. **冒烟脚本里不要留「按 20 步外推」的时间字段。** 20 步被进程启动开销主导，
   外推值可差 10 倍（实例：外推 `≈ 60.9 min` vs 实测 6.5 min），这类字段一旦留在证据文件里
   就会被后人误引。
6. **契约副本要如实标注「逐字」还是「摘要」。** 执行者常会压缩契约副本；
   规范：判据线逐字、其余可摘要，并把标注写准。
7. **契约必须写明「预算不够时砍什么」**（砍臂/砍步数/砍指标，不砍判据线），
   以及成本预算的唯一数字（§8）。
8. **契约里的「臂数」必须与「干预档数」一致，成本必须按臂数 × 本实验实测步时估。**
   实例：某契约正文写「2 臂」，而干预指定 k=32 与 k=64 两档 ⇒ 实为 3 臂；成本还借用了另一
   实验的步时，而目标配置实测 **2.2×** 慢（54.1 vs 24.5 ms/step，因必须算全分数矩阵且离开
   SDPA 融合核）⇒ 预算低估 1.4–1.8×。
   规范：① 臂数 = 干预档数 ×（1 + 重跑数），写进契约时数一遍；② 成本 = 臂数 ×
   **本实验先测的步时**（先 20 步实测再定预算），不得借用其他实验的步时；
   ③ 干预若会离开融合核（稀疏/自实现注意力），必须预估内核回退的倍数。
9. **「省算力」类干预必须报成本交叉点，而不只报理论降幅。**
   实例：内容 top-k 在 T=256 上理论注意力 FLOPs 下降（k/T），但**实测净开销**
   （慢 2.2×、显存 2×）⇒ 只在长上下文才可能回本。规范：理论值与实测值并报，
   并明确写出「在什么序列长度上开始回本」。
10. **仪器类实验必须同时给「依赖」与「保留」两条腿。**
    实例：KV 消融保留曲线量的是**依赖**（bpc 对可见集的敏感度）——低损伤也可能是
    模型本来就不用它（这正是「假保留」的另一面）。规范：保留类仪器必须再加一条
    **检索腿**（needle / 线性探针重建），否则「安全丢弃半径」会被误读成「信息保住了」。
11. **单点曲线不得当可加外推；累计效应必须直接测。**
    实例（本项目最贵的一次入账错误）：测出「删除恰在距离 d 的 KV」在 d≥32 时
    代价 ≤0.004，被入账成「**安全丢弃半径 d*≈32**」；直接测累计版本发现
    **只保留最近 32 个位置 = +0.212 bpc（单点读数的 15 倍）**，只保留 64/128/192 分别为
    +0.081/+0.020/+0.004。规范：任何「删掉一段 / 保留一段」的结论必须直接测**累计**配置；
    单点（单个距离、单个位置）曲线只能用于描述**形状**，不得用于**求和/外推**。
    同时要求：报「安全半径/预算线」时，必须同时给「按距离的单点」与「按累计预算的曲线」两列。
12. **「A 比 B 好」必须先把两者的删除/可见性预算对齐到同一物理量。**
    实例：三种优先级规则对齐了「删除位置数」，但没有对齐「掉掉的可见性对数」
    （N=8：2012 vs 1562 对）⇒ 字面优势是对齐口径造成的假象，重对齐后消失。规范：
    比较压缩/稀疏/丢弃类规则时，除了「删多少个」还要报「掉多少可见性对数」并给出两套口径。
13. **`catalog.yaml` 的标量不得以 `*` 或 `**` 开头**（YAML 会当别名/锚点，直接解析失败）。
    规范：写 `catalog.yaml` 时凡值以 `*` 开头一律加引号，或不用 Markdown 强调；改完必须跑一次
    `python3 -c "import yaml;yaml.safe_load(open('catalog.yaml'))"` 再提交。
    （`catalog.yaml` 已退役，见顶部迁移通告 / `docs/structure.md` §15；此 YAML 标量纪律对迁移后的
    `project.yaml` 同样适用。）

### 17.14 判据的「基准」必须唯一且显式

每个判据必须同时写明四项，缺一不得开跑：

1. **基准是谁**（哪个臂、哪个配置、哪个口径）；
2. **代价项相对谁算**（与基准同一口径，不得混用）；
3. **主判据是哪一个**（两种读法并存时必须显式指定 primary，另一个降为并列）；
4. **算力账**：若两臂的**推理算力不同**（如 K 路径集成 vs 单线），必须把算力价签写入结论句，
   并给出「把同样算力投给基准臂」的近似参照（可标注为近似），否则不得表述为部署优势。

**推论**：`A→B→C` 阶梯比「A vs C」更稳——它能一次拆开多因素，避免二次返工；
若预算只够两臂，选**有部署意义的那个基准**。

### 17.15 收敛门禁必须落在「决定判据的那个损失」上

1. 收敛门禁**必须**落在**决定判据的那个量**上（例：决定准确率的答案行 CE），不得用聚合损失代替
   （总 CE 被「已学会的 filler」主导会掩盖任务相关部分的欠拟合，按字面会误判「已收敛」）；
2. 报告必须**并报**聚合损失与任务损失两套斜率，并说明二者是否分歧；
3. 若两套口径结论相反，**采信任务损失口径**，并把分歧本身写进结论（它正是「欠拟合被掩盖」的证据）。

### 17.16 同族两点的「相对刻度」必须一致

宣称「两点趋势」时必须保证两点在同一相对刻度上、且都不是退化点：

1. 相对刻度一致（例：窗口占 T 的**同一比例**——128@256 与 256@512，均为 50%）；
2. 排除退化点（恒等/空集/无操作）——**用单测钉住**「该配置在此 T 下确实非退化」
   （例：窗口 256 在 T=256 上是恒等算子）；
3. 若无法构造第二个真点，**就如实报「单点」**（§17.11），不得用退化点凑数。

### 17.17 净和不可排序时，必须给「分量分解」两列

当「净效应落在不可排序带」时，报告**必须**附分量分解至少两列：

1. 该干预对**基准质量**的增量（例：clean 税）；
2. 该干预对**目标量**的增量（例：K 路径集成增益）；

并据此区分「机制无用」与「机制有效但代价抵消」——**这两种要在结论里分开写**，不得合并成「无效」。

### 17.18 判决腿必须在训练分布内

1. **主判据的距离档/难度档必须在训练分布内**；超额档只能作为**外推声明**，并显式标注；
2. 契约写「主腿 = 某任务召回」时**必须钉死参数范围**（距离档、Q 数、K 数），否则等于没定判据；
3. 若某腿的**同配置重跑方差 ≥ 结论效应**，该腿**降级为辅助腿**，并在报告首段写明
   （越界腿在同配置下的 run-to-run 方差可能极大，不足以当主判据）。

## 18. 先站巨人肩膀：每个契约必须有「既有做法」节

> 用户原话要点：每讨论一个设计/创新/方法，**应先去联想业界有哪些已做出来的实验是基于这个
> 设计的、它为什么这么设计、效果怎么样**。我们可能首先需要站在巨人肩膀上，不是从头造轮子，
> 只不过把这个肩膀更加清晰化——别人已经用过、或用过类似的，我们把它剥离出来再进一步。

**规范**：每个实验契约新增必需节 **§既有做法（prior art）**，写四件事：

1. **谁做过**（论文/系统名 + 一句话它做了什么）；
2. **为什么这么设计**（它声称解决什么、动机是什么）；
3. **它的实测结果**（同尺寸/同 FLOPs 下有效无效；不确定就标「记忆/待核」）；
4. **我们的增量在哪**（复现？剥离某个因素？换尺度？换任务？还是纯新）。

- 允许「未找到直接前例」——但必须写明**检索了什么词、看了什么来源**。
- 知识来源标注：`官网/论文（有链接）` / `记忆（未核）` / `本地实测`。**记忆类结论不得当判据**，
  只能用于设计方向。
- 检索方式：可用 `researcher` subagent（有 web 工具）；若无检索能力，如实标注并降级为记忆。

## 19. 任务的「局部先验抗性」是长程结论的前提

> 用户原话要点：模型太小太弱，**越小越弱的模型对远距离 context 越不敏感**，因为大部分靠
> 语言先验补强，从未涌现真正的长程能力，所以它对远期历史「没有特别的需求」。

**推论（写入方法学）**：在 enwik8 这类**局部统计极强**的数据上测「长程依赖 / 信息搬运」，
会把「模型不需要」误读成「机制搬运不了」。因此：

- 凡涉及**长程记忆 / 压缩 / 信息搬运**的结论，必须在一个**局部先验无法补全**的任务上复核
  （合成任务：随机键值关联回忆、induction、复制、变距离回忆）。
- 报告必须**同时给**「在强局部先验任务上」与「在弱局部先验（合成）任务上」两组数；
  若两者结论不同，**以合成任务为准**并说明差异原因。
- 相应地：长程类的「无效」结论，默认解释为「在该任务/该尺度上不划算」，
  **不得**表述为「该机制不可能」。
- **合成任务的结论外推力弱**：真实文本代理口径的自身噪声（同一模型只换种子）可能**大于**
  要测的效应 ⇒ 合成任务上的结论必须标注适用域，并把「真实文本上的同口径复现」列为待办。

## 20. GPU 互斥锁协议（并行 agent 的前提）

单卡 4090 要支持**多个 agent 并行**，GPU 必须显式串行。**所有 GPU 工作（训练/评测）**遵守：

```bash
# 取锁（最多等 10 分钟；等不到就上报，不许杀别人的进程）
LOCK=/tmp/pathlm_gpu.lock
n=0
while ! mkdir "$LOCK" 2>/dev/null; do
  hp=$(cat "$LOCK/holder_pid" 2>/dev/null)
  stale=0; reason=""
  if [ -n "$hp" ] && ! kill -0 "$hp" 2>/dev/null; then stale=1; reason="holder_pid $hp 已死"; fi
  if [ -z "$hp" ] && [ -d "$LOCK" ] && [ $(( $(date +%s) - $(stat -c %Y "$LOCK") )) -gt 900 ]; then
    stale=1; reason="无 holder_pid 且锁龄 >15min"; fi
  if [ $stale -eq 1 ]; then
    echo "reclaim: $reason"
    rm -f "$LOCK/holder_pid" "$LOCK/heartbeat" 2>/dev/null   # 先清空内容再 rmdir
    rmdir "$LOCK" 2>/dev/null || true
    continue
  fi
  sleep 15; n=$((n+1)); [ $n -gt 40 ] && exit 9
done
echo $$ > "$LOCK/holder_pid"; touch "$LOCK/heartbeat"
trap 'rm -f "$LOCK/holder_pid" "$LOCK/heartbeat" 2>/dev/null; rmdir "$LOCK" 2>/dev/null' EXIT
# ... GPU 工作（峰值 ≤5GB net；长训练 nohup 后台 + ≤110s 轮询，轮询时 touch "$LOCK/heartbeat"）...
rm -f "$LOCK/holder_pid" "$LOCK/heartbeat" 2>/dev/null; rmdir "$LOCK" 2>/dev/null
```

- **自愈规则**：等待者在循环里判定并回收陈旧锁——任一条成立即回收：① 锁目录内 `holder_pid`
  不存在或其进程已死；② 无 `holder_pid` 且锁龄 >15 min。回收与释放一律**先 `rm -f` 内容再
  `rmdir`**（锁目录含 `holder_pid` 时 `rmdir` 删不掉非空目录）；循环路径上**始终有 `sleep`**，
  回收失败不得空转。
- **不得用 `pgrep` 判据**：`pgrep -af "train|run.py"` 会命中等待者自己的命令行，导致陈旧锁永不回收。
- **等待上限 10 分钟**（40×15s）；等不到就上报，**不许杀别人的进程**。
- **纯 CPU 工作**（情报、设计、写文档、对账、汇总已落盘数据）**不取锁**，可自由并行。
- **锁泄漏判定**：锁存在 >120 分钟**且** `nvidia-smi` 无我们的训练进程 ⇒ 可 `rmdir` 并在报告中记录。
- 任何「等锁超时 / 锁泄漏 / 显存超预算」都要在最终汇报里显式列出。

### 20.1 锁粒度：多臂驱动必须按臂释放

1. **多臂驱动按臂释放/重取**：每臂结束后 `rm -f $LOCK/holder_pid $LOCK/heartbeat; rmdir $LOCK`，
   留 **≥60 秒窗口**，再重新取锁跑下一臂；只有**整程 <10 min** 才允许整程持锁。
2. **短任务插队**：纯推理、**≤2 min**、峰值 **≤1GB** 的任务，满足「`nvidia-smi` 空闲 ≥3GB」时
   **可并发插入**，不必等整轮训练结束；但必须在报告里登记为「§20 一次性并发例外」，附前后空闲读数与自身峰值。
3. 例外任务**不得取锁、不得动锁目录**；长训练**不得**为省事整程独占。
4. 复核清单新增一项：**是否存在违反 20.1 的整程持锁**（有则记录，但只判「是否影响结论」）。

### 20.2 显存礼貌线与「配方一致性」冲突时：优先配方一致，但必须记账

1. **5GB 是共享卡礼貌线，不是科学约束**；当它与「保持两臂配方逐字段一致」冲突时，**优先配方一致**。
2. 代价必须三件套记账：① 逐臂实测 `peak_gpu_mem_mb`；② 跑前后各记一次 `nvidia-smi memory.free`
   （证明余量 ≥8GB）；③ 在最终汇报里显式列为**超礼貌线的偏离**。
3. **禁止**为了让数字好看而改批大小/步数/精度——那会破坏基准与实验的可比性（§15 / §17.14）。
4. 若余量不足 8GB，则**不是**选改配方，而是**排队等锁**（§20.1）。

### 20.3 被外部占用降速时：缩步数保「臂间同刻度」，不缩臂、不等卡

优先级从高到低：

1. **保持臂间同 token 预算**（阶梯/对照的公平性由「臂间相等」保证，不由绝对步数保证）；
2. **缩步数**（而不是砍臂、不是换配方、不是等卡），并在报告首段声明「**Nk 快照口径、与既往 Mk 不可比**」；
3. **必须附答案行 CE 末窗斜率**（§17.15），并说明「只读臂间增量、绝对水平是快照」；
4. 如实记账环境争用与实测步时（外因不得用来改科学设定，只能用来改**规模**）。

## 21. 不重复造轮子：业界做透的**直接写结论**，不做实验

> 用户原话要点：我们不做业已做出来的东西，永远在业界做出来的东西**之上**再研究；
> 如果业界已经完全研究透了，就**直接把结论写进对应目录**。

**分诊规则**（每个格子写文档时必须给三选一）：

| 判定 | 处置 |
|---|---|
| **(a) 业界已研究透**（同任务、同机制、规模足够、结论一致） | **不跑实验**。在对应目录写 `PRIOR_ART.md` 的结论条目，并在 `catalog.yaml` 的 `local` 值里**显式标注「业界结论，非本地实测」**（附可核实出处，或标 `记忆·未核`）。（`catalog.yaml` 已退役，见顶部迁移通告 / `docs/structure.md` §15；迁移后等效落点 = 该研究项 `project.yaml` 的 `sota_baseline`/`conclusion`，非本地实测须显式标注。） |
| **(b) 业界没有 / 结论不一致 / 我们的设定实质不同**（13M、局部先验抗性任务、单因素受控、旁路形态） | **做实验**，契约必须写「我们的增量在哪」 |
| **(c) 查不到**（含检索不可用） | 按 `记忆·未核` 记录方向；**不得**据此判定 (a) |

- 「我们只复现一遍」不算增量：复现只允许发生在**判据本身有争议**或**我们要把它作为判据线**时。
- (a) 类条目**不得**进入状态灯的 `judged`（那是本地实测的口径）；其格以 `status: todo` 登记，`verdict` 注明「尚未核实／待立项」。业界结论必须给出**可核实的出处**；检索不可用时标 `记忆·未核`，**不得**作为结论或免做依据。

## 22. 共享文件的并发写：代码编辑锁 + 锚点声明

**规则**（并行推进的前提）：

1. **派发前先做共享面分析**：哪些线要改哪些共享文件；**同一文件不得有两个并行写入者**。
2. 若无法避免（同一实现空间的两条线），使用 **`/tmp/pathlm_code.lock` 代码编辑锁**：
   只在「读-改-写」窗口内持锁，改完立刻释放；**锁顺序固定：先 code 锁、再 GPU 锁**（防死锁）。
3. **先声明锚点再改**：插入点写成可核对锚点；只做**局部追加**，禁止整块重写。
4. **改完回读校验**：逐条 grep 断言其他线的标记仍在；**禁止** `git checkout`/`stash`/任何回滚他人改动。
5. **测试顺序**：先定向（自己的 + 邻线的 `-k` 子集），再全量。
6. **指纹与重叠归属如实记录**：把共享文件的 sha256 记进 `MODEL.md`，并在报告里写明
   「本轮共享文件还含 X 线的未提交改动」——口径重叠必须写出来。
7. 更优解：**把新逻辑放进新模块**，共享文件只留最少的接线（例：配置字段 + `if λ>0` 的损失接线）。

### 22.8 派发前必须做「能力面分析」，不只共享面分析

**规则（与共享面分析并列，派发前逐条做）**：

1. **能力面**：契约要求的每个 flag/组合，引擎是否支持？两两与三者**组合**是否有互斥校验？
   （最低成本检查：`grep -n "ValueError\|互斥" pathlm/depth_ar.py` 列出所有校验，再核对契约。）
2. **块类/实现面**：不同特性是否换了不同的 block 类（导致无法共存）？
3. 若不可组合：**要么**把契约降到当前可达的忠实子问题（并显式声明未测因子、禁止外推），
   **要么**把「使可组合」立成**带技术要点与验收单测的后续项**——**不允许**含糊成「以后再说」，
   **也不允许**在未获授权时改引擎绕开。

## 23. 每个格子必须做到「预算内极致」

> 用户原话要点：所有研究项并行运行；主 Agent 负责确保**每个项目都做到 scope 内/预算内能做到的极致**；
> 具体活由 sub-agent 干。

**「极致」的可执行定义**（每格在收口前必须逐条回答，写进该格的 `notes` 或对应 ticket）：

| # | 问题 | 不合格的表现 |
|---|---|---|
| 1 | **既有做法查过了吗**（§18）？业界做透的部分是否已写成 `PRIOR_ART.md` 结论（§21）？ | 还在重复做业界已做透的事 |
| 2 | **判据是最严的那个吗**？是否用了诚实对手（§11）、是否有毁源/因果/活性三类护栏？ | 只有单一有利指标、无对照 |
| 3 | **对照是错的哪一类**都试过吗（同参数量 §15、同算力、同字节预算 §17.12）？ | 只跟弱对照比 |
| 4 | **规模/预算的边界探过吗**？是否至少两档规模或两个预算点（§17.11 禁外推）？ | 单点结论当趋势 |
| 5 | **反方向/否证路径**是否走完（失败决策树四层）？ | 只报正面 |
| 6 | **未测项是否显式列成「下一步最小实验 + 成本」**？ | 留一句「未来工作」了事 |
| 7 | **复核是否通过**（§14，含 §14b 顺序）？ | 未复核即入账 |

**主 Agent 职责**：对每个 `judged` 格跑一遍这七问，缺项的排进下一波；**不允许**在一个格还缺
关键对照/关键预算点时就把它当「完成」。**并行度**：知识线（CPU）+ GPU 线（锁串行）+ 复核线
同时推进，下一波在上一波落盘后立刻派发。

## 24. 方法学检查表：十三类**已实测**缺陷

> 本节是**过程性检查表**，不是新的证据要求：下面每一条都是本仓库**真实发生过**的缺陷（附出处）。
> 写契约、写对账、改门限/口径之前逐条对照一次；命中任一条即不得入账。与
> §5（校验命令）、§10（活性判据）、§12（对账义务）、§14（独立复核）配套使用。

1. **恒真断言**：断言里的关键参数没传进去（或取了会退化的默认值）⇒ 条件恒真、断言永远通过。
   反例：2634 的 `rf`（主干有效感受野）曾按默认值 `0` 调用，泄漏断言 `eval_lo − rf ≥ corrupt_hi`
   退化成恒真式；修法是把 `rf` 改成**必填关键字参数**并由模型规格派生
   （`axes/1-time/1.1.4.1-explicit-memory/experiments/2634-carry-realtext-13m/realtext_probe.py:45-49,120-132`）。
2. **不可达判据**：判据的符号/方向写反 ⇒ 无论数据怎样都判不过（或都能过）。
   反例：2634 的毁源对照把 `two_proportion` 的参数顺序传反，判的成了「地板显著高于植入」，
   该判据**永远不可能通过**；修法是把方向固化进 `needle_stats.beyond_above_floor`，并加一条
   「应通过」构造输入的单测（`2634-carry-realtext-13m/analysis.md:208`）。
3. **引数无出处**：报告里的数字在仓库里找不到家（没有 `results.json`/日志字段可回算）。
   反例：2636 成本腿墙钟列曾写不存在的「轮2」四值 1.234/1.005/0.883/1.799；改为
   `cost.measured.ratio_by_T` 的实测 0.992/0.915/1.069/1.784（`.scratch/52-a6-longt/issues/01-a6-longt.md` P0-1）。
4. **数据反驳结论**：表里列了与结论相反的分量，却没算、没解释。
   反例：2634 的毁源对照整体桶判「无区分力」，但同索引硬子集上通道臂比无通道臂高 1.0–1.4pp
   （绝对水平 **2.421% / 2.253%** vs **1.042% / 1.210%**，即 **2.32× / 1.86×**）、CI 排除 0 ⇒ 结论必须写成「整体无区分力 +
   硬子集弱证据、可检索性未证」（`2634-carry-realtext-13m/analysis.md:18,44-48,92,212-236`）。
5. **等价范围小于声称**：证据只覆盖了声称范围的一部分 ⇒ 复用/等价结论越界。
   反例：2633 的「语义等价」只覆盖 `pathlm/**`，而运行期漂移还含训练脚本 `train_depth_ar.py`；
   训练脚本层未证等价时 `reuse_scope` 必须降级为「仅 pathlm/**」
   （`2633-carry-seed2/equality_vs_2631.py:37,235-236`、`analysis.md:206-231`）。
6. **参考线口径写错**：把同预算/同口径的参照臂说成「预算不同」（或反之），参照系就失去意义。
   反例：2634 的参考尺度是 `2610` 的 trunk——同尺寸、同预算 12k 步 × bs32 × T256 = 98.3M token，
   差别只在评测批数（96×16 vs 24×16）与可见性，不得写成「训练预算不同」
   （`2634-carry-realtext-13m/analysis.md:141-147`）。
7. **字段错位**：YAML 缩进把格内字段归给了上一格（默认 loader 不报错）。
   反例：`catalog.yaml` 曾有 22 处 `prior_art_source` 漂到上一格；现由
   `tools/check_catalog_strict.py`（§2 归属核对 + §3 游离键）机检
   （另见 `.scratch/50-critical-audit/FMG-AUDIT.md:148`）。
   （`check_catalog_strict.py` 已退役，见顶部迁移通告 / `docs/structure.md` §15；
   「字段错位」纪律对 `project.yaml` 同样适用，同一规则由 `check_tree.py` 的字段校验承接。）
8. **恒等式当因果**：把逐项相消的记账恒等式当成可加的因果分解（交互项被漏报）。
   反例：R7 的税拆解——三项相加恒真，真实分解含交互项 −0.1392（两轴不独立）
   （`axes/7-references/experiments/R7-existing-early-exit/2623-standard-early-exit-13m/analysis.md:115-119,324`）。
9. **判决判据的合取被读成半个成功**：`A 且 B` 型判决只满足了 A 就写成「成立 / 有条件成立」。
   反例：R7 的 D1 要求 `bpc` 与 `tf@4` 两条腿同时成立，第二条不成立（0.8402 < 0.9102 − σ_tf）
   ⇒ 只能写「D1 触发条件未满足、降级为待测」，不得写「有条件成立」
   （`2623-standard-early-exit-13m/analysis.md:157`）。
10. **死代码冒充对账**：对账脚本遍历的键名与产物实际键名不匹配 ⇒ 断言从未执行、却报全绿。
   反例：R7 的 `reconcile_numbers.py` 曾遍历 `decode.items()` 里 `spec_g*` 前缀的键（该键不存在），
   四条 spec 腿的恒等式/口径断言全部空转
   （`axes/7-references/experiments/R7-existing-early-exit/2623-standard-early-exit-13m/reconcile_numbers.py:101-111`）。
11. **修复引入新错**：下调/替换门限或口径时没同步下游比较句 ⇒ 报告自相矛盾。
   反例：2636 把工程带换成判据量噪声（0.009459/0.006231）后，下游比较句仍按旧带 0.014 写「带内」，
   与 0.012210/0.010573 判「越界」冲突（`2636-longT-unified/analysis.md:40,89,125,274`）。
12. **测试绿但交付入口不可复现**：生产者改了报告键名而漏改调用方，`pytest` 不跑文档化入口
   ⇒ 全绿掩盖 KeyError。反例：2633 的 `compare()` 把键改名为
   `implementation_equivalent_to_2631_runtime`，而 `run.py` 仍读旧键 ⇒ 复现入口崩溃
   （`2633-carry-seed2/equality_vs_2631.py:49-58,68-73`、`run.py:121`）；现由
   `assert_report_schema` 的**冻结键清单**在生产者与消费方两侧各核一次。
13. **局部修复 / 局部重构**：只改「改动直接指向的那一处」，没扫它的**相邻面** ⇒ 同一产物里
   留下自相矛盾，或「修复」的覆盖范围小于声称。四种形态各有一个真实反例：
   - **改了定义处、没改引用处**：2633-carry-seed2 的 `compare()` 把报告键改名为
     `implementation_equivalent_to_2631_runtime`，漏改 `run.py` 的消费点 ⇒ **文档化入口
     `KeyError`**（与第 12 类同一事故，这里看重的是「只改定义处」这个动作；
     `2633-carry-seed2/equality_vs_2631.py:49-58,68-73`、`run.py:158-160`）。
   - **改了一个字段、没扫同一产物的兄弟字段**：2633 回填 `cost.lock_accounting` 却没同步
     `run.py` 写出的 `cost.lock_note` ⇒ 同一份 `results.json` 里两处对**同一件事**口径相反
     （`2633-carry-seed2/run.py:76-123,466-476`；护栏 = `_assert_lock_consistency`）。
   - **改了门限、没改下游比较句**：2636 把「带内」门限从旧口径 `0.0158`（单臂 bpc 跨 seed
     极值）下调为判据量噪声 `0.0095`（Δ 跨 seed 极差）后，下游仍写「两口径之差 `0.0123`
     落在噪声带内」——`0.0123 > 0.0095`，句子与自己的门限相反
     （`2636-longT-unified/analysis.md:40,125`）。
   - **修复的覆盖范围小于声称**：2623 的 `fill_share.py` 只回填**标记位**（`SHARE_*`），
     正文里**没打标记**的手输数字仍不在覆盖内 ⇒ 编造值 `1.9641` 从这个缝漏出；现由
     `audit_numbers.py` 对**每个数字 token** 做可失败审计
     （`2623-standard-early-exit-13m/` 下的 `fill_share.py` / `audit_numbers.py`）。

   - **只改了实验文档、漏了账本与生成页**：2634 的硬子集召回从产物 `0.022529` 誊写进正文时
     误成 `2.53%`（真值 **2.253%**）；发现后只改了 `2634-carry-realtext-13m/analysis.md`，**账本**
     `catalog.yaml` 的 M1 `verdict` 与**生成页** `archive/wiki-legacy/axes/M-carrier/M1-carrier-type/README.md`
     仍留 `2.53%` ⇒ 账本与它自己引用的证据矛盾。现由
     `tools/check_catalog_strict.py` 的 **跨表面一致性**机检（`local.key_numbers` 声明的关键数字
     必须在**账本 verdict / 生成页 / 实验产物**三类表面逐字出现；注入 `2.53%` 即红）；
     另有 `local.key_numbers_forbidden` 的**已废止数字黑名单**（同一检查器 0b）——被替换掉的旧值
     出现在三类表面任何一处即失败（本轮 `2.53%`、`约 2.2×` 均已入黑名单）。

   **强制动作**：改动后必须 `grep` 回扫**所有**引用点，并对**同一产物内互相关联的字段加
   一致性断言**——改定义处就回扫引用处、改一个字段就扫兄弟字段、改门限就扫下游比较句，
   让「两处相反」在写盘前就失败（如 2633 的 `_assert_lock_consistency`）。
   **三类表面（实验文档 / `catalog.yaml` verdict / 生成页）必须逐字一致**：关键数字用
   `local.key_numbers` 声明，`tools/check_catalog_strict.py` 会在三类表面上机检
   （改数字后必须 `python3 tools/build_wiki.py` 重生成页面，否则页面这一面必红）。

   > （`catalog.yaml` / `build_wiki.py` / `check_catalog_strict.py` / 生成页均属**已退役**的生成式
   > wiki 机制，见顶部迁移通告 / `docs/structure.md` §15；此条款仅对已归档的旧页/旧账本适用。
   > 其**分析纪律**——关键数字必须逐表面一致、改数字必须回扫所有引用点——**仍然生效**；
   > 迁移后的落点为 `project.yaml` 的 `conclusion`/`argument` 与实验产物一致。）

**两条强制动作**（每个契约 / 对账脚本 / 门限或口径修改收口前必做）：

- ① **可达性自证**：任何断言与判据都必须**构造一个能让它失败（或通过）的输入**跑一遍，
  并把这个构造钉进测试。第 1、2、10 类缺陷只有这一步能抓住——读代码看不出「恒真」和「空转」。
- ② **引用点回扫 + 入口真跑**：任何改动后回扫**所有**引用点（`grep` 逐条确认改了几处、漏了几处），
  并**按文档化的入口真的跑一次**（不是只跑 `pytest`）。第 11、12 类缺陷只有这一步能抓住。
