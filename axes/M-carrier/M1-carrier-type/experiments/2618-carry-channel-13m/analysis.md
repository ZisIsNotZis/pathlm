## 0. 人话摘要（先看这段）

**我们想干什么。** 我们想看一件事：如果模型在处理一段长文本时**只能看见最近 16 个字符**
（超出这个距离就真的看不见），那么在给了它一个**专门的「记事本」**（一块固定大小的记忆，
可以随时写、随时读）之后，**它能不能把远处看过的信息搬到近处来用**？以及，笔记**怎么写**
更好——是「见到什么就往上加」（plain 累加写），还是「只写本子上还没有的那部分」（delta
残差写，也就是我们常说的「只搬上次没搬的」）？

**怎么测的。** 我们造了一个**不靠猜、只能靠记住**的小游戏：先给 8 对「钥匙→值」，中间隔
两百多个字符的空白，最后问其中一把钥匙对应的值。因为这个游戏里的键和值都是随机符号，
**看最近 16 个字符是绝对猜不出来的**（窗口里只有空白和一个「提问标记」）。三个臂除了「记
事本」之外**完全一样**（同 13.5M 参数、同 12k 步、同种子、同窗口）：
① 不给记事本（U0）；② 给记事本、plain 写（U1）；③ 给记事本、delta 写（U2）。

**测出来多少**（准确率口径；瞎猜 = 1/64 = **1.56%**，括号里是 95% 置信区间）：

| 小游戏（8 对） | ① 没记事本 | ② plain 写 | ③ delta 写 |
|---|---|---|---|
| 答对率 | **1.37%**（1.05–1.77）≈ 瞎猜 | **0.07%**（0.02–0.22），**比瞎猜还差** | **9.50%**（8.64–10.43）= **6.1 倍瞎猜** |
| 把远处那对「钥匙→值」**毁掉**之后 | 1.37%（无所谓） | 0.07%（无所谓） | **0.81%**（0.57–1.13）≈ 瞎猜 ✓ |

**怎么读。**
1. **「没记事本 ⇒ 真答不出」这条前提成立了**（判据①）。U0 是 1.37%，瞎猜 1.56%，
   置信区间下界 1.05% ≤ 瞎猜 ✓；而且被问的那对钥匙离提问处 **241–255 个字符**，**100% 落
   在 16 字符窗口之外**（`premise_check.json`）——所以 U0 的低分不是「任务有漏洞」，而是
   「确实看不见、也没地方存」。
2. **有了 delta 记事本，信息真的被搬过来了**（判据②）：9.50% vs 1.37%，差 **+8.13pp**，
   两个 95% 区间**不重叠** ⇒ 主判据通过。而且**毁掉远处那对键值之后，分数掉回 0.81% ≈
   瞎猜**（判据④）⇒ 这 9.5% 确实是「从远处搬过来的内容」，不是位置或局部规律的伪命中。
3. **「只搬上次没搬的」明显更好**（判据③）：delta 比正式 plain 臂高 **+9.42pp**，区间不重叠；
   即使拿「plain 学到的那次重跑」比，仍高 **+6.15pp**（区间不重叠）。
   机制侧的数字也支持这个读法：plain 的记事本**越写越胀**（状态范数从 50 涨到 71.8 还在涨），
   delta 的一直**稳在 ~3**（2.93 均值 / 3.11 末值）——plain 把重复内容反复堆上去，把有限的
   空间浪费掉了；delta 每次都先扣掉「本子上已经有了的那部分」，所以同样的空间能装下更多不同
   的东西。
4. **但有一件必须先说清的不确定性**（判据⑥的重跑臂）：**plain 臂的学习结果是不可复现的**。
   同配置同种子跑两次：正式 U1 停在答案行 loss **4.184**（≈ 瞎猜 4.1589，什么都没学到），
   重跑臂 U1rep 降到 **2.2524**（真的学到了）；更早一次试跑也已到 3.5015（留存数据里该值出现在 U1rep 的 **step 5000**）。
   ⇒ **plain 臂是「有时能学、有时学不动」的双稳态**，而 delta 臂一次就学得很扎实
   （答案行 loss 4.1589 → **1.4772**）。两条 plain 轨迹直到 step ~2400 都逐位相近
   （差异 3e-4/步），之后才分岔 ⇒ 这是**训练侧的临界现象**，不是评测噪声。
   **但判据③没有因此翻车**：拿「plain 学到的那一次」和 delta 比，
   **U1rep 3.34%**（CI 2.84–3.94）vs **U2 9.50%**（CI 8.64–10.43）⇒ **Δ = +6.15pp，区间
   仍然不重叠**（差值 CI [5.10pp, 7.21pp]）。也就是说：**delta 优于 plain 这件事在最有利
   于 plain 的那次读数上仍然成立**（本次读数为 +9.42pp，稳健下界为 +6.15pp）。

**结论与下一步。** 主判据（②）通过：**显式写入通道确实能把窗口外信息搬进可达范围，而且搬
的内容经得起「毁源」对照**。并列判据（③）在本读数下指向 delta 优于 plain，但由于 plain
臂的双稳态，下一步应该做的是**先把训练不稳定这件事量化**（每臂 3–5 个种子，或固定
「答案行 loss 是否逃出瞎猜线」作为学习成功判据再做规则对比），而不是直接宣布 delta 规则胜出。

## 2. 六问

1. **它是干什么的**：让模型有一个**固定的记事本**（一块 `H×dh×dh = 8192` 个数的状态，
   与序列长度无关），把已经看过的信息写进去，并在需要时读出来——这样即使注意力只看最近
   16 个位置，远处看过的内容仍然可用。
2. **相对普通 decoder-only transformer 改了什么**：只在**加了一路固定状态的写入/读出**：
   `k̂ = normalize(W_k h)、v = W_v h、β = σ(W_β h + b_β)`，状态按位置因果更新
   （plain：`S_t = S_{t−1} + β v k̂ᵀ`；delta：`S_t = S_{t−1}(I − βk̂k̂ᵀ) + β v k̂ᵀ`），
   读出 `mem_t = S_t q_t` 加到**每层**的注意力输出上（每层一个可学的读出增益 γ，零初始化）。
   主干（注意力 / MLP / 残差 / tied 读出）**一个字没改**；参数量 +264,296（**+1.95%**，
   13,536,768 → 13,801,064），U1 与 U2 **逐位等参数**（同一组张量，只改更新式）。
3. **为什么改**：既有实测说「只靠掩码逼模型只看近处」= **只丢不搬**（窗口 32 训练后窗外针召回
   与无记忆地板差 +0.0043；窗口 192 训练的差值恰好 0.000），而这块 13M 主干在**关联回忆**
   上准确率 0.0061 ≈ 瞎猜 ⇒ 长程检索能力是零。所以要么给「搬」一条通道，要么就永远测不到
   搬运。delta 写针对的是「有限状态的容量被重复写入浪费」这个具体痛点。
4. **怎么测的**：对照组 = **同一模型去掉通道**（U0，参数量只差 1.95%）；指标 = **准确率口径**
   （不用 bpc——训练侧 bpc 噪声 0.0156 已接近方差界）；口径 = 12k 步快照（不是渐近）、
   单卡共享 4090、合成任务（局部先验抗性已证）；每个读数都配**毁源对照臂**与二项 CI。
5. **测出来多少**：见 §0 表。参照系三件：瞎猜 1.56%、局部先验 1.56%（K=8 时窗口内没有任何
   符号）、U0 1.37%。δ = **+8.13pp**（8.64–10.43 vs 1.05–1.77）⇒ 差距从「完全为 0」变成
   「约 6 倍瞎猜」。**但绝对值只有 9.5%**：通道搬过来的信息是**弱**的（12k 步、13M、单状态
   —— 对照业界 MQAR 的做法这只是很小的规模）。
6. **结论与下一步**：**通道成立（判据②过），delta 优于 plain（判据③本次读数过，但受
   plain 双稳态限定）**。下一步优先做「学习稳定性」而不是「换更大规模」：多 seed × 固定
   「是否逃出瞎猜线」的成功判据，再谈规则优劣；其次才是容量/距离的规模曲线。

## 4. 显式实现决策（SCHEMA §17.8，超预算后的取舍，已获主 Agent 裁决批准）

**决策**：把「每层各一个 `dh×dh` 状态」改成**单共享槽**（一个状态、在输入流上算一次，每层
用自己的 query 读出 `γ_ℓ ⊙ mem_t`）。

**触发它的实测**（同配方、同卡、13M/bs32/T256，`chunk=64`）：

| 实装 | U0 步时 | U1 plain | U2 delta | 推断单臂墙钟 |
|---|---|---|---|---|
| per-layer（12 个状态） | 49–54 ms | **207 ms** | **396–425 ms** | 11 / 41 / **79–85 min** |
| 单共享槽（本实验采用） | 49–54 ms | **60.7 ms** | **73.1 ms** | 11.1 / 13.5 / 16.3 min（实测见 §5.3） |

> 上表两组是**同一台共享卡上两次独立测量**（实现期计时基准 + 最终训练）：
> per-layer 那一组另有一份**落盘日志**（`smoke/smoke_u{0,1,2}/train_log.jsonl`，
> 420 步）给出约 **43 / 208 / 396–410** ms/step（由各臂 `train_log.jsonl` 累计 `min` 字段推导；原写 63.2/221.1/410.5 中的 U0 值在日志中无出处）（与基准相差 5–7%，同处
> **3.5× / 6.5×** 量级）；单共享槽那一组在最终训练日志上的平均步时（墙钟/步数）为
> 55.6 / **67.4** / **81.3** ms ⇒ 倍数 **1.21× / 1.46×**。两组各自内部同口径可比，
> 跨组不作精确比较（不同批次的共享卡占用不同）。

**根因（不是 FLOPs）**：逐算子 CUDA 派发与 autograd 节点开销。实测单个 batched
`solve_triangular` GPU 时间 0.04 ms、单个 `bmm` 0.10 ms，但**每个算子的 CPU 派发 60–150 µs、
每个 autograd 节点 ≈180 µs**；per-layer 每 chunk ≈22 算子 × 4 chunk × 12 层 ≈ **1000 算子/步**
（前后向 ~2500 节点）⇒ 4.3×/8.5× 基线步时。加大 chunk 只把 delta 降到 180 ms（C=256）且峰值
显存升到 9.2 GB（超 5 GB 净预算），所以**单共享槽是唯一既在预算内、又保持契约语义的形态**。

**代价与收益（如实记账）**：
- 代价：写入表达力较弱——写入张量来自**输入流 h₀** 而不是各层隐状态（每层仍有自己的读出
  增益，但读的内容与各层深度无关）；状态容量是 `H·dh·dh = 8192` 个数（与 T 无关）。
- 收益：与 **MQAR / 线性注意力家族的标准形态**（一个状态层 + 若干全注意力层）直接可比；
  扫描从 12 次降到 1 次；步时倍数 1.24×（plain）/ 1.49×（delta）。
- 契约语义不变：因果（位置 t 只用 `S_{≤t}`）、U1/U2 逐位等参数（唯一变量 = 写入式）、
  单边零恒等起步、窗口与通道共存、毁源对照臂。

| `read_share`（读出/注意力输出量级，训练均值→末值） | **0** | 0.0566 → 0.1322 | **0.7440 → 0.7078** |
| 评测期 `read_share_per_layer`（探针） | 0 | 0.0852 | **0.3867** |
| 槽的分数质量 `Σ_j|β_j(k̂_j·q_t)|`（探针） | 0 | 3.191 | **22.136** |
| `far_read_norm_frac`（读出里窗口外份额，精确） | — | 0.8814 | 1.0026 |
| 反事实 `rel_dev_vs_channel_off` / `vs_other_rule` | — | >0 / >0 | >0 / >0 |

→ **干预活着且真的被读**：U2 的读出量级是注意力输出的 0.74 倍、槽质量 22.1（对照 softmax
分支恒为 1），且读出**几乎全部来自窗口之外**（far 份额 1.00）。U0 的这些量恒为 **0**。

### 5.4 副产品

- 状态大小与序列长度**无关**（8192 个数/样本，解析值；KV cache 对照：6,291,456 B/样本）；
- 一个可复用的**「窗口 + 显式通道」训练/评测夹具**（`train_depth_ar.py --synth-task assoc-mqar
  --carry-write {none,plain,delta}`）与三件仪器（活性量、读取量、毁源对照）。

## 6. 读数表

### 6.1 主腿（关联回忆，含毁源对照；n=4096/格）

见 §1 的 K 表与 §5.2。**毁源口径**：把 `[0, 2K)` 的 (key,value) 换成新随机符号，查询行/答案/
距离逐位不变（`longrange_tasks.corrupt_span`）。

### 6.2 为什么 U1 低于瞎猜

U1 的主腿（0.000732）与距离腿（0–0.00293）**都低于瞎猜**。这不是噪声：CI 上界 0.002151
≪ 0.015625。机制侧的对应物是 plain 的状态**无界增长**（`state_fro` 71.8 且仍在涨）——读出
向量随之变大（`read_norm` 37.5），把残差流推向少数几个符号，于是「猜」的系统性偏差压过了
均匀基线。**这是一条负面读数**：plain 写不仅没搬来信息，还**污染了读出**。

### 6.3 距离腿（变距离回忆，三臂 × 六档；n=1024/点）

| 距离 d | 源 key 位置 | 源是否在窗口内 | U0 | U1 | U2（主臂） | U2 毁源后 |
|---|---|---|---|---|---|---|
| 16 | 239 | 值在窗口内（键不在） | 0.011719 | 0.002930 | 0.036133 | 0.007812 |
| 32 | 223 | 否 | 0.014648 | 0.000000 | 0.000000 | 0.005859 |
| 64 | 191 | 否 | 0.017578 | 0.001953 | **0.289062** | 0.010742 |
| 128 | 127 | 否 | 0.015625 | 0.000000 | **0.101562** | 0.008789 |
| 192 | 63 | 否 | 0.019531 | 0.001953 | 0.000977 | 0.002930 |
| 255 | 0 | 否 | 0.015625 | 0.000000 | **0.594727** | 0.008789 |

→ U0 六档全部 ≈ 瞎猜（与 2617 电池零样本读数同口径）；U1 全部 ≤ 瞎猜；**U2 六档并非全部
高于瞎猜**——**d=32 = 0.000000、d=192 = 0.000977 低于 chance 0.015625**；最远处
（d=255，源在最开头）**0.594727**。**曲线不是单调的**（d=32/192 低于 chance 而
 d=64/255 很高）——最可能的解释是训练分布的位置结构（训练时键值对固定落在最前面
`[0,16)`、查询块固定在末尾），使某些「源位置」在训练分布里没有对应物；这属于**该构造的
局限**，不能读成「距离越远越好」。按 SCHEMA §17.11，此处只描述形状，不做外推。

## 7. 对账与失败决策树

### 7.1 三道对账（SCHEMA §12，只对**支持假设**的数字做）

1. **算术对账**。任务的可答集合是 64 个符号 ⇒ 瞎猜 = 1/64 = 0.015625；二项下界
   `p±1.96√(p(1−p)/n)`，n=4096 时 0.094971 的区间半宽 ≈ 0.0090（实测 CI 0.086368–0.104333
   半宽 0.0090 ✓），U0 的 0.013672 半宽 ≈ 0.0036（实测 0.010544–0.017711 ✓）。**差值 CI**
   [7.16pp, 9.10pp] 不含 0 ✓。**训练侧 loss 的算术下界**：一个 batch 里真正不可预测的行 =
   16 个键值行 + 8 个提问键行 + 8 个答案行 = 32 行（其余 223 行是空白，可预测），
   32×ln64/255 = **0.522**；U0 的末行 loss **0.5059** 略低于该界（键是**不放回**抽取的，
   后面的键略可预测）⇒ 与「U0 只学会了可预测部分」自洽 ✓。U2 的 0.3260 与 0.522 的差额 0.196 若**全部**记在 8 个答案行上，需要每行省
   0.196×255/8 = **6.26 nats**，超过答案行的最大可省量 ln64 = 4.16 ⇒ **不可能**，说明收益
   不止来自答案行：**提问键行也变可预测了**（答案行 CE 实测只降了 4.1589−1.4772 = 2.68
   nats，占 8×2.68/255 = 0.084，其余 ~0.11 来自提问键/其他行）⇒ 与 `slot_score_mass` 22.1
   的强读出量一致 ✓（这条给出**上界式**对账：单靠答案行解释不了观察到的 loss 下降）。
2. **任务对账**。三个臂评的是**同一个任务定义、同一批任务批（同 seed）、同一位置集、
   同一窗口掩码**（`accuracy(..., keep_mask=window_anchor_keep_mask(T,16,0))`）。毁源臂只把
   源内容替换成同分布随机符号，其余逐位不变。**没有「假上下文 + 真目标」式对照**。
3. **口径对账**。所有准确率都是 12k 步快照的训练结果、评测用**训练同款掩码**、批大小与批数
   三臂一致（bs=64 × 64 批 = 4096 查询）；训练 loss 斜率三臂**同方法**（同窗对数步数区段
   200–12000、同 log-log 线性拟合）。**bpc 未用作判据**。

### 7.2 失败决策树执行记录（测量 → 实现 → 规模 → 设计）

- **测量**：先做判据①（前提校验）⇒ 过（§1）。窗口活性量 `window_mask_probe` 的
  `max|Δlogit| = 2.106155 > 0`（掩码真的在起作用）；查询-key 距离 241–255、100% 窗外。
- **实现**：变异验证 7 处**全部抓红且逐字节还原**（`mutation_report.json`）；其中「把因果
  掩码放宽一格（位置 t 读到 t+1 的写入）」= **未来泄漏**必须抓红（M1 ✓）、「去掉自写入」
  （M2 ✓）、「delta 退化成 plain」（M3 ✓）、「单边零起步被破坏」（M4 ✓）、「读出被摘掉」
  （M5 ✓）、「CLI 没接线」（M6 ✓）、「训练任务 gap 变小 ⇒ 局部可抄」（M7 ✓）。
- **规模/不稳定**（本批**新发现**）：**plain 臂双稳态**。两次同配置同 seed 训练：正式 U1
  答案行 CE 末值 **4.184**（≈ 瞎猜 4.1589）、评测准确率 **0.0732%**；重跑臂 U1rep 答案行 CE
  **2.2524**、准确率 **3.3447%**。两臂同代码同数据流（首批 loss 都是 4.7499，step ≤2400
  差异仅 ~3e-4/步），在 step ~3000–4000 分岔 ⇒ **「学不学得动」是训练侧临界现象**。
  **处置**：① 主判据②不受影响（U0 三次都没学到，U2 一次就学到 1.4772）；
  ② 判据③用**两支 plain 都过一遍**：正式臂 +9.42pp、重跑臂 **+6.15pp**，两次都 ≥3pp 且
  CI 不重叠 ⇒ **判据③在最有利于 plain 的读数下仍成立**；③ 但「delta 规则本质更优」这类
  强表述仍**不作为结论**（n=1/规则 × 2 支）。已记入 `stability.md` §3 与 `divergence.json`。
- **设计**：不适用——U2 的收益过了毁源对照臂（不是位置/局部先验伪命中）。

## 9. 残差风险与不确定项

1. **plain 臂双稳态**（最重要）：判据③在两支 plain 读数（正式 +9.42pp / 重跑 +6.15pp）下
   都成立，但**每支都只是 n=1**；要分离「规则效应」与「学习不稳定」仍需多 seed + 预登记的
   「学习成功判据」（例如答案行 CE < ln64 − 0.5）。
2. **单共享槽 = 显式实现决策**：写入表达力弱于 per-layer（见 §4）；结论只对该形态成立。
3. **只跑了 1 个种子/臂**（除重跑散度），准确率的**跨种子**散布未测；判据②的效应
   （+8.13pp）远大于评测噪声（同 seed 复现差 0.0），但训练侧散布未知。
4. **距离腿曲线不单调**（§6.3），受训练分布位置结构混杂；只描述形状，不外推。
5. **绝对水平低**（9.5%）：这是 13M / 12k 步 / 单状态的小规模读数，按 SCHEMA §19
   **不得**读成「业界做不到」或「做到也就这么点」。
6. **既有做法全部为「记忆·未核」**（本环境无 web 工具）：只作设计方向，不作判据。
