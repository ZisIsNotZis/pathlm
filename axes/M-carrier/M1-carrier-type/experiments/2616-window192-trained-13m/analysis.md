## 1. 人话摘要（先看这一段）

**要回答的问题**：把模型的「可见历史」砍成有限的窗口（只看最近 N 个字符），
**砍到 N=192 时，质量还掉不掉？**

上一批（ticket 32-O）已经测过 N=32：那样训练出来的模型，质量比「什么都能看」的普通
模型差 **0.0866 bpc**（每字符比特数，越低越好；1.4836 → 1.5701）。但同一个天平也告诉
我们：**不重训**、直接把一个普通的全注意力模型在评测时限制到「最近 192」，
代价只有 **+0.004 bpc**；限制到 128 是 +0.020、64 是 +0.081。于是有了这个问题：
**窗口长度是不是一条带悬崖的杠杆？换成 192，训练税能不能压到 ≈0？**

**做法**：同一个 13.5M 的小变压器，用和 32-O 逐字段相同的配方再训一次（12000 步、
批 32、序列 256、seed 0），唯一改动 = 训练时每个字符只看「最近 192 个位置 + 开头 8 个
锚点」；对照 = 仓库里已有的全注意力主干（复用，不重训），并用同一件天平在**同一批**
评测窗口上量。

**三句话结论**：

1. **主判据过了，而且是本批少见的正面结论**：窗口 192 训练出来的模型，在它自己的
   工作点上 clean bpc = **1.480756**，对照 = **1.483569** ⇒ **税 = −0.0028 bpc**（负数
   = 略好，量级在噪声内）。预登记门槛「税 ≤ 0.014 ⇒ 有界内存可近零代价」**成立**。
   同配置重跑一遍得到 **+0.0007 bpc**——两次都在 ±0.004 内 ⇒ 这个「≈0」是稳的。
2. **但这个「免费」有明确的边界，不是「窗口训练很神」**：把同一个有限预算套在
   **没重训**的全注意力模型上，代价也只有 **+0.0029 bpc**（同一族掩码、同一批窗口）。
   也就是说，192 这个预算砍掉的只是 **4.85% 的可见性对数**（256 个位置只丢 56 个），
   本来就几乎不疼——**这一档没有头寸可赚**。作为对照，32 那一档：不重训的代价是
   **+0.1495**，训练后压到 **+0.0866**，即训练**补回了 42%**。所以「窗口训练」的价值
   在砍得狠的时候才出现，而不在 192。
3. **窗口放宽后，窗口外的针仍然只是「丢了」**：把一段真实文本短语埋在窗口外再问它，
   window192 在整桶「窗口外」针上的召回 **0.475954**，同掩码、同一批针但不植入内容的
   「无记忆地板」是 **0.444444**（差 +3.2pp < 预登记的 10pp 门槛）⇒ 记「丢了」。
   把这个桶拆开看更干净：**尾部还有 1~6 个字符落在窗口内的那 109 根**（可以从可见的
   尾巴推断）差 +17.4pp；**整段（7 个字符）都在窗口外的 494 根差恰好 0.000**
   （0.457490 vs 0.457490）。整桶的
   +3.2pp 完全由前者造成（加权平均自洽）⇒ **没有「信息被搬到近处」的证据**。
   同一批针在**窗口内**的召回是 0.719263 vs 地板 0.437186（+28.2pp）⇒ 仪器能测出
   「记忆存在」时的信号，所以「窗口外 = 0」是真读数，不是仪器失灵。

**必须写在最前面的两条限制**（否则容易被误读）：

- **训练侧只有两个直接测得的点（32 与 192），不得内插也不得外推**。我们**不能**因此
  说「税在 64/128 是多少」，也**不能**说「窗口长度是一条平滑/带悬崖的曲线」——
  那两次比较分别只给出「这一档贵/不贵」两个事实（SCHEMA §17.11）。
- 192 这一档的「近零代价」**不是因为训练变强**，而是因为**它本来就不疼**（不重训也
  +0.0029）。真正的「训练把税补回来」只在 32 那一档被直接测到（0.1495 → 0.0866）。

## 2. 六问（面向用户，逐问回答）

1. **它是干什么的**：让模型在推理时只依赖最近的一小段历史（滑动窗口 / ring-buffer KV），
   从而把 KV 内存与注意力开销钉在上界上，而不随上下文长度增长。
2. **相对普通的 decoder-only transformer 改了什么**：**结构、参数量一点没改**
   （13,536,768 参数，两臂逐位相同；掩码不引入任何参数）。唯一改动是**训练时的注意力
   可见集**：每个字符只允许看「距离 < 192 的位置」以及「最前面 8 个锚点位置」，
   其余键在训练前向里被掩掉（`keep[i,j] = (j≤i) ∧ ((i−j)<192 ∨ j<8)`）。
   计算量的额外开销 = 多一个 bool 掩码：实测步时 **42.1 ms vs 40.1 ms = 1.05×**。
3. **为什么要改**：如果「只看近处」的质量代价接近 0，那么长上下文的内存/墙钟开销可以
   被砍掉而不付质量代价（A9/A10 两条线的前提）。32-O 已经证明 32 太狠；本实验回答
   「放到 192 是否就免费」。
4. **怎么测的**：两臂跑同一件天平——① 依赖腿：在同一批评测窗口上删除指定位置的 KV
   （距离曲线 / 左前缀曲线 / 只留最近 d 曲线 / **同族锚点预算曲线**），测 bpc 损伤；
   ② 检索腿：在 256 长的窗口里植入 8 根真实文本「针」，看答案行能否答对，
   分母分桶（锚点 / 窗口内 / **窗口外**），并与「不植入内容」的同掩码地板配对比较。
   对照 = `full` 臂（同配方、全可见、复用 2610 的 `trunk.pt`，sha256 断言）。
   指标 = clean bpc（每字符比特数，越低越好）；口径 = 快照（matched-step 12k）+ 各自
   工作点（native，= 它推理时真正用的可见集）。
5. **测出来多少**（**数字 + 参照系 + 人话量级**）：
   - 质量税（native 口径）：**1.4836 → 1.4808，税 −0.0028 bpc**；参照系 = 同尺寸同配方
     全注意力主干；方差界 0.014 ⇒ 「没有可分辨的差异」。重跑臂 +0.0007 ⇒ 两次都 ≈0。
   - 作为量级感：32-O 的 32 窗口税 **+0.0866**，是本实验的 30 倍以上。
   - 预算对齐（同一族掩码、同一批窗口，不重训）：192 → 丢 4.85% 可见性对，代价 +0.0029；
     128 → 丢 22.07%，代价 +0.0147；64 → 丢 51.74%，代价 +0.0596；32 → 丢 71.24%，
     代价 +0.1495。⇒ **代价跟着「砍掉多少可见性对」走，而不是跟着窗口数字走**。
   - 内存（解析口径，必须与实测分开）：每行 KV 位置 256 → 200，**−21.9%**；
     实测显存**不下降**（本仪器仍是 dense SDPA + bool 掩码，照算整张 256×256 分数矩阵）
     ⇒ 真正的省要在部署侧实现 ring-buffer KV，本实验不主张实测显存收益。
6. **结论与下一步**：**在 192 这一档，「有界内存可近零代价」成立**（判据①过），
   但原因是没有头寸（不重训也几乎免费），而不是训练换来的；32 那一档训练确实把税从
   0.1495 补到 0.0866（补回 42%），但税仍然显著。**下一步**（属主 Agent 的产品决策，
   本实验只给数据）：若要继续压内存，要么在 192 与 32 之间**直接测** 64/128 两个新点
   （禁止内插），要么换机制（显式摘要/压缩写入，而不是靠注意力掩码「逼」出局部依赖），
   要么接受 32 档的税并把它算进价签。

## 4. 判据达成（逐条，判据线未改）

| 判据 | 预登记门槛（契约 Q 逐字） | 实测 | 判定 |
|---|---|---|---|
| ① 质量税 | 税 ≤ **0.014** ⇒ 近零代价成立；税 ≥ **+0.050** ⇒ 悬崖在 192 以下 | 税 = **−0.002813**（1.483569 → 1.480756） | ✅ **近零代价成立**（且为负，量级在噪声内） |
| ② 曲线定位 | 已有 4 个 `recent:32/64/128/192` 评测期点 + 本次训练点 → 2 个训练点，标「不得外推内插」 | 见 §5.3；训练点 = 32 → +0.086566、192 → −0.002813，**标注已写** | ✅ 表已给、标注已写 |
| ③ 保留（窗口外针） | 与 32 的结果对照，验证「窗口外的针是否仍然只是丢了」 | 整桶 0.475954 vs 地板 0.444444 = **+0.031510 < 0.10** ⇒ 丢了；**完全不可见子桶 gap = 0.000** | ✅ **仍然是「丢了」** |

**判据①的口径说明**：bpc 取**各自工作点**（native）——`full` = 全可见（它的原生配置），
`window192` = 训练掩码（最近 192 + 8 锚点）；这与 32-O 的判据①完全同口径，因此两个
训练点可直接并列。release 口径（全可见下评 window192 臂）也一并报：
**1.478378**，比 full 的 1.483569 好 **0.005190**（该口径对 window192 不是 OOD，
与 32-O 里 window32 的 release 口径差 0.137 的情形不同——因为 192 只砍掉 4.85% 的
可见性对，模型几乎仍见过全部键）。

**判据③的口径说明**：桶的归属由 `needle_fate` 依「短语 7 个位置**全部**可见」判定，
`beyond` = 至少一个位置落在窗口外 ⇒ 该桶**包含「短语横跨窗口边界」的针**（尾巴还可见）。
预登记规则用整桶（与 32-O 一致）；§5.4 另给「整段都在窗口外」的子桶作为**附加诊断**
（不参与判据）。

### 7.2 排查顺序与结论（methodology §14）

1. **测量问题** → 已排除：仪器自检（release == identity 逐位；训练掩码 == 评测掩码
   逐位、max\|Δlogit\| = 0.0；行均值 == token 均值 7/7）、同 seed 重跑 3.65e-07、
   与 2614 记录 max\|Δ\| = 0.0、针构造基线逐位复现契约 M。
2. **实现问题** → 已排除：3 条真实尺度单测全绿；变异验证 **6/6 抓红**（删锚点项 /
   窗口 off-by-one / **把窗口夹到 32** / forward 不传掩码 / 锚点取在末端 /
   forward 侧漏锚点），破坏后逐字节还原（sha256 一致）。其中「把 window 夹到 32」
   这一条正是本实验的命门（干预真的生效），被
   `test_window192_keep_mask_counts_and_boundary_at_real_scale` 与
   `test_window192_forward_matches_eval_mask_and_differs_from_32` 抓红。
3. **规模问题** → **部分成立并已登记**：13M / 256 上下文下，192 这个预算**太宽**
   （只砍 4.85% 的可见性对），所以「近零代价」里没有多少训练可贡献的部分；
   「训练能把税补回来」只在 32 档被直接测到（补回 42%，但税仍 0.0866）。
4. **设计问题** → 在本次数据范围内：**「把窗口放到 192 就能免费」成立**，
   但**「窗口长度是不是一条带悬崖的杠杆」本批无法判定**（只有两个训练点，
   禁止内插外推）。
5. **口径/判据问题** → 判据线与执行前一致（逐字抄录，未改一字）；额外给的
   「完全不可见子桶」只是**附加诊断**，不参与判据。

## 8. 残余风险与未完成项

1. **只有两个训练点**（32 与 192）：不能判定悬崖形状/位置，也不能给出 64/128 的税。
   这是契约 Q 的范围（预算 15–25 min），**不是遗漏**。
2. **训练侧不可逐位复现**（项目级已知事实）：本实验用整条 12k 重跑给出量级
   （native 口径 0.003486、release 0.003398，均 < 方差界 0.014）。判据①的两个读数
   （−0.0028 / +0.0007）都在该量级内 ⇒ 「∈ 噪声带、近零」是正确读数，
   **不能**用它反推「window192 真的比 full 好」。
3. **未跑 2×（24k）点**（SCHEMA §16）：契约固定 12k 步。两臂同方法斜率已给（§6.3），
   末 25% 两臂都平且几乎重合 ⇒ 快照结论；更长训练是否改变「税 ≈0」未测。
4. **判据③的 beyond 桶天然混入「横跨边界」的针**（109/603）：已用附加诊断拆开
   （整段在外 = gap 0.000）；32-O 的记录里没有这个拆分，所以两档的**整桶**数字可比，
   **子桶**不可比（32 档的横跨比例不同）。
5. **「省内存」只有解析口径**：本仪器（dense SDPA + bool 掩码）**实测显存不下降**；
   ring-buffer KV 的真实收益需要部署侧实现后另测。同理，注意力对数只降 4.85%，
   **不主张算力收益**。
6. **判据①的口径依赖「native 工作点」**：若改用 release 口径（全可见下评 window192），
   数字变成 +0.005190（full 更好）——两个口径都报了，主判据按契约用 native
   （与 32-O 一致）。
7. **本实验未改任何实现**（`pathlm/depth_ar.py`、`train_depth_ar.py` 指纹与 2615 记录
   逐字节相同）——契约 Q 授权改它们，但「窗口长度是参数」的既有实现已覆盖 192，
   所以没有改动即最诚实的选择（新加的 3 条单测落在授权文件 `tests/test_depth_ar.py`）。
8. **本实验未撤回任何先前结论**。需要登记的「口径发现」只有一条：
   window192 的 **release 口径不是 OOD**（1.478378 vs native 1.480756，差 0.002378），
   与 32-O 的 window32（差 0.137232）形成对照——原因 = 192 档只砍掉 4.85% 的可见性对。

### 9.1 省算力侧的核算（SCHEMA §17.9：成本交叉点）

本干预在**推理期不引入任何新算子**（同架构、同参数量）；它的「省」来自**可见集变小**：
放行的因果对 = 31300 / 32896 = **95.15%**（只砍掉 4.85%）。⇒ 不存在「理论降幅大、实测
反而变慢」的回退问题（没有离开 SDPA 融合核的新算子，只是多传一个 bool 掩码）。
**唯一的成本在训练期**：步时 42.1 vs 40.1 ms = **1.05×**（一次性）。

**成本交叉点**：部署侧要真正回本，必须把窗口外的 KV 丢掉（ring-buffer）：每行 KV 位置
256 → 200（**−21.9%**），注意力对数 −4.85%（T=256 固定）。⇒ 在**任何** T 上，
只要部署侧实现了 ring-buffer，就是**严格更省**（省的比例随 T 增大而增大：
窗口外位置占比 = 1 − 200/T）；而本仪器（dense + 掩码）**实测不省**（194.7 MiB 不变）。
**回本点因此不在序列长度上，而在「有没有实现 ring-buffer」上**——这是与 31-J
（内容 top-k：理论省、实测反而慢 2.2×）的关键区别。

### 9.2 「省内存」：解析 vs 实测（契约纪律）

| 口径 | 数字 | 说明 |
|---|---|---|
| 解析（KV 位置/行） | 256 → 200（**−21.9%**） | 滑动窗口部署只保留最近 192 + 8 锚点 |
| 解析（注意力可见对） | 32896 → 31300（**−4.85%**） | 只在因果三角内计数 |
