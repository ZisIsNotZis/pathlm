# 2635 · 判读：递推/线性状态载体（把注意力换成递推状态）——**没有拿到质量读数**

> 契约：同目录 `README.md`（§4 判据线预登记，未改一字）。原始结果：`results.json`、

> **快照口径**：enwik8 真实文本、13M 稠密主干、3,000 步（24.6M token）/臂、全因果（无窗口）。

## 0. 人话摘要（先看这段）

**想做什么**：把主干里的**注意力算子整个换掉**，改成一个「固定大小的递推状态」——每个位置
只把自己的信息加进状态，下一个位置直接读状态（这是 SSM / Mamba / RWKV / 线性注意力那一族
的核心想法），状态大小与序列长度**无关**。这格此前只有**成本数据、没有质量数据**（唯一一次
尝试因训练期「卡死」被判定不可行）。

**这次的结果：仍然没有拿到质量读数——但原因被查清了，而且**不是**「进程卡死」。**

- 预登记判据①（可跑性：日志每 200 步推进）**不通过**：日志在 **step 1000** 之后不再增长，
  停摆门（≥180 s 无新步）据此触发，全线程栈落在 `train_depth_ar.py::train → loss.backward()
  → torch/autograd/graph.py::_run_backward`（**与 2616 记录的签名完全一致**）。
- **但训练器自己的计数说明了真相**：`grad_skips = 1854`、有效优化步 = `1146`，
  **1854 + 1146 = 3000 = 配置步数**（对账通过），训练墙钟 4.43 min ≈ 3000 × 88 ms/step。
  ⇒ **进程把 3000 步全跑完了**并落盘了 `model.pt` / `results.json`。
  日志为什么停写？因为**训练器只在「未被梯度门跳过的步」写日志**——数值发散后绝大多数步
  都被「梯度范数 > 1e4 或非有限 ⇒ 跳过」拦掉了，于是**看起来像卡死，其实在烧步**。
- **真实的故障是数值发散**：归一化分母触到下限（`den_min = 1e-6`）、状态范数涨到 **476**、
  梯度范数最大 **5.7e8**、均值 **1.1e6**（对照 stock 臂：0.81 均值 / 9.87 最大 / **0 次跳过**）。
- **质量读数（只能当参考）**：3,000 步 matched-step 的 clean bpc：stock **1.7704** vs
  linear **5.9238**（+4.15 bpc）——但这是**发散步**的数字，**不能**读成「线性载体质量差」。
- **活性**：算子的**反事实**证据是活的（同权重把算子换回全注意力，输出相对偏差均值 0.211、
  最小 0.018；块间状态质量占比 0.376），但**数值前提**不成立（`phi_min` 在 fp32 下触到 0、
  `den_min = 2.1e-5`）⇒ 按预登记口径判据③也不通过，且原因是发散而非「开关没接上」。
- **给 2616 的那次判定的修正（重要）**：2616 把同一症状读作「实现层停摆」并据此判
  「当前实装不可行」。本实验给出**更精确的诊断**：**「日志停写」不等于「进程停摆」**——
  这个训练器在梯度跳过时不写日志，所以「日志冻住 + CPU 在烧」这一对观测**也可能**是
  「数值发散后在原地烧步」。2616 的进程被提前终止、没有终点产物，因此**不能**凭本实验改写
  它的结论；但**它当时的停机判据与本次相同**，所以「2616 的停摆至少部分是日志停写的假象」
  是一个**待复核假设**（复核方式见 §10）。

**一句话**：递推/线性载体在 13M/3k 步下**数值发散**（62% 的步被梯度门跳过），因此**本格仍
只有成本与诊断、没有质量结论**；但诊断比上一轮精确了一步——**「卡死」是仪器假象，
「发散」是真的**。

## 1. 六个必答问题

1. **它是干什么的**：把注意力（每个位置去「看」前面所有位置、算力/缓存随长度平方增长）换成
   **固定大小的递推状态**（每层每头一个 `dh×dh` 矩阵，逐位置累加写入、逐位置读出），
   使每层的时间与显存对长度**线性**、推理缓存**与长度无关**。
2. **相对普通 decoder-only transformer 改了什么**：唯一变量 = 注意力算子。stock 臂 =
   `out_i = Σ_j softmax(q_i·k_j/√dh)·v_j`（走 SDPA 融合核）；linear 臂 = 归一化线性核
   `out_i = Σ_{j≤i} φ(q_i)·φ(k_j)·v_j / Σ_{j≤i} φ(q_i)·φ(k_j)`，φ = elu+1，
   用**累积状态**实装（不物化 T×T 分数矩阵）。**参数量逐位相同**（13,536,768，引擎单测钉住）。
3. **为什么要改**：长上下文时代最主流的三条省算力路线之一（另两条：稀疏注意力、显式记忆）。
   本格问的是**载体类型**里的「递归状态（SSM/RNN）」这一族在**我们这套装置**上能不能站住。
4. **怎么测的**：两臂（stock / linear）同配方、同数据（enwik8）、同 seed、**同步数 3,000**
   （为什么是 3k：2616 的二分显示 1.2k–3k 步的独立进程全部跑通；≥6k 的 12k 运行有 ~1/2 停摆）。
   指标 = clean bpc（全因果）+ 四任务长程电池（侧腿）+ 算子活性/反事实。工程门 = 停摆门
   （`stall_gate.py`：`PATHLM_DUMP_STACKS=150` + 两级「无日志推进」信号）。
5. **测出来多少**：bpc stock **1.7704** / linear **5.9238**（**发散步**，见 §4）；停摆门触发步
   **1000**、`grad_skips` **1854/3000**、`gnorm_max` **5.7e8**、`den_min` **1e-6**、
   `state_norm` **476**。参照系：同尺寸 stock 臂 `gnorm` 均值 0.81、最大 9.87、**0 次跳过**。
6. **结论与下一步**：见 §8/§10。

## 3. 停摆诊断（任务要求的「栈 / 触发步 / 诊断二分」）

**观测链（原始证据在 `stall_report_linear.json` 与 `train_linear.log`；再分析与口径对齐见
`stall_reanalysis.py` → `stall_report_linear_v2.json`）**：

1. `train_log.jsonl` 的末条是 `step 1000`（mtime 冻结）；
2. faulthandler（`PATHLM_DUMP_STACKS=150`）周期性打出的全线程栈：
   `Timeout (0:02:30)! … train_depth_ar.py:306 in train → torch/_tensor.py:623 backward →
   torch/autograd/graph.py:1072 _engine_run_backward`（**卡在反向内部**，与 2616 同签名）；
3. 停摆门在「≥180 s 无新步」时记 `no_log_progress`、超过 `kill_secs` 才终止
   （**本实验用的初版门在 180 s 就终止了**——见 §3.2 的修正）；
4. **训练器计数**：`gnorm_monitor.grad_skips = 1854`、`attn_linear_layer_samples = 13752`
   ⇒ 有效步 = 13752 / 12 层 = **1146**；**1854 + 1146 = 3000 = 配置步数**（对账通过）；
5. `model.pt` 与 `results.json` 都在训练结束后落盘（wall 4.43 min ≈ 3000 × 88 ms/step）。

**诊断二分（把三种解释逐一排除）**：

| 解释 | 判定 | 依据 |
|---|---|---|
| (a) 进程停摆/死锁 | **排除** | 步数对账 3000 通过；墙钟与步时一致；终点产物齐全 |
| (b) OOM / 崩溃 | **排除** | 无异常栈（栈是 faulthandler 的超时转储，不是 traceback）；峰值 2139.7 MB ≪ 24 GB |
| (c) **数值发散 + 日志假象** | **采信** | `den_min` 触到 1e-6、`gnorm_max` 5.7e8、`grad_skips` 62% 的步、日志只在未跳过的步写 |

**§3.1.1 旧报告里的两个字段被重新利用（复核 P2-3）**：
- `cpu_delta_10s = 0.0`（采集前 10 s 内该进程 CPU 时间**没有增长**）——这是「**不是** 2616
  观测到的『~98% 单核持续烧却卡死』」的**正面证据**，与「进程已在收尾/已结束」一致；
  旧报告当时没有把它用于判定。
- `status = "stalled"` 是**旧版门**（180 s 即终止）的字样，当前 `stall_gate.py` 根本产不出该
  状态（两级：`no_log_progress` / `killed_after_no_log_progress`）⇒ 原始报告**不改写**，
  由 `stall_report_linear_v2.json` 逐字段对照并给出「按当前门同一份日志会记 `finished`」。

**§3.2 门的修正（已实现 + 单测钉住）**：`stall_gate.py` 改为**两级**——
`--stall-secs`（缺省 180）只**记事件**（`no_log_progress`，非致命），
`--kill-secs`（缺省 900）才终止；并新增单测
`test_stall_gate_does_not_kill_log_frozen_but_finishing_run`（日志冻住但进程能自己结束 ⇒
必须记 `finished`，不得误杀）。本实验线性臂当时用的是**初版门**（180 s 即终止），
原始报告保留为 `stall_report_linear.json`（`status="stalled"`）——它是**当时的原始证据**，
不做改写；修正后的口径写在本节与脚本 docstring 里。

## 4. 质量腿（**只能作发散步参考**）

口径：`retention.masked_bpc(keep_mask=None, 96×16, window_seed=2)`（全因果），matched-step 3,000 步。

| 臂 | clean bpc | 训练末 loss（nat/token） | loss 斜率（200→3000 步，nat/1k 步） | `gnorm` 均值 / 最大 / 跳过步 |
|---|---:|---:|---:|---|
| `stock` | **1.770396** | 1.2154 | −0.2822 | 0.814 / 9.87 / **0** |
| `linear` | **5.923848** | 2.0702（末次日志 = step 1000） | −0.1306 | **1.1e6 / 5.7e8 / 1854** |

- `Δbpc = bpc_stock − bpc_linear = **−4.15**`（负 = 线性臂**更差**）。

- 单点、无方差界（只在 seed 0 上跑一次）⇒ 连「不可分辨」都称不上（§9.3）。

## 8. 结论（M1 视角；「该族可不可行」的家在 A6/2637）

1. **本格仍没有「线性载体的质量」结论**：这次拿到的是一个**发散步**（62% 的步被梯度门跳过、
   `gnorm` 冲到 1e8 量级），不是可读的质量腿。**该实现该配置下的结论是「不可训练（数值
   发散）」**——不是「线性载体质量差」，也不是「这一族不可行」（后者属 A 轴
   `2637-linear-attn-quality` 的判据）。
2. **诊断结论（本实验的主要产出）**：
   - 真实故障 = **归一化线性注意力的数值发散**（分母塌陷 → 梯度爆炸 → 梯度门拦截绝大多数步）；
   - **「日志停写」不等于「进程停摆」**：训练器只在未跳过的步写日志，因此在发散步上
     「日志冻住 + CPU 在烧」是**必然**现象；本实验的步数对账（1854 + 1146 = 3000）与
     终点产物证明进程跑完了全部步。
   - 这一条**修正了本格的表述**：「实现层停摆」应改为「**该实现在该配置下不可训练（数值
     发散）**」；与之配套的仪器修正（两级门 + 不误杀单测）已经落地。
3. **要让它可跑需要什么**（候选，均属**新干预**、需新契约）：
   ① 去掉归一化分母（RWKV/衰减型递推：`S_t = a_t ⊙ S_{t−1} + b_t ⊙ (v kᵀ)`，无分母可塌）；
   ② 换特征映射（cosformer / 特征归一化，避免 `den → 0`）；
   ③ 更保守的数值配方（更小的 lr、`grad_clip` 更严、bf16→fp32 状态更新、warmup 更长）。
   **成本量级**：每候选 2 臂 × 3k 步 ≈ **10 min GPU**（本实验实测 stock 2.12 min / linear 6.36 min
   / 3k 步）；若要在 12k 步上拿结论，需先证明该配方在 3k 步上不发散。

## 9. scope 与能力面限制（含与 A6/2637 的分工）

- 「**窗口 + 线性载体**」这个最贴近本格搬运问题的组合**现在不可测**：引擎硬互斥
  `attn_linear ⊕ train_window`（构造期校验，`tests/test_recursive_carrier_13m.py` 钉住）。
  ⇒ 本实验只测了「全可见下把注意力换成递推状态」这一忠实子问题，**不得**外推。
- 结论只适用于：**enwik8 / 13M / 3,000 步快照 / 全因果 / φ = elu+1 的归一化线性核**。
- **分工（避免两处事实）**：本实验只提供 M1 视角的三件事——「窗口 + 线性载体」因引擎硬互斥
  **不可测**、该快照**拿不到**质量读数（发散步）、以及**诊断与可复用教训**。
  「线性注意力这一族可不可行」的权威叙事在 A 轴
  （`axes/A-mixing/A6-mixing-operator/`，续作 `2637-linear-attn-quality`）——本文件不重复
