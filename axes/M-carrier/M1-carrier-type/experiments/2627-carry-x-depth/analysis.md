# 分析 · 2627-carry-x-depth（delta 搬运通道 × dense 全深度监督，13M）

## 人话摘要

**想解决什么**：我们手上有两个各自单独测过、都好看的本事——一个是给模型装一条「显式小本本」
（delta 搬运通道），让它能把训练窗口外的信息记住并在提问处取出来；另一个是让模型「每一层都能
答题」（dense 全深度监督），于是能用浅层当草稿加速。问题是：**这两样东西装在同一副骨架（13M
变压器）上，会不会打架？** 这是它们第一次一起上机。

**怎么测的**：把两个开关排成 2×2 四格（都不开 / 只开搬运 / 只开浅层监督 / 两个都开），同数据、
同步数、同随机种子，唯一差别就是这两个开关。任务是「随机键值关联回忆」——把 8 对随机 (键,值)
放在最前面，把可见窗口裁到最近 16 个位置，于是**不看小本本就必须靠猜**（猜中率 1/64 ≈ 1.6%）。

**测出来多少**：
- **搬运通道一开，成绩从 1.48% 跳到 35.78%**（近 24 倍；两者置信区间完全不重叠）。这就是它的
  老本事，在本设置下复现。
- **只开浅层监督（不装通道）**：成绩还是 1.47% —— 与不开没区别（差 0.006 个百分点，落在噪声里）。
  因为它没有小本本可翻，浅层监督帮不上这个任务。
- **两个都开**：36.16%——比「只有通道」的 35.78% 高 0.38 个百分点（置信区间仍重叠 ⇒ **统计上分不开**）。
- **可叠加性**：交互项 = +0.38 个百分点，落在 ±1.4pp 的预登记阈值带内 ⇒ 在**召回**这个目标上，
  两样东西**可加、不打架**（契约判据⑤的「负增量」没有触发）。
- **出口资产（浅层草稿能不能用）**：只开浅层监督时，浅层出口与全栈的一致率从 87.84% 抬到
  **99.84%**；两个都开时是 94.47%——**通道在开会轻微吃掉一点出口资产**（−5.4pp），但它们都远
  高于基线的 87.84%。

**代价**：浅层监督会让模型在真实英文文本（enwik8，且这些模型从没在真实文本上训练过）上的
字符级困惑代价大幅恶化（55.07 → 125.74 bpc），两个都开更差（1322.98）——这是**分布外**的
质量读数，只作方向性警告（见 §5.3）。

**一句话结论**：**搬运通道与浅层监督在「把信息搬过去」这件事上互不干扰（可加）；代价是浅层
监督本身会牺牲真实文本上的质量，并且在被搬运通道压着时出口资产会被吃掉一小块。**

## 2. 能力面与契约偏离（先读这一节）

契约字面的 `carry × per-token depth(随机退出)` **在引擎里不存在**：carry 硬要求 `dense=True`，
而 dense 主干**忽略** `exit_depths`（随机退出只在非 dense 的 ragged 路径成立，那条路径拒绝
carry）。ENG1 解除的是 `GQA × carry × window`，不包含这一对。**主 Agent 裁决（2026-10-06）**：
深度因子改用 dense 兼容的 `--dense-aux`（dense 全深度并行监督）。完整能力面分析见
`README.md §4b/§4c`。「ragged 随机退出 + proj-fill」（产出 100M `tf@4=0.9726` 的真配方）是
**显式未测因子**，**禁止外推**。

## 5. 判读

### 5.1 主判据：训练分布内多查询召回（距离 107–240 ≤ 240，n=16384/臂）

| 臂 | 命中 | 准确率 | Wilson 95% CI | chance | 局部先验 | 毁源后 |
|---|---|---|---|---|---|---|
| `base` | 242 | 1.48% | [1.30, 1.67] | 1.56% | 1.37% | 1.48% |
| `carry` | 5862 | **35.78%** | [35.05, 36.52] | 1.56% | 1.37% | 1.70% |
| `depth` | 241 | 1.47% | [1.30, 1.67] | 1.56% | 1.37% | 1.47% |
| `both` | 5924 | **36.16%** | [35.42, 36.90] | 1.56% | 1.37% | 1.71% |

- **`base` ≈ chance**（1.48% vs 1.56%；局部先验 1.37% ≈ chance）⇒ 任务确实「不搬就答不出」，
  前提校验通过。
- **`carry` − `base` = +34.30pp**，两 Wilson CI **不重叠**（p<1e-6）⇒ 搬运通道的正面资产复现。
- **`depth` − `base` = −0.006pp**，CI 重叠（p=0.96）⇒ 浅层监督对这条**无通道**的任务**无作用**
  （没有小本本，浅层监督无从发挥）。
- **`both` − `carry` = +0.378pp**，CI 重叠（p=0.48）⇒ 浅层监督**不伤**通道的召回。
- **交互项 = +0.385pp**，落在 ±1.4pp 预登记阈值带内 ⇒ **可加**（契约判据⑤的「负增量」未触发）。

**去伪影复算**（剔除 Q=K 最后一块的排除法伪影，距离 ≤223，n=14336/臂）：base 1.46% /
carry 26.60% / depth 1.44% / both 27.04%；交互项 **+0.46pp**——结论不变。

### 5.2 逐叠加步增量（判据③，§17.17 分量分解，pp）

| 分解项 | 定义 | 主判据腿（分布内） | 全因果 | 单查询（分布外，仅参照） |
|---|---|---|---|---|
| `carry@depth_off` | carry − base | **+34.30** | +34.65 | −1.12 |
| `depth@carry_off` | depth − base | **−0.006** | −0.012 | −0.10 |
| `carry@depth_on` | both − depth | **+34.69** | +34.11 | +14.89 |
| `depth@carry_on` | both − carry | **+0.378** | −0.549 | +15.92 |
| `interaction` | (both−carry)−(depth−base) | **+0.385** | −0.537 | +16.02 |
| `net_vs_base` | both − base | **+34.68** | +34.10 | +14.79 |

- 净和（+34.68）与任一单向增量都不同 ⇒ **只看净和会掩盖「depth 单独无用」**（§17.17 的分量分解）。
- 主判据腿的交互项 +0.385pp ≈ 0 ⇒ 两因子**可加**。
- 单查询腿（距离 241–255 > 训练上限 240）的 +16pp 交互项是**分布外读数**：§17.18 事故（该腿
  同配置重跑差 15×）表明这类腿**不可靠**，本实验**只登记为外推观察、不作判据**。

### 5.3 出口资产 tf@4 / tf@6（判据②）

| 臂 | tf@4（synth 分布内） | tf@6（synth） | tf@4（enwik8，跨分布） |
|---|---|---|---|
| `base` | 87.84% | 87.84% | 90.09% |
| `carry` | 88.53% | 89.85% | 87.51% |
| `depth` | **99.84%** | 99.90% | 20.73% |
| `both` | **94.47%** | 94.88% | 52.86% |

- **分布内口径（有意义）**：`depth`（浅层监督）把 tf@4 从 87.84% 抬到 **99.84%**（+12.0pp）——
  出口资产确实被造出来了。装通道后回落一点到 94.47%（`depth@carry_on` 仅 +5.94pp；
  tf@4 交互项 **−6.06pp**）⇒ **通道在开时会吃掉一部分出口资产**（把读出的表达力分给了搬运），
  但 94.47% 仍远高于基线。
- **enwik8 口径（跨分布，不可比 100M）**：这些模型**只在合成任务上训练**，enwik8 是分布外；
  `depth` 臂的 tf@4(enwik8) 低到 20.73% 不是「出口坏了」，而是「浅层出口被训练成合成任务的
  预测器 ⇒ 在真实文本上必然与全栈分歧」。**100M 的 0.9726 是 enwik8 训练模型的 enwik8 读数，
  与本表不可比**（同家族、不同实现、不同分布）。
- **`carry` 因子的 tf@4 交互（分量分解，§17.17）**：在 depth 关时 carry 对 tf@4 近乎无影响
  （+0.69pp），在 depth 开时 −5.37pp ⇒ `both` 比「可加预测」低 6.06pp。**这是本实验里唯一
  稳定的负交互，但它落在「出口资产」腿上，不在召回判据上。**

### 5.4 质量代价项：clean bpc（enwik8 尾段，**跨分布**，非召回判据）

| 臂 | clean bpc | Δ vs base | 备注 |
|---|---|---|---|
| `base` | 55.07 | — | 合成训练 ⇒ 真实文本上本就差 |
| `carry` | 52.36 | −2.71 | 通道无显著伤害 |
| `depth` | 125.74 | **+70.67** | 浅层监督大幅恶化真实文本读数 |
| `both` | 1322.98 | **+1267.91** | 通道 × 浅层监督叠加恶化（交互 +1200 bpc） |

- 四臂 bpc 都 ≫ `log2(206)=7.69`（合成训练 ⇒ 真实文本上「非退化锚」极弱，**绝对水平不可解**）。
- **口径警告**：dense-aux 把最终深度 CE 的权重从 1/1 摊薄到 1/13 ⇒ 最终深度头分到的梯度少了，

  文本上有质量代价，且与通道叠加时更差**（与 ticket 23c H1 在同分布 enwik8 上 +0.108 bpc 的
  已知税方向一致，量级不可比）。

### P2-a · 「`train_<arm>.log` 不在 git」——经核为**误报**，未做改动

- 复核原文：`README.md §7` / `MODEL.md` 的派生产物表列了 `train_{base,carry,depth,both}.log`，
  而仓根 `.gitignore` 的 `*.log` 会匹配它们 ⇒ 断言「none are in git」。
- **实测（2026-10-06）**：这四个文件**是已跟踪文件**（`fb1e491` 提交时随本线入库；blob 在 `HEAD`）：

  ```bash
  $ git ls-files 'axes/M-carrier/M1-carrier-type/experiments/2627-carry-x-depth/train_*.log'
  axes/.../train_base.log  axes/.../train_both.log  axes/.../train_carry.log  axes/.../train_depth.log
  $ git check-ignore -v axes/.../train_base.log        # 退出码 1：.gitignore 不作用于已跟踪文件
  $ git ls-tree HEAD -- axes/.../train_base.log        # 100644 blob c7be78f8…  → 确在 HEAD
  ```

- `.gitignore` 只作用于**未跟踪**文件；已跟踪文件不受其影响。因此 `README.md §7` / `MODEL.md`
  的「（全部入库，不含权重）」声明**成立**，`train_<arm>.log` **保留**在派生产物清单里、**不删**
  （删掉反而会让清单与实际跟踪状态不符）。
- 结论：该项复核的**前提不成立**，**无需修正**；如实记录以备追溯。
