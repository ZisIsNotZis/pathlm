## 0. 人话摘要（先看这段）

**要回答的问题。** 上一批（U1）发现：给一个只看得见最近 **16 个位置**的小模型一块
固定大小的「速记板」，把要记的东西从 4 对加到 32 对，答对率会从 **54% 掉到 6%**
（这条成立）；但把**速记板本身做大 8 倍**，答对率一点没变（这条「不成立」）。
问题是：那四块板子当时只训了 **1 万步**、答案行的误差还在明显下降——**「板子做大没用」
会不会只是「训练还不够」？** 本实验把训练**翻倍到 2.4 万步**，只改板子大小
（每个头 **16 维 vs 128 维**，总状态 4,096 vs 32,768 个浮点，**×8**），先证明两条臂
都**接近平台**，再重判容量轴。

新名词就地解释：**answer-CE（答案行交叉熵）** 是「被问的那些位置上，模型对正确符号
的困惑度」，单位 nats，它是本任务里**唯一决定答对率的量**（总 loss 被大量已经学会的填充符
主导，几乎不动，因此用总 loss 判「有没有收敛」会**恒真**——这一条详见 §4①）；
**chance** 是瞎猜命中率 = 1/64 = **0.015625**。

**三句话结论：**

1. **收敛门禁过了。** 两条臂在最后 8,000 步里，answer-CE 的斜率分别是
   **−0.00696/1k 步**（板子 16）与 **−0.00545/1k 步**（板子 128），都 **< 0.01**
   ⇒ 已接近平台（这是判定容量轴的前提，见 §4①）。
2. **容量轴仍然无效——而且这次是「加固」，不是「没测出来」。** 在最关键的那一档
   （要记 8 对，= 训练同档）：板子 16 得 **0.3686**、板子 128 得 **0.3677**，
   差 **−0.093 个百分点**（置信区间完全重叠）；另外三档（4/16/32 对）差
   **−0.31 / +0.12 / −0.21 个百分点**，**全部不可分辨**。也就是说：
   **把板子做大 8 倍，准确率一动都不动。**
3. **上批唯一的「容量效应」被证伪为训练伪影。** U1 曾报：最容易的任务（4 对）上，
   **最大的板子反而明显更差**（0.4218 vs 0.5306，差 11 个百分点、置信区间不重叠）。
   跑满 2.4 万步后，板子 128 在 4 对上回到 **0.5267**（比 U1 高 **+10.49 个百分点**，
   区间不重叠），与板子 16 的 0.5298 只差 **−0.31 个百分点**。⇒ **那个「越大越差」
   是「训练不足」造成的，不是容量的代价。**

**为什么会这样、排除了哪些别的解释：**

- **不是「训练还不够」**：门禁过了（①），而且**把步数翻倍对准确率几乎没有影响**——
  8/16/32 对三档在 10k→24k 之间只动了 **−0.37 ~ +0.18 个百分点**（区间全重叠，§5）。
  唯一大动的是 U1 那个异常格子（+10.49pp，见上）。
- **不是「板子没用上」**：每 200 步落盘的读出占比从 step 0 的 **0.0**（读出增益零初始化
  ⇒ 起步逐位等于无板子）单调涨到 **0.38–0.47**；状态范数 0.18→1.84（16）/0.73→4.01（128）；
  反向探针（同权重关掉整条通道）偏差 **6.6%–11.6%**；12 格的**毁源对照全部掉回 chance**
  （0.0146–0.0169，作废格数 **0**）。⇒ 读数确实来自「搬过来的信息」。
- **不是「种子没接上」或「两臂其实一个模型」**：step 0 的 loss 三臂全等（4.7499）、
  主干张量**逐位相同**、注意力头恒为 8、状态浮点精确 ×8（`results.json::selfchecks`）。
- **不是「读数被训练抖动淹掉」**：同配置同 seed 的重跑臂（`S16_rep`）在 8 对上与 `S16` 差
  **+0.22 个百分点**、区间重叠（§4③.2）⇒ 训练侧散度**远小于**判据线 3pp。

**一句话结论：** 在 13.8M / 窗口 16 / 合成关联回忆这个设定下，**训练预算翻倍不会改变
容量结论**；准确率的瓶颈既不是状态宽度、也不是「1 万步不够」。
按 SCHEMA §19 的口径：这只能读作「**该任务/该尺度上，把状态宽度从 16 加到 128 不划算**」，
**不得**写成「容量不可能」——注意 answer-CE 仍在缓慢下降（1.5581 → 1.4149，−9.19%），
只是**没有转化成答对**。

## 1. 六问（按 `AGENTS.md` 的汇报纪律）

1. **它是干什么的**：给一个只看得见最近 16 个位置的模型一块**固定大小的可写速记板**，
   让它把更早看到、已经滑出窗口的信息写下来，之后还能读回来回答问题；本实验问的是
   **把这块板做大 8 倍、并把训练翻倍之后，它有没有变得更有用**。
2. **相对普通的 decoder-only transformer 改了什么**：在**输入流**上加**一条单共享记忆槽**
   （状态 `S ∈ R^{H_c×dh×dh}`，本实验 4,096 或 32,768 个浮点，**与序列长度无关**），
   每个位置按 **delta 规则**写一次
   `S ← S(I − β k̂k̂ᵀ) + β v k̂ᵀ = S + β(v − Sk̂)k̂ᵀ`（「只写板子上还没有的那部分」）；
   每一层再从板上读一次 `mem = S q`，乘一个可学的逐记忆槽头增益 γ 加到注意力输出上。
   **γ 零初始化 ⇒ 起步逐位等于无板子基线**；可学参数只多约 2.6 万（+0.02%）；
   **注意力路径完全不动**（头数 8、掩码、主干权重逐位相同）。
3. **为什么要改**：训练时窗口掩码把远处的键挡在外面（`train_window=16, train_anchors=0`），
   模型**不搬就答不出**；这块板就是「搬」的路径。U1 已经证明「难度曲线成立」但
   「容量曲线不成立」，且四臂**未收敛** ⇒ 本实验是那条结论的**收敛后复核**。
4. **怎么测的**：合成**多查询关联回忆**任务（`tools/evalkit/longrange_tasks.py::assoc_recall_multi_batch`，
   **不用 enwik8**）；训练与评测用**同一个**可见性掩码 `window_anchor_keep_mask(T,16,0)`；
   主判据用**准确率**（不是 bpc）；每格跑**毁源对照臂**；判据用 Wilson 二项 95% CI；
   另外跑一条**同 seed 重跑臂**量训练侧散度。
5. **测出来多少**：见 §0 与 §3–§5。参照系：chance = **0.015625**；
   8 对时板子 16 / 板子 128 分别是 **23.59× / 23.53× chance**。
6. **结论与下一步**：**容量轴在该尺度/该任务上仍不成立（加固）**，且上批唯一的容量效应
   （大板在 4 对上更差）被证伪为训练伪影。下一步不该再加大 `dh` 或加长训练，
   而应换**需求侧**（更难的 K、更长的序列、per-layer 记忆槽）或换**任务型**
   （复制/induction 已验证不同结论）。

**唯一变量** = 记忆槽状态宽度 `dh`；`S16_rep` 与 `S16` **逐字段完全相同**（只为量散度）。
注意力逐位不动（`results.json::selfchecks.structure_by_arm`，`attn_heads` 恒为 `[8]`、
`trunk_bitwise_equal_to_ref` 三臂全 `true`）。
参数量随 dh **有 ±0.03% 的差**（写门表 `beta_w` 形状随记忆槽头数变）——这是本实验的
**已知不等参数处**，如实记账（SCHEMA §15）：它远小于状态浮点的量级差（×8），
因此不会把「容量」误记成「参数」。
**取舍记账（SCHEMA §17.8）**：若改用 `n_heads` 来改 dh，会同时改注意力头维度 ⇒ 破单因素；
`carry_state_dim` 把两者解耦（既有开关，本轮**未改共享文件**），
单测 `test_carry_state_dim_decouples_state_from_attention_heads` 钉住、变异 M1/M2 抓红。

### 4.① 收敛门禁的三套口径（**这是本节最要紧的表**）

| 口径 | `S16` | `S128` | 是否作门禁 |
|---|---|---|---|

| U1 同方法 log-log 斜率（总 CE，窗口 [200,24000]） | −0.044098 | −0.030966 | 对照 |
| U1 同方法 log-log 斜率（答案行 CE，窗口 [200,24000]） | −0.215343 | −0.196213 | 对照 |

**为什么总 CE 不能当门禁（编排方指定必须写明的判读）**：用**U1 已落盘的 10k 日志**
按同一公式复算，四臂在末窗 [6000,10000] 的**总 CE** 斜率只有
**−0.00036 / −0.00046 / −0.00055 / −0.00050 per 1k**（相对下降 0.85–1.00%）——
**按契约字面（总 CE），U1 在 1 万步就已经「收敛」**，可 U1 自己报的是「未收敛」
（它用的是 log-log 口径 −0.065~−0.051）。同一窗口的**答案行 CE** 斜率是
**−0.032454 / −0.029842 / −0.026499 / −0.027561 per 1k**（相对下降 6.8–8.0%），
**远未收敛**（四臂的这四个数由 U1 已提交的 `train/<arm>/train_log.jsonl` 按本目录
`capacity_converged_lib.linear_window` 同一公式复算；其中 `D16`/`D128` 也落在
`results.json::convergence.u1_10k_reference` 里可机检）。⇒ **总 CE 口径在本任务上恒真、无区分度**（它被已经学会的填充符主导），
必须采信**答案行**口径——它是唯一决定准确率的量。这一条已写进 `README.md` §4①，
本实验的读数一致（总 CE 斜率 −0.000176 / −0.000122，答案行 −0.006963 / −0.005449）。

  ⇒ 把训练预算翻倍**没有改变**这个任务上的准确率。
- **唯一的例外正是 U1 的异常格**：U1 在 K=4 上测得「最大的板子反而差 11pp」
  （0.4218 vs 0.5306，CI 不重叠）；24k 之后它回到 0.5267（**+10.488pp**），
  与小板差 **−0.312pp**、CI 重叠。⇒ **U1 的那个「容量效应」是训练伪影**。
  **为什么不能归因给训练侧散度**（重要的排他论证）：如果是纯抖动，它应该在
  **同为 dh=16 的那一对**上也出现同样量级——实测 `dh16/K=4` 的 10k→24k 差只有
  **−0.078pp**；而同配置重跑（24k vs 24k）在四个档上的差也只有
  **+0.020 ~ +0.220pp**（`stability.md` §3.2）。一个 **+10.488pp** 的位移出现在
  **只改了状态宽度的那一臂**上、且方向是「变好」，最简解释就是**该臂前 10k 步还没从
  大状态的坏初始化里走出来**（这也与 U1 列出的候选解释 (b)「大状态早期难优化」一致，
  但本实验只测了两个端点，**不足以在 (a) 读出增益变粗 / (b) 早期难优化 之间定罪**）。
- 与 §4② 合起来：**训练伪影被排除之后，容量轴依然无效**——所以 U1 的
  「容量曲线不成立」**不是**训练不足造成的假象，本实验把它**加固**为
  「该尺度/该任务上容量不是约束」。

## 10. 口径声明（数字必须带口径）

- **准确率口径**（不用 bpc）：chance = 1/64 = 0.015625；
  区间 = Wilson score 95% CI；「可比」= CI 不重叠；
  Δ < 0.014 的排序在本仓方法学里无效（`docs/methodology.md`）。
- **Δ 的符号**（全篇一致，SCHEMA §17.3）：`Δ = acc(大状态) − acc(小状态)`，正 = 大状态更好。
- **直接测点、禁外推**：4 个 K 档 × 2 主臂 + 1 重跑臂 = 12 个直接测点；
  U1 的 10k 读数**只读引用**；**没有**任何点是从别处推来的。
- **训练侧口径**：24,000 步、bs 32、T 256、lr 1e-3、AdamW+cosine、seed 0；
  **门禁已过**（答案行 CE 末窗斜率 −0.006963 / −0.005449，\|·\| < 0.01）⇒ 本实验的读数
  **有资格**作容量结论（这是与 U1 的关键差别）。
- **评测口径**：训练与评测同一掩码 `window_anchor_keep_mask(256,16,0)`；
  难度档 `(K,Q) = (4,4)/(8,8)/(16,8)/(32,8)`，`Q ≤ K` 是生成器硬约束。
- **本地/业界**：本文件所有数字都是**本地实测**；业界结论见 `README.md` §6
  （全 `记忆·未核`，仅作方向、**不作判据**）。

## 11. 失败决策树（README §10 的实际走向）

| 分支 | 是否触发 | 证据 |
|---|---|---|
| ① 测量：`S16`/`S128` 不显著高于 chance | 否 | 0.368604 [0.362021, 0.375235] ≫ 0.015625（23.59×） |
| ② 实现：某臂活性量恒为 0 | 否 | `read_share` 0→0.38/0.42/0.47、`β`≈0.31–0.34、反事实偏差 6.6–11.6%；变异 M1–M3 全抓红 |
| ③ 收敛门禁未过 | **否** | 答案行 CE 末窗斜率 −0.006963 / −0.005449（\|·\| < 0.01） |
| ④ 规模/结论：收敛后 Δ < 3pp 或 CI 重叠 | **是** | §4②（四个档位全部不可分辨） |
| ⑤ 设计：某格毁源后不掉 | 否 | 12 格毁源全 ≈ chance，作废 0 格 |
| ⑥ 归因：重跑臂 CI 不重叠 | 否 | `S16` vs `S16_rep` Δ=+0.22pp、CI 重叠 |

**这不是一条「机制不可能」的结论**（SCHEMA §19），而是「**该任务/该尺度上，把状态宽度
从 16 加到 128 不划算**」。注意 answer-CE 在末窗仍在缓慢下降（1.5581 → 1.4149，
相对 **−9.19%**，从 10k 到 24k），但**没有转化成准确率**——所以「再训久一点」在本任务上
不是解药；要动就动**需求侧**（K、序列长度、每层记忆槽）或**任务型**。

## 12. 下一步（建议，供编排方取舍）

1. **不要再加大 `dh`、也不要再加长训练**——本条已被两个独立方向否证（10k 与 24k 的
   容量曲线一样平；U1 的唯一容量效应是训练伪影）。
2. **换需求侧**：把 K 推到 64/128（更靠近容量边界），或把 T 拉长到 512/1024
   （让「要记的东西」随距离增长）。注意 SCHEMA §17.11：单点不得外推，要**直接测**。
3. **换任务型**：复制/induction 在本地读数上与关联回忆**结论不同**
   （`2617`：复制 0.1333、induction 0.0586）⇒ 容量轴是否在其它任务型上成立是**另一个问题**。
4. **方法论产出（可直接复用）**：① 「总 CE 当收敛门禁会恒真」的实测反例（§4①）；
   ② 「同 seed 训练非逐位确定」的直接读数（`stability.md` §2），凡是 3pp 级判据都必须配
   重跑臂；③ 锁粒度：多臂驱动应按臂释放/重取（`train_all.sh` 新版 + §8 台账）。
