## 0. 人话摘要（先读这段）

**这一格在问什么。** 一句话：**把一段上下文里某些位置的「记忆」（KV）删掉，模型会变差多少？**
这不是要改模型，而是要**造一件天平**——因为这条长上下文主线一直在说「丢掉一些位置的信息」，
却从来没有量过「丢掉多少、丢哪些位置、疼到什么程度」。它同时也正面回答最初的问题：
**左边那段最老的上下文，到底能不能丢、丢多少才开始疼。**

**相对普通的 decoder-only transformer 改了什么。** **什么都没改。**模型（一个普通的
12 层、256 宽、13.5M 参数的因果自注意力变压器）原封不动，权重不动、不重训、不加参数。
唯一的动作是**评测时**把注意力掩码上某些 key 设成「对某些查询不可见」——也就是模拟
「部署时把这些 KV 从缓存里扔掉」会发生什么。改动量级：**0 个参数**。

**为什么要改。** 省显存、省带宽的所有主张（窗口截断、驱逐、量化、摘要压缩）都在花同一笔钱：
**丢掉信息**。要在这些方案之间比较，先得知道这笔钱的汇率。而且一开始的原始问题就是
「左前缀能不能丢」。

**怎么测的。** 同一个模型、同一批 24×16 个评测窗口（enwik8 最后 1 千万字节）、
**同一个位置集**，只改「哪些位置的 key 被删」；指标是 **clean bpc**（每字符比特数，
越低越好；普通同尺寸变压器的参照就是它自己的全注意力 **1.4836**）。三个方向：

| 曲线 | 删什么 | 想回答 |
|---|---|---|
| 距离曲线 | 与查询距离**恰好**为 d 的 KV（d = 1…255） | 近处的记忆值多少 |
| 前缀截断 | **最远的 N 个**位置的 KV（N = 8…255） | 左前缀能丢多少 |
| 连续段删除 | 一段连续位置（随机起点，长度 4/16/64，各 8 个起点） | 是「按距离」还是「按内容」重要 |

**测出来多少**（`damage` = bpc 变差多少，正 = 更差；判据阈值 0.014 是这台天平的分辨率）：

| 干预 | 变差多少（bpc） | 参照系与人话量级 |
|---|---|---|
| 删「距离 1」的 KV（每个查询丢掉**紧邻前一个**字符） | **+3.245** | 灾难：bpc 1.48 → 4.73。近邻记忆几乎就是全部信息 |
| 删「距离 8」 | +0.090 | 仍然明显（是阈值的 6.4 倍） |
| 删「距离 16」 | +0.0165 | 刚过阈值一点点 |
| 删「距离 ≥ 32 的 KV」（保留最近 31 个位置） | **+0.0037 以内** | **安全**：代价 < 0.014 ⇒ **安全丢弃半径 d\* = 32** |
| 删「最远的 8 个位置」（全部查询口径） | **+0.197** | 看着很疼——但这**不是**「丢老前缀」的代价，见下 |
| 删「最远的 8 个位置」（只算**历史 ≥128** 的查询） | **+0.0085** | **安全**（< 0.014）：老前缀对长上下文查询很便宜 |
| 删「最远的 16 个位置」（只算历史 ≥128 的查询） | +0.0135 | 刚好在阈值边上 |
| 删「最远的 32 个位置」（只算历史 ≥128 的查询） | +0.0256 | 开始疼 |
| 删「连续 4 个位置」（随机起点，8 次平均） | +0.114 | 同样只删 4 个位置，代价是「各删 4 个远处的 KV」的几十倍 |

**结论与下一步。**

1. **天平造好了，而且可信**：三条曲线**严格单调**（不加任何噪声容差），同 seed 重跑
   逐配置差 **4.9e-07**（阈值 0.005），仪器自检「精确因果掩码 == 原始前向」**逐位相等**。
2. **安全丢弃半径 d\* = 32**：与查询距离 ≥ 32 的 KV 全丢，代价 < 0.014 bpc
   （在 256 长度的窗口上，等于「只保留最近 31 个位置」）。距离 ≤ 8 的 KV 是命根子。
3. **左前缀：能丢，但要分清两种代价。** 全查询口径下丢最远 8 个位置就 +0.197 ——
   这**主要是伪影**：位置 0–7 的查询被删掉全部历史后只剩自己，它们贡献了 +0.088；
   紧邻的 8–15 号查询也几乎只剩自己，贡献 +0.072。**对历史 ≥ 128 的查询，
   丢最远 8 个（甚至 16 个）只花 0.0085（0.0135）bpc**。所以「左前缀」本身很便宜，
   疼的是**把短历史查询的上下文一起砍掉**。
4. **按距离比按内容重要得多**：连续 4 个位置（不管落在哪，落在哪都一样，8 个起点的
   散布只有 0.107–0.120）代价 +0.114，远大于「按距离挑 4 个远的」。也就是说，
   在这档规模上，**决定代价的是「删的位置离查询有多近」，几乎不是「删的内容是什么」**。
5. **下一步**：这台天平可直接给 A9/A10/M2 复用（对话里说的「保留召回」）；
   未做的是契约里标「可选」的 attention-mass 统计（哪些位置真的被读到）。

### 2.3 前缀曲线的分解（诊断，非判据）

前缀删除有两个机制叠在一起：(i) **位置 i < N 的查询本身被抽掉全部历史**（只剩对角）；
(ii) 前缀外的查询丢掉最老的 N 个 key。三段 band 的贡献之和 == 总 damage（对账通过）：

| N | 总 damage | i < N（"冷启动"） | N ≤ i < 2N | i ≥ 2N | i ≥ 128 的配对 damage |
|---:|---:|---:|---:|---:|---:|
| 8 | +0.19653 | +0.0883 | +0.0724 | +0.0359 | **+0.0085** |
| 16 | +0.34488 | +0.2120 | +0.1004 | +0.0325 | **+0.0135** |
| 32 | +0.64098 | +0.4807 | +0.1283 | +0.0320 | +0.0256 |
| 64 | +1.24802 | +1.0401 | +0.1747 | +0.0333 | +0.0668 |
| 128 | +2.42948 | +2.1935 | +0.2360 | 0 | +0.4739 |
| 192 | +3.56284 | +3.3521 | +0.2107 | 0 | +2.7496 |
| 255 | +4.44473 | +4.4447 | 0 | 0 | +4.5203 |

**读法**：全查询口径的前缀曲线**不是**「老前缀值多少」，而是「老前缀 + 被连累的短历史查询」
合起来值多少。回答「左前缀能丢多少」应该看最后一列（长上下文查询，历史 ≥ 128）：
**N ≤ 16 安全（< 0.014），N = 32 起开始疼**。

代价 +0.114（差一个数量级以上），因为连续段必然包含若干个查询的最近邻 key。

## 4. 判据达成（对照 §4 逐字判据线）

| 判据 | 要求 | 实测 | 判决 |
|---|---|---|---|
| **(a) 三条曲线单调** | 距离/前缀/连续段曲线单调 | 三条**严格单调**（tol = 0）；用噪声容差 2σ = 0.0302 复检仍单调 | **通过** |
| **(b) 复现性** | 同 seed 重跑 Δbpc 差 < 0.005 | 40 个配置全部重跑，最大差 **4.94e-07** | **通过** |
| **(c) 基线数字** | 安全丢弃半径 d\* + 前缀曲线 | d\*（字面读法，见下）= 255；**可操作读法 = 32**；前缀曲线 7 点全给 | **通过** |
| **(d) 非单调 ⇒ 不可信** | 无 | 未触发 | **不适用** |

**判据 (a) 的方向歧义（如实报，未改判据）**：契约括注写「距离越远/丢得越多，损伤不应更小」。
对前缀/连续段这正是 damage 递增（与我们一致）；对**距离曲线**，字面读法要求
「越远损伤越大」，与物理预期相反。我们把两种读法都跑了：
物理方向（damage 随 d 非增）**单调**；字面方向**非单调**（8 处逆序，最大 −1.256）。
我们按 SCHEMA §17.1 的纪律**不改判据**，把两种结果都留在
`results.json::criteria.a_detail` 与 `a_distance_literal_direction`，供复核裁决。
本报告正文一律采用物理方向（「距离越远，损伤不增」）。

**判据 (c) 的退化（如实报，未改判据）**：「Δbpc < 0.014 的最大 d」在单调递减曲线上
是退化的——满足条件的集合 {32, 64, 128, 255}，最大值恒为最大测试距离 255。
故并列给出**可操作读法**：**从 d = 32 起，更远的 KV 全部可丢（保留最近 31 个位置），
累计代价 < 0.014 bpc**。两个数都在 `results.json::criteria` 里。

## 6. 对账（SCHEMA §12 三道 + §16）

### 6.1 算术对账

- **Δ 定义自洽**：`Δ = bpc_对照 − bpc_实验`，`damage = −Δ`；逐点核对
  （例 d = 1：1.483569 − 4.728587 = −3.245018 == Δ ✓）。
- **被删对数闭式**：距离 = `T − d`（T=256：255, 254, …, 1 ✓）；前缀 =
  `Σ_{j<N}(T−1−j)`（N=8 → 2012 ✓；N=255 → 32640 ✓）；连续段 =
  `Σ_{j=s}^{s+L−1}(T−1−j)`（L=4, s=83 → 682 ✓）。三项均与实测逐位相符。
- **行均值 == token 均值**：`row_bpc` 的均值与 `masked_bpc` 逐配置断言 < 1e-6（实测 ~3e-8）。
- **分解闭合**：三段 band 贡献之和 == 总 damage（7/7 逐点成立，见 §2.3）。
- **上下界**：bpc 上界 = log2(206) = 7.69（均匀分布）；实测最大 5.93（N=255）✓；
  下界 = 全注意力基线 1.4836；**没有任何配置低于基线**（删信息只会更差，与假设一致）。
- **跨曲线一致性**：前缀 N=8 对长上下文查询的代价 +0.0085，与「距离 ≥ 120 的单距离
  damage（0.0005）× 8 个 key ≈ 0.004」同量级 ✓（不是同一个量的精确等式，只是量级核对）。

### 6.2 任务对账

- 对照臂与主臂**同一模型、同一批窗口、同一位置集、同一读出**；差别只有可见集。
  不是「假上下文 + 真目标」式对照（SCHEMA §13）。
- 三要素：**输入分布** = 真实 enwik8 字符流（相同窗口）；**要预测什么** = 下一个字符
  （因果移位 CE）；**部署对应** = 推理时把某些位置的 KV 逐出缓存/不重建，省显存与带宽。

### 6.3 口径对账

- 两臂同为**纯推理快照口径**（同一 checkpoint，无训练、无步数差），不是 matched-step
  或渐近口径——本实验不存在训练口径差。
- 评测数值类型、README 中记录的 bpc 口径（bits/char）、窗口数、批大小、seed 全部一致。
- 跨批比较提示：本实验 **43.4 s 的 137 次评测全在同一进程、同一 seed 下完成**；
  唯一跨批数字是与 2610 的锚 1.4836 的比较（差 3.1e-05，来自锚的 4 位小数舍入）。

### 6.4 收敛对账（§16）

**不适用**：本实验不报训练增益（无训练、无 loss 斜率、无更长训练点）。被测量的
checkpoint 是固定的 12k 步快照，其 bpc 1.4836 已由 2610 记录；本实验只做同一快照下的
成对删除比较。

## 7. 干预活性（SCHEMA §10）

- `params_added = 0`，`weights_changed = false`——干预不在权重里，在注意力可见集里。
- **活性量**：每个配置的被删因果 (query, key) 对数与占比（`n_dropped_pairs` /
  `dropped_frac`），逐配置落盘在 `results.json` 与 `retention_log.jsonl`。
  例：距离 d=8 → 删 248 对（0.75%）；前缀 N=64 → 删 14 304 对（43.48%）；
  连续段 L=16 → 删 2 152 对（6.5%）。
- **是否活着**：**活的**。① 身份掩码与基线逐位相等（干预关 = 恒等，证明掩码路径本身
  不引入偏差）；② 最大 |damage| = 4.44 bpc（远大于噪声）；③ 单测
  `test_deletion_is_live_changes_logits_and_raises_bpc` 断言「删位置必须改变 logits，
  且近处删除的影响大于远处」。
- **§17.4「每 200 步落盘」不适用**：本实验无训练步；等价物是**每个配置完成即写**
  `retention_log.jsonl`（137 行，逐条含 bpc/耗时）。

## 10. 失败路径、失败决策树与限制（照 AGENTS.md「失败也要讲人话」）

### 10.1 失败决策树（结果不好时先分清是谁的错）

| 症状 | 诊断顺序 | 处置 | 本次是否触发 |
|---|---|---|---|
| 曲线非单调 | ① 位置集合实现 bug → ② 评测窗口/CE 口径 → ③ 噪声 | 先跑 `mutate.py` + 单测；再对照 `noise_floor` 的 σ；非噪声则记 ERRATA 并修仪器 | 未触发（tol=0 即单调） |
| 出现「负损伤」（删 KV 反而更好） | ① 配对口径（两臂窗口/位置集不一致）→ ② 真效应 | 先查 `window_seed` 与查询集是否配对；真效应则如实记录 | 未触发（无配置低于基线） |
| 复现性不过（Δ 差 ≥ 0.005） | ① GPU 非确定性 → ② 未固定的随机源 | 固定 seed 重跑；仍不过则升级为仪器缺陷 | 未触发（4.9e-07 / 逐位相同） |
| 身份掩码 ≠ 释放版基线 | 掩码语义或对角约定错 | 停：仪器不可信，先修（本次逐位相等） | 未触发 |
| 与 2610 锚 1.4836 差很多 | 窗口/评估口径不一致 | 用同一 `window_seed` + 批数复算 | 未触发（差 3.1e-05，来自锚的 4 位小数） |


1. **前缀全查询口径看起来"很疼"是伪影，不是机制结论。**
   原本以为：丢最远 8 个位置应该很便宜。实际：+0.197 bpc。为什么：位置 0–7 的查询被删掉
   全部历史后只剩自己（CE 从 ~1.5 升到 5.35 bpc），贡献 +0.088；紧邻的 8–15 号查询也几乎
   只剩自己，贡献 +0.072。**排除了**「前缀内容本身很值钱」这个解释——对历史 ≥128 的查询
   同样的删除只花 +0.0085。
2. **契约「方法 4：attention-mass 统计」未做**（契约标注为「可选」）。原因见 README §3，
   不是失败，是范围决定；本实验用按距离的 damage 曲线间接反映「哪些位置被读到」。
3. **本仪器只测「一次性删除固定位置集合」**，不测「逐出后继续解码」的在线效应
   （那是 A3/ring-buffer 线的范围）；也不测「删除后重训/微调」（纯推理口径）。
   **也未加 depth-ar 形态的对照 checkpoint**（契约写「若预算允许」）：预算允许
   （43 s），但该形态走门控 + 混合深度 KV 填充路径，而填充会把「删掉的 KV」用
   冻结表征回填——「删除是否生效」在 fill 语义下是未裁决的设计问题，且需要
   第二条前向路径 + 单测 + 变异。理由与建议见 `README.md` §3。
4. **连续段曲线不能干净地区分「按内容」与「按位置」**：一段连续位置必然包含若干查询的
   最近邻 key，所以它必然昂贵。它能说明的是「同一长度、不同起点，代价几乎不变
   （极差 0.2–0.6%）」⇒ 内容是次要因素，但**不能**据此断言「内容完全不重要」
   （需要按内容挑位置的对照，属后续）。
