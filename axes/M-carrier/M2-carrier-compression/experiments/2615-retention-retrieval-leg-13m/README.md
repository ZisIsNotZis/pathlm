## 1. 命题

**「低损伤」到底是因为模型本来就不用这段记忆，还是因为记忆还在？**
现有天平（ticket 31-I）只量**依赖**（bpc 对可见集的敏感度）；本实验给它加一条**检索腿**
——把「针」（一段植进窗口的真实文本短语）放进去，删掉记忆后再问，看还能不能答出来。
仪器类实验的判据 = **两条腿是否给出不同信息 + 基线数字**。

## 2. 动机（**逐字**抄录契约「动机」段）

> 动机（SCHEMA §17 第 10 条）：现有曲线量的是**依赖**；低损伤可能是「模型本来就不用」。
> 必须加一条检索腿，把「不需要」与「保住了」分开。

## 3. 方法（**逐字**抄录契约「方法」段）

> 方法：在 T=256 的窗口里植入 K=8 对「针」（x→y 关联，内容不在原文出现，沿用本项目
> needle v2 构造：`archive/legacy-docs/experiments.md` §needle 与
> `.scratch/05-m1-followup/evidence`），查询尾提问；
> 对每个「保留配置」（全保留 / 删除最远 N / 只保留最近 d / 连续段删除）同时测
> **两条腿**：
> 1. **依赖腿**（已有）：clean bpc 的 Δ；
> 2. **保留腿**（新增）：针的**召回率**（以及「窗口内 / 锚区 / 窗口外」分桶，沿用历史分桶语义）。

### 3.1 构造修复（摘要 + 实测理由；**不改判据线**）

契约原文要求沿用 **needle v2**（`pathlm/data.py::needle_batch`：随机字节对针）。本实验
**先按要求测了它的基线**：**召回 1.5%**（`results.json::v2_construction_diagnosis`，
n=1260，anchor 1.7% / in_window 1.5%）——远低于契约自己的 50% 门槛。
按契约「基线 <50% 视为构造问题，先修构造再测，不得带病判读」，我们**先修构造**。

诊断（测量，不是猜测）：本项目被测量的 13.5M 主干是在**纯文本**上训练的（`p_needle=0`），
它没有「任意内容复制」能力——随机字节对的答案不可从线索先验得到，模型也搬不动它：

| 诊断探针（同主干、同一批窗口） | 实测 |
|---|---|
| v2 构造（随机字节对针，契约原文） | 召回 **1.5%** |
| 真实文本短语针（**needle v3**，本实验采用） | 召回 **68.7%** |
| 随机 token 序列复读（经典 induction 探针，m=16…96） | 10–12%（≈ 不可用） |
| 线索=真实 6 字节、答案=随机字节（任意复制探针） | 6%（≈ 不可用） |

⇒ 该主干**能**从上下文里「续写真实文本」，**不能**复制任意内容。所以针的内容改用
**真实 enwik8 短语**（关联仍然唯一：短语不得已在窗口正文里出现），线索长度 L=6。

**needle v3 定义**（`phrase_needle_batch`）：尾块每根针占 L+1=7 行
`[mask, cue_0 … cue_5]`，答案 = 短语的下一个字节 `phrase[6]`，在答案行 `q_row`
（输入 = `cue[5]`）上计 top-1 命中；窗口正文 `[0, q0=200)` 里植入该短语的副本
（位置 `p`，间距 ≥ L+1 ⇒ 针位互不重叠，每根针只被放一次）。`plant=False`
（同一 generator 状态）⇒ 线索相同、副本不存在 ⇒ 检索腿的**地板**。

### 3.2 分桶（「沿用历史分桶语义」在**全注意力**主干上的落地）

历史分桶（`pathlm/eval.py::needle_acc`）按 `window`/`anchors` 分：`anchor`（针落在最前面
`anchors` 个位置）/ `beyond`（针被驱逐，允许失败）/ `in_window`（可达）。本主干是
**全注意力**（`window=0`），历史代码在该配置下会把所有针归入 `in_window`（退化）。
因此把「窗口」换成**该保留配置的有效可见集**（同一件仪器、同一掩码语义）：

| 桶 | 定义 |
|---|---|
| `anchor`（锚区） | 针的起点 `p < anchors = 8`（历史锚区语义；单列一桶） |
| `window`（窗口内，可达） | 非锚针，且短语全部 L+1 个位置对其答案行**都可见** |
| `beyond`（窗口外，被删） | 非锚针，短语**有任意一个位置不可见**（半删 = 被删） |

桶之间**互斥**，`sum(桶计数) == 针数`（单测 + 变异验证钉住；见 §6）。

保留配置：**全保留** / **删最远 N**（`prefix`，N∈{8,16,32,64,128}）/ **只保留最近 d**
（`recent`，d∈{16,32,64,128,144,160,176,192,256}，其中 256 ≡ 全保留，作恒等自检）/
**连续段删除**（`segment`，L∈{4,16,64}，每长度 8 个固定起点，`start_seed=11`，与 2614 同法）。

## 4. 判据线（**逐字**抄录契约「判据」段，未改一字）

> - **判据（预登记）**：
>   - 主判据：两条腿必须**给出不同信息**——存在「依赖腿几乎无伤（|Δbpc|<0.014）但保留腿崩掉
>     （召回下降 >30pp）」的配置区间 ⇒ 证明「低损伤 ≠ 保住了」，仪器成立；
>   - 若两腿在所有配置下同向同幅 ⇒ 说明该模型上「依赖」可代理「保留」，也要如实记录（这本身是结论）；
>   - 阈值前先报**全保留基线**的召回率（若基线 <50% 视为构造问题，先修构造再测，不得带病判读）。

**执行时的操作性定义（不改判据，只把符号落定）**：

- 符号统一 `Δ = bpc_对照 − bpc_实验`（正 = 改善，SCHEMA §17.3）；本实验删除只会抬高 bpc，
  所以 Δ ≤ 0、`damage = −Δ ≥ 0`。主判据里的「|Δbpc|」= `|delta_bpc|`（全查询口径），
  并列报 `damage_qmin128`（历史长上下文口径）与 `damage_qmin200`（= 针的答案行所在行的
  配对口径，SCHEMA §13 的同一位置集）两个口径，三个都算一遍、都如实报。
- 「召回下降」= `全保留基线召回 − 该配置召回`（**同一个 4096 根针的批次**，逐针配对）。
  并列报**配对口径**（只在「该配置真正删掉的那些针」上算，上限/下限都来自同一批针）与
  **难度控制口径**（只在「无针控制臂也答不出」的针上算）。
- 依赖腿的「几乎无伤」阈值沿用契约的 **0.014**（methodology §2 方差界），未改。

## 5. 单因素声明

唯一因素 = **注意力可见集**（哪些 (query, key) 对参与注意力）。被测量模型、checkpoint、
数据流、评测窗口、位置集、读出、针的植入方案与随机种子全部逐字段一致；不改权重、
不训练、不引入任何新参数（`results.json::intervention.params_added = 0`）。
基底 = 主流标准 decoder-only transformer（`DepthARModel(dense=True)`，12 层 × 256 宽 × 8 头，
tied 读出、无 final LN）。无「必要性例外」。

**两条腿说的是同一件事吗？**（SCHEMA §13 三要素）两条腿共用同一件仪器、同一批窗口、
同一位置集、同一读出：

| | 依赖腿 | 保留腿 |
|---|---|---|
| 输入分布 | 真实 enwik8 字符流（窗口 `window_seed=2`，24×16） | 同一窗口的真实文本 + 植入的短语针（32×16 行，4096 根针） |
| 要预测什么 | 下一个字符（因果移位 CE → bpc） | 答案行上的短语下一字节（top-1 命中） |
| 部署对应 | 推理时把某些位置的 KV 逐出缓存 | 同一件事：那根针（一条可查的事实）还在不在 |

## 6. 对照与方差

- **对照 = 同一模型的全注意力自身**（`keep_mask=None`，走释放版 `is_causal=True` 路径）。
  身份（精确因果）掩码与它**逐位相等**（`bitwise_equal = true`）⇒ 不是跨 run 对照。
- **检索腿的地板对照** = 无针控制臂（`plant=False`，同一 generator 状态 ⇒ 针位与线索逐一配对）。
- **依赖腿跨实验等值性（SCHEMA §9）**：本实验的 `prefix` 曲线与本实验进程内**重跑**的
  2614 曲线逐位相同（`reproducibility.max_abs_damage_diff = 0.0`），且与 2614 记录值逐点
  相同（例 N=8：0.196528 vs 2614 的 0.19653）⇒ 复用是同进程重算，不存在跨 run 混杂。
- 方差界：Δ < 0.014 不可排序（methodology §2）。跨**窗口 seed** 的依赖腿 damage σ =
  0.0014–0.0042（n=4）；跨**针 seed** 的召回 σ = 0.026–0.035（n=3）——都远小于 30pp 的判据跨度。

## 8. 成本（唯一数字 = 契约 §「成本」行）

- 契约写的预算是**纯推理 ≈10–20 min**。
- **实测**：墙钟 **56.98 s（0.95 min）**，**1425 次评测**，39 个保留配置 × 4096 根针，
  峰值显存 **142.7 MiB（net）**——远低于契约预算与 ≤5GB 净预算。
- 可中断性：是（纯推理，无训练状态；重跑成本 57 s）。
- 冒烟：`python3 run.py --smoke`（约 4 s，落 `smoke/`，实测步时/显存，**不外推时间字段**，
  遵循 SCHEMA §17.5）。预算不够时砍「连续段起点数 → needle seed 数」，**不砍判据线**。

## 10. 失败决策树

| 症状 | 诊断顺序 | 处置 |
|---|---|---|
| 基线召回 <50% | ① 构造（针的内容/线索长度）② 评分口径（未移位 / 桶判错）③ 模型确实不会 | 先跑 `run.py` 的 `v2_construction_diagnosis` 与 `smoke`；本实验实测 v2 = 1.5% ⇒ 按契约修构造（needle v3）；修完仍 <50% 才判「该主干无检索头寸」 |
| 召回远低于地板（比无针还差） | ① 删除波及**查询块本身**（线索没了）② 掩码实现 | 检查配置是否覆盖 `[q0, T)`；是则标记 `overlaps_query_block` 并另算（本次 8 个 segment 配置命中） |
| 同一配置两次召回差很多 | ① seed 未固定 ② 桶判定用了**跨批**状态 | 本实验逐针同批同序比对（`paired_*`），跨 seed 散布已报（σ ≤ 3.5pp） |
| 两条腿在所有配置上同向同幅 | 不是 bug | 按契约第二分支如实记录为结论 |
| 主判据未达成 | ① 是「没有低损伤配置」还是「保留腿掉不动」 | 分别报 `n_low_damage_configs`（低损伤配置数）与 `instrument_gap`（动态范围上限）：本次两者都指向同一结论 |

`results.json`（两条腿 × 39 配置 + 构造诊断 + 地板 + 判据块 + 配对/难度控制口径 + 噪声底 +
