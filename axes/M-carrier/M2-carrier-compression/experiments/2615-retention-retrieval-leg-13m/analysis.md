## 0. 人话摘要（先读这段）

**这一格在问什么。** 我们上一批造了一件天平：**把某段记忆（KV）从注意力里删掉，质量掉多少**
——量出来的是「模型**多依赖**这段记忆」。但「不疼」有两种可能：① 信息确实保住了；
② 模型**本来就不用它**。这一格就是给天平补一条**检索腿**：往窗口里塞几根「针」
（一段真实文本小片段，只在窗口里出现过一次），删掉记忆后再问它——**还答得出来吗？**
只有把「不需要」和「保住了」分开，后面的压缩/驱逐方案才有可信的价签。

**相对普通的 decoder-only transformer 改了什么。** **模型一个字节都没改**：同一个
13.5M 主干（12 层、256 宽）、权重不动、不训练、不加参数。改的只是**评测方式**：
同一次前向里，一边算 bpc（依赖腿），一边看那几根针答不答得出来（保留腿）。

**为什么要改。** 「省显存/省带宽」的所有方案都在花同一笔钱——**丢掉信息**。上一批只
量了「多疼」，没量「信息还在不在」。低损伤如果只是「模型不用」，那它**不能**当作
「可以安全丢」的证据。

**怎么测的。** 同一主干、同一批 enwik8 末段窗口、同一套注意力掩码，跑两类保留配置：
① **依赖腿** = 删位置后的 clean bpc 变化（越低越疼，单位 bpc，分辨率 0.014）；
② **保留腿** = 4096 根植入的针的 top-1 召回率（越高越好，单位百分点 pp）。
「针」= 一段真实文本的 7 个字节，前 6 个作为线索在尾部复读、第 7 个是答案；
窗口正文里植入同一段，**答案只能从窗口里那次出现拿到**。对照组：**不植入**（针不存在），
针位与线索与主臂逐一配对 ⇒ 这是召回率的**地板**。

**测出来多少**（数字 + 参照系 + 人话量级）：

| 量 | 实测 | 参照系与人话量级 |
|---|---|---|
| 全保留基线召回 | **0.687**（68.7%） | 契约门槛 50% ⇒ **构造达标** |
| 无针控制臂召回（地板） | **0.433**（43.3%） | **关键发现**：一根针都没有时，模型照样能「答对」43%——因为线索本身是真实文本，语言先验就能接下去 |
| 仪器动态范围（基线 − 地板） | **0.254**（25.4pp） | 判据要 30pp：**非重叠配置实测可达**（最大下降 34.4pp，配对口径 59.0pp）⇒ 可及 |
| 契约指定的 needle v2（随机字节对）基线召回 | **0.015**（1.5%） | 远低于 50% ⇒ 按契约**先修构造**（改用真实文本短语针） |
| 低损伤配置（\|Δbpc\|<0.014）的最大召回下降 | **10.3pp**（配对口径 21.5pp） | 判据阈值 30pp ⇒ **未达成** |
| 被删的针 vs 没被删的针（同一批） | 0.433 vs 0.694 | 仪器**是活的**：没被删的针召回一点没掉 |

**结论与下一步。**

1. **仪器建成了，而且可信**：掩码把针删掉后召回掉到 0.43（= 地板），没删的针保持 0.69
   （= 基线），两侧都对得上；同一配置重跑逐位相同（差 0.0）。
2. **主判据未达成（中性）**，两条腿在 39 个配置上**同向**（Pearson r = −0.47）。
   原因有两个，都是**真结论**、不是实现问题：
   - ① **保留腿自己的动态范围只有 25.4pp**：线索是一段真实文本，模型不看记忆也能接出
     43% 的答案（这本身是「假保留」在**检索腿**上的翻版）。哪怕把针全删光，也只能掉 25pp。
   - ② **「低损伤」的配置里删掉的针太少**：唯一「几乎无伤」的家族是「只保留最近 d」的
     大 d（d=144…192，Δbpc −0.014…−0.004），但它们只删掉 6%–19% 的针。
3. **重要副产品（跨实验对账发现）**：上一批（2614）的**「安全丢弃半径 d\*=32：距离 ≥32 的
   KV 全部可丢，累计代价 <0.014」不成立**。那是把**单距离**曲线的点**当成可加**外推来的；
   实测「把所有距离 ≥32 的 key 一起删掉」（= `recent:d=32`）代价 **+0.212 bpc**，是那个
   数字的 **15 倍**。删一条距离的 key 时模型能用别的距离的 key 顶上，一起删就没有退路了。
   ⇒ 本批的「低损伤配置区间」比契约预设的窄得多，这正是主判据落空的结构性原因之一。
4. **下一步建议**：① 2614/M2/INDEX 里的「安全半径 d\*≈32」需要按累计口径改写（本实验的
   `recent` 曲线就是它的累计版本）；② 若要让检索腿有 30pp 以上的动态范围，得换一个
   **答案不能从线索先验猜到**的任务（本主干没有任意内容复制能力，实测 6%，所以做不到）；
   ③ 真正能把两条腿分开的实验，应该是「按**内容**挑选要删的 key」（A10 的优先级对决），
   因为位置型删除对 bpc 和召回是同一把尺子。

## 1. 仪器自检与等值性（先排除「测量问题」）

| 检查 | 结果 |
|---|---|
| 全注意力基线（释放版 `is_causal=True`） | bpc **1.483569** |
| 身份掩码（显式精确因果掩码） | bpc **1.483569**（逐位相等） |
| 与 2610/MODEL.md 记录的锚 1.4836 差 | 3.1e-05（锚只写了 4 位小数） |
| 与 2614 的依赖腿逐点对照（同一进程重算） | `prefix` N=8/16/32/64/128 damage 全**逐位相同**（0.196528 / 0.344876 / 0.640980 / 1.248019 / 2.429482） |
| 同 seed 重跑（6 个配置） | 最大差 **0.0**（逐位相同），阈值 0.005 ⇒ 通过 |
| 检索腿配对自检 | `plant=False` 与 `plant=True` 在**同一 generator 状态**下 meta 逐字段相同（单测 + 运行时断言） |
| 变异验证（4 处「针被删错/放错/半删当没删/最近 d 差一」） | **4/4 抓红**，还原后 sha256 一致 |

⇒ 两条腿与基线**同引擎、同代码路径、同数据流、同窗口、同位置集**，不是跨 run 对照
（无 SCHEMA §9 的复用混杂）。

**分桶判定的内部一致性**（最强的活性证据）：配置 `prefix:N=8` 只删掉最前面 8 个位置，
正好命中锚区的针：

- 没被碰到的针（窗口内桶）：召回 **0.6943**，与全保留基线的窗口桶 **0.6945** 一致（差 0.0002）；
- 被删掉的针（锚区桶）：召回 **0.4587**，与「没有针」的地板 **0.4331** 同量级。

也就是说：**删除只影响被删的那些针，可达的针一点没受影响** —— 仪器是活的、标定过的。

## 2. 构造诊断（为什么不用契约原文的 needle v2）

契约原文要求沿用 v2（随机字节对针）。先测它的基线（`results.json::v2_construction_diagnosis`）：

| 构造 | 针数 | 召回率 | 达到 50% 门槛 |
|---|---:|---:|---|
| v2（`pathlm.data.needle_batch`，随机字节对） | 1260 | **0.0151** | ✗ |
| v2 分桶：anchor / in_window | 232 / 1028 | 0.0172 / 0.0146 | ✗ |
| **v3（本实验：真实文本短语针，L=6）** | 4096 | **0.6868** | ✓ |

诊断探针（同主干）：

| 探针 | 实测召回 |
|---|---:|
| 随机 token 序列复读（induction），m=16/32/48/64/96 | 0.116 / 0.108 / 0.107 / 0.098 / 0.091 |
| 线索 = 真实 6 字节、答案 = 随机字节（任意复制） | 0.058 |
| 线索 = 真实 6 字节、答案 = 自然续写（v3） | 0.700 |

⇒ 该主干（纯文本训练，`p_needle=0`）**没有任意内容复制能力**，只能「续写真实文本」。
用随机字节对的 v2 在这个主干上必然退化到语言先验，测不到记忆。按契约「基线 <50% ⇒
构造问题 ⇒ 先修构造」，改用真实文本短语针：答案仍然唯一（该短语不得**预先**出现在窗口正文里），
但答案的**来源**是窗口里那次植入——这正是我们要问的「记忆在不在」。

## 6. 对账（SCHEMA §12 三道 + §16）

### 6.1 算术对账

- **Δ 定义自洽**：`Δ = bpc_对照 − bpc_实验`；逐点核对（例 `prefix:N=8`：
  1.483569 − 1.680097 = −0.196528 ✓）。
- **行均值 == token 均值**：`row_bpc` 均值与 `masked_bpc` 逐配置断言 < 1e-6（实测 ~1e-8）。
- **上下界**：bpc 上界 = log2(206) = 7.69（均匀）；实测最大 3.913（N=128）；
  **没有任何配置低于基线**（删信息只会更差，与假设一致）。
- **召回上下界**：召回 ∈ [0, 1]；实测最大 0.795（`recent:d=32` 的窗口内桶，n=83）、
  最小 0.140（`segment:L=64@172` 的锚区桶，任务被破坏）✓。
- **配对口径的算术对账**：`deleted_share` 与 `retention.buckets` 的计数逐配置相加一致
  （`n_window + n_anchor + n_beyond == 4096`，39/39 成立）✓。
- **配对分解闭合**：`n_deleted`（= 短语里**至少一个**位置对其答案行不可见的针）与桶口径闭合：
  `n_deleted == 被删的锚针数 + n_beyond`，39/39 逐配置成立 ✓。
- **「保留最近 d」的闭式计数**：query i（= q−1）保留的因果对数 = `Σ_{q=1..T} min(d, q)`（含对角）
  ⇒ 删掉的 = `T(T+1)/2 − Σ_{q=1..T} min(d, q)`。逐点核对：
  d=32 → `32896 − 7696 = 25200`（实测 **25200** ✓）；d=16 → **28920** ✓；
  d=256（全保留）→ **0** ✓（单测 `test_recent_keep_mask_keeps_only_last_d_keys` 也钉住）。

### 6.2 任务对账

- 两条腿**共用同一件仪器、同一批窗口、同一位置集、同一读出**，差别只有可见集与
  「针在哪里」；不是「假上下文 + 真目标」式对照（SCHEMA §13）。
- 检索腿的对照臂（无针）**输入分布**相同（同一批窗口、同一线索），**要预测什么**相同
  （答案行的下一字节），**部署对应**相同（那根针在不在缓存里）。⇒ 三要素齐备。
- **排除**「答案来自尾块线索本身」这条替代解释：无针控制臂把这个来源单独量了出来
  （0.433），所有「记忆的贡献」都是相对它算的（§3.4 配对口径）。

### 6.3 口径对账

- 两臂同为**纯推理快照口径**（同一 checkpoint，无训练、无步数差），不存在训练口径差。
- 依赖腿三个口径（full / qmin128 / qmin200）**分开报**，主判据按契约正文的全查询口径判，
  三个口径都扫了一遍，结论一致（§4）。
- 跨批比较提示：本实验所有数字在同一进程、同一 seed 下算出；唯一跨实验数字是
  §5.2 与 2614/2610 的对照。

### 6.4 收敛对账（§16）

**不适用**：本实验不报训练增益（无训练、无 loss 斜率、无更长训练点）。被测量 checkpoint
是固定的 12k 步快照（bpc 1.4836 由 2610 记录）。

### 6.5 跨实验对账发现：2614 的「安全半径 d\*=32」是**不可加外推**

2614 的 `criteria.c_safe_radius_d_operational` 写「**距离 ≥ 32 的 KV 全部可丢，累计代价
< 0.014 bpc**」（`axes/M-carrier/M2-carrier-compression/README.md` 也写了「d≥32 ≤+0.004」
与「安全丢弃半径 d\*≈32」）。该结论是把**单距离**曲线的点当成可加得到的。本实验的
`recent:d` 家族就是它的**直接测量版**（只保留最近 d = 删除所有距离 ≥ d 的 key）：

| 「累计可丢」的读法 | 2614 的推断 | 本实验实测 Δbpc | 倍数 |
|---|---:|---:|---:|
| 距离 ≥ 32 全丢（`recent:d=32`） | <0.014 | **+0.212** | **15×** |
| 距离 ≥ 64 全丢（`recent:d=64`） | （未给） | +0.081 | — |
| 距离 ≥ 128 全丢（`recent:d=128`） | （未给） | +0.020 | — |
| 距离 ≥ 192 全丢（`recent:d=192`） | （未给） | +0.004 | — |

**结论：单距离删除曲线不可加**（删一条距离的 key 时，模型可以用别的距离的 key 补偿；
一起删就没有退路）。⇒ 2614/M2 的「安全丢弃半径」需要按**累计**口径改写为
「距离 ≥ 144 全丢时 Δbpc = +0.0138（刚在噪声带内）、距离 ≥ 192 时 +0.0042」。
本实验不改他人产出的数字，只在此记录发现（ERRATA 归属 2614 / M2 / INDEX，需主 Agent 处置）。

## 7. 干预活性（SCHEMA §10）

- `params_added = 0`，`weights_changed = false` —— 干预不在权重里，在注意力可见集与针的植入里。
- **活性量**：每个配置的被删因果 (query,key) 对数与占比（`n_dropped_pairs` / `dropped_frac`），
  以及逐批判定的针命中与分桶，**每批量即写** `retention_log.jsonl`（82 行；本实验无训练步，
  批 = 步的等价物，见 SCHEMA §17.4）。
- **是否活着**：**活的**，三条独立证据：① 身份掩码与基线**逐位相等**（干预关 = 恒等）；
  ② 可达的针跨 39 个配置召回稳定在 0.69–0.72，被删的针稳定落在 0.33–0.56（§3.3 两条水平线）；
  ③ 单测 `test_needle_recall_counts_every_needle_once_and_tracks_the_buckets` 断言
  「掩码把针删光时，总召回 == 窗口外桶召回」（无泄漏）。

| 主判据未达成 | 是「没有低损伤配置」还是「保留腿掉不动」 | **触发** ⇒ 两者都报（§4） |

### 8.2 失败也要讲人话（原本以为 → 实际 → 为什么 → 排除了什么）

1. **原本以为**：v2 的随机字节对针能直接测检索（历史 X2v2 上 in_window 84.9%）。
   **实际**：在本 checkpoint 上只有 1.5%。**为什么**：X2v2 是**用针批次训练过**的模型
   （`p_needle=0.1`），本主干是纯文本训练的（`p_needle=0`）。**排除了**「v2 实现坏了」
   ——同一份 `needle_batch` 代码在同主干上跑出的是可复现的 1.5%，且随机 token 复读探针
   也只有 10%，两条独立证据都指向「主干没有任意内容复制能力」。
2. **原本以为**：把针全删掉，召回应该掉到接近 0。**实际**：只掉到 43.3%。
   **为什么**：线索是真实文本，语言先验能补出约 43% 的答案。**排除了**「地板测量错了」
   ——无针控制臂与主臂逐针配对（同 generator 状态、meta 逐字段相同），且「把副本里的
   答案字节换成随机字节」会让召回**低于**地板（诊断性观察，见 `results.json::v2_construction_diagnosis`），说明地板不是噪声。
3. **原本以为**（契约预设：「依赖腿几乎无伤 |Δbpc|<0.014 的配置区间」来自 2614 的安全半径）。
   **实际**：那个区间几乎不存在——按累计口径，删距离 ≥32 的 key 代价 +0.212。
   **为什么**：2614 的单距离曲线不可加（§6.5）。**排除了**「本实验的 `recent` 实现错了」
   ——`recent_keep_mask` 的删对数闭式核对通过（d=32 → 25200 对 ✓），且 `d=256` 与基线逐位相等。

### 8.3 限制

1. **本仪器只测「一次性删除固定位置集合」**（纯推理快照），不测「逐出后继续解码」的在线效应。
2. **保留腿的绝对分辨率受限于地板 43.3%**：任何「召回下降到 X pp」的结论都必须相对这条
   地板读（本报告一律如此）。
3. **难度控制子集基线 46.6% < 50%**，故只作诊断（§5.3）。
4. **不覆盖「按内容挑选要删的 key」**：本实验的全部配置都是**位置型**删除，而位置型删除
   对 bpc 与召回是同一把尺子（这解释了 r = −0.47）。真正的分离要靠内容型优先级
   （契约 N/A10）。
