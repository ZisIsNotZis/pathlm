# CRITIQUE · M2-carrier-compression（载体压缩）— 独立批判审计（2026-10-04）

## ① 这是什么（我的理解）

研究「载体怎么压（内存换质量）」；本仓真正建成的是一台**保留/依赖天平**
（KV 消融 + 检索腿），并测了驱逐；量化/摘要/低秩三支要么借用他格、要么零经验。

## ② 对着什么 sota，我们偏离在哪

- 业界标准：KV 量化（KIVI / KVQuant / SmoothQuant / LLM.int8()）、驱逐窗口
  （H2O / Scissorhands / SnapKV / StreamingLLM）、摘要压缩（Compressive Transformer /
  AutoCompressors / ICAE）、低秩（MLA）——`axes/M-carrier/PRIOR_ART.md` 块② 逐条列出，
  并自己判 **(a)**（`:96` 分诊表：M2 的量化/摘要/低秩「业界均已做透」）。
- **偏离（重要，且是自造口径）**：本仓为「因果/流式量化」定义了一个**逐值 fp16 scale**
  （`tools/evalkit/kv_quant.py` 模块 docstring「每值一个 fp16 scale……int8 净 3 B/值、
  int4 净 2.5 B/值」；代码 `running_amax = x.abs().cummax(dim=-2)` 得 `[...,H,T,head_dim]` scale）。
  由此得出 `R1`/`M2` 的结论「**量化在任何拓扑上都是内存负收益**」。
  但**因果性只要求 scale 不依赖未来，不要求逐值一个 scale**：KIVI 的 K 侧 per-channel /
  V 侧 per-token 静态标尺是 O(1/N) 开销且完全因果。⇒ 这条结论是**标尺粒度的产物**，
  不是「因果代价」。

## ③ 五类问题逐条判定

1. **开倒车：有（主结论层面）。** 驱逐价格（+0.058~0.121，`catalog.yaml:1062`）+ 「大窗口
   训练税近零」都是业界默认；本地的检索腿方法论（§17.12「掉多少可见性对数」）是真增量。

2. **过程错误：有，两条。**
   - **旧数字被冻结但仍在引用**：`M2-carrier-compression/README.md:7` 自认
     「KV 量化已有本地实测（R1/2614、2618/2621；但旧价签在「非因果 scale」下失效，
     已入冻结清单，待 R1 因果口径重测）」。冻结清单见 `docs/OPEN_PROBLEMS.md` §3。
   - **实验原文与 ERRATA 不同步**：`M2/README.md:52` 记了 ERRATA（单距离曲线不得当可加外推，
     只留最近 32 = +0.212 bpc，单点 15 倍），但**实验自身的判读文件仍在首屏给出被撤回的结论**：
     `experiments/2614-kv-ablation-retention-13m/analysis.md:45,56,162,175,192` 五处
     「**安全丢弃半径 d\* = 32**」。⇒ 任何直接读 2614 的人会拿到已废结论。

3. **结论错误：有。**
   - 「驱逐 +0.058~0.121」是**评测期掩码**的代价（不改模型），不是部署价签；本仓在 2616 里
     已明确「实测显存不下降」。这一条在 M2 里被写成 `tax`，容易被读成「部署代价」。
   - 还有一条真正要紧的：**「量化省内存」的符号反转来自逐值标尺**（见 ②）。**正确结论应为**：
     「在本仓选择的『逐值因果标尺』口径下，int8/int4 的值+标尺总字节为 3.0/2.5 B/值，
     大于 fp16 的 2 B/值；若采用业界 per-channel/per-token 标尺，结论会反转，
     本仓**未测**该口径的质量」。R1 的 `verdict` 目前把它写成「**任何拓扑上**都是负收益」。

4. **无意义：部分是。** 「摘要压缩 / 低秩（MLA 式）」两支按 §21 属 (a)（业界已做透），
   若不接入本仓的天平做同字节预算对照，就没有增量 ⇒ 建议从「零经验待做」列表中删去。

5. **值得做：有**——但做的是「**同一字节预算横轴**下的量化/驱逐/窗口对照」
   （`PRIOR_ART.md:108` 自己也这么说），并**必须**同时用 per-channel 标尺复测一次，
   否则「量化不省内存」这条会计入错误账。

## ⑤ 正确验证方式（若补做量化）

- **该涨**：相对 fp16 的**总字节下降**（含标尺）。
- **该跌**：Δbpc 必须落在 ±0.014 内（若超带，量化不成立）。
- **必须不变**：**严格因果逐请求**——两条必要测试（改未来 token 不改过去 logits；
  改同批其他请求不改本请求 logits）必须为绿；`fp32` 档与释放版前向逐位相等。
