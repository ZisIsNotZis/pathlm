## 1. 这条研究是什么

普通 decoder-only transformer 每一层的宽度（`d_model`）都相同，等于假设「所有深度同等重要」。
本项在**总参数逐位对齐**（Σ_l w_l² 相等）的前提下，把宽度按深度重新分配成四种形态之一
（等宽 / 金字塔 / 沙漏 / 倒金字塔），看 clean bpc 是否越 0.014 噪声带。

## 2. 干预怎么实现（引擎无逐层 d_model ⇒ 实验内自造）

残差流恒 256 宽；第 l 层只在**前 w_l 个通道**（前缀子空间）上运算：该层 LN / attention
qkv-proj / FFN 权重取前缀子矩阵（FFN 隐藏 = 4·w_l），结果写回 `x[..., :w_l]`，其余通道原样通过。
实现 = `run.py::PrefixSubspaceBlock(Block)`，**复用共享 `Block.forward`**（把前缀交给它，
块内部 `d = w_l`），只在本层外把未触及的通道拼回 ⇒ 前缀路径与 stock 路径是同一段数值代码。
`w_l = 256` 时该层是恒等切片 ⇒ 逐位等于 stock（等值门 T1，`pytest` 24 passed，含 CUDA
bf16 autocast × train/eval）。

## 3. 臂与预算（Σ_l w_l² 逐位相等）

| 臂 | schedule（层 1→8） | Σw² | Σw | 解析参数量 | 解析 MACs/token（attn / ffn / 读出） |
|---|---|---|---|---|---|
| EQ | `[192,192,192,192,192,192,192,192]` | 294,912 | 1,536 | 4,203,520 | 1,966,080 / 2,359,296 / 52,736 = **4,378,112** |
| PYR | `[256,224,224,192,192,160,160,64]` | 294,912 | 1,472 | 4,202,688 | 1,933,312 / 2,359,296 / 52,736 = **4,345,344** |
| HG | `[64,160,192,224,256,224,192,160]` | 294,912 | 1,472 | 4,202,688 | 同上 = **4,345,344** |
| APYR | `[64,160,160,192,192,224,224,256]` | 294,912 | 1,472 | 4,202,688 | 同上 = **4,345,344** |
| U4（锚，复用不重训） | `[256]×8` | 524,288 | 2,048 | 6,962,688 | 3,145,728 / 4,194,304 / 52,736 = **7,392,768** |

- **对齐口径**：契约对齐的是 `Σ_l w_l²`（逐位相等）。总参数还含 `13·Σw_l` 的偏置项 ⇒
  EQ 与三臂差 **832 参数（0.020%）**、MACs 差 **32,768（0.75%）**（EQ 的 attention 项
  `Σ 2·T·w_l` 更大）。这两项**逐位报告**，不回避、也不据此改预算。
- **PYR/HG/APYR 参数与 MACs 完全相等**：三者是同一宽度多重集的三种**逐层分配**
  ⇒ 「非均匀 vs 等宽」之外，还能读出「分配形态」这一层。
- **U4 复用三道具**（`harness/SCHEMA.md` §9）：① 全层 `w_l = d` 的前缀模型 == stock 逐位（T1）；
  ② 逐字段配置对照 `anchor_config_parity`（全等）；③ 口径标注（`depth_curve` 最终深度、
  generator seed 2、同一解析代价公式）。
