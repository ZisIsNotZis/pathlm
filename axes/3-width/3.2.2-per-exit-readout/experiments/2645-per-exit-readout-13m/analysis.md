# 2645 · 逐出口读出 · 分析（人话摘要 + 判据读数 + 边界）

## 0 人话摘要

**问题**：普通 transformer 只有一个出口（末层），一张「状态 → 词表」的映射就够。有了多出口
（早退 / 每层都能出答案）之后，每个出口要不要**自己一套**映射？本实验问的是它值不值那笔
多出来的读出参数与算力。

**改了什么**：只改「出口 → 词表」这一段，主干（层数、宽度、注意力、FFN、门、退出采样）逐位不动。
对照臂 `T` = 共享 tied 表（stock 做法）；实验臂 `PE` = 共享表 + 每个出口一个 256×256 变换
（`logits_k = (M_k h_k)·Eᵀ`，`M_k = I` 起步 ⇒ 起步逐位等于 `T`）。

**怎么测的**：13M / 8 层 / 256 宽 / 9 个出口 / 变深度 + 随机退出，12k 步、enwik8 字符级
（vocab=206），两个 seed（0/1）各跑一对；指标是各出口 clean bpc（越低越好）、各出口的
「草稿被全深度出口接受」的比例 `tf@k`（率类，走按批配对 bootstrap 95% CI）、读出参数量。
0.014 bpc 带只用于配对 bpc 差；`tf@k` 是率类，**不跨量纲借用**这个带。

**测出来多少**：

- **末层（全深度）质量：`PE` 明显更好**——clean bpc 1.7513 vs 1.8370（seed 0）、1.7517 vs
  1.8328（seed 1），即 `PE` 低 **0.0857 / 0.0811** bpc（Δ = PE − T，两 seed 同向、各自越
  0.014 带 6 倍以上）。逐深度看，`PE` 在 9 个出口里的 8 个（seed 0）与全部 9 个（seed 1）
  都比 `T` 的 bpc 低，最深层的差在 0.08 量级、最浅层（深度 0）从 5.37 → 3.93 bpc（差 1.44）。
- **相对接受率：`PE` 更低**——`tf@2 / tf@3 / tf@4`（用第 2/3/4 层草稿、被**全深度出口**接受的
  比例，是相对量而不是早退的可用性）在**两个 seed 都下降**：−0.0468 / −0.0159（深度 2）、
  −0.0278 / −0.0207（深度 3）、−0.0204 / −0.0219（深度 4），每一条的配对 CI 都不含 0；深度 1
  只在 seed 0 上升（+0.0082）、seed 1 不可分（+0.0029，CI 含 0）⇒ **「浅出口的相对接受率变高」
  不成立**。按早退的本义看绝对曲线则相反：`PE` 4 层 1.7567 已优于 `T` 用满 8 层的 1.8370。
- **代价**：读出参数 **+589,824**（9 个出口 × 65,536），相对 `T` 的总参数 **+8.5%**（7,552,512 vs
  6,962,688；占 `PE` 自身总量 7.8%，同一笔钱的另一个分母）；每 token 训练期算力 **+589,824 MACs
  （+7.5%**，分母 = `T` 的训练总 7,814,656 → `PE` 8,404,480，9 个出口都要算 logits），
  推理期只 1 个出口 ⇒ 每 token **+65,536 MACs（+0.9%**，7,392,768 → 7,458,304）。
- 校准与软提交：`prob0` ECE 0.0028 / 0.0073（`T` 是 0.0062 / 0.0056，容差 0.003 内）；
  出口 argmax 与「状态在 tied 表基上的坐标」argmax 的一致率从 1.0 掉到 0.71 / 0.70
  （`PE` 的出口头不再是纯 tied 表，这是构造性的，不是缺陷）。

**结论（本尺度）**：逐出口读出**不是相对接受率（`tf@k`）的杠杆，而且绝对前沿更好**。
它让末层更强、`tf@k` 反而更低，而 `tf@k` 是**相对**全深度出口的接受率——给末层加固会机械地
压低它。按早退的本义（少跑层数换质量）读绝对曲线：`PE` 的 **4 层 1.7567 bpc 已优于 `T` 用满
8 层的 1.8370**（seed 1 同形 1.7595 vs 1.8328）⇒ **可用性变好**。所以准确的一句话是：
**它买到的是「多给读出容量」，不是「出口→词表形态」的好处；被否证的是「浅出口相对接受率该涨」
这条判据，而不是「逐出口读出让早退不可用」**——把 `tf@k` 当早退可用性的主判是本判据的设计缺陷
（`project.yaml::failure_analysis` ①）。

**第二批（等参数对照臂 `WIDE`，§6）已回答「这笔参数值不值」**：把同一笔参数给主干（每层 FFN
隐藏宽 1024 → 1168，+590,976 参数、训练期每 token MACs 与 `PE` 逐位相等）后，末层 clean bpc 在
s0 只低 **0.0039**（落带内）、在 s1 反而高 **0.0248**；而 `PE` 相对这个等参数对照的残余是
**−0.0818 / −0.1059**（两 seed 同向、各自越 0.014 带 5.8 / 7.6 倍）⇒ **参数不是全部解释**，
这笔增益只能记在「读出位置上的容量」名下。

## 2 为什么 `tf@k` 下降而绝对质量上升（判据口径的坑，定律 9）

`tf@k` 的定义是「深度 k 的 greedy 草稿被**全深度出口**接受的比例」。`PE` 给 9 个出口各加了
一个 `M_k`，其中也包含全深度出口（深度 8）——而末层的 CE 权重是 1.0、其它出口等权，所以
末层出口被加强得最多。逐深度 clean bpc 摆出来看得很清楚（越低越好，`T` → `PE`）：

| 深度 | 0 | 1 | 2 | 3 | 4 | 8 |
|---|---|---|---|---|---|---|
| seed 0 `T` | 5.3663 | 2.3943 | 1.9585 | 1.8598 | 1.8422 | 1.8370 |
| seed 0 `PE` | 3.9309 | 2.2755 | 1.9698 | 1.7966 | 1.7567 | 1.7513 |
| seed 1 `T` | 5.4436 | 2.3728 | 2.0417 | 1.8646 | 1.8386 | 1.8328 |
| seed 1 `PE` | 3.9305 | 2.2899 | 1.9866 | 1.7881 | 1.7595 | 1.7517 |

`PE` 的绝对质量几乎每个深度都更好（唯一例外：seed 0 深度 2 差 0.011，落带内），但末层进步
更大 ⇒ 相对接受率下降。**这条改变了判词该怎么说**：按早退的本义（少跑层数换质量），4 层
1.7567 已优于 `T` 的 8 层 1.8370 ⇒ 可用性变好，所以本项被否证的是「浅出口相对接受率该涨」这条
判据，不是「逐出口读出让早退不可用」；把 `tf@k` 当早退可用性的主判是判据设计缺陷
（`project.yaml::failure_analysis` ①）。两件事必须一起读，否则会把「末层变强」误读成「`PE` 变差」。

## 3 已凭单测钉住的事实（不依赖 GPU 跑臂）

| 事实 | 证据（单测） |
|---|---|
| `T` 臂 = stock tied 读出（逐位相同，含 `depth=None` 的全深度出口） | `T1`（2 项） |
| `PE`（`M_k = I`）起步**逐位等于** `T` | `T1` |
| 四臂主干 + tied 表同 seed 逐位相同（唯一变量 = 每出口读出） | `T3` |
| 每出口参数：`PE` 65,536 / `IND` 52,736 / `LR` 7,392（×9 出口），与实测落盘一致 | `T3` |
| 门能变红：改一个出口的头只让该出口 logits 变（其余逐位不变）；`PE` 起步梯度非零 | `T4` |
| 表达力（本尺度）：V=206 < d=256 ⇒ `E·M` 可表达任意线性头 ⇒ `PE` 的头族**包含** `IND` 的表族 | `T5`（`lstsq` 残差 < 1e-5） |
| 因果性、锚逐字段对照、自持接受率电池与引擎 `tf_acceptance` 逐位一致 | `T6` / `T7` / `T8` |

## 4 与 `3.2.1` / `2.1.1` 的边界

`3.2.1` 的 `PD` 臂（`h_k → h_k + P_k(Q_k h_k)` 再走共享 tied 表）落在 `PE` 的同一函数族内，
其判词是「`PD` 被等参数共享宽变换对照否证」。本实验的 `PE` 是另一种参数化（直接 `M_k`、恒等
起步、主判据是逐出口 `tf@k`），两个读数**不是同一件事**，但必须同框读：两者都说「给读出加
容量能推质量，但推不出早退的可用性」。跑不跑这层归深度轴 `2.1.1`，本项只判「出口 → 词表」。

## 5 未测项（预登记之外不推断）

1. **等参数对照臂的范围**：`WIDE` 只把「这笔参数花在主干」实现为**一种**放法（每层 FFN 等宽加宽
   144，读数见 §6）⇒ 不得读成「任何地方多参数都买不到质量」，只能读成「FFN 等宽加宽这一种放法
   在本尺度买不到可排序的质量」。其它放法（加层、加宽 `d_model`、加宽 attention）未测。
2. `IND`（每出口独立表）与 `LR`（每出口低秩校正）本轮未跑 ⇒ 「只有不可 scale 的独立表能提升」
   这条否证分支无本地读数。
3. 单尺寸（13M / 8L / V=206）：真词表（100k+）下 `PE` 的表达力优势消失（V > d 时 `E·M` 只有
   d 维自由度）⇒ 结论**不外推**。
4. 出口位置 / 出口数固定为「每层 + 全深度」（9 个）；出口数对结论的影响未测。
5. 只测训练期逐层监督（aux 等权 1.0）；推理期早退调度不在本项。

## 6 第二批：等参数对照臂 `WIDE`（参数是不是全部解释）

### 6.0 人话摘要

**问题**：第一轮判「逐出口读出（`PE`）让末层与各出口的绝对质量都更好」，但 `PE` 比对照臂 `T`
多 589,824 个参数（相对总参数 **+8.5%**）。所以那句话有两种读法：**「多了参数所以更好」**
（谁拿这 8.5% 都会变好）还是**「读出结构本身有额外收益」**（这笔钱只有在读出位置上才值）。
这一批就是把这笔钱换个地方花，看能不能买到同样的东西。

**改了什么**：只改「这笔参数花在哪」。新臂 `WIDE` = 与 `T` 逐位相同的 stock tied 读出，但**主干**
每层 FFN 隐藏宽 1024 → 1168（`mlp_hidden_sched = [1168]×8`）。读出这一侧它一个参数都没多。
记账（单测 `T9` 钉住）：参数 7,553,664（= `T` + 590,976，比 `PE` 的 +589,824 多 **1,152** =
+0.015% 总参数，方向对对照臂有利）；每 token 训练 MACs 8,404,480，**与 `PE` 逐位相等**；
推理期比 `PE` 多 524,288 MACs/token（FFN 加宽在推理也要付，同样对对照臂有利）。

**测出来多少**（`results.json::per_seed.s{0,1}.arm_rows.WIDE`，逐 seed 的 clean bpc）：

| seed | `T` | `PE` | `WIDE`（等参数主干） | Δ_W = WIDE − T | Δ_P = PE − T | 残余 R = PE − WIDE |
|---|---|---|---|---|---|---|
| 0 | 1.8370 | 1.7513 | 1.8331 | **−0.0039**（落带内） | −0.0857 | **−0.0818**（5.8× 带） |
| 1 | 1.8328 | 1.7517 | 1.8576 | **+0.0248**（1.8× 带，更差） | −0.0811 | **−0.1059**（7.6× 带） |

**人话判读**：把**同一笔 8.5% 参数**给主干，第一个 seed 只买到 0.0039 bpc（噪声带 0.014 的
0.28 倍，等于没买到），第二个 seed 反而**差了** 0.0248。也就是说：**「多了参数」这件事本身
解释不了 `PE` 的增益**——同样一笔钱花在主干上买不到；`PE` 相对这个等参数对照臂还剩
**0.082 / 0.106 bpc**（5.8 / 7.6 倍噪声带）。所以这笔增益只能记在**「读出位置上的容量」**名下
（第一轮的说法「多给读出容量」），不能记成「参数总量是旋钮」（那条旋钮已在 `3.1.1` / `3.1.4`
判过，这里的读数与它同向：`3.1.4` 的总量斜率「每省 1% 每 token 算力 ≈ +0.0014 bpc」外推
+8.5% 只能买到约 0.010，实测 −0.0039 还在它之内）。

**硬币的另一面（必须一起读）**：`WIDE` 自己的跨 seed 散布是 **0.0245**，是 `T`（0.0042）与
`PE`（0.0004）的 5.8 / 61 倍，也大于本仓自认的种子散布上界 0.0138（`harness/methodology.md` §2）
⇒ s1 那个 **+0.0248** 含臂 × seed 交互与方差不稳，**不能**读成「加宽 FFN 有害」；能说的只有
「没有一个 seed 显示这笔钱花在主干上能追平 `PE`」。训练末窗 loss 的旁证同向：`WIDE` 对 `T` 是
+0.0123（s0）/ −0.0006（s1）（`train_log.jsonl` 末条，参考线、不进判据）。

### 6.1 判据应用（按预登记机械判定，未改判据线）

预登记的四分支（`README.md` §4-P5、`config.json::p5_rule`）按 0.014 带判 `Δ_W` 与 `R`：

| seed | Δ_W 相对 0.014 带 | 残余 R 相对 0.014 带 | 落入的分支 |
|---|---|---|---|
| 0 | −0.0039，带内 | −0.0818，越带 5.8 倍 | `params_not_the_explanation` |
| 1 | +0.0248，越带 1.8 倍 | −0.1059，越带 7.6 倍 | `params_explain_part` |

**两 seed 分支不一致 ⇒ 按预登记的 n 规则（`config.json::p5_rule::n2_rule`）判：
「本 n 下分支不可判」，不取平均掩盖。** 所需样本量按预登记近似式
`n_req = ceil((2.9·sd/|mean − band|)²)`（`results.json::cross_seed.P5_equal_param.n_req`）：

* `Δ_W`（决定分支的那个量）：两 seed 均值 **+0.0104**、sd 0.0203 ⇒ `|mean| < 0.014` ⇒
  **不存在有限样本量**能把 `Δ_W` 判成「越带且由参数解释」。换句话说：**「参数是全部解释」这个
  读法在任何 n 下都没有本地支撑**；
* 残余 `R`：均值 **−0.0938**、sd 0.017 ⇒ `n_req = 1` ⇒ **n=2 已足够**判「`R` 越带且方向为
  `PE` 更优」。

**所以两件事分开写**（这是本批最重要的一句）：

1. **明确回答：参数不是全部解释。** 残余 `R` 在**两个 seed 各自越带、方向相同**（−0.0818 /
   −0.1059，5.8 / 7.6 倍带），且**没有一个 seed** 显示等参数主干对照能追平 `PE`：s0 只买到
   0.0039（落带内，等于没买到），s1 反而差 0.0248 ⇒ 「多拿 8.5% 参数就能拿分」这一解释被两 seed
   共同排除。这笔增益的位置是**读出**。
2. **哪一条不可判**：`WIDE` 自己那一腿的**符号**（「主干花这笔钱落带内」还是「主干花这笔钱
   反而更差」）——`WIDE` 的跨 seed 散布 0.0245 大于种子散布上界，这一条要给判词需要更多
   seed，而按上面的公式，任何 n 都不能把它判成「正收益」。结论里不得把 s1 的 +0.0248 当成
   「加宽 FFN 有害」的证据。

### 6.2 副判据（只报告，不参与 `P5` 判词）

| 读数 | seed 0 | seed 1 | 来源 |
|---|---|---|---|
| `WIDE` 的 `tf@k` Δ 相对 `T`（深度 1 / 2 / 4） | +0.0125 / −0.0250 / −0.0051 | +0.0192 / +0.0313 / <0.0001 | `results.json::per_seed.s{0,1}.arm_rows.WIDE.delta_tf_by_depth` |
| `prob0` ECE（`T` 对照） | 0.0069（0.0062） | 0.0064（0.0056） | 同文件 `prob0_ece`（容差 0.003 内） |
| 出口 argmax 与 tied 表基坐标一致率 | 1.0 | 1.0 | 同文件 `tied_argmax_agreement`（构造性 1.0：`WIDE` 的读出就是 tied 表） |
| 评测确定性 / 因果性 | `reeval_bitwise_identical = true` | 同 | `results_WIDE_s{0,1}_12k.json` |

`tf@k` 在这条臂上两 seed 不同向（深度 2：−0.0250 vs +0.0313）⇒ 不构成任何方向性结论；
它本来也不是 `P5` 的判据量（`P5` 只判 clean bpc 残余）。

### 6.3 判据设计缺陷（本批新发现的一条，写在这里而不改判据线）

四分支规则对 `Δ_W` 取了**绝对值** ⇒ 它把「对照臂**更差**」与「参数解释了**一部分**增益」归到
同一个分支（`params_explain_part`）。s1 就是这样落进去的：`Δ_W = +0.0248` 意味着这笔钱在主干上
**什么都没买到、方向还是负的**，说「参数解释一部分」是错读。**正确的分支规则应当带符号**
（`Δ_W ≥ −band` 一律归「参数不是解释」），但这要**下一轮预登记**，不在本轮事后改
（本轮按原规则判「分支不可判」）。同类的第一轮事例是 `tf@k` 被当早退可用性主判
（`project.yaml::failure_analysis` ①）；这一条记为 ④。

### 6.4 边界

* `WIDE` 只代表「把这笔参数花在主干」的**一种**放法（每层 FFN 等宽加宽 144）；加层、加宽
  `d_model`、加宽 attention 未测 ⇒ 结论不得写成「主干多参数一律无用」。
* `WIDE` 改的是主干，因此它**不是** `T` 的逐位超集（加宽 FFN 改变 RNG 流），也不能与 `PE`
  共享初始化：两臂比的不是同一个模型，而是「同一笔参数花在哪」。
* 单尺寸（13M / 8L / V=206）、两 seed：不外推到真词表与更大规模。
