> 原始数字 = `results_<arm>_s0.json`（逐臂）+ `results.json`（汇总判据）；

## 0 人话摘要

**问题**：语言模型的「宽度」这只旋钮——把整个残差流和每层一起做小（`d_model` 256→192），
以及让训练期习惯多档宽度、推理时同一个权重切到不同宽度（弹性宽度）——到底值不值。

**干了什么**：在**训练/数据/配方逐位相同**、唯一变量 = 宽度分配的前提下跑了两条臂
（enwik8 字符级、13M 档、12000 步 = 98.3M token，seed 0）：

- `D192`（WP1）：uniform 减宽，d 256→192、头数 8→6（head_dim 恒 32）。引擎**原生**配置，无干预代码。
- `WD256`（WP2）：训练每步在宽度 {128,192,256} 等概率采样、只在前 w 个残差通道组成的前缀子网络上
  做前向；一个 checkpoint 推理时可切成三档**真变小**的原生模型。

对照组 = 另一只旋钮的两块锚（复用 2641 同配方实测）：`U4` = 全宽 stock（**1.5314**）、
`U2` = 全宽但 FFN 预算砍半（**1.5709**）。质量口径 = clean bpc（越低越好，噪声带 0.014）。

**答案（数字 + 参照系 + 人话量级）**：

1. **整体减宽明显要付质量税**：d 256→192 后 clean bpc 从 **1.5314 掉到 1.5841**，差 **+0.0527**。
   0.014 是项目自认的噪声带，**+0.0527 ≈ 3.8 倍噪声带 ⇒ 可排序：减宽更差**（不是抖动）。
2. **但它换来的算力也是真便宜，且略优于另一只旋钮**：D192 每 token 等效 **4,364,928 MACs**，
   比全宽省 **40.96%**；参数 **3,944,064**，比全宽少 **43.4%**。**每省 1% 算力付 0.001287 bpc**，
   而 FFN 砍半的 U2 是 **0.001392 bpc**（≈ 贵 8%）⇒ 在从 U4 出发的射线上，**整体减宽比砍 FFN 略便宜**。
   两者**互不支配**：U2 更准（1.5709）、D192 更省（4.36M vs 5.30M MACs）。
3. **弹性宽度（一训多档）在本尺度不成立**：同一个 WD256 checkpoint 切到三档，质量确实**单调**
   （1.6178 @256 / 1.6327 @192 / 1.7301 @128，越宽越好），**但每一档都比同宽「单独训」的模型差**：
   - 全宽档 256：**1.6178 vs U4 的 1.5314 = +0.0864**——**宽度 dropout 这个正则本身就把全宽模型弄差了**；
   - 192 档：**1.6327 vs 单独训的 D192 的 1.5841 = +0.0486**（越 0.014 带 3.5 倍）。

   人话：**「一次训练服务多档」没有白拿**——它让每一档都变差，最贵的全宽档亏得最多；这条路线在本尺度
   应当判**不成立**。
4. **排除了哪些别的解释**：
   - 减宽臂走原生 `--d/--heads`，没有构造后切片 ⇒「实现不等价」被排除；参数/维数审计逐位通过（§3）。
   - WD256 的「省算力可达」不是掩码假象：切片模型里**不存在任何 d=256 的张量**，实测参数 == 解析参数，
     活跃维 == 目标 w，且 T1/T2 等值门在 fp32 与 bf16 autocast 下**逐位相等**（§3）。
   - 质量变差不是「没训好」：同 seed、同步数、同 batch、同评测批（paired），脏得一致的只有宽度。

## 1 这条研究线是什么（六问）

1. **干什么的**：判断「宽度」是否是独立于 FFN 预算的设计维度，以及「一次训练多种宽度」是否免费。
2. **相对普通 decoder-only transformer 改了什么**：
   - `D192`：只把 `d_model` 与头数等比压小（head_dim 恒 32 ⇒ 6 头），FFN 隐藏维 `4d` 随之 1024→768；
     参数与每 token 算力按 ≈`(w/d)²` 缩。**没加也没减任何结构**，就是同架构更窄。
   - `WD256`：参数集合与全宽 stock **逐位相同**（同 seed 同构造），只改前向——训练每步采样
     `w∈{128,192,256}`，在残差通道**前缀子网络**上前向（QKV/attn-out/FFN 权重按前缀行/列取子矩阵，
     LN 与残差在活跃前缀上算，读出头取 `E[:, :w]`）。部署 = 把同一 checkpoint 的前缀子矩阵装进**原生
     d=w 的 stock 模型**（真变小，不是掩码）。
3. **为什么要改**：宽度是最直观的算力旋钮之一；若弹性宽度成立，一次训练可服务多档部署、省掉逐档重训。
4. **怎么测的**：唯一变量 = 宽度分配；其余全同（步数 12000、batch 32、seq 256、lr 1e-3、seed 0、
   mlp_mult 4、dense/sequential/uniform、tied 读出，与 2641 逐字段同）。指标 = **clean bpc**（最终深度、
   无退出、序列级、越低越好；`depth_curve` 固定 eval generator seed 2、n_batches=20、batch_size=16）。
   代价一律**等效理论量**（每 token MACs、参数量）；**墙钟/吞吐只进 `run_log.txt`，不进判据**。
5. **测出来多少**：见 §0 与 §4 表。
6. **结论与下一步**：见 §5。下一步最小实验 = 补 `D128:0`（WP1 第二档，本单因 GPU 队列未跑）以闭合 P5b。

## 2 接手者做的实现修正（不改数值路径）

1. **活性 hook 的 tuple 输出**（前一位 worker 冒烟 rc=1 的根因）：`Block.forward` 返回
   `(block_out, telemetry)` 元组，原 hook 写 `y = out.detach()` ⇒ 训练后活性测量抛 `AttributeError`。
   修法：hook 取 `out[0]`（tuple 主输出）。只改测量路径，不碰训练/评测数值。
   回归门 = `test_2642_uniform_narrowing.py::test_p4_liveness_hook_accepts_block_tuple_output`
   （在 D192 与 WD256 的三档切片模型上都跑；变异版 `out_t = out` 已验证会变红：AttributeError）。
2. **WD256 触发的共享活性探针**：共享 `train_depth_ar.main()` 训练后调 `kv_head_liveness(model, x)`，
   它在 `blk.qkv` 上挂 hook 并跑 `model(...)`；但 `WidthDropoutModel.forward` 走前缀子网络
   （`F.linear` 直接取 `blk.qkv.weight` 切片），qkv hook 一个都不触发 ⇒ 共享断言
   `len(widths)==n_layers` 失败（`pathlm/depth_ar.py:713`），冒烟 rc=1。
   修法（`run.py`，沿用其既有的 `TDA.DepthARModel` 工厂 monkeypatch 模式）：`train_arm` 期间把
   `TDA.kv_head_liveness` 换成安全包装——探测期改成「同 cfg、同 `state_dict`、原生 d=256 的 stock 模型」
   再跑原探针。WD256 在 w=256 的前向与 stock **逐位相同**（T1 门），且该探针只读 qkv **输出宽度**
   （形状类活性量），**不参与训练/评测数值路径、不入判据**。`pathlm/**`、`train_*.py` **零改动**。
3. **排程**：GPU 锁队列很长；接手者按主管 21:50 判据**放弃 D128:0**，正式臂 = `D192:0` → `WD256:0`（见 §6）。

## 4 数据表

### 4.1 WP1 与前沿（x = 每 token 等效 MACs，y = clean bpc，越低越好）

| 臂 | d / 头数 | clean bpc | Δbpc vs U4 | 每 token MACs | 算力 vs U4 | 参数量 | FFN 参数 |
|---|---|---|---|---|---|---|---|
| **U4**（锚，复用） | 256 / 8 | **1.5314** | — | 7,392,768 | 100% | 6,962,688 | 4,204,544 |
| **U2**（锚，复用，另一只旋钮） | 256 / 8（FFN r=2） | **1.5709** | +0.0395 | 5,295,616 | −28.37% | 4,861,440 | 2,103,296 |
| **D192**（WP1） | 192 / 6 | **1.5841** | **+0.0527** | 4,364,928 | **−40.96%** | 3,944,064 | 2,366,976 |
| D128（WP1） | 128 / 4 | **未跑**（GPU 队列，见 §6） | — | 2,123,520（解析） | −71.27%（解析） | 1,777,408（解析） | 1,053,696（解析） |

**每 1% 算力节省的质量代价**（= Δbpc(相对 U4) / 算力节省 %）：U2 = **0.001392**、D192 = **0.001287**
⇒ D192 在这条射线上**略便宜（约 −8%）**。D192 与 U2 **互不支配**（U2 更准、D192 更省）。

### 4.2 WP2 弹性宽度（同一 checkpoint 三档切片）

| 档（同一 `model.pt` 的前缀子矩阵） | clean bpc | 每 token MACs | 参数量 | FFN 参数 | Δbpc vs 同宽 uniform |
|---|---|---|---|---|---|
| WD256@256 | **1.6178** | 7,392,768 | 6,962,688 | 4,204,544 | +0.0864（vs U4） |
| WD256@192 | **1.6327** | 4,364,928 | 3,944,064 | 2,366,976 | **+0.0486**（vs D192） |
| WD256@128 | **1.7301** | 2,123,520 | 1,777,408 | 1,053,696 | 无同宽 uniform（D128 未跑） |

- 单调性：**严格单调**（128 > 192 > 256）。相邻档差：192→256 = **0.0149**、128→192 = **0.0974**
  ⇒ 192/256 两档**刚好可排序**（越 0.014 带），128/192 之间大幅可排序。
- 同一 checkpoint 证据：`model_pt_sha256` 单值、三档 `width`/`n_heads`/`hidden_by_layer` 逐档一致；
  训练期宽度采样直方图 ≈ 等概率（128:0.324 / 192:0.336 / 256:0.340，`runs/WD256-s0-12k/width_samples.json`）。
- 每 token 每省 1% 算力的质量代价：WD256@192 = **0.002473**、WD256@128 = **0.002788**
  —— 比 uniform D192 的 0.001287 与 U2 的 0.001392 **都贵约 2 倍**。

## 5 判据 P1–P5（对照 `results.json`）

- **P1（Δ vs U4，带 0.014）**：D192 **+0.0527 ⇒ 可分：减宽更差**（越带 3.8 倍）。
  D128 未跑 ⇒ 本判据只覆盖 d=192 一档。
- **P2（前沿对照，等算力位点）**：D192 与 U2 互不支配；按「每省 1% 算力付多少 bpc」，
  D192（0.001287）**略优于** U2（0.001392）⇒ **整体减宽与 FFN 减半各有所长，减宽不落下风**。
  WD256 两档（0.002473 / 0.002788）明显更贵 ⇒ 在同等算力位点上**弹性宽度不占前沿**。
- **P3（WD256 弹性）**：三档**单调**（越宽越好），但 **`|bpc_WD256@192 − bpc_D192| = 0.0486 ≥ 0.014`**，
  且 WD256 各档都更差 ⇒ **明确劣于同宽 uniform**。**弹性宽度在本尺度不成立（一训多档要付代价）**；
  尤其**全宽档也被拉低 +0.0864**（宽度 dropout 作为正则本身伤害容量）。
- **P4（必须不变/活性）**：
  - 评测确定性（`--no-train` 重评逐位一致）：**已跑、逐位一致**。D192：`bitwise_equal=true`、
    `bpc_by_depth_bitwise_equal=true`（1.5841 == 1.5841）。WD256 三档：`clean_bpc_by_width_bitwise_equal=true`，
    128/192/256 各自 `bitwise_equal=true`、`bpc_by_depth_bitwise_equal=true`。
    证据 = `reeval_D192_s0.json` / `reeval_WD256_s0.json`。
  - 因果性：D192 与 WD256 三档全 pass（改末位 ⇒ 前位逐位不变、末位必变）。
  - 活性：逐层 ‖out‖/‖in‖ 最小值 > 1（每层真参与前向）。
  - 参数/维数审计：实测 == 解析（D192、WD256 三档）；WD256 切片无全宽张量、活跃维 == 目标 w。
  - 等值门 T1/T2：fp32 与 bf16 autocast 下**全部逐位相等**（`equivalence_gates_all_pass = true`）。
- **P5（否证线）**：预登记脚本的 P5a/P5b 要求 D192 与 D128 **同时在场**；**D128 未跑** ⇒ 脚本按设计
  输出「D192/D128 结果缺失」，无法给出机器判定。据已有读数人工判读：
  - **P5a（噪声带）不成立**：D192 的 +0.0527 明确越 0.014 带 ⇒ 减宽在本尺度**要付可排序的质量税**。
  - **P5b（前沿优势）**：D192 的斜率 0.001287 **优于** U2 的 0.001392 ⇒ **不能判「d_model 减宽不占
    前沿优势」**；但只有 d=192 一档，**需 D128 复核**该斜率是否在更小宽度处反转。
  - **P5c（WP2 弹性）成立（即被否证）**：WD256@192 比同宽 uniform 差 0.0486 ≥ 0.014 ⇒
    **「一训多档」在本尺度不成立**，并如实落盘各档质量（不外推）。

**归因三分**（`docs/research-schema.md` §7）：WP1 属①**设计问题**（d_model 减宽本身在此尺度有明显质量税，
但每算力代价并不比 FFN 旋钮差）；WP2 属③**innovation 本身失败**（弹性宽度在 13M/12k 尺度不成立，
且全宽档被正则拉低），非实现问题——T1/T2 等值门逐位通过，实现是干净的。

## 6 未跑项、受阻与排程

  ⇒ 宽度 128 的读数只由 **WD256@128 切片**给出（1.7301），**没有同宽 uniform D128 对照**。
- **评测确定性重评（P4-①）**：**已跑、逐位一致**。两条臂各抢到一次锁间隙（`run_log.txt` 的
  `tight reeval lock acquired / tight reeval <arm> rc=0`）：D192 22:30:37–22:30:40、WD256 22:32:22–22:32:27。
  证据 = `reeval_D192_s0.json`（1.5841 == 1.5841）、`reeval_WD256_s0.json`（三档各自 prev == now）。
- 取锁与排程过程全在 `run_log.txt`（按臂取/放、臂间 ≥61 s；轮询 15s→4s→1s 自适应；**未杀任何他人进程、
  未动他人锁**）。

## 7 口径声明

- 质量口径 = clean bpc（最终深度、无退出、序列级、越低越好），eval 批固定 generator seed 2、
  n_batches=20、batch_size=16，与 2641 逐字段同口径（paired）。
- 方差带 = 0.014 bpc（`docs/research-schema.md` §12.1 / C1，限配对 Δ、≥5 窗口）。本实验另报历史同配置
  dense 13M/12k run 散布 1.5257 / 1.5287 / 1.5298 / 1.5314（极差 0.0057）作参照，不替代 0.014。
- 代价 = 等效理论量（每 token MACs：attention `4w²+2Tw`、FFN `2·r·w²`、tied 读出 `w·V`，V=206）。
  **墙钟/吞吐只进 `run_log.txt`，不进本文件任何判据或代价表述。**
- 锚（U4/U2）复用 2641 的 `results_*.json`，逐字段配置对照由 `--aggregate` 复核（`anchor_config_parity`）。
