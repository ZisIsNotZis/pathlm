# 2647 · 同层内位置相关宽度（3.1.3 / W-C）· 分析

判据与口径见同目录 `README.md`（**预登记、起跑后不改**）；本文件只做读数、判读与未做项声明。

## 0. 人话摘要（先看这段）

这份实验想问一件很具体的事：普通的 decoder-only transformer 在同一层里，序列中**每个位置都用同样多的通道**去算。如果让前 128 个位置用宽通道（256 维）、后 128 个位置用窄通道（128 维）
——或者反过来——能不能把「平均每 token 要算多少」降下来（按解析口径降 35%），同时不把模型质量弄坏？

做法是**同一套权重、只改每个位置用哪些通道**：窄段位置在这一层里只在残差流的**前 128 维**上运算
（LN、qkv、输出投影、FFN 都取权重的前缀子矩阵，FFN 隐藏维 4×128；q/k/v 的尾部 4 个头置零），
**注意力的可见范围一个字节都没改**。因此每个臂的参数逐位相同（都是 6,962,688），唯一差别是
「位置→宽度」这张表。

**现状（最重要的一段）：12k 步的两条臂（PN/NP）没有跑出来**——GPU 被仓里别的作业占着，我们的
作业从 23:29 起一直排在 `/tmp/pathlm_gpu.lock` 队列里（§5 有事实与时间戳）。所以
**P1（质量）与 P3 的两个臂（长程召回）没有读数、判不了**。按预登记契约，这属于「未跑」，
既不算通过也不算失败——**不能**把它读成「无差别」。

已经拿到手、可以独立复核的有三类：

1. **实现对不对**：10 条单测全绿，其中两条是硬门——「窄段宽度设成 256（等于不缩）时前向与
   stock **逐位相同**」和「attention 调用参数与 stock **逐位相同**」（可见集合没被碰过的证据），
   另有一条变异用例（把窄段掩码取错维度）证明这些门不是恒真；
2. **代价账**：平均激活通道 256 → 192（−25%）、每 token 等效 MACs 7,392,768 → 4,771,328
   （−35.5%），且 stock 的解析值 7,392,768 与锚 `2641/U4-s0` 的**实测**值逐位一致；
3. **长程召回探针在锚上的实测**：准确率 0（Wilson 95% 上界 0.0074，chance = 1/64 = 0.0156），
   答案位交叉熵 6.84，而「均匀乱猜」的交叉熵是 4.16（在答案集上）——**这个 13M/12k 步、
   只在 enwik8 上训过的 checkpoint 在这个零样本合成任务上连乱猜都不如**。也就是说这条召回列
   在当前 checkpoint 上只能量出「没学会」，量不出「窄段有没有丢长程信息」（§6）。

## 1. 它是干什么的 / 改了什么 / 为什么（六问）

1. **要它干什么**：让序列里「离查询很远的位置」和「正在被查询的位置」**不用同一个宽度的子网络**，
   从而在给定质量下把**每 token 平均等效算力**降下来（不是降参数量——参数一个都没少）。
2. **相对普通 decoder-only transformer 改了什么**：同一层内按**绝对位置**给不同位置不同宽度：
   宽段位置走全宽（256 通道 / 8 个头 / FFN 1024 隐藏），窄段位置走「残差流前 128 维上的子网络」
   （4 个头 / FFN 隐藏 512）。改动量级：窄段位置的每 token 乘加数按通道数平方缩放，两臂的
   每 token 平均等效 MACs 从 7.39M 降到 4.77M（−35.5%），**参数量不变**、**层数不变**、
   **attention 可见集合不变**。
3. **为什么要改**：对准的痛点是条件计算 / 位置相关容量这条路（local-global 分段处理的位置版）
   的承诺：同层内按位置省算力。它不改「位置能看到谁」（那是时间轴 `1.1`/`1.2`），也不改层数
   （深度轴 `2.1`）。
4. **怎么测**：对照 = stock 同层同宽全位置（锚 `2641` 的 `U4-s0` = 1.5314，13M/dense/12k/seed0，
   同 `depth_curve` 口径）；指标 = clean bpc（最终深度、序列级，越低越好）+ 每 token 平均激活
   通道数与等效 MACs（该跌）+ 零样本合成长程召回 `assoc-mqar`（K=8/Q=8/gap=14，rate 类走
   Wilson/配对 bootstrap，不跨量纲借用 0.014）；口径 = 等效理论量，**墙钟与吞吐不进判据**。
5. **测出来多少**：**质量与召回没有读数（未跑，见 §5）**；代价与实现对上了（§2/§3）。
6. **结论与下一步**：**判不了**（不是「没差别」）。下一步最小实验 = 抢到 GPU 后按
   `train_arms.sh` 跑 `PN:0 NP:0` 两条 12k 臂（每条约 8 min GPU + 评测），再跑三个模型的
   召回探针（纯推理，CPU 3 s / 个）。

## 2. 臂与代价（已定，可复核）

| 臂 | 位置→宽度（0..127 / 128..255） | 每 token 平均激活通道 | 每 token 等效 MACs | 相对 stock | 参数 |
|---|---|---|---|---|---|
| `FULL`（= stock，只做门与锚） | 256 / 256 | 256 | 7,392,768 | 1.000000 | 6,962,688 |
| `PN` | 256 / 128 | 192 | 4,771,328 | 0.645405 | 6,962,688 |
| `NP` | 128 / 256 | 192 | 4,771,328 | 0.645405 | 6,962,688 |

- 解析：每层每 token，宽 `w` 的 attention = `4w² + 2Tw`、FFN = `8w²`；按位置段加权再加 tied
  读出 `d·V`（`T=256, d=256, L=8, V=206`）。单测 `test_t3_analytic_cost_matches_independent_derivation`
  用**独立重推**的公式核对（不是引用实现里的常数）。
- 与锚对账：`FULL` 的解析 MACs = 7,392,768 = `2641/U4-s0` 的 `macs_per_token.total`（逐位）；
  `FULL` 臂装锚的 `model.pt` 时 `missing=[] unexpected=[]`、参数量 6,962,688 = 锚（逐位）。
- 实测（不只看代码）：单测 `test_t3_measured_channels_match_segment_width` 在一次真实前向里用
  forward hook 数了「进入 `qkv` 的非零通道数」与「GELU 之后进入 `mlp[2]` 的非零隐藏单元数」：
  `PN` = 256/128 与 1024/512，`NP` = 128/256 与 512/1024，与段宽逐位一致。

## 4. P1：质量（**未跑**）· P2：代价（解析 + 实测，已对上）

`PN` / `NP` 的 12k clean bpc **没有读数**：`results_PN_s0.json` / `results_NP_s0.json` 不存在
（训练作业一直在排队，§5）。因此：

- Δbpc(PN − 1.5314)、Δbpc(NP − 1.5314)、Δbpc(PN − NP) 三者**都没有值**，
  0.014 bpc 带的判读**没有做出**；
- 明确声明：**不是**「|Δ| < 0.014 的不可排序」（H0），也**不是**「越带退化」——是**未测**。

### P2（该跌：已跌，解析与实测一致）

## 5. GPU 锁饥饿：事实、时间戳与后果（本实验未跑完的直接原因）

- 本实验起工 2026-10-14T23:0x；`23:29:0x` 启动 60 步冒烟（`STEPS=60 HOLD_ALL=1`，
  detached，`smoke_driver.log`）；`23:30:17` 启动 12k detached supervisor-retry
  （`supervise_arms.sh`，`ARMS="PN:0 NP:0"`，`STEPS=12000`，deadline +4 h，`supervise.log`）。
- 两个作业都需要 `/tmp/pathlm_gpu.lock`。该锁从 23:17 起被另一个作业持有（`holder_pid`
  2620551 = 轴 5 的实验 `2656-lowrank-vs-headshare-13m` 的驱动进程），到本文件写成为止
  **一直没释放**（每次查看 `holder_pid` 都是 2620551，心跳在更新）。
- 同期在排队等同一把锁的还有：`2655-fp8-hd64`（其日志明确记了「等锁超时 600s」）、
  `2653`、`2651`、`2654`、`2646`、`2644`、`2645` 等（`pgrep -af supervise_arms` 可见多个实例）。
  单臂 12k 约 8–13 min，队列长度 > 5 ⇒ 在本轮时间盒（95 min）内拿到锁的概率很低。
- **本实验没有杀任何别人的进程、没有回收任何人的锁**（按 §9/§20 与派单边界）；发起的两个
  detached 作业仍在重试，**父级/integrator 可以继续收**：读数一落地就是
  `results_PN_s0.json` / `results_NP_s0.json`（`supervise.log` 里会记 `supervise DONE`），
  之后跑 `python3 run.py --aggregate` 即得 P1/P2 汇总。
- 60 步冒烟在锁饥饿下也**没跑成**；不过冒烟要确认的两件事——「窄段真的是窄的前向」
  与「attention mask 未变」——已由 CPU 单测 T2/T3b/T5/T6 **等价覆盖**（门在 CPU 上同样能变红，
  见 §3）。**GPU 训练路径本身未在 12k 作业里跑过**，这是本包的真实空缺。

## 6. P3 长程召回列：锚上的实测（已跑）与这条列的适用边界

预登记口径：在**同一个已训 checkpoint** 上用引擎自带合成任务 `assoc-mqar`
（`assoc_recall_multi_batch`：`n_pairs=8, n_queries=8, gap=14`，seq 256，`sym_vocab=64`，
chance = 1/64 = 0.015625）评测 `PN` / `NP` / 锚 `2641 U4-s0`，报 top-1 准确率 + Wilson 95% CI +
相对锚的配对 bootstrap ΔCI（率类，不跨量纲借用 0.014）。配对单元 = (序列, 查询)，
4 批 × 16 序列 × 8 查询 = **512**。

**已跑的部分（锚）**：`synth_anchor2641U4-s0_s0.json`（权重 = `2641/runs/U4-s0-12k/model.pt`，
sha256 `d4e6e33e…`，**设备 = CPU**、纯推理、确定性）：

| 量 | 值 | 参照 |
|---|---|---|
| top-1 准确率 | **0.0**（n = 512，命中 0） | chance（答案集均匀）0.015625；Wilson 95% CI 上界 0.0074 |
| 答案位交叉熵 | **6.835** | 乱猜 4.159（答案集 64）/ 5.328（模型词表 206） |
| 距离 | 107–240（中位 147） | gap=14 ⇒ 局部窗口里没有任何符号 |

判读：这个只在 enwik8 上训过 12k 步的 13M 模型，**在这个零样本任务上比乱猜还差**
（CE 6.84 > 4.16，准确率 0），说明它根本没有「按 cue 找回远端 (key,value)」这个能力。
因此：

- 这条列在当前 checkpoint 上的**分辨力下限**很差：三臂若都贴地板（0 命中），配对 bootstrap 的
  Δ 恒为 0，CI 也几乎退化为 [0, 0] ⇒ 会得到「不可分」，但那只是「三者都不会」，**不是**
  「窄段没丢长程信息」。这一点必须在判读里说清楚，不能把「都贴地板」当成「该不跌」的证据；
- **`PN` / `NP` 两个臂的探针未跑**（没 checkpoint）；契约要求的「三臂同框」没有完成；
- **后加的辅助列（不是判据）**：为了在地板区仍有分辨力，探针多落了一个「答案位交叉熵」
  （`answer_ce_mean`）与配对 ΔCE（`paired_delta_ce_vs_anchor`）。它在起跑后加入，理由见上；
  **判据仍是准确率 + CI**，CE 只作辅助，且这一条的加入写在这里声明。
- 下一步成本：若要把这条列变成有分辨力的判据，需要**在分布内训练**该任务（契约 U 的协议：
  `--synth-task assoc-mqar --synth-pairs 8 --synth-queries 8 --synth-gap 14`，约 8 min/臂）或改用
  一个真会做的 checkpoint；零样本直评在本仓 13M 档上已被证明不可用。

## 8. 口径、禁入项与自认弱点

- 口径：一切质量读数 = clean bpc（最终深度、序列级、`n_batches=20, bs=16`, eval seed 2）；
  一切代价 = 等效理论量；**墙钟/吞吐只出现在过程日志里，未进任何判据**；率类指标走 CI，
  bpc 差走 0.014 带，不跨量纲借用；结论不越 13M / 12k / seq 256 / seed 0 外推。
- **自认弱点 1**：主判据（质量）**没有读数**，本包只有实现对门 + 代价账 + 锚的召回探针；
  因此本实验**不能**用来做「位置相关宽度值不值」的判断，只能作为「跑得起来的完整装置 + 已对账的
  代价 + 一条被证伪可行性的探针」。
- **自认弱点 2**：召回列的零样本设计在本仓 13M 档上事后来看是无效的（锚即贴地板），
  这是**预登记口径的缺陷**（我把「零样本探针」当成了有分辨力的列），应在下一轮改成分布内训练
  探针；另外 `GATE` 臂（位置 gate）按派单允许只落契约未跑，所以「位置 gate 能不能比固定分段更好」
  这一问完全没有回答。
- 另注：`PN`/`NP` 只有 seed 0（无跨 seed 散布），分段只测了「绝对位置前/后 128」这一种定义
  （「距离近端/远端」「内容分区」两种定义未测），这些都已登记在 `README.md` §9。
