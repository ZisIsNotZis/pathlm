# 2641 · 前馈隐藏比的质量-代价前沿 + **等 FFN 预算**下的逐层非均匀宽度 · 13M · dense

## 1. 命题（一句话，可证伪）

在**训练/数据/主干逐位相同**、且**每 token 等价 FFN 算力与 FFN 参数量逐位相等**的前提下，
把 FFN 隐藏宽按深度**非均匀**分配（金字塔 / 倒金字塔）相对**等宽**分配，
能否把 clean bpc 改善超过项目方差带（0.014）？

- **H1（备择）**：非均匀分配在等 FFN 预算下相对等宽可排序更优（按 0.014 带判）；
- **H0（零假设）**：非均匀分配相对等宽**不可排序**（|Δbpc| < 0.014）⇒ 在本尺度，
  「FFN 宽度沿深度怎么分」不是独立于「总 FFN 预算」的设计维度。

本条直接对准轴的**核心问题**：非均匀宽度能不能在**同一质量-代价前沿**上、
用**相同或更少**的等效算力拿到**类似**质量。若 H0 成立，则宽度轴（3.1.2 / 3.1.4 的
「逐层变化」半边）在本尺度上只剩「总量」这一个自由度，逐层分配是记账噪音。

## 2. 单因素声明

**唯一变量 = 每层 FFN 中间维 r_l·d（逐层 FFN 宽度分配）**。

- 基底 = 主流标准 decoder-only transformer（`train_depth_ar.py --dense`：无 carry 门、
  无退出采样、仅最终深度 CE；= stock 形态 + 共享底座三条必要偏离，见 `docs/design.md` §2）；
- attention / LN / embedding / 位置嵌入 / 读出（tied 线性）**逐位相同**；
- 数据、步数、批大小、lr、seed、评测批（`depth_curve` 固定 generator seed 2）全同；
- **非必要性例外：无**。

### 2.1 干预实现（为什么它不是「换了个模型」）

所有臂都先用**同一个** (`depth-ar` 引擎，未改动) 构造 `DepthARConfig(..., mlp_mult=4)`
的完整模型 —— 即所有臂的 embedding / attention / LN / FFN 权重**来自同一次随机初始化抽样**。
之后本实验**只对 FFN 的两个矩阵做前缀切片**，使第 l 层隐藏维变成 r_l·d：

```
narrow_ffn_prefix(model, r_schedule):
    lin1 = blk.mlp[0]   # Linear(d, 4d)      → 只保留前 r_l·d 行（含 bias）
    lin2 = blk.mlp[2]   # Linear(4d, d)      → 只保留前 r_l·d 列
    （mlp[1] = GELU、mlp[3] = Dropout 接线不变）
```

于是臂与臂之间**唯一**的差别是「保留了多少 FFN 中间通道、在第几层保留」——
这既不是「不同初始化的两个模型」，也不是「不同参数量的两个模型」（见 §3 的 r 对齐）。
切片的实现等值性由 §8 的等值性门（T1–T3）钉住：均匀 r=2 的切片模型与引擎原生
`mlp_mult=2` 模型**逐位同前向**。

> **为什么不用引擎原生 `--mlp-mult` 做逐层臂**：`mlp_mult` 是**全局**标量，引擎没有
> 「逐层 FFN 宽」开关（`pathlm/depth_ar.py` 的 `Block` 只接受 `cfg.mlp_mult`）。
> 本实验因此把逐层 schedule 实现在**实验目录内**（不碰共享 `pathlm/**`、不碰
> `train_*.py`）。「把该开关收进引擎」的申请已按边界纪律记入
> `.scratch/64-axis3-width/TICKET.md`（含最小 patch 描述），由 Main 裁决，本实验不擅改。

## 3. 臂与r对齐（等 FFN 预算）

d = 256，L = 8，r_max = 4（= stock）。**Σ_l r_l 与 Σ_l r_l² 口径见下表**：
每层 FFN 参数量 = 2·r_l·d²（+ 小偏置），每 token 每层 FFN MACs = 2·r_l·d²
⇒ **两个量都只依赖 Σ_l r_l** ⇒ 「Σr 相等」= 「FFN 参数逐位相等」+「每 token FFN 算力逐位相等」。

| 臂 | r 向量 (l=1..8) | Σr | FFN 参数（解析） | 每 token FFN MACs（解析） | 含义 |
|---|---|---|---|---|---|
| **U4** | 4,4,4,4,4,4,4,4 | 32 | 8·2·4·256² = 4,194,304 | 8·2·4·256² = 4.19M | stock = **代价 100% 参照** |
| **U2** | 2,2,2,2,2,2,2,2 | 16 | 2,097,152 | 2.10M | **等宽**（等 FFN 预算的对照臂） |
| **PYR** | 4,3,2,2,2,1,1,1 | 16 | 2,097,152 | 2.10M | 金字塔（前宽后窄） |
| **APYR** | 1,1,1,2,2,2,3,4 | 16 | 2,097,152 | 2.10M | 倒金字塔（= PYR 的镜像） |

- PYR 与 APYR 是**同一条宽度多重集 {4,3,2,2,2,1,1,1} 的两种深度顺序** ⇒ 两者之间
  连「宽度取值集合」都完全相同，只有**深度顺序**不同。这是对「深度顺序有没有信息」
  的最干净对照。
- 训练侧一切超参相同；**逐位相同**由同一次初始化 + 同一 `train()` 代码路径保证。

## 4. 判据线（**预登记，不可改**）

| # | 判据 | 该涨 / 该跌 / 必须不变 | 判定规则 |
|---|---|---|---|
| **P1** | 等 FFN 预算下的逐层分配差：`Δ_up = bpc_U2 − bpc_PYR`（正 = PYR 更好） | 该涨（备择）/ 不可排序（零假设） | `Δ_up ≥ +0.014` ⇒ **可分、顺序有增益**；`\|Δ_up\| < 0.014` ⇒ **不可排序（H0 成立）**；`Δ_up ≤ −0.014` ⇒ 非均匀**反向**有害 |
| **P2** | 镜像对照：`Δ_down = bpc_U2 − bpc_APYR` | 同 P1 | 与 P1 联合读：两臂**同向可分**才叫「顺序有增益」；一正一负 ⇒ 判「顺序有效但方向由 schedule 定」；两者都带内 ⇒ H0 |
| **P3** | 前沿斜率：`(每 token 等价 MACs, clean bpc)`，以 U4 = 100% 代价为原点 | 该跌（代价）/ 该不跌（质量） | 报 U4→U2 的 `Δbpc per 1% FLOPs` 与三/四点支配关系（谁被谁支配，含等代价平局判定） |
| **P4** | seed 复现 | 该不变 | 同一 Δ 在两个 seed 上**同号**；不同号 ⇒ 该 Δ 记为「不可复现」，只报带 |
| **P5** | 对照与等值性门 | 必须不变 | U4-s0 的 clean bpc 与历史 dense 13M 锚（`.scratch/23-depth-ar/evidence/23d-dense-B-12k` = **1.5287**；2613 全新重训 baseline-s0 = **1.5257**）之差 < 0.005 ⇒ 本实验与既有 dense 主干同引擎、同配方 |
| **P6** | 干预活性（`SCHEMA.md` §10） | 必须报 | 逐层 FFN 隐藏维审计 == schedule（逐位）；逐层 FFN 输出相对幅度非零（窄层不是死路径） |

- 质量口径 = **clean bpc**（`DepthARConfig(dense=True)` 下只有最终深度被监督 ⇒
  `depth_curve()[-1]["bpc"]`，序列级、越低越好），eval 批固定 seed 2（臂间同一批）。
- 方差带 = **0.014**（`docs/methodology.md` §2：13M 跨 run bpc 漂移界）。
  本实验另报**同配置跨 seed 实测散布**（2613 的 baseline s0/s1 = 1.5257/1.5298 ⇒ 0.0041）
  作参照，但**不以它替代 0.014 预登记门槛**（口径选择属框架性取舍，上报 Main）。

## 5. 对照与方差

- 自包含：**全部臂本实验从头训练**，不复用任何历史 run 作手臂（历史只作 §4-P5 的等值性锚）。
- n = 2 seed（0 / 1）：每臂在两个 seed 上重训；报逐 seed 值、逐 seed Δ 与跨 seed 极差。
- 两臂之间不得比较不同 token 预算：所有臂 `steps=12000, batch=32, seq=256` =
  **98.3M token**（enwik8 前 90M 的 1.09 epoch）**matched-step / 同 token 预算**。
- 收敛对账（`SCHEMA.md` §16）：报每臂**同方法**（末 25% 同一窗口、同一最小二乘）
  训练 loss 斜率，防「某臂收敛更慢」被读成「质量更差」。

## 6. 规模、预算与显存

- 规模：13M 档（d=256 / L=8 / h=8 / T=256 / B=32）＝本仓全部 26xx 实验的同一档。
- **`gpu_wall_budget: 60 min`（唯一数字，含冒烟 + 全部臂 + 全部评测）**；GPU 按
  `SCHEMA.md` §20 互斥锁**按臂取/放**（臂间 ≥60 s）。
- 预算不够时砍什么（`SCHEMA.md` §8）：先砍**臂数**（先砍 U4-s1，再砍 APYR-s1），
  再砍 seed 数，**不砍判据线、不砍步数**（步数一改臂间刻度就不可比）。
- 显存：13M dense 形态峰值 ≤5GB net（共享卡礼貌线，§20.2 记账）。

## 7. 指标表（逐项分析，不合成单一分数）

| 维度 | 指标 | 与谁比 |
|---|---|---|
| 解决什么问题 | 逐层 FFN 宽度分配是否独立于 FFN 总量的设计维度 | — |
| 代价 | 每 token 等价 MACs（FFN / attention / 读出分列）+ FFN 参数 | U4（100%）/ 臂间 Σr 相等 |
| 有效性 | clean bpc（越低越好，须越 0.014 才可排序） | U2（等宽、等预算）+ U4（100% 代价锚） |

| 可控性 | r_l → bpc 的单调/方向性（PYR vs APYR） | 互为镜像 |
| 副产品 | 逐层 FFN 输出幅度（哪层 FFN 被真用） | 臂间 |
| 活性 | 逐层隐藏维审计、等值性门（P6/P5） | schedule 定义 |

## 8. 等值性门与变异验证（`SCHEMA.md` §9 / `docs/methodology.md` §5）

单测文件 `test_2641_ffn_ratio.py`（自包含，不改共享 `tests/`）：

- **T1 同前向（等值性）**：引擎原生 `mlp_mult=2` 模型 A 与本实验「`mlp_mult=4` 构造 +
  均匀 r=2 前缀切片」模型 B，把 A 的 `state_dict()` 装进 B ⇒ 两者**逐位同前向**
  （同输入 max\|Δlogit\| == 0）⇒ 切片实现与引擎原生窄 FFN 等价。
- **T2 参数审计**：按 schedule 解析式算出的 FFN 参数 / 总参数 == 实测（逐位）。
- **T3 变异（必须抓红）**：把切片「故意切断」（少切一层 / 切错维 / 不切）⇒ 参数审计与
  T1 必须变红；证明这三个门不是恒真的摆设。
- 训练侧另有 300 步冒烟（`smoke_stock_300`，记录步时/显存，不入判据）。

## 9. 否证条件（做不出来时怎么区分）

- 若 P1 与 P2 都落在 0.014 带内 ⇒ **H0 成立**：判「逐层非均匀 FFN 宽度在等 FFN 预算下
  无可排序增益」，本读数并入 `3.1.2`（逐层宽度变化）的深度形状结论，本项不再单独主张。
- 若 P5（等值性门）失败 ⇒ 视为**实现/口径问题**，先修实现再判机制（不得据此判机制失败）。
- 若 P4 不同号 ⇒ 记为**方差问题**（不可复现），结论只写「不可排序」，不写方向。
- 归因三分（`docs/research-schema.md` §7）：判负时必须区分
  ①**设计问题**（FFN 逐层分配本身在此尺度无头寸）②**结构问题**（引擎/接线逼出的退化，
  如切片实现不等价、attention 占算力比过大使 FFN 分配无从体现）③**innovation 本身失败**
  （「非均匀宽度」这条路线在等预算下不成立）。

## 10. 既有做法（`SCHEMA.md` §18，先站巨人肩膀）

- FFN 隐藏比与 GLU 变体（Shazeer 2020 的 SwiGLU r≈8/3 等价取舍）——本实验**不重造 GLU**，
  只固定 GELU 配方调 r；外部条目标 `记忆·未核`（本环境检索不可用），只作设计方向、**不作判据**。
- 逐层宽度 / 深度方向 capacity schedule（金字塔、hourglass、结构化剪枝的 schedule 一族）：
  业界把它当 NAS / 剪枝的副产物，**少见**在「等 FFN 参数 + 等每 token FFN 算力 +
  同一次初始化」下做的**受控单因素**读数 —— 本实验的增量就在这个受控对照与其
  在**本项目自己的**质量-代价前沿（13M / enwik8 / 0.014 带 / matched-step）上的位置。
- 结论**不假设**业界已有定论方向（不写「金字塔一定更好」）；PYR 与 APYR 互为镜像正是
  为了不预设方向。

## 11. scope 与混杂声明（`SCHEMA.md` §4）

- 单轴单格：只改 `3.1.4 前馈隐藏比`的「逐层变化」半边；与深度轴 `2.3.1`（逐层容量）
  在实现上相邻，本实验只读**FFN 宽**这一面，深度形状读数归 `2.3.1`；
  「整体 d_model 逐层变化」（`3.1.2`）本实验**不测**（引擎无该开关）。
- 已知混杂/局限（写死在契约里，防事后解释）：
  1. 逐层宽度不同的模型**参数量相等**但**每层计算量不等** ⇒ 层间流水节拍由最宽层决定，
     本实验只报**每 token 等价 MACs 总和**与**每层分布**两列（不用任何时间量）；
  2. 前缀切片让「保留哪些通道」与通道下标相关；在 i.i.d. 初始化下保留子集是 i.i.d. 的，
     因此不引入方向性偏置，但**同一层窄臂的存活通道是宽臂的前缀**（这是刻意的：
     它让臂间初始化完全一致）；
  3. 13M / 12k 快照：只读臂间增量，绝对水平是快照值（`SCHEMA.md` §20.3）；
  4. 单任务（enwik8 字符级 next-token）：结论不外推到其他任务/规模。
