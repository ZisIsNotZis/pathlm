# 2644 · 通道稀疏激活（per-token top-k 条件计算 vs 固定前缀常开）—— 分析与结论

## 0. 人话摘要

**这个实验在问什么。** 普通 transformer 每个 token 都把 FFN 的 1024 个隐藏通道全算一遍，不管这个
token 难不难。本实验把 FFN 权重**一个不少地留着**（总参数量逐臂逐位相同，6 962 688），只改前向里
「哪些通道参与」：`K50` / `K25` 每个 token 按 `|pre-activation|` **动态**挑 512 / 256 个通道，
`F50` 是**无条件性的退化对照**（固定常开前 512 个通道，不挑），`D` 是 dense 锚（复用 `2641` 的
`U4-s0`，1.5314）。要回答的是两件事：①「保参数、少算通道」换掉多少质量；②「按内容挑通道」比
「固定砍一半」更强吗（即条件性本身有没有独立收益）。

**量出来的结果（同一配置、12k 步 / 98.3M token、clean bpc 越低越好；主表 = seed 0，`K50`/`F50` 另有 seed 1 见 §2.1）。**

| 臂 | 每 token 总 MACs（相对 `D`） | 实省的算力 | clean bpc | Δ vs `D`（正 = 更差） | 越 0.014 带 |
|---|---|---|---|---|---|
| `D`（dense 锚 `U4-s0`） | 7 392 768（×1.000） | — | **1.5314** | — | — |
| `F50`（固定前缀 512 通道） | 5 295 616（×0.716） | −28.4% | 1.5678 | +0.0364 | **越带（2.6×）** |
| `K50`（按内容选 512） | 6 344 192（×0.858） | −14.2% | 1.6295 | +0.0981 | **越带（7.0×）** |
| `K25`（按内容选 256） | 5 819 904（×0.787） | −21.3% | 1.6417 | +0.1103 | **越带（7.9×）** |

**三条结论（人话）。**

1. **「只激活部分通道」是真实但很贵的旋钮。** 三个稀疏臂都省下了实打实的每 token 算力
   （−14.2%～−28.4%，`K50` 因为必须先算全部 pre-activation 才有得挑，只能省 14.2%），代价是
   0.036～0.110 的 clean bpc，全部越出 0.014 噪声带。**没有一臂落在「省算力不吃质量」的区间里**。
2. **条件性本身没有收益，反而是负的。** 预登记的主判 `K50` vs `F50` = **+0.0617**（4.4× 带）：
   按内容挑一半，比干脆固定常开一半**更差**，而且它的算力还更高（6.34M vs 5.30M MACs，+19.8%）。
   即：在这套「用 `|pre-activation|` 大小当选择器」的实现下，**把选择交给每个 token 的决定，比不上
   把哪一半写死**。所以「保参数、按内容选通道」这条路线**没有**在本尺度上打开一条新的前沿维度。
3. **「留着参数但不用」比「把参数砍掉」好还是差，本项判不了。** 在同一每 token 算力位点
   （5 295 616 MACs），`F50`（保参数、砍计算）1.5678 对 `U2-s0`（`2641`：FFN 参数也减半）1.5709 ——
   相差 0.0031。但这是**两条独立 run 的读数**（不同 checkpoint、不同臂，`U2-s0` 是复用锚），
   本项**没有这一对的配对读数**，而 0.014 带只对「配对 Δ、≥5 窗口」成立 ⇒ 0.0031 只能当
   **参考线**：既不称「不可分辨」，也不称「可分辨」，这一档**本项无判词**。

**seed 1 复现（n=2）。** 主判的两臂 `K50` / `F50` 又在 `seed 1` 上整程重训（同配方、同 12k 步）：
`K50` 1.6263、`F50` 1.5625 ⇒ Δ(`K50` − `F50`) = **+0.0638**，与 seed 0 的 +0.0617 同向、同量级、
同样远越 0.014 带（4.6×）。逐臂对 dense 锚的 Δ 也同向：`K50` +0.0949（6.8× 带）、
`F50` +0.0311（2.2× 带）。⇒ 主判不靠单点快照。

**为什么不是「机制无效」而是「本设计下有害」。** 坍缩门（`README.md` §4 的 P2/P4）是绿的：`K50` 的
逐 token 选择一致率 `mode_set_share` = **0.0**（Wilson 95% CI `[0.0, 6e-06]`），选择熵
`H/logH` = 0.980（坍缩端是 0.900、均匀随机端是 1.0）；`K25` 同理（0.0 / 0.938，坍缩端 0.800）。
⇒ 两个内容臂**确实在逐 token 换通道**，没有退化成固定前缀。`F50` 的 `mode_set_share` = 1.0 是
构造性的上界（它恒选同一批通道）。所以上表的「更差」不是「选了个寂寞」，而是「真选了、还更差」。

**一句话**：在 13M / 1.1 epoch 的受控设定里，总参数不变、每 token 只算部分 FFN 通道能把算力降到
0.72–0.86 倍，但质量代价 0.036–0.110 bpc（2.6–7.9 倍噪声带）；把「哪部分」交给 token 自己按内容挑，
比固定砍一半更差 +0.0617 且更费算力 ⇒ **本设计下条件性无收益、且为负**。

## 1. 口径与设备

- **设备**：单卡 RTX 4090（训练）；评测与活性探针同设备（`DEVICE = "cuda"`，同一台机器、同一批
  评测窗口序）。臂间逐臂取放 `/tmp/pathlm_gpu.lock`（`SCHEMA.md` §20.1），臂间 ≥61 s。
- **判据线**：`README.md` §4（预登记、不可改）。主判 = `clean bpc` 配对 Δ 对 dense 锚，带 = 0.014
  bpc；率类（选择一致率 / 熵）走 Wilson 95% CI 与 batch 聚类 bootstrap，**不跨量纲借用** 0.014。
- **锚复用**：`D` = `2641-ffn-ratio-frontier-13m` 的 `U4-s0`（1.5314），`U2-s0`（1.5709）作同算力
  参照；复用按 `SCHEMA.md` §9 三道门（本实验 `mask ≡ 1` 时前向与 stock 逐位相同的等值门由
  `test_2644_channel_sparsity.py::T1` 钉住、变异 `T2` 钉住它不是恒真）。
- **每臂配方**：`d=256, layers=8, heads=8, seq=256, mlp_mult=4, steps=12000, bs=32, lr=1e-3, seed=0`，
  enwik8 字符级（vocab 206），98 304 000 token/臂。评测 `n_batches=20, batch_size=16,
  eval_generator_seed=2`，两趟曲线逐位相同（`reeval_bitwise_identical = true`，三臂全 True）。
- **算力口径**：等效理论量 MACs/token（`cost` 字段），**墙钟不进判据**。实现口径（primary）=
  「按内容选通道必须先把全部 pre-activation 算出来」⇒ `lin1` 的 `d·H` 省不掉，`K*` 只省 `lin2`
  ⇒ `K50` 真实省 FFN 的 25%（不是名字暗示的 50%）；`F50` 固定前缀可以同时切两个矩阵 ⇒ 省 50%。
  两列都报（`ffn_macs_impl` / `ffn_macs_contract`）。
- **臂表：预声明 → 实跑（替换已声明）**。研究项 `method` 预声明的四臂是 {stock 全通道,
  通道 top-k 激活, 门控稀疏, 极化（一半常开 / 一半条件开）}；本实验实跑 {`D` dense 锚, `K50`,
  `K25`, `F50`}，对应关系与替换如下：
  - 「通道 top-k 激活」= `K50` / `K25`：按 `|pre-activation|` 逐 token 取 top-k，**选择器无参数**。
  - 「极化」**只以退化形态实跑**：`F50` 把「条件开」的那一半**恒关**（固定常开前 512），
    是极化在「门控恒定关闭」处的特例；带门控的真极化（条件半区按 token 开合）**未测**。
  - 「门控稀疏」**未测**：它需要可学习门控（+ 常见负载均衡辅助项），本轮把「选择信号从哪来」
    单独隔离，只用无参数幅度选择器。
  - **对判词范围的影响**：下面所有判词只覆盖「用既有激活幅度逐 token 选」与「固定前缀」两种形态；
    **不覆盖**带可学习门控 / 真极化的形态（已登记在 §10 与 `project.yaml::gaps` / `failure_analysis`）。

## 3. 主判：条件性 vs 无条件性（P4）

| 量 | 值 | 判读 |
|---|---|---|
| Δ(`K50` − `F50`) | **+0.0617** | 越 0.014 带 4.4 倍，方向「`K50` 更差」 ⇒ **条件性有害** |
| 同判据下的算力对比 | `K50` 6 344 192 vs `F50` 5 295 616 MACs/token（`K50` 贵 +19.8%） | `K50` **又贵又差** |
| `K50` 的 `mode_set_share` / Wilson 95% CI | 0.0 / `[0.0, 6e-06]` | 选择逐 token 真变化（坍缩上界 = 1.0） |
| `K50` 的选择熵 `H/logH` | 0.979831（坍缩端 0.9、均匀端 1.0） | 接近均匀端，未坍缩 |
| `F50` 的 `mode_set_share` / CI | 1.0 / `[0.999994, 1.0]` | 构造性坍缩上界（无条件性对照） |
| Δ(`K50` − `F50`) 逐 seed | seed 0 **+0.0617**、seed 1 **+0.0638** | 两 seed 同向、同量级、均越带（`results.json::cross_seed`） |

**判词（预登记 P4 的第三个分支）**：`K50` 可排序劣于 `F50` ⇒ 「条件性**有害**：固定前缀更优」。
H1（条件选通道可排序更优）**被否证**；H0（不可排序）也**不成立**——两者不但可排序，而且差距比带大
4.4 倍。坍缩分支（「使用率坍缩到少数通道 ⇒ 机制失效」）**未命中**。

## 5. 活性列（P2：坍缩门）

| 臂 | 逐层「至少被用过一次」的通道数（8 层） | 选择熵 `H/logH`（坍缩端 / 均匀端） | `mode_set_share` | 反传探针：有梯度的 `lin1` 行数（末层） |
|---|---|---|---|---|
| `K50` | 1024 / 1018 / 1023 / 1019 / 1023 / 1024 / 1023 / 1024 | 0.980（0.9 / 1.0） | 0.0 | 1023（全部通道参与梯度） |
| `K25` | 961 / 849 / 857 / 858 / 855 / 823 / 781 / 732 | 0.938（0.8 / 1.0） | 0.0 | 688 |
| `F50` | 512 × 8（构造性） | 0.900（= 坍缩端） | 1.0 | 512（未用的一半恒 0 梯度） |

- `F50` 的反传探针是对 `README` §8 `T4` 的**训练后实测版**：未用的后 512 个通道的 `lin1` 行 /
  `lin2` 列梯度恒 0，而参数仍在账上（总参数与 `K50`/`K25` 逐位相同 6 962 688）。
- `K25` 的末层只有 688/1024 个通道**在探针批上**拿到了梯度（探针 = 一批前向 + 一次反传），
  不能读作「整个 12k 步都没被选到过」——探针只覆一个批次的 token。
  都没被选到过**（选择器无参数、只按 `|pre|`，被压到低幅度的通道难以翻身）。这是「按幅度选」的
  自强化副作用，不是坍缩（`mode_set_share` 仍为 0）。

## 7. 局限与口径偏差

- **n = 2（`K50` / `F50` 各有 seed 0、1），`K25` 仍 n = 1**：两 seed 只给「方向一致 + 幅度量级」，
  **不给方差估计**；`2641` 同配置跨 seed 散布 1.5257 / 1.5298 可作参照。
- **matched-step 而非渐近**：末窗斜率仍为正（+0.0042～+0.0050 /1k 步）⇒ 三臂都未收敛到平台，
  绝对水平只在本 12k 步预算内可比。
- **`K50` 的训练日志含重复追加**：`K50` 臂先后起跑多次（评测端故障，见下），`runs/K50-s0-12k/`
  的 `train_log.jsonl` 累积了多份同配置日志，末窗斜率按 `step ∈ [9000, 11999]` 过滤后取到
  64 个点（其余两臂 16 个点）。因为各次都是同一 seed/同一配置，斜率读数不受方向影响，但**点数是
  重复的**，如实记在这里。
- **装置修复（口径偏差已声明）**：`ffn_dead_zone` 探针原先在 `evaluate` 的 `no_grad` 上下文里调
  `loss.backward()`，必然抛 `RuntimeError: element 0 of tensors does not require grad`，因此
  **先前几次起跑都在训练完成后、出读数之前崩掉**（训练本身已完成、`model.pt` 已落盘）。
  重跑把探针改成自持 `torch.enable_grad()`：`K50` / `F50` 用已落盘 checkpoint 走 `--no-train` 重评，
  `K25` 从头训练。逐臂读数的代码版本可核：seed 0 三臂的 `results_<臂>_s0.json::code_hash_run_py`
  = `4d1865b1…`，它逐字节等于提交 `6e34d95` 的 `run.py` **去掉 `--aggregate` 段里的 `delta_directions`
  五行**后的内容（`git show 6e34d95:…/run.py` 删这五行后 sha256 应为该值）；seed 1 两臂与本次聚合的
  版本哈希分别落在 `results.json::arms_by_seed.*.s1.code_hash_run_py` 与 `results.json::code_hash_run_py`
  （本轮补 seed 1 时对 `run.py` 的改动**全在 `aggregate()` 内**，`--arm` 的评测路径一字未动）。
  而 seed 0 的产出版本相对预登记提交 `7e47522` 的 `run.py`，**唯一源码差异就是这条探针的
  `torch.enable_grad()` 包裹**。
- **训练侧数字是转的、不是重测的**：`results_<臂>_s0.json::shared_train_results`（`params` /
  `train_tokens` / `wall_minutes` / `peak_gpu_mem_mb`）由评测入口从该臂自己的
  `runs/<臂>-s0-12k/results.json` 读入，属训练 run 的记账，**不是** `--no-train` 重评时的重测值；
  重评只重算 `eval` / `activation_profile` / `dead_zone_probe` / `causal` 这几块。
- **选择器开销未计入 MACs**：每层每 token 一次 `H` 元素 top-k（约 `H` 次比较）不计入上表 MACs
  （`README` §3 已声明）。若计入，内容臂相对固定前缀臂更不划算——本表的口径对 `K*` 是**宽容**的。

## 10. 下一步（最小实验 + 成本）

- **换一个有学习信号的选择器**（`README` §9 的决策树里没有的形态）：本项的 `|pre|` 选择器无参数、无辅助
  损失，P4 的结论只覆盖「用既有激活幅度当信号」这一形态。最小实验 = 加一条 `K50` 变体臂，选择器
  带一个可学习打分（或对「被选中比例」加负载均衡辅助项），12k 步 ≈ 8 min GPU/臂，判据线不变。
  **这是把「条件性无收益」从「本实现」推向「机制」的唯一便宜路径**，也是 `4.1`–`4.3`（MoE，Backlog）
  在 13M 上最便宜的前哨。

  未测（`SCHEMA.md` §17.12 同一陷阱，`2642` 侧的对照已记在 `docs/cost-table.md` 定律 11 一节）。
