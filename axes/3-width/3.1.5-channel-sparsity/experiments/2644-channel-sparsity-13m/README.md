# 2644 · 通道稀疏激活（per-token top-k 条件计算 vs 固定前缀常开）· 13M · dense

本文件是**预登记契约**：§1–§10 在起跑前写定，起跑后**不改**；口径差异只在 `analysis.md` 里声明。

## 1. 命题（一句话，可证伪）

在**训练/数据/主干逐位相同**、且**总参数量逐臂相同**（完整 FFN 权重都保留）的前提下，
把每个 token 的 FFN 隐藏通道按 `|pre-activation|` **逐 token 动态**取 top-k（`k = 50%` / `25%`），
相对**固定前缀常开 50%**（`F50`，无「条件性」的退化对照）以及 dense 锚（`U4-s0`，1.5314），
clean bpc 的差异能否超过项目方差带（0.014 bpc）？

- **H1（备择）**：条件选择（`K50`）相对无条件的等计算对照（`F50`）可排序更优
  ⇒ 「**保参数、条件选择通道**」是独立于「砍参数」的算力-质量前沿维度；
- **H0（零假设）**：`K50` 与 `F50` 不可排序（|Δbpc| < 0.014）⇒ 本尺度上「选哪些通道」
  不比「固定砍一半」更强，条件性本身没有独立收益。

对准的痛点：MoE / 条件计算许诺「参数不变、每 token 算力下降」。本条的机制**没有路由参数**、
不做容量权衡，只问一件事：**用既有激活内容选通道**这件事本身值不值。

## 2. 单因素声明

**唯一变量 = 每 token 参与前向的 FFN 隐藏通道子集**。

- 基底 = 主流标准 decoder-only transformer（`train_depth_ar.py --dense --topology sequential
  --exit-mode uniform`；三条共享底座偏离见 `docs/design.md` §2）；
- attention / LN / embedding / 位置嵌入 / 读出头（tied 线性）/ 优化器 / 步数 / 批大小 / lr / seed /
  数据切分 / 评测批（`depth_curve`，`n_batches=20, bs=16, generator seed 2`）**逐字段相同**；
- **总参数逐臂相同**：所有臂都保留完整 FFN 权重（`mlp_mult=4`，1024 隐藏通道），只改前向里
  「哪些通道参与」。`F50` 的未用通道参数在训练中梯度恒 0（恒等死区），这**不是**参数裁剪
  （参数依然在账上），由 §8 的门钉住；
- **必要性例外：无**。

### 2.1 干预实现（为什么它不是「换了个模型」）

- 挂点 = 各 `Block.mlp`（`nn.Sequential(Linear(d,H), GELU(), Linear(H,d), Dropout)`，
  `H = mlp_mult·d = 1024`），`Block.forward` 里以模块调用 `x = x + self.mlp(self.ln2(x))`。
- 本实验在**实验目录内**把每个 `blk.mlp` 换成包装模块 `SparseFFN(orig_mlp, arm)`，前向为
  `out = lin2(gelu(lin1(x)) * mask)` + `Dropout`，**不改引擎**（`pathlm/**`、`train_*.py` 一字未动）；
  训练时把 `train_depth_ar` 模块里的全局名 `DepthARModel` 换成工厂（与 `2641-ffn-ratio-frontier-13m/run.py` 同款接线），
  其余训练/落盘全走共享 `main()`。
- `mask` 形状 `[B,T,H]`、与激活 **同 dtype**：
  - `K50`/`K25`：`mask = scatter(ones, topk(|pre|, k))`，`k = 50%` / `25%` 的通道，**选择器无参数**；
  - `F50`：`mask[..., :H/2] = 1`，其余 0（固定前缀，无条件性）；
  - **等值门**：`mask` 全 1（`k = H`）时前向与 stock **逐位相同**（`x * 1.0` 在 IEEE 下精确；
    测试 `T1` 钉住，变异 `T2` 必须变红）。
- 三个臂的主干来自**同一次随机抽样**（同 seed、同一构造路径；`SparseFFN` 不引入新参数）。

## 3. 臂定义与代价

配置（逐字段沿用共同不变量）：`d=256, layers=8, heads=8, seq=256, mlp_mult=4, steps=12000, bs=32, lr=1e-3, seed=0`，
enwik8 字符级（vocab 206），`data/enwik8_full.npz`。

每 token FFN 等效 MACs（`d=256, H=1024, k = 激活通道数`）：

| 臂 | 每 token 激活通道 | 实现口径 FFN MACs（lin1 **全**算 + lin2 按 k） | 契约口径（2·H·d·k 比例） | FFN 参数 | 总参数量 | 每 token 总 MACs |
|---|---|---|---|---|---|---|
| `D`（锚 `U4-s0`，复用） | 1024（100%） | 524288 | 524288 | 4,204,544 | 6,962,688 | 7,392,768 |
| `K50` | 512（50%，按内容选） | **393216**（0.75×） | 262144（0.50×） | 4,204,544 | 6,962,688 | 6,344,192（0.858×） |
| `K25` | 256（25%，按内容选） | **327680**（0.625×） | 131072（0.25×） | 4,204,544 | 6,962,688 | 5,819,904（0.787×） |
| `F50`（对照） | 512（固定前缀，**无**条件性） | **262144**（0.50×） | 262144（0.50×） | 4,204,544 | 6,962,688 | 5,295,616（0.716×） |
| `U2-s0`（2641 复用，同框参照） | 512（**参数也减半**） | 262144（0.50×） | 262144 | 2,103,296 | 4,861,440 | 5,295,616 |

**代价口径的关键点（写在判据之前，不在事后找补）**：按内容选择通道**必须先算出全部
pre-activation**，因此 `lin1` 的 `d·H = 262144` MACs **无法省**，省下的只是 `lin2`
（`k·d`）。⇒ `K50` 的真实 FFN 节省是 **25%**，不是名字暗示的 50%；只有 `F50`
（固定前缀，可以同时切 `lin1` 与 `lin2`）才拿到 **50%**。两列都报：**实现口径**
（primary，用于 P1/P3 的算力对齐）与**契约口径**（并列，仅作对照）。
选择器本身的比较/排序开销不计 MACs，单列为 `selector_ops_per_token`（= 每层每 token
一次 `H` 元素 top-k，约 `H` 次比较），在 `analysis.md` 里作为定性说明。

## 4. 判据线（预登记，不可事后调整）

基准唯一且显式：**基准 = `D` 臂（2641 `U4-s0`，clean bpc 1.5314）**；
**代价项相对谁算** = 相对同一配置的解析量（每 token MACs / 参数）；
**主判据** = `P1` 的 `K50` vs `D` clean bpc 配对 Δ（`F50`、`K25` 并列）。

- **P1（质量 vs 代价）**：Δbpc(`K50`−`D`)、Δbpc(`K25`−`D`)、Δbpc(`F50`−`D`)，带 = **0.014 bpc**；
  并报每 token MACs（实现口径）。判定：`|Δ| ≤ 0.014` 不可排序，反之可排序（方向按符号）。
- **P2（活性列，必须）**：
  - 逐通道**激活频率分布**（跨 20 个评测批、逐层聚合）：报 `min/deciles/max` 与
    「频率 > 0 的通道数」；
  - **使用熵**：`p_j` = 通道 j 被选中的频率（Σ_j p_j = k，是平均计数不是分布），
    归一化 `q_j = p_j / k`；报 `H(q)/log H`（`H(q) = −Σ q_j log q_j`）。**刻度两端都钉死**：
    完全坍缩（每 token 恒选同一批 k 个通道）⇒ `q` 在前 k 个上均匀 ⇒ `H(q)/log H = log k / log H`
    （`K50` = 0.9、`K25` = 0.8）；均匀随机选择 ⇒ `q_j = 1/H` ⇒ 比值 = 1.0。⇒ **没有绝对门，
    只与 `F50` 的同口径读数比**（`F50` 构造性地 = 完全坍缩值）。**率类指标单独定门**
    （batch 聚类 bootstrap / Wilson 95% CI），`0.014` 不跨量纲借用；
  - **逐 token 选择一致率**（第二个、更强的坍缩指标）= 每个 (层, 位置) 的选择集等于该层
    众数集的比例。`F50` 恒为 1.0（构造性地坍缩上界）；`K50` 的该值 ≈ 1.0 即等价于 `F50`
    ⇒ 判机制退化。
- **P3（同框：保参数换计算 vs 减参数换计算）**：把 `F50`（保参数、砍计算）与
  `U2-s0`（2641，减参数、同计算，clean bpc **1.5709**）在同算力位点（每 token 总 MACs 5295616）
  上并排：谁占前沿？（`Δbpc` 仍按 0.014 带判）。
- **P4（否证线）**：
  - 若 `K50` 相对 `D` 的质量代价吃掉全部算力收益（Δbpc ≥ +0.014 且无其它收益）
    **或** `K50` 与 `F50` 不可排序（|Δ| ≤ 0.014）⇒ 判「条件性无独立收益，本尺度机制不成立」；
  - 若通道使用率坍缩到少数通道（逐 token 选择一致率 ≈ 1 或归一化熵 ≈ `F50` 水平）
    ⇒ 判「机制失效（退化为固定前缀）」；
  - 若 `K50` 可排序优于 `F50` ⇒ 判「条件性有效」，再按 §17.14 给算力价签。
- **带声明**：clean bpc 差用 0.014 bpc 带；使用率/熵等率类指标走配对 bootstrap / Wilson 95% CI，
  不跨量纲借用。
- **必须不变**：总参数量（逐臂逐位相同）、因果性。

## 5. 对照与方差

- 锚复用 = 2641 `U4-s0`（`D`）与 `U2-s0`（同算力参照），按 `SCHEMA.md` §9 三道门：
  ① 实现层 equality（本实验 `mask≡1` 时前向与 stock 逐位相同；`F50` 掩码全 0 的那一半
  参数梯度恒 0 的口径在 `analysis.md` 声明）；② 配置层 equality（逐字段对照 `2641-ffn-ratio-frontier-13m/config.json`）；
  ③ 口径标注（`n_batches=20, bs=16, seed 2, steps 12000, seed 0`）。
- 方差界 = 0.014 bpc（`docs/methodology.md` §2）；同 config 跨 seed 散布（2641: 1.5257/1.5298）作参照。
- n=1（仅 seed 0）：越带结论为单点快照，只报增量方向。

## 8. 单测与冒烟（含变异）

- 先 **60 步冒烟 rc=0**，再全跑（`docs/methodology.md` §5）。
- 单测 `test_2644_channel_sparsity.py`（自包含，不改共享 `tests/`）：
  - `T1` **等值门**：`keep_frac = 1.0`（mask 全 1）时 `SparseFFN` 前向与 stock `blk.mlp`
    **逐位相同**（整个模型最终深度 logits 逐位相同）；
  - `T2` **变异**：`keep_frac = 0.5` 时 logits 与 stock **不同**（门能变红）；
  - `T3` **参数同量**：三个臂与 stock 的总参数量逐位相同（`SparseFFN` 不引入参数）；
  - `T4` **F50 死区**：`F50` 未用通道（后 H/2）的 `lin1.weight.grad` 与 `lin2.weight.grad` 恒为 0，
    而 `K50` 的 `lin1` 梯度非 0（选择器让全部通道都参与梯度 ⇒ 机制不是死的）；
  - `T5` **计算账**：`analytic_cost()` 的 `macs_per_token` 与 §3 表逐位一致；
  - `T6` **因果性**：改未来 token 不改变更早位置的 logits。
- 关键开关做变异验证：故意把 `mask` 写成「恒全 1（丢筛选）」⇒ `T1` 绿但 `T2` 红（两条一起才有意义）。

## 9. 失败决策树

- 冒烟 rc≠0 ⇒ 修实现，不跑 12k。
- 单测红 ⇒ 修实现；等值门恒真（变异不变红）⇒ 门无效，重写门。
- 锁等不到（>25 min）⇒ 按 `K50` → `F50` → `K25` 优先级跑；未跑臂如实写「未跑」，**不编读数**。
- 频率/熵探针若与掩码实现不一致 ⇒ 先修测量（`docs/methodology.md` §5 反例：假失败）。

## 11. 既有做法（站巨人肩膀）

- 本轴 `2641`（`3.1.4`）：等 FFN 预算下逐层非均匀宽度；`U2-s0` = 1.5709 是「**减参数**换 50% FFN 算力」
  的本仓实测位点，本条 `F50` 正是它的**保参数孪生**。
- `2642`（`3.1.1` 均匀收窄）：解码器整体宽度收窄的位点。
- `docs/design.md` §2 / `SCHEMA.md` §15：减参数的结构改动要与「同 FLOPs 的稀疏/稠密对照」比，
  故本条的 `F50` 对照是**必要的**，不是可选的。
- 业界 MoE / 条件计算（switch-transformer 一族）用**可学习路由**换来「参数不增、算力降」，
  但路由本身有容量/负载均衡代价；本条刻意**去掉路由器**，只测「既有激活内容选通道」的纯条件性。
  业界数字不作结论依据；本仓以本地单跑为准（`SCHEMA.md` §21）。
