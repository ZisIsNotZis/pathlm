# 2651 · 权重量化最小判决（含标尺字节账）—— 判读（`analysis.md`）

> 本文件是**当前结论**；契约与判据线在 `README.md` / `config.json::criterion`（运行前写入）；数字在 `results.json`；表在 `table.md`；过程流水在 `JOURNAL.md`。本文件由 `fill_analysis.py` 从 `results.json` 生成（设备口径：`cpu`）。

## 0. 人话摘要

**这条研究在问什么**：同一个 13.5M 的普通解码器变压器（d256/12 层/8 头、只做最后一层语言建模损失、权重是冻结的），把它的**权重**从 fp16 改存成 int8 或 int4（并额外存标尺，即每个量化块换算回真实数值用的一个 fp16 系数），质量会掉多少、到底省不省内存？KV 缓存、激活、偏置、归一化和输出读出**逐位不动**，所以这只是一次单因素测量。

**为什么要问**：权重量化是部署侧最常被默认的省内存手段，「int8 基本不损、int4 有损」常被当成经验。我们不做 GPTQ/AWQ 那类二阶补偿，只测**最朴素的对称分组假量化**在这个尺度上的真实代价，并且把「标尺本身也要占字节」算清楚——标尺不是免费的，这是最常见的账目陷阱。

**该跌的（每参数部署字节，含标尺）**：`fp16` 2.000000 字节/参数（÷fp16 = ×1.0000）；`int8_per_channel` 1.005515 字节/参数（÷fp16 = ×0.5028）；`int8_group32` 1.062500 字节/参数（÷fp16 = ×0.5312）；`int4_group32` 0.562500 字节/参数（÷fp16 = ×0.2812）。也就是说 int8 大约把权重面减半、int4 大约减到三分之一（不是四分之一——标尺要钱）。

**该不跌/可排序的质量代价（clean bpc，越低越好；判定口径 = 5 个窗口上的配对 Δ，带 = 0.014 bpc）**：`int8_per_channel` 与 fp16 的最大配对 Δ = 0.000305 ⇒ **不越带**；`int8_group32` 与 fp16 的最大配对 Δ = 0.000117 ⇒ **不越带**；`int4_group32` 与 fp16 的最大配对 Δ = 0.014904 ⇒ **越带**。 `int4_group32` 的越带**只刚越**：`max|配对 Δ| = 0.014904`，超出带 +0.000904；判定用逐窗 `max|Δ|` 聚合（非均值，见 `config.json::criterion`），5 窗 Δ 均值 = 0.013946 **落在带内** ⇒ 该越带判定依赖 max 聚合。

**该保持的（合成 copy 召回，把前面出现过的符号串原样搬回来；chance = 0.0156 = 1/64）**：`fp16` 0.1413；`int8_per_channel` 0.1423；`int8_group32` 0.1419；`int4_group32` 0.1478；fp16 的局部先验（只看最近 8 个 token）= 0.0146，毁源对照（把要搬的源片段整段换随机符号）见 §3。

**结论一句话**：**int8 在这一档基本是白赚**：字节减半左右，clean bpc 的配对代价落在 0.014 的噪声带内（该带内不可排序）。**int4（每 32 个值一把标尺）掉出噪声带**：按契约判「int4 在本规模有损」，回退 int8；它省到 0.562500 字节/参数，代价是 clean bpc 掉 +0.014186（相对 fp16）。**值不值**：把「字节」当钱、把「clean bpc」当货，`int8_per_channel` 在 1.005515 字节/参数上字节更省且质量不可分辨（**不构成严格支配**） fp16；`int8_group32` 在 1.062500 字节/参数上字节更省且质量不可分辨（**不构成严格支配**） fp16；`int4_group32` 在 0.562500 字节/参数上**不支配** fp16（`dominates` = 字节不多于 fp16 **且**质量代价落在 0.014 带内、即**不可分辨**，**不构成 Pareto 严格改进** ⇒ int4 因越带而不支配 fp16，尽管它最省）；`int8_per_channel` vs `int8_group32`：前者在 1.005515 字节/参数上字节更省且质量不可分辨（`dominates_group32 = True`）——本模型行长远大于 32 ⇒ 每行一把标尺比每 32 值一把更省，且质量代价都在带内。

> 术语：`bpc` = 每字符比特数（越低越好）；`标尺（scale）` = 把量化整数换算回实数的一个 fp16 系数；`配对 Δ` = 同一批评测窗口上 `bpc_臂 − bpc_fp16`（正 = 量化更差）；`越带` = `max|配对 Δ|` 超过 0.014，即「在本尺度确有可排序的质量代价」（聚合 = 逐窗 `max|Δ|`，非均值，见 `config.json::criterion`）；`dominates` = 字节不更多、且质量代价落在 0.014 带内（即**质量不可分辨**，**不构成 Pareto 严格改进**）。

## 4. 三道对账

### 对账① 字节账 ↔ 实现（G3/G4）

`int8_per_channel` 标尺个数 = `n_out`（每行一把）；`group G` 标尺个数 = `n_out·n_in/G`（要求 `G | n_in`）；两者在 `wq_arms.activity_of` 内**逐矩阵断言**，对不上直接报错、不出数。本次四个臂 `scales_match_analytic` 全 = True，取整误差界（`max_abs_err ≤ 0.5·s_max`）违例 = 0 个矩阵；G3+G4 门禁 = {'int8_per_channel': True, 'int8_group32': True, 'int4_group32': True}。

### 对账② `fp16` 臂 ↔ 历史锚 / 独立路径（G2）

- 主路径 `bpc_of` = 1.483569，独立路径 `retention.masked_bpc` = 1.483569，**逐位相等 = True**（本 run 的 device = `cpu`）。
- 与 GPU 历史锚 1.483569 的差 = **2.70e-07**；本口径下「跨设备比锚」是否在力：`False`（CPU 口径下门禁只要求两条路径逐位相等；锚比较作为**并列读数**报告）。若该差 < 1e-6，说明 CPU 与 GPU 口径在本模型/本窗口上事实上重合。
- `fp16` 臂的 logits 与 stock 释放前向**逐位相等 = True**；`fp16` 臂**不装任何补丁**（`patch_reversibility.fp16.logits_changed_when_patched = False`）。
- 量化臂装上真的改 logits、拆掉**逐位还原**：`int8_per_channel` 改=True/还原=True；`int8_group32` 改=True/还原=True；`int4_group32` 改=True/还原=True；补丁无残留 = True。
- `gates.*` 死权重：清零后 logits 逐位不变 = True，还原逐位 = True（12 个模块、789504 个参数）⇒ 它们只进字节账、不进质量读数。

### 对账③ 配对 Δ ↔ 带

逐臂 `max|配对 Δ|`：`int8_per_channel` 0.000305（不越带，逐窗符号 ['+', '+', '-', '+', '+']）；`int8_group32` 0.000117（不越带，逐窗符号 ['+', '-', '-', '+', '+']）；`int4_group32` 0.014904（越带，逐窗符号 ['+', '+', '+', '+', '+']） ｜ 在力带 = 0.014 bpc，口径 = 配对 Δ、5 窗口。**注意**：单臂跨窗口 bpc 极差（§2 末）是**另一口径**，与 0.014 不得混用。

## 5. 失败与局限

1. **单 seed 冻结 checkpoint**：被测权重是单个 seed 训练出来的 ⇒ 训练侧散布未知，本实验**不据此宣称结构优劣**，结论只作**这些点**的描述、不外推到别的尺度 / 别的 `in_features`（`in_features` 更长时 `2/n_in` 更小、`2/G` 不变，本实验不外推该效应）。
2. **设备口径（本批）**：本批四个臂**全跑在同一台机器的 CPU 上**（`device=cpu`），不取 GPU 锁（SCHEMA §20 不适用：CPU 工作不与 GPU 作业互斥）。臂间比较因此是同设备同口径；与 GPU 历史锚的比较是**跨设备**，只作并列读数（实测差 2.70e-07）。判据（配对 Δ、0.014 带）不受影响：`batch()` 的取数只依赖 seed/窗口，与设备无关。
3. **不做离群保护 / 不做误差补偿**：本实验只做最朴素的对称分组假量化——不含 GPTQ 的Hessian 补偿、不含 AWQ 的激活感知通道缩放、不含 LLM.int8() 的离群通道留 fp16。因此 int4 掉得多时，第一个嫌疑是「未做离群保护」，不是「4 bit 本身不行」。
4. **不做组合实验**：权重 × KV × 激活的组合留白是显式声明（`README.md` §2），不是遗漏。
5. **显存**：本批为 **CPU 口径** ⇒ 显存 **未测**（`peak_mem_mib = null`）；「峰值不随档下降」是**实现层**性质（假量化权重现算成 fp32 再前向），不是本批的读数。判据横轴只用解析字节账（值 + 标尺）。
6. **召回是合成任务**：copy / induction / var_recall 是受控合成任务，只说明「在这类把前面信息原样搬运的任务上是否可分辨」；`at_floor = true` ≠「机制无效」。率类指标不借 0.014 带。
7. **未测的臂**：`int4_per_channel`（解析 0.5 + 2/n_in ≈ 0.508 B/参数）本批**未测**，见 §6 下一步。

## 6. 下一步（未测项 → 最小实验）

- **`int4_per_channel`（解析 ≈0.508 B/参数，比 `int4_group32` 还省）**：本批未测。它回答「int4 的损失是位宽造成的还是标尺粒度造成的」——最小实验 = 加一个臂，同窗口序跑同一套读数。
- **离群通道保护（LLM.int8() 式）**：若 int4 越带，这是最可能把代价压回带内的改动；最小实验 = 在 `wq_arms.fake_quantize_weight` 上加一条「amax 超过阈值的通道留 fp16」的分支，重跑同一套四臂。
- **更细的 int4 分组（G=8/16）**：`int4 group-8` 解析 0.75 B/参数，仍比 int8 省；回答「标尺粒度能买回多少 int4 的质量」。
- **跨尺度验证**：本结论只在 13.5M / 单 checkpoint 上成立；换 `in_features` 更长的主干（`2/n_in` 更小、`2/G` 不变）才是外推的必经一步。
