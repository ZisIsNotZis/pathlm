# 2655 · `head_dim=64` 的 KV 标尺摊薄（WP2 的实测腿）—— 分析与结论

## 0. 人话摘要

**这件实验在问什么。** KV cache 存成 8 位有两种省内存的存法：**int8** 要为每一小块数据配一把
「标尺」（记录该块的最大值，反量化时用），标尺本身要占内存——每 `G` 个相邻的值摊一把 fp16 标尺，
即每值多花 `2/G` 字节；`G` 只能取到「沿单个注意力头维度」的大小，因为标尺一旦跨 token 就会让
未来信息泄进过去（违反前缀确定性）。**头维度（head_dim）越大，同一把标尺能罩住的相邻值越多**，
所以省幅越接近 50% 的上限。本实验把模型换成 `head_dim=64`（`--heads 4`，其余配方与 `2616` mha 臂
逐字段一致）训练 12k 步，然后在同一个 checkpoint 上量 `G=64` 与 `fp8 E4M3`（免标尺）的字节与质量，
并把「实测标尺密度」与解析式 `1 + 2/G` 逐项对账——这正是研究项 5.5 的 WP2 缺的那条实测腿
（此前 `head_dim=64` 的 48.4375% 只有解析价签）。

**量出来的结果（CPU、`window_seed=2`、24×16）。**

| 臂 | 每值字节 | 每位置字节 | 相对 fp16（精确比值） | clean bpc（越低越好） | 配对 Δ vs fp16（5 窗取最大） | 越 0.014 带 | copy 召回 [95% CI] | at_floor |
|---|---|---|---|---|---|---|---|---|
| `fp16`（基线） | 2.00000 | 12288 | ×1.000000 | **1.483031** | — | — | 0.2025 [0.1831, 0.2233] | 否 |
| `int8_block_g64` | 1.03125 | **6336** | ×0.515625 → **48.4375%** | 1.483140 | +0.000226 | 不越 | 0.2025 [0.1831, 0.2233] | 否 |
| `fp8_e4m3`（免标尺） | 1.00000 | **6144** | ×0.500000 → **50.0000%** | 1.484297 | +0.002294 | 不越 | 0.1953 [0.1763, 0.2159] | 否 |

参照系：`bpc` = 每字符比特数（越低越好），本 checkpoint 的 fp16 基线是 **1.483031**；
`0.014 bpc` 是跨格噪声带（限配对 Δ、≥5 窗口）；`at_floor` 读作「该任务上不可分辨」，
**不是**「机制无效」。免标尺臂的 `fp8_e4m3` 动态范围 ±448（E4M3 无 inf，超限饱和）。

**三道对账（WP2 的验收核心）。**

1. **解析 × 实测逐臂一致**：实测标尺密度 = `n_scales/n_values` = 「每值摊到几把标尺」，实测值
   恰好是 `1/G`（G=64 → 0.015625；G=32 → 0.03125；G=16 → 0.0625；fp8/fp16 → 0），
   乘 2 B/把得每值标尺字节，加值字节后乘 6144 得**每位置字节**——五个臂的实测与解析价签
   **逐位相同、差 0**（`wp2_reconciliation.all_consistent = True`）。
2. **`head_dim=64` 的省幅成立**：`int8_block_g64` 实测 **6336 B/位置、48.4375%**，
   与解析式一致；`head_dim=32` 的封顶点（G=32 封顶）是 6528 B/位置、**46.875%**，
   本 run 在同一 `head_dim=64` 模型上用 G=32 复现出**同一个 6528**（实测），
   两点的差 = 192 B/位置 = 1.5625 个 fp16 百分点。
   **关键澄清**：`n_kv_heads·head_dim = d_model = 256` 恒定 ⇒ 每位置的 KV **值数恒为 6144**
   （`head_dim=64` 是 `2·12·4·64`，`head_dim=32` 是 `2·12·8·32`，同值）⇒ **`head_dim` 没有省掉任何值**，
   省的是**标尺被摊薄的份数**（`head_dim` 只决定 G 能取到多大）。
3. **护栏全绿**：严格前缀不变性两条（改未来 token / 改同批邻居 ⇒ 过去位置 logits 不变）
   五个臂全 **True/True**；非量化（`mode="fp32"`）恒等臂在同一设备、同一窗口序下，
   `bpc_of` 与库路径 `retention.masked_bpc` **逐位相等**（1.471526，`abs_diff = 0.0`）；
   实现层 `int8 + 块标尺 G=64` 的前向与 `2632/block_arms` **逐位相等**。

**结论（四句）。**
1. **WP2 的实测腿补齐**：`head_dim=64`、G=64 ⇒ 每位置 **6336 B**、省幅 **48.4375%**，
   实测标尺密度 `1/64` 与解析 `2/64` 摊薄项逐位一致 ⇒ 判据的否证条件③（实测与解析不符）
   **未命中**；「大 head_dim 更接近 50%」在本尺度上**有实测支撑**（48.4375% vs 46.875%）。
2. **`fp8_e4m3` 免标尺在同字节轴上仍占优**：6144 B/位置（比 int8+G=64 再省 192 B/位置 = 3.03%），
   配对 Δ `max|Δ| = 0.002294 < 0.014` ⇒ 不越带；`fp8_e4m3` 相对 `int8_block_g64` 的 5 窗配对 Δ
   `max|Δ| = 0.002279` ⇒ 二者在本尺度**质量不可分辨**（按每位置字节取 fp8_e4m3）；
   实测标尺数 = 0 ⇒ **「免标尺」前提成立**（饱和占比 0，KV 数值没有触到 ±448）。
3. **块标尺的 `G` 在这个尺度上只是字节旋钮**：scan 口径（6×16, seed 2）下
   G ∈ {16, 32, 64} 的 clean bpc = 1.495037 / 1.494940 / 1.495123，与 fp16 的 1.495012
   互差 ≤ 1.2e-4，远小于 0.014 带 ⇒ 省字节没有换来可分辨的质量代价。
4. **单点不外推**：以上只描述 `head_dim=64`、13M、T=256、seed 0 这一个点
   （`SCHEMA.md` §17.11）；不推 `head_dim=128`、别的规模或别的 T。

**一句话**：把 `head_dim` 从 32 抬到 64，块标尺的摊薄从封顶 46.875% 走到 **48.4375%**
（实测与解析逐位一致），质量代价落在 0.014 带内，而免标尺的 `fp8_e4m3` 仍以 6144 B/位置
（fp16 的一半）保持同字节轴上的字节优势。

## 4. WP2 的分账

### 4.1 解析 × 实测（逐臂，WP2 验收量）

解析：每值字节 = 值字节 + `SCALE_BYTES/G`（fp8 免标尺 ⇒ 1.0）；每位置字节 = 每值字节 × 6144。
实测：探针批上的 `n_scales/n_values` × 2 B/把 + 值字节。**五臂差 = 0，全部一致**
（`wp2_reconciliation`，`all_consistent = True`）：

| 臂 | 解析每值字节 | 实测每值字节 | 解析每位置字节 | 实测每位置字节 | 差 |
|---|---|---|---|---|---|
| `fp16` | 2.00000 | 2.00000 | 12288 | 12288.0 | 0 |
| `int8_block_g64` | 1.03125 | 1.03125 | 6336 | 6336.0 | 0 |
| `int8_block_g32` | 1.06250 | 1.06250 | 6528 | 6528.0 | 0 |
| `int8_block_g16` | 1.12500 | 1.12500 | 6912 | 6912.0 | 0 |
| `fp8_e4m3` | 1.00000 | 1.00000 | 6144 | 6144.0 | 0 |

> 口径提醒：这里的「实测」是**实测标尺密度**（探针批上的标尺把数 ⇒ `2/G` 摊薄项），
> 不等于「实测显存峰值」——评测实现把 K/V 立刻反量化，峰值不随档下降。部署价签 = 解析字节 ×
> 实测密度，两者已在上面逐位对上；真正的峰值要等分块 cache 实现（见 §5）。

### 4.2 `head_dim` × G 阶梯与「值数不变」

| head_dim | G | 合法（G 整除 head_dim） | 每值字节 `1+2/G` | 每位置字节 | ×fp16 | 省幅 |
|---|---|---|---|---|---|---|
| 32 | 8 | 是 | 1.25000 | 7680 | ×0.625000 | 37.5% |
| 32 | 16 | 是 | 1.12500 | 6912 | ×0.562500 | 43.75% |
| 32 | 32 | 是 | 1.06250 | 6528 | ×0.531250 | **46.875%（封顶）** |
| 32 | 64 | 否（不整除 head_dim=32） | 1.03125 | 6336 | ×0.515625 | 48.4375%（不合法的假想点） |
| 64 | 8 | 是 | 1.25000 | 7680 | ×0.625000 | 37.5% |
| 64 | 16 | 是 | 1.12500 | 6912 | ×0.562500 | 43.75% |
| 64 | 32 | 是 | 1.06250 | 6528 | ×0.531250 | 46.875% |
| 64 | 64 | 是 | 1.03125 | 6336 | ×0.515625 | **48.4375%** |

- **每位置值数恒为 6144**（`2·12·n_kv_heads·head_dim`，只要 `n_kv_heads·head_dim = d_model = 256`）
  ⇒ `head_dim` **不省值数**；抬 `head_dim` 的唯一作用是**把 G 的上限抬到 head_dim**
  （G=64 在 hd32 上不合法：块要跨 token 才够 64 个值，标尺就依赖未来 ⇒ 违反前缀确定性），
  于是标尺从 1/32 摊到 1/64。列 `32/64` 行是假想点，只用来标出「不合法」。
- 本 run 在 `head_dim=64` 上**实测**了 G ∈ {16,32,64} 三个合法点（§3）；
  `head_dim=32` 的实测点在 `2653`（G ∈ {8,16,32}，实测标尺密度 0.125/0.0625/0.03125，逐位一致）。
- 两点对照：**hd64 G=64 = 6336 B/位置（48.4375%）** vs **hd32 G=32 = 6528 B/位置（46.875%）**，
  差 192 B/位置；而 **hd64 G=32 实测也是 6528**（同字节、不同 head_dim）⇒ 字节量由 `G` 决定、
  `head_dim` 只决定 `G` 能取多大。

### 4.3 前缀不变性两条 + 配对 Δ 与带的关系

- **前缀不变性**（改未来 token / 改同批邻居 ⇒ 过去位置 logits 不变）：5 个臂全 **True/True**，
  fp32 恒等臂的探针自检同样 True/True。这是**会失败的检验**（逐位比较 logits，不是恒真式）；
  块标尺沿 `head_dim` 只依赖当前 token 自己的值 ⇒ 无需 staging。
- **配对 Δ（5 窗口，2×16 均匀口径，臂 − fp16）**：

| 臂 | seed 2 | seed 3 | seed 4 | seed 5 | seed 6 | 均值 | max\|Δ\| | 对 0.014 带 |
|---|---|---|---|---|---|---|---|---|
| `int8_block_g64` | +0.000070 | +0.000040 | +0.000015 | +0.000120 | +0.000226 | +0.000094 | 0.000226 | **不越** |
| `fp8_e4m3` | +0.000575 | +0.000426 | +0.002294 | +0.002094 | +0.001475 | +0.001373 | 0.002294 | **不越** |

- **`fp8_e4m3` vs `int8_block_g64`（判据要求「同字节轴上能否排序」）**：由同一批逐窗读数相减得
  seed 2…6 = +0.000505 / +0.000386 / +0.002279 / +0.001974 / +0.001249（均值 +0.001279），
  `max|Δ| = 0.002279 < 0.014` ⇒ **质量上不可分辨**；而每位置字节 6144 < 6336
  （再省 192 B/位置 = 3.03%）⇒ 按每位置字节取 `fp8_e4m3`。
  （派生量，来源 = `results.json::points[].bpc_paired_windows`，未另存。）
- **在力带声明**：主判 = **跨格 0.014 bpc 带（限配对 Δ、≥5 窗口，本 run 满足 5 个）**。
  本格自测「单臂跨窗口 bpc 极差」= **0.194059**（窗口 seed 2→6 从 1.38 到 1.58），
  **远大于** 0.014 ⇒ 它在这批数据上**不能当排序带**（窗口难度本身跨 0.19 bpc）；
  按预登记**两带不混用**，主判只用配对 Δ（配对差已把窗口难度消掉）。

### 4.4 非量化臂逐位复原 + 实现层 equality（仪器自检）

- `bpc_of`（本实验路径）= `retention.masked_bpc`（库路径）= **1.471526**，`abs_diff = 0.0`、
  **逐位相等 = True**（fp32 恒等臂、2 批、seed 2、同设备）⇒ 非量化臂在同设备内逐位复原。
- 本模块 `mode="fp32"` 前向 = 生产前向（`2619`）**逐位相等 = True**；
  本模块 `int8 + 块标尺 G=64` 前向 = `2632/block_arms` 前向**逐位相等 = True**
  ⇒「唯一改动 = KV 数值格式」成立（fp8 臂只是把同一个往返算子换成 fp8）。
- 任何一条为 False 时 `hp64_arms.py` 直接 assert 退出、不出数（判据 gate）。

## 5. 失败与局限

1. **单个 checkpoint（seed 0）**：读数只描述这一个 13M 模型；`head_dim=64` 的第二 seed
   （`hd64-s1`）**未训练完成**（driver 等 GPU 锁超时后排队重试，见 `train_driver_state.json`）
   ⇒ 本 run 是 **n = 1**，不报跨 seed 方差、不宣称结构优劣。
2. **整程 CPU**：CPU 与 GPU 的绝对 bpc 并列但**不构成判据**（本 run 不宣称逐位等于 GPU 锚）；
   判据只用同设备、同窗口序的配对 Δ。
3. **解析字节 ≠ 实测峰值**：§4.1 的「实测」是实测**标尺密度**（⇒ `2/G` 摊薄项），
   评测实现立刻反量化 ⇒ 显存峰值不随档下降；真正的部署峰值要等分块 cache 实现（未做）。
4. **`fp16` 臂不是恒等臂**：它的 KV 真的走了一次 fp16 往返（`rel_err 1.77e-4`），
   是「2 B/值」的部署口径基线；逐位复原那条护栏落在 `mode="fp32"` 的恒等臂上（§4.4）。
5. **召回腿只有 copy 可分辨**：induction / var_recall 全部落地板（n=16）⇒ 本主干在那两条腿上
   不可分辨，按 `SCHEMA.md` §19 不得写成「机制无效」。
6. **单点不外推**：13M、T=256、`head_dim ∈ {32,64}`；不推 `head_dim=128`、别的规模、别的 T。
7. **G=64 只在 `head_dim=64` 上合法**：它靠「同一 token 内沿 head_dim 凑满 64 个值」，
   所以这条收益**与 `n_kv_heads·head_dim = d_model` 的设定绑定**，换结构要重算。
