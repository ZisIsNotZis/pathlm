# 2664 · 低秩压缩（MLA 式）vs 直接量化 · 同每位置部署字节的判决 —— 分析与结论

> 事实的家：本实验读数在 `results.json`（聚合）+ `results_<臂>_<档>_<run>.json`（29 份逐臂）；
> 研究项的判词在 `../../project.yaml::conclusion`；判据线是运行前冻结的 `README.md` §4 + `config.json`。
> 本文件只做一件事：把那些读数读成一句能站住的话，并把不能站住的部分写清楚。

## 0. 人话摘要

**它在问什么。** 模型生成长文本时，要把读过的每个历史位置的 key/value 存下来，这块记忆随上下文线性膨胀。
省它有两条路：**低秩压缩**（MLA 式：先把每位置的 K/V 压成一条短向量，用时再展开，省的是**维度**）
与**直接量化**（K/V 还是那些数，只是每个数用 8 位或 4 位存，省的是**精度**）。
两条路各自报数字的多，**摆在同一个「每位置部署字节」上比过的少**。本实验就把它们摆到同一根轴上：
13M 的同一副骨架（12 层 × 256 宽 × 8 头 × 序列长 256），同配方从零训 12000 步（98.3M token），只改 K/V 的存法。

**量出来的结果。**

| 每位置字节 | 低秩那条路（潜向量） | clean bpc | 量化那条路 | clean bpc | 配对 Δ（低秩 − 量化，正 = 低秩更差） | 判 |
|---|---|---|---|---|---|---|
| **6528 B**（fp16 的 ×0.53125） | 潜维 272（`mla_c272`，+6.86% 参数） | 1.484880 / 1.481292 | int8 块标尺 G=32（`mha@int8`） | 1.482004 / 1.482874 | **+0.002876 / −0.001582** | **两条都落 0.014 带内 ⇒ 不可分** |
| **3456 B**（×0.28125） | 潜维 144（`mla_c144`，−1.86% 参数） | 1.488682 / 1.475687 | int4 块标尺 G=32（`mha@int4`） | 1.505358 / 1.501846 | **−0.016676 / −0.026159** | **两条都越带 ⇒ 低秩更好** |
| **3072 B**（×0.25） | 潜维 128（`mla_c128`，−2.95% 参数） | 1.480730 / 1.477781 | 头共享 GQA2（`gqa2`，−8.75% 参数） | 1.496324 / 1.495938 | **−0.015594 / −0.018157** | 越带 ⇒ 低秩更好，**但这一腿参数不等** |
| 3072 B（同字节、等参数） | 同上 | 1.480730 / 1.477781 | 头共享 GQA2 **等参数**（`gqa2_eq`，13,536,516） | 1.494677 / 1.481265 | **−0.013947 / −0.003484** | **两条都落带内 ⇒ 对头共享无优势** |

参照系：`bpc` 是「每字符比特数」，越低越好；本仓同尺寸 fp16 全因果基线在 1.48 附近
（`results.json::points.mha.runs[mode=fp16].bpc` = 1.482022 / 1.482822）。**0.014 bpc** 是跨格噪声带
（限配对 Δ、24 个评测窗口）——比它小的差异在这个尺度上读作「分不出好坏」。
表里每格两个数 = seed 0 / seed 1（格 C 的对照一侧是两次 seed 0 独立运行，见表注）。

**结论（五句）。**

1. **在 6528 B 这一档，低秩与 8 位量化分不出好坏**（配对 Δ +0.0029 / −0.0016，两条都落带内），
   而低秩这一侧还多付 17.71% 单层 FFN 的上投影算力、并且必须从零训练 ⇒ **这一档上低秩没有理由**。
2. **在 3456 B 这一档，低秩明确更好**（−0.0167 / −0.0262，两 seed 同向越带，约 1.2–1.9 倍带宽）：
   差距几乎全部来自 **4 位量化的损伤**（int4 相对 fp16 +0.021180），而不是低秩变强——低秩潜维 144 自己
   相对 fp16 的损伤只有 **−0.000237**（在带内）。
3. **两条路的失效模式不同，而且低秩的失效点还没被摸到**：量化在 8 位无损（+0.000017）、
   4 位开始伤质量（+0.021180，越带）；低秩从 272 → 144 → 128 一路无损伤
   （+0.000664 / −0.000237 / −0.003167，全在带内）⇒ **低秩的失效点在 3072 B 以下，本实验没测到**。
4. **对头共享（GQA2）的表观优势是参数账**：等字节下低秩赢 −0.0169，但把 GQA2 的参数补齐
   （`gqa2_eq`）之后差距缩到 **−0.013947 / −0.003484，两条都落带内** ⇒ 按本项预登记的否证条件，
   **「低秩相对头共享产生新知识」在本尺度被否证**（详见 §4.3）。
5. **代价已入账**：上投影每 token 1,671,168 MACs（潜维 272）= 单层 FFN 的 17.71%、潜维 144 时 9.375%、
   潜维 128 时 8.333%；且低秩改的是 K/V 投影矩阵本身，**没有「保住已训权重只包一层」的轻量路径**。

## 2. 六问逐条

1. **它是干什么的**：让模型在长上下文里只花更少的内存记住历史——把每个历史位置的 K/V 压小，同时尽量不掉语言建模质量。
2. **相对普通 decoder-only transformer 改了什么**：普通变压器每个头各存一份 K/V（每位置 `2·n_heads·d_head` 个 fp16 值，本实验 6144 值 = 12288 B）；低秩臂在每层把 `x` 经下投影压成一条 `d_c` 维潜向量并**只缓存它**（每位置 `2·d_c` 值），用时再经上投影还原每头的 K/V。改动量级：潜维 272 时每位置 3264 值（−46.875% 字节）、参数 **+6.86%**（14,464,512 对 13,536,768）、解码期每 token 上投影 **+1,671,168 MACs**（单层 FFN 的 17.71%）；潜维 144 时每位置 1728 值、参数 −1.86%、上投影 884,736 MACs；潜维 128 时每位置 1536 值、参数 −2.95%、上投影 786,432 MACs。量化臂不改模型，只在推理时把 K/V 换成 int8/int4 + 沿头维度每 32 值一把标尺（1.0625 / 0.5625 B/值），参数与算力都不变。
3. **为什么要改**：痛点是**显存**（长上下文的 KV cache 随长度线性涨）。低秩省维度、量化省精度，两条路都在省同一块内存；本项问的是**同一字节预算下哪条更值、各自从哪一档开始伤质量**。
4. **怎么测的**：对照 = 同尺寸 stock fp16 MHA 全因果基线（1.482022 / 1.482822）+ 同字节对手（`mha@int8`、`mha@int4`、`gqa2`）+ 等参数对照（`mla_c272_eq`、`gqa2_eq`）+ 同 seed 复跑（噪声地板）。指标 = clean bpc（24 批 × 16 × 256、`window_seed=2`、同一条 `bpc_of` 入口）+ 合成长程召回（copy / induction / var_recall，配对 bootstrap）+ 每位置部署字节（解析式，与实测张量形状对账）+ 前缀不变性。口径是**等价理论量**（每位置字节、每 token MACs、tokens-per-forward），墙钟不进判据。
5. **测出来多少**：见 §0 表与 §4；一句话量级——**3456 B 这一档低秩比 4 位量化好在 0.017–0.026 bpc（带是 0.014），6528 B 这一档两者差 0.003 以内（不可分），对头共享的优势在参数补齐后落到带内**。
6. **结论与下一步**：见 §0 五句 + §10（未测项与下一步最小实验）。采纳面：**潜维 128/144 这一族确实能在 3072–3456 B 上做到「不花质量」**，比 4 位量化更安全；不采纳面：**6528 B 这一档不必用低秩**（同字节下与 int8 不可分，却要付上投影算力与从零训练），**对头共享也没有净增量**。

## 3. 契约与预登记的处置（先说清两件会影响可信度的事）

### 3.1 一次指纹转写错字，以及 `run.py` 在校验分支上的一处改动

`config.json::model_arms[gqa2_eq].runs[1].sha256` 记的是

**判定：转写错字，不是换文件。** 三条证据：

③ 其余 6 个复用 checkpoint 的指纹逐条对得上。

## 4. 同字节三格：判决

### 4.1 格 A · 6528 B · 低秩 c272 vs int8 块标尺

| 配对 | 低秩 | 对照 | Δbpc（低秩 − 对照） |
|---|---|---|---|
| seed 0 | `mla-c272-s0` 1.484880 | `mha-12k-s0`@int8 1.482004 | **+0.002876** |
| seed 1 | `mla-c272-s1` 1.481292 | `mha-s1`@int8 1.482874 | **−0.001582** |

`delta_bpc_mean = 0.000647`、`n_pairs = 2`、`n_above_band = 0`、`n_below_band = 0`、`n_in_band = 2`
⇒ `verdict = indistinguishable_in_band`（`results.json::same_byte.groups[0]`）。
**等参数夹逼**（派生：`points.mla_c272_eq.runs[].bpc` − `points.mha.runs[mode=int8].bpc`，逐 seed 配对）：
`mla-c272-eq-s0` 1.484399 − 1.482004 = **+0.002395**；`mla-c272-eq-s1` 1.489149 − 1.482874 = **+0.006275**
（均值 +0.004335）⇒ 把低秩那一侧多出来的 +6.86% 参数收回去之后，符号一致地偏向 int8，但**两条仍落带内**。
读法：**这一档上不可分**；但低秩为「不可分」付了上投影算力（17.71% 单层 FFN）与从零训练，
8 位量化这边 `params_added = 0`、算力不变 ⇒ **按代价取量化**。

### 4.2 格 B · 3456 B · 低秩 c144 vs int4 块标尺

| 配对 | 低秩 | 对照 | Δbpc |
|---|---|---|---|
| seed 0 | `mla-c144-s0` 1.488682 | `mha-12k-s0`@int4 1.505358 | **−0.016676** |
| seed 1 | `mla-c144-s1` 1.475687 | `mha-s1`@int4 1.501846 | **−0.026159** |

`delta_bpc_mean = −0.021417`、`n_below_band = 2` ⇒ `verdict = low_rank_better_sortable`
（`results.json::same_byte.groups[1]`）。低秩这一侧参数还**少** 1.86%（13,284,864 对 13,536,768），
即这个方向上参数账对低秩不利、仍胜出。拆解：int4 相对 fp16 的损伤 **+0.021180**（两 seed：+0.023336 / +0.019024），
低秩 c144 相对 fp16 的损伤 **−0.000237**（+0.006660 / −0.007135，落带内）⇒ **差距是 4 位量化买来的，不是低秩买来的**。

### 4.3 格 C · 3072 B · 低秩 c128 vs 头共享 GQA2（以及等参数夹逼）

| 配对 | 低秩 | 对照 | Δbpc |
|---|---|---|---|
| seed 0 | `mla-c128-s0` 1.480730 | `gqa-12k-s0`@fp16 1.496324 | **−0.015594** |
| 「seed 1」 | `mla-c128-s1` 1.477781 | `gqa-12k-s0-rep`@fp16 1.495938（**两次 seed 0 运行**） | **−0.018157**（`seed_aligned = false`，如实标注） |

`delta_bpc_mean = −0.016876`、`n_below_band = 2` ⇒ `verdict = low_rank_better_sortable`。
**但这一格两侧参数不等**：GQA2 少 8.75% 参数（12,352,512 对 13,137,408）。等参数对照
`gqa2_eq`（13,536,516，−252 对 MHA）的读数是：

| 配对 | 低秩 | 对照（等参数 GQA2） | Δbpc |
|---|---|---|---|
| seed 0 | 1.480730 | `gqa2-eq-s0` 1.494677 | **−0.013947**（带内，差 0.000053 触带） |
| seed 1 | 1.477781 | `gqa2-eq-s1` 1.481265 | **−0.003484** |

**两条都落 0.014 带内**（派生：`points.mla_c128.runs[].bpc` − `points.gqa2_eq.runs[mode=fp16].bpc`）。
⇒ 格 C 的 `low_rank_better_sortable` 只对「按训练预算摆在那里的 GQA2」成立；**把参数补齐之后，低秩对头共享无可分优势**。
这正好命中 `project.yaml::falsification` 的第一条：*「若 MLA 式低秩压缩在等参数对照下相对同字节头共享臂的
clean bpc 不占优（越噪声带变差或持平）⇒ 判低秩压缩在本尺度不产生新知识」*——**该否证条件在本尺度成立**。
附一条反向的可信度检查：把参数给头共享也**确实有用**——`gqa2_eq` 相对 `gqa2` 在 seed 0 是 −0.001647、
在 seed 1 是 −0.014673（两次 seed 0 运行之间的散布 0.000386，见 §1），即等参数这一步不是走过场。

**不可判的情形没有出现**：三格的配对 Δ 都没有「一条越带、一条落带」，故不需要报 `n_req`（`README.md` §4 的分支）。

## 5. 族内失效模式（谁从哪一档开始伤质量）

键路径：`results.json::damage`（正 = 更差）。

| 族 | 档 | 相对同族 fp16 载体的 Δbpc | 越 0.014 带？ |
|---|---|---|---|
| 量化（MHA） | int8 块标尺 G=32（1.0625 B/值，6528 B/位置） | **+0.000017**（−0.000018 / +0.000052） | 不越 |
| 量化（MHA） | int4 块标尺 G=32（0.5625 B/值，3456 B/位置） | **+0.021180**（+0.023336 / +0.019024） | **越（1.5× 带）** |
| 低秩 | 潜维 272（+6.86% 参数） | **+0.000664**（+0.002858 / −0.001530） | 不越 |
| 低秩 | 潜维 272 + FFN 减宽（等参数） | **+0.004352**（+0.002377 / +0.006327） | 不越 |
| 低秩 | 潜维 144（−1.86% 参数） | **−0.000237**（+0.006660 / −0.007135） | 不越 |
| 低秩 | 潜维 128（−2.95% 参数） | **−0.003167**（−0.001292 / −0.005041） | 不越 |

人话：**量化的失效点在 8 位与 4 位之间**（8 位在这副骨架上近乎无损，4 位一次越过带宽）；**低秩的失效点没被摸到**——
潜维从 272 一路砍到 128（每位置字节从 6528 砍到 3072，4× 压缩）质量始终在带内，甚至略好于 fp16 基线
（−0.003167 是相对 fp16 的，量级在噪声地板内，不作「低秩更好」的结论）。
⇒ 下一档（`mla_c64`，1536 B / 8× 压缩）才是低秩失效点的位置，本实验没测（§10）。

顺带一条族内参照（不进同字节三格）：`gqa2` 上的 int4 是 **+0.056802**（1.553126 − 1.496324），
比 MHA 上的 int4 更疼——但 `gqa2@int4` 的字节（3072 B 解析口径不变）不在本实验的字节轴上，
故只作现象记录，不作判据。

## 6. 第二腿：合成长程召回（率类，走配对 bootstrap，不借 0.014）

键路径：`results.json::recall_paired[].pairs.<任务>`（`delta` = 低秩命中率 − 对照命中率）、
`::recall_floor_reference`（chance 与局部先验地板）、`points[*].runs[*].recall_*`（逐臂绝对命中率与 Wilson 95% CI）。

| 格 | 任务 | 配对 Δ（低秩 − 对照） | bootstrap 95% CI | 含 0？ |
|---|---|---|---|---|
| A（6528 B，vs int8） | copy（按位置） | **+0.037760** | [+0.022786, +0.053711] | 否 |
| A | induction（按起点） | **+0.066406** | [+0.039062, +0.093750] | 否 |
| A | var_recall（按距离） | +0.008464 | [−0.001302, +0.018880] | 是 |
| B（3456 B，vs int4） | copy | −0.005208 | [−0.018888, +0.008797] | 是 |
| B | induction | 0.000000 | [−0.021484, +0.021533] | 是 |
| B | var_recall | **−0.010417** | [−0.018229, −0.002604] | 否（对照略高） |
| C（3072 B，vs gqa2） | copy | **−0.031576** | [−0.044596, −0.016927] | 否（对照更高） |
| C | induction | **+0.039062** | [+0.017578, +0.062500] | 否（低秩更高） |
| C | var_recall | −0.005208 | [−0.012370, +0.001302] | 是 |

读法（三条，不许压成一句「第二腿没塌或塌了」）：
1. **A 格：低秩在 copy / induction 上明显高于 int8**（+3.8pp / +6.6pp，CI 不含 0）——即 8 位量化在 **bpc 上无损**
   的那一档，**召回腿上有可测的隐性损伤**；低秩没有。第二腿在这里**给了 bpc 看不见的信号**。
2. **B 格：低秩 bpc 更好但 var_recall 略低**（−1.04pp，CI 不含 0）⇒ 「bpc 好 ⇒ 召回好」不成立，两条腿必须分开报。
3. **C 格：低秩 copy 更低、induction 更高**，方向相反；而 var_recall 整条腿在**局部先验地板**上
   （所有臂 `at_floor = true`：地板阈值 0.025831，各臂 0.0072–0.0267）⇒ **这一档距离分量在本尺度不区分臂**，
   不得拿它下判词。copy 与 induction 两腿绝对命中率均在 chance（0.015625）与地板之上（0.1169–0.2461 / 0.0273–0.2051），
   但 `gqa2/gqa-12k-s0` 的 induction 命中 0.027344 已在**地板阈值 0.030999 之下**（`at_floor = true`）⇒
   C 格 induction 那一列的低秩优势有一部分是「对照贴地板」造成的，**不能读成低秩的 induction 能力更强**。

## 7. 代价（必须报的那一半）

键路径：`results.json::points.<臂>.runs[0].decode_cost`、`::points.<臂>.params`、`config.json::model_arms[].params_analytic`。

| 臂 | 每位置值数 | 每位置部署字节 | ×fp16 | 参数 | 上投影 MACs/层/token | 上投影 / 单层 FFN | 上投影 FLOPs/token（12 层） |
|---|---|---|---|---|---|---|---|
| `mha`（fp16/int8/int4） | 6144 | 12288 / 6528 / 3456 | 1 / 0.53125 / 0.28125 | 13,536,768 | 0 | 0 | 0 |
| `gqa2` / `gqa2_eq` | 1536 | 3072 | 0.25 | 12,352,512 / 13,536,516 | 0 | 0 | 0 |
| `mla_c272` / `mla_c272_eq` | 3264 | 6528 | 0.53125 | 14,464,512 / 13,536,495 | **139,264** | **17.7083%** | 3,342,336 |
| `mla_c144` | 1728 | 3456 | 0.28125 | 13,284,864 | **73,728** | **9.375%** | 1,769,472 |
| `mla_c128` | 1536 | 3072 | 0.25 | 13,137,408 | **65,536** | **8.333%** | 1,572,864 |

- 上投影只依赖**当前已生成位置**的潜向量 ⇒ 不引入额外顺序依赖、不需要 staging；
  `layer-passes` 每 token 仍是 `L`、`tokens-per-forward = 1`（低秩不加层、量化不改算力）。
- 「须从零训练」的代价：7 支新训臂各 12000 步 / 98.3M token（墙钟 8.23–10.07 min/臂，**不入判据**，只作复现成本）。
- 量化臂的代价面：`params_added = 0`、解码算力不变（多的是反量化的位运算，本口径不计）。
- **代价记账的读法**：格 A 上低秩以 17.71% 的 FFN 当量算力换来「与 int8 不可分」的质量 ⇒ 不利；
  格 B 上以 9.375% 换来「比 int4 好 0.017–0.026 bpc」⇒ 这是本实验里唯一站得住的交换。

## 8. 字节与训练健康对账

- **字节**：`L·d_c·2`（低秩，无标尺）与 `2·L·n_heads·d_head·(value_bytes + 2/G)`（量化，G=32）两条解析式，
  与实测张量形状反算逐条相等（如 `mla_c272` 的 `values_per_position = 3264`、`bytes_per_position = 6528`；
  `mha@int8` 的 `n_values = 6,291,456`、`n_scales = 196,608 = n_values/32`）⇒ **不使用插值，同字节是解析等式**：
  `12·272·2 = 6528 = 12·2·8·32·1.0625`；`12·144·2 = 3456 = 12·2·8·32·0.5625`；`12·128·2 = 3072 = 12·2·2·32·2`。
- **训练健康**：15 支（臂, 运行）`train_health.healthy = true` 全为真；`grad_skips = 0` 全为 0；`steps_done = 11999` 是训练日志（每 200 步一条）的最后一条记录步，配置步数是 12000；`gnorm_max` 分族：MHA 9.87–10.72、GQA 9.12–10.30、低秩 16.93–22.41（低秩侧更高是下/上投影那条新增路径的常态，未出现跳步）；
  5 支复用臂的 `train_health.healthy = true`。
- **实现 vs 部署**：评测期 int8/int4 立刻反量化、潜向量立刻上投影 ⇒ 实测显存峰值不随档下降；
  解析部署字节与实测峰值分列、不混用（本实验不报峰值，属未测项）。

## 9. 失败面与局限

1. **n = 2**：每格两侧各 2 条（格 C 的对照一侧是两次 seed 0 运行，`seed_aligned = false`）⇒ 只给方向一致性，
   不给跨 seed 分布。格 C 等参数对照的两条 Δ（−0.013947 / −0.003484）一条贴着带边（差 0.000053）、
   一条远在带内，这是本实验最脆的一处读数：**它不改变「落带内 ⇒ 不占优」的判词，但它说明这一档离带边很近**。
2. **单尺度、单序列长**：13M / L=12 / d=256 / T=256；`T > 256` 与更大规模都不外推。
3. **var_recall 整条腿在局部先验地板上**（所有臂 `at_floor = true`）⇒ 距离分量在本尺度没有区分力，
   第二腿的判词只由 copy / induction 承担。
4. **低秩的失效点没测到**：3072 B 仍是带内无损，低秩的失效 rank 在 `d_c < 128`（§10）。
5. **字节账是解析价签，不是实测峰值**：评测期即时反量化/上投影，真实实现的峰值下降本实验不测。
6. **`gqa2@int4` 这一族内点不在字节轴上**（解析字节仍是 3072 B），只作现象记录。
7. **格 C 的身份凭证降级**：`gqa2-eq-s1` 的指纹以 §3.1 的方式支撑（mtime + 尺寸 + 实测哈希 + 62 位前缀），
   不靠契约里那串转写错字。
