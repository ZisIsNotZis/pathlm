## 0. 人话摘要（先读这一段）

**这是干什么的。** 这条线只回答一个工程问题：**把 Transformer 的 KV 缓存（推理时存下来的
「注意力记忆」）压小，究竟能省多少内存、质量掉多少**。它不改模型结构、不训练——被测的
13.5M 稠密 decoder-only 变压器（12 层 × 256 维 × 8 头）与普通变压器逐字段相同，量的是
**推理期存哪几个字节**。

**为什么重测（本轮唯一改动）。** 上一批（`2621`，27 个点）的价签是在**非因果**量化下测的：
标尺按「整段序列 + 整批请求」的最大值算 ⇒ 一个位置的存储值会被**未来 token**或**同批别的
请求**改写（因果掩码挡不住）。这既不可部署、也不是评测该有的自由度。本轮把量化器改成
**逐请求、严格因果、流式**（位置 t 的标尺只看 ≤ t 的值，写完不改），**其余一切不变**
（同一批 checkpoint、同一数据流、同一 27 个臂、同一判据）。

**测出来两件事，第二件推翻了旧账。**

1. **质量：因果口径下的损伤比旧账更小**（旧账把量化代价算大了）。非量化臂逐位不变
   （max|Δbpc| = 0 ⇒ 唯一改动确实只有量化器）；int8 的损伤 +0.000117、int4 +0.024748
   （旧账分别是 +0.00015 与 +0.0457）。**但这张质量表是在「每值配一个自己的标尺」这个
   最贵的存法下测的**——见第 2 件。
2. **内存：旧账的「int8 省一半」在严格因果口径下不成立，而且是反的。**
   严格因果 ⇒ 标尺逐位置变、无法摊薄 ⇒ 每个值要多存一个 2 字节的 fp16 标尺：
   **int8 = 1 B 值 + 2 B 标尺 = 3 B/值**（fp16 基线 2 B/值）、**int4 = 0.5 + 2 = 2.5 B/值**。
   换成部署关心的每位置字节：**int8 18 432 B/位置（是 fp16 的 1.5 倍）、int4 15 360（1.25 倍）**。
   即：**按本实验实现的口径，量化不省内存，反而多占 50% / 25%**；图上 10 个量化臂的横坐标
   整体右移越过 fp16 基线，**全部相对同拓扑的不量化臂变成「更多字节、质量不更好（或更差）」**。

**要真省内存只有一条路（本文给出但未实现、未测）：分块标尺 + 块内回填。** 每 32 个连续位置
共享一个标尺，摊薄后 int8 ≈ 1.0625 B/值（省 **46.9%**，不是 50%）、int4 ≈ 0.5625（省 **71.9%**，
不是 75%）。**代价必须明写**：块内不再是严格前缀确定——块首位置的存储值会被同块后续最多
**31 个位置**改写；回填需要 staging 缓冲（0.182 MiB/请求）；**而且它的质量代价本实验根本没测**
（现有质量数字全是「最贵的那个存法」下的）。

**结论与下一步。** 采纳：头共享（MQA 省 87.5%）、窗口（win128 省 50%，质量损伤 0.020）——
这两条是真正的省内存杠杆，且它们不涉及标尺。**不采纳**：严格因果逐值标尺下的 KV int8/int4
量化——它在内存轴上是负收益（质量近无损但等于白花钱买更小的缓存，int4 还额外损伤 0.019）。
待补：(b) 方案要先立决定（它会放弃「过去位置严格前缀确定」，这是产品级取舍），然后测它的
质量代价；在那之前，「量化省内存」这条主张在部署口径下**只能按 46.9% / 71.9% 的天花板**说，
且必须注明违反前缀确定。

## 3. 与旧口径的方向对照（判据 ②）

- **非量化臂逐位不变**：max |Δbpc| = 0（17 个非量化臂：8 窗口 + 3 窗口×锚点 + 3 头共享 + 2 头共享×窗口 + `fp16`）⇒ 本轮唯一
  改动的因子确实只有量化器标尺约定，其余全部可复现（`table.md` 表 2 / 表 4）。
- **量化臂的 10 个点全部朝「损伤更小」的方向变**：Δbpc(新−旧) 全为负。
  - `int8`：1.483721 → 1.483688（−0.000033，远在噪声带内，**不可排序**）；
  - `int4`：1.529232 → 1.508319（**−0.020913**，即旧口径把 int4 的代价**夸大了 0.021 bpc**）；
  - 组合臂同向：`gqa_int4` −0.049054、`mqa_int4` −0.101390、`win16_anchor16_int4` −0.030634、
    `win32_anchor32_int4` −0.021909；int8 组合臂在 −0.00003…−0.00025 量级（不可排序）。
- **方向上为什么不奇怪（算术对账）**：旧口径的标尺 = **整段序列**的 amax；本口径的标尺 =
  **截至当前位置**的 running max ≤ 整段 amax。取整误差上界 `|x̂−x| ≤ 0.5·标尺` 随标尺**单调**
  ⇒ 本口径每个位置的误差上界**不大于**旧口径 ⇒ 质量代价只可能更小，实测与之一致。
  **换句话说是同一根绳子的两头**：因果逐值标尺既给出了最细的步长（质量最好），
  也给出了最大的存储开销（每值一个标尺）——本批的质量数字买的就是这个最贵的存法。

> 说明：旧口径的 bpc 出自 `2621`（`results.json::causal_vs_old.rows[*].bpc_old`，逐字未改）；
> 对照的是 `2621` 的**同一 27 点**、同一数据流、同一 checkpoint。

## 4. 部署口径答复：**「int8 省内存」成立吗？**

### 4.1 严格因果逐值标尺（方案 a = 本实验实现）：**不成立，而且是反的**

| 点 | 值字节 | 标尺 | 真实字节/位置 | 相对 fp16 基线（12 288） |
|---|---|---|---|---|
| `fp16`（基线） | 12288 | 无 | 12288 | — |
| `int8` | 6144 | 2 B/值 | **18432** | **多占 50%**（旧账称 −50%） |
| `int4` | 3072 | 2 B/值 | **15360** | **多占 25%**（旧账称 −75%） |

原因一句话：**严格前缀确定的价钱就是「标尺不能摊薄」**（`kv_quant.py` 的实现：位置 t 写完即定、
不重编码、没有 fp16 残差窗口）。因此**「int8 省一半」只有在假定标尺免费时才成立**。

**逐臂把它钉死**（每行拿同拓扑的**不量化**臂做对照，这是最诚实的对手）：

| 量化臂 | 同拓扑 fp16 臂 | 字节 (a)：臂 / 参照 | 倍率 | 损伤 bpc：臂 / 参照 | (a) 口径判读 |
|---|---|---|---|---|---|
| `int8` | `fp16` | 18432 / 12288 | ×1.50 | +0.000117 / +0.000000 | 无优势（质量差异不可排序，字节多 50%） |
| `int4` | `fp16` | 15360 / 12288 | ×1.25 | +0.024748 / +0.000000 | **被支配**（字节更多 + 质量更差） |
| `gqa_int8` | `gqa` | 4608 / 3072 | ×1.50 | +0.014386 / +0.014299 | 无优势 |
| `gqa_int4` | `gqa` | 3840 / 3072 | ×1.25 | +0.061458 / +0.014299 | 被支配 |
| `mqa_int8` | `mqa` | 2304 / 1536 | ×1.50 | +0.011935 / +0.011737 | 无优势 |
| `mqa_int4` | `mqa` | 1920 / 1536 | ×1.25 | +0.105930 / +0.011737 | 被支配 |
| `win32_int8` | `win32` | 2304 / 1536 | ×1.50 | +0.211865 / +0.211813 | 无优势（同一掩码，只有存法不同） |
| `win64_int8` | `win64` | 4608 / 3072 | ×1.50 | +0.080569 / +0.080506 | 无优势 |
| `win16_anchor16_int4` | `win16_anchor16` | 1920 / 1536 | ×1.25 | +0.429034 / +0.374835 | 被支配 |
| `win32_anchor32_int4` | `win32_anchor32` | 3840 / 3072 | ×1.25 | +0.138009 / +0.106968 | 被支配 |

**10 个量化臂无一例外**：字节倍率恒为 ×1.50（int8）/ ×1.25（int4），而质量**不更好**
（int8 型 5 个：与不量化臂的差异不可排序；int4 型 5 个：更差 0.019–0.054 bpc）。⇒ 在 (a) 口径下
**量化在任何拓扑上都是内存轴的负收益**，图上 Pareto 前沿只剩「窗口 / 头共享 + fp16 存储」。

> **此结论已被 `2632-kv-block-scale` 取代（见 R1 格页）**：块标尺沿 `head_dim` G=32 下 int8 =
> 6528 B/位置 = fp16 的 ×0.53（省 46.875%）且**严格前缀不变** ⇒ 量化是省内存手段；
> 「内存负收益」是**逐值标尺实现**的产物。

> 旧账的入场句是「用每值 1 / 0.5 字节替代 2 字节，**省访存**」（`2621-kv-budget-rest/README.md`）。
> 这句在 (a) 口径下**两种货币都错**：容量是 3 B/值（而非 1）；解码时每个值也要多读 2 字节的
> 标尺（访问量同样升高）。除非标尺能留在片上/寄存器——那正是 (b) 要解决的问题。

### 4.2 分块标尺 + 块内回填（方案 b，**本实验未实现、未测**）：成立，但要打折并让出性质

| 块大小 G | 标尺 B/值 | 过去值受未来影响的**最大距离** | int8 B/值 | int4 B/值 | int8 省幅 | int4 省幅 |
|---|---|---|---|---|---|---|
| 8 | 0.2500 | 7 个位置 | 1.2500 | 0.7500 | 37.5% | 62.5% |
| 16 | 0.1250 | 15 个位置 | 1.1250 | 0.6250 | 43.8% | 68.8% |
| **32** | 0.0625 | **31 个位置** | **1.0625** | **0.5625** | **46.9%** | **71.9%** |
| 64 | 0.0312 | 63 个位置 | 1.0312 | 0.5312 | 48.4% | 73.4% |
| 128 | 0.0156 | 127 个位置 | 1.0156 | 0.5156 | 49.2% | 74.2% |

→ **G=32 时 int8 省 46.9%（不是 50%）、int4 省 71.9%（不是 75%）**；把 G 拉到 128 也只能到
49.2% / 74.2%，而违反距离涨到 127 个位置。**「省 50% / 75%」是这条曲线的极限，不是任何
可行块的现值。**

代价三条（全部如实记账，`table.md` 表 5 同）：

1. **违反严格前缀确定性**：块内过去值的存储表示会被同块后续 ≤ G−1 个位置改写（回填后冻结）。
   这不是「实现差异」，是**让出**了本实验判据 ① 检的那条性质（所以 (b) 不能沿用 (a) 的质量数字）。
2. **staging**：块关闭前必须留着原始 fp16 值才能按最终标尺重编码 ⇒ 平均 15.5 个位置的 fp16 缓冲
   = **0.182 MiB/请求**（与 T 无关；T=256 时折合 744 B/位置，T=4096 时 46.5 B/位置）。
3. **重算 / 写放大**：每值 1 次编码 + 1 次延迟写（块关闭时一次性写一个块）。若不留 staging，
   就得先按 running 标尺编码、关块时重编码 ⇒ 每值 2 次编码 + **二次取整误差（未测）**。
   本表的摊薄分母取 `min(G, 段长)`，是**乐观上界**（窗口/块不对齐时省得更少）。

**质量代价未知（不许当成已测）**：块内 amax ≥ 位置 amax ⇒ (b) 每值的误差上界只会更大
（倍数 = 块内 amax / 位置 amax ≥ 1），但本实验**没有**任何 (b) 口径的 bpc/召回读数。
所以 (b) 只能作为**候选设计**，不是结论。

### 4.3 第三种口径（解析注记，未测）：标尺沿**非 token 轴**共享可以不违反因果

V 若按 token 取 `head_dim`（32 个通道）维 amax，位置 t 的标尺只由 t 自己决定 ⇒ 严格因果、
而且只用 2/32 = 0.0625 B/值（与 G=32 的 (b) 同价）。K 侧做不到（沿 token 轴才有足够动态范围），
所以业界（KIVI 类）是「K 分块 + V 逐 token」；该设计下违反前缀确定的只有 K 一半的值。
本实验未测这条，只用来说明「(a) 的 3 B/值不是物理下限、而是本实现的口径」。

> **「K 侧做不到」已被 `2632-kv-block-scale` 否证（见 R1 格页）**：K 也可沿 `head_dim` 分块
> （`block` 方案）摊到 `2/G` B/值**且保持严格因果**；非 token 轴的摊薄不是 V 的特权。

## 5. 三道对账（SCHEMA §12）

1. **算术对账**（字节必须自洽，且给上下界）：
   - (a) 的每值成本 = `值字节 + 2`（标尺是 fp16）。int8 = 3.0、int4 = 2.5、fp16 = 2.0 是**等式**，
     不是估计；每位置总量 = `2·L·n_kv_heads·head_dim·(值字节+标尺)·kept/T`，与 `results.json`
     记录的 `bytes_per_position`（值字节）逐点对账通过（`budget_caliber.deployment_bytes` 内部断言，
     单测 `test_segments_reproduce_the_recorded_axis_factor_for_every_arm` 钉住）。
   - **下界**：标尺最小可行 dtype 是 fp8（1 B）⇒ (a) 的物理下界 = int8 2.0 B/值（**与 fp16 打平**）、
     int4 1.5（省 25%）。⇒ 即便把标尺换成最省的 1 字节，「int8 省一半」也不成立（最多打平）。
   - **上界/代价**：`|x̂−x| ≤ 0.5·scale`（取整误差，running max 不越界 ⇒ 无额外 clip 误差）。
     实测 `clipped_frac ≈ 0.96%`（int8）不是真剪裁：复现检查（`torch.manual_seed(0)`、
     `randn(2,4,256,32)*0.1`、int8）显示越界位置 240/65536 **全部**是「该位置就是 running max」
     的位置，超出 qmax ≤ 7.63e-6（≈ 127 的 1 ulp），最大取整误差 1.49e-8，且全体满足
     `|x̂−x| ≤ 0.5·scale`（最大比值 0.99998 < 1）。
   - 旧账夸大方向的**不等式**：running max ≤ 全段 amax ⇒ 本口径误差上界 ≤ 旧口径（见 §3）。
2. **任务对账**：
   - 质量两腿与来源实验同任务、同数据流、同位置集（`bpc_of` 与 `masked_bpc` 逐位相等、
     `synth_accuracy` 与仪器 n/hits 全等）⇒ 与 `2619/2620/2621` 的读数可比。
   - **质量数字与 (a) 价签同源**（同一 `cummax` 实现、同一评测前向）；**(b) 的价签没有对应的
     质量测量** ⇒ 不许把 (a) 的 bpc/召回挂到 (b) 的字节上。
   - **评测期 GPU 峰值（462.5 MiB）不是内存价签**：评测实现立刻反量化、峰值不随档下降。
3. **口径对账**：T = 256 固定；窗口/锚点臂的 `kept/T` 与 T 有关（同一窗口在更长上下文里更省），
   量化臂的每位置字节与 T 无关，(b) 的 staging 是与 T 无关的常数项 ⇒ **禁外推到别的 T**；
   本批是**快照口径**（12k/12k 步的冻结 checkpoint，单 seed），只描述这些点。

## 6. 统计口径声明（复核 B2：不许把同一序列的多次查询当独立二项样本）

- 本表的召回 CI 沿用 `2619/2620/2621` 的 **Wilson 95%**（按池化计数）。**B2 指出的问题适用**：
  同一序列的多个查询共享同一 KV 表、不放回 ⇒ 独立二项假设偏乐观，Wilson 区间**偏窄**。
- **如实量化这个偏差**（本实验数据自带三个源位置簇，每簇 n = 1024）：

| 臂 | copy 池化 | Wilson 95% | 逐源簇（src_pos = 0 / 96 / 191） | 三簇极差 | Wilson 半宽 |
|---|---|---|---|---|---|
| `fp16` | 0.1413 | [0.1294, 0.1540] | 0.1406 / 0.1572 / 0.1260 | 0.0312 | 0.0123 |
| `int8` | 0.1416 | [0.1297, 0.1544] | 0.1406 / 0.1572 / 0.1270 | 0.0303 | 0.0123 |
| `int4` | 0.1270 | [0.1156, 0.1392] | 0.1270 / 0.1445 / 0.1094 | 0.0352 | 0.0118 |
| `gqa` | 0.1689 | [0.1561, 0.1826] | 0.1826 / 0.1807 / 0.1436 | 0.0391 | 0.0132 |
| `mqa` | 0.2432 | [0.2283, 0.2586] | 0.1875 / 0.2607 / 0.2812 | 0.0938 | 0.0152 |
| `mqa_int4` | 0.1950 | [0.1814, 0.2094] | 0.1455 / 0.2148 / 0.2246 | 0.0791 | 0.0140 |
| `win64` | 0.0589 | [0.0511, 0.0678] | 0.0127 / 0.0205 / 0.1436 | 0.1309 | 0.0083 |

  ⇒ 簇间极差（0.03–0.13）**大于** Wilson 半宽（0.008–0.015）**2.5–15.7 倍**（逐行 2.46 / 2.46 / 2.99 /
  2.95 / 6.18 / 5.65 / 15.69）：**池化 CI 偏窄是实测的，
  不是猜测**。因此本文件的召回**水平值**只作描述，不作排序依据。
- **按 B2 的建议另做簇 bootstrap**（簇 = 源位置，3 簇，重抽样 2 万次，`random.seed(0)`）：
  水平值的半宽是 Wilson 的 **1.2–7.8 倍**（fp16 ×1.3、int8 ×1.2、int4 ×1.5、gqa ×1.5、
  mqa_int4 ×2.8、mqa ×3.1、win64 ×7.8）。
  **只有 3 个簇 ⇒ 区间粒度很粗**（端点只能落在簇准确率上），故它只当稳健性检查，不当精确 CI。

  复现该区间的口径（本文件写入时实跑过，`mqa_int4` 为例）：

  ```python
  import json, random; random.seed(0)
  P = {p['arm']: p for p in json.load(open('results.json'))['points']}
  v = [P['mqa_int4']['recall_copy']['per_setting'][k]['accuracy'] for k in ('0', '96', '191')]
  m = sorted(sum(random.choice(v) for _ in range(3)) / 3 for _ in range(20000))
  print(m[500], m[19500])          # → 0.1455 0.2246（= 上文 [0.1455, 0.2246]）
  ```
- **配对比较（本文件实际用到的那些）在聚类下依然稳**：同一查询集上逐簇做差，
  `int8 − fp16` = 0 / 0 / +0.001（簇 bootstrap 95% = [0.0000, +0.0010]）、
  `gqa_int8 − gqa` = 0 / −0.002 / −0.001（[−0.0020, 0.0000]）、
  `win64_int8 − win64` = 0 / 0 / +0.001（[0.0000, +0.0010]）、
  `int4 − fp16` = −0.0137 / −0.0127 / −0.0166（[−0.0166, −0.0127]）、
  `mqa_int4 − mqa` = −0.042 / −0.046 / −0.057（[−0.0566, −0.0420]）。
  ⇒ 「int8 型与不量化臂**无差异**」「int4 型**确有损失**」在配对/聚类口径下方向一致。
- 剂量口径：bpc 用预登记的 Δ < 0.014 不可排序；召回没有等价的预登记带 ⇒ 召回差异只在
  「三簇方向一致且幅度 ≫ 簇内极差」时才陈述趋势。

## 8. 失败与局限（「以为会怎样 / 实际怎样 / 为什么 / 排除了什么」）

1. **以为**：把量化器改成因果口径后，量化臂的内存价签（值字节）不用动，只是质量数字略变。
   **实际**：质量确实只略变（且在「损伤更小」方向），但内存价签**整体作废**——因果性本身要付
   「每值一个标尺」的钱，值字节列把它隐藏了。
   **为什么**：严格前缀确定 ⇒ 标尺随位置变化 ⇒ 无法摊薄（`kv_quant.py` 的性质表已明写）。
   **排除的解释**：不是「实现没修好」（前缀不变性 27/27 成立）、不是「仪器换了」
   （非量化臂逐位不变、bpc 与仪器逐位相等）、也不是「多算了评测显存」（462.5 MiB 单列，不进解析列）。
2. **以为**：`(b)` 可以作为「既省内存又不违反因果」的方案直接采用。
   **实际**：`(b)` 是**放弃**块内前缀确定性换来的（违反距离 ≤ G−1 = 31 个位置），而且它的
   质量代价本实验**没有测**。**排除的解释**：不是「(b) 不可行」——它在工程上常见（KIVI 类），
   而是它属于**产品级取舍**（能否接受块内回写），须先立决定再测。
3. **以为**：评测实现里 `clipped_frac ≈ 0.96%` 意味着 causal 标尺也会剪裁、误差上界不成立。
   **实际**：那只是 running-max 位置上的浮点边界（超出 qmax ≤ 1 ulp），取整误差仍 ≤ 0.5·标尺
   （§5 算术对账的复现检查）。
4. **局限**：① 单 seed、单规模（13.5M）、单 T（256）、快照口径；② 质量数字只覆盖 (a)；
   ③ (b) 的块对齐是乐观取值；④ 头共享族的参数量混杂（−8.75%/−10.25%）未解，本文件不据此
   宣称「头共享优于窗口」；⑤ 本实验**不改** `tools/evalkit/kv_quant.py`、不改 `catalog.yaml`。
