# 2642 · 跨家族同字节预算重画（块标尺口径）—— 判读

> 契约（本目录）：`README.md` + `config.json::criterion`（**运行前**写入）。
> 表：`table.md`；机器可读：`results.json`；日志：`run_log.txt`；脚本：`frontier_ledger.py`。
> 本实验是**纯再分析**：无前向、无训练、不占 GPU 锁、不联网；唯一数据源 = `2632` 的落盘读数。

---

## 0. 人话摘要（先读这一段）

**这是干什么的。** 上一格（5.1）已经判定「8 位 KV 量化近无损、省约一半内存」。但那条判定只在一个族里读：
同一个模型，只改它缓存数值的精度。可「省 KV 内存」还有别的招——**头共享**（让多个查询头共用一份键值，GQA/MQA）
和**窗口**（干脆只留最近若干个位置）。这三招谁更值？只能在**同一条内存横轴**上比：横轴 = 每个位置
真正要占的字节（数值 + 标尺，不含虚的「比特数」），纵轴 = 质量（越低越好的 bpc）与长程召回（越高越好）。

**为什么必须重画。** 旧的那张跨家族图建立在**逐值标尺**口径上（每个数值配一把 2 字节标尺），那个口径
把「省一半内存」反算成了「多占一半内存」，已经作废（55-review W-08 / R8）。本实验用**块标尺**口径
（沿 head_dim 每 32 个值共用一把标尺 = 每值多 2/32 字节）把 27 个已测点重新摆到同一条轴上。

**测出来三件事。**

1. **口径对账零误差。** 我不用 `2632` 给的字节数，而是从原始因子（层数、KV 头数、头维、保留位置数、
   值字节、标尺方案）**独立重算** 27 臂的部署字节，与 `2632` 记录的数字**逐位相等**（`max|Δ| = 0`）。
   同时发现一个容易踩的坑：`2632` 的 `points[*].bytes_per_position` 是**只算数值**的口径，
   量化臂上它比**部署口径**小（int8：6144 vs 6528）——两者不是一回事，混用就是口径错。

2. **同字节的跨家族比较是可能的，一共 7 个字节水平**（432 / 768 / 816 / 864 / 1536 / 1632 / 3072 B/位置），
   不需要插值。**在这 7 个水平上，bpc 最低的**都是**头共享族**的点（432: `mqa_int4`；768: `gqa_win64`；
   816: `mqa_int8`；864: `gqa_int4`；1536: `mqa`；1632: `gqa_int8`；3072: `gqa`）。
   看第二腿（长程 copy 召回）也一样：816 B/位置的 `mqa_int8` 召回 0.2448，同字节的 `win32_int8`
   只有 0.0143（差 17 倍）。
逐组核对（每组的 `recall_copy_ci` 都在 `results.json::same_byte_groups[*].members[*]` 里）：**7/7 组的「bpc 最优臂」同时就是「copy 召回最高臂」**，且它与组内其余臂的 Wilson 95% CI **不重叠**（1536 组与 2 个臂不重叠、3072 组与 2 个臂不重叠，其余组与组内唯一的对照臂不重叠）⇒ 两条腿**同向**，即「头族更优」不是单腿假象；但两条腿同样都被参数量混杂污染（见 §3）。

3. **但这个「头共享更值」的读数被参数量混杂污染，本实验把它拆开了。** 头共享族的 checkpoint 参数更少：
   磁盘实测 MHA 13536768 参数，GQA 12352512（少 8.75%），MQA 12155136（少 10.21%）；
   差额与解析式 `L·(2·d_model+2)·(H−n_kv)·head_dim` **逐位相等**。也就是说：头共享省的不只是 KV 字节，
   还可能因为「参数更少、同样 token 预算下更欠训练」而在某些指标上失真 ⇒ **不能说头共享在字节轴上
   纯机制更好**，只能说「在**当前这套不同参数量**的 checkpoint 上，它在每个同字节水平上都赢」。
   要读「纯机制」必须补等参数臂——本实验把这一步的成本登记在 §7。

**顺带两件必须诚实报的。** ① 8 位里 **int8+块标尺不是最省的**：同价对手 fp8（解析 1 B/值、无显式标尺 =
6144 B/位置 = ×0.50）比 int8+块标尺（6528 B/位置）省 384 B/位置，而 fp8 的**质量本轴没测**（归 `5.5`）。
② 旧说法「同一 −75% 档 GQA 便宜 3.2×」随逐值标尺口径一起作废：块标尺下 −71.875% 的档位是 trunk int4
（3456 B/位置），头共享 fp16 GQA 是 3072 B/位置——两族**不再落在同一字节水平**上，旧的「同档」比法不成立。

## 2. 同一「每位置部署字节」轴上的跨家族读数

横轴公式：`部署字节/位置 = 2(K,V) · L · n_kv_heads_eff · head_dim · (值字节 + 标尺字节/值) · (kept / T)`，
其中块标尺 `标尺字节/值 = 2/G = 0.0625`（G=32），非量化臂为 0；T=256。`staging`（只有非因果方案需要）
**单列、不进主横轴**。判据带 = 在力带 **0.036324 bpc**（本格自测的单臂跨窗口极差；标准口径要求配对 Δ、
≥5 窗口，本批只有 3 个 ⇒ 退用更保守的单臂带）。

7 个跨家族同字节组（完整表见 `table.md` 表 2），每组都列 bpc 与 copy 召回两腿：

| 字节/位置 | 组内族 | bpc 最低臂（参数混杂？） | bpc 极差（>带即可排序） |
|---|---|---|---|
| 432 | 头共享×量化 / 窗口×量化 | `mqa_int4`（是） | 0.268919 ✔ |
| 768 | 头共享×窗口 / trunk×窗口 | `gqa_win64`（是） | 0.526426 ✔ |
| 816 | 头共享×量化 / 窗口×量化 | `mqa_int8`（是） | 0.201684 ✔ |
| 864 | 头共享×量化 / 窗口×量化 | `gqa_int4`（是） | 0.069358 ✔ |
| 1536 | 头共享 / 头共享×窗口 / trunk×窗口 / trunk×窗口+锚点 | `mqa`（是） | 0.364643 ✔ |
| 1632 | 头共享×量化 / 窗口×量化 | `gqa_int8`（是） | 0.067753 ✔ |
| 3072 | 头共享 / trunk×窗口 / trunk×窗口+锚点 | `gqa`（是） | 0.094214 ✔ |

**读法**：同字节组内 bpc 极差**全部越带**（可排序），且 **7/7 组的最优点都是头族**；
但 7/7 组的头族点都带参数量混杂标记 ⇒ 该优势**不能**直接归因给「头共享机制」。
非头族之间的同字节对照（1536 组内 `win32` 1.695384 vs `win16_anchor16` 1.858406，差 0.163022 **越带** ⇒ 窗口臂在该字节水平上严格优于窗口+锚点臂；3072 组内 `win64` 1.564077 vs `win32_anchor32` 1.590539，差 0.026462 **在带内** ⇒ bpc 腿**不可排序**）。
特别地，3072 B/位置这一对**两腿结论不一致**：bpc 腿不可排序（+0.026462 < 0.036324），但长程 copy 召回腿的锚点臂
0.0934 [0.0836, 0.1042] 与窗口臂 0.0589 [0.0511, 0.0678] 的 Wilson 95% CI **不重叠** ⇒ 锚点臂在召回腿上更好。
按本轴的组合判定纪律（`2621` §1「两条腿结论不一致必须显式标注」），此处**不得**只看一条腿下结论。

## 3. 参数混杂拆开（本项此前记为「未拆」）

`5.1` 的 `conclusion_review` / `gaps` 此前记「头共享族有参数量混杂（−8.75%/−10.25%）未拆」。本实验拆开：

| checkpoint | 参数量（磁盘实测，`torch` 数 state_dict） | n_kv_heads | 与 MHA 的差（实测） | 与 MHA 的差（解析） | 相对 |
|---|---|---|---|---|---|
| trunk | 13536768 | 8 | — | — | — |
| mha | 13536768 | 8 | — | — | — |
| gqa | 12352512 | 2 | 1184256 | 1184256 | 8.75% |
| mqa | 12155136 | 1 | 1381632 | 1381632 | 10.21% |

解析式 = `L · (2·d_model + 2) · (H − n_kv) · head_dim`（含 k/v 投影偏置，系数 2 来自 k 与 v 两个投影）
⇒ **解析与实测逐位一致**。旧记的 −10.25% 与磁盘实测（−10.2065%）略有出入（早先的估算口径未落盘，无法回溯其来源），已按磁盘实测更正为 **−10.21%**。

**为什么这很重要**：同尺寸同 token 预算下，头共享族的模型**更小** ⇒ 它的质量读数与字节优势不是同一个
自由度的比较；「头共享在每个同字节水平上都赢」这个事实**不能**读成「头共享机制更省内存且不亏质量」。
要读纯机制必须补等参数臂（把省下的参数还给 FFN/宽度，见表 6 的成本）。

## 4. 8 位方案里的字节最优（fp8 解析点）

| 方案 | 值字节/值 | 标尺字节/值 | 部署字节/位置 | ×fp16 | 质量 |
|---|---|---|---|---|---|
| fp16（全因果基线） | 2 | 0 | 12288 | ×1.00 | 1.483571 |
| int8 + 块标尺 G=32 | 1 | 0.0625 | 6528 | ×0.53 | 1.483672（Δ+0.000101） |
| **fp8（E4M3/E5M2）** | 1 | 0（免显式标尺） | **6144** | **×0.50** | **未测** |

⇒ 只能报「fp8 解析上比 int8+块标尺省 384 B/位置（−5.9%）、质量未知」；**不得**声称 int8+块标尺是
所有 8 位方案的最优。补这个质量点 = `5.5` 的 WP1（成本见表 6）。

## 5. 被作废说法的替代读数

- 作废：「同一 −75% 档 GQA 便宜 3.2×」（建立在逐值标尺 int4 上，55-review W-08 / R8）。
- 替代（块标尺口径）：`−71.875%` 档 = trunk `int4` = **3456 B/位置**（bpc 1.506093）；头共享 fp16 `gqa`
  = **3072 B/位置**（bpc 1.496325，但少 8.75% 参数）。两族**不同档**，旧「同档 3.2×」不可复现。
- 跨家族比较的正规读法 = §2 的同字节分组（7 个水平），不再用「压缩率档位」对齐。

## 6. Pareto（同一条字节轴）

- **原始 bpc 序**（严格更好才算支配）非支配集 = `mqa_int4`, `gqa_win64`, `mqa_int8`, `mqa`, `int8`, `mha`
  （6 臂）。其中 **4 个是头族**（`mqa_int4` / `gqa_win64` / `mqa_int8` / `mqa`；另 2 个是 trunk 基线 `mha` 与
  trunk×量化 `int8`）⇒ 原始 Pareto 的前沿**绝大部分被头族占住**；原始序的被支配点及其支配者见
  `results.json::pareto.raw_dominated_with_dominator`（21 条），例如 `int4`（3456 B，bpc 1.506093）
  被 `mqa_int8`（816 B，1.493933）支配、`fp16`（12288 B，1.483571）被 `mha`（同字节，1.482026）支配。
  **这正是参数量混杂的可见后果**：原始序里大量 trunk 臂被「更小参数的头族臂」支配，不能读成机制优势。
- **越 0.036324 带才算更好**（更保守）= 16 臂（见 `table.md` 表 4）；越带序的被支配点及其支配者见
  `results.json::pareto.dominated_with_dominator`。
- 注意：`int4`（3456 B）在原始序里被 `mqa_int8`（816 B）支配；在越带序里两者都留在前沿
  （`int4` 的 bpc 优势不足 0.036324 ⇒ 不构成「严格更好」）。

## 7. 限制与下一步（不谎报「完成」的边界）

1. **不插值**：bpc–字节前沿不光滑（不同机制损伤机理不同），两点之间插值 = 编造数据 ⇒ 本实验只在
   **恰好同字节**的点上做直接比较。未覆盖的字节水平（如 1920 / 6144 之外的量化档）需要补臂。
2. **同参数族的纯机制比较仍缺**：头共享族与 trunk 族不同参数 ⇒ 需要一个**等参数**臂（把
   `Δparams` 还给 FFN 或宽度）才能读「头共享 / 量化 / 窗口在等参数下的同字节序」。**下一步最小实验 +
   等效算力成本**：训练 1 个等参数 GQA 臂（宽度/FFN 补偿 1184256 参数）⇒ 每 token 训练 FLOPs ≈ 同
   trunk 基线 × (1 + Δparams/params) ≈ ×1.09；token 预算、步数、seed 数（n≥2）与 `2616` 对齐 ⇒
   约 2 个 run × 12k 步 × 98.3M token 量级的等效算力（GPU 按 `harness/SCHEMA.md` §20 串行）。
3. **fp8 质量未测**（`5.5` WP1）：本实验只能给它的解析价签。
4. **单尺度**：T=256、`head_dim`=32；窗口臂的 `kept/T` 与 T 有关，`head_dim` 更大时刻标尺摊得更薄
   （归 `5.5` WP2）。禁外推。
5. **证据力上限**：本实验不产生新的质量证据；它的结论强度上限 = 落盘读数在统一口径下的正确重排
   （已在 `results.json::answer.cannot_claim` 列明）。
