## 2. 三条腿为什么都要有（SCHEMA §17 第 10 条）

- **bpc 腿**（clean bpc）量的是「模型对语言建模有多依赖这些 KV」——**依赖**；
- **召回腿**（合成 copy / induction / var_recall）量的是「远处信息还在不在、取不取
  得回」——**保留**；
- **毁源腿**量的是「召回读数是否真的来自被搬运的那段信息」——**归因**。

低损伤 + 低召回 = 「模型本来就不用」（假保留）；低损伤 + 正常召回 = 「真保住了」。
只报 bpc 无法区分这两者（本项目最贵的一次入账错误，见 SCHEMA §17.11 与本仓 A4 格）。

## 3. 方差界

- **bpc**：`docs/methodology.md` 的排序门槛 **0.014**。本实验所有 bpc 都是
  **同进程同路径**重测，且与来源实验**逐位一致**（14/14，见
  `results.json::cross_check_vs_source`）⇒ 跨实验口径差为 0。
- **召回**：Wilson 95% CI（`results.json::points[*].recall_copy.wilson95`）。
  两点 CI 重叠 ⇒ **不可排序**；某腿 ≤ `chance + 2·σ_wilson` ⇒ 判据 C4 的
  `at_floor = true`（读作「在该任务上不可分辨」，不是「机制无效」）。
- **重跑散度**：本实验为纯推理、无随机采样 ⇒ 同 seed 重跑应逐位相同；令 `rerun`
  记录见 `results.json`（两次全跑对比）。
