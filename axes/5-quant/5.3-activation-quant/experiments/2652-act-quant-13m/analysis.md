## 0. 人话摘要

**把模型前向里的「中间激活」从 fp16 压成 int8 再算一遍，质量几乎不变；压成 4 位就崩了。**

只改一处：每层 4 个 `nn.Linear` 的**输入激活**（每个 token 共 27648 个数）以 int8 存放，
并给每个 token 配一把 fp16 动态标尺（per-token）。激活占用的字节从 fp16 的
**55296 B/token 降到 27744 B/token（省 49.8%）**，而 clean bpc 只从 **1.47462 涨到 1.47815**：
5 个窗口上「同臂同窗口 − fp16」的**配对 Δ 最大 0.00353 bpc**，**落在预登记的 0.014 噪声带内
⇒ 在本尺度上 int8 激活的质量代价与 fp16 不可分辨**。长程召回（copy）从 14.13% 到 13.87%，
95% 置信区间重叠，也看不出下降。

换成 **4 位**激活（13920 B/token，省 74.8%）则**在本尺度不成立**：bpc 从 1.47 崩到 **5.04**
（配对 Δ ≈ 3.6，**远超 0.014 带**），copy 召回掉到 **2.02%**、**落到地板**（`at_floor=true`）。

**离群通道没有迫使回退**：逐层通道峰值超过中位数 6 倍的通道只有 8 个（int8）/ 18 个（4 位），
若真把它们留在 fp16，只吃掉标称省幅的 **0.03% / 0.07%** —— 远小于「迫使回退」的门槛。预登记只写
「省幅**远小于标称**」（`config.json::criterion.verbatim_contract`），**10% 是实现层 `run.py` 自设的
活性阈值**（`run.py` 的 `saving_eaten_frac > 0.10`，未写进 `criterion`）；本读数对阈值取 1%/10%/50%
中任何一个都不变。

三句话讲清相对「普通 decoder-only 变压器」改了什么：**结构没改、参数没增（`params_added=0`）、
没训练、KV 精度没动**；只是在 4 处矩阵乘的输入上多做了一次「取整—反取整」往返（对称假量化），
主 FLOPs 不变。为什么要改：激活量化是低比特服务（W8A8）的一半难点，而它的难处正是
「同一 token 内不同通道量级差几个数量级」。怎么测的：同一冻结 trunk、同一数据流、同一窗口序，
把 fp16 / int8 / 4 位 / W8A8 四臂在同一进程里**配对**比 bpc 与长程召回。

## 2. 三道对账

### ① 激活字节账 ↔ 实现（逐张量对账）

| 项 | 解析账 | 实现实测 | 对账 |
|---|---|---|---|
| 张量数（每臂） | 48 | 48 | ✓ |
| A8/A4 标尺数 | 4 张量 × 12 层 × 16 批 × 256 tok = 196608 | 196608 | ✓ |
| fp16 标尺数 | 0（恒等，无标尺） | 0 | ✓ |
| A8 值字节 | 27648 × 1 B + 96 = 27744 B/token | — | ✓ |
| A4 值字节 | 27648 × 0.5 B + 96 = 13920 B/token | — | ✓ |

`aq_arms.activation_bytes_per_token` 与实现测到的 `n_tensors_observed` / `n_scales`
**逐臂一致** ⇒ 字节账不是自证的解析行。

### ② fp16 臂 ↔ 历史锚 / 独立路径（硬护栏）

- `bpc_of(AqForward fp16)` = **1.474620661**；独立路径 `retention.masked_bpc` =
  **1.474620661**；**逐位相同 = True**。⇒ 复刻前向与既有评估管线在数值上完全等价。
- 复刻前向 ↔ 既有仪器（`masked_logits`）**逐位相同 = True**（probe 批）。
- 变异测试：`selftest_aq.py` 7 个变异**全部抓红** + 源文件逐字节还原。
- **与历史锚 1.483569 的差：原因 = 批数（口径）不同，本轮已由实测并列确认**（不再只是推断）。
  本轮补跑 `python3 run.py --anchor-single-point --device cpu`（同一 `bpc_of` 路径，24×16@seed2，
  ≈36 s CPU）：

  | 口径 | 设备 | fp16 bpc | 与锚 1.483569 的 \|Δ\| |
  |---|---|---|---|
  | **3×16@seed2**（主表主窗，缩口径） | CPU | 1.474621 | 8.95e-03 |
  | **24×16@seed2**（历史锚口径，本轮补跑单点） | CPU | **1.483569** | **2.70e-07** |
  | 24×16@seed2（GPU 历史锚，`2614`） | GPU | 1.483569 | — |

  `batch()` 同 `window_seed` 同序 ⇒ 24 批的头 3 批**就是**主窗的 3 批；CPU 24×16 与 GPU 锚只差
  2.70e-07（< 1e-6）⇒ **设备不是原因，批数是**：`bpc_of` 是「该批序列上的 token 平均 CE」，
  批数不同 ⇒ 取样子集不同 ⇒ bpc 不同。同 run 内 `masked_bpc`（独立实现）在 24×16 同口径下与
  `bpc_of` **逐位相同**（`results.json::anchor_single_point.independent_path_same_caliber`），
  证明评估路径本身无误。（独立旁证：`2651`（5.2）在 CPU 24×16@seed2 上同样得 1.483569。）
  ⇒ **不与 1.483569 跨口径直接比；判据只用同设备、同窗口序、同批数的配对 Δ**
  （锚可比性单列于 `results.json::anchor_single_point`，不进主表）。

### ③ 配对 Δ ↔ 判据带

预登记带 = **0.014 bpc**，口径 = 配对 Δ、≥5 窗口。本 run 跑 **5 个窗口 seed = [2,3,4,5,6]**
⇒ **满足 ≥5**，直接用 0.014。

- `A8`：max|配对Δ| = **0.003530** ≤ 0.014 ⇒ **不越带**（代价落在噪声带内）。
- `A4`：max|配对Δ| = **3.598298** > 0.014 ⇒ **越带**（代价真的可分辨）。
- 逐窗口配对 Δ（A8）= [+0.003530, +0.001373, +0.003384, +0.001477, +0.001117]；
  （A4）= [+3.565646, +3.481809, +3.531002, +3.564068, +3.598298]。

## 3. 判据线结论（回到 §9 失败决策树）

1. **对照失效？** 否。`fp16` 与独立路径逐位一致、复刻↔库逐位一致（§2②）。
2. **测量**？量化臂 `changed_frac` = 0.997 / 0.998 / W8A8 见 `results.json`（>0 ⇒ 干预是活的）；
   变异 7/7 抓红（§2②）。
3. **字节账**？解析账与实测逐张量一致（§2①）。
4. **结论**：
   - `A8`（int8 激活，per-token 标尺）：**在本尺度成立**——省 49.8% 激活字节，bpc 代价 ≤0.00353
     落在 0.014 带内，召回不可分辨，离群通道不迫使回退。
   - `A4`（4 位激活）：**在本尺度不成立**——省 74.8% 字节，但 bpc 崩坏（Δ≈3.6）、copy 掉到地板。
   - `W8A8`（组合臂：权重 int8 per-channel + 激活 int8，**显式标注为组合**）：激活字节与 A8
     相同（27744 B/token，省 49.8%），bpc 1.477052（配对 Δ max 0.002955，**不越带**），
     copy 0.1445、CI 与 fp16 重叠。它与 A8 的差 = **权重因子**（权重从 24.00 MiB 的 fp16 降到
     12.06 MiB 的 int8，权重 `changed_frac`=0.997、`rel_err`=0.0086），**不计入激活因子**。
     ⇒ 在该部署组合点上，激活与权重同时 int8 也**未越 0.014 带**。

## 4. 离群通道（活性列）——「是否迫使回退」

| 臂 | 通道峰值 outlier_idx（均值） | 最坏张量 | 中位通道有效位 `eff_bits` | >6×中位数的通道数 | 回退吃掉的省幅 | 迫使回退? |
|---|---|---|---|---|---|---|
| `fp16` | 3.355 | `L01.qkv` 10.91 | 14.49 | 8（结构读数） | — | — |
| `A8` | 3.359 | `L01.qkv` 10.96 | **6.49** | **8 / 27648** | **0.00029（0.03%）** | **否** |
| `A4` | 3.733 | `L01.qkv` 12.54 | **2.36** | **18 / 27648** | **0.00065（0.07%）** | **否** |

- `outlier_index = 通道 |激活| 峰值 / 通道中位数`：整模型均值只有 ~3.4，最坏的 `L01.qkv`
  约 11–12.5 ⇒ 该主干的激活**离群通道并不极端**（对比大模型里常见的 >100 倍）。
- 「回退到高精度」是**反事实**（本实现全通道整型，不回退）：即便把 >6× 中位数的通道留在 fp16，
  也只吃掉标称省幅的 **0.03% / 0.07%** ⇒ **远低于「迫使回退」的门槛**（预登记只说「远小于标称」，
  10% 是 `run.py` 自设的活性阈值，见 §0 与 §5.3）。
- **可分辨性注记**（README §9.5）：`outlier_index` 用单点极值统计（max/median），对单个离群通道
  敏感；本读数由 4096 token × in_features 的样本得出，`chan_amax_median` 未触 clamp，读数稳定。

## 5. 失败与局限（必须读）

1. **单 seed 冻结 checkpoint** ⇒ 本实验**不**据此宣称任何结构优劣；结论只描述这 4 个点
   （13M / enwik8 尾段 / T=256 / 单 seed）。
2. **设备口径**：本 run 在 **CPU** 上跑（GPU 锁被其它轴长期占用，见 §7）⇒ 主表 `fp16` 臂 bpc =
   1.474621 与 GPU 历史锚 1.483569 **不可直接比**。§2② 已用 24×16@seed2 单点实测把原因确认
   为**批数口径差**（CPU 24×16 = 1.483569，与锚差 2.70e-07），不是设备也不是实现缺陷。
   判据只用**同设备、同窗口序、同批数**的配对 Δ；字节账与活性列与设备无关。
3. **预算裁剪（已如实登记；实情是「超出 README §7 的预登记裁剪条款范围」）**：CPU 实测 ~3–6 s/批
   （负载均值 27–30 / 12 核）。`README.md` §7 预登记的裁剪条款只授权两件：① 额外窗口 seed 的
   `n_batches` 24→**8**；② 砍副腿（induction / var_recall）。**本 run 的裁剪超出该范围**：
   主窗 24→**3**、附加窗 24→**2**、copy 主腿 2→1、副腿 16→1
   （`run_log.txt` 的「缩批量：main3/extra2/copy1/ind1/var1」行）。**判据线未动**（仍 5 窗口、
   0.014 带、配对 Δ）。
   - **对结论的影响**：配对 Δ 的**有效性不受影响**（同一 seed 用同一批数据的差分把窗口/子集效应
     消掉，且 `batch()` 取数只依赖 seed 与窗口、与批数无关）；但 ① 每窗序列数变少（主窗 48、
     附加窗 32）⇒ bpc 绝对精度下降、配对 Δ 噪声变大 ⇒ A8 的「不越带」只能读作「**在本缩口径下
     未能分辨**」，不是强证据；② 5 个窗口**批数不等**（主窗 3、附加 2）⇒ 不得称「同口径、无批量
     混杂」；③ 与历史锚 1.483569 的**跨 run 可比性失效**（锚可比性改由 24×16@seed2 单点
     `results.json::anchor_single_point` 承载，见 §2②）。A4 的「越带」幅度
     （≈3.6）远大于任何合理噪声 ⇒ 该结论稳健。
   - **补齐成本**：主窗恢复 24×16、附加窗 8×16 ⇒ CPU ~28 min / GPU ~1 min（§6 第 1 行）。
4. **副腿在地板**：induction 四臂 0.0、var_recall 近 0 ⇒ 该主干在这两条副腿上不可分辨，
   只能作「未观察到差异」的记录，不能反证机制。
5. **未测**：`fp8`（5.5 课题）、SmoothQuant 式尺度迁移、真实显存峰值（评测实现立即反量化 ⇒
   峰值不随档下降，只报解析字节列）、更大尺度/别的 checkpoint、别的 T。
6. **W8A8 的权重字节**是整模型口径（12.58M 参数 × 1 B + per-channel 标尺），与**每 token**的
   激活字节**不同量纲**，分列、不得相加。
