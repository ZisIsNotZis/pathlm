# 2650 · 批量验证的正确性门禁、失败模式与验证开销 —— 当前结论

## 人话摘要

我们在同一个 13M 小模型上，把「一次批量验证前向里送进去的候选集」换成一堆**更激进**（一次送 8 个
候选、或把不同预测头的候选拼起来）和**对抗性**（随机 token、概率最低的 token、同一个 token 抄 4 遍）
的集合，看两件事：**(1) 这个「批量验证」到底是不是真的在验证——会不会偷偷接受错 token；(2) 多验证
几个候选，值不值。**

结论一句话：**它是真验证**，但**多塞候选很快就划不来了**。

- **真验证**：随机候选的接受率只有 **1.85%**（≈抽签中奖率 4/206=1.94%），概率最低的候选接受率是
  **0%**，而它们发出的文字**仍然逐位等于普通贪心解码**——候选是错的就不接受、也不污染后续，门禁没漏。
- **值不值**：把候选从 4 个加到 8 个，接受率只从 **93.2% 涨到 97.8%**（+4.7 个百分点），每 token 的
  等效计算量却从 **4.5 倍**翻到 **8.8 倍**（相对普通逐 token 前向）。边际收益（每多一个候选换来的
  接受率）从 K=1→2 的 0.116 掉到 K=4→8 的 0.019，**只剩 1/6**。所以**硬指标（每 token 顺序前向次数）
上验证不吃掉收益**（它只加并行行、不加顺序步），但**算力轴上 K>4 不划算**。

面向用户的两个数字（13m_s0，越低/越高见标注）：
- 「普通单候选投机」（`combo_pw`）：接受率 80.0%，平均每 token 发 **2.43** 个 token；
- 「一次验 4 个候选」（`tree_topk4`）：接受率 93.2%，平均每 token 发 **2.66** 个；
- 「一次验 8 个候选」（`aggr_topk8`）：接受率 97.8%，平均每 token 发 **2.74** 个，但等效算力是普通解码的 **8.8 倍**。

### V1（必须不变，硬门）——**通过**
**全部臂 × 全部已跑 ckpt × 全部 prompt** 的发出流**逐位 == native 贪心流**（含对抗臂），
且每臂 `n_forward == n_rounds`（每轮恰 1 次顺序前向）。13M 上零分歧。

### V2（负对照该跌 / 门禁灵敏度）——**通过（门禁是真验证）**

| ckpt | 臂 | α₁ | Wilson 95% | 阈值 | 发出流 == native | 判词 |
|---|---|---|---|---|---|---|
| 13m_s0 | `adv_random_k4` | 0.018495 | [0.0138, 0.0248] | <0.06 | ✅ | 与均匀随机假接受率 4/206≈0.0194 同量级 |
| 13m_s0 | `adv_bottomk4` | 0.0 | [0.0, 0.0016] | ≤0.02 | ✅ | 概率最低的候选**从不**被接受 |
| 13m_s1 | `adv_random_k4` | 0.021212 | [0.0161, 0.0279] | <0.06 | ✅ | 同上 |

两个对抗臂的 α₁ 均远低于 0.05，且发出流逐位无损 ⇒ **接受判据是「候选 == 目标模型该位置 argmax」
的真验证**，不是「来了就收」。否证条件 1 未触发。

### V3（退化等价）——**通过**
`single_k1_ctl`（K=1 走本实验树机制）与 `dup_k4`（同一候选抄 4 份）的逐轮 `accepts` 与 2640
`combo_pw` **逐个相同**，α₁/τ 逐位相等（13m_s0：0.800000 / 1.432323；13m_s1：0.845275 / 1.503634）。

| ckpt | 臂 | Δα₁ | 配对 95% CI | CI 含 0 | \|Δα₁\|≤0.014 | **饱和？** |
|---|---|---|---|---|---|---|
| 13m_s0 | `aggr_topk8` | +0.046740 | [0.0296, 0.0629] | 否 | 否 | **否** |
| 13m_s0 | `aggr_union_heads` | +0.019284 | [0.0043, 0.0354] | 否 | 否 | **否** |
| 13m_s1 | `aggr_topk8` | +0.033279 | [0.0171, 0.0486] | 否 | 否 | **否** |

⇒ 按 V4 预登记（CI 含 0 **或** \|Δα₁\|≤0.014 才判饱和），K=4→8 **未饱和**：更多候选**仍**带来
统计可辨的接受率提升（+3.3~4.7 个百分点）。但提升幅度不大（相对 93%→98%）。

### V5（代价轴台账，如实报、不作判据）
13m_s0，K 同族取自同一 `pw_mix.q` 分布（K=1=`single_k1_ctl`，K=2=2640 `tree_qpw_k2` 指针，
K=4=`repro_topk4`，K=8=`aggr_topk8`）：

| K | τ_K | τ_K/K | τ_K/τ_oracle | R_K（2640 口径） | R_K（README 原式） | 每 token 顺序前向 = 1/(1+τ_K) |
|---|---|---|---|---|---|---|
| 1 | 1.432323 | 1.432 | 0.811 | 1.2334 | 3.7002 | 0.4112 |
| 2 | 1.548148 | 0.774 | 0.876 | 2.3547 | 7.0640 | 0.3924 |
| 4 | 1.658590 | 0.415 | 0.939 | 4.5137 | 13.541 | 0.3761 |
| 8 | 1.735828 | 0.217 | 0.982 | 8.7725 | 26.317 | 0.3654 |

边际 `Δτ/ΔK`：**K=1→2 = 0.1158**，K=2→4 = 0.0552，**K=4→8 = 0.0193**。
预登记阈值 = 0.5 ×（K=1→2 的 Δτ/ΔK）= 0.0579。K=4→8 的 0.0193 < 0.0579 ⇒
**判「K>4 的验证开销不划算（边际收益已降到 1/6）」**（`k4_to_k8_worth_it = False`；13m_s1 同判）。

- **「验证开销是否吞掉 τ 收益」的答案**：
  - **硬指标**（每 token 顺序前向次数 = 1/(1+τ)）：验证只增加**并行行**、不增加**顺序前向次数**
    ⇒ **不吞**。K 从 1 到 8，顺序前向次数 0.411→0.365 反而略降。
  - **FLOPs 轴**：`R_K` 随 K 近乎线性增长（1.23→8.77），K=4→8 的边际 τ 收益已 < 阈值的一半
    ⇒ **K>4 不划算**。收益被**候选集覆盖率**（τ_K/τ_oracle 在 K=4 已达 0.939）而非验证行数限制住。
- **口径注（contract 存疑，未擅改）**：README §4 V5 写 `R_K = 3K·(1+γ)/(1+τ_K)`，而 2640 已落盘
  口径是 `R = B_verified·(1+γ)/(1+τ) = 3K/(1+τ_K)`（`B_verified` = 每轮行数 = K）。两者相差因子
  `(1+γ)=3`。上表**两种并列**（`R_K（2640 口径）` 与 `R_K（README 原式）`），请主管裁决口径；
  但 **`Δτ/ΔK` 的判词不依赖该因子**（τ 是直接测量量）。

## 口径与边界

- 位置口径、prompt 集、温度 0、γ=2、B=1 与 2640 逐字段一致；唯一变量 = 位置 N+2 的候选集 C。
- **禁墙钟**：`results.json` 无墙钟字段（`test_results_json_has_no_wall_clock_fields` 机器可核）；
  GPU 实耗（401s 整程）只出现在 `run_log.txt`。
- 方差：按 prompt 聚类 bootstrap（B=2000，seed=2650）；率类另给 Wilson 95%。
- **禁外推**：绝对水平只适用于该 checkpoint / 该 prompt 集 / 温度 0 / γ=2 / enwik8 char 文本。
- `results.json::criteria.V5_cost_ledger` **是离线派生字段（不是 run 直接产出）**：由 `recompute_v5.py`
  从已落盘 τ/α₁ 离线重算（修一个 int/str 键 bug，不含重新测量；见 `results.json::v5_recomputed_note`）。
