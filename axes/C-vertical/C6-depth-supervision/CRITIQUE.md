### ① 这个课题是什么（我自己的话）
规定训练时**哪些深度被监督**（只监督最后一层 / 每层都监督 / 随机让每个位置在不同深度退出），看哪个深度在推理时真的能当出口用。

### ② 对着什么 sota，我们偏离在哪
- 对着 deep supervision（GoogLeNet 辅助头）、LayerSkip 的 early-exit loss、CALM 的置信损失（`axes/C-vertical/PRIOR_ART.md:127-135`）。
- **偏离（关键，口径）**：**LayerSkip 的标准做法是「正常训练 + 一个轻量早退项」**（早退损失是附加，主目标不被重新归一）。本项目把「全深度并行监督」做成形态的一部分，并把**主目标（最终深度 CE）重新归一**：`pathlm/depth_ar.py:2267` `loss/(w*(n_readouts-1)+final_weight)` ⇒ 100M 配方下最终深度只占 2/14。这使「深度监督的税」与业界「early-exit loss 的代价」不可直接对照。
- 另一个偏离：把「出口资产」的对照做成**训练过的读出 vs 未训练的读出**（见下 ③-2）。

### ③ 五类问题逐条判定
**1 开倒车：有。** headline「出口资产只能由深度维监督造出来——这是本项目最有迁移价值的一条结论」（`catalog.yaml:610` 的 verdict、`axes/C-vertical/README.md:39`）恰好是 LayerSkip 的设计前提（仓库自己的 PRIOR_ART 第 127-135 行已列出 LayerSkip 用 early-exit loss）。**业界标准：要让早退可用，必须用早退损失训练出口；我们偏离在：把它当本项目的发现，且证据对是「训练过的读出 vs 没训练的读出」。**

**2 过程错误：有，3 处。**
- **(a) 0.12 vs 0.97 的对照是「未训练读出」。** `tf@4 = 0.1199` 出自 `.scratch/24-depth-ar-100m/evidence/24b-decode-wall-dense.json::tf_note`：**「dense 中间深度读出无直接监督（仅最终 CE），tf 为 depth-k 残差态 tied 读出与 depth-L 读出的 argmax 一致率——截断资产 proxy，非训练出口资产」**（探针 `24b-probe-wall-tf.py` 亦同）。同一仓库 13M 的同款 proxy 给 **0.444**（`C3/.../2613/analysis.md §1`：「顺手补测其 tf@4 = 0.444」）。所以「0.12」不是稳定的形态量，而是「未训练线性探针」的随规模漂移值；把它当「纯 dense trunk 没有浅层截断资产」的事实（`catalog.yaml:611`、`2524-depth-ar-100m/README.md:27`）是过度解读。**真正回答这个问题的是 EX1（probe 头，13M，`18-exit-probe/evidence/SUMMARY.md`）：出口**存在**但浅层很贵（depth 6 = +0.93 bpc）；以及缺测的 `23d-H1-12k` 的 tf@4（见 C5 ④）。**
- **(b) tax 行跨引擎混写。** `catalog.yaml:608`「全深度等权 +0.067（13M）；dense 0.2 剂量的税为负（EX2 1.6097 vs 无 dense 1.6698）」——这两个数出自 **m1 引擎/PathLM 形态**的 ticket 04 `L2` 与 ticket 18 `EX2`（`.scratch/04-m1-runs/evidence/SUMMARY.md:10`「L2 1.5744 +0.067」、`.scratch/18-exit-probe/evidence/SUMMARY.md:8-10`），而 23 系**同引擎**的对应量是 **+0.284（3.6k）/ +0.108（12k）**（`23c-decomposition.json` / `23d-decomposition.json`）。同一行里放两个引擎、两个符号的数，读者无法定价。
- **(c) benefit 行是噪声。** `catalog.yaml:609`「退火配方 C 等效验证吞吐 122.8 vs A 112.9 tok/s（+9%）」：我按公式复算——加速@4 = (1+tf@4)/(1+4/12)：A = 1.9726/1.3333 = 1.4794，C = 1.9666/1.3333 = **1.4750（比 A 略低）**；等效 tok/s = 加速 × full-depth 实测墙钟：A = 1.4794×76.32 = 112.9，C = 1.4750×83.24 = 122.8。**所以 +9% 全部来自 full-depth 墙钟差（76.32 vs 83.24），而该统计量在本协议下的自身散布是 43–88 tok/s（`25b` 49.5 / `25c` 83.2 / `100m-s0` 76.3，同臂逐 prompt 极差 ±10–15%）** ⇒ 这条 benefit 是机器噪声。

**3 结论错误：有。** 正确结论：(i)「出口资产必须由深度维监督造出」**作为业内既有做法**记录（reference 口径），本地增量是**税**（+0.284 @3.6k / +0.108 @12k，同引擎）；(ii)「纯 dense trunk 无出口资产」应写成「未训练的 tied 读出 proxy 给 0.12（100M）/ 0.444（13M）——**这只是 proxy，不是能力判决**」；(iii)「剂量响应随规模翻转（13M 温和 / 100M 崩溃 +1.73）」是 **n=1 × 2 个尺度点、8× 跳档、无中间点**，只能作方向性观察。

**4 无意义：不宜删课题，但有一条子结论应转为 reference 并停止再测**：「只监督最终深度 ⇒ 没有可用的浅出口」是业已确定的（LayerSkip/CALM 的前提），不必再花实验。

**5 值得做：是。** 与 C5 同一个判决点：`23d-H1-12k` 的 `tf@4`（≈5 min）——如果它 ≫0.12，那么「出口资产」不需要门/退出/填充堆栈，形态税就有一大块是可拆的。

### ⑤ 正确的验证方式
- **该涨**：`tf@k`（且必须与**同读出训练量**的对照比，别拿未训练读出当对手）；「出口资产 + 等效吞吐」这一组合口径。
- **该跌**：全深度监督带来的同引擎底座税（matched-step，或 matched-token）。
- **必须不变**：主判据所用的损失口径（若改归一化必须显式声明并双报聚合损失与任务损失两套斜率，SCHEMA §17.15）；监督权重=0 时应逐位回到「只监督最终深度」的基线（可失败单测）；判据线不得事后调整。
