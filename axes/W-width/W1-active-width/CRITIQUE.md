## ① 它是什么（我的理解）
本格问：能不能让每个 token **用更少的通道/宽度跑完整个栈**（训练时裁通道、或推断时裁、或 width dropout），即「减宽」这条路线值不值。

## ② 对着什么 sota / 我们偏离在哪
- **sota**（本仓 `axes/W-width/PRIOR_ART.md` §W1 自列，`记忆·未核`）：结构化剪枝一系（LLM-Pruner / Sheared LLaMA / Minitron）「减宽 = 减容量、要付质量」；弹性宽度（MatFormer / width dropout）「一次训练多档成本」。
- **偏离**：本格**没有测减宽**。它测的是「把**读出**限制在前 360 维子空间」（`--readout-dims 360`），那是**读出几何（W4）**的干预，不是「每 token 用更少通道算完整栈」。

## ③ 五类问题逐条
**1. 开倒车：有。** 本格 verdict「减宽 = 减容量，不买灵活性」正是 PRIOR_ART §W1 自判为 **(a) 业界已有**的那条（该文件的机器可读分诊表 W1 行直接写「账本该条可标 reference 口径」）。本格把行业共识当本地 judged 结论。

**2. 过程错误：有（命题与干预错配——本格最硬的一条）。**
- `axes/W-width/W1-active-width/README.md:31-32`（§3 状态）**自己写「本地已测：（无）」**，而 front-matter `status: judged`、`verdict` 有判读。
- 唯一本地证据 `.scratch/25-tax-attribution`（`README.md:9` evidence 行）是 B 臂 `--readout-dims 360`：`d=720` 的模型里「unembed 与全部出口头只读 `h[:360]`」（`.scratch/25-tax-attribution/evidence/SUMMARY.md` §1 配置表）。这既没减少计算（`_run_stack` 仍跑全宽）、也没减少参数（trunk/embedding 全维），量的是**读出可见空间**。
- 另一条支撑「用户本地独立实验（减宽）同样『效果微妙』」（`W1-active-width/README.md:36`）**在仓库里没有任何 artifact**（无目录、无 results.json、无脚本）⇒ 不可核实，却写在 §5 失败路径里当第 4 条。

**3. 结论错误：有。** 「减宽 = 减容量」在本仓**没有本地实测支持**（本格没有减宽实验）；它唯一的本地读数（读出切片 clean 2.1475、恢复 −50.4%）证明的是「**把读出子空间砍掉会让状态能量迁出**」，这是 W4 域的结论。把 W4 的读数当 W1 的判决，等于**换变量得结论**。
正确结论应是：「在本引擎上，限制**读出可见子空间**会强烈恶化（clean 2.1475）并触发状态能量迁出；**减宽本身未被测**。」

**4. 无意义：否。** 「每 token 用更少宽度」是真命题（弹性宽度/早退宽度语族），但本格**没做**。

**5. 值得做：是（高优先 —— 这是 W 轴最容易出真结论的一格）。**
