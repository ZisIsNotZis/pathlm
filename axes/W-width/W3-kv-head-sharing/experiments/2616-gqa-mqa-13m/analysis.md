## 1. 人话摘要（先看这一段）

**这条线想让模型「少记一点、多省一半以上的显存」**：普通 transformer 在生成每一个字时，都要把
前面所有字的「键」和「值」（KV cache，注意力回头要查的表）留在显存里，8 个注意力头各存一份。
工业界的做法是让若干个头**共用**同一份 K/V（GQA：2 份；MQA：1 份），显存直接按比例降。
我们把它放进本仓库的参照线里测一次：**代价到底是不是「近无损」**。

**改了什么**（相对普通 decoder-only transformer）：注意力里**查询头数不变（8 个）**，只有
K/V 的头数从 8 → 2（GQA）或 1（MQA）；每层 K/V 投影矩阵的输出宽度从 256 → 64 / 32（头维度
仍是 32）。参数量同时**减少** 1,184,256（GQA，−8.75%）/ 1,381,632（MQA，−10.21%），
所以这个改动不是「等参数换个接线」，而是**减参数**（记为混杂项）。

**怎么测的**：三臂（mha / gqa / mqa）**同一配方从零训练** 12k 步（98.3M 字符，seed 0），
外加重跑一遍 gqa 量**重跑散度**；指标 = clean bpc（**每字符比特数，越低越好**），
用与 2610/2614/2615/2616-Q 同一评测窗口（24×16、seed 2）。KV 内存按**解析口径**
（部署真正要存的字节数，用前向里**实际张量形状**算）。

**测出来多少**（三臂点值 + 参照系 + 人话量级）：

| 臂 | clean bpc（越低越好） | 相对基线 | KV cache 每位置字节（fp16） | 参数量 |
|---|---|---|---|---|
| mha（基线，8 个 KV 头） | **1.4820** | — | 12288 B | 13,536,768 |
| gqa（2 个 KV 头） | **1.4963** | **+0.0143 bpc（+0.96%）** | **3072 B（−75%）** | 12,352,512 |
| gqa 重跑（同 seed） | **1.4959** | +0.0139 bpc（+0.94%） | 3072 B（−75%） | 12,352,512 |
| mqa（1 个 KV 头） | **1.4938** | **+0.0118 bpc（+0.80%）** | **1536 B（−87.5%）** | 12,155,136 |

参照系（同一模型规格、同一评测口径的现成价签）：

- **int8 KV**（把 KV 存成 8 位，评测期量化、不重训）：**+0.00015 bpc（近无损）、−50% 内存**。
- **int4 KV**：**+0.0457 bpc（有代价）、−75% 内存**。
- 因此「−75% 内存」这一档有两个实测点：**GQA +0.0143** vs **int4 +0.0457** —— GQA 在
  同一内存下降上代价只有 int4 的约 **1/3**；而「−50% 内存」那一档 int8 几乎免费（+0.00015），
  便宜得离谱。

**结论与下一步**：**GQA 落在「可分辨门槛」的正上方，MQA 落在正下方**——
判据线是 `|Δbpc| < 0.014 ⇒ 近无损`：
- GQA 的首跑 = **+0.0143（越界 ⇒ 记代价）**，但**同 seed 重跑 = +0.0139（在门槛内）**，
  两次正好跨在门槛两侧 ⇒ **以本实验的分辨率无法把它判定为「近无损」或「有代价」**，
  保守读法是**不保证近无损**（因此不写进「近无损」参照线）；
- MQA = **+0.0118（在门槛内 ⇒ 记近无损）**，−87.5% 内存、参数少 10.2%；
  **但这不足以说明 MQA 比 GQA 好**——两者只差 0.0025 ≪ 0.014，**不可排序**。
- 一句话给用户：**"KV 头共享在 13M/12k 快照上不是免费的午餐"**：省掉 75%–87.5% 的 KV
  内存要付大约 **0.012–0.014 bpc（相对 ~1%）** 的质量代价，正好压在方差界上；
  它比 int4（同 −75% 内存、+0.046）划算得多，但仍明显不如 int8（−50%、+0.00015）。
  下一步若要拿它跟 int8 争，得先补两件本实验没做的事：**等参数对照**（§15）与
  **更长训练点**（§16，本实验预算不含）。

## 2. 六问（面向用户，逐问回答）

1. **它是干什么的**：让模型在做长文本生成时，显存里保存的「注意力要回看的键值表」（KV cache）
   变小——8 组 K/V 变成 2 组或 1 组，长上下文/大 batch 解码的显存与带宽压力随之下降。
2. **相对普通的 decoder-only transformer 改了什么**：只改注意力的 **K/V 头数**（8 → 2 / 1），
   查询头数、头维度（32）、层数（12）、宽度（256）、MLP、读出、训练配方全部不动。
   量级：KV cache 每位置元素数 512 → 128 → 64（−75% / −87.5%）；总参数 −8.7% / −10.2%；
   注意力 FLOPs 与可见性对数不变（每个查询头仍然看全部因果键）。
3. **为什么要改**：解码期显存/带宽瓶颈（memory-bound），KV cache 是主要占用项；减少头数是
   工业界已验证的免费/近免费路线（GQA/MQA/MLA）。地图上 W3 是空白，「省 KV 内存」参照线缺这条腿。
4. **怎么测的**：三臂同配方 12k 步从零训练（bs32、seq256、seed 0、98.3M tokens），
   外加 gqa 同 seed 重跑一次；指标 = **clean bpc**（clean = 干净输入流、因果移位 CE 的
   token 平均；快照口径、matched-step）；KV 内存 = **解析**字节数（按前向实际张量形状）；
   对照组 = 同实验的 mha 臂（自训，非复用历史权重）+ 现成的 int8/int4 KV 参照线。
5. **测出来多少**：见 §1 表 —— bpc 1.4820（基线）→ 1.4963（GQA，+0.0143）/ 1.4938（MQA，
   +0.0118）；KV 12288 → 3072 / 1536 B/位置。人话：**质量掉约 1%（0.012–0.014 bpc）换掉
   75%–87.5% 的 KV 显存**；同内存档位比 int4 便宜 3 倍，但仍远不如 int8 便宜。
6. **结论与下一步**：**有条件采纳/待补**。GQA 的代价贴在门槛上、两次重跑给出了不同判定 ⇒
   本实验只能记「≈+0.014 bpc、分辨率不足」，**不能**写进「近无损」参照线；MQA 形式上进门槛，
   但与 GQA 不可排序。要把它升级成可采纳结论，必须先补：**等参数对照臂**（去掉容量差异，
   SCHEMA §15）与 **2× 训练点**（24k，SCHEMA §16）。不补的替代解释 = 代价来自「少 10% 参数」
   而不是「共享 KV 头」，以及「只是收敛慢了一点」（末 25% 斜率四臂都平，见 §5.4，暂不支持后者）。

= 单 batch loss 的噪声级），说明四臂在 12k 步时都**已进入平台**，Δbpc 不是「有人还在降」的
产物。**但 2×（24k）训练点未跑**（契约预算 = 3 臂 + 1 重跑，不含 2×）⇒ 本结论只作**快照口径**。

### 5.5 参照线对照（同规格、同评测口径；int8/int4 来自 `R1` 2614 实验）

| 省 KV 内存的路线 | KV 下降 | clean bpc 代价 | 需要重训? | 备注 |
|---|---|---|---|---|
| int8 KV（评测期量化） | −50% | **+0.00015**（近无损） | 否 | 现役参照线 |
| **GQA（2 KV 头）** | **−75%** | **+0.0143（重跑 +0.0139，贴门槛）** | 是 | 本实验 |
| int4 KV（评测期量化） | −75% | +0.0457（有代价） | 否 | 同内存档：GQA 便宜 ≈3.2× |
| **MQA（1 KV 头）** | **−87.5%** | **+0.0118（门槛内）** | 是 | 本实验 |

**口径警告（同一件事吗）**：int8/int4 是**评测期量化**（权重已训练好，只改 KV 的存法）；
GQA/MQA 是**架构改动 + 从零重训**。两者都在 13.5M、同架构规格、同评测窗口下量**同一个 clean bpc**，
但「代价」的来源不同（数值误差 vs 训练后的质量损失），因此这张表只作**同内存档位的量级对照**，
不作「谁更优」的产品结论。**与 int8 叠加属组合实验，本仓库显式留白（不做组合）。**

## 6. 三道对账（SCHEMA §12；`results.json::reconciliation.all_pass = true`）

### 6.1 算术对账

| 量 | 公式 | 期望 | 实测 | 一致 |
|---|---|---|---|---|
| KV 字节/位置（mha/gqa/mqa） | `L·2·n_kv_heads·dh·2B` | 12288 / 3072 / 1536 | 12288 / 3072 / 1536 | ✅ |
| 参数量差（gqa） | `−2·(d − n_kv·dh)·(d+1)·L` = −2·192·257·12 | −1,184,256 | 12,352,512 − 13,536,768 = −1,184,256 | ✅ |
| 参数量差（mqa） | −2·224·257·12 | −1,381,632 | 12,155,136 − 13,536,768 = −1,381,632 | ✅ |
| bpc 物理区间 | 0 < bpc < 8 | — | 1.4820 / 1.4963 / 1.4938 / 1.4959 | ✅ |
| 两条评测路径 | 同一数据流同位置集 | 相等 | 四位小数逐位相同 | ✅ |

> 第一次实现时把参数量差写成 `−2·(d−n_kv·dh)·d·L`（漏了 qkv 的**偏置**半边差），
> 差 4608 个参数，被本对账当场抓住并改成 `(d+1)`（见 `results.json::reconciliation::arithmetic`
> 的 `formula` 字段）。这是一次真实的自查命中，记录在此以免后人重复。

### 6.2 任务对账（SCHEMA §13：对照臂三要素）

| 对照臂 | 输入是什么分布 | 要预测什么 | 部署中对应什么 |
|---|---|---|---|
| mha（自训基线） | enwik8 前 90M 的 char 流、seq256 窗口（与三臂同一数据流、同 seed） | 下一个字符（因果移位） | 标准 8 头 KV cache |
| gqa / mqa | **完全相同**（同 seed 同窗口序） | 同一目标 | 2 头 / 1 头 KV cache（`[B, n_kv, T, 32]`） |
| 重跑臂 gqa_rep | 同 gqa（同 seed，起点权重逐位相同） | 同 | 同 |

- **没有「假上下文 + 真目标」式对照**；四臂的读出都只依赖各自的状态。
- **可见性对数四臂相同**：每层每个 query 头都看全部因果键，注意力对数 = `n_heads·T(T+1)/2`
  ——这是 SCHEMA §17.12 要求的第二套口径：本干预的「删除量」在**注意力可见性**上是 **0**，
  它只压缩 **KV 的存储宽度**。与窗口/逐出类干预（同时删可见性）不能混着比；与 int8/int4
  （同样不动可见性、只动存储）是同一口径，可以并表。

### 6.3 口径对账

| 项 | 四臂是否一致 | 说明 |
|---|---|---|
| 训练口径 | ✅ | 同 steps/bs/seq/lr/seed/数据/优化器/退火（§3 逐字段表） |
| 评测口径 | ✅ | 同一 `run.py` 电池、同 24×16、同 window_seed=2、同位置集 |
| 快照 vs 渐近 | ✅ 同为快照 | matched-step 12k（98.3M tokens，未收敛）；**无渐近点** |
| 内存口径 | ⚠️ 分两栏 | 解析（按实际张量形状）vs 实测（峰值不降）；收益主张只用解析 |
| 参数口径 | ⚠️ **不等参数** | 剪枝类：GQA/MQA 参数 −8.7%/−10.2% ⇒ 代价里混着容量差（§15 的例外方向），无等参数对照臂 |

## 7. 失败归因与失败决策树

### 7.1 决策树（预登记于 `README.md §10`，按实际结果走一遍）

| 症状 | 是否出现 | 处置 |
|---|---|---|
| 三臂 bpc 差 < 0.014 **且** KV 下降比 ≠ −75%/−87.5% | **否**（KV 下降比与预登记逐位一致） | — |
| 形状对了但重跑散度 ≥ 0.005 | **否**（0.0004） | — |
| GQA/MQA 显著变差（damage ≥ 0.014） | **GQA 是（+0.0143），MQA 否（+0.0118）** | 记为代价，并写清「它在什么条件下才可能回本」 |
| GQA/MQA 显著变好（Δ ≥ +0.014） | 否 | — |
| 解析内存下降但实测不降 | **是**（预期内） | 双报两套口径，不主张实测收益 |

### 7.2 排查顺序（methodology §14：先测量 → 再实现 → 再规模 → 最后设计）

1. **测量问题**：已排除。① 两条独立评测路径给出同一个数；② 电池三次调用四臂 bpc 完全相同；
   ③ KV 字节与参数量都被算术对账逐位钉住；④ 评测窗口序与 2610/2614/2615 同源，
   mha 臂 1.4820 vs 历史同规格 1.4836（差 0.0016，在 run-to-run 量级内）。
2. **实现问题**：已排除。变异验证 8 处（`mutate.py`）**全部抓红并逐字节还原**，
   包括最关键的「只改标签没改张量」（S1/S3/S5）与「开关是死的」（S7/S8）；
   前向实际张量形状 `[8, 2, 256, 32]` / `[8, 1, 256, 32]` 与部署侧 KV cache 形状一致。
3. **规模问题（未排除，且是本实验的主要限制）**：13M/12k 快照。文献上的 GQA「近无损」多出现在
   **更大模型 + 从已有权重继续训练/蒸馏**的设定；本实验是**从零训练的小模型**，
   容量本来紧张 ⇒ 减 10% 参数 + 共享 KV 头更容易掉点。**这解释了为什么我们的数字比行业口径悲观**，
   但**没有测**更大规模，故只作假设登记（不得当结论）。
4. **设计问题**：在「代价贴门槛」这一读法下，判定 = **该设计在此规模下有小代价**（不是免费），
   条件性成立：显存极紧张且不能用量化时，−75%/−87.5% 换 ~1% bpc 是合理交易。

### 7.3 排除了哪些替代解释

- 「只是评测噪声」：**部分排除**——同 seed 重跑散度只有 0.0004 bpc，而 GQA 的 damage 是 0.0143，
  比噪声大 ≈36×。但 **GQA 的判定跨门槛**（0.0143 / 0.0139）说明它**恰好**落在 0.014 的判决线上，
  所以正确读法是「≈0.014，正好在可分辨边缘」，不是「稳定地掉 0.0143」。
- 「是 acc/别的位置集造成的假象」：acc 同向（0.6942 vs 0.6968），幅度在二项噪声内。
- 「是训练没跑够」：末 25% 斜率四臂全平（±1e−06 nats/step），暂不支持；但 24k 点未测 ⇒ 不能排除。

## 8. 残余风险与未完成项

1. **等参数对照臂未跑**（SCHEMA §15）：GQA/MQA 少了 8.7%/10.2% 的参数，代价里混着容量差。
   补法（下一步）：让 GQA 臂把省下的参数加到 MLP/宽度上，重训 12k ⇒ 才能把「共享 KV 头」与
   「参数变少」分开。
2. **2× 训练点（24k）未跑**（SCHEMA §16）：契约预算 = 3 臂 + 1 重跑。
3. **n=1 种子**：每臂只有一个种子，重跑是**同 seed**（量数值不确定性，不量种子散布）。
   项目级种子散布界仍取 0.0138/0.014（methodology §2）。
4. **GQA 的判定不可复现**（0.0143 vs 0.0139 跨门槛）⇒ 参照线里只能记「≈+0.014、贴边界」。
5. **训练侧非确定性**：同 seed 同配方两次训练的末值差 0.0004 bpc（gqa vs gqa_rep），
   起点权重逐位相同（首行 loss 与 KV 范数完全相同）⇒ 差异来自 CUDA 归约顺序，不是数据序。
6. **未测长上下文实测收益**（墙钟/吞吐）：本实验只做 13M/seq256 的质量与解析内存，
   没有做长 T 推理的吞吐对比（那是另一个实验的口径）。

### 9.1 「省算力」侧核算（SCHEMA §17.9：成本交叉点）

KV 头共享**不省训练算力**（实测步时 mha 45.23 / gqa 45.23 / mqa 42.21 ms，无系统差异），
注意力的 FLOPs 与可见性对数也不变 ⇒ 没有「在某个 T 上回本」的算力交叉点。
它省的是**解码期 KV 显存/带宽**：解析收益与 T 成正比（每位置固定省 9216 B（GQA）/ 10752 B（MQA）），
T 越大收益越大（§5.2 的公式表）；但**实测显存收益本实验未主张**（峰会由激活与 T×T 分数主导，
真要兑现需要部署侧的 grouped-query 内核 + 长上下文批推理）。

## 10. 口径标注（§3 清单）

- **bpc**：clean bpc（每字符比特数，越低越好）= 最终深度读出的因果移位 CE 的 token 平均；
  **matched-step 快照口径**（12k 步、98.3M tokens、未收敛）；非渐近、非墙钟、非 FLOPs。
- **Δ 符号**（SCHEMA §17.3）：`Δ_schema = bpc_对照(mha) − bpc_实验`（正 = 实验臂更好）；
  `damage = −Δ_schema`（正 = 更差）。本实验三行数据都按这个符号写。
- **内存**：**解析**（按前向实际张量形状算的 KV cache 字节数，部署关心的量）与
  **实测**（CUDA 峰值/子进程采样）分开报；收益主张只用解析口径。
- **参数**：剪枝类，`−2·(d − n_kv·dh)·(d+1)·L`（含 qkv 偏置半边差），实测与公式逐位一致。
- **外推纪律（SCHEMA §17.11）**：本实验直接测了 **8 / 2 / 1** 三个 KV 头数**点值**。
  可以描述这三点的形状；**不得内插**（不许估 4 头）也**不得外推**（不许估 100M 规模或更长训练）。
  2 头与 1 头的差 0.0025 ≪ 0.014 ⇒ **不许排序**。
- **报「安全半径/预算线」类结论**：本实验类型不同（不是可见性预算），对应的两套口径是
  「KV 存储量（本干预真的降）」与「可见性对数（本干预不变）」，见 §6.2。
