# stability · 2616 KV 头共享（GQA / MQA）（13M dense）

口径：全部数字来自 `results.json`（四臂：mha / gqa / mqa / gqa_rep）、
`runs/<arm>/train_log.jsonl`、`smoke/smoke_report.json`；报告数字由 `reconcile_numbers.py`
逐条回算（`reconcile_report.json`）。

## 0. 一句话

**评测侧完全可复现（同一电池调用三次，四臂 bpc 逐位相同）；训练侧有小的 run-to-run
非确定性（同 seed 同配方重训 gqa：末值差 0.0004 bpc、末行 KV 权重范数差 0.024）。**
GQA 的判据读数（damage 0.0143 vs 0.0139）**正好跨在 0.014 门槛两侧** ⇒ 正确读数是
「≈ +0.014 bpc，本实验分辨率不足以判定近无损」，**不能**读成「GQA 稳定掉 0.0143」，
也不能读成「GQA 与 MQA 有差别」（两者只差 0.0025 ≪ 0.014）。

## 1. 评测侧复现性

| 检查 | 结果 |
|---|---|
| 同一次电池调用内 `depth_curve` 重跑（同窗口序、同 seed、同代码） | 四臂 `bpc_eval_rerun_abs_diff` = **0.0**（1.4820 / 1.4963 / 1.4938 / 1.4959 逐位相同） |
| 第二条**独立实现**的评测路径（`tools/evalkit/retention.masked_bpc`，`keep_mask=None`） | 1.482026 / 1.496325 / 1.493763 / 1.495943 —— 与 `depth_curve` **四位小数相同** |
| 整个电池**跨调用**复现（训练后 1 次 + 单独重跑 2 次，间隔数分钟） | 四臂 bpc **完全一致**（三次调用给出同一组数）；前两次调用的结果快照存为 `results_eval_run1.json` / `results_eval_run2.json`，与最终 `results.json` 的 `arms[*].bpc_clean` 逐位相同 |
| 训练后评测 vs 后期调用的 GPU 同期占用 | 他人任务占用不变（≈6.9 GB），无排队 ⇒ 不构成口径差异 |

结论：**纯推理评测侧没有可观测随机性**（本实验取 0.0；历史实验量级 ≈3.6e−07，同量级）。

## 2. 训练侧 run-to-run 散度（同 seed、同配方、同数据序）

- 起点：gqa 与 gqa_rep 的**初始权重逐位相同**（首行训练日志 loss 都是 5.4463，
  首行 KV 权重范数都是 3.619、各头行范数都是 [1.8152, 1.8325]）⇒ 数据序/初始化一致，
  差异只能来自 CUDA 归约顺序。
- 终点：`loss` 1.0170 vs 1.0184（末行 nats）、`clean bpc` **1.4963 vs 1.4959**（差 **0.0004**）、
  `kv_rows_fro_mean` 10.6968 vs 10.6732（差 0.024）。
- 与重跑阈值比：0.0004 < 0.005 ⇒ `rerun_divergence.pass = true`。
- 与项目方差界比：0.0004 ≪ 0.014 ⇒ 重跑散度**不足以**解释任何一臂的 damage（0.0118–0.0143）。
- **但它足以改变判定**：gqa 的两次读数跨在 0.014 门槛两侧（`same_verdict = false`），
  这是本实验最重要的稳定性事实（见 §0 与 `analysis.md §4`）。

## 3. 判据读数的稳定性（逐条）

| 判据读数 | 首跑 | 重跑 | 差异 | 是否跨门槛 |
|---|---|---|---|---|
| gqa damage（vs mha 1.4820） | **+0.0143**（越界） | **+0.0139**（门槛内） | 0.0004 | **是（跨 0.014）** |
| mqa damage（vs mha 1.4820） | +0.0118（门槛内） | 未重跑 | — | 否（离门槛 0.0022） |
| gqa − mqa（臂间排序） | 0.0025 | — | — | **不可排序**（≪ 0.014） |

**保守读法（写进参照线的口径）**：GQA「≈ +0.014 bpc、贴方差界、n=2 重跑不足以判定近无损」；
MQA「+0.0118 bpc、门槛内，但不得与 GQA 排序」。**不**因为一次重跑落在门槛内就改判。

## 5. 活性量的稳定性

- MHA 臂：开关关闭 ⇒ 训练日志**不写** `kv_heads` 字段（0 行）；这是「基线没有被改动」的旁证
  （`kv_head_liveness.enabled = false`、`block_python_class = "Block"`）。
- GQA/MQA 臂：`kv_heads` 字段**每 200 步一行、共 61 行**（步 0..11999，与其余训练日志同一行）。
- 形状类活性量是**静态**的（不会随步变化）：61 行都报同一组形状
  `[B, n_kv_heads, T, 32]`；动态量（`kv_rows_fro_mean`、每头 K 投影行范数）随训练单调增长
  ⇒ 变窄的 K/V 投影确实在被训练。
