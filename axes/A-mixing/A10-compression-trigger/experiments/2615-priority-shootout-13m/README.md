## 1. 命题

**「按访问频率（LRU）先压谁」比「按距离先压谁」更好吗？** 用户的压缩设计前提是前者。
现在天平（契约 M 的依赖腿 + 检索腿）可以直接比：**删除预算完全相同**（删同样多的位置）时，
三条优先级规则（`distance` / `lru` / `content`）谁的两条腿掉得更少。
可证伪：若三者在两条腿上的差异都低于阈值 ⇒ **优先级规则不带来可见收益**。

## 2. 动机（**逐字**抄录契约「动机」段）

> 动机：用户提出「访问感知（LRU）压缩」——每个 token 记住自己被读过多少次，越久没被读到
> 的越先压。现在我们有天平可以**直接**比较三种「先压谁」的优先级。

## 3. 干预（**逐字**抄录契约「干预」段）

> 干预（唯一变量 = **记录被谁丢弃的优先级规则**，**删除预算完全相同**）：
>   - `distance`：先删最远的（现基线语义）；
>   - `lru`：先删「最近 k 步内被注意质量最少」的（注意质量 = 该位置收到的注意力权重之和，
>     在全保留前向里统计，**评测期可观测**）；
>   - `content`：先删「内容与查询最不相似」的（按 key 范数或与查询的平均相似度）。
>   三者删同样数量的位置（N ∈ {8,32,64}），比较两条腿（依赖 + 保留，用契约 M 的器材）。

### 3.1 操作性定义（摘要；**把契约里的量落到可执行**，不改判据）

| 契约词 | 落地 | 位置 |
|---|---|---|
| 注意质量 = 该位置收到的注意力权重之和 | `mass_total[j] = Σ_{i>j} A[i,j]`（跨层跨头平均，**排除对角线**：自己读自己不算「被读过」；含对角线的版本另报） | `attention_stats` |
| 「最近 k 步内被注意质量最少」 | `mass_recent[k][j] = Σ_{i ≥ T−k, i>j} A[i,j]`（T=256 为窗口末端，最近 k 个查询） | `attention_stats` |
| 与查询最不相似（内容） | 主臂 = 与查询的**平均余弦相似度**最小 `cos_query[j] = mean_{i>j} cos(q_i, k_j)`；敏感性臂 = **key 范数**最小 | `priority_drop_mask(content)` |
| 「先删最远的」 | 绝对位置最小的 N 个（= `prefix_keep_mask`，现基线语义；单测钉住与它逐位一致） | `priority_drop_mask(distance)` |
| 删除预算完全相同 | **位置个数**相同（每条臂同一个 N）；实际影响的 (query,key) 对数随位置不同 ⇒ 用 `mask_stats.n_dropped_pairs` 如实另报 | `mask_stats` |

**统计量的逐序列语义**：删除决策是逐序列的（每条序列有自己的历史）⇒ 统计量按窗口算
（`attention_stats` 返回 `[B, T]`），同一批里的每个窗口有自己的删除集
（`drop_mask_keep` → `[B, T, T]` 掩码）。**契约未定义 `lru` 的 k** ⇒ 预登记：主判据臂固定
**k=64**（窗口的 1/4），并把 k∈{32,128,256} 作为敏感性臂（k=256 时
`mass_recent[256] ≡ mass_total`，正好是契约括注「该位置收到的注意力权重之和」的字面读法）。

**平局次序**（契约未定义，预登记）：`lru`/`lastused` 用全窗口质量 `mass_total` 作次级键，
`content` 用另一个内容读数作次级键，最后按位置升序 ⇒ 规则完全确定（单测钉住）。

**额外的一条敏感性规则 `lastused`**（不参与判据）：「越久没被读过」的最直接落地 =
质量加权平均查询下标 `Σ A[i,j]·i / Σ A[i,j]` 最小（= 最后一次被读到的时间最早）。

## 4. 判据线（**逐字**抄录契约「判据」段，未改一字）

> 判据：若 lru 或 content 在**同等删除预算**下保留腿召回高 ≥10pp 或依赖腿伤害低 ≥0.014
> ⇒ 优先级规则有信息量（前提成立）；若三者差异都低于阈值 ⇒ 优先级规则无可见收益
> （LRU 前提在该规模被否证）。必须报注意力质量的分布与三种规则实际删掉集合的重叠度。

**执行时的操作性落地（不改判据，只把符号与口径落定）**：

- 符号统一 `Δ = bpc_对照 − bpc_实验`（正 = 改善，SCHEMA §17.3）；删除只会抬高 bpc ⇒
  Δ ≤ 0，`damage = −Δ ≥ 0`。「依赖腿伤害低 ≥0.014」= `damage(distance,N) − damage(rule,N) ≥ 0.014`。
- 「保留腿召回高 ≥10pp」= `recall(rule,N) − recall(distance,N) ≥ 0.10`（同一批 4096 根针、
  逐针配对）。
- 逐一在 N ∈ {8,32,64} 上算；**任一个 N 上任一条规则满足 ⇒ 前提成立**（契约的析取）。
- 同时报**反方向**的数字（distance 比它们好多少），并报「契约未定义 k」的两档敏感性。
- 依赖腿另报两个历史口径（`damage_qmin128` 长上下文口径、`damage_qmin200` = 针的答案行
  所在行），保留腿另报**分桶**（anchor / window / beyond）与**配对口径**（只在该配置真正
  删掉的那些针上算）。
- 判据线在本文件写下时**尚未运行**全电池（预登记）。

## 5. 单因素声明

唯一因素 = **丢弃优先级规则**（`distance` / `lru` / `content`）。被测量模型、checkpoint、
数据流、评测窗口、位置集、读出、针的植入方案与随机种子、每档的**删除位置个数**全部逐字段
一致（对照表见 §9）；不改权重、不训练、不新增参数（`params_added = 0`）。
两组敏感性臂（`lru` 的 k、`content` 的另一种读数、`lastused`）不参与判据，只用来证明
结论**不依赖契约留白的那个选择**。

**混杂声明（必须与结论同读）**：优先级统计量取自**全保留前向的整窗口**（含该窗口未来的
查询），即「事后可见」的统计——三条规则里只有 `distance` 不需要任何统计。这个不对称
**偏向** `lru`/`content`；因此它们若不占优，是更强的负结果。流式（只看过去）版本的 LRU
只会更弱，本实验不声称它等价。

## 6. 对照与方差

- **对照臂** = `distance`（现基线语义 = `prefix_keep_mask`），与 `lru`/`content` 同预算。
- **方差界**：Δbpc < 0.014 不可排序（methodology §2）；召回按跨针 seed σ 与二项 SE 双报
  （见 `stability.md`）。
- **复用对照**（SCHEMA §9）：契约 M 的 `prefix:N∈{8,32,64}` 是同 checkpoint、同数据流、
  同窗口序（seed=2）、同针批（seed=3）的历史 run ⇒ 本实验在**同一进程内**用 `masked_bpc`
  重算这三个点，要求与 M 记录的数字一致（并给逐字段配置对照表）。
- **噪声底**：跨窗口 seed ∈ {3,4,5,6}（依赖腿）、跨针 seed ∈ {3,13,23}（保留腿）。
- **复现性**：三个档位同 seed 重跑，阈值 0.005。

## 8. 成本（唯一数字）

共享 4090（24GB，常被占 8–12GB），纯推理，GPU 任务串行。

- **臂数**（SCHEMA §17.8）：判据臂 **9**（3 规则 × 3 档）+ 基线 **1** + 敏感性 **14**
  （`lru` k∈{32,128,256} × 3 档 = 9、`lastused` × 3 档 = 3、`content(key_norm)` × 2 档 = 2）
  = **24 个配置**；重跑 **3** ⇒ 共 **27 次臂评测**，每条臂在两条腿上各评一遍。
- **步时与显存**（实测，跑完全电池后回填；**不外推**）：冒烟（`run.py --smoke`，2 批 + 2 针批，
  273 次前向）墙钟 **6.8 s**、峰值显存 **318.0 MiB**；全电池（92 个配置、4444 次前向）墙钟
  **101.57 s**（四次独立全跑 100.01 / 124.99 / 103.56 / 101.57 s，差异来自共享卡争用；数字 0 差异）、
  峰值显存 **318.0 MiB**、平均 **22.9 ms/前向**。契约预算「纯推理 ≈10–20 min」**高估了一个数量级**。
- 预算不够时砍：**先砍敏感性臂，再砍噪声底 seed，再砍针批数**；判据臂（9+1）与两条腿不砍。

## 10. 失败决策树

1. **测量问题**：`damage(distance)` 与契约 M 的 `prefix` 记录不一致 ⇒ 先查数据流/窗口序/掩码语义，
   修好再跑（本实验把这一条写成 run.py 的断言）。
2. **实现问题**：三种规则的删除集意外相同（重叠度 = 1）⇒ 变异验证 + 单测先排除实现 bug，
   再谈机制。
3. **规模问题**：13.5M / 12k 步的主干可能「本来就不用远处」⇒ 若 `distance` 的伤害集中在
   被删段的 query 上（`qmin` 口径远大于全查询口径），换更长的窗口/更大模型才能分辨。
4. **设计问题**：若 `lru`/`content` 的伤害**高于** `distance`（不持平而是更差）⇒ 如实记为
   否证，并写明「在什么条件下才可能有效」（例如统计量必须排除查询块、或需要长度更大的窗口）。

## 12. 产出与结果（运行后回填；判据线见 §4，未改一字）

**判据（位置预算口径，契约字面）**：`priority_rules_informative`——`lru:k=64` 与 `content` 在
N=8 上依赖腿伤害分别低 **+0.015914 / +0.024363**（门槛 0.014），`content` 在 N=64 上低
**+0.037807**；保留腿在任何 N 上都未过 10pp（最大 **+1.71pp**，且该腿**算术不可达**，见下）。
N=32 上两条规则都**更差**（−0.055697 / −0.020782）。

**对账后的裁决（本实验的净结论）**：删除**位置数**相同，但删掉的**可见性对数**不同
（N=8：`distance` 2012 对 vs `lru` 1562 / `content` 1859）。按对数重对齐（56 点曲线插值）后
−`lru` 变 **−0.0170**、`content` 只剩 **+0.0132**（低于噪声带 0.014）；N=64 的 `content`
剩 **+0.0092**（同样低于门槛）；单位代价（每千对）`lru` 0.1041–0.1156 最贵。⇒
**「LRU 前提成立」这一推论撤回**（ERRATA，见 `analysis.md` §6.4）；判据线本身未改。

**另两条契约要求的报告**：① 注意力质量分布——位置 0 的 `mass_total` = 9.374（第 25 百分位的
12.7 倍），「最少被读」的位置几乎全在中段；② 三规则被删集合的重叠度（Jaccard，逐窗口均值）——
`distance` vs `lru` = 0.034 / 0.270 / 0.472（N=8/32/64），`distance` vs `content` = 0.060 / 0.451 /
0.756 ⇒ **删得确实不一样，但没有换来两条腿的任何可见收益**。
