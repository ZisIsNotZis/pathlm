# A10-compression-trigger · 压缩触发与优先级

> 轴：**A 序列混合机制** ｜ 状态：**✅ judged**

> **判读**：「按访问频率优先压（LRU）」在同等删除预算下没有可见收益**——字面优势经对账后归因于「恰好删掉的可见性对数更少」，重对齐后消失。压缩优先级这一维度在 13M/256 快照上未测出信息量。

## 1. 命题

什么时候压、按什么优先级决定「谁先被压」。

## 2. 选项枚举（本格全部可能取值）

1. `固定（每 k 个位置压一次）`
2. `距离（最远的先压，本项目 eviction 语义）`
3. `访问频率（LRU：越久没被读到的越先压）`
4. `学习式（可微压缩调度器）`
5. `信号驱动（prob0 / 分歧度决定该位置能否被压）`

## 3. 状态（我们做了什么 / 行业做了什么）

**本地已测**：（无净收益）注意力质量分布：位置 0 的 mass 9.374 = 第 25 百分位的 12.7 倍，「最少被读」几乎全在中段

**行业口径**：Compressive Transformer（compression rate 固定）、Memorizing Transformer
（检索式保留）、StreamingLLM（sink + 驱逐）。

## 4. 结论与数字

- **税**：依赖腿伤害（N=8/32/64）：distance +0.197/+0.641/+1.248；lru +0.181/+0.697/+1.331；content +0.172/+0.662/+1.210 ⇒ N=8 上 lru/content 字面更低（+0.0159/+0.0244）
- **收益**：（无净收益）注意力质量分布：位置 0 的 mass 9.374 = 第 25 百分位的 12.7 倍，「最少被读」几乎全在中段
- **判读**：「按访问频率优先压（LRU）」在同等删除预算下没有可见收益**——字面优势经对账后归因于「恰好删掉的可见性对数更少」，重对齐后消失。压缩优先级这一维度在 13M/256 快照上未测出信息量。

## 5. 失败路径与原因

1. **字面优势来源是「删得更省」而不是「删得更聪明」**——删同样多的**位置**，掉的**可见性对数**不同（N=8：distance 2012 对 vs lru 1562 / content 1859）；按**对数**重对齐后 lru −0.0170（由正转负）、content +0.0132（<0.014 噪声带）⇒ **「LRU 前提成立」被否证**
2. 保留腿三规则最大差仅 **+1.71pp**（门槛 10pp）；且该门槛在本配置下用经验上界看也不可达（子桶已见删后召回升高）
3. 被删集合重叠度 Jaccard(distance↔lru) = 0.034/0.270/0.472 ⇒ 三种规则**确实删得不一样**，却没换来收益
4. 独立旁证「低损伤 ≠ 保住了」：`lru:k=256` bpc 伤害最低（+0.0885）但召回崩 4.5→22.8pp
5. 用户的「LRU 式增量搬运」更严谨的对应物不是「驱逐调度」（本格已测负），而是「写入算子」——delta 规则 `S ← S + β(v − Sk)kᵀ` = 字面意义的「只搬上次没搬的」（`记忆·未核` + 本地形式化）。本格结论只覆盖「驱逐调度」这一子形式，**不得**推广为「LRU 思想不可能」；delta 写入比 plain 多一次 matvec ⇒ 不得假装同 FLOPs（SCHEMA §15）
6. **C 线情报（`记忆·未核`）**：跨层 KV 共享业界已有占位（CLA/YOCO/MLKV，均均匀模式）；**「层特异 KV 头数 / 不等共享」与「同一 KV 字节预算下的最优分配」未找到直接前例**（可能真空白，也可能检索不到）⇒ 要做先核证
7. 未测：流式（只看过去）LRU、>13.5M/T=256 的规模；本实验统计量含整窗未来查询，**偏向** lru/content ⇒ 负结论偏强

## 6. 判据与判决实验设计

- **判据**：保留曲线（在固定压缩率 ρ 下的重建质量）+ 压缩率-质量曲线
