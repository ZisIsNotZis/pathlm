## 人话摘要（先看这段）

**要干什么。** 我们在一台 7.16M 参数的小变压器上，比较两种看历史的方式：**全因果**
（每个位置能看到前面所有字符）与**只看最近一半**（窗口 = 序列长度的一半）。看窗口能不能
省事，关键看它在多长的序列上「不再亏质量」。上两轮测过 T=256/512（ticket 39-X3）与 T=1024
（ticket 40-Y2），但 **T=1024 的全因果那一侧训练到一半会炸**（梯度范数冲到 1740.9），
所以那一点不可信。上一轮（ticket 42-W1）已用 **QK-Norm**（把每个注意力头的 query/key 向量
各自缩成单位长度，**不加任何参数**）把它按住，并推荐一个「只在序列长度 > 512 时才启用」的
长度条件档 `qk-normfrom512`。本轮就是用这个修复，把 **三个序列长度一次性重新跑一遍**，
拿一组自洽的「干净三点」。

**这轮怎么测的。** 六个臂 = 序列长度 {256, 512, 1024} × {全因果, 窗口 = 一半}，**全部**套
`qk-normfrom512`。因为阈值是 512，**T=256/512 的四个臂根本没挂这个 hook**（和普通模型
逐算子相同），只有 T=1024 的两个臂真的做了逐头归一。判断标准 = 同一个长度下
「全因果的 bpc − 窗口的 bpc」（bpc = 每字符比特数，**越低越好**；所以这个差 **正数 = 窗口更好**，
**负数 = 窗口更差**），相差不到 **0.014** 就算「不亏（噪声带内）」。

**测出来多少（先看关键数字）。**

| 序列长度 T | 全因果 bpc | 窗口 bpc | Δ = 全因果 − 窗口 | 判定 |
|---|---|---|---|---|
| 256（窗口 128，占 50%） | 1.631129 | 1.646881 | **−0.015752** | **窗口更差（越界）** |
| 512（窗口 256，占 50%） | 1.639843 | 1.654944 | **−0.015101** | **窗口更差（越界）** |
| 1024（窗口 512，占 50%） | 1.712069 | 1.702805 | **+0.009264** | **不亏（噪声带内）** |

**人话量级与参照系。** 三点形状 = **更差 → 更差 → 不亏**。也就是说：在 T=256 和 T=512 上，
只看最近一半会让质量掉 **0.015 bpc 左右**（相对全因果自己，约掉 0.9%–1.0%，越过了 0.014
的噪声界）；到了 **T=1024 才第一次进入「不亏」带**（窗口反而略好 0.0093，但在噪声带内，
**不能当成「窗口更好」**）。⚠️ T=512 这一点是**勉强越界**（|Δ|=0.0151，只比界 0.014 高 8%），
所以「交叉点落在 T=512 与 T=1024 之间」只能当作**方向**，不是精确位置。

**稳定性前置（判据②，本实验的入场券）**：T=1024 的全因果臂 `gnorm_max = **7.25**`
（阈值 <100）、跳步 **0** —— **通过了**。拿它和修复前的 1740.9 / 29578.6 比，是同一量级的
「不炸」；和健康窗口臂的 7.29 同量级。**⇒ 三点可信。**

**代价与边界。** ① **口径**：本轮是**自洽的新配方**（bs8 + `qk-normfrom512` + 每臂
**49.2M token** 的半预算快照），**不能**和旧点（X3 用 bs32、Y2 用 bs8 且全因果臂爆炸）
直接并列——旧点见下方单独列表。② 窗口在**墙钟上并不省**：实测窗口臂比全因果臂**慢**
（比值 1.19×/1.16×/1.07×），因为窗口掩码走的是**稠密 bool 掩码**（O(T²)），理论省下的
注意力 MACs **没有兑现**（实测注意力占比 5.6%/6.6%/8.5%，远低于公式的 14.3%/25%/40%）。
③ 显存峰值最高 2.016 GiB（T=1024 窗口臂），远低于 5GB 礼貌线。

**禁外推。** 只描述这三点（7.16M / bs8 / 49.2M token / 单 seed），**不外推**到其它 T、规模、
batch、token 预算；「交叉点 T*」不作数值断言。

## 1. 这条研究线是什么 + 相对普通 transformer 改了什么（AGENTS.md 六问）

1. **它是干什么的**：让模型在长上下文里**只看最近一段历史**（窗口），而不是每个位置都看前面
   全部。若能不亏质量地做到，就省掉长距离注意力的算力/内存。
2. **相对普通 decoder-only transformer 改了什么**：**只改训练期可见集**——
   普通全因果是 `keep[i,j] = (j ≤ i)`；窗口是 `keep[i,j] = (j ≤ i) ∧ ((i−j) < w)`，
   `w = T/2`（相对刻度 50%）。**参数量完全不变**（掩码零参数）。本实验额外把 W1 的
   QK-Norm（逐头 L2 归一 q/k、乘 √d_h、**零参数**）作为**固定修复**套在所有臂上，
   其中 T ≤ 512 时它按设计**不挂钩子**。
3. **为什么盯着它**：注意力 FLOPs 随 T² 增长 ⇒ 长 T 上按位置丢弃远端键是标准省算法。
   但**质量代价是否随 T 缩小**（长上下文是否更需要那些远端键）必须实测——本项目在
   T=256 上已测出窗口净亏，需要看长端拐点。
4. **怎么测的**：同一主干（d=256/L=8/h=8/mlp=4、bs8、seed0、lr1e-3、enwik8 前 90M/末 10M），
   每个 T 跑 full 与 window 两臂，同一 token 预算（49.2M），用 clean bpc（enwik8 评测流，
   `window_seed=2`、20 批 × bs16）的差 Δ = full − window 作主判据；bpc 是**快照口径**（非渐近）。
5. **测出来多少**：见上表（更差 / 更差 / 不亏）；稳定性前置通过（full@1024 gnorm_max 7.25）。
6. **结论与下一步**：**在 T=256/512 上窗口仍越界亏质量（约 0.015 bpc），到 T=1024 首次不亏**；
   采纳与否取决于产品对「长上下文省算力」的需求——但**墙钟在当前实装下并不省**（掩码是稠密
   bool），故该机制的实用化前提是**换成块稀疏/FlashAttention 变体的真窗口核**（下一步最小实验）。

## 2. 判据① 质量三点（只描述、禁外推）

**主判据口径**：`Δbpc(T) = bpc_full(T) − bpc_window(T)`（正 = 窗口更好）；
native 工作点（full 臂 = 全因果；window 臂 = 自身训练掩码）。方差界 = **0.014**。

| T | 窗口 | bpc_full | bpc_window | Δ native | 带宽分类 | bpc_release 对照 Δ |
|---|---|---|---|---|---|---|
| 256 | 128 | 1.631129 | 1.646881 | **−0.015752** | 窗口更差（越界） | −0.395705 |
| 512 | 256 | 1.639843 | 1.654944 | **−0.015101** | 窗口更差（越界） | −0.585748 |
| 1024 | 512 | 1.712069 | 1.702805 | **+0.009264** | 不亏（噪声带内） | −0.753456 |

- 三点形状（native）：**更差（越界）→ 更差（越界）→ 不亏（噪声带内）**。
- `bpc_release` = 把窗口臂拿**全可见**评测（释放路径）得到的 Δ；三点都大幅为负（−0.40/−0.59/−0.75），
  说明窗口臂**真的没在用它没见过的远端键**（不是「假保留」的另一面）——这是并列描述，**不是判据**。
- **边界提醒（如实记）**：T=512 的 |Δ| = 0.0151，只比 0.014 界高 8% ⇒ 该点**贴边越界**；
  它落在 2625 实测的 run-to-run bpc 极差（T=512 ≈ 0.0045）之上，但幅度不大 ⇒ 只描述，不强调。

## 4. 判据③ 注意力占比实测 vs 公式

| T | 实测 `attn_island / model_step` | 实测（窗口臂同口径） | 公式 `512T/(512T+786432)` | 公式 − 实测 |
|---|---|---|---|---|
| 256 | 0.0559 | 0.0665 | 0.1429 | 0.0870 |
| 512 | 0.0662 | 0.0735 | 0.2500 | 0.1838 |
| 1024 | 0.0845 | 0.1192 | 0.4000 | 0.3155 |

- 实测口径 = 「注意力子层孤岛（qkv → 注意力 → out 投影）fwd+bwd 中位墙钟」/「整模型一步
  fwd+bwd 中位墙钟」（**单层孤岛 vs 8 层整模型**，沿用 2622/2623 的既有定义）。
- **实测远低于公式**（5.6/6.6/8.5% vs 14.3/25/40%）⇒ **公式（MAC 占比）显著高估了墙钟注意力
  占比**：在这些小尺寸上，注意力核高度优化，而 qkv/投影/MLP 等被「整层 8 层」摊薄。
- **公式值只作对照，不是判据**（§17.11）。旧点同口径实测（2622-X3）= 5.41%@256 → 10.78%@512；
  本实验 T=256 一致（5.6%），T=512 低（6.6% vs 10.8%）——**machine/kernel 状态导致的量级差**，
  已如实记录，不作机制结论。

## 10. 失败路径与排除（SCHEMA §5）

| 试了什么 | 结果 | 排除了什么解释 |
|---|---|---|
| 直接复用 W1 的 QK-Norm hook | 单测（长度条件零 hook / 逐头 √d_h / 零参数）+ 4 条变异全抓红 | 排除「开关是死的 / 实现另写一份」 |
| `full@T=1024` 是否复现爆炸 | 不复现（gnorm_max 7.25、跳步 0） | 排除「QK-Norm 只在全局档（min_t=0）有效、长度条件档失效」 |
| 短 T 是否被 QK-Norm 波及 | T=256/512 四臂 `n_qkv_hooks=0`（结构零 hook） | 排除「长度条件档偷偷改了短 T 前向」 |
| 窗口是否省墙钟 | `r_time > 1`（窗口更慢） | 排除「稠密 bool 掩码能兑现 FLOPs 节省」 |
| 合成任务是否有信号 | 全部 ≈ chance | 排除「本尺度 enwik8 权重上有可测长程搬运」 |

**未排除 / 局限**：① 单 seed（n=1）⇒ Δ 无 seed 方差，靠 0.014 噪声界把关；
② 半 token 预算（49.2M）⇒ 与 98.3M 旧点不可比；③ T=512 点贴边越界，交叉点位置不精确。

## 12. 禁外推与下一步最小实验

**禁外推**：本结论只覆盖 **7.16M / bs8 / 49.2M token / seed0 / enwik8** 这一组配置与三点
（T=256/512/1024）；**不外推**到其它 T、规模、batch、token 预算、数据集或渐近极限；不给出
「交叉点 T*」的数值断言。

**下一步最小实验（带成本）**：
1. **n=2 seed 复核**（T=256/512/1024 六臂重跑 seed1，≈60 min GPU）⇒ 给 Δ 的 seed 方差，收紧
   T=512 贴边点的判读。
2. **全预算点**（每臂 98.3M token；≈99 min GPU）⇒ 把「拐点是否被半预算移动」测出来。
3. **真窗口核**（块稀疏 / windowed FlashAttention）替换稠密 bool 掩码 ⇒ 检验 FLOPs 节省
   能否兑现为墙钟收益（当前 `r_time > 1`）；这是「窗口算子在长 T 实用化」的关键前置。
