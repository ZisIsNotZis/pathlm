## 人话摘要（先看这段）

**我们在测什么**：把训练序列长度再拉长一档到 **1024 个字符**，然后让模型「只看最近一半」
（窗口 512），看**质量掉不掉、算力省不省、显存够不够**。这是 A6 那条线的**第三个点**——前两点是
T=256（窗口 128）和 T=512（窗口 256），窗口都占序列的一半（同相对刻度 50%）。「窗口注意力」相对
**普通 decoder-only transformer（全因果注意力）**改的就一件事：每个位置只能看它前面最近的 512 个键，
更远的键在注意力里被遮掉；参数量不变（就是加一层掩码）。

**三句话**：

1. **质量这一点测出来「窗口反而更好」，但这个结论不能用。** 本点 Δbpc = **+0.023419**（正=窗口更好，
   越 0.014 噪声界）——照预登记字面分类是「新算子更好（越界）」。**但基准臂（全因果）自己训练到后半段
   炸了**：`gnorm_max=1740.92`（mean 6.53），而窗口臂只有 7.35；两条 loss 曲线到第 ~9800 步几乎逐点
   相同，之后全因果臂上冲。⇒ **该点不可归因于窗口算子**，三点形状只能记成
   **「更差(256) → 不亏(512) → 不可判(1024)」**。band 分类按字面保留，不改判据。
2. **算力：理论上窗口把注意力 MACs 砍一半、整模型等效 FLOPs 降 20%，但实测没兑现**。窗口走的是
   **稠密 bool 掩码**（照样算满 1024×1024 再遮掉），两轮实测墙钟 `ms(窗口)/ms(full)` = **1.71×（冒烟轮）
   与 1.17×（评测轮）**——**窗口更慢**，方向两轮一致。注意力子层占整模型步时的**实测**占比从
   5.41%@256 → 10.78%@512 → **28.29%@1024**（与公式 14.29%→25.0%→40.0% 同向，绝对值更低）。
3. **显存没越界**：T=1024 窗口臂训练峰值 torch **1.915 GiB**（`nvidia-smi` 子进程 2.53 GB），
   在 5GB net 预算内。T=1024 的位置表相对 T=512 只加 **+131,072 参数 = +1.87%**（相对 T=256 加
   +196,608 = **+2.82%**，与 K10 的「+2.8%」一致）。

**一句话给决策**：在 7.16M / 98.3M token 这个尺度上，**第三点因基准臂自身不稳定而无法判决**——
不能说「窗口在 T=1024 变好了」。该怀疑点已由 **seed=1 双臂同配方重跑（Z1 `2624-longT-1024-seed1`）**
检验：爆炸**复现且更猛**（`full` gnorm_max 1740.92 → 29578.57）⇒ `catalog.yaml` 记该点「**永久不可归因**」
（引用 Z1 不改变本点结论），**不得外推**。

## 1. 命题与两臂（§2 单因素）

stock decoder-only transformer（`train_depth_ar.py --dense`，d=256/L=8/h=8/mlp=4，**bs8**，seed0，
lr1e-3，`exit-mode uniform`）。**唯一变量 = 训练期可见窗口**（关闭 vs T/2 = 512）；与前两点（256/512）
之间只改 `seq_len`（位置表随之线性变大，是必然后果）。

| 臂 | T | 窗口 w | w/T | 步数 | token | 参数 | 训练墙钟 | 峰值(torch) |
|---|---|---|---|---|---|---|---|---|
| `full-1024` | 1024 | 0（全因果） | — | 12000 | 98.3M | 7,159,296 | 9.02 min | 0.914 GiB |
| `win512-1024` | 1024 | 512 | 50% | 12000 | 98.3M | 7,159,296 | 10.02 min | 1.915 GiB |

- **同 token 预算 98.3M**（与 2622 的 T=256/512 四点同口径：12000×8×1024）；两臂逐字段一致，仅
  `train_window` 不同。
- ⚠️ **batch 口径与 X3 不同（必须随三点表一起说）**：本实验因窗口臂在 **bs32 / bs16 下训练均 OOM**
  （`results.json::criteria.criterion_3_memory`；见 §4 记账），两臂统一用 **bs8**；X3 两点用 **bs32**。
  token 预算三点一致（98.3M），但 batch 不同 ⇒ **与 X3 两点不可直接并列比较**，三点只作描述、禁外推。
- **同相对刻度 50%**（SCHEMA §17.16）：`window128@T=256` / `window256@T=512` / `window512@T=1024`。
  第三点**非退化**（`w=512 < T=1024`），单测钉住（`tests/test_longT_1024.py`）。

## 2. 判据① 质量：三点（只描述、禁外推）

`Δ = bpc_full − bpc_window`（正 = 窗口更好）；方差界 0.014（`docs/methodology.md §2`）。

| 点 | 口径 | bpc(full) | bpc(window) | **Δ** | band 分类（字面） |
|---|---|---|---|---|---|
| T=256 · w=128 | native（窗口臂用自身训练掩码） | 1.525389 | 1.540225 | **−0.014836** | 新算子更差（越界） |
| T=512 · w=256 | native | 1.574020 | 1.582750 | **−0.008730** | 不亏（噪声带内） |
| T=1024 · w=512 | native | **1.510446** | **1.487027** | **+0.023419** | 新算子更好（越界）**但不可判** |

> 前两点来自 ticket 39-X3（`2622-longT-512/results.json`，**跨 run 引用、未改数字**）；第三点为本实验。

**⚠️ 判读（本点不可归因于窗口算子）**：

- **band 分类照字面保留**（不得事后改判据）：三点 = **更差（越界）→ 不亏（带内）→ 更好（越界）**。
- **但第三点不可归因于窗口算子**：**基准 `full-1024` 臂自身不稳定**——`gnorm_max = 1740.92`
  （mean 6.533，clip@1.0 已生效）vs `win512` 臂 `gnorm_max = 7.35`（mean 0.562）；两臂 loss 到
  ~step 9800 几乎逐点相同，之后 full 上冲（9800–10600：full 1.284/1.369/1.038/1.278/1.437 vs
  win 1.006/1.070/0.919/1.138/0.944）。⇒ full 的最终质量被自身训练不稳定拉低，**Δ 很可能是「基准被
  炸坏」而非「窗口更好」**。
- ⇒ **三点形状记为「更差 → 不亏 → 不可判」**（而非「更差 → 不亏 → 更好」）。
- **n=1**（单 seed，无重跑散度）；**禁外推**（§17.11）。

**release 口径（并列）**：T=1024 的 bpc(full)=1.510446、bpc(window)=1.908688，Δ = **−0.398242**
（窗口训练的权重在**全可见**下反而差很多）——与 X3 的 −0.233451（T=512）定性一致。

## 3. 判据② 注意力占比：实测 vs 公式（只描述）

`attn_share(T) = 512T/(512T+786432)`（K10 公式；T=1024 = **0.4000**）。

| T | 注意力孤岛 fwd+bwd (ms) | 整模型步 (ms) | **实测 占比 = 孤岛/整模型** | 公式值 |
|---|---|---|---|---|
| 256（X3） | 1.756 | 32.474 | **5.41%** | 14.29% |
| 512（X3） | 3.205 | 29.738 | **10.78%** | 25.00% |
| **1024（本实验）** | **8.148** | **28.798** | **28.29%** | **40.00%** |

- **趋势**：实测 5.41% → 10.78% → 28.29%（×1.99、×2.62）；公式 14.29% → 25.0% → 40.0%
  （×1.75、×1.60）。**方向一致（都随 T 上升）**；绝对值差距来自口径——公式只数 MACs，实测的
  「整模型步时」还含 embedding / 读出 / 优化器 / LayerNorm 与内核开销。
- **公式值只作对照，不是判据**（§17.11）。

## 4. 判据③ 显存：未越界（但本机余量 < §20.2 的 8GB）

| 臂 | 峰值 torch | 峰值 `nvidia-smi`（子进程） |
|---|---|---|
| full-1024 | 0.914 GiB | 1.48 GB |
| **win512-1024** | **1.915 GiB** | **2.53 GB** |

**最大峰值 1.915 GiB < 5 GiB net** ⇒ 未越界。（窗口臂峰值 > full，因为物化 `[B,H,T,T]` bool 掩码，
与 A6 top-k / X3 同因。）

**§20.2 记账（batch 决定过程 + 余量）**：
- T=1024 上 **bs32 的窗口臂 OOM**（预测峰值 ~6.7 GiB）；改 **bs16 后训练仍 OOM 一次**（窗口臂训练峰值
  4.06 GiB）——当时另一 agent 的 `pytest tests/` 与 Y1 的 eval **并发占卡**（§20.1 短任务插队），把卡占满。
  ⇒ 两臂统一降到 **bs8**（同配方），token 预算不变。**窗口臂在 bs32/bs16 OOM、bs8 成功**，是实测事实。
- **跑前后 `nvidia-smi memory.free`**：before **4624 MB** / after **4099 MB**。本机**背景进程**
  （两个 `llama-server`）常驻占 ~18.3 GiB ⇒ **全卡 free 仅 ~4.6 GiB，§20.2 的「跑前后余量 ≥8GB」
  在本机无法满足**（如实记账；未碰、不杀别人进程）。

## 5. 判据④ 墙钟（两轮，方向一致：窗口更慢）

| 轮次 | 口径 | full (ms) | window (ms) | `r_time` = w/full |
|---|---|---|---|---|
| 冒烟轮（preflight） | bs16 | 35.856 | 61.459 | **1.714** |
| 评测轮（eval cost_probe） | bs8 | 28.798 | 33.561 | **1.165** |

- **两轮方向一致：窗口更慢**（都是 O(T²) 稠密 bool 掩码，没有兑现理论节省）。⚠️ 两轮 batch 不同
  （bs16 / bs8），`r_time` 只作定性方向；**不得**把任一值当作窗口的墙钟收益。
- **理论（等效 FLOPs）**：窗口保留的因果对占比 **0.749756**；注意力 MACs 降 **50%**；整模型每 token
  理论等效 FLOPs 降 **20.0%**（`1 − (attn_win+other)/(attn_full+other)`）。**未兑现**。

## 6. 长 T 训练稳定性观察（工程债线索，不改配方；**不得**据此声称「窗口更稳定」）

主 Agent 要求留档。逐臂：

| 臂 | gnorm_max | gnorm_mean | grad_skips | 末日志 loss | 末窗斜率(nats/1k) |
|---|---|---|---|---|---|
| full-1024 | **1740.92** | 6.533 | 0 | 1.081 | 0.12962 |
| win512-1024 | 7.35 | 0.562 | 0 | 1.078 | 0.18957 |

- **clip 已生效**：训练器对参数做 `clip_grad_norm_(..., 1.0)`；`grad_skips=0` ⇒ 未触「gnorm>1e4 跳步」
  阈值。full 臂那次 1740.92 的尖峰被 clip 到 1.0，但步照走 ⇒ **参数被一次大梯度扰动**。
- **爆炸从哪一步开始**：按每 200 步日志（原始文件 `<arm>-train_log.jsonl`，**已入库**），full 的最大采样 gnorm（128.85）落在 step ~10000；两臂
  loss 到 step ~9800 近同，之后 full 上冲、win 未。**win 臂为何更稳：不知道**（n=1；可能是窗口掩码的
  正则效果，也可能是 seed 运气）——**不得**据此声称「窗口更稳定」（§17.11 禁外推）。
- **工程债线索**：本尺度（T=1024，bs8）下全因果注意力出现梯度尖峰；下一波（seed=1 复跑）**已复现且更猛**
  （Z1，full gnorm_max 1740.92 → 29578.57；见 §10）。

## 7. §19 合成长程腿：**空结果（诚实报）**

用 `var_recall_batch`（**未改工具**）在 T=1024 距离档 {256,300,512,768,1000} 上评测两臂（每档 n=64）。

| 臂 | 距离档（准确率） |
|---|---|
| `full-1024` | 256:0.016, 300:0.000, 512:0.000, 768:0.047, 1000:0.000 |
| `win512-1024` | 256:0.016, 300:0.016, 512:0.000, 768:0.000, 1000:0.000 |

**chance = 1/64 = 0.015625；局部先验 ≈ chance（抗性检查全部通过）**。两臂**全部落在 chance 附近**
（≤0.047，n=64 的 95% 抽样区间约 ±0.03）⇒ **不能区分窗口与 full**。原因同 X3：两臂**训练在 enwik8 上**，
`var_recall` 是**分布外**任务 ⇒ 13M/98M token 的 enwik8 模型不会做关联回忆。**这条腿是空结果**，
既没有支持也没有推翻「窗口伤长程」。

## 8. 干预活性与仪器自检（§10）

- **窗口干预活着**：`win512-1024` 的 `window_mask_probe`（掩码开/关同一批输入的最后一层 logits 最大差）
  = **0.1864**（>0）；`window_mask_liveness` 每 200 步随日志落盘，`visible_frac` **0.749756**（非 1，
  `n_visible_pairs=393472` / `causal_pairs=524800`）。full 臂 `window_mask=null`（无干预）。
- **仪器自检**：full 臂的「释放版 vs 显式精确因果掩码」最大 logit 差 = **0.0**（逐位一致）；窗口臂
  该差 = **20.20**（这是**掩码本身的效果**，不是仪器不等价——窗口臂 native 前向本就带掩码）。

## 9. 三道对账（§12）

1. **算术对账**：两臂 token = 12000×8×1024 = 98,304,000（逐位相等）；位置表参数增量
   T=1024−T=512 = **+131,072**（= 512×256），T=1024−T=256 = **+196,608 = +2.82%**（与 K10 一致）；
   `visible_frac` 实测 == 闭式 `Σ min(i+1,512)/524800`（0.749756 == 393472/524800）；占比公式
   T=1024 == 0.4000。全部脚本化（`reconcile_numbers.py`）。
2. **任务对账**：两臂**同数据切分**（enwik8 前 90M/末 10M）、**同评测流**（`window_seed=2`、20 批×16）；
   native 口径 = 各臂自己的训练掩码，release 口径 = 全可见——两个口径都报。
3. **口径对账**：matched-token（98.3M）；Δ 用**同点自己的 full** 作基准（§17.14：基准唯一）；
   **算力账**：窗口臂推理算力理论上更低（注意力 MACs −50%）但**实测墙钟更慢**（r_time>1），
   该价签写进结论句（§17.14）。

**有利数字（本点 Δ=+0.0234「更好」）的对账结论**：它**通过**算术/任务/口径三道，但**基准臂不稳定**
（§6）⇒ 只表述为「**该点不可判**」，**不**表述为「窗口在 T=1024 更好」。

**跨 run 一致性交叉检查（不是判据，只是 sanity）**：本实验 `full-1024` = **1.5104**，比 X3 的
`full-512`（1.5740）**低 0.064**（同 token 预算下序列更长、每步覆盖更多上下文）⇒ 量级合理；
但 batch 不同（bs8 vs bs32），**只作定性交叉参考，不可直接并列**。

## 10. 失败路径与原因 / 下一步（§23 第 6 问）

1. **基准臂不稳定（本点主障碍）**：full-1024 gnorm 尖峰 1740.92、loss 后半上冲 ⇒ Δ 被混淆。
   该缺口**已由 Z1 填补（ticket 41-Z1）**：`axes/A-mixing/A6-mixing-operator/experiments/2624-longT-1024-seed1/`
   以 seed=1、bs8、同步数双臂同配方重跑，`full` 臂 gnorm_max = **29578.57**（seed0 为 1740.92，×17.0）、
   跳步 3 次、爆炸点 ~step 6200 ⇒ 爆炸**非 seed 特异、复现且更猛**；`catalog.yaml` 据此把该点记为「**永久不可归因**」。
   本点 Δ=+0.0234 仍只作「**不可判**」，band 分类照字面未改（引用 Z1 不改变本点结论）。
2. **batch 与 X3 不同**：T=1024 因 OOM 用 bs8，X3 用 bs32 ⇒ 三点不可直接并列（已在三点表标注）。
   修法：若下一波卡空出，可在 bs32 复跑（本机现不可行——背景常驻 18.3 GiB）。
3. **墙钟收益未兑现**：窗口走稠密 bool 掩码 ⇒ O(T²) 照算。要拿墙钟收益必须换真正的带状/稀疏内核
   （工程线，非本格）。
4. **合成腿空结果**：enwik8 权重在分布外任务上全 chance ⇒ 不能区分两臂；真正的长程判决需
   **在合成任务上训练**两臂（属 A9/Y3 实验）。
5. **未测项清单**：
   - seed=1 双臂重跑——**已完成**（Z1 `2624-longT-1024-seed1`，full gnorm_max=29578.57 ⇒ 爆炸复现且更猛，见本节第 1 条）；
   - T=2048 第四点（理论 attention 占比 57.1%；显存估 >5GB，本机不可行）；
   - 真正的带状/稀疏内核下重测 `r_time`，验证理论 20% 是否兑现（工程线）。

## 11. 与 A6 / K10 的关系

- **A6 的「T=256 净亏」**（内容 top-k，k=32 Δ=−0.0166）与本实验的**位置式窗口**在 T=256 的
  Δ=−0.0148 同量级、同方向；到 T=512 窗口的 Δ 收窄到 −0.0087（带内）；**T=1024 本点的正 Δ 不可用**
  （基准臂不稳定）。三种算子在短 T 端行为定性一致。
- **K10 数字核对**：T=1024 的位置表参数增量 **+196,608 = +2.82%**（相对 T=256）——与 K10 的
  「T=1024 +196,608（+2.8%）」**一致**。
  T=1024 注意力占比公式 **40.0%** 与 K10 §4.1 表一致。
- **单因素/scale 声明**：本实验只描述 7.16M / 98.3M token / T=1024 **一个点**，**禁外推**。
