## 人话摘要（先看这段）

**要干什么。** A6 格此前有一条看着很漂亮的长上下文结论：「窗口（只看最近一半历史）的**质量代价
随序列长度 T 增大而消失**」——在 T=256/512 上窗口比全因果差约 0.015 bpc（越过了 0.014 噪声界），
到 T=1024/2048 就掉回噪声带内。审计（`.scratch/50-critical-audit/A-Audit.md`）指出这条结论**靠不住**：
四点里步数是 24000/12000/6000/3000 不等，而优化器的学习率调度以**步数**为分母（退火刻度不同），
而且 T=2048 那点还是「补到 6000 步」的混口径。本实验就是去统一这个口径：**把四点都放在同一个
步数（6000 步）下重跑**，再把「窗口到底省不省」用一次会话里测出来的**质量 / 解析 FLOPs / 实测墙钟 /
峰值显存**四条腿一次讲清。

**怎么做的。** T=1024 与 T=2048 的同 step（6000 步）两点此前已存在（`2626`/`2629`，同引擎、同 bs8、
同 seed0、同修复档），**只读复用**；本实验**新跑** T=256 / T=512 两点（full/窗口各一臂，6000 步）。

**测出来多少（先看关键数字）。**

**同 step（都是 6000 步）四点：**

| T | 窗口 | 全因果 bpc | 窗口 bpc | Δ = 全因果 − 窗口 | 判定 | token/臂 |
|---|---|---|---|---|---|---|
| 256 | 128（占 50%） | 1.946343 | 1.949885 | **−0.003542** | **不亏（带内）** | 12.29M |
| 512 | 256（占 50%） | 1.786939 | 1.791467 | **−0.004528** | **不亏（带内）** | 24.58M |
| 1024 | 512（占 50%） | 1.712069 | 1.702805 | **+0.009264** | **不亏（带内）** | 49.15M |
| 2048 | 1024（占 50%） | 1.705365 | 1.701179 | **+0.004186** | **不亏（带内）** | 98.30M |

**同 token（各 49.15M）四点（旧口径，全部只读复用）：** 窗口更差@256（−0.015752）→ 窗口更差@512
（−0.015101）→ 不亏@1024（+0.009264）→ 不亏@2048（+0.004361）。

**这两张表给出了本轮最重要的一句话：** 同一条研究，只换「步数对齐」还是「token 对齐」，短 T 那两点的
结论就从**「越界亏」翻成「带内不亏」**。也就是说，此前那条「窗口的代价随 T 消失」**不是一条稳健的
现象**，而是**口径敏感**的：短 T 在「同 token」口径下被训得更久（T=256 拿到 24000 步，是 T=2048 的 8 倍），
窗口代价才显出来；一旦把步数拉平，T=256 只训了 12.29M token（末态 loss 1.42，而 T=1024 是 1.21），
模型**更依赖局部先验、更用不上远距离上下文**，窗口自然「免费」。**两个方向都是欠/过训练的产物，
所以两个口径都不能单独当趋势。**

**决定性的一条（噪声门限本格自测）：** 本轮把 T=256/512 的**四个臂各换 seed 重跑一次**（八臂全齐），
单臂跨 seed 极差 **0.0030–0.0158**（最大 = T=256 全因果臂：**1.946343（seed0）→ 1.930552（seed1）**，
极差 **0.015791**）——**比本项目的 0.014「噪声带」还大**；而 Δ 自己也在跨 seed 下翻了近 0.01（T=256：
−0.0035→−0.0130）、甚至变号（T=512：−0.0045→+0.0017）。而上面四条 Δ 的绝对值全部 ≤0.0158。
⇒ **这四点的 Δ 都落在本格自己的 seed 噪声内，跨 T 的排序（以及「窗口代价随 T 消失」）不成立**（这条独立坐实了审计 §4-①：0.014 不是全局可排序线，必须本格自测）。

**四条腿「省不省」（同一次会话实测，见 §5）：** 一次会话里对 T×{full,窗口} 各测了整模型一步墙钟与峰值显存。

| T | 解析 FLOPs（注意力） | 解析 FLOPs（整层 all-in） | 实测墙钟 r_time = 窗/全（两轮） | 实测峰值显存 r_mem = 窗/全 |
|---|---|---|---|---|
| 256 | **−50%** | −7.1% | 1.03 / 1.23 | 1.17 |
| 512 | **−50%** | −12.5% | 0.98 / 1.01 | 1.49 |
| 1024 | **−50%** | −20.0% | 1.08 / 0.88 | 2.04 |
| 2048 | **−50%** | −28.6% | **1.27 / 1.80** | **3.31** |

**⇒ 口径裁决：解析 FLOPs 省（注意力砍一半，整层降幅随 T 增大）；实测墙钟不省（两轮里没有一档给出
一致 <1 的读数；T=2048 两轮都明显更慢 1.27/1.80）；峰值显存反而更费（窗口臂物化稠密 T×T 掩码，
1.17→3.31 倍，T 越大越费）。** 即：**「窗口在当前实装下墙钟不省」——坐实**（并补上新的一条：
**显存也不省，且随 T 恶化**）。

**禁外推。** 本结论只覆盖 **7.16M / bs8 / seed0 / enwik8 / S=6000（T=256/512 新臂）** 与只读复用的
T=1024/2048 同 step 点；不外推到其它 T、规模、batch、token 预算、数据集或渐近极限；不给「交叉点 T*」。

## 1. 这条研究线是什么 + 相对普通 transformer 改了什么（AGENTS.md 六问）

1. **它是干什么的**：让模型在长上下文里**只看最近一段历史**（滑动窗口），而不是每个位置都看前面全部。
   若能在不亏质量的前提下做到，就省掉远距离注意力的算力/内存。
2. **相对普通 decoder-only transformer 改了什么**：**只改训练期可见集**——普通全因果
   `keep[i,j] = (j ≤ i)`；窗口 `keep[i,j] = (j ≤ i) ∧ ((i−j) < w)`，`w = T/2`（同相对刻度 50%）。
   **参数完全不变**（掩码零参数）。全部臂套 `2625` 的**长度条件档 QK-Norm**（`qk-normfrom512`）作为
   长 T 稳定性修复（零参数；T ≤ 512 臂 `n_qkv_hooks == 0`，逐算子等于 stock）。
3. **为什么盯着它**：注意力 FLOPs 随 T² 增长，长 T 上按位置丢弃远端键是标准省算法；但质量代价是否
   随 T 缩小，本项目此前只有**混合口径**的四点，必须统一口径后重判。
4. **怎么测的**：同一主干（d=256/L=8/h=8/mlp=4、bs8、seed0、lr1e-3、enwik8 前 90M/末 10M），
   四点**同 step S=6000**；每点 full 与 window（w=T/2）两臂；主判据 = clean bpc（enwik8 评测流，
   `window_seed=2`，20 批 × bs16）的 `Δ = bpc_full − bpc_window`。
5. **测出来多少**：同 step 四点 **全部落在噪声带内**（Δ = −0.0035 / −0.0045 / +0.0093 / +0.0042）；
   同 token 副口径四点 **窗口更差 → 窗口更差 → 不亏 → 不亏**；**本格 seed 噪声 0.0158 > 上述所有 |Δ|**
   ⇒ 两种口径都不能当趋势。
6. **结论与下一步**：「窗口代价随 T 消失」**不成立**（口径敏感 + 落在本格噪声内）；真正稳健的是**成本腿**：
   FLOPs 省、**墙钟与显存都不省**。要拿到干净的质量形状，需要 **n≥2 seed + 每点足够收敛**的关键格（§11）。

## 2. 判据 C1：质量 —— 同 step 四点与同 token 副口径（只描述、禁外推）

**主判据口径**：`Δ(T) = bpc_full(T) − bpc_window(T)`（正 = 窗口更好）；native 工作点（full = 全因果；
window = 自身训练掩码）。工程方差带 **0.014**；本格自测 seed 噪声见 §4。

**同 step（S=6000）四点：**

| T | 窗口 | bpc_full | bpc_window | Δ native | 带宽分类 | steps | token/臂 |
|---|---|---|---|---|---|---|---|
| 256 | 128 | 1.946343 | 1.949885 | **−0.003542** | 不亏（噪声带内） | 6000 | 12.288M |
| 512 | 256 | 1.786939 | 1.791467 | **−0.004528** | 不亏（噪声带内） | 6000 | 24.576M |
| 1024 | 512 | 1.712069 | 1.702805 | **+0.009264** | 不亏（噪声带内） | 6000（引用 2626） | 49.152M |
| 2048 | 1024 | 1.705365 | 1.701179 | **+0.004186** | 不亏（噪声带内） | 6000（引用 2629） | 98.304M |

- 形状（同 step）：**不亏 → 不亏 → 不亏 → 不亏**。
- **token 预算随 T 线性**（12.29M→98.30M）：同 step 口径下**不可能**同时对齐 token（`tokens = steps·bs·T`），
  这是物理事实，已按 §2 预登记声明。

**同 token（49.152M/臂）副口径四点（全部只读复用）：**

| T | Δ native | 带宽分类 | steps |
|---|---|---|---|
| 256 | −0.015752 | 窗口更差（越界） | 24000 |
| 512 | −0.015101 | 窗口更差（越界） | 12000 |
| 1024 | +0.009264 | 不亏（噪声带内） | 6000 |
| 2048 | +0.004361 | 不亏（噪声带内） | 3000 |

**两种口径的对照（本轮的核心发现）：**

- 同一批 T=256 研究，同 token 口径判「越界亏」（−0.0158），同 step 口径判「带内不亏」（−0.0035）。
  **口径一换，结论翻转**。
- 机制解释（两侧都是训练的产物，必须并列写出）：
  - **同 token**：T=256 拿到 24000 步（= T=2048 的 8 倍），退火更充分、更收敛（末态 loss 更低），
    模型更会用远距离上下文 ⇒ 窗口代价显现；
  - **同 step**：T=256 只训 12.29M token（末态 loss 1.42，而 T=1024 是 1.21），**欠训练 ⇒ 更依赖局部先验
    ⇒ 用不上远距离上下文 ⇒ 窗口「免费」**。
- ⇒ **不能把任何一个口径的短 T 结果读成「窗口代价」的大小**；也不能读出「随 T 消失」。
  §4 的 seed 噪声进一步说明：两个口径的差异（0.0123）本身也在本格噪声（0.0158）之内。

**收敛口径（§17.15/§16）**：判据损失 = enwik8 CE（bpc），取训练日志 loss 末窗斜率：

| 臂 | 末态 loss | 末窗斜率 (nats/1k) |
|---|---|---|
| full-256-s6k | 1.4157 | −0.148 |
| win128-256-s6k | 1.4101 | −0.174 |
| full-512-s6k | 1.0606 | −0.074 |
| win256-512-s6k | 1.0706 | −0.043 |
| full-256-s6k-s1 | 1.3651 | +0.068 |

⇒ 两臂**同 step 同调度**，故 Δ 是 **matched-step 对照**；绝对水平是**快照**（末窗斜率仍非零、T=256 臂
远未收敛）。**跨上下文的绝对 loss 不可比**。

## 4. 判据 C4：噪声门限**本格**自测（四对 seed）

- **单臂跨 seed极差**（同配置、唯一差别 seed，八臂全部跑齐）：

| 臂 | bpc(seed0) | bpc(seed1) | 单臂极差 |
|---|---|---|---|
| `full-256-s6k` | 1.946343 | 1.930552 | **0.015791** |
| `win128-256-s6k` | 1.949885 | 1.943553 | 0.006332 |
| `full-512-s6k` | 1.786939 | 1.796186 | 0.009247 |
| `win256-512-s6k` | 1.791467 | 1.794483 | 0.003016 |

- **Δ 的跨 seed 极差**（同一点两臂各自的 seed 一致）：T=256：Δ = −0.003542(seed0) → −0.013001(seed1)，极差 **0.009459**；
  T=512：Δ = −0.004528(seed0) → +0.001703(seed1)，极差 **0.006231**。
- **含义**：本格单臂噪声 **0.003–0.0158**（最大 = `full-256` 的 **0.0158 > 项目 0.014 带**）；
  两臂之差的噪声只会更大（若两臂独立，≈√2× 单臂）。⇒ §2 四条 Δ（|Δ| ≤ 0.0158）**全部落在本格
  噪声内**，跨 T 排序不成立；**同一点的 Δ 自己也在跨 seed 下翻了近 0.01（T=256）甚至变号（T=512）**
  ⇒ **单 seed 的 Δ 本身不足以定序**。
- **与 2625 的对照**：`2625` 在同一 13M/enwik8 谱系上测得 T=512 单臂两次重跑极差 **0.0045**；
  本轮测得 0.0030–0.0158 ⇒ **噪声是格/点/臂相关的**，进一步支持审计 §4-①：
  **不存在单一全局可排序线**（这正是审计引用的 ticket 11 原文「no single global floor」）。

## 5. 判据 C3：四条腿「省不省」（逐 T 回答）

同一会话内对 8 个配置（T × {full, window}）实测整模型一步 fwd+bwd 中位墙钟与 torch 峰值显存
（套 QK-Norm 同配方）。**两轮**（preflight / eval）并报。

| T | 解析 FLOPs：注意力 − | 解析 FLOPs：整层 all-in − | r_time 轮1 | r_time 轮2 | r_mem 轮2 | 峰值 full→win (GiB) |
|---|---|---|---|---|---|---|
| 256 | 50% | 7.14% | 1.028 | 1.234 | 1.169 | 0.296 → 0.346 |
| 512 | 50% | 12.5% | 0.984 | 1.005 | 1.487 | 0.456 → 0.678 |
| 1024 | 50% | 20.0% | 1.076 | 0.883 | 2.036 | 0.911 → 1.855 |
| 2048 | 50% | 28.57% | 1.273 | 1.799 | 3.305 | 1.688 → 5.579 |

- **质量腿**（= §2 Δ）：四点全带内（但见 §2/§4：不可当趋势）。
- **解析 FLOPs 腿**：**省**。注意力每 token 每层 MACs `2·w·d` vs `2·T·d` ⇒ 恒 **−50%**
  （窗口 = T/2）；整层 all-in 降幅 = `512w/(512w+786432)` 族公式 ⇒ **−7.1% → −28.6%**（随 T 增大），
  与公式口径一致（`cost.theory`）。
- **实测墙钟腿**：**不省**。两轮里 **没有一档**给出**一致**的 r_time < 1：
  T=256（1.028/1.234，两轮都更慢）、T=512（0.984/1.005，方向不明）、T=1024（1.076/0.883，方向相反）、
  T=2048（1.273/1.799，**两轮都明显更慢**）。⇒ **坐实「窗口在当前实装下墙钟不省」**：稠密 bool 掩码
  照算满 T×T 再遮掉，理论省下的注意力 MACs **没有兑现**（注意力孤岛占比实测 0.11–0.36，公式
  0.14–0.57，公式只数 MACs）。
- **峰值显存腿**：**不省，且随 T 恶化**。窗口臂物化稠密 T×T 掩码，r_mem = **1.17 / 1.49 / 2.04 / 3.31**
  （T 越大越费）；T=2048 窗口臂 **5.58 GiB > 5GB 礼貌线**（§20.2 记账：本行即显式偏离；余量仍 ≫8GB）。
- **一句话裁决**：**解析 FLOPs 省；实测墙钟不省；峰值显存更费（随 T 恶化）。** 窗口算子在本实装下
  **只在纸面上省算力**——实用化前提是把稠密掩码换成真正的带状/块稀疏核（§11 下一步）。

## 8. 三道对账（SCHEMA §12；脚本 `reconcile_numbers.py` → `reconcile_report.json`）

## 9. 失败路径与排除（SCHEMA §5）

| 试了什么 | 结果 | 排除了什么解释 |
|---|---|---|
| 复用 W1 的 QK-Norm hook | 单测（T≤512 零 hook 且逐位不变 / T>512 挂 hook 且改前向 / 零参数）+ 6 条变异全抓红 | 排除「开关是死的 / 长度条件档偷偷改短 T」 |
| 四点 full 臂是否稳 | 全 `gnorm_max ∈ [6.84, 7.70]`、跳步 0 + 引用臂 7.25/7.22 | 排除「长 T 崩溃」（QK-Norm 修复后） |
| 四点是否因口径不同而不同 | 同 token 与大 step 两套读数并报 | 证明「窗口代价随 T 消失」是**口径敏感**、非稳健现象 |
| 窗口是否省墙钟 | 两轮 8 配置实测 r_time 无一致 <1 | **坐实**「稠密 bool 掩码不兑现 FLOPs 节省」 |
| 窗口是否省显存 | r_mem 1.17–3.31（随 T 增） | 排除「窗口省显存」（实际更费） |
| 合成任务是否有信号 | 全 0.000（< chance） | 排除「本尺度有可测长程搬运」 |

**未排除 / 局限**：① **四点 token 预算不等**（同 step 的物理后果）；② 同 step 四点**收敛度异质**

## 11. 禁外推与下一步最小实验

**禁外推**：本结论只覆盖 **7.16M / bs8 / seed0 / enwik8 / S=6000（T=256/512 新臂）** 与只读复用的
T=1024/2048 同 step 点；**不外推**到其它 T、规模、batch、token 预算、数据集或渐近极限；不给
「交叉点 T*」的数值断言。

**下一步最小实验（带成本）**：
1. **收敛度对齐的干净形状**（关键）：选一个 4 点都接近收敛的 token 预算（各点 ~98–200M token，
   但**同 step 不可能**——需明确取舍），或改用**同一退火比例 + 同 token** 的折中；≈ 60–90 min。
2. **真窗口核**（块稀疏 / windowed FlashAttention）替换稠密 bool 掩码 ⇒ 检验 FLOPs 节省能否兑现为
   墙钟收益（当前 r_time 无一致 <1）；这是「窗口算子实用化」的关键前置，也是本格成本腿从「纸面省」
   到「实测省」的唯一路径。
3. **更多 T / 更长训练点的 seed 重复**（把 §4 的单格噪声扩到四点）——用于给「同 step 四点是否真的
   都在一个带内」下更硬的结论。

## 附：机制归属（诚实标注）
