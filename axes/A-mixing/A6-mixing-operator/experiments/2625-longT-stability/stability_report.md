> 契约：同目录 `README.md`（判据线逐字，未改）。原始结果：`runs/<arm>/results.json`、
> `runs/<arm>/train_log.jsonl`、`runs/<arm>/probe.jsonl`；对账：`reconcile_report.json`；

## 人话摘要（先看这段）

**要解决的是什么问题。** 我们在 7.16M 的小变压器上把训练序列拉到 **1024 个字符**，想让
「只看最近一半（窗口 512）」和「全因果（每个位置能看到前面全部）」两种模型对比长序列行为。
问题是：**全因果那一侧训练到一半会突然炸**——梯度范数（gnorm，衡量每一步参数更新有多猛；
健康值 ~0.5）在两个随机种子上分别冲到 **1740.9** 和 **29578.6**，第二次还触发了 3 次跳步。
窗口那一侧两 seed 都稳（7.35 / 7.66）。基准臂自己炸了，长序列的任何「谁更好」都没法下结论——
这就是**挡住整条长 T 线的工程债**。

**这次做了什么。** 先做**诊断**（CPU 上量已落盘的 8 个模型 + 一个带探针的训练跑），再按
单因素逐个试候选补丁。诊断找到了很清楚的元凶：**第 1 层的注意力 logits 在训练中一路无界增长**。
在带探针的那次训练里，第 1 层每行注意力的 logits 尺度（RMS）从第 200 步的 **0.60** 单调涨到
第 6800 步的 **86.1**；而第 0 层稳在 ~0.7、第 2–7 层稳在 25–66 与 4–5。两跑炸掉的模型里，
这个量最终到了 **1.9×10⁵ / 3.6×10⁵**，注意力分布几乎完全塌缩成一个点（最大概率 0.95 / 0.97，
熵 0.10 / 0.07 nats）。也就是说：**模型把第 1 层的注意力越练越尖，尖到某个点之后一个坏 batch
就能把梯度推到天上**（炸完后永久留疤：第 1 层 `qkv` 权重范数 109.5 / 131.5，其余 8 个健康臂
都在 16–25）。

**怎么修的。** 给 q/k 做「按头归一化」（QK-Norm）：把每个注意力头的 query / key 向量各自缩成
单位长度再乘回 √d_h。这一下把 logits 的**上界钉死在 √32 ≈ 5.7**，模型再想把注意力练尖也
练不上去。改动的量级很小：**不加任何参数**（只是每个头做一个 L2 归一），只在 `qkv` 输出上
加一个逐头缩放。

**测出来多少（判据①：两 seed 都稳）**：

| 臂（T=1024，bs8，12000 步） | 原 `gnorm_max` | QK-Norm 后 `gnorm_max` | 跳步 | 结果 |
|---|---|---|---|---|
| seed=0 | 1740.92 | **7.25** | 0（原 0） | 不再炸 |
| seed=1 | 29578.57 | **7.58** | 0（原 3） | 不再炸 |
| 判据线 | — | < 100 | 0 | — |

**参照系**：健康的窗口臂在同样配方下 gnorm_max 是 7.35 / 7.66——修完之后全因果臂的
7.25 / 7.58 与它**同一量级**。而且 QK-Norm 的好处不止「不炸」：**两 seed 的末态质量也变得可复现**
——clean bpc（每字符比特数，越低越好）= **1.5432（seed0）/ 1.5437（seed1）**，两 seed 只差 0.0005；
而未修的基准两 seed 是 1.5104 / 1.6064，**差 0.096**（那不是窗口的功劳，是 seed1 那次被炸坏的）。

**代价与边界（判据②）**。全局 QK-Norm 会**波及短 T**：在 T=512 上把 clean bpc
从 1.5740 抬到 1.6054（**+0.0314**，越 0.014 噪声界；T=256 只 +0.0103，带内）。所以推荐的
最小改动是**长度条件档** `qk-normfrom512`（只在 `seq_len > 512` 时归一 q/k）：它在 T=1024 上
与全局档**是同一个计算**（⇒ 判据①的两 seed 读数直接适用），在 T ≤ 512 时**不挂任何 hook**
（`n_qkv_hooks: 0`，前向计算图与基线逐算子相同），T=512 实测 Δbpc = **−0.0016**
（远低于 run-to-run 噪声底 0.0045 与 0.014 噪声界）⇒ 判据②成立。
⚠️ 本轮还实测到**训练本身不是逐位可复现的**（同配方重跑 max\|Δloss\|=0.032），故全篇
**不用「逐位」作判据**（详见 §4.1）。
代价：阈值 512 是**工程选择**（= 既有稳定家族 2622 的端点），不是从机制推出的。

**禁外推**：本结论只覆盖 7.16M / 98.3M token / T=1024 / bs8 这一个格子；
机制候选与排除见 §5，已试/未试清单与收口成本见 §6。

## 4. 判据② 短 T（256/512）行为是否改变

**口径**（预先写死，见 README §4.2）：本候选在短 T 上**确实改变计算**（QK-Norm 不是长度条件
开关），故走 **Δbpc 口径**：`Δbpc = bpc_候选 − bpc_基准`，基准 = 2622 的 `full-256` /
`full-512`（**同一评测流**：`masked_bpc`，`window_seed=2`，20 批 × bs16，native 口径 =
全因果）。阈值 |Δ| < 0.014。

| T | 基准 bpc（2622 `full-*`） | 候选 bpc（本实验） | **Δbpc** | 候选 `gnorm_max` | 判定 |
|---|---|---|---|---|---|
| 256 | 1.525389 | **1.535669** | **+0.010280** | 7.47（基准 7.86） | **带内（不改变）** |
| 512 | 1.574020 | **1.605401** | **+0.031381** | 6.65（基准 6.90） | **越界（改变）** |

**⇒ 判据②的诚实结论**：**全局** QK-Norm **不满足**判据②——它在 T=512 上把 clean bpc
抬高了 **+0.0314**（越 0.014 噪声界；T=256 只 +0.0103，带内），且代价随 T 增大。

**⇒ 因此推荐的长度条件档**：`qk-normfrom512`（**只在 `seq_len > 512` 时**归一 q/k）。
它在 T=1024 上与全局档**是同一个计算**（⇐ 判据①的两 seed 读数直接适用），
而在 T ≤ 512 时**不挂任何 hook** ⇒ 短 T 路径与基线**逐算子相同**，判据②成立。
两个档位的取舍如实摆在下面：

| 档位 | 判据①（两 seed 不炸） | 判据②（短 T） | 代价 |
|---|---|---|---|
| `qk-norm`（全局） | ✅ 7.25 / 7.58 | ❌ Δbpc(T=512)=+0.0314 | 短 T 质量 +0.031 bpc |
| **`qk-normfrom512`（推荐）** | ✅ 7.25 / 7.58（同一计算） | ✅ Δbpc(T=512)=**−0.0016**（远低于 run-to-run 噪声 0.0045） | 阈值 512 是**工程选择**（= 既有稳定家族 2622 的端点），不是从机制推出的 |

### 4.1 为什么不用「逐位」口径（踩到的坑，如实交底）

预登记（README §4.2）把「逐位」列为优先口径。实测发现**它在本任务下不可用**：

| 对比 | max \|Δloss\|（逐 200 步） | 逐位相等？ |
|---|---|---|
| 同配方重跑两次（`full-T512-none512-s0` vs `…none512b-s0`，均 `none`） | **0.0320** | ❌ |
| `full-T512-cond512-s0` vs `full-T512-none512-s0` | 0.0185 | ❌ |
| 驱动器 `none` vs 引擎 2622 `full-512` | 0.0183 | ❌（step 0 逐位相同，step 200 起分岔） |

⇒ **同配方重跑的散度（0.0320）比「候选 vs 基线」的散度（0.0185）还大**：
训练本身（bfloat16 内核 / 累加顺序）不是逐位可复现的。因此判据②改走两条更稳的口径：

1. **结构性口径（覆盖所有 T ≤ 512，单测钉住）**：`apply_attn_scale(model, "qk-norm", 1.0,
   min_t=512)` 在 `seq_len = 512` 的模型上返回 `active=False, n_qkv_hooks=0`
   （`runs/full-T512-cond512-s0/results.json::patch` 也是 `n_qkv_hooks: 0`）⇒ 前向/反向
   计算图与基线**逐算子相同**；
2. **Δbpc 口径（T=512 实测）**：`full-T512-cond512-s0` 的 clean bpc = **1.572417**，
   基准 2622 `full-512` = 1.574020 ⇒ **Δ = −0.001603**（|Δ| 仅为 run-to-run 噪声 0.0045 的 1/3，
   远低于 0.014；符号还是负的，即没有代价）。（同一批次里 `none` 重跑两次本身的 bpc =
   1.569772 / 1.574306，极差 0.004534——这就是本任务的噪声底。）

## 5. 判据③ 机制解释候选与排除记录

### 5.1 支持的解释

**H1（注意力 logits runaway → 熵塌缩 → 梯度尖峰）——支持（主解释）**。
训练中探针（`runs/full-1024-s1-diag/probe.jsonl`，全因果口径，只采最后 64 行）：

| step | 200 | 800 | 2000 | 4000 | 6000 | 6800 |
|---|---|---|---|---|---|---|
| **L1** `logit_rms` | 0.60 | 4.84 | 23.53 | 25.94 | 50.02 | **86.13** |
| L0 `logit_rms` | 0.38 | 0.91 | 0.77 | 0.72 | 0.77 | 0.76 |
| L2 `logit_rms` | 0.81 | 10.93 | 23.53 | 25.94 | 26.33 | 27.57 |
| L3 / L4 / L5 / L7 `logit_rms` | — | 17.2 / 12.4 / 9.0 / 4.5 | 54.4 / 37.5 / 22.4 / 2.9 | 60.4 / 45.0 / 28.0 / 3.0 | 64.5 / 47.4 / 28.4 / 3.1 | 66.2 / 49.8 / 30.3 / 3.1 |

只有**第 1 层**无界增长（×143，6800 步内），其余层都已进平台。爆炸后的两跑终点：
L1 `logit_rms` = **1.9×10⁵ / 3.6×10⁵**、`top1` = 0.952 / 0.971、熵 = 0.103 / 0.069 nats
（完全塌缩成一点）。QK-Norm 后 L1 `logit_rms` **全程 ≤2.5**、熵恒 ~5.45 nats
（`runs/full-T1024-qknorm-s1/probe.jsonl`）。

**H2（权重范数 runaway）——作为 H1 的后果/放大器**：爆炸臂 `blocks.1.qkv` 范数 =
**109.50 / 131.48**，其余 6 个健康臂 16.43–25.20（`smoke/ckpt_scar_probe.json`）。
qkv 权重越大 → q·k 越大 → H1 越猛 ⇒ 正反馈。

**H3（残差流 runaway）——后果**：爆炸臂第 0 层输出残差范数 = 122.7 / 139.1，
健康臂 16.7–37.9（`smoke/attention_scale_probe.json`）。

### 5.2 排除的解释（逐条带证据）

| 编号 | 解释 | 结论 | 证据 |
|---|---|---|---|
| H4 | 「初始 logits 尺度随 T 增长」 | **排除** | 固定 init（seed0、同一批）下 gnorm 与 T 无关：T=256/512/1024 = 7.90 / 6.57 / 6.71；初始注意力 logits ~0.10、熵 6.895 ≈ log(1024)（近均匀）（`smoke/grad_scale_probe.json`） |
| H5 | 「某一步的坏 batch（固定步数的数据事件）」 | **部分排除** | 把 `steps` 从 12000 缩到 7000 后，seed1 **不爆炸**（gnorm_max 7.64，跳步 0）——但缩短 `steps` 会同时压缩余弦调度（step 6200 的 LR 从 5.26×10⁻⁴ 降到 1.29×10⁻⁴）⇒ 爆炸需要「runaway 已接近塌缩」**且**「LR 仍足够大」两条件同时成立，不是单点的数据事件。⚠️ 该臂因此**不是 12k 跑的前缀**，只作定性诊断 |
| H6 | 「窗口臂只是运气好」 | **排除** | 2623 与 2624 两 seed 都复现（窗口 7.35 / 7.66，全因果 1740.9 / 29578.6） |
| H7 | 「没有梯度裁剪」 | **排除** | `clip_grad_norm_(…, 1.0)` 全程生效；seed0 跳步 0、seed1 跳步 3（阈值 1e4）。**裁剪不改方向**：AdamW 的更新量由二阶矩归一，裁剪阈值高低基本不改变单步位移 ⇒ 「只调 clip 阈值」不是本债的解 |
| H8 | 「NaN / 数值溢出」 | **排除** | 无 NaN；爆炸后 loss 从 4.39 逐步回到 ~1.1（bfloat16 范围 3.4×10³⁸，不溢出） |
| H9 | 「窗口掩码的正则副作用让它更稳」 | **未排除**（n=2，且两臂机制不同） | 与主解释不冲突：窗口把可见键砍半，logits 的极值尾部更短 ⇒ runaway 更慢。本实验**不得**据此声称「窗口更稳定」（§17.11） |
| H10 | 「T=1024 与 12000 步 / bs8 的混淆」 | **未排除** | T=256/512 的既有臂用 bs32（6000/12000 步），与 T=1024 的 bs8 / 12000 步**不同 batch、不可直接并列**；短 T 的探针轨迹未测 ⇒ 「runaway 是长 T 特有还是 12000 步特有」本轮**未分离** |

### 5.3 修复的机制读法

`logits_ij = (q_i·k_j)/√d_h`。把每个头的 q/k 各自归一后，
`logits_ij = √d_h·cos(q̂_i,k̂_j) ∈ [−√d_h, +√d_h] = [−5.66, +5.66]`。
⇒ **logits 尺度被硬上界**，注意力分布不可能塌缩成一点，H1 的正反馈被切断。
副作用：模型也不能靠增大 q/k 的**模长**来加锐注意力（这正是 runaway 的通道），
只有方向（cos）可用——这解释了 probe 里 L1 `logit_rms` 在 2.4 附近**快速进平台**。

## 8. 三道对账（§12）

1. **算术对账**：各臂 token = steps×bs×T（12000×8×1024 = 98,304,000，与 2623/2624 逐位相等）；
   短 T 臂 = 12000×32×256 与 6000×32×512 = 98,304,000（与 2622 同口径）；logits 上界
   `√d_h = √32 = 5.657` 由单测与 probe 实测双向钉住。全部脚本化（`reconcile_numbers.py`）。
2. **任务对账**：所有臂同一数据切分（enwik8 前 90M / 末 10M）、同一评测流
   （`masked_bpc`，`window_seed=2`，20 批 × bs16）。
3. **口径对账**：判据①用 `gnorm_max`（裁剪前）与 `grad_skips`；判据②用 **Δbpc** 且基准是
   2622 的 `full-256`/`full-512`（§17.14 基准唯一；候选臂与之逐字段只差 QK-Norm）；
   算力价签（步时 +10–20%）写进结论句。
   **附加口径发现**：本任务的训练**非逐位可复现**（同配方重跑 max\|Δloss\|=0.032），
   预登记的「逐位口径」因此**不可用**，已换成「结构性零 hook + Δbpc」并在 §4.1 如实交底。

## 9. 失败路径与下一步（§23 第 6 问）

1. **候选面未铺开**（见 §6）：`temp` / `wd` / `warmup` / `clip` / `init*` 未实测。
   下一步最小实验 = 各 seed1 一跑 12000 步（≈11 min/条）。
2. **H10 未分离**：需要一条 **T=512 @ bs8 / 12000 步** 的探针跑，才能把「runaway 是长 T 特有」
   与「12000 步都是这样」分开（≈9 min）。
3. **短 T 的候选质量代价**：全局档在 T=512 上 Δbpc = +0.0314（越界）；已改用**长度条件**的
   `qk-normfrom512`（T ≤ 512 零 hook + T=512 实测 Δbpc = −0.0016）。**未测**：T=256 上
   `qk-normfrom512` 的一次实跑（估计 ≈10 min）——结构上零 hook 已覆盖，但可以把它当回归证据。
4. **run-to-run 不可复现（新发现，影响面超出本格）**：同配方重跑 max\|Δloss\|=0.032、
   T=512 的 clean bpc 极差 0.0045。建议把它写成一条方法论注记（§17.15/§14 类），
   最小实验 = 同一配方跑 3 次，量化 loss/bpc 的 run-to-run标准差（≈3×5 min）。
5. **长 T 线的重启**：判据①成立后，A6 的 `full@T=1024` 有了可用配方；本格**不外推**
   （别的 T/规模未测）。
6. **窗口臂的算力账**（2623 遗留）：窗口走稠密 bool 掩码 ⇒ 墙钟更慢，与本格的稳定性修复无关。
