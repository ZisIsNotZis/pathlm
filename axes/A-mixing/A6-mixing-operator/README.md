# A6-mixing-operator · 混合算子

> 轴：**A 序列混合机制** ｜ 状态：**✅ judged**

> **判读**：内容选择式 Top-K 稀疏注意力在 **T=256 上净亏**：质量越删越差（k=32 越界有害、k=64 只在噪声带内），成本**实测上升** 2.2×（慢且更占显存）——稀疏的收益要到长上下文才可能出现。

## 1. 命题

用什么算子合并被看见的信息（不改变可见集合，只改变合并方式与成本）。

## 2. 选项枚举（本格全部可能取值）

1. `softmax 注意力（本项目基底）`
2. `Top-K 稀疏注意力（内容选择式，NSA/MoBA 族）`
3. `线性注意力 / kernel 化`
4. `SSM / 递归扫描（Mamba/RWKV 族）`
5. `卷积（局部固定核）`
6. `池化（PoolFormer 式无参数混合）`
7. `MLP-Mixer（token 维全连接混合）`
8. `傅里叶 / 全局变换（FNet 族）`

## 3. 状态（我们做了什么 / 行业做了什么）

**本地已测**：理论：保留键数 −87.5%/−75%、注意力 FLOPs −43.75%/−37.5%（QKᵀ 因内容选择不可省）、整模型每 token FLOPs −6.25%/−5.36%、**KV 缓存 −0%**（结构性）

**行业口径**：长上下文吞吐上稀疏/线性/SSM 明显占优；短上下文质量上偏差不一，
混合架构（注意力 + SSM 层交替，Jamba/Zamba 式）成为主流折中。
**本地实测为其补上「T=256 时净亏」的下界**：稀疏算子必须先跨过注意力占比的交叉点。

## 4. 结论与数字

- **税**：k=32 Δ = **−0.0166**（越 0.014 界，配对 20/20 批同向，t=−7.7）；k=64 Δ = **−0.0095**（带内但配对可检出，16/20，t=−4.1）；基线 full 1.5304（同配置历史 1.5287 / 重跑 1.5279）；剂量单调（k 越小越差）
- **收益**：理论：保留键数 −87.5%/−75%、注意力 FLOPs −43.75%/−37.5%（QKᵀ 因内容选择不可省）、整模型每 token FLOPs −6.25%/−5.36%、**KV 缓存 −0%**（结构性）
- **判读**：内容选择式 Top-K 稀疏注意力在 **T=256 上净亏**：质量越删越差（k=32 越界有害、k=64 只在噪声带内），成本**实测上升** 2.2×（慢且更占显存）——稀疏的收益要到长上下文才可能出现。

## 5. 失败路径与原因

1. **成本实测量反方向**：整模型一步 24.34 → 54.02/54.76 ms（**2.22×/2.25× 慢**），进程峰值显存 1.47 → 2.55/2.57 GB（1.7×）；孤岛参考实现（真稀疏 gather）仍 1.63×/2.13× ⇒ 「T=256 净开销」是结论而非实现 bug
2. **质量也越界**：k=32 的 Δ 达 −0.0166（>0.014），k=64 仅落在噪声带内（−0.0095）；两臂 loss 斜率同方法可比（0.0025/0.0037/0.0031，极差 0.0012）⇒ 水平差不是收敛差
3. 交叉点只有公式外推（注意力占比 14.3%@256 → 72.7%@4096），**长 T 端未实测**；2× 训练点未做 ⇒ 限快照口径

## 6. 判据与判决实验设计

- **判据**：bpc + 长上下文吞吐 + 内存（三段：质量 / 算力 / 内存）

## 7. 成本估计

- 13M 单臂 ~25–60 min（内容 top-k 实测步时是全注意力的 2.2×，预算须按实测估）
