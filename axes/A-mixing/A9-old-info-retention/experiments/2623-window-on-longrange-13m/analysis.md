# 2623 · A9 合成长程判决（训练 window vs full）——分析

## 0. 人话摘要（先给结论，再给数字）

**这是干什么的。** 想问一句很实际的话：**如果把注意力限制成「每个位置只看最近 16 个 token」，
模型在需要「记住很久以前的一对键值、最后一口气把它取出来」的任务上，会不会吃亏？**
窗户（window）注意力是业界常见的省算力手段；本实验就在 13M 小模型上，把「窗户」这**一个**
变量单独拿出来，看它是不是「白省」。

**相对普通 decoder-only transformer 改了什么。** 只改**可见性掩码**：`full` 臂每个位置能看
它之前的所有 token（普通因果注意力）；`win16` 臂每个位置只能看最近 16 个 token（`keep[i,j] =
(j≤i) ∧ (i−j<16)`）。**参数量一个不差**（两臂都是 13,536,768），计算量也只差在那张掩码上。

**为什么改。** 窗户注意力的动机是省算力/省显存；它对准的痛点是长上下文开销。风险是：**把远处
信息挡在窗外后，模型就没有路径把远处信息带到提问处**。

**怎么测的。** 两臂都在**同一件合成关联回忆任务**上训练（随机键值对 + 多个提问，答案**不可由
局部统计猜出**），12k 步、bs32、T=256、同 seed、同优化器，**唯一差别是掩码**。训练后按各臂
**自己的掩码**评测：召回准确率（含 chance 基线与 95% 二项 CI）、**毁源对照臂**（把源片段换成
随机符号）、距离曲线、clean bit/token（辅助）。口径 = 准确率；chance = 1/64 = 0.015625；
答案行 CE 是决定准确率的那个损失。

**测出来多少（数字 + 参照系 + 人话量级）。**

| | 召回准确率（K=8 主腿） | 参照 |
|---|---|---|
| `full`（普通全注意力） | **0.3665**，95% CI [0.3591, 0.3739] | = **23.5 倍** chance |
| `win16`（只看最近 16） | **0.0144**，CI [0.0127, 0.0163] | ≈ chance（**0.92 倍**），**99% 的二项 CI 都压在 chance 上** |
| `win16_rep`（同配置重跑） | 0.0146 | ≈ chance（复现） |
| chance（随机猜 / 64 选 1） | 0.015625 | — |

**人话量级**：全注意力模型每 100 次提问答对约 37 次；只看 16 个 token 的模型每 100 次答对
**约 1.4 次**——和纯随机（约 1.6 次）没区别。两者差 **35.2 个百分点**（差值 95% CI [34.4, 36.0]pp，
两臂 Wilson CI **完全不重叠**，z≈81）。**毁源对照**：把被问的那对键值换成随机符号后，`full` 从
0.3665 掉到 **0.0145**（≈chance）⇒ 它的召回**确实来自那段远处信息**，不是局部先验或位置小抄。

**结论与下一步。** **在真正的长程任务上，纯窗户（无搬运通道）会 100% 丢掉远处信息——不是
「少赚」而是「全丢」**。所以「窗户白省」在本尺度**不成立**；它只覆盖「靠掩码逼出搬运」这条
路（与 2615/32-O 一致），**不覆盖「给显式搬运通道」**——ticket 35（2618）已证：同一任务加一个
**delta 写通道**后，窗口 16 臂召回从 ≈chance 升到 0.095（6× chance），毁源后掉回 0.008 ⇒
**修法是给通道，不是把窗户关掉**。下一步最小实验（见 §10）：给窗口臂加显式 carry 通道并同训练，
直接在本天平上量「通道能把窗户救回多少」。

## 1. 命题与判决

| 判据 | 操作化 | 结果 | 判决 |
|---|---|---|---|
| ① 合成召回（主腿） | 各臂 native 掩码下 `assoc_recall_multi_batch`（训练同族任务、held-out）K=8 | `full` 0.3665（CI 下界 0.3591 **>** chance）；`win16` 0.0144（CI 下界 0.0127 **≤** chance） | **过**：full 学会回忆，win16 与 chance 不可区分 |
| ① 窗口伤长程 | `full − win16` 两比例差 ≥10pp 且 CI 不重叠 | **Δ=35.2pp**，CI 不重叠（z≈81） | **过** |
| ② 毁源对照 | `corrupt_span(0,2K)` 后准确率 | `full` 0.3665→**0.0145**（≈chance）；`win16` 0.0144→0.0144 | **过**：full 的召回来自源信息 |
| ③ 距离腿 | 多查询 by-distance 曲线 + `var_recall` 六档 | full 随距离升高（d≈226–240 达 1.0）；win16 全档 ≈chance | **过**（主读数见 §5） |
| ④ clean bpc（辅助） | 任务分布上的干净 bit/token | full 答案行 **1.897**；win16 **5.999**（=chance 6.0） | 辅助腿：与召回口径一致 |

## 2. 逐字段对照（§9，唯一变量 = 掩码）

| 字段 | `full` | `win16` / `win16_rep` |
|---|---|---|
| `--train-window` | 0（无掩码） | 16 |
| `--train-anchors` | 0 | 0 |
| d / layers / heads / mlp | 256 / 12 / 8 / 6 | 同 |
| seq-len / bs / steps | 256 / 32 / 12000 | 同 |
| seed / lr / optimizer | 0 / 1e-3 / AdamW+cosine | 同 |
| 训练任务 | `assoc-mqar` pairs8 queries8 gap14 | 同 |
| 参数量 | 13,536,768 | 同（掩码零参数） |
| 块类 | stock `Block` | 同（窗口是正交装饰层） |
| **唯一不同** | 可见性 = 全因果 | 可见性 = 最近 16（对全层共享） |

`run.py` 自检：两臂（三臂）`params` 逐位相等；`full` 释放版 vs 显式因果掩码 max|Δlogit|=**0.0**；
`win16` 模型自带窗口前向 vs `masked_logits`+`window_anchor_keep_mask` max|Δlogit|=**0.0**
⇒ **训练掩码 == 评测掩码**（唯一实现点 `window_anchor_keep_mask`）。

## 3. 三道对账（§12，脚本化 `reconcile_numbers.py`，87 项 0 失败）

1. **算术对账**：训练 token = 步数×bs×T = 24×32×256×... = 12000×32×256 = 98,304,000（逐臂
   闭式相等）；`accuracy == n_hits/n`；`chance == 1/64`；毁源 n == 主 n；`chance_bits == log2(64) == 6.0`；
   三臂 `params` 相等。
2. **任务对账**：主腿源 key 距离 min=107（median 175）**≥ 窗 16**（源恒在窗外）；距离腿
   `source_inside_window == (d<window)` 逐档一致；主腿 K/Q/gap 与训练同档（K8/Q8/gap14）；
   vocab206 / cue205 一致。
3. **口径对账**：各臂 `train_log` 末步 == `results.json` 记录；窗口掩码口径（`full` 无掩码 /
   `win16` 每 200 步落盘 `visible_frac=0.120866<1`）；判决行 CE 有记录；5 个共享文件指纹一致。

## 4. 干预活性（§10）

- `window_mask_liveness`（每 200 步落盘，`train_log` 逐行）：`win16`/`win16_rep` 的
  `visible_frac = 3976/32896 = 0.120866`、`alive=True`、`params_added=0`；功能探针
  `max_abs_logit_diff_masked_vs_open = 2.106`（>0）⇒ 掩码**真的改了前向**。
- `full` 臂无掩码：`train_window=0`、释放版，无干预（对照臂）。
- 训练侧 `synth_answer_ce` 每 200 步落盘：`full` 从 4.42 降到 **1.50**（仍下降）；
  `win16`/`win16_rep` 从 ~4.57 只降到 **4.24**（≈chance 4.16）⇒ **窗口臂的答案行 CE 12k 步
  一直贴在 chance 上**，与准确率口径一致（不是「没训够」，是**结构性搬不到**）。

## 5. 距离读数（判据 ③）

**主读数 = 多查询主腿 by-distance（`full` K=8，n=16384）**：准确率随「被问的 pair 离提问处
多远」**单调升高**——近端（d≈107–150）约 0.10–0.30，远端（d≈226–240）达 **1.0**。（远端更高
是因为源的键值对在序列最前面、与后面的提问 block 分离更清楚。）`win16` 全部距离档都在窗外、
全部 ≈chance。

**次读数 = `var_recall` 六档（次级，位置外推，见 §9）**：`full` 六档全 **0.000**；`win16`
0.016–0.023（≈chance）。这里的 0.000 是**位置外推伪影**，不是「full 搬不动」，见 §9。

## 6. clean bpc（判据 ④，辅助腿）

任务分布上的干净下一 token CE（bit/token，越低越好；全位置 / 判决行；chance=6.0）：

| 臂 | 全位置 | **判决行** |
|---|---|---|
| `full` | 0.4723 | **1.8969** |
| `win16` | 0.7296 | **5.9993** |
| `win16_rep` | 0.7294 | 5.9974 |

全位置口径两臂都远低于 chance（因为绝大部分位置是不可预测的 filler，但 filler 本身可预测）。
**判决行口径才决定准确率**（§17.15）：`full` 1.90 bit（<chance 6.0）⇒ 真的在答；`win16`
6.00 bit（=chance）⇒ 在猜。**这就是「窗口臂训练不产生绕路」的直接证据。**

## 7. 收敛、快照口径与禁用外推（§16 / §17.11 / §17.15 / §17.16 / §17.17）

- 判决行 CE 末段斜率（step 200–12000）：`full` **−0.6117/1k**（仍在下降，**未收敛**）；
  `win16` −0.0525/1k、`win16_rep` −0.0722/1k（贴近 chance 的微降）。
- **因此 `full` 的召回是「快照」**（12k 步，判据行 CE 仍降）——但本判决的**符号是结构性的**：
  `win16` 的源**证明性地**落在窗外（min 距离 107 ≫ 窗 16），**再训也不会改变它看不到源**这一
  事实（2618 的通道臂说明「要救必须给通道」）。故「窗口伤长程」不受快照口径影响；`full` 的
  **绝对值**（0.3665）是快照下界，须带「未收敛」标注引用。
- **禁外推（§17.11）**：本结论只覆盖 **13M / 12k / window=16 / anchors=0 / 无搬运通道**
  这一格；**不得**外推到其他规模、其他窗口长度、或带了 carry 通道的配置（后者 2618 已单测）。
- **非退化（§17.16）**：`window=16@T=256` 经单测钉住**非退化**（`visible_frac=0.120866<1`），
  不是恒等/空算子；但本实验是「两臂同配方单点对比」而非「同族两点趋势」，故 §17.16 只要求
  非退化这一点。
- **§17.17 不触发**：本实验净效应**可排序**（Δ=35.2pp、CI 不重叠），且代价项方向与收益项
  同向（`full` 的 clean bpc 也不差：全位置 0.472 vs 0.730）⇒ 不存在「净和不可排序、需分量
  分解」的情形。
- 复现臂 `win16_rep`（同 seed 同配方重跑）召回 0.0146 vs 主臂 0.0144 ⇒ **n=1 负结论已复现**
  （见 §8）。

## 8. 稳定性与复现

- **纯推理复现**：`win16` 主腿 K=8 同 seed 重跑，`n_hits` **25 == 25**（逐位同读数）。
- **训练侧复现**：`win16_rep` 整条 12k 重跑，召回 0.0146、答案行 CE 4.2244（主臂 4.2449）⇒
  结论复现（训练侧固定 seed 在本引擎不可逐位复现是项目级已知事实）。
- gnorm max：full 159 / win16 159 / win16_rep 196，无 NaN。

## 9. ERRATA / 执行期发现的测量问题（**必须随结论一起说**）

**问题**：契约写「合成召回（主腿）」但**未指定任务变体**。最初把**单查询**
`assoc_recall_batch`（查询键在**最后一个位置**）当主腿，实测 `full` = **0.0000**、`win16` =
0.0122，看起来「两臂都 ≈chance」。

**诊断**：这是**测量问题，不是「full 搬不动」**。多查询训练布局里**最后一个位置恒为 filler**，
`full` 学到一个位置先验「末位预测 filler」；单查询/`var_recall` 把查询键放在末位（位置外推），
于是 `full` 在末位吐 filler（实测其预测 token 恒为 64=filler）。**证据**：同一 `full` 权重在
**训练同族**的多查询布局上 K=8 = **0.3665**（23.5× chance），K=4 = 0.177、K=16 = 0.109。

**处置（methodology §14：先排除测量问题）**：主腿改用 **`assoc_recall_multi_batch`（训练
同族布局、held-out 新键值）**；单查询 `assoc_recall_batch` 与 `var_recall` 作**次级**如实报告
（`results.json::secondary_single_query` / `distance_leg`）。两个读数都落盘、**不隐藏**。
判据线未改，只把「测量哪件任务」定清（§17.14 基准唯一且显式）。

## 10. 失败路径 / 下一步

| 症状 | 诊断 | 处置 |
|---|---|---|
| （已发生）单查询变体 full=0 | **位置外推伪影**（末位先验） | 主腿改用训练同族任务，单查询作次级（§9） |
| `win16` 召回 ≈ chance | **结构性**：源恒在窗外、无搬运通道 | 判决成立；修法 = 给显式通道（2618 已证 delta 通道 → 6× chance） |
| `full` 判据行 CE 未收敛 | 快照（12k） | 标「快照下界」；**未做 2× 长训点**（见下） |

**未测项（下一步最小实验 + 成本）**：
1. **给 `win16` 臂加 delta carry 通道**并同训练，直接量「通道把窗户救回多少」（≈14 min 单臂；
   属 M1 格复核，2618 已在**训练/评测同为窗口 16** 下证过 6× chance）；
2. **2× 长训点（24k）** 看 `full` 召回是否继续升、Δ 是否稳定（§16，≈26 min）；
3. `var_recall` 的**非末位变体**（把查询键移到训练见过的位置）以取得对 `full` 可判读的距离曲线
   （需改 `longrange_tasks`，属工具线）。

## 11. 口径与实测墙钟

- **口径**：准确率（native 掩码）；chance=1/64；95% Wilson CI 与两比例 pooled z；bpc = bit/token；
  Δ 一律 `Δ = full − win16`（正 = full 更好）。
- **实测墙钟**：训练 full **13.01** / win16 **13.75** / win16_rep **14.18** min；评测全电池
  **1.03** min；步时稳态 ≈**72 ms/step**（400 步探针，共享卡争用）。峰值显存 full **1630.4 MB** /
  win16 **2015.3 MB**（**< 5GB net**，未触礼貌线）。
- **锁台账**：取锁/释放按 §20.1（整程 >10 min ⇒ 按臂释放 + 臂间 ≥60s）；共享卡上与 Y1/Y2 线
  竞争，win16 与 win16_rep 各经历过 1 次 10 min 取锁超时（rc=9），由 `run_eval_then_rep.sh` /
  `--arms` 分次补跑完成；无锁泄漏、未杀他人进程。

## 12. 与既往实验的关系

- **ticket 32-O（2615，enwik8 训窗口）**：强局部先验任务，结论「窗口训练不产生右移、窗口外针
  是丢了不是搬了」。本实验是它的**合成弱局部先验对照**（§19）：结论同向且更强——**windows
  在真正长程任务上直接归零**。两者共同支持 A9 的「靠掩码逼搬运」负结论。
- **ticket 35（2618/2619/2620，M1）**：同一合成任务上，**给显式写通道**（delta）后窗口臂召回
  6× chance；本实验（无通道）是其**缺失的对照**：无通道的窗口臂 = chance。⇒ **通道是关键，
  不是窗口开关**。
