# CRITIQUE · F3-stopping（停止条件）— 独立批判审计（2026-10-04）

## ① 这是什么（我的理解）

研究「什么时候停止重复算力」：固定轮数、按模型自身置信度逐 token 门控、收敛判据、
还是把「质量-成本前沿」当带约束优化去求解（Slider）。

## ② 对着什么 sota，我们偏离在哪

- 业界标准：ACT（Graves 2016）、PonderNet、PABEE、CALM（Schuster 2022）、
  Mixture-of-Depths（Raposo 2024）——「按模型置信度自适应早退／选择性计算」是**成熟行业做法**，
  本仓 `axes/F-iteration/PRIOR_ART.md:143` 自认 (a)。
- 偏离点（真增量）：**多货币预算求解器 + 校准闭环**在公开工作里少见端到端（`PRIOR_ART.md:88`
  「未找到」）。这是本格唯一可能的增量，但它是**工程交付物**，不是可证伪结论。

## ③ 五类问题逐条判定

1. **开倒车：有（主结论层面）。** 「选择性问题获证」＝ 业界已证的置信门控早退
   （ACT/CALM 系）。我们的增量应是求解器与 100M 标度，而不是「选择性成立」本身。

2. **过程错误：有，两条。**
   - **判据被事后替换**：`.scratch/14-allocator/issues/01-step1-completion.md` 实验 1(2)
     预登记判据为「最低置信桶的每 FLOP 收益 ≥ 最高置信桶的 **2×**」；该文件自己的裁决段写
     「**我原定的判据（最低桶 ≥ 最高桶 2×）不是正确的透镜**」，改用「增益随置信单调下降、
     高置信带变号 + 门控把符号翻转」这一读法。⇒ 本格的 headline（`catalog.yaml:962`
     「选择性问题（愿景核心命题）获证」）建立在**跑后换过的判据**上。
   - **单点/单种子**：选择性读数来自 3 个 checkpoint（ALLOC/INT2/C1M），每格 n=1；
     INT2 与 C1M 的配方不同（C1M 还是旧引擎）。判据线附近无重复。

3. **结论错误：有。**
   - 「严格占优点复现（**0.635 fwd/tok @2.0502** vs plain 1.0 @**2.0545**）」
     （`catalog.yaml:962`）。原始证据 `.scratch/15-slider-rung3/evidence/SUMMARY.md` §3：
     k=1 spec τ=0.98 bpc **2.0502** vs plain **2.0545** ⇒ **Δ = 0.0043 < 0.014**
     （`docs/methodology.md:19`）⇒ **bpc 侧不可排序**，「bpc 更好」的说法不成立。
     可成立的部分只有「同质量（带内）下**少 37% forwards**」。
   - 「分配器本身不额外加税（单轮 mixture == overwrite，设计保证）」——这是**设计恒等式**
     （`pathlm/model.py:531-540`），不是测量结果；而门控开火本身是要付前向的
     （fires 22.16% @τ=0.98，`SUMMARY.md` §1 表），把它写成「不加税」容易被读成免费。
   - **正确结论应该是**：「按 prob0 门控把第二轮只花在低置信位置，可把净有害的均匀重试
     翻成净有益（INT2 −0.0193→+0.0211；C1M +0.0570→+0.1284，损坏输入 bpc）；
     代价是 k=1 spec 口径下 forwards 0.635 vs 1.000；**质量侧无超带差异**」。

4. **无意义：无**（选择性是真问题，且 G5 已证明多线不可用后，「把算力给谁」更重要）。

5. **值得做：有（补做最严判据）**，且与 G1 高度重叠——建议 F3/G1 合并到一条线，
   避免同一批证据写两次结论。

## ⑤ 正确验证方式（若补做）

- **该涨**：低置信分桶的**每 FLOP 修复收益**（预登记：分桶单调 + 低置信桶 ≥ 高置信桶 2×，
  这条原判据应**照原样**跑一次，不许换代）。

  `fire split gap ≤ 0.004`（跨半区开火率一致性）。
