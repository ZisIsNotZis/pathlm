## 0. 人话摘要（先说人话，再上数据）

**它是干什么的。** 普通注意力让每个词去看它前面**所有**词，算力与缓存随上下文长度平方增长。
线性注意力想做的事是：**把「看所有词」改写成「维护一个固定大小的记忆」**——每个词只把自己的
信息加进一个记忆矩阵，下一词直接读这个记忆，于是每层的算力与缓存在**长度上变成线性**
（理想情况下缓存甚至是常数，不随上下文增长）。这是长上下文时代最主流的三条省算力路线之一
（另外两条：稀疏注意力、状态空间模型），也是本仓库设计空间地图上 `A6` 混合算子格在
ticket 31-J（内容 top-k）之后要补的第二块。

**相对普通的 decoder-only transformer 改了什么。** 只改注意力算子本身，别的一律不动：

- 普通（基线）注意力：`out_i = Σ_j softmax(q_i·k_j/√dh) · v_j`——要先把所有分数
  `q·kᵀ`（一个 T×T 矩阵）算出来再做 softmax；
- 本实验的线性注意力：`out_i = Σ_{j≤i} (φ(q_i)·φ(k_j)) · v_j / Σ_{j≤i} φ(q_i)·φ(k_j)`，
  其中 **φ(x) = elu(x)+1**（一个逐元素的特征映射）。数学上就是「把 softmax 换成归一化的
  线性核」，但因为它可以改写成 `φ(q)ᵀ · [Σ_{j≤i} φ(k_j) v_jᵀ] / [φ(q)ᵀ · Σ_{j≤i} φ(k_j)]`，
  于是**不需要 T×T 分数矩阵**——只要一个 `dh×dh` 的记忆（状态）矩阵，每层每头一份。
- 改动量级：**参数量增量 = 0**（6,962,688 → 6,962,688，两臂逐位相同，单测钉住）；
  每 token 每层注意力的乘加数从 `2·T·d`（T=256 时 131,072）降到
  `2·d·dh + 2·C·d`（本实装分块 C=64 时 49,664；流式形式只有 16,896）。

**为什么要改。** ① 省算力：T 越大越省（本实装的理论交叉点 T* ≈ 96，流式形式 T* ≈ 32）；
② 省缓存：推理时不需要 KV 缓存，只要常数大小的状态（解析口径：T=256 时小 93.6%，
T 越大越接近 100%）。这是本轴上最可能「不亏」的算子——上一块（内容 top-k）已被证明
**两样都做不到**（质量越界 + 实测 2.2× 慢、KV 一字节不省）。

**怎么测的。** 同一台天平上的两个臂，唯一变量 = 注意力算子：

- 同一 stock 13M decoder-only（d=256 / 8 层 / 8 头 / seq 256 / bs 32 / mlp 4 / tied 读出）；
- 同一数据（enwik8 前 90M 字符训练、末 10M 评测）、同 seed 0、同 12k 步（98.3M token）；
- 指标 = **clean bpc**（每字符比特数，越低越好 = 压得越准），口径 = matched-step 快照；
- **Δ 两个符号都报**（见 §4）；阈值 0.014 = 本项目的方差界。

**测出来多少（人话版）。**

- **算力（实测，同机同时刻；`results.json::cost`）**：整模型一步的墙钟，线性注意力在 T=256 时是基线的
  **2.58×**（59.8 ms vs 23.2 ms），T=1024 降到 1.74×，T=2048 降到 1.53×——**一路在缩小，
  但在实测到的 2048 以内始终没有回本**；只看**注意力子层**这一块（孤岛口径）则在
  **T=1024 首次反超**（11.2 ms vs 11.6 ms，0.96×），T=2048 时是 0.68×。
- **内存**：解析口径下线性注意力**省 93.6%**（T=256，推理缓存从 131,072 个元素降到常数
  8,448 个；T 越大越接近 −100%）；但**实测训练峰值显存反而涨 1.41–1.47×**
  （T=256 时 1.14 GiB vs 0.81 GiB）——因为训练用的是并行分块形式，要物化块级状态与块内分数。
- **质量**：全注意力臂跑完 12k 步，clean bpc = **1.5268**；**线性注意力臂没有跑完**——它在第 2 次尝试时报废于一个**训练期卡死**（不是数值发散、不是 OOM：
进程卡在 `loss.backward()` 里，CPU 满载、GPU 不再前进、日志停在某一步；两次卡死都在
分母塌到数值下限之后）。因此本实验的**可信结论是「干预在当前实装 + 当前共享卡环境下不可行」
加上**一整套已经实测到的**成本数据（这是契约判据 ② 要求的东西），
而不是一条线性注意力的质量结论。**我看过哪些方向、停在哪、为什么不继续**见 §3；
**成本数据**见 §6；**口径与未决问题**见 §12。

## 1. 结论一句话

**线性注意力在 13M / T=256 上：理论省算力（每 token 每层注意力 MACs −62%）、
理论省缓存（推理缓存 −93.6% 且在 T→∞ 时趋向 −100%），但本实装既没有实测省时
（T=256 时整模型步时 ×2.58、T=2048 时 ×1.53；只有**注意力子层**在 T=1024 反超 0.96×），
也没有在本次执行中跑完 12k 步——**三次尝试分别停在第 800 / ~500 / 400 步**，
报**训练期卡死**（卡在 `loss.backward()` 内、CPU 满载、显存不变），
而卡死每次都紧跟在**归一化分母塌陷**（φ 下溢到 0 ⇒ 分母触到 clamp 下限 1e-6）之后。**
⇒ 本实验如实记「**干预不可行（在本次环境与实装下）**」，并把判据 ② 的成本数据完整交出。

> **后续（指针）**：本仓后续实验 `2637-linear-attn-quality`（ticket `52-A6L`）在 **bs8 / 6000 步 /
> 引擎指纹 `f2e72361`** 下**未复现**停摆，并给出质量腿（原实装·带伤 Δ=−0.214；稳定化·核已改 Δ=−0.624）。
> 那**不是**对本结论的推翻：`2637` 明写 **本实验的 bs32×12000 步配置未复跑、引擎版本不同
> （`cafb532e` → `f2e72361`）⇒ 停摆触发条件仍未分离**。「当前实装下不可行」按本配置保留。

**这次不做什么（防止把结论做成另一个实验）**：
- 不改判据线（判据原文见 `README.md` §4）；
- 不把 `linear` 换成别的算子（例如 cosformer 的 relu 形式、加特征归一化）来「救」它——
  那是**另一个实验**，需要新的契约与预登记判据；
- 不削减步数来凑一条「能跑完」的结果（那会变成不等预算比较）。

## 4. Δ 的符号与判据 1 的判读（预登记，未改）

契约 R 判据 1 的原文：`|Δbpc| < 0.014 ⇒ 与全注意力同质量；Δ ≥ +0.014 ⇒ 线性化在该规模有害
（记录幅度）`。这句话在符号上有两种读法（SCHEMA §17.3 要求全篇统一），本实验**两个都报、
不选**：

| 名字 | 定义 | 本次是否可得 |
|---|---|---|
| `delta_bpc_schema` | `bpc_full − bpc_linear`（SCHEMA §17.3：正 = 线性更好） | **不可得**（linear 臂未产出 12k clean bpc） |
| `delta_bpc_contract` | `bpc_linear − bpc_full`（契约句面读法：正 = 线性更差） | 同上 |

判读：**判据 1 本次无法判定**（不是「不满足」，是「无数据」）——按 SCHEMA 纪律，
无数据的判据不得写成 pass，也不得事后调整判据线。

## 5. 实现层证据（可失败单测 / 变异 / 活性 / O(T) 证明）

### 5.1 可失败单测（12 条，`tests/test_depth_ar.py` 的 linear 段）

① 缺省关闭逐位还原 v1；② φ ≡ elu+1 的公式（含 relu+1 与去掉 +1 两种错版的分叉点）；
③ 分块实装 == 显式打分参考实现（多 chunk / 多 shape）+ chunk 只是实现细节；
④ **严格因果**（改未来 token，前面位置逐位不变——这条钉住 `cumsum − chunk`
带来的 1 ulp 未来泄漏，实现用「cumsum 右移补零」的 exclusive prefix 写法）；
⑤ **O(T) 证据**（FLOP 计数：×T×4 ⇒ 线性 ×4.0 vs 全注意力 ×16.0；`TorchDispatchMode`
形状追踪：全程不物化 T×T 张量）；⑥ 仪器自检（精确因果掩码下，评测端显式打分路径
与训练路径数值一致；删一个键 ⇒ 输出必须变化）；⑦ 两臂参数量与初始化逐位相同；
⑧ 开关必须改变前向 + 活性量（φ>0/den>0/inter_mass_frac 有值）；
⑨ 护栏（只在 dense+sequential、与 top-k/窗口互斥、chunk 必须整除、stock 路径守卫）；
⑩ 反向可达且每个位置的 v 与 φ(k) 都拿到非零梯度；⑪ 活性块与真实数据流上的探针契约；
⑫ 核质量分布仪器（同一权重下 linear vs full 两个分布可与手算复现，kind 非法报错）。

### 5.2 变异验证（6 处破坏全部抓红 + 逐字节还原）

见 `mutation_report.json`：① 块内不去三角（非因果）；② 块间状态 inclusive cumsum；
③ φ = elu（去掉 +1）；④ 线性块直接调 SDPA（换个名字的全注意力）；⑤ 去掉归一化分母；
⑥ 仪器掩码路径忽略掩码。每次变异后 `pathlm/depth_ar.py` 逐字节还原
（`restored_byte_identical = true`），还原后基线单测全绿。

### 5.3 活性量与**数值塌陷**（SCHEMA §10 + 本实验的意外发现）

活性量每 200 步落盘（`<arm>-train_log.jsonl` 的 `attn_linear` 块）。它是「干预活着」的证据，
也是**卡死的先行指标**：

| 量 | full 臂 | linear 臂（前 ~1000 步，逐 200 步可核） | 含义 |
|---|---|---|---|
| `phi_min` | `null`（开关关闭） | 0.195 → 0.0078 → **0.0** | φ = elu+1 在负半轴下溢（fp32 下 x ≲ −16 时 φ 恰好为 0） |
| `den_min` | — | 26.4 → 2.34 → **1e-06（触到 clamp 下限）** | 归一化分母塌陷 ⇒ `out = num/1e-6` 会放大 10⁶ 量级 |
| `inter_mass_frac` | — | 0.585 → 0.5829 → 0.5468（attempt3 留存日志） | 输出范数中来自「块间状态（远过去）」的份额——**机制确实被用到** |
| `gnorm` | 0.5–0.8（全程） | 0.85–1.5 → **5065.9**（尖峰） | 分母塌陷后梯度爆炸（clip 到 1.0 才没发散） |

一句话：**干预是活的**（φ 生效、状态通道被读、同权重换算子有偏差 `rel_dev > 0`），
但**激活它的那条路同时把分母推到了数值下限**；两次训练卡死都发生在这个状态之后。
这是本实验给出的最重要的一条负面结论：在本实装的 `elu+1` + `1e-6` clamp 组合下，
线性注意力的**训练稳定性**在 13M / enwik8 / lr=1e-3 上是脆弱的。

| 2048 | 88.837 | 135.745 | **1.528** | 5.585 / 8.230 | 30.556 / 20.695（**0.68×**） |

（数字 = `results.json::cost.measured.ratio_by_T` / `attn_island_by_T`，由 `reconcile_numbers.py`
逐项回算核对：每个比值都由原始 ms/显存重算。）

**读法（诚实分账）**：
1. **理论是省的**（注意力 MACs −62%、推理缓存 −93.6%），**本实装的实测步时在 256–2048 全段是涨的**；
2. 这条差距的原因与上一块（内容 top-k）不同：top-k 是「算法本征」的亏（必须算全分数矩阵），
   而线性注意力是**纯实装代价**——本实装用 PyTorch 算子拼出分块形式（块间状态 `cumsum`/`cat`、
   每层 ~20 个额外算子、离开 SDPA 融合核），没有任何融合核；注意力子层孤岛的实测比值
   （`cost.measured.attn_island_by_T`）把「算法本征」与「本实装」分开报；
3. **实测交叉点（两个口径分开报）**：
   - **注意力子层（孤岛）**：**512 < T* ≤ 1024**——T=1024 时 linear 首次更快（0.96×），
     T=2048 时 0.68×（这是「算法本征」一侧的实测交叉点）；
   - **整模型**：实测范围内（256–2048）**始终 > 1**，T=2048 仍 **1.53×**
     ⇒ 如实记「**整模型在本卡本批内未回本**」；
   - 理论交叉点（`T* = dh + C = 96`／流式 `dh = 32`）是**公式**，与实测差 1–1.5 个数量级，
     差距来自：无融合核、逐层 ~20 个额外算子、以及整模型的注意力占比只有 14.3%@T=256
     （所以注意力省 62% 只等于整模型省 8.9%）。**不得内插/外推**：T>2048 的「回本点」
     本批没有测。

## 12. 口径标注与未决问题（不得外推的部分）

- **口径**：成本三口径（MACs 公式 / ms/step / 峰值显存）**分别标注、互不换算**；
  质量口径本次只有 `full` 臂。
- **不得外推**：理论交叉点（96 / 32）是**公式**，本批实测在 256–2048 全段未回本 ⇒
  「长 T 回本」在本批**没有实测支持**。
- **未决**：① 线性注意力在该规模的质量税（缺 12k 快照）；② 卡死的确切根因
  （需要能在共享卡上复现的最小脚本 + 运行时栈）；③ 若换用数值稳健的特征映射
  （特征归一化 / 相对 clamp）是否会同时解决质量与卡死——**这是下一个实验**，不是本次结论。
- **反向的正面证据（如实记录）**：本实装确实是 O(T)（FLOP 计数 ×4.0 vs ×16.0、不物化 T×T）、
  参数量零增量、推理缓存解析口径 −93.6%——这三条与「不可行」并不矛盾：
  **不可行的是本实装的训练稳定性，不是线性注意力这个方向的数学**。
