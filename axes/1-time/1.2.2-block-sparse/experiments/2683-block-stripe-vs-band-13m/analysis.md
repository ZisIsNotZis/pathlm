# 2683 · 同可见键数下「块条带」对「均匀条带」：判读

## 0 人话摘要（先说结论，再上表）

**同样花 24 个可见键，「最近 16 + 一块对齐的远块」与「最近 24」在质量上分不出高低**（判词：**无质量增量**）。
两个 seed 的点估计都略偏向均匀条带（−0.011552 / −0.010784），方向一致、配对标准误只有 0.0016–0.0018，
但**都没越过预登记的 0.014 bpc 带** ⇒ 按 `harness/methodology.md` §2 的纪律，这两个数**不可排序**，
判词只能写「同字节下块粒度这个非均匀性买不到质量」。

bpc（每字符比特数，越低越好）的三行读法：

| 花多少键 | 怎么花 | clean bpc（seed 0 / 1） | 相对全因果（Δ = bpc_条带类 − bpc_full） |
|---|---|---|---|
| 256（全看） | — | **1.502689** | — |
| 24 | 全给最近 24 个位置（均匀条带，主判对照） | **1.599270 / 1.598631** | −0.096581 / −0.095942 |
| 24 | 最近 16 + 滞后 4 块的一块对齐 8 键（块条带，主判实验臂） | **1.610822 / 1.609415** | −0.108133 / −0.106726 |
| 24 | 最近 16 + 最前 8 恒可见（局部+全局，同字节轴上的第三个模式） | **1.622527 / 1.621799** | −0.119838 / −0.119110 |

三行连起来看有信息量：**把 8 个键从「最近处」挪走，挪得越远质量越差，且差得单调**——
条带（全在最近处）1.5986–1.5993 < 块条带（挪到距离 25–39、中间留 9–16 个键的洞）1.6094–1.6108 <
局部+全局（挪到最前 0–7）1.6218–1.6225。块条带落在中间，而且它离条带的距离（0.011）比局部+全局
（0.023）近一半——这与「远键离得越近、损失越小」一致。这张表就是「掩码真的在起作用」的证据：
如果远块根本没进前向，块条带不会精准地落在这两者之间。

**一句话判读**：块稀疏（BigBird 式）的**块粒度**这个非均匀性，在 T=256 / 每位置 24 键 / 13M 上
**买不到质量**；读数支持「不是实装坏了，而是这笔交易不赚」（证据与反证据见 §7）。

## 1 六问（格式契约，`harness/SCHEMA.md` §25）

**1 它是干什么的。** 让模型在**每个位置只看 24 个键**（不到全序列的十分之一）的前提下覆盖整条序列：
近处细看、远处按块粗看，而不是把 24 个键全给最近的 24 个位置。

**2 相对普通的 decoder-only transformer 改了什么。** 只改注意力可见集，公式层：
`keep[i,j] = (j ≤ i) ∧ ( (i − j) < 16 ∨ j ∈ [8·⌊i/8⌋ − 32, 8·⌊i/8⌋ − 32 + 8) )`，
即最近 16 个位置恒可见，外加**一块 8 个键的块对齐远块**（滞后 4 个块；行内偏移 `r = i mod 8` 时
远块落在距离 `[25 + r, 32 + r]`）。改动量级：**新增参数 0**（仍是 stock `Block`），
每位置可见键数在稳态恒为 24（= 16 + 8），逐行与均匀条带**逐行相等**；
实装是稠密 bool 掩码 ⇒ 每 token 等效注意力 FLOPs 的省幅是**结构上界、未兑现**（§6）。
实现在 `block_sparse.py`（`BlockStripeModel` 只覆写 `_window_mask`），自证 `python3 block_sparse.py`。

**3 为什么要改。** 痛点是长上下文里注意力的 T² 成本与 KV 读带宽。业界主流的省法是「非均匀可见集」
（Longformer 的 local+global、BigBird 的 block sparse）——这些方法都在**同样的 FLOPs 预算**下主张
质量更好。本仓先把「非均匀本身值不值」这一层单独问出来：`2677` 已判局部+全局在 24 键时**更差** 0.023；
块粒度是同一问题上的第二个、也是 BigBird 最核心的形态，此前**从未实装、无读数**（`project.yaml::gaps` 第一条）。

**4 怎么测的。** 单因素：唯一变量 = 24 个可见键怎么分配。七臂同骨架（d=256 / L=12 / h=8 / T=256 /
mlp×6 / bs32 / lr1e-3 / 12k 步 / 98.3M token、enwik8 前 90M 训练、末 10M 评测）：
两支新训练的块条带臂（seed 0/1）+ 复用 `2677` 的均匀条带两臂 + 复用 `2662` 的局部+全局两臂 + `full` 上界。
指标 = clean bpc（`masked_logits` 因果移位 CE，每臂在自身可见性下评测）；口径 = matched-step 快照、
96 批 × bs16、`window_seed=2`、**逐窗口配对**（1536 个窗口）；判据线 = 预登记的 0.014 bpc 带
（**只用于配对 Δ、≥5 窗口**，`harness/methodology.md` §2），**两个 seed 各自判一次**；
Δ 方向 = `bpc_均匀条带 − bpc_块条带`（正 = 块条带更好）。契约见 `README.md` §3，机器可读副本 `config.json`，
判据落盘 `results.json::main_verdict`。

**5 测出来多少。** 见上表与 §3：Δ = **−0.011552 / −0.010784**（两 seed），都在 0.014 带内（83% / 77% 带），
配对窗口里对块条带有利的占 42.4% / 44.1%。参照系：同样少看 232 个键，均匀条带付 0.0966、块条带付
0.1067 → 块条带的**窗口税只比均匀条带多约 0.011**（不是 0.1 量级），也就是说块条带并没有把近处信息
丢掉一大截，只是没赚到。

**6 结论与下一步。** 不采纳（无质量增量，同字节下不值得换）。这是**设计问题还是别的问题**：
见 §7——本实现的活性与正确性证据齐（掩码活、同源、等键、参数一致、口径未漂移），
所以不属「实装坏了」；但它属「**本设计下无信号**」而不是「块稀疏这个机制被否证」
（`atlas/playbook.md` 定律 10）。下一步最小实验（当前未做）：0 训练 token 的评测期掩码反事实
（`attribution.py`，≈3 min GPU），把「远块那 8 个键对这个模型值多少」直接量出来。

## 3 主判（判据①）

Δ = `bpc_win24a0 − bpc_block8l4`（正 = 块条带更好）；1536 个评测窗口逐窗口配对。

| seed | Δ bpc | 配对 sd | se | t | 对块条带有利的窗口占比 | 判词 |
|---|---|---|---|---|---|---|
| 0 | **−0.011552** | 0.061569 | 0.001571 | −7.35 | 42.4% | 无质量增量（落带内，带宽的 83%） |
| 1 | **−0.010784** | 0.069895 | 0.001783 | −6.05 | 44.1% | 无质量增量（落带内，带宽的 77%） |

两 seed **同向**（都为负、都落带内）⇒ 按预登记三态，判词 = **无质量增量**。
键路径：`results.json::main_block_stripe_vs_band.0` 与 `::.1`、判词 `results.json::main_verdict`。

**这一行必须读对（否则会读成自相矛盾）**：配对设计下这个差**统计上很确定**（6–7 个标准误，
`t_stat` 见上行），但它**小于 0.014 带**——那个带是 13M 跨 run 的 bpc 漂移界（`harness/methodology.md`
§2），不是「配对差的置信区间」。所以正确说法是：**方向一致为负、幅度在带内 ⇒ 不可排序**
（不是「没有差别」，也不是「块条带更差」）。预登记把 ① 的三态写成「越带才算占优 / 更差」，
本实验按它执行，没有事后改线。

## 7 机制不成立，还是本实现不成立

这是本格的核心区分（`atlas/playbook.md` 定律 10：缺条件的结论只能记「本设计下无信号」，不得读成「机制无效」）。
逐条列出**已实测**的证据与**推断**，不混写：

**属「实现成立」的实测证据（4 条）**

1. 掩码真的进了训练前向：`mask_calls_during_training = 4,608,048`（`train/block8l4_s0/results.json::block_sparse_mask`、
   `::s1` 同值）——不是「开关开着、掩码没跑」的死干预。
2. 训练与评测用**同一张**掩码：`fingerprint_sha256 = 304839561ec8…` 两侧相等
   （`results.json::train_eval_mask_same.<臂>.same_mask = true`），且「模型自己的前向」
   与「显式掩码前向」逐位相同（`::forward_path_check.<臂>.max_abs_logit_diff = 0.0`）。
3. 预算严格对齐：逐行可见键数逐行相等（`mismatch_rows = 0`）、`n_visible_pairs` 同为 5868、
   参数量逐位相等 ⇒ 两臂的差不能记在「少看/多看键」或「参数不同」上。
4. 尺子没漂：五个复用臂逐位复现 `2677`（`::reuse_gate`）。

**属「机制层面」的实测证据（2 条）**

5. 三个 24 键模式的质量**单调地**随「键被挪走多远」下降：条带 1.5986–1.5993 → 块条带 1.6094–1.6108
   → 局部+全局 1.6218–1.6225（§0 表、§4 参照线）。这张掩码确实在按它构造的距离结构限制信息。
6. 同一机制在**宽预算**下不可分辨：`2677` 的 200 键剂量点（192 + 8 全局）与全因果 Δ = +0.001784 落带内
   （`axes/1-time/1.2.2-block-sparse/experiments/2677-local-global-vs-band-13m/results.json::paired_vs_full.win192a8_s0`）
   ⇒ 这一族掩码本身不坏，坏的是「紧预算下把键挪出最近处」这笔交易。

**仍是推断（没有直接实测，不当结论用）**：`块` 这个粒度把 8 个键从距离 16–23 换成距离 25–39、
且每行留 9–16 个键的洞 ⇒ 在 enwik8 这种局部相关文本上，换来的是「同样的 8 个键、更大的距离、更碎的覆盖」，
所以没有增量。这条与第 5、6 条的**方向**一致，但「那 8 个远键对这个模型到底值多少 bpc」**没有被直接量过**：
本实验没有「最近 16」的反事实臂。补齐它的最小实验是 0 训练 token 的评测期掩码消融
（同 `axes/1-time/1.1.1-hard-window/experiments/2679-anchor-eval-ablation-13m` 的做法，
脚本已落盘为 `attribution.py`，≈3 min GPU）；它给出「关掉远块后 bpc 涨/跌多少」，
才能把「远块没用」与「远块有用但不如近处 8 个键」分开。**在它跑出来之前，本实验的判词只到
「本设计下无质量增量」这一层，不推到「块稀疏机制无效」。**

## 8 边界（不能从本实验读出来的东西）

- **不能**读成「块稀疏 / BigBird 式掩码无效」：本实验只测了**一个**确定性成员，且只测 `LAG=4`（与本地带
  不相交的最小滞后，是对非均匀性**最有利**的设定）。随机块、跨块条带、多块、更远滞后都未测。
- **不能**读成「块条带更差」：点估计两 seed 同向为负，但按预登记的 0.014 带不可排序（§3）。
- **不能**推广到别的 T / 规模：T 固定 256、13M、12k 步、enwik8 单语料，n=2 只覆盖主判两臂。
- **不能**说省了算力：省幅是结构上界（−90.6% 每位置 KV 字节），本实装是稠密 bool 掩码，墙钟与显存都没省
  （§6，`atlas/playbook.md` 定律 11）。
- **率类召回腿未跑**：本判词只对质量腿（bpc）成立。远块是否让远端内容可召回，读数在
  `axes/1-time/1.1.1-hard-window/experiments/2662-hard-window-anchor-13m/results.json`（指针，本文件不转述）；
  按 `harness/methodology.md` §2 的「不跨量纲借用 0.014」纪律，率类要按配对 bootstrap / Wilson CI 另判。
- **不能**把 0.011 当跨格常数：它是 13M / T=256 / 24 键 / 这一批评测窗口上的一个点。
