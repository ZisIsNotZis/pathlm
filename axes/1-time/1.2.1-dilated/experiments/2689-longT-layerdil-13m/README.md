## 1 要回答的判决问题

上一轮（`2678`）在 **T=256** 上判出两半：真实文本上把同 32 个可见位置摊开（近端 16 + 16 个摊满前缀的
空洞点）**不换质量**（Δ = bpc_win − bpc_dil = +0.01195 / +0.00696，两 seed 同向但都落 0.014 带内）；
而需要远处信息时掩码**确实搬得动**（合成关联回忆 n=2）。留下的问题是：

> **「真实文本不需要空洞掩码」这条在长 T 上还成立吗？** 合成任务已证明机制可用，
> 如果长 T 上真实文本开始吃远处信息，上一轮的否证就只在本尺度成立。

两件事必须分开答（§4）：

* **长 T 腿（核心）**：同 32 个可见键、同 98.3M token 预算，把 T 从 256 推到 1024、2048，
  配对 Δ(T) = bpc_win(T) − bpc_dil(T) 是否越 0.014 带？若越，从哪个 T 开始、斜率多大？
  若一直落带内，是「长 T 上真实文本不需要远处信息」还是「本尺度/本 k 分辨不出」？
* **逐层递增 dilation 腿（机制侧补充）**：把空洞点**按层**推远（第 ℓ 层 stride 2^ℓ，LongNet 式），
  长 T 上相对「各层同一张摊满前缀的掩码」有没有质量增量？这条腿回答的是
  「上一轮的空掩码是**每层都摊开**，如果只有深层摊开、浅层保持连续窗口，结果会不会变」。

一句话可证伪的形式：*在 13M / 98.3M token / T ∈ {1024, 2048} 的 matched-token 配方下，
`dil32` 相对 `win32`（同 32 键）的配对 clean bpc Δ 两 seed 都落 0.014 带内，且空洞臂对自身
远处键的边际价值（判据③ 的 D(T)）相对 T=256 不涨 ⇒ 上一轮的否证在长 T 上保持。*

## 2 臂的设计（唯一变量 = 每个可见位置怎么挑）

`k = 32`，三族掩码**逐行可见键数都等于 `min(32, i+1)`**（判据④ 机检）：

| 臂族 | 可见集（第 i 行） | 最远可达距离（T=2048） |
|---|---|---|
| `win32` | 最近的 32 个位置 `j ∈ [i−31, i]` | 31（恒定） |
| `dil32` | 近端窗口 16 个 `j ∈ [i−15, i]` **+** 16 个摊满前缀的空洞点（`2678` 同一条规则） | `i`（`i ≥ 32` 时铺满整个前缀） |
| `lad32` | 近端窗口 16 个 **+** 第 ℓ 层的 16 个点按 stride `s_ℓ = 2^ℓ` 往远处取（`span_ℓ = min(P−1, s_ℓ·15)`） | 第 0 层 31 → 第 7 层 `16 + min(i−16, 1920)` |

* `lad32` 的第 0 层（`s=1`）其 far 点 = 紧邻本地窗口外的 15 个连续位置 ⇒ **该层掩码与 `win32` 逐位相同**
  （判据④ 的 c5b 机检这一条）；`s_ℓ` 越大摊得越远 ⇒ 逐层可达距离单调不减。
* 掩码是**静态位置掩码**（与内容、与步数无关），构造在实验目录的 `run.py`（`DilatedBlock` 把掩码
  buffer 挂在自己的 `Block` 上，走 `Block.forward(attn_mask=...)` 的既有掩码路径），
  **不改** `pathlm/**`、`train_depth_ar.py`、`tools/**`、`tests/**`。
* 窗口臂走引擎既有的 `train_window=32`（与 `2676` 的 `win32` 同一条路）。

## 3 配方与三个 T 点（跨 T 只作趋势描述，禁外推）

| 字段 | 值 |
|---|---|
| 形态 | stock dense decoder-only（`dense=True`、`topology=sequential`、无退出 / 无 carry / 无填充） |
| d / layers / heads / mlp_mult / dropout / norm_cap | 256 / 8 / 8 / 4 / 0.0 / 1.0 |
| lr / 数据 | 1e-3 / `data/enwik8_full.npz`（前 90M 训练、末 10M 评测，字符级 vocab 206） |
| **每个 T 点的 token 预算** | **98,304,000 token / 臂**（三点相等） |
| T=256 | bs 32 × 12000 步（两臂 checkpoint **复用** `2676`、`2678`，本实验只评测 + 等值门） |
| T=1024 | bs 16 × 6000 步（新训，seed 0） |
| T=2048 | bs 8 × 6000 步（新训，seed 0 与 1） |
| 训练入口 | `train_depth_ar.train()`（同一个训练函数，不复制训练循环） |
| 评测 | 20 批 × bs16、`window_seed=2` 的**配对** clean bpc（臂间逐批配对；每个 T 各自一套评窗） |

* **batch_size 随 T 变、token 预算不变**：`bs·T` 恒为 16,384（T=256 那点是 32×256 = 8,192，
  与 `2676`/`2678` 的原配方一致，因为该点要复用它的读数与 checkpoint）。跨 T 比较**只比同一 T 内的
  配对 Δ**，不比绝对 bpc 水平。
* **不用 qk-norm**：`1.1.1` 的长 T 线在 `full` 臂上观测到 T ≥ 1024 的 gnorm 爆炸（seed0 1740.92 /
  seed1 29578.57），修复手段是长度条件的逐头 q/k L2 归一。本实验三族掩码的每行可见键数都只有 32，
  与 `2625` 里两 seed 都稳的窗口臂同类（7.35 / 7.66），因此**不加**这个非标准因素；判据⑦ 用
  `gnorm_max < 100 且 skips == 0` 作入场门，破门即该臂作废（不硬判、不换配方）。

## 4 判据线（预登记，跑后不改）

**Δ 方向统一**（`harness/SCHEMA.md` §17.3）：**Δ = 读数_对照 − 读数_实验**，"实验" 永远是
"更值钱的那一臂"（`config.json::pairs` 逐对点名），⇒ **Δ > 0 = 实验臂更好**。

| # | 判据 | 判定线 | 该涨 / 该跌 / 必须不变 |
|---|---|---|---|
| ① **主判（长 T 腿）** | `Δ(T, s) = bpc_win(T,s) − bpc_dil(T,s)`，同批配对 | **0.014 bpc 带**（`config.json::band_bpc`，仅配对 Δ）：`≥ +0.014` = 空洞更好、`\|Δ\| < 0.014` = 无质量增量、`≤ −0.014` = 空洞更差。T=256 与 T=2048 出 n=2，T=1024 出 n=1（趋势点） | 该涨或如实报无增量 |
| ② **机制腿（逐层递增）** | `Δ_lad = bpc_dil32 − bpc_lad32`（T=2048，同一批） | 同 0.014 带 | 该涨（逐层递增该比平铺更好） |
| ③ **远处键的边际价值（描述量）** | `D(T) = bpc(空洞臂只留近端 16) − bpc(空洞臂原掩码)`，同批配对 | 逐 T 报，并报 `D(2048) − D(256)`；`≥ +0.014` 记「远处键的边际价值随 T 上升」 | 该涨（长 T 上更吃远处信息） |
| ④ **必须不变：掩码结构** | 三族掩码逐行可见键数 `= min(32, i+1)`；`mismatch_rows == 0`；`⊆ causal` 且 `mask_offending_future_pairs == 0`；`lad32` 的第 0 层与 `win32` **逐位相同**；`lad32` 逐层可达距离单调不减 | 机检，落盘 | 必须不变 |
| ⑤ **必须不变：参数量与构造路径** | 同一 T 内各臂参数量逐位相等；`dil32` / `lad32` 与 stock 构造**逐参数相同**（转换后核对，唯一变量 = 掩码） | 机检，落盘 | 必须不变 |
| ⑥ **等值门（口径未漂移）** | 本实验在 T=256 上重算的 `win32` / `win32_s1` / `dil32` / `dil32_s1` 逐批 bpc 必须与 `2678-dilated-vs-window-13m/results.json::per_batch_bpc` **逐位相同** | 不等即中止判决（评测口径漂移） | 必须不变 |
| ⑦ **入场门（稳定性）** | 每个新训臂 `gnorm_max < 100` 且 `grad_skips == 0` | 破门 ⇒ 该臂作废、不进判据、如实登记（不换配方、不硬判） | 必须不变 |
| ⑧ **申报不进判据** | 墙钟、峰值显存、每 token 可见键数、掩码最远可达距离列 | 逐臂申报 | — |

**判词规则（`config.json::verdict_rules`，机械应用）**

1. **① 主判（每个 T 各自出词）**：两 seed 同向且各自越带 ⇒ 按该方向入账（n=2）；
   同向但至少一个落带内、或两 seed 不同向 ⇒ 该 T 判「本 n 下不可排序」，**不解释成噪声、不取平均掩盖**。
   T=1024 只有 seed 0 ⇒ 只按该 seed 的 Δ 与带分类出词，**不作 n=2 结论**，只作趋势点。
2. **② 机制腿**：T=2048 上 `Δ_lad` 与带比较，n=1（只 seed 0）⇒ 出词但标明「只见一次」。
3. **③ 的用法（回答「不需要」还是「分辨不出」）**：
   * 若 ① 在 T=2048 判「无质量增量」**且** `D(2048) − D(256) < 0.014` ⇒ 判
     **「长 T 上真实文本不需要远处信息」**（模型连它读到的远处位置都没变得更依赖）；
   * 若 ① 在 T=2048 判「无质量增量」**但** `D(2048) − D(256) ≥ 0.014` ⇒ 判
     **「本 k 分辨不出」**：远处键在长 T 上确实更被依赖，但 32 键里只有 16 个远处点、
     覆盖率从 T=256 的 32/256 = 12.5% 掉到 T=2048 的 32/2048 = 1.5%，固定 k 抓不住它；
     此时报**所需 k**（与 T=256 同密度需 `k_far ≈ 16·T/256`）与**所需样本量**
     `n_req = ceil((1.96·sd/0.014)^2)`。
4. **「分辨不出（仪器侧）」的独立出口**：若某 T 的配对 Δ 全部落带内、但该 T 的实测解析力
   `2·SE(Δ) > 0.014` ⇒ 该 T 的「带内」是仪器侧结论，须报 `n_req`，**不得**读成「无质量增量」。
5. **「所需 T」怎么写**：固定 k 下远处点的覆盖率 `k/T` 随 T 单调下降（12.5% → 1.5%），
   所以「更大 T 会让固定 k 的空洞臂越线」不是本判据的推论；若数据出现随 T 单调上升的 Δ，
   按观测点给的斜率写**趋势**、不给外推值（`harness/SCHEMA.md` §17.11）。

**否证线（预登记）**：① 在 T=2048 两 seed 都落带内 **且** `D(2048) − D(256) < 0.014` ⇒
上一轮「真实文本上摊开位置不换质量」的否证**在长 T 上保持**，本格的结论范围从 T=256 扩到 T=2048
（仍不外推到更大规模、真稀疏核、更大 k）。若 ① 在 T=2048 越带为负（空洞更差）⇒ 判「按位置最近在长 T
上占优」，并须与 ③ 的读数一起解释。

## 5 预算与掉臂规则（跑之前就定）

| 项 | 值 |
|---|---|
| 训练 GPU | 7 支新臂：T=2048 五支（win/dil × 2 seed + lad × 1）+ T=1024 两支；实测步时 T=2048 ≈ 152 ms/步（6000 步 ≈ 15.2 min/臂）、T=1024 ≈ 93 ms/步（6000 步 ≈ 9.3 min/臂）⇒ **≈ 95 min**（上限 120 min） |
| 单臂 timeout | 20 min（`train_arms.sh`），超时该臂登记「未跑」，不推断 |
| 显存 | 实测 T=2048 峰值 10.5 GB（§20.2 三件套：逐臂申报 + 跑前后 `nvidia-smi memory.free` + 汇报里登记为超 5 GB 礼貌线的偏离）；T=1024 ≈ 6.4 GB |
| 可中断性 | 每 200 步落 `train_log.jsonl`；断点即重取锁重跑该臂 |
| **掉臂规则** | 按 `config.json::train_priority` 的槽位跑，GPU 预算（墙钟或他人占用）不够时**从队尾丢臂**；丢掉的臂在 `results.json::arms_not_run` 里如实登记，不进判据、**不当负结论** |
| 外部占用 | 卡上另有更高优先级项目（`/home/z/vibe/nomos`）；每臂开跑前查 `nvidia-smi`，空闲 < 8 GB 即排队等锁，不抢不杀 |

## 6 失败决策树

| 症状 | 处置 |
|---|---|
| 新臂 NaN / 发散（gnorm 尖峰、跳步 > 0） | 判据⑦ 破门：该臂作废、登记「未跑」，不进判据（不换配方重跑——换配方就换了单因素） |
| 掩码逐行计数不等 / 不 ⊆ 因果 / `lad32` 第 0 层 ≠ `win32` | 实现缺陷，中止判决（不硬判） |
| 等值门（⑥）：T=256 的逐批 bpc 复现不了 `2678` | 评测口径漂移，中止判决 |
| 单臂 timeout（>20 min）或锁等待超时 | 如实登记「未跑」，该臂不计入判据 |
| 两 seed 不同向 | 该 T 判「本 n 下不可排序」，不取平均掩盖 |
| 某 T 的 `2·SE(Δ) > 0.014` | 判「分辨不出（仪器侧）」并报 `n_req`，不写「无质量增量」 |
