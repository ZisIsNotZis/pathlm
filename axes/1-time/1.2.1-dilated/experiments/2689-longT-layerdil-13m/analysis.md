# 2689 · 长 T 上的空洞采样 + 逐层递增 dilation · 分析（人话摘要 + 判据读数 + 边界）

## 0 人话摘要

**它是干什么的（六问 1）**：让模型在「每个位置只看 32 个键」这个固定预算下，尽量别丢掉远处上下文。

**相对普通 decoder-only 改了什么（六问 2）**：什么参数都没加、什么矩阵都没换，只换注意力**能看见哪些
位置**。三族掩码的每行可见键数逐行相等（都 = `min(32, i+1)`）：`win32` 看最近 32 个；`dil32` 看近端
16 个 **+** 16 个等距铺满整个前缀的空洞点；`lad32` 看近端 16 个 **+** 第 ℓ 层按 stride `2^ℓ` 往远处铺的
16 个点。参数量 6,962,688（T=256）/ 7,159,296（T=1024）/ 7,421,440（T=2048），同 T 内三族**逐位相等**
（`results.json::n_params`）。

**为什么要改（六问 3）**：硬窗口下「感受野」与「每 token 可见量」同增同减；空洞采样号称能在同预算下
扩感受野。上一轮（`2678`）在 T=256 上判出「真实文本上摊开位置**不换质量**」，但那只在一个 T 点成立。
本轮把同一对臂推到 T=1024 / 2048，问：**那条否证在长 T 上还成立吗？**

**怎么测的（六问 4）**：13M / 8 层 / 256 宽 dense 主干，`data/enwik8_full.npz`，每个 T 点**同
98,304,000 token 预算**（T=256 是 32×256×12000，T=1024 是 16×1024×6000，T=2048 是 8×2048×6000）；
指标 = 20 批 × bs16、`window_seed=2` 的**同批配对** clean bpc（越低越好），判定线 = 0.014 配对带，
Δ = bpc_对照 − bpc_实验（**正 = 实验臂更好**）。跨 T 不比较绝对 bpc，只比同一 T 内的配对 Δ。

**测出来多少（六问 5）**：

| T | seed | Δ = 窗32 − 空洞32 | 带分类 | 人话 |
|---|---|---|---|---|
| 256 | 0 / 1 | **+0.01195 / +0.00696** | 都落带内 | 摊开**没买到质量**（与 `2678` 逐位一致） |
| 1024 | 0（单 seed） | **−0.01679** | 本轮越负带，**但跨带边界** | 点估计已经翻负；三次重训里两次落带内（−0.01142），**不可判**该点是否越带 |
| 2048 | 0 / 1 | **−0.02794 / −0.03147** | 都越**负**带 | 摊开**更差**：2.0 倍 / 2.2 倍带宽 |

人话量级：T=2048 上「把 32 个位置摊开」比「取最近 32 个」贵 **0.028–0.031 bpc**。同尺度的噪声带是
0.014，所以这不是噪声——两个 seed 同向、各自越带 2 倍左右，20 个评测批里绝大多数批都是同一个方向
（`results.json::criteria.c1_quality_by_T.by_T`）。同一 T 内相对全因果的参照臂本轮**没有**（见 §5）。

**机制腿（逐层递增 dilation）**：`lad32` 相对「每层都摊开」的 `dil32` 便宜 **+0.02947 bpc**
（Δ = 平铺 − 逐层，t = 19.33、20/20 批同向、越正带 2.1 倍；`results.json::criteria.c2_layered_arm.pair`）。
人话：**同样是 16 个远处点，「浅层保持连续窗口、只让深层摊远」比「每层都摊开」好 0.029**——分布方式
本身值钱。这条只有 seed 0 一条臂（n=1），只见一次；而且它的绝对值已经追平窗口臂（20 批均值
1.69806 对 1.69959，差 0.00153、落带内，见 §1 的 ②附 行，描述量不谈配对检验）。

**远处键的边际价值（判据③，描述量）**：把某支空洞臂的远处点全去掉、只留近端 16 个重评测，
比分掉 **0.10204（T=256）→ 0.20217（T=1024）→ 0.31570（T=2048）**，`D(2048) − D(256) = +0.21366`
（`results.json::criteria.c3_far_key_dependence`）。人话：**长 T 上模型确实更依赖它读到的那 16 个远处
点**——可它仍然输给「最近 32 个」。这两条一起说的是：远处位置**有信息**，但**摊开这 16 个点的覆盖
率代价（32/2048 = 1.6%）大于它买回来的东西**。

**结论与下一步（六问 6）**：见 §1 的三句话——①长 T 上摊开更差（n=2，改判）；②逐层递增比每层平铺好
0.029（n=1）；③带内不是仪器侧结论。下一步的最小实验见 §5。

**判词的三句话（按 `config.json::verdict_rules` 机械应用，未手改）**：

1. **T=2048 上「同 32 键把位置摊开」在真实文本上更差**（n=2，两 seed 同向、各自越负带）⇒ 长 T 上
   **按位置最近仍占优**，`2678` 在 T=256 的「无质量增量」在长 T 上收紧成「有质量损失」。
2. **逐层递增 dilation 相对每层平铺有质量增量**（+0.02947，越正带；n=1）⇒ 「怎么分布远处点」不是无关
   变量：浅层保持连续窗口、只让深层摊远，比每层都摊开好。
3. **本仪器在三个 T 上都有分辨力**（1.96·SE 全部 < 0.014）⇒ 带内的那个 T（256）不读成「分辨不出」，
   而是「确实没到带宽」；T=1024 的带分类**不稳**，按 §1 的 ①附 行处理。

## 2 结构与必须不变的项（判据④ 的落盘列）

- 三族掩码逐行可见键数 = `min(32, i+1)`，三个 T 全部 `mismatch_rows = 0`、`mask_offending_future_pairs = 0`。
- `lad32` 第 0 层与 `win32` **逐位相同**（`lad_layer0_equals_win32` = true），且逐层最远可达距离单调不减
  （T=2048：31 → 46 → 76 → 136 → 256 → 496 → 976 → 1936）。
- 同 T 内 `win32` / `dil32` / `lad32` 参数量逐位相等；5 支掩码臂的 `conversion_check.params_identical_to_stock`
  全为 true（转换只挂掩码 buffer，参数逐位不变）。
- 逐臂申报（不进判据，`results.json::train_declaration`）：T=2048 臂墙钟 4.19–4.26 min、峰值显存
  5844.7–5871.7 MB；T=1024 臂 2.87–2.93 min、3788.7–3795.7 MB；复用臂的墙钟/显存来自
  `2676` / `2678` 的逐跑读数。**峰值显存超 5 GB 礼貌线**这件事按 `harness/SCHEMA.md` §20.2 在此登记。

## 3 定律 9 / 10 的逐条核对：这次「不需要」不再是唯一解释

`atlas/playbook.md` 的**定律 9**（判据设计比实验本身更值钱）与**定律 10**（先问机制要有变化空间，设计上
必须满足什么）在本轮各有一条要核对的东西：

| 定律 10 的条件 | 本实验满足吗 | 证据 |
|---|---|---|
| 信息确实超出可见范围 | **满足**（长 T 上远处位置在可达范围内且被使用） | `criteria.c3_far_key_dependence`：去掉远处点会贵 0.10 → 0.32 bpc |
| 等参数 / 等深度 / 等算力对照 | **满足** | `params_equal_within_T` = true、同 T 同 token 预算 |
| 判据量效应超过本格自测噪声 | **满足**（T=2048 两个 seed 都越带 2 倍左右） | `by_T["2048"].band_classes` = 两 `beyond_negative` |
| 有真实核（纸面省算力兑现） | **不满足** | 稠密 bool 掩码，省算力一点没兑现（与 `1.2.2` 共用缺口） |

所以本轮不能再把「无增量」写成唯一读法：**在 T=2048 上，机制不是「没变化空间」，而是变化方向为负**——
远处点被用得更多（判据③ 涨），但为了让它们进来而挤掉的 16 个近端键更值钱。这与 `2678` 在 T=256 的
「无质量增量」不矛盾，是**同一个设计的效应随 T 变号**（见 §4）。

## 4 与 `2678`（T=256 判「无质量增量」）的关系：尺度依赖，不是矛盾

两轮的 T=256 读数是**同一条**：`2678` 的 4 支复用臂逐批 bpc 在本实验仪器上逐位复现
（`criteria.c5_reuse_equivalence` 4/4 = true），Δ 也同为 +0.01195 / +0.00696、同为 `in_band`。
变的是 T：把同一对臂推到 2048（同 token 预算、同参数量、同评测仪器）后，Δ 从 +0.012（带内）走到
−0.028 / −0.031（越负带）。所以正确的写法是：

> **「同 32 键摊开位置」在 T=256 上与「取最近 32 个」不可排序，在 T=2048 上明确更差。**
> 这条结论的作用域是「13M / dense / enwik8 字符级 / 98.3M token / k=32」，随 T 变号这件事本身是本轮
> 新增的事实，**不得**反过来改 `2678` 在 T=256 的判词，也**不得**外推到 k≠32、53.9M 或真稀疏核。

一个必须一起读的旁证：判据② 说明「同样的 16 个远处点，分布方式比有无更值钱」——把浅层留住连续窗口
（`lad32`）之后，同一支 T=2048 臂与窗口臂的差缩到 −0.00153（落带内，见 §1 的 ②附 行）。

## 5 未测项与边界（预登记之外不推断）

1. **没有 T ≥ 1024 的全因果参照臂**：`full` 臂在 T ≥ 1024 上需要长度条件的 qk-norm 才稳（`1.1.1` 的长 T
   线），那会引入第二个因素，故本轮不训。⇒ 本轮的「差多少」只在「32 键两族之间」有意义，**不能**换成
   「相对全因果差多少」。
2. **T=1024 只有 seed 0，且带分类在三次重训里不稳**（−0.01142 / −0.01142 / −0.01679）：该点只作趋势点。
   补 n=2 要再训 1 对臂（`win32-t1024-s1` + `dil32-t1024-s1`）≈ 8 min GPU。
3. **k=32 之外未测**：「加远处点的数量能不能买回来」由 `2690` 问，但那一轮四支臂里三支破稳定性门、
   剩下一支只有 n=1（见 `2690-dilated-density-k144-13m/analysis.md`），**问题仍然开着**。
4. **逐层臂只有 seed 0**（n=1）：+0.02947 只见一次；要给 n=2 需再训 1 支臂（`lad32-t2048-s1`，
   T=2048、bs8、6000 步 ≈ 4.3 min GPU）。
5. **稠密 bool 掩码**：纸面 `O(T·k)` 一点没兑现成实测算力（与 `1.2.2` 共用缺口）。
6. **不外推**：13M / 8 层 / enwik8 字符级 / 98.3M token 一点，53.9M 及以上、真稀疏核、别的语料都未测。

## 6 本轮的实现更正与定序披露（读结论前必须知道）

- **两处汇总阶段的缺陷**（都在「把已算好的数拼成人话/判词」那一段，判据线一字未改）：
  ① `run.py:499` 把 `band_classes` 的值（字符串）当 dict 下标取 `v["band_class"]` ⇒ 首次评测直接
  `TypeError`，判词与 `results.json` 都写不出；② `main_verdict.answer` 只按「deltas 非空」分支，负越带时
  仍以「长 T 上出现质量增量」开头，数与词互相打脸。另有一处 ③ `delta_directions` 漏声明配对统计里的四个 Δ
  字段（`sd_of_paired_delta` / `min_delta` / `max_delta` / `frac_batches_delta_gt_0`），`check_tree` 判红。
  三处分别由提交 `560af16` / `376b8f2` / `0ad2f0f` 修好，都**不碰** 0.014 带、配对表、判词分支与入场门。
- **重绑与重产出**：`run.py` 是契约文件，改它必须显式重绑 ⇒ `bound_at` 从 14:02:34 依次改为
  15:06:13 → 15:07:11 → **15:57:45**（`run.py` 哈希 `73c27847…`）。每次重绑都把「已存在的读数」记进
  `prereg_binding.json::readings_existing_at_bind`（**它们的定序不可判**），并且每次重绑后**全部读数
  重产出**（7 支臂重训、评测重跑），使进入判据的每一份读数都由绑定代码产出：
  `prereg_bind --check` = 与绑定不符 0、本实验读数全部「分提交有先后」。重绑之后 `run.py` 不再改动。
- **三次独立的训练-评测**（每轮都是 7 支臂重训 + 一次评测，同一配方同一 seed）：T=2048 的 Δ 依次为
  −0.02768 / −0.03252（首批）、−0.02938 / −0.03357（第二轮）、−0.02794 / −0.03147（本轮）；
  Δ_lad 依次 +0.02032 / +0.02077 / **+0.02947**；T=1024 依次 −0.01237（均值差）/ −0.01142 / −0.01679。
  **带分类与方向在 T=2048 上三次一致**，T=1024 上不一致（见 §1 的 ①附 行）。这些差异来自训练的浮点
  归约非确定性（同配方同 seed 不逐位相同），量级 ≤0.009、与 0.014 带同阶，**没有**为对齐而改数或反复重跑。
  本文件引用的数字一律是**最后一轮**（`results.json` 现值、哈希 `73c27847…`）的落盘值。
- 复用臂（`2676` / `2678` 的 4 支 checkpoint）不重训，逐位不变；首批评测（旧 `run.py`）的日志留在
  `eval_preretrain.out`，可对照三轮的 per-arm bpc。
- 逐跑 `train_log.jsonl` 是**追加写**（现在每支臂的文件里有三轮各 31 行，每 200 步一行）。读数只认
  `results.json`（它随每轮重训被整份重写），日志要按轮次分段读。
