# 2690 · 长 T 上「远处点的数目」买不买得到质量 · 分析（人话摘要 + 作废登记 + 机制诊断）

## 0 人话摘要

**它是干什么的（六问 1）**：回答 `2689` 留下的一个岔口。`2689` 在 T=2048 上判出「把 32 个可见位置摊开
比取最近 32 个更差」，但那只说明**这一种密度**的摊开不值钱，没说清「远处信息本身不值钱」还是
「32 个键里只放 16 个远处点太稀」。本实验只改**远处点的数目**：16 → 128（近端 16 窗口逐位不变）。

**相对普通 decoder-only 改了什么（六问 2）**：仍然只换可见掩码，不加参数。实验臂 `dil144` 每行可见键数
`min(144, i+1)`（近端 16 + 128 个等距铺满前缀的远处点），对照臂 `dil32` 是 `min(32, i+1)`
（近端 16 + 16 个远处点，即 `2689` 的 `dil32`）。两臂参数量逐位相等 7,421,440、近端 16 窗口逐位相同
（`results.json::criteria.c2_must_not_change`），远处点平均间距 67.24 → 7.94（`structure_checks`）。

**为什么要改（六问 3）**：这一条能把 `2689` 的「更差」拆成两种解释：远处信息不值钱（加密度也不买），
还是 32 键太稀、抓不住（加密度就买得到）。

**怎么测的（六问 4）**：与 `2689` 的 T=2048 点逐字段一致的配方（13M / bs8 / 6000 步 / 98.3M token /
enwik8 字符级 / seed 0 与 1），20 批配对 clean bpc，判定线 0.014 配对带，
Δ = bpc(16 个远处点) − bpc(128 个远处点)（正 = 远处点多更好）。对照臂的读数在**本实验仪器上重算**，
等值门（判据④）通过：`criteria.c3_reuse_equivalence` 两支 `dil32` 臂的逐批 bpc 与 `2689`
**逐位相同**（`reproduced` = true）。

**测出来多少（六问 5）**：**本轮没有取得可用于判词的读数**——不是因为「测出来一样」，而是因为
**这套配置坐在稳定边缘上，过门的支臂在两次重训之间换了种子、而且方向相反**。预登记的入场门
（判据⑤：`gnorm_max < 100` 且 `grad_skips == 0`）在三次独立训练-评测（3 轮 × 2 seed = 6 个臂次）里的记录：

| 2690 的训练-评测 | `dil144` seed 0 的 `gnorm_max` | `dil144` seed 1 的 `gnorm_max` | 过门的臂 | 过门臂的 Δ |
|---|---|---|---|---|
| 第一次 | 119.49 | 44332.79（另加 `grad_skips` 19、损失卡在 2.6–2.9） | 无 | — |
| 第二次 | 495.50 | **74.64** | seed 1 | **−0.11563**（远处点加密后**更差**，20/20 批同向） |
| 第三次（本轮） | **23.50** | 524.79 | seed 0 | **+0.02347**（远处点加密后**更好**，19/20 批同向） |

⇒ 六个臂次里只有两个过门，而且这两个**seed 不同、方向相反**。人话：**这套配置（每行 144 键 / T=2048 /
无 qk-norm）会让训练随机地炸或不炸；哪一支活下来是运气，活下来的那一支给的答案也不一样。**
本轮落盘的聚合读数因此只有 n=1（seed 0：`delta_bpc` = +0.02347、`two_se` = 0.00920、`t_stat` = 5.00、
`frac_batches_delta_gt_0` = 0.95、`n_req_for_band` = 9），按 `config.json::verdict_rules`「n=1 只报读数、
不落判词」，**不写成「加密远处点有用」**——同一条规则下，第二次那支过门臂的 −0.11563 也不写成「没用」。

**结论与下一步（六问 6）**：按 `README.md` §5 的预登记处置「破门 ⇒ 该臂作废、登记『未跑』、不进判据
（不换配方重跑）」+ `verdict_rules`「n=1 只报读数、不落判词」⇒ **本轮不出判词**。人话：**「把远处点从
16 加密到 128 能不能买回质量」这个问题仍然没有答案，而这次连测量都不可靠——先决条件是让这条配置
训得稳**（`gnorm_max` 在六次里跨了三个数量级：23.5 → 44332.79）。`2689` 的「本 k 分辨不出」岔口因此
仍然开着，登记在 `project.yaml::gaps`。

## 2 机制诊断：为什么这条密度路线在本尺度不成立（先撞稳定性门）

结构、参数量、等值门三条都通过（§1），破的是**优化稳定性**：每行可见键数从 32 涨到 144 之后，
T=2048 上注意力分数的动态范围更大，而本契约特意**不**加长度条件的 qk-norm（那会引入第二个因素）。
六次臂次的 `gnorm_max` 是 23.50 / 74.64 / 119.49 / 495.50 / 524.79 / 44332.79 —— **同一配方、同一 seed、
只重训一次就能跨三个数量级**（seed 0：119.49 → 495.50 → 23.50；seed 1：44332.79 → 74.64 → 524.79）。
同尺度下每行 32 个可见键的 11 支臂（`2689`）全部 `gnorm_max` 6.85–7.23、跳步 0，所以这不是「卡坏了」，
而是**可见键数把训练推到稳定边缘**。

这条经验可复用，写法就是本节第一段：**在 13M / T=2048 / 无 qk-norm 的 dense 主干上，把每行可见键数
从 32 抬到 144 会让训练不稳定（六次臂次只有两次过 `gnorm_max < 100` 的门），因此任何「加密稀疏采样点」
的实验都必须先解决稳定性（长度条件的 qk-norm 或更低 lr / 更长 warmup），否则测到的不是质量差，
是「活不活得下来」。**

## 3 与 `2689` 的关系（读本节前不要把机械判词当结论）

- `2689` 判的是「32 键内摊开 vs 最近 32」，本轮**不改变**那条结论。
- 本轮想补的是「远处点从 16 加到 128 能不能买回质量」，**没有答**：`1.2.1` 的「本 k 分辨不出 / 远处信息
  不值钱」这个岔口仍然开着，`project.yaml::gaps` 按未测项登记。
- 可引用的副产品只有一条：**稳定性事实**（§2）。

## 4 未测项与下一步最小实验（都不属本里程碑）

1. **加长度条件 qk-norm 重做 144 键对照**：那是把「唯一变量」换成两个（掩码 + 归一化），**必须另立契约
   重新预登记**；成本 = 2 支 `dil144` + 2 支同配方 `dil32`（对照也要同一归一化，否则不公平）
   ≈ 4 × 4.3 min + 评测 ≈ 20 min GPU。
2. **降密度试稳**：`n_dil` 64（每行 80 键）在 T=2048 上是否既稳又不明显更差？成本同 2 支臂 ≈ 10 min；
   仍属新契约，且要先写清「80 键与 32 键的差要超过多少才算」。
3. **降 T 到 1024 做同一密度问题**：显存与动态范围都更小，但「远处点覆盖率」的解释力随之变弱
   （1024/144 = 14%，已接近 T=256 的 12.5%），与 `2689` 的岔口关系更远。
4. **不改配方重跑同一臂**：按预登记的熔断纪律**不做**（重跑同一 seed 不能改判，且这是「凑出想要的
   结果」的做法）。

## 5 定序披露与读数边界

- 本实验的绑定早于它自己的第一批读数（首次 `bound_at` = 2026-10-21T14:13:52+08:00，绑定那一刻
  `readings_existing_at_bind` 为空）。此后为修两处**汇总阶段**的缺陷（`delta_directions` 漏声明两个实际存在的
  Δ 字段、又多声明了两个不存在的字段名；数值与判据线未动）两次重绑，最终 `bound_at` = 16:49:51、
  `run.py` 哈希 `69a3ee85…`；每次重绑后两支臂都重训、评测重跑，使现存读数全部由绑定代码产出
  （`prereg_bind --check`：与绑定不符 0）。
- 逐跑 `train_log.jsonl` 是**追加写**：现在每个臂的文件里有三次训练各若干行。读数只认 `results.json`
  （它随每轮重训被整份重写），日志分段看。
- 现有读数（本轮）：`dil144-t2048-s0` bpc 1.70405、`gnorm_max` 23.50；`dil144-t2048-s1` bpc 1.84452、
  `gnorm_max` 524.79（作废）。对照臂 `dil32-t2048-s0` 1.72753、`dil32-t2048-s1` 1.73300。
  `dil144` 的读数保留作**机制诊断**，不进任何判据、不作正负结论。
