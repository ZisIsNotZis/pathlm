## 人话摘要（先读这一段）

**这个实验在问什么**：一个 13M 的小语言模型，训练时只看**最近 16 个字**（窗口），
逼它把「很久以前见过的键值对」写进一块**固定记忆**（搬运通道 / carry）里，之后被问到时
从记忆里翻出来。现在问：**给这套「记忆 + 头共享（GQA，把注意力的 K/V 头从 8 个砍到 2 个，
省显存）」的模型，评测时再把 KV cache 压成 int8（每值 1 字节、再省一半内存），召回会不会崩？**
——这正是 ticket 38-W3 只测了一半的问题（W3 的载体是 MHA，没测 GQA）。

**主结论（干净、确定性）**：**不会崩**。评测期 int8 与 fp16 的召回**逐位相同**（
`0.928% → 0.928%`，命中数 19/2048 完全一样；另两条腿也都是 0.0pp / −0.024pp）⇒
**评测期 int8 不破坏 GQA+carry 通道**（本任务 / 本尺度）。这条是同一批权重上的确定性
评测，**不含训练随机性**，是 Z3 的核心问题。

**次要结论（n=1、两条腿结论相反 ⇒ 不可排序）**：把 K/V 头从 8 砍到 2（GQA，省 **8.58%**
参数）后，在**距离 241–255 的判决腿**上召回掉 **−3.03pp**（CI 不重叠），但在**训练同分布**
的腿（距离 107–240）上反而**高 +0.90pp**（CI 重叠）⇒ **两条腿符号相反、幅度都小 ⇒ 不可排序**，
既不能写「GQA 有害」也不能写「GQA 有益」。**且 GQA 还少了 8.58% 参数（§15 混杂）**，
本来就不能把差值直接归给「头共享」。

**必须记住的一条新发现（方法学级）**：**我的 `carry_gqa`（0.93%）与 Y1 里同配置的
`gqa_carry_window`（15.33%）差了 15 倍**——我把仪器/接线/配置/能力四类解释都排除了
（用自己的评测 harness 评 Y1 的权重 → 14.26% ⇒ **仪器无罪**；两条臂的**全因果**口径
= 15.5% / 9.9%，与 Y1 的 ~15% 一致 ⇒ **能力无罪**）⇒ **「距离 241–255」这条判决腿在 6k
步下 run-to-run 方差极大**（跨会话不可复现）。**该腿不得作为此类比较的主判据**——
详见 `stability.md`。这解释了为什么上一条「GQA 增量」只能标 n=1。

**术语**：`关联回忆`（MQAR）= 先给一串「键→值」、末尾问某个键、要答出对应值；`chance`
= 答案集上的瞎猜命中率（本题 1/64 ≈ 1.56%）；`窗口`（window）= 训练/评测时每个位置只能
看到最近 16 个 token；`carry` = 一块与序列长度无关的固定状态记忆；`GQA` = 多个查询头共享
少数 K/V 头（省 KV cache）；`int8` = 把 K/V 每值存成 1 字节（fp16 是 2 字节）；`CI` =
二项/正态置信区间；`pp` = 百分点。

## 1. 它是干什么的（一句话）

把 ENG1 解开的「GQA × 搬运通道 × 可见窗口」组合**训练出来**，再在**评测期**把 KV 压成
int8，量「头共享」与「低比特压缩」各自对长程关联召回付/得多少——补 W3 丢掉的 GQA 因子
与「训练质量腿」。

## 2. 相对普通 decoder-only transformer 改了什么

| 特性 | 结构层面改了什么 | 量级 |
|---|---|---|
| carry（`--carry-write delta`） | 加一块 `d×d` 固定状态：每步 `S←S(I−βk̂k̂ᵀ)+βvk̂ᵀ`；每层读出 `a←a+γ⊙(S q)`（γ 单边零起步） | **+264,296 参数**；状态大小与 T 无关 |
| window（`--train-window 16`） | 训练/评测同一掩码：每个查询只看最近 16 位（`keep[i,j]=(j≤i)∧(i−j<16)`） | **+0 参数**；可见对数 3,976 / 32,896（12.09%） |
| GQA（`--n-kv-heads 2`） | 注意力 K/V 投影只产生 2 个头（Q 仍 8），SDPA `enable_gqa=True` 按组广播 | qkv 输出宽 768→384；**总参数 −1,184,256（−8.58% vs carry_mha）** |
| int8 KV（评测期） | K/V 存成 int8（对称 per-channel）再读回；**不训练、不加参数** | **+0 参数**；每值 2→1 字节 |

（三个结构特性的引擎可组合性由 ENG1/ticket 39-X2 提供；本线不改引擎，只组合已有开关。）

## 3. 为什么要改

- **carry**：把窗口外的信息搬进可达范围（长上下文「丢了但搬了」，2618 的正面结果）。
- **GQA**：KV cache 与 KV 投影随 `n_kv_heads` 等比缩小 ⇒ 部署省显存/访存。
- **window**：制造「不搬就答不出」的需求（SCHEMA §19 的局部先验抗性），并省长上下文算力。
- **int8**：KV 访存瓶颈下每值 2→1 字节（与 GQA 叠加 ⇒ 解析每位置字节从 12288 降到 1536，
  **−87.5%**）。

## 4. 怎么测的（口径）

- **任务 = 合成关联回忆**（`tools/evalkit/longrange_tasks.py`）：`assoc_recall_multi_batch`
  （K=8、Q=8、gap=14）**训练**；评测三套口径（同一件任务、同批序、同种子）：
  1. **判决腿（Z3 契约的「主腿」）**：`assoc_recall_batch`（单查询 K=8），native window16；
     被问 pair 的 key 距离 **241–255**（窗外 ⇒ 不搬就答不出）。**（见 §7D：此腿方差大）**。
  2. **全因果交叉口径**：`keep_mask=None`（去掉窗口需求）。
  3. **训练分布内腿**：`assoc_recall_multi_batch`（多查询 Q=8），距离 **107–240**（≤ 训练上限）。
- **对照**：三行 = `carry_mha_fp16`（基准，W3 载体形态）/ `carry_gqa_fp16`（换头共享）/
  `carry_gqa_int8`（换 int8，**同权重**）；Wilson 95% CI + `two_proportion` 差值 CI。
- **训练配方**（两条被训练的臂逐字段一致，seed=0）：6k 步 × bs32 × T256 = 49.0M token，
  lr 1e-3，AdamW + cosine。**6k 快照**（与 2618 的 12k 口径标注见 §8）。
- **第二/第三腿并报**；**毁源对照臂**（把源 KV 段 `[0,2K)` 换成新随机符号）。

## 6. 活性量与收敛门禁

**活性量**（每 200 步一行；`results.json::train_activity`）：

| 臂 | KV 头形状 | carry read_share（末值） | window mask | 末行证据 |
|---|---|---|---|---|
| `carry_mha` | MHA（无此开关，`k_shape=[8,8,256,32]`） | **0.8564**（γ 已逃逸） | alive（12.09%） | `read_scale_absmean=0.1082`，`state_fro=2.657` |
| `carry_gqa` | **`k_shape=[8,2,256,32]`**，`qkv_out_width=384`，`kv_reduction=0.75` | **0.7541** | alive（12.09%） | `read_scale_absmean=0.1054`，`state_fro=2.076` |

**量化活性**（§10，取自真实前向）：int8 `changed_frac=0.9993`、`rel_err=4.80e-3`、
`clipped_frac=1.18e-4`；fp16 `rel_err=1.75e-4`（近无损）⇒ **量化真的改了数值、且 int8
比 fp16 粗**（不是假标签）。

**收敛门禁（§17.15，落在答案行 CE `synth_answer_ce` 上）**：末窗（4500→5999）斜率
`carry_mha = −0.0668 nats/1k`、`carry_gqa = −0.0583 nats/1k`，末值 1.62 / 1.58（chance CE=4.16）
⇒ **两臂都远未收敛** ⇒ **只读臂间增量，绝对水平是 6k 快照**。

**毁源对照**：三行的毁源后准确率（0.10–0.59%）都在 chance 附近、CI 下界 ≤ 4×chance
⇒ **三行读数都来自被搬运的源信息**（C3 通过，无行作废）。

## 7. 判读（分层结论，按主 Agent 裁决）

### 7A. 主结论：评测期 int8 不破坏「GQA + carry」通道（干净、确定性）

int8 vs fp16 = **0.0pp**（判决腿、全因果腿命中数逐位相同；分布内腿 −0.024pp）。
**同一批权重、确定性评测** ⇒ 不含训练随机性 ⇒ 直接回答 Z3 的核心问题。
**表述**：*「int8 级 KV 量化与 GQA+carry 通道兼容（本任务 13M / 本尺度）」*——
**不外推**到 MQA、int4、其它块类或更大尺度（§17.11）。

### 7B. 次要结论：GQA 增量 **n=1、跨腿符号相反 ⇒ 不可排序**

GQA 在判决腿 −3.03pp（CI 不重叠）、全因果 −5.62pp，但在训练分布内腿 **+0.90pp**（CI 重叠）。
两条腿符号相反、幅度都在个位数 pp ⇒ **不写成「GQA 有害」或「GQA 有益」**（§17.17）。
**归因声明（SCHEMA §15）**：GQA 是**剪枝类**（减参数 −1,184,256 = −8.58%）⇒ 按 §15 例外
应拿「同 FLOPs 的稀疏/稠密对照」比，本实验的对照 `carry_mha` **参数更多**，所以任何差值
都不能归因于「头共享」本身——它同时含「少了 8.58% 参数」。**结论只能是「多出的那 8.58%
参数在本任务的分布内腿上没换来质量（+0.90pp 不可分）」，绝不是「等参数下 GQA 更优/更差」。**

### 7C. 参数量差（判据 ④）

`carry_mha` 13,801,064 → `carry_gqa` 12,616,808（**−1,184,256 = −8.581%**）。
int8 行 +0 参数（只换存储精度）⇒ `int8_vs_fp16` 无参数量混杂。

### 7D. **方法学发现（主 Agent 要求显式记录）：判决腿（241–255）在 6k 下方差极大**

**同配置**（GQA2 + carry delta + window16，6k，seed0，同引擎）在我这轮主腿 = **0.93%**，
而 **Y1（2623）的 `gqa_carry_window` = 15.33%**——**差 15×**。四类排除：
① **仪器无罪**：用我的 harness 评 Y1 的权重 → 14.26%（且 released 与我的 fp16 档同读数）；
我的 fp32 档与 released **逐位相等**（两块类各一条自检）。
② **配置无罪**：同引擎（`depth_ar.py` 自 ENG1/`b96ac47` 后未改）、同 steps/bs/lr/seed、
同 window16/anchors0（两边训练日志 `window_mask` 逐字段相同、alive 12.09%）。
③ **能力无罪**：我的两条臂**全因果**口径 = 15.5% / 9.9%，与 Y1 的 ~15% 一致。
④ **非「模型没学会搬运」**：`read_share` 与 Y1 同量级（0.75 vs 0.81）、答案 CE 同量级
（1.58 vs 1.59）⇒ 差异**只在 window16 条件下**（记忆是否学会跨窗搬运的 run-to-run 方差）。
⇒ **「距离 241–255」这条判决腿在 6k 步下 run-to-run 方差极大，不得作为此类比较的主判据**。
**下一步最小实验（已排，≈26 min GPU）**：两臂 seed=1 复现，量化该腿方差（方差确认 ⇒ 永久
降级为辅助腿）。详见 `stability.md`。

## 8. 失败也要讲人话 / 未定的东西

- **原本以为**：GQA + int8 两重压缩可能让搬运通道「崩」（W3 的担忧）；三行在判决腿上应
  与 Y1 的 ~15% 同量级。
- **实际**：int8 对召回**完全没有影响**（逐位相同）——这是最干净的结果；GQA 增量跨腿符号
  相反（不可排序）；而判决腿的绝对水平与 Y1 差 15×（方差）。
- **为什么**：int8 的 per-channel 对称量化在本题的 K/V 动态范围下近无损（rel_err 4.8e-3，
  clipped 1.2e-4）；GQA 的 −8.58% 参数在分布内腿上没换来质量；判决腿越出训练距离分布
  （241–255 > 240）且 6k 远未收敛 ⇒ 高方差。
- **排除了哪些别的解释**：不是死开关（量化 changed_frac 0.9993、carry read_share 0.75、
  窗口 alive 12.09%）；不是局部先验（毁源后三行全落回 chance 附近）；不是仪器（fp32 逐位
  等值 + Y1 权重交叉复现，见 §7D）。
- **未定 / 显式留白**：① GQA 增量的**符号**未定（跨腿冲突，需分布内腿的 seed 复现）；
  ② `carry_mha + int8` 行 Z3 未列（W3 已单独回答），本线不做；③ MQA/int4/更大尺度未测；
  ④ **契约口径修正（主 Agent 认领）**：Z3 契约写「主腿 = 合成关联回忆召回」但**未钉死
  距离档**，导致用了超额距离腿（241–255）当主判据——这是**契约缺陷**；今后该类比较的
  主腿一律用**训练分布内**的距离档。

## 9. scope / 复核

本研究只做单轴单格实验，基底恒为 stock 对照；唯一变量 = 头投影（MHA/GQA）与评测期 KV
精度（fp16/int8），carry+window16 是常量。完成后按 SCHEMA §14（含 §14b 顺序屏障）另派
fresh-context 只读复核者独立检查。

## 10. 成本、锁与显存记账（§20 / §20.1 / §20.2 / §20.3）

  172 / 159 ms/step × 6k），加臂间 65s 窗口 ⇒ 训练合计 ≈ 25.8 min。**按臂取/放锁**，

  亦 < 5GB net。
- **§20.3 外部争用**：训练时共享卡上有两个 `llama-server` 常驻（~19.5GB / util ~99%），
  实测步时为空卡（2618 的 U2≈73 ms/step）的 ~2× ⇒ 按 §20.3 保持**臂间同 token 预算**
  （两条训练的臂一律 6k），并以 6k 快照口径报告（与 2618 的 12k 不可直接比）。

  （纯推理、≤2 min、峰值 <1GB、空闲 ≥3GB）**并发插入**，未取锁、未动锁目录
  （跑前/后 `nvidia-smi` 空闲 15890 / 15889 MiB）。
- **§8 预算**：`README §4c` 的 `gpu_wall_budget: 40 min`；本线实际 GPU 墙钟 ≈ 30 min。
