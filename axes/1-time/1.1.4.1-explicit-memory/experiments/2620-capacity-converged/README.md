# 2620 · 容量轴在「收敛后」是否有效（13M · 合成关联回忆 · 2 臂 × 24k 步 + 重跑臂）

> 契约来源：`.scratch/37-gaps/issues/01-gaps.md` 的「契约 V2」（逐字抄录见 §14）。
> 本目录实现它。**判据线在 §4 预先写下，读数之前不得修改。**
> 前置：U1（`../2619-carry-difficulty-capacity/`）测出「难度曲线成立、容量曲线不成立」，
> 但四臂 10k 步**未收敛** ⇒ 契约 V2 要求在**收敛后**重判容量轴。
> GPU 工作全程持 `/tmp/pathlm_gpu.lock`（SCHEMA §20，含自愈修正协议）。

## 1. 命题（人话）

U1 的结论是「把速记板做大到 4/8/16 倍，几乎没有用」。但 U1 的四条臂在 10,000 步时
**答案行交叉熵仍在明显下降**，所以「没用」可能只是**训练不够**（模型还没学会填满小板），
而不是「容量不是约束」。本实验把**训练步数翻倍到 24,000**，只改**状态宽度**这一个变量
（`dh=16` vs `dh=128`，×8），先证明两条臂**已接近平台**，再重判容量轴。

一句话可证伪的形式：*「在 24k 步、答案行 CE 已接近平台的前提下，`dh=128` 的关联回忆准确率
比 `dh=16` 高 ≥3pp 且 95% CI 不重叠。」*

## 2. 单因素声明

- **基底**：本仓 stock dense decoder-only trunk（`DepthARModel(dense=True)`：tied 读出 +
  无 final LayerNorm + 顺序残差），13.8M（d256×12 层×8 头×mlp6×T256），**写规则恒为 delta**。
- **唯一变量 = 记忆槽状态宽度 `dh`**（`--carry-state-dim` ∈ {16, 128}）。
  两臂**只差这一个字段**（其余逐字段一致，含 seed=0、步数 24,000、任务、窗口、lr）。
- **注意力路径逐位不动**（权重/头数/掩码不变）⇒ 曲线只能归因到状态宽度。
- **与 U1 的单因素对齐**：本实验沿用 U1 的 `D16`/`D128` 臂定义（同 `dh`、同任务、同窗口、
  同 lr、同 seed），唯一差别是**步数 10,000 → 24,000**。⇒ 本实验与 U1 的差是**预算差**，
  不是配方差（对照表见 §5）。
- **必要性与取舍（显式记账，SCHEMA §17.8）**：参数量随 `dh` 有 **±0.03% 的差**
  （写门表 `beta_w` 形状随记忆槽头数变）——这是本实验的**已知不等参数处**（同 U1）。
  它远小于状态浮点的量级差（×8），不会把「容量」误记成「参数」。
- **`dh=64` 档被砍（显式记账）**：契约写「若预算允许再加 64」。实测步时 95–98 ms/步
  ⇒ 24k/臂 ≈38 min，3 臂已 ≈115 min（超契约 50 min 预算 2.3×，**已由编排方批准**）
  ⇒ **不加 64 档**，判据线不砍（SCHEMA §17.7 的砍序：砍臂 > 砍步数 > 不砍判据线）。

## 3. 干预定义（实现，不是标签）

`--carry-state-dim`（`pathlm/depth_ar.py::DepthARConfig.carry_state_dim`，**既有开关，本轮未改
共享文件**）：单共享记忆槽 `CarryChannel` 的每个头把 `dh` 维键映到 `dh` 维值，
状态 `S ∈ R^{H_c×dh×dh}`，其中 **记忆槽头数 `H_c = d_model / dh`**（与注意力头数 8 解耦）。
总状态浮点 = `H_c·dh² = d_model·dh` ⇒ `dh` 翻倍、状态翻倍。

```
写入（每位置一次，来自输入流 h0）：k̂=normalize(W_k h0)、v=W_v h0、β=σ(W_β h0+b_β)
  delta：S_t = S_{t−1}(I − β_t k̂_t k̂_tᵀ) + β_t v_t k̂_tᵀ
读出（每层各一次）：a ← a_SDPA(窗口掩码)；a ← a + γ_ℓ ⊙ mem_t，mem_t = S_t q_t
```

| 臂 | `dh` | 记忆槽头数 `H_c` | 状态浮点/样本 | 参数量 | 角色 |
|---|---|---|---|---|---|
| `S16` | 16 | 16 | 4,096 | 13,803,216 | 小状态臂（主判据左端） |
| `S128` | 128 | 2 | 32,768 | 13,799,450 | 大状态臂（主判据右端） |
| `S16_rep` | 16 | 16 | 4,096 | 13,803,216 | **重跑臂**（与 `S16` 逐字段相同，量训练侧散度） |

## 4. 判据线（**预登记**，读数前写下；逐字对应契约 V2，见 §14 的抄录）

主腿用**准确率口径**（不用 bpc——合成任务 CE 是混合量，且训练侧 bpc 噪声已超方差界）。
`Δ = acc(大状态) − acc(小状态)`（正 = 大状态更好；全篇同号，SCHEMA §17.3）。

### ① 收敛前提（门禁，**编排方裁定的口径**）

- **门禁口径（唯一）**：主门禁 = **`synth_answer_ce` 末窗线性斜率的绝对值 < 0.01/1k 步**，
  或**末窗相对下降 < 1%**。**不是总 CE。**
  - 定义：末窗 = 最后 8,000 步（step ∈ [16000, 23999]）；斜率 = 对该窗内每 200 步一条的
    `synth_answer_ce` 做 step 的普通最小二乘，乘以 1000（单位 = nats / 1k 步）；
    相对下降 = (首个末窗值 − 末值) / 首个末窗值。
  - **「相对下降 < 1%」的实现口径（读数前写明）**：判的是**末窗相对变化幅度 < 1%**
    （`|rel_drop| < 0.01`）——**上升（`rel_drop < 0`）也算「变化幅度」**，只有幅度
    < 1% 才当「接近平台」；若答案行 CE 在这 8k 步里掉超过 1% 或涨超过 1%，都不算收敛。
    （只判 `rel_drop < 0.01` 会把「还在变差」误判成达标，是不允许的实现。）
  - 两臂（`S16`、`S128`）**都必须**满足；**未收敛则本实验不作容量结论**，只报曲线。
- **必附对照（不作门禁）**：三套并报——
  (a) 总 CE（训练 log 的 `loss`）末窗线性斜率；
  (b) 总 CE 与答案行 CE 的 **U1 同方法 log-log 斜率**（log loss 对 log step），窗口
      [200, 24000]（全段）与 [16000, 24000]（末窗），与 U1 的 [200, 12000] 同方法可比；
  (c) 同一套口径在 **U1 的 10k 日志**上的值。
- **必须写明的判读（编排方指定）**：**总 CE 口径在本任务上恒真、无区分度**——U1 四臂
  在末窗 [6000,10000] 的总 CE 斜率只有 **−0.00036 ~ −0.00055 /1k 步**（相对下降
  0.85–1.00%），按合同字面在 10k 步就已「收敛」；而同一窗口的**答案行 CE** 斜率是
  **−0.027 ~ −0.032 /1k 步**（相对下降 6.8–8.0%），远未收敛。⇒ 采信**答案行**口径，
  因为**准确率只由答案行决定**（U1 自称「未收敛」用的是 log-log 口径，与合同字面的
  总 CE 口径矛盾，本实验如实记录这一矛盾并按答案行口径判门禁）。

### ② 主判据（容量轴是否有效）

- **主腿 = `K=8`（= 训练同档）**。判据：**收敛后** `acc(S128) ≥ acc(S16) + 3pp` **且**
  两条臂的 Wilson 95% CI **不重叠** ⇒ **容量轴有效**（U1 的「不成立」是训练伪影）；
  否则 ⇒ **该尺度容量确实不是约束**（U1 结论加固；按 SCHEMA §19，只能表述为
  「该任务/该尺度上不划算」，**不得**写成「容量不可能」）。
- **四个 K 档全部报出、逐档判读、不作事后挑选**（K=4/8/16/32）。若主腿不过而**高压档
  （K≥16）**过，另记一句「容量轴仅在需求接近容量时可见」，**不改变主腿的否证**。
- 方差界（`docs/methodology.md`）：Δ < 0.014 不可排序；本判据线用 3pp + CI 不重叠。

### ③ 对照与稳健性（强制）

1. **毁源对照臂（强制）**：每格跑 `corrupt_span(0, 2K)`。任何格子若毁源后
   Wilson CI 下界 > 4×chance（= 0.0625）⇒ **该格判读作废**。
2. **训练侧重跑散度 ≥1 臂（强制）**：`S16_rep` 与 `S16` 逐字段相同（同 seed 重跑）。
   报出（i）两跑在**同步骤**上的 loss / 答案行 CE 差（0/2k/…/24k 全轨迹），
   （ii）最终模型在 `K=8` 上的准确率差与 CI 关系。
   - **预登记的解读规则**（不是新判据）：若 `S16` 与 `S16_rep` 在 `K=8` 上 CI **不重叠**
     ⇒ 直接记「**训练侧散度 ≥ 本尺度判据线（3pp）**，本尺度不可分辨」，②的「成立」结论
     降级为「不可复现 ⇒ 待定」；若 CI 重叠且 |Δ| < 3pp ⇒ 训练侧散度不足以解释主判据。
3. **活性量每 200 步落盘（强制）**：`state_fro` / `beta_mean` / `write_rel` / `read_share`
   （`train/<arm>/train_log.jsonl` 的 `attn_carry` 块，共 121 行/臂）。
   训练结束再跑 `carry_probe` 反事实与 `read_mass`。
4. **不重复造轮子**：**不重训**无通道基线（ticket 35 `2618` 已实测无通道 ≈ chance），
   本实验对照 = **chance 线 + 毁源臂 + 局部先验**（三者都对同一读数施压）。
5. **单点不得外推**（SCHEMA §17.11）：每个 K 档都是直接测点；不拟合、不外推。

## 6. 既有做法（prior art，SCHEMA §18）

> **检索条件声明**：本环境**联网检索不可用**（未注册任何 web / `web_search` / `source_check`
> 工具；与 ticket 36/37 各 knowledge run 同因）。下列全部为 **`记忆·未核`**，
> **只用于设计方向，不作为判据**（SCHEMA §18/§21(c)）。定量条目的完整盘点见
> `archive/wiki-legacy/axes/M-carrier/PRIOR_ART_CAPACITY.md`（ticket 37-K7，本文的直接依据）。

1. **谁做过**
   - **MQAR / Zoology**（Arora et al.，约 2023）：多查询关联回忆合成诊断任务；据此刻画
     「准确率 vs 状态大小 / 层数」曲线。`记忆·未核`
   - **Mamba / Mamba-2 / RWKV / RetNet / GLA 的 state-size 消融**：把 `d_state` 当旋钮扫。
     `记忆·未核`
   - **DeltaNet / Gated DeltaNet / DeltaProduct**（约 2024–2025）：残差写 `S←S+β(v−Sk)kᵀ`，
     报告在 MQAR 一类上优于 Mamba-2。`记忆·未核`
   - **理论侧**：「可存储关联数 ~ 状态维度」（把 `S=Σvkᵀ` 看成秩受 `d_state` 限制的关联表）。
     **函数形式（线性/次线性）与拐点位置我不确定，不写数字。** `记忆·未核`
2. **为什么这么设计**：状态成为瓶颈时需要一个**不靠语言先验**的探针把瓶颈量出来，
   而瓶颈的边界被反复描述为「**状态容量 ÷ 需回忆信息量**」的比值 ⇒ 所以业界把它画成
   **二维**（容量 × 难度）曲线，而不是一个点。
3. **它的实测结果**：一致观测是「需回忆的关联数上升 ⇒ 单状态模型准确率明显下降、
   softmax 注意力几乎不掉」；「状态维度增大 ⇒ 可回忆信息量上升」的方向一致，但
   **线性还是次线性不确定**。**不确定**：公开工作是否控制**局部先验**、是否有**同配置
   重跑**来界定训练侧散度、是否在 13M 级验证过。`记忆·未核`
4. **我们的增量在哪（⇒ §21 判 **(b) 做实验****）**
   - **尺度**：13M（业界曲线多在 100M–1B 级）；
   - **任务**：局部先验抗性受控（窗口内无符号 ⇒ 局部先验退化到 chance，SCHEMA §19）；
   - **单因素受控**：只改状态宽度、**注意力逐位不动**（业界扫 state size 时通常整模型一起变）；
   - **本实验独有的增量**：**先把「收敛」证成门禁，再判容量**——业界曲线大多只报
     「某个 token 预算下的点」；本实验给出「同配置 24k 步 + 同 seed 重跑臂」两个
     界定训练侧散度的读数，从而能区分「容量不是约束」与「训练预算不够」。
   - **我们不声称**任何「首创」，也不复现业界结论当自己的判据。
5. **若可检索应查的关键词**：`MQAR Zoology associative recall state size curve`、
   `DeltaNet Gated DeltaNet state dimension ablation recall`、`Mamba-2 state size MQAR`、
   `linear attention memory capacity scaling law recall`、`associative memory capacity
   Hopfield delta rule orthogonal keys`、`state size recall saturation plateau`、
   `training budget confound capacity ablation`.

## 8. 成本（唯一预算数字 + 砍什么）

`gpu_wall_budget: 115 min`（**编排方批准的 3 臂 × 24k 方案**；
契约原估 50 min，实测步时推翻，见下）。

| 项 | 实测/预算 |
|---|---|
| 冒烟 20 步 × 3 臂 | ≈1 min |
| 单臂步时 | **95–98 ms/步**（600 步实测：`dh16` 64.89 s、`dh128` 67.28 s；U1 记录 89 ms/步） |
| 单臂 24k 步 | **≈38 min**（契约原估 25 min/臂——**低估约 1.5×**） |
| 3 臂训练 | **≈114 min**（`S16` + `S128` + `S16_rep`） |
| 评测电池（纯推理） | ≈1–2 min（3 臂 × 4 档 × 2 主/毁源 × 40 批） |
| 峰值显存 | 预算 ≤5GB **净**；U1 同配方实测 2.24–2.38 GB |

**外部占用披露（影响步时，不是我们的进程）**：冒烟期间 `nvidia-smi` 显示
**外部 `llama-server` 占 10,912 MiB、GPU util 91%**（另有外部 `python3 mpl_run` 客户端）。
本实验的步时读数是在此**争用**下测得的；U1 记录的 89 ms/步是无此争用的读数 ⇒
「95–98 vs 89 ms/步」的差**可能来自争用**，如实并列。

**砍什么（SCHEMA §17.7 + 编排方指令）**：预算不够时的顺序是
**砍 `dh=64` 档（已砍）> 砍评测批数 > 把重跑臂降到 12k**；
**不砍** `K=8` 与 `K=32` 两个端档、**不砍**毁源对照臂、**不砍**判据 ①②③ 三线。
中途若 wall clock 明显恶化（外部占用再涨）⇒ **先报数再决定**，不自行削判据。

## 10. 失败决策树（测量 → 实现 → 规模 → 设计）

1. **测量**：`S16`/`S128` 在 `K=8` 不显著高于 chance ⇒ 先查窗口是否生效
   （`window_mask` 活性量）、查询-key 距离分布、局部先验读数；先修设置再判。
2. **实现**：某臂 `read_share`/`β_mean`/`state_fro` 任一恒为 0 ⇒ 跑变异验证（`mutate.py`）
   排除死开关与半接线。
3. **收敛门禁未过**：答案行 CE 末窗斜率 |·| ≥ 0.01/1k 且相对下降 ≥1% ⇒
   **本实验不作容量结论**，只报曲线与三套斜率（契约 ① 的明文要求）。
4. **规模/结论**：收敛后仍 `Δ < 3pp` 或 CI 重叠 ⇒ 记「该任务/该尺度上容量不是约束」
   （SCHEMA §19：**不得**表述为「机制不可能」）。
5. **设计**：某格毁源后不掉（CI 下界 > 4×chance）⇒ 该格判读作废。
6. **归因**：`S16` vs `S16_rep` 在 `K=8` 上 CI 不重叠 ⇒ 先归因**训练侧散度**
   （§4③.2 的预登记规则），② 的结论降级为「待定」。

## 14. 契约 V2 逐字抄录（来源 `.scratch/37-gaps/issues/01-gaps.md`）

> ## 契约 V2：容量轴在「收敛后」是否有效（训练，2 臂 × 24k）
>
> - 目录：`axes/1-time/1.1.4.1-explicit-memory/experiments/2620-capacity-converged/`
> - 动机：U1 的容量曲线不成立，但其四臂**一万步均未收敛**（斜率 −0.065~−0.051）⇒ 必须先在收敛后重判。
> - 干预（唯一变量 = 状态维度）：固定 K=8，`--carry-state-dim` ∈ {16, 128}（若预算允许再加 64），
>   训练 **24k 步**（2× U1），其余逐字段一致（seed=0、同任务同窗口）。
> - **判据（预登记）**：
>   1. **收敛前提**：两臂都必须给出「同方法末窗 loss 斜率」并证明已接近平台（斜率绝对值 < 0.01/1k 步，
>      或 loss 相对下降 < 1%）；**未收敛则本实验不作容量结论**，只报曲线；
>   2. **主判据**：收敛后大状态臂准确率 **≥ 小状态臂 + 3pp 且 95% CI 不重叠** ⇒ 容量轴有效
>      （U1 的「不成立」是训练伪影）；否则 ⇒ 该尺度容量确实不是约束（结论加固）；
>   3. 毁源对照臂必做；活性量（状态浮点、读出占比）每 200 步落盘；训练侧重跑散度 ≥1 臂。
> - 成本：2 臂 × ≈25 min ≈ 50 min。用**既有** `--carry-state-dim`，**不需要改共享文件**（降低冲突面）。

**与契约的两处显式偏离（均经编排方批准）**：

1. **臂数 2 → 3**：加 `S16_rep` 重跑臂以满足判据 ③（训练侧散度 ≥1 臂）；预算是 3 臂 × 24k。
2. **判据 ① 的口径**：契约字面的「loss 斜率 < 0.01/1k」在本任务上**恒真**（总 CE 在 10k 步
   就已 −0.0004 /1k）⇒ 按编排方裁决，门禁改用 **`synth_answer_ce`（答案行 CE）** 的
   末窗线性斜率；总 CE 与 log-log 斜率**照报但不作门禁**（详见 §4①）。
