## 1. 命题

**ticket 40 的 Y1（ENG1 四臂阶梯，2623）在 6k 快照上给出三条读数：GQA 省 8.748% 参数
而测不到质量代价、carry 的增益只出现在距离越界处、窗口被 carry 接住。这三条各有一个
未决的替代解释。** 一句话可证伪的形式：*把每个替代解释都配一个对照臂量一遍，三条读数
里哪一条能站住、哪一条被替代解释吃掉。*

三个补点：

1. **①「GQA 省参数不伤质量」是不是「参数少」造成的？**（GQA 少 8.748% 参数 ⇒ Y1 的
   结论只证明「多出的那 8.75% 参数在本题上没换来质量」，**不等于**「等参数下 GQA 不劣」。）
2. **② 分布内腿的读数是不是被 Q=K 的排除法伪影污染的？**（2623 的 Q=8 多查询任务，
   末块的 pair 是**唯一没被前面问过**的那一对 ⇒ 可由排除法白拿，实测末块四臂全 100%。）
3. **③ carry 的 +15.5pp 是快照假象还是随训练保持？**（6k 是单一预算点；carry 在更长
   预算下是否仍占优，未测。）

## 2. 单因素声明（口径）

- **基底**：本仓 stock dense decoder-only trunk（13.5M：d256 × 12 层 × 8 头 × mlp6 × T256，
  tied 读出 + 顺序残差），`DepthARModel(dense=True, topology="sequential")`。
- **三点各自单因素，且都只改一个字段**：

  | 点 | 唯一变量 | 对照 |
  |---|---|---|
  | ① | `mlp_mult`（6 → 5） | 两个 MHA 点（`stock` 13,536,768 / `mha_mlp5` 11,960,832）夹住 GQA（12,352,512） |
  | ② | **评测口径**（Q=8 → Q=7，即 K=8 时的 Q=K → Q=K−1） | 同一批检查点的 Q=8 读数 + 其逐查询块分解 |
  | ③ | **步数**（6000 → 10000） | 每对臂内 flags 逐字段相同，只差步数 |

- **②是评测口径变更，不是训练配方变更**（见 §4c）：四臂仍是 2623 的 Q=8 训练检查点。
  「单因素」在这里的含义 = **同一批权重、只改评测任务的 Q**。
- **③的两对用同一相对刻度**（§17.16）：`gqa`/`gqa_10k` 与 `gqa_carry`/`gqa_carry_10k`
  的步数都是 6000 → 10000（比 1.6667），且每对内部 flags/mlp_mult 逐字段相同。

## 3. 干预定义（必须写清，因为它是「实现」而非「标签」）

- **①的干预 = 容量补偿**：把 MHA 的 MLP 宽度从 `6·d` 收到 `5·d`（`--mlp-mult 5`），
  使 MHA 的参数量落**低于** GQA，与 `stock` 一起构成夹住 GQA 的**容量括号**。
  **这不是逐位等参数臂**（见 §4b）：现有 CLI 只有整数 `--mlp-mult`，
  要用 MHA 精确命中 12,352,512 需要 MLP 隐宽 = 1343.63（非整数）⇒ 逐位等参数在本引擎的
  现有开关注册表里**做不到**。① 因此读作「**容量斜率 + 插值残差**」。
- **②的干预 = 任务构造**：把多查询布局的查询数从 Q=K=8 改成 Q=K−1=7
  （`tools/evalkit/longrange_tasks.py::assoc_recall_multi_batch` 的既有参数，**不改工具**）。
  Q=K 时末块问的是**唯一没被前面问过**的那一对（`points.unique_unqueried_last_block`
  可从 batch 直接核验：Q=8 全 True、Q=7 全 False），排除法伪影条件由构造消除。
- **③的干预 = token 预算**：`--steps 10000`（81.9M token）对 `--steps 6000`（49.0M token），
  其余（数据生成器、bs32、lr、优化器、seed 0）逐字段相同。
- 三点都**不改引擎代码**（本线不写 `pathlm/`）。

## 4. 判据线（**逐字**抄录 Z2 契约，一字未改）

> ## Z2 · Y1 的三个补点（≈40–60 min GPU）
> - 目录：`axes/M-carrier/M1-carrier-type/experiments/2624-composable-followups-13m/`
> - 三个补点（各自单因素，可分批）：
>   ① **GQA 的 §15 等参数对照**（GQA 参数少 8.748% ⇒ 需一个等参数对照臂来分离「头共享」与「参数少」）；
>   ② **无泄漏 Q=7 任务**（上轮多查末块有 Q=K 消除泄漏，被排除；重建无泄漏版本重测分布内腿）；
>   ③ **carry 双臂 12k 复跑**（6k 是快照；carry 的增益是否随训练保持）。
> - 判据：每点按 §17.17 给**分量分解**（对基准质量 + 对目标量）；毁源对照臂；活性量；同相对刻度（§17.16）。

### 4a. 执行时的操作性定义（不改判据，只把口径落定）

- **分母与方差带**：准确率差用 **pp**，方差带 **1.4pp**（`docs/methodology.md`）；bpc 用
  **0.014**。Wilson 95% CI 与 `two_proportion` 的差值 CI 逐列报。
- **基准恒为 `stock`**（SCHEMA §15/§17.14）；① 的「基准」另有一个显式定义：
  **插值到 GQA 参数量处的 MHA**（口径已写死在 `run.py` 的 `interp_at_target`，且**禁外推**）。
- **每条腿两列（§17.17 分量分解）**：
  - **对基准质量的增量** = 分布内腿（**② 的无泄漏 Q=7**）与 clean bpc（非退化锚，见 §5）；
  - **对目标量的增量** = 判决腿（单查询 assoc-mqar，被问 pair 的距离 241–255）。
- **毁源对照臂**（每点每条腿都跑）：把源 KV 段 `[0, 2K)` 换成同分布新随机符号；任一腿
  毁源后 CI 下界 > 4×chance ⇒ 该读数作废。
- **活性量**：KV 头形状（`kv_heads`）/ carry（`attn_carry`）/ 窗口（`window_mask`）
  每 200 步落盘（来自各臂训练日志，本线只读不写）。
- **收敛门禁（§17.15）**：落在答案行 CE（`synth_answer_ce`）的末窗斜率上；6k 臂取末 1/4
  （4500→5999），10k 臂取末 1/4（7500→9999）；聚合 loss 与任务 loss 两套并报。

### 4b. 落定一：① 用「容量括号 + 插值」，不做逐位等参数臂（**主 Agent 裁决**）

**事实（执行前实测）**：GQA = 12,352,512，stock(MHA) = 13,536,768。要把 MHA 的参数量补到
GQA 处，唯一可用的位置就是 MLP 宽度；而现有开关只有整数 `--mlp-mult`
（隐宽 = `mlp_mult·d`，每步 256 ⇒ 每层 131,328 参数、全模型 1,575,936）：
`mlp_mult=5` ⇒ 11,960,832（比 GQA 少 3.2%），精确命中需要隐宽 1343.63 ⇒ **不可能**。

**三个候选实现**：(A1) 新加 `--mlp-hidden` 引擎开关（可行，需改 6 个块类 + 代码锁 +
单测 + 变异，CPU ≈30 min）；(A2) 用既有 `--readout-wide-shared 765` 把 MHA 补到
**恰好** 12,352,512（391,680 个名义参数落在冗余共享读出上 ⇒ 引入读出混杂）；
(A3) 容量括号 + 插值。

**裁决 = (A3)**：它直接回答「GQA 的差距是不是『参数少』造成的」，且**不动引擎、不引入
读出混杂**。执行要求（逐条落地）：
1. 新增 1 臂 `mha_mlp5`（MHA + `mlp_mult=5`），与既有 `stock` 作容量括号，报 **MHA 的容量斜率**；
2. 把 GQA 与**插值到 12.35M 的 MHA** 比 ⇒ 结论写成「若 MHA 两点已平 ⇒『参数少』不是解释；
   若斜率显著 ⇒ 差距可部分归因参数」；
3. **必须显式声明**「这不是逐位等参数臂」，并给出三点参数量与 bpc 的小表（`results.json::
   p1_gqa_capacity_bracket`）。
4. **归因声明（SCHEMA §15 例外）**：GQA 是**剪枝类**（减参数），§15 的例外条款要求拿
   「同 FLOPs 的稀疏/稠密对照」比；本点给的是**容量括号 + 插值**，是 §15 精神下的替代实现
   ——**不得**被读成逐位等参数对照。

### 4c. 落定二：③ 用 10k × {gqa, gqa_carry}；② 只评测不重训（**主 Agent 裁决**）

**事实（步时先测；卡被两个 llama-server 占 19.9GB/100% util）**：

| 臂 | 实测步时（200 步 × bs32 × T256） | 峰值显存 |
|---|---|---|
| `gqa` | 99.0 ms/step | 1538.1 MB |
| `gqa_carry` | 177.0 ms/step | 1809.5 MB |
| `gqa_carry_window` | 171.0 ms/step | 2193.6 MB |
| `mha_mlp5` | 93.0 ms/step | 1497.2 MB |

⇒ 契约字面的 **12k × 2 臂 = (99+177)×12000 ≈ 55 min**，加 ①（9.3 min）与 ②（2.5 min）
会超「≈40–60 min」。另：Z2 文字说「carry 双臂」，而 2623 的 `analysis.md §9` 写的是
「12k 重跑 `gqa_carry`/`gqa_carry_window` 两臂」——那两臂**都带 carry**，只能量 window 步，
**答不了「carry 增益是否保持」**（需要无 carry 的对照臂）。

**裁决**：
1. **③ = 10k × {`gqa`, `gqa_carry`}**（(99+177)×10000 = 46 min），即 **1.667× 于 6k 基线**
   的第二个预算点；臂对解析为「(无 carry, 有 carry)」而非「两个 carry 臂」；
2. **总 GPU 预算放宽到 ≈70 min**（含三臂训练 55.3 min + 评测 ~4 min）；
3. 报告首段声明「**10k 快照口径、1.667× 于 6k、与 12k 不可比**」，并附答案行 CE 末窗斜率
   （§17.15）与实测步时；
4. **② 只做评测**：Q=7 上重测 2623 的四个 Q=8 检查点（≈2.5 min），并**并报 Q=8 的逐查询块
   分解**以直接暴露末块伪影；**不**重训 4 臂（4×8 min 放不下，且问题可由「评测 + 逐块分解」
   回答）。报告里写明这一取舍。

## 6. 成本（§8 的唯一预算数字 + 砍什么）

```
gpu_wall_budget: 70 min   # 主 Agent 裁决（§4c）；含三臂训练 55.3 min + 评测 ~4 min + 步时先测
```

- **先测步时再定预算**（§17.8/§20.3）：见 §4c 表（实测）。
- **实测峰值显存**：逐臂训练 1.49–2.19 GB **< 5GB net 礼貌线**；评测 ≤0.6 GB。跑前/跑后
  `nvidia-smi` 空闲读数记入 `train_followups.runlog`。
- **预算不够时砍什么**（§17.7）：砍步数（**成对同步砍**，不砍单臂）> 砍评测批数/距离档；
  **不砍判据线**（三点各自的对照、毁源、活性量、分量分解都必须出）。
- **§20.1 锁记账**：`train_followups.sh` **按臂**取/放锁、臂间 65s 窗口（不整程独占）；
  本波同卡另有其它 agent 的 GPU 线在**同一锁**上串行（等待时长、holder PID 全部记入
  `train_followups.runlog`）——本条线实测等锁 19 min（19:39–19:58，见 runlog）。

## 8. 失败决策树（测量 → 实现 → 规模 → 设计）

1. **测量**：重评 2623 的四臂与 2623 的 `results.json` 不一致 ⇒ 先查 `run.py` 的接线
   （种子/批数/掩码/距离桶），**不得**动模型、不得改判据。
2. **实现**：`mha_mlp5` 的参数量 ≠ 11,960,832（`mlp_mult` 没生效）或 `gqa_10k` 的步数 ≠
   10000（跑成 6k）⇒ 跑变异验证排除死开关；活性量逐 200 步非零才认读数。
3. **规模**：三个读数都落在方差带内 ⇒ 如实报「本尺度/本任务上不可分辨」，
   **不得**表述为「机制不可能」（SCHEMA §19）。
4. **设计**：① 的 MHA 斜率方向与 GQA 残差冲突（例如 MHA 随参数**变差**）⇒ 检查括号
   是否非退化（§17.16）并如实记录；② 若 Q=7 的末块仍有抬升 ⇒ 报「伪影被削弱但未清零」
   的可能机制与未区分项，**不得**把 Q=7 直接叫「完全无泄漏」；③ 若 10k 的 carry 增量
   与 6k 差异不可排序 ⇒ 报「保持」，并附答案行 CE 斜率说明两点都未收敛/已收敛。

| 2 | **MQAR / 关联回忆**：Zoology（Arora 等 2023，`memory`/`assoc recall` 合成任务，记忆·未核）；JetMoE / Ba et al. 的「MQAR」命名 | 用合成任务把「记忆容量」与「语言先验」解耦 | 记忆类机制在 MQAR 上优势明显；任务构造对结果影响极大 | 本线把**任务构造漏洞**（Q=K 末块排除法）做成可核验谓词并去掉它（Q=K−1），给出**无伪影的分布内读数** |
| 3 | **预算轴（matched-step vs 快照）**：Chinchilla 式「同一配方的更长预算点」（记忆·未核） | 短训练的增益可能是收敛加速而非最终质量（本仓 §16 已把这条写成纪律） | 本仓实例：读出重参数化 12k −0.0812 → 24k −0.0463（缩 43%） | 本线把 carry 的 +15.5pp 放到 6k→10k 的预算轴上复核 |
| 4 | **消融的置换/构造伪影**：induction head 的「同键重复查询」构造（记忆·未核） | 多查询构造里若允许重复查询，模型可用「抄上一个答案」绕开记忆 | 本仓 2623 已记 Q=K 的排除法伪影 | 同理，本线把「唯一未被问过」做成谓词 + 逐块分解 |

**若可检索应查**：`GQA vs MHA parameter-matched ablation`、`multi-query associative recall
leakage`、`snapshot gains convergence compensation small scale`。

## scope 声明

本研究**只做单轴单格实验**，基底恒为 stock 对照；本实验是 M1 载体类型格内 Y1 阶梯的
**三点补测**（容量括号 / 无泄漏评测口径 / 预算轴第二点）。**不做组合实验**；
`attn_sparse_k` / `attn_linear` 与组合的交互仍受引擎互斥限制，是显式留白、不是遗漏。
评测期 KV 量化（2621/W3 的压缩面）不在本线 scope。`deps` 只记录已知耦合方向
（M1 载体类型 ← ENG1 引擎可组合性；与 2623 的读数耦合；与 2618 的判决腿仪器耦合）。
