# 2685 判读 · int4 档与 carry 族的 int8 档叠到同一条「每位置部署字节 → 质量」图上

## 0 人话摘要（先人话，数据在后）

**原本要回答什么**：里程碑验收第 4 条要「量化档同图」，上一轮只叠了 **int8**，且只能给纯窗族叠
——显式状态族（下面简称 **carry**）上不了同一张图，因为量化前向只支持 stock 块，`CarryChannelBlock`
不在它的支持面内。于是两处缺口：**int4 档完全没有**；**carry 只能以 fp16 档出现在图上**，
而它的对手纯窗族用的是自己最省的档。这一不对称对 carry 不利，但「给 carry 同档以后它还占不占优」
从未测过。

**实际怎样**：给 `CarryChannelBlock` 写了一条**只做推理期**的量化前向（KV 精度 × 状态精度两轴分开），
47 个格全部在盘 checkpoint 上实测，0 训练 token。四件结果：

1. **新前向是忠实复刻（这是本轮的承重墙）**：13 条臂在「两轴都不量化」时与 `2681` 落盘值
   **13/13 逐位相等（1e-6）**，9 条纯窗臂的 int8 格 **9/9 相等**。所以下面每个数与 `2680`/`2681` 同一台仪器。
2. **carry 的 int8 全档近无损**：只换 KV **+0.000021**（CI95 [−0.000001, 0.000043]）、再换状态
   **−0.000001**（CI95 [−0.000011, 0.000010]）⇒ 字节从 393,216 砍到 **208,896（×0.53125）**，
   bpc 1.527595 → **1.527616**。与它**同字节**的纯窗最强点 `win32@int8`（208,896 B / 1.595857）
   差 **0.068241**（41 σ_cell、4.9 × 0.014 带）⇒ **不被支配**，且这是真正的同字节直接点比。
3. **carry 的 int4 全档也近无损，且同字节上把纯窗甩开**：KV 与状态都在 int4 档时 **+0.004864**
   （CI95 [0.004457, 0.005274]，带内、2.9 σ_cell），字节 **110,592 = fp16 的 28.125%**，bpc 1.532460。
   与它同字节的 `win32@int4`（110,592 B / 1.625945）差 **0.093485**（56 σ_cell、6.7 × 0.014 带）⇒ 也不被支配。
4. **int4 档在纯窗族上不是近无损——这条必须讲清楚**：k ≤ 24 的五条臂只涨 **+0.0050 ~ +0.0064**（带内），
   但 k = 32 / 60 / 64 / 128 涨 **+0.0301 / +0.0371 / +0.0359 / +0.0198**，**越 0.014 带**
   （18.1 / 22.3 / 21.6 / 11.9 σ_cell）。机制上说得通：int4 的误差按**被量化的 KV 值数**累积，
   窗口越长每位置要存的值越多，代价越大。**所以「int4 近无损」只在短窗/状态这条路上成立，不能外推。**

**为什么「carry 的 int8 档不被支配」这件事本身有点意外**：它不是被同字节的纯窗点威胁，而是被
**自己的 int4 档**追近——carry@int4（110,592 B / 1.532460）比 carry@int8（208,896 B / 1.527616）
只差 **0.004844**（带内、2.9 σ_cell）⇒ 按判据⑤ 不被支配（差 < 0.014），但在人话上要说清：
**这张图上 carry 的价签可以再左移一半字节而质量「不可分辨」**，int8 档因此不是 carry 的下包络前沿点，
它是同一机制在更贵字节上的不可分辨复本。

**没解决的**：真实长上下文（T ≫ 256）没测；carry 的健康读数（RECALL 轴）本轮没重跑（它仍是 `2684` 的网格，
0 训练 token，不随量化档变）；carry 臂多 264,296 参数的混杂仍在；除 `win16` / `carry16` 各两 seed 外都是 n=1。

## 3 它把什么说清楚了、没说什么

- **说清楚了**：在这张 47 点网格上，carry 点的**两个量化档（int8 全档 208,896 B、int4 全档 110,592 B）
  都不被任何不更多字节的点按一个可排序带支配**；两个同字节对手（纯窗 k=32 的 int8 / int4 档）分别差
  0.068241 与 0.093485，方向一致、量级远超 0.014 带。carry 的三档量化在本尺度近无损（≤ 0.004864）。
- **说清楚了（反向）**：int4 档**不是**免费的通用档：纯窗族 k ≥ 32 的 int4 代价 +0.0198 ~ +0.0371 越带。
  因此「int4 近无损」这个说法只在 KV 值数少的点（短窗、以及 carry 那条只有 16 个位置的窗口 + 状态）上成立。
- **没说**：T ≫ 256（状态是固定成本，摊平优势未测）；召回轴随量化档的变化（本轮 0 个召回读数，
  `2684` 的召回网格仍基于 fp16 checkpoint）；参数的混杂（carry 臂多 264,296 参数）；多 seed
  （除 `win16` 两 seed、`carry16` 两 seed 外均 n=1）；除块标尺 G=32 之外的标尺方案。
- **不能说**：不能说「carry 在任意字节水平占优」——`win128@int8`（835,584 B / 1.513366）在**更多字节**上
  比 carry 更好，这是正常的「花钱买质量」，两者不在同一预算点，不构成支配关系。
