## 0. 人话摘要（先看这段）

**上一轮说了什么**：用「单共享槽」版显式记忆（一个 8192-float 的小本子被 12 层**共用**、
只从输入层抄写一次、不遗忘）时，它**不值**——把它放在「每位置占多少内存 vs 质量」图上，
它被一个只宽 1 格、内存更少的纯注意力窗口严格支配（`2638`）。当时的免责声明是：
「机制没坏，是我们被迫用了退化实现（逐层独立状态 + 内容写门 + 遗忘被引擎开销砍掉了）」。

**这一轮干了什么**：引擎侧把那个退化实现补回来了（E1：**每层一个自己的小本子**、
「该不该写」由**这一层此刻看到的内容**决定、可选遗忘 γ），且默认行为逐位不变
（独立复核 PASS）。我们用**同一个配方**（窗口 16、13M、enwik8、12k 步、同评测口径）
重训了完整机制，重新画同一张图。

**结果一句话**：**翻转了——完整机制不值钱的结论是错的那一个：完整机制在等内存点上
明确便宜了同预算纯窗口，且把「丢掉长上下文」的损失补回了 80%。**

**为什么这么说（数字 + 参照系）**：普通注意力看最近 16 个位置时 bpc = 1.6281
（bpc = 每字符比特数，越低越好），全量注意力 = 1.5027，中间 **0.1254** 就是「丢掉长上下文」
的全部代价。

| 做法 | 每位置等效内存（k_eff，等效窗口位置数） | bpc | 补回了多少差距 |
|---|---|---|---|
| 窗口 16（无记忆） | 16.00 | 1.6281 | 0% |
| 窗口 17 | 17.00 | 1.6241 | 3.2% |
| **单共享槽记忆（上轮的退化版，`2638`）** | **17.33** | **1.6250** | **2.5%** |
| 窗口 24 | 24.00 | 1.5999 | 22.5% |
| **窗口 32（等内存对照点）** | **32.00** | **1.5958** | **25.8%** |
| **完整机制（逐层状态 + 内容写门，γ=1）** | **32.00** | **1.5276** | **80.1%** |
| 完整机制 + 遗忘 γ=0.99 | 32.00 | 1.5855 | 33.9% |
| 窗口 128 | 128.00 | 1.5133 | 91.5% |
| 全量注意力（stock 全因果） | 256.00 | 1.5027 | 100% |

- **等内存直接对撞**（同一 393,216 字节：窗口 16 + 12×8192 floats 状态 ↔ 窗口 32）：
  完整机制 **1.5276** vs 窗口 32 **1.5958** ⇒ **好 0.0682 bpc**。这个差是
  本格自测噪声带（0.00166）的 **41 倍**、跨格参考带（0.014）的 **4.9 倍**；
  换一个评测窗口序（`window_seed=7`）重算是 **+0.0719**（同号、同量级）。
- **人话量级**：完整机制的质量**大约等于把窗口开到 111 位置的纯注意力**（在 win32→win128
  的窗口族读数上线性内插：0.0682/0.0825 = 0.83 ⇒ 32 + 0.83×96 ≈ 111；只作量级参照、
  不外推），而它只花「窗口 32」的内存。
- **它现在在质量-代价下包络上**（`win16 … win32 → **carrypl16** → win128 → full`），
  把等字节的 `win32` 从包络上挤了下去（支配关系：`win32` 被 `carrypl16`/`carrypl16d` 支配）。
- **完备度本身值多少**：同一格子里，从退化单共享槽（1.6250）换到完整机制（1.5276）
  = **0.0974 bpc**（chunk 匹配对照口径 0.1013）——比「窗口 16 → 窗口 24」的收益（0.0283）
  还大 3.4 倍。⇒ 上一轮判「机制不值」**确实是那一个退化实现的产物**。
- **遗忘 γ 这条腿没帮上忙**：γ=0.99 时状态每步乘 0.99，256 步后只剩 7.6% ⇒ 1.5855
  （仍比等字节窗口 32 好 0.0103，但比 γ=1 差 0.0579）。**只测了一个 γ**，不能据此说
  「衰减无用」；只说明「在 T=256 上 γ=0.99 忘得太狠」（下一步最小实验见 §7）。
- **还不稳的地方（详见 §7）**：单一规模/数据/训练长度；**只有一个种子**；
  E1 把「逐层独立状态」与「写门取自本层当前 hidden」绑在一个开关里 ⇒ **无法区分**增益
  来自哪一半；等参数量对照未做（完备臂多 264,296 参数 = +1.95%）；可检索性（召回）轴未测。

## 3. 噪声带与敏感性（口径并列，不自选）

- **本格自测 σ_cell**（同配置换种子极差，2 样本 ⇒ 描述量）：`win16` = 0.000983、
  `carry16` = **0.001661**；跨格参考带 = **0.014**（`docs/methodology.md:19`）。
  主判据量级 **0.0682**：41× σ_cell、4.9× 0.014 带 ⇒ **两带读法都判「越带」**（与上轮相反，
  上轮的 0.000875 是带内）。
- **实现细节敏感性（chunk）**：单共享槽同配置 `chunk=64`（1.624979）vs `chunk=256`（1.628940）
  ⇒ **0.003961**（≈2.4 σ_cell）。⇒ 「改一个只影响浮点累加顺序的实现细节」在本格会造成
  ~0.004 bpc 的差异（量级 > σ_cell）。该量级**远小于**主判据的 0.0682；且「完备 vs 退化」的
  对照在两个 chunk 口径下都给 0.0974 / 0.1013（差 0.004，与 chunk 敏感性一致）。
- **摊平口径敏感性（`sensitivity` 块，非判据）**：状态是固定成本（与 T 无关），若把 T=256 的
  状态成本摊到每位置（`k_eff_amort = (kv + state/T)/12288`），完备臂 `k_eff_amort = 16.06`、
  同点纯窗口插值 1.62786 ⇒ `+0.100265`（**同号、更大**）。⇒ 主结论不依赖「状态怎么折价」这个口径。
  （真实长上下文 T≫256 的前沿点未测 ⇒ §7。）
- **状态精度脚注**：横轴把状态按 **fp16（2 B/元素）** 计（196,608 B）。引擎内部一律升 fp32
  （`_carry_cast`）⇒ 若按 fp32 记，`k_eff = 48`、同预算纯窗口点更低（win48 ≈ 1.582，
  在 win32→win128 上线性内插）⇒ **完备机制仍占优（1.528 < 1.582），结论方向不变**。

## 5. 失败归因（机制 vs 实现）：上一轮的否证**改判为「该实现」**

上一轮（`2638`）判「被否证」时的归因链是：①设计/实现（主因，单共享槽 = 退化实现）；
②结构（状态容量 / 快照收敛）；③非 innovation 失败。本轮把①消掉后：

| 归因 | 上轮读数 | 本轮读数 | 判定 |
|---|---|---|---|
| ① 实现退化（单共享槽、h₀ 写、无门控/遗忘） | 2.5% gap-closing、被 win17 支配 | 完整机制 **80.1%**、等字节点上 +0.0682 bpc、在包络上 | **确认是主因**：退化实现把收益压掉了 **0.0974 bpc**（32×） |
| ② 结构（状态容量 / 12k 快照收敛） | 未分离 | 仍**未分离**：完整臂状态 12× 大、参数量 +1.95%、单一训练长度 | **未决**（进 gaps：等参数对照、第二规模点、更长训练） |
| ③ innovation 本身失败 | 上轮已排除 | 仍排除；本轮是**正证据** | **不成立** |
| ④ 交付维度（milestone 两轴） | 只交付 bpc 轴 | 仍只交付 bpc 轴（召回轴未测） | **仍未达标**（进 gaps） |

**唯一变量声明（诚实记账）**：完备臂相对 `carry16` 的差别 = E1 的**一个开关**
（`carry_per_layer`），而 E1 把「每层独立状态」与「写门/键/值取自本层当前 hidden」
**绑在同一个开关里**（见 `E1-CARRYCHANNEL.md` §1 的显式实现决策）⇒ 本实验**不能**把
0.0974 bpc 归因到两者中哪一个；这是本轮最大的归因缺口（下一步最小实验见 §7）。
**但该 0.0974 bpc 是等参数对照**：`carry16_s0` 与 `carrypl16_s0` 的参数量完全相同
（均为 13,801,064，见 `results.json.checkpoints[*].n_params`）⇒ 「退化实现压掉了收益」
这个结论**不能被「完备臂参数更多」解释**（等参数缺口只影响「完备臂 vs 纯窗口」那一半）。
`carry_chunk` 差异（64→256）已按 §3 量化（0.004 量级），且给出 chunk 匹配对照
（`c16c256_s0`），不构成混淆。

## 6. 六个必答问题

1. **它是干什么的**：让模型把看过的东西写进一个**固定大小的本子**（与序列长度无关），
   需要时按当前问题读出来 ⇒ 在不扩大注意力窗口的前提下，把窗口外的信息带到现在，
   让长上下文账单有界。
2. **相对普通 decoder-only transformer 改了什么**：主干不动；在每层的注意力输出后加一路
   记忆读出 `a ← a + γ_ℓ ⊙ mem_t`，其中 `mem_t = S_t q_t`，状态按 delta 规则写
   `S ← S + β(v − S k̂)k̂ᵀ`（本轮完整版：**每层一个自己的 S**，写门 `β=σ(W_β h+b)`、
   键/值都取**该层当前 hidden**，可选 `S ← γS + write`）。改动量级：**+264,296 参数
   （+1.95%）**；状态 **12×8192 = 98,304 floats**（fp16 = 每位置等效 196,608 B = 16 个窗口位置）。
3. **为什么要改**：注意力窗口外信息直接丢失；把「过去」压进一个与 T 无关的载体是
   长上下文账单有界的唯一途径。痛点是**质量-内存权衡**，不是「有没有通道」。
4. **怎么测的**：同一配方（enwik8、13M、T=256、12k 步、bs32、seed 0）训 3 个新臂
   （完备 γ=1 / 完备 γ=0.99 / 单共享槽 chunk 匹配对照），与 10 个复用臂落在同一张
   (每位置等效 KV 字节, clean bpc) 图上；口径 = 同 96×16 窗口序、同 token 数、matched-step；
   **禁墙钟**（墙钟只作成本记录）。
5. **测出来多少**：见 §0 的表——等字节点上 **1.5276 vs 1.5958（好 0.0682 bpc）**，
   把「窗口 16 → 全量」的差距从 2.5%（退化版）补到 **80.1%**；代价与窗口 32 相同、
   比全量小 8 倍。人话：**质量约等于窗口 111 的纯注意力，内存只花窗口 32 的**。
6. **结论与下一步**：**完整机制被支持**（在等内存点上改善前沿）；下一步 = 拆开
   「逐层状态 vs 写入源」、等参数对照、第二规模点/更长训练、召回轴与量化点同图、
   γ 扫（见 §7 与 `project.yaml` 的 `gaps`）。
