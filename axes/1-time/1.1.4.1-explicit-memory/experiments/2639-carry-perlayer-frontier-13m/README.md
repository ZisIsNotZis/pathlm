# 2639 · 完整机制（逐层独立状态 + 内容写门 + 可选衰减 γ）的质量-代价前沿 · 13M · dense

> 契约来源：`.scratch/62-axis1-time/TICKET.md` §3 序 1 的**第二轮**（同一 WP：研究项 `1.1.4.1` 的 WP1）。
> 动机：WP1 第一轮（实验 `2638`）判「显式状态点被同预算纯窗口严格支配」，但其否证归因是
> **「单共享槽 = 被引擎/墙钟开销逼出的退化实现，完整机制未测」**（`55-review` M-05/M-06；
> `2638-carry-frontier-13m/analysis.md` §5、`project.yaml` failure_analysis ①②③）。引擎侧 E1
> （`.scratch/67-engine-changes/E1-CARRYCHANNEL.md`，独立复核 PASS `REVIEW-E1.md`）已给出
> **逐层独立状态 + 内容相关写入门 + 可选衰减 γ**——本实验用该完整机制**重测同一前沿**，
> 回答「是机制不成立，还是那一个退化实现不成立」。
> 入口：`train_arms.sh`（训练完备机制臂，按臂取/放 §20 GPU 锁）→ `run.py`（纯推理评测 + 前沿）；
> 预登记契约 = 本文件；配置 `config.json`；原始结果 `results.json`；判读 `analysis.md`；
> 权重清单 `MODEL.md`（权重 `*.pt` 不入库）。

## 1. 命题（一句话、可证伪）

**把「完整」显式记忆机制（逐层独立状态 + 内容相关写入门 + 可选衰减 γ）放进
「每位置等效 KV 字节 vs clean bpc」的前沿后，它是否相对同代价的纯窗口改善前沿？**

可证伪形式：*在 13M / enwik8 / T=256 / 12k 步、与 2638 逐字段同配方下，把完备机制臂
（`carrypl16`，窗口 16 + delta 逐层状态）落在同一张 (每位置等效 KV 字节, clean bpc) 图上：
其总字节 = 393,216 B，与 `win32` **逐字节相等** ⇒ 与 `win32` 是**同一个预算点**的直接对撞。
若 `carrypl16` 的 bpc **不低于** `win32`，则「显式状态在同等内存下优于纯窗口」这一信息右移的
自身目的**在完整机制下也被否证**（该预算点不值得付）；若低于且在噪声带外，则该预算点上
存在前沿改善，否则不可排序。*

**这一轮的特殊地位**：`carrypl16` 相对 2638 的 `carry16`，差别**只在机制完备度**
（单共享槽 → 逐层独立状态；写门由 h₀ 派生 → 由当前层 hidden 派生；γ 可选），
配方、数据、步数、评测口径**逐字段相同** ⇒ 「退化实现」这一借口在本轮被**消掉**。

## 2. 单因素声明

- **基底**：stock dense decoder-only 全因果主干（tied 读出 + 无 final LayerNorm + 顺序残差），
  13.54M（d256 × 12 层 × 8 头 × mlp6 × T256）——即 2610 全因果主干、2634 四臂、2638 十臂的同一规格。
- **唯一变量（相对 2638）**：carry 通道的**完备度开关**：
  `carry_per_layer`（逐层独立状态 + 写门取自当前层 hidden）与 `carry_decay`（可选衰减 γ）。
  其余（窗口 16、anchors 0、delta 规则、12k 步、bs32、lr1e-3、AdamW+cosine、`--exit-mode uniform`、
  同 token 预算 98.3M、同评测口径）**逐字段不动**。
- **`carry_chunk` 的显式记账（预登记于执行前）**：E1 的文档把 `carry_chunk` 定义为
  **实现细节（「只改浮点累加顺序，不改语义」）**，并由独立复核在 fp64 下把分块实装与逐位置
  参考实现对拍到 <1e-12（`REVIEW-E1.md` §3）。逐层模式下按层循环、`chunk=64` 时每步 12×4=48 次
  chunk 调用，300/600 步冒烟实测 **350 ms/step**；`chunk=256`（T=256 ⇒ 每层单块）实测
  **153 ms/step**（2.3×）⇒ 本实验**新臂一律用 `chunk=256`**，并把 `chunk` 作为**已知的、
  只影响浮点累加顺序**的实现差异记账（不复用臂仍是 `chunk=64`；本实验另训一个
  `chunk=256` 的**单共享槽对照臂**，既给出「完备 vs 退化」的 chunk 匹配对照，也充当
  chunk 敏感性的探针：同配置 c64/c256 的差 = chunk 数值路径的量级）。
- **相对纯窗口臂的唯一变量**：有无 carry 通道（+264,296 参数，写投影**层间共用**——
  E1 已声明的范围内决策，见 `REVIEW-E1.md` §6 O4；逐层差异只来自各层输入表征与逐层读出增益）。
- **引擎能力面**：E1 为**附加式、默认关闭**（`carry_per_layer=False` / `carry_decay=1.0`），
  默认路径逐位不变（独立复核 PASS）；本实验只**打开**该开关，不改共享 `pathlm/**`。

## 3. 干预定义

- `full`：不传注意力掩码（`is_causal=True`）⇒ stock 因果路径（复用 2610 `trunk.pt`）。
- `win{K}`：`keep[i,j] = (j ≤ i) ∧ ((i−j) < K)`（`train_anchors=0`）；训练与评测共用
  `pathlm.depth_ar.window_anchor_keep_mask(T, K, 0)`。
- `carry16`（**上轮退化版**，复用 2634）：窗口 16 + delta 通道，**单共享槽**（`shared_slots=true`：
  12 层共用 8192 floats、只从 h₀ 写、无衰减）。
- **`carrypl16`（本轮完备版，本实验训练）**：窗口 16 + delta 通道，`carry_per_layer=True`
  （每层自己的 8192-float 状态，写门 β/键/值取自**该层当前 hidden**），`carry_decay=1.0`。
- **`carrypl16d`（本轮完备版 + 衰减，本实验训练，预算允许时）**：同 `carrypl16`，
  `carry_decay=0.99`（`S ← 0.99·S + write`，GLA 式遗忘）。

**本实验不改任何共享文件**（`pathlm/**`、`train_depth_ar.py`、`tools/**`）：训练用目录内
`train_pl.py`（把 `DepthARConfig` 换成带 E1 缺省的子类，见该文件 docstring），评测只调
`tools/evalkit/retention.masked_bpc`。

## 4. 判据线（预登记，写下后不得改）

> 判据③ 的量与判定线：`pl_minus_win32 = bpc(win32_s0) − bpc(carrypl16)`（正 = carrypl 更好，
> 与 `SCHEMA.md` §17.3「Δ = 对照 − 实验，正 = 改善」一致）⇒ `>0` 改善 / `≈0` 不可排序 / **`<0` 被支配**。
> **注意（本轮与 2638 的结构差异）**：`carrypl16` 的每位置等效字节 = 196,608（窗口 16）+ 196,608
> （12 层 × 8192 floats fp16）= **393,216 B**，与 `win32_s0` **逐字节相等** ⇒ 主判据是**等预算点的
> 直接点比**，不依赖任何插值。

| # | 判据 | 判定线 | 该涨/该跌/必须不变 |
|---|---|---|---|
| ① | **前提（口径一致）**：全部臂走同一份 96×16 窗口序（`window_seed=2`），token 数相同；窗口掩码可见对数等于声明值 | 逐臂断言通过（`selfchecks[*].ok`、`nondegenerate`） | 必须不变 |
| ② | **代价（该跌）**：完备机制点的每位置等效 KV 字节 `k_eff` 远小于 full | `k_eff(carrypl16) = 32.0` vs `k_eff(full) = 256` | 该跌 |
| ③ | **主判据（等预算点比）**：`pl_minus_win32 = bpc(win32_s0) − bpc(carrypl16)`（**正 = carrypl 更好**） | `> 0`（噪声带外）⇒ 前沿改善（机制翻转）；`≈ 0`（带内）⇒ 不可排序；`< 0` ⇒ **被等预算纯窗口支配** | 该涨 |
| ④ | **必要条件（该涨）**：完备机制相对同窗无通道（`win16_s0`）的 clean bpc 增益 Δbpc > 0（配对）；且通道活着（`carry_liveness.alive`、评测期读/写活性） | Δbpc > 0 且 live 断言通过 | 该涨 |
| ⑤ | **机制 vs 实现（本轮的核心问题）**：判「完整机制翻转」= 判据③ 的 `pl_minus_win32 ≥ +σ` 且判据④ 成立；否则**维持被否证**，且 `failure_analysis` 必须据此区分「机制本身」与「该实现」 | 见 ③ 的带 | — |
| ⑥ | **禁外推**：结论只适用于 enwik8 / T=256 / 13M / 12k 步快照；纯窗口曲线的线性插值只用于**定位**、不外推 | — | — |

**并列报出的辅助读数（不构成判据，只报数）**：
- `pl_minus_win17 = bpc(win17_s0) − bpc(carrypl16)`：与上一轮的胜者比——carrypl 花 **1.88×** 字节
  是否至少赢过 `win17`（208,896 B）。
- `pl_minus_interp_window`：纯窗口曲线在 `k_eff = 32` 处的线性插值值（= `win32` 点本身，
  因 32 是网格点；如无边界点则 `null`，不外推）。
- `marginal_efficiency`：`Δbpc / Δbytes`（相对同窗无通道）——完备机制每字节边际质量。
- `pl_vs_shared`：`bpc(carry16_s0) − bpc(carrypl16)`：**完备度本身**（消掉退化实现）值多少 bpc。

### 4a. 操作性定义

- **clean bpc**：`masked_bpc(model, eval_arr, keep_mask, n_batches=96, batch_size=16,
  window_seed=2)`；`full` 臂 `keep_mask=None`。token 数 = 96×16×255 = 391,680。
- **每位置等效 KV 字节**：`kv_bytes(k) = n_layers × 2 × d_model × bytes_per_elem × k`
  （fp16 ⇒ `bytes_per_elem=2`），`= 12288 × k` 字节；
  **完备机制状态另加 `n_layers × n_heads × dh × dh × 2` = 12 × 8192 × 2 = 196,608 字节**
  （逐层独立状态；单共享槽只加 16,384 字节）。横轴等价量 **`k_eff` = 总字节 / 12288**。
- **噪声带（双列，按 C1 裁决，不自选）**：① 本格自测带 σ_cell ＝ **0.00166**（2634 同配置换种子
  的极差，`2638` 沿用）为主判；② 跨格 0.014 bpc 带（限配对 Δ、≥5 窗口）为参考。**两带并列报出**。
  若预算允许跑 `carrypl16_s1`，另报**本轮臂内**换种子极差作为同口径补充（不替换 σ_cell）。
- **状态精度假设（显式记账，同 2638）**：横轴把 carry 状态按 fp16（2 B/元素）计。
  引擎内部一律升 fp32 ⇒ 若按 fp32 记，`k_eff` 更大、结论方向不变且更强。
- **敏感性读数（**不构成判据**，执行前登记 `2026-10-14T07:43+08:00`）**：状态的固定成本与 T 无关，
  而窗口的 KV 随 T 线性增长。冻结口径（62-F2 / 2638，也是本实验的判据口径）把状态整块计作
  等效字节（「同 T 下同内存 footprint」）。**另一口径**把 T=256 的固定状态成本摊到每位置上
  （`k_eff_amort = (kv + state/T)/12288`）⇒ 同一臂的 k_eff 更小。两口径回答**不同问题**
  （「同上下文长度下同内存预算」vs「长上下文下状态被摊平后的边际优势」），因此 `run.py` 落一个
  `sensitivity` 块**并列报出摊平口径的读数**；**判据一律用冻结口径**。真实长上下文（T≫256）下的
  前沿点**未测**（见 `gaps`）。
- **gap-closing 比例** `r = Δc / Δg`：`Δc = bpc(win16_s0) − bpc(carrypl16)`，
  `Δg = bpc(win16_s0) − bpc(full)`。

## 6. 成本（§8 的唯一预算数字 + 砍什么）

`gpu_wall_budget: 85 min`（3 个新臂训练 + 评测 + 对账）。
**步时实测（预登记，300/600 步冒烟，chunk=256）**：153 ms/step ⇒ 12k 步 ≈ **30.6 min/臂**
（逐层臂）；单共享槽 chunk=256 约 1/12 的扫描量 ⇒ ≈ 8–10 min。已用冒烟墙钟：
`chunk=64` 350 ms/step、`chunk=256` 153 ms/step（差值 = 每步 36 次 chunk 调用开销）。
**砍的优先级（预登记）**：① **不砍** `carrypl16_s0`、不砍 12k 步（保住与 2638/2634 的同口径）；
② 其次保 `c16c256_s0`（9 min，兼顾 chunk 敏感性与 chunk 匹配的退化对照）；
③ `carrypl16d_s0`（γ）最后，若其不能在 **08:30 前启动**则**不跑**，列入 `gaps`；
④ 仍不足时**砍补充臂，不砍步数、不砍判据线、不砍复用臂与 full 锚**；
⑤ 硬时间盒 2.5h（本轮整体）：到点即停，按已落盘证据出结论、未跑臂如实列进 `gaps`。

## 9. 失败决策树（测量 → 实现 → 规模 → 设计）

1. **测量**：口径不一致（token 数/窗口序不同）⇒ 先修仪器再判。
2. **实现**：`carry_liveness.alive=False` 或逐层状态未生效（各层状态相同 / 只连了 h₀ 扫描）
   ⇒ 先排除死开关（E1 已给单测抓力，本实验仍要落盘逐层活性）。
3. **规模**：`carrypl16` 相对 `win16` 的 Δbpc 落在噪声带内 ⇒ 只读作「该尺度不划算」，
   **不得**写成「机制不可能」（SCHEMA §19）；下一步 = 更大步数/规模、更长训练、更宽状态。
4. **设计**：`carrypl16` 的 bpc 更好但字节代价更大 ⇒ 用边际效率（Δbpc / Δ字节）判断，
   而非只看 bpc；等价地看等预算点对撞（判据③）。
