# controls · 2617 合成长程任务电池

本目录说明本实验的**对照臂与变异验证**（SCHEMA §13：每个对照臂必须写明「输入是什么
分布 / 要预测什么 / 部署中对应什么」）。对照臂读数落在 `../results.json`
（`controls` / `mutation` / `tasks[*].local_prior` 块）。

## 对照臂（同一任务定义、同一输入分布、同一位置集）

| 臂 | 输入分布 | 要预测什么 | 部署中对应什么 | 实测（本批） |
|---|---|---|---|---|
| `chance` | 任务分布，无信息 | 答案集（64 符号）均匀猜 | 「没有任何长程能力」的地板 | 1/64 = 0.015625 |
| `local_prior`（k=8） | 只看最近 8 个 token | 仅凭局部证据猜答案（最长后缀最近邻 + 词频回退） | 「只用最近上下文」的强对手 | 四任务 0.010–0.022（≈chance） |
| `corrupt_span`（源对照臂） | 同任务，但把复制/induction 的**源片段**换成全新随机符号（其余逐位不变） | 同答案 | 「源信息不存在时仍答对」的伪命中检测 | copy 0.133→0.012，induction 0.059→0.016 |
| `shuffle_answers`（变异验证） | 同任务、同 token，答案标签整体随机置换 | 同答案 | 「准确率是否与上下文无关」的变异验证 | var_recall(d=64) 0.008→0.016（回 chance） |

## 为什么必须有 `corrupt_span`

复制 / induction 的读数（0.133 / 0.059）在没有源对照时**无法区分**两件事：

1. 模型真的把远处的源片段搬来用了（真长程）；
2. 模型命中的是位置规律 / 局部先验 / 任务构造漏洞（伪命中）。

把源片段毁掉后准确率**掉回 chance**（0.012 / 0.016），才能把读数归因到源信息。
这是 SCHEMA §12「有利数字的对账义务」与 §13「对照臂可比性」的直接落地——
**任何支持假设的数字都要有一个能被证伪的对照**。

## 哪些前提由单元测试钉住

`tests/test_longrange_tasks.py`（14 个可失败单测）：

- 四个任务的布局 / 答案恒等式 / 距离字段逐点对；
- 局部先验抗性（四任务 < ceiling）；
- 局部先验**是真预测器**（窗口内能答对）——否则判据 (a) 是假的；
- `shuffle_answers` 后准确率回 chance；
- `corrupt_span` 只改指定 span、查询行/答案/距离逐位不变；
- 掩码可见性复用 `retention.recent_keep_mask` 且掩码真的被注意力读到；
- 生成器种子可复现。
