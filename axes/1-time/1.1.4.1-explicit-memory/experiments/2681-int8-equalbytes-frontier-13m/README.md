# 2681 · 补齐 int8 档与显式状态「同字节」的那一格（纯窗 k=60 / k=64）· 13M

> 归属：`axes/1-time/1.1.4.1-explicit-memory`（研究项 1.1.4.1「显式记忆槽 / 线性状态」的 WP1）。

> 预登记契约 = 本文件；配置 `config.json`；原始读数 `results.json`；判读 `analysis.md`；权重清单 `MODEL.md`。
> 复用仪器（只读导入，不复制实现）：`../2632` 之外的 `axes/5-quant/5.1-kv-quant/experiments/2632-kv-block-scale/block_arms.py`
> 的块标尺量化前向、`axes/1-time/1.1.1-hard-window/experiments/2662-hard-window-anchor-13m/realtext_probe.py`
> 的配对 bootstrap；臂表与判据常数照抄 `../2680-quant-overlay-frontier-13m` 并显式列出补了哪两格。

## 1 命题（一句话、可证伪）

`2680` 把 KV 的 int8 + 块标尺档叠进「每位置部署字节 vs clean bpc」以后，显式状态点
（`carrypl16_s0`：393,216 B、1.527595）**在本网格上不被支配**，但那一轮自己报出的「决定性那一格」
——int8 下 k≈60（391,680 B，与 393,216 B 同字节水平）——的纯窗臂**不在盘上**，所以只能说
「本网格上不被支配」，不能说「同字节仍占优」。

**可证伪形式**：*训两条纯窗臂 `win60` / `win64`（stock 规格，0 新代码），对各自 checkpoint 只做
评测期的 fp16 与 int8 + 块标尺（G=32）两档，把新点并入 `2680` 的同一张（部署字节, clean bpc）网格*。
若网格里存在 `total_bytes ≤ 393,216` 且 `bpc ≤ 1.527595 − 0.014` 的点 ⇒ **显式状态点被支配**
（那一点的每位置字节不高于显式状态，质量还低出一个可排序带）。否则 ⇒ 在**含 k=60 的网格**上不被支配，
结论强度就从「本网格」升到「含该格的网格」。

## 2 单因素声明

- **基底**：与 `2634` / `2638` / `2639` / `2680` 逐字段同一 stock dense 规格（d256 × 12 层 × 8 头 × mlp6 × T256，13.54M，
  tied 读出 + 无 final LayerNorm + 顺序残差），同一数据（enwik8 前 90M 字符训练 / 末 10M 字符评测）、
  12k 步、bs32、lr 1e-3、AdamW+cosine、`--exit-mode uniform`、`--train-anchors 0`、seed 0、98.3M token。
- **唯一变量 = 训练期可见窗口 K ∈ {60, 64}**（`train_anchors=0`），以及随之而来的**评测期数值格式**
  （fp16 / int8 块标尺 G=32）两档。掩码、数据、窗口序、token 预算不变。
- **两臂的来源是「同一根轴上的两个新格」，不是第二个机制**：k 本来就是本格的主轴（`2638` 已训 k=17/18/24/32/128），
  本实验只在其上补 k=60 与 k=64。量化是 `5.1` 已判定的既有档位，本次只把它叠到这两条新臂上。
- **本实验不改任何共享文件**（`pathlm/**`、`train_depth_ar.py`、`tools/**`）：只用既有开关
  `--train-window/--train-anchors/--carry-write`，评测只调既有函数。

## 3 为什么补 k=60（`gaps` 写的是「训 win64」，本实验改成 win60 + win64 两格）

字节账（`config.json::cost_axis`，与 `2639`/`2680` 同一口径）：
每位置每键的 KV 值数 = `n_layers × 2 × d_model` = 6144；fp16 = 2 B/值 ⇒ 12,288 B/键；
int8 + 块标尺 G=32 = 1 B/值 + 2 B/32 值 ⇒ 6528 B/键。

| k | fp16 B/位置 | int8 B/位置 | 相对 carry 的 393,216 B |
|---|---|---|---|
| 32（已在盘） | 393,216 | 208,896 | 少 184,320 |
| **60（本实验）** | 737,280 | **391,680** | **少 1,536（同字节水平，且严格更少）** |
| **64（本实验）** | 786,432 | **417,792** | 多 24,576 |
| 128（已在盘） | 1,572,864 | 835,584 | 多 442,368 |

判据④ 的支配集是 `total_bytes ≤ 393,216` ⇒ 只有 k ≤ 60 的 int8 点能进这个集合，**`win64@int8` 进不去**
（417,792 > 393,216）。所以 `gaps` 里「训 win64」这一句按字面做，**填不上**决定性那一格；
k=60 才是 int8 下仍落在 carry 字节水平以内的最大窗口。两条臂都训、都报：
k=60 决定判据④，k=64 报「多花 6.25% 字节的纯窗能到哪」这一方向读数。预算因此从 1 臂变 2 臂（仍是同一条轴上的补点）。

## 5 判据线（**预登记：写下后不得改**）

| # | 判据 | 判定线 | 该涨 / 该跌 / 必须不变 |
|---|---|---|---|
| ① | **仪器复现门** | 11 条复用臂的 fp16 clean bpc 与 `../2680-quant-overlay-frontier-13m/results.json::rows.win32_s0.bpc_fp16`（其余 10 条同名字段）**1e-6 内相等**；不等 ⇒ 本实验作废（仪器 / 权重 / 窗口序变了），判据线不改 | **必须不变** |
| ② | **字节账（该跌）** | 两条新臂 `bytes_int8 / bytes_fp16 == 0.53125` 逐臂精确相等；`win60` int8 = 391,680、`win64` int8 = 417,792，与解析值逐位对账 | 该跌 |
| ③ | **质量腿（该不跌）** | 逐新臂 `Δ_int8 = bpc(int8) − bpc(fp16)`，按窗口配对 bootstrap（10k 次，seed 2681）给 95% CI；`|Δ_int8| < 0.014` ⇒ **「本尺度无质量增量」**（禁写「无信号」）；`≥ 0.014` ⇒ 量化在这条臂上有可排序代价，如实报 | 该不跌 |
| ④ | **主判（支配）** | 在 13 臂合并网格上重算：显式状态点被支配 ⇔ 存在 `total_bytes ≤ 393,216` 且 `bpc ≤ 1.527595 − 0.014 = 1.513595` 的点。若最小差距 < 0.014 ⇒ 「同一字节水平不可排序」 | 二选一如实报 |
| ⑤ | **决定性格必须报** | 报出 `win60@int8`（391,680 B）这格的 bpc、它与 carry 的差、它与 0.014 带的关系；**禁止在两点之间插值造点**；结论必须写明「含 k=60/k=64 的网格」这一限定 | 必须报 |
| ⑥ | **往返一致** | `win60` / `win64` 的 fp16 点也必须作为纯窗前沿点入网格（不能只入量化档）；两档逐臂并存 | 必须报 |
| ⑦ | **口径** | 横轴 = 每位置缓存字节（值 + 块标尺，`2639`/`2680` 同一口径）；配对 Δ 用 0.014 bpc 带、不跨量纲借用；`n=1` 的臂（除 `win16` 两 seed 与 `carry16` 两 seed）只能标「临时」；**墙钟不进判据** | 口径 |

## 6 否证条件

- 判据① 不成立 ⇒ 本实验作废（同一 checkpoint、同一窗口序、同一函数应逐位复现 2680 的 fp16 读数）。
- 判据④ 若 `win60@int8` 的 bpc ≤ 1.513595 ⇒ **显式状态在 393,216 B 这一预算点上被同字节纯窗口支配**，
  这是允许的判决，且必须直接写进 `project.yaml::conclusion`，不得降级成「不可排序」。
- 若判据④ 两向都不到 0.014 ⇒ 只许写「本网格上不可排序」，不许写成「carry 占优」。

## 7 成本

- 训练 2 臂 × 12k 步 ≈ 2 × 9 min GPU（`2638` 同配方实测）；评测 13 臂 × 2 档 ≈ 1 min GPU（`2680` 实测 0.81 min / 11 臂）。
- 预算上界：**39 min GPU**，一次一臂地取 `/tmp/pathlm_gpu.lock`（`harness/SCHEMA.md` §20；臂间 ≥60s）。
  `local_lm_research` 优先：开跑前确认没有别人的 GPU 作业在跑。
