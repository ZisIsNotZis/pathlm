# controls — 2623 · 长 T 第三点 T=1024

本实验的两臂在**同一脚本、同一配方、同一数据流**下自包含双跑，不复用历史 run 作判据臂
（SCHEMA §9）。两臂关系：

| 臂 | 角色 | 对照关系 |
|---|---|---|
| `full-1024` | T=1024 的基线 | `win512-1024` 的对照（同 T、同 token、同步数、同 batch、同 seed） |
| `win512-1024` | **第三点**（窗口 = T/2，相对刻度 50%） | 相对 `full-1024` 的 Δ |

## §13 每个对照臂的三要素

- **输入分布**：char 级 enwik8（前 90M train / 末 10M eval），与主臂**同一份**；
- **要预测什么**：下一个字符（因果移位 CE）；
- **部署对应**：训练期可见窗口的开关（关闭 = 全上下文；512 = 位置式窗口注意力）。

## 与前两点（X3）的关系

`T=256` / `T=512` 两点由 ticket 39-X3（`2622-longT-512`，bs32）给出，本实验**跨 run 引用**其
`results.json`（`criteria.criterion_1_quality.native_operating_point`），**不重跑、不改数字**。
三点同相对刻度 50%（128@256 / 256@512 / 512@1024）。

⚠️ **口径差异（必须随三点表一起说）**：本实验因 T=1024 的窗口臂在 **bs32 与 bs16 下训练均 OOM**
（卡上背景进程常驻 ~18.3 GiB），两臂统一用 **bs8**（12000 步）；X3 四臂用 **bs32**
（T=256/512 分别 12000/6000 步）。token 预算三点一致（98.3M），
但 batch 不同 ⇒ 三点**只作并列描述，禁止外推**（§17.11/§17.16）。

## 口径

- **native 工作点**（判据①主口径）：窗口臂在**自身训练掩码**下评测；full 臂在全因果下评测。
- **release 口径**（并列）：窗口臂在**全可见**下评测（问「窗口训练出的权重还认不认远端信息」）。
- **方差界**：Δ < 0.014 不可排序（`harness/methodology.md §2`）。

## 已知限制（不在本实验预算内）

- n=1 单 seed，无重跑散度。
- 合成长程腿在 enwik8 训练的权重上是分布外任务 ⇒ 预期全在 chance，**不能区分窗口与 full**
  （真正的对照需在合成任务上训练两臂，属 A9/Y3 实验）。
- 本机背景进程（两个 `llama-server`）常驻占 ~19.5 GiB ⇒ 全卡 free ~4.6 GiB；§20.2 的
  「跑前后余量 ≥8GB」在本机无法满足，如实记账（见 `results.json::criteria.criterion_3_memory`）。
