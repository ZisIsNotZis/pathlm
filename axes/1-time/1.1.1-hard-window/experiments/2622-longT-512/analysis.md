## 人话摘要（先看这段）

**我们在测一件很朴素的事**：把训练序列长度从 256 拉到 512，然后让模型「只看最近一半」
（窗口 128@256、窗口 256@512，两者的窗口都占序列的一半），看看**质量掉不掉、算力省不省、
显存够不够**。这是 A6 那条线第一次把序列拉到 256 以上——之前那个「注意力占比 14.3%@256 →
72.7%@4096」只是**公式外推**，从没实测过。

三句话结论：

1. **质量：窗口几乎没有代价，而且越长的 T 代价越小。** 窗口相对全注意力在 native 口径下
   亏 **0.0148 bpc @T=256**（略超本项目的 0.014 噪声界），到 **T=512 缩到 0.0087 bpc**
   （落在噪声界内）。两次都是「窗口略亏」，方向一致；按判据的**带宽分类**，T=256 记「亏」、
   T=512 记「不亏」⇒ 按契约第 ④ 条，**T=512 记为「窗口算子交叉点出现的首个观测点」**
   （单点，不外推）。⚠️ 注意它只是「噪声界内测不出差别」，**不是**「窗口更好」。
2. **算力：理论上省，实测没兑现。** 窗口把注意力 MACs 砍掉 **50%**（每 token 只看 w 而非 T 个键），
   整模型每 token 的理论等效 FLOPs 分别降 **7.1%@128/256、12.5%@256/512**——因为本实装走的是
   **稠密 bool 掩码**（照样算满 T×T 再遮掉），所以**墙钟没有节省**：两轮实测的
   `ms(窗口)/ms(full)` 一次 1.09、一次 0.91，方向相反 ⇒ 只能说「≈1，本批测不出方向」。
   注意力子层占整模型步时的**实测**占比从 **5.4%@256 涨到 10.8%@512**（涨约 2×），
   与公式 14.3%→25.0% 的**趋势**一致（都翻倍），但绝对值更低（公式只数 MACs，
   不含 embedding/读出/优化器等本开销）。
3. **显存：没越界。** T=512 窗口臂训练峰值 torch **2.70 GiB**（`nvidia-smi` 子进程 3.29 GB），
   全部分布在 5GB net 预算内。T=512 的位置表只加 **+65,536 参数 = +0.94%**。

**一句话给决策**：在 6.96M / 98.3M token 这个尺度上，**位置式窗口注意力在 T=512 上已经进入
「与全注意力不可区分」的质量带**，代价是**本实装不省墙钟**（要省墙钟得换成真正的带状/稀疏核）。
这是单点观测，**不外推**到「更大的 T 也成立」。

## 1. 命题与四臂（§2 单因素）

stock decoder-only transformer（`train_depth_ar.py --dense`，d=256/L=8/h=8/mlp=4，bs32，
seed0，lr1e-3，`exit-mode uniform`）。**唯一变量 = 训练期可见窗口**（关闭 vs T/2）；
两个 T 点之间只改 `seq_len`（位置表随之线性变大，是必然后果）。

| 臂 | T | 窗口 w | w/T | 步数 | token | 参数 | 训练墙钟 | 峰值(torch) |
|---|---|---|---|---|---|---|---|---|
| `full-256` | 256 | 0（全因果） | — | 12000 | 98.3M | 6,962,688 | 10.37 min | 0.911 GiB |
| `win128-256` | 256 | 128 | 50% | 12000 | 98.3M | 6,962,688 | 8.35 min | 1.161 GiB |
| `full-512` | 512 | 0（全因果） | — | 6000 | 98.3M | 7,028,224 | 4.01 min | 1.697 GiB |
| `win256-512` | 512 | 256 | 50% | 6000 | 98.3M | 7,028,224 | 4.68 min | 2.697 GiB |

- **同 token 预算 98.3M**（与 A6 的 T=256 12k 步同口径）；T=512 因每步 token 翻倍而步数减半。
  四臂 token 预算逐位相等（`reconcile_report.json` 断言）。
- **同相对刻度 50%**（SCHEMA §17.16）：`window128@T=256` 与 `window256@T=512`。
- ⚠️ **「窗口 256@T=256」是退化点**：`window_anchor_keep_mask(256,256,0)` 与精确因果掩码
  **逐位相等**（两臂参数也逐位相等 ⇒ Δbpc≡0）。它是**恒等算子**，不能当第二点——这是本实验
  开跑前发现并上报给主 Agent 的契约缺陷（已立 `SCHEMA §17.16`）。**单测钉住**
  （`tests/test_longT_512.py::test_window256_at_T256_is_identity_and_thus_degenerate`）。

## 2. 判据① 质量：两点（只描述、禁外推）

`Δ = bpc_full − bpc_window`（正 = 窗口更好）；方差界 0.014（`harness/methodology.md §2`）。

| 点 | 口径 | bpc(full) | bpc(window) | **Δ** | 带宽分类 |
|---|---|---|---|---|---|
| T=256 · w=128 | **native**（窗口臂用自身训练掩码） | 1.525389 | 1.540225 | **Δ256(native) = −0.014836** | 亏（\|Δ\|≥0.014） |
| T=512 · w=256 | **native** | 1.574020 | 1.582750 | **Δ512(native) = −0.008730** | 不亏（\|Δ\|<0.014） |
| T=256 · w=128 | release（全可见评测） | 1.525389 | 1.637071 | Δ256(release) = −0.111682 | — |
| T=512 · w=256 | release | 1.574020 | 1.807471 | Δ512(release) = −0.233451 | — |

**判读（两种读法都报，主口径 = 契约的带宽分类，SCHEMA §17.14）**：

- **带宽分类（主口径，契约「同判据」字面）**：T=256 = **亏**，T=512 = **不亏** ⇒ **异号**。
  ⇒ 按判据④，**T=512 记为「窗口算子交叉点出现的首个观测点」**。
- **raw Δ 符号（并列描述）**：两点 Δ 都是**负的**（窗口都略差）⇒ **同号**。
  即「窗口一直略亏，只是 T=512 的幅度收窄到噪声界内」。
- **绝对质量注意**：`full-512`（1.574）比 `full-256`（1.525）**差 0.049**——同 token 预算下
  序列变长、每步覆盖更少窗口，质量本身下降。所以 T=512 的点是「两个都更差的臂相比」。

**证据等级**：**n=1（单 seed，无重跑）**。Δ256=−0.0148 仅**略微**越过 0.014 界，Δ512=−0.0087 在界内
⇒ 两点都落在「排序不可靠」的边缘；本判读只作**描述**，不作趋势外推（§17.11/§17.16）。

**收敛对账（§16，两臂同方法、同 25% 末窗）**：末窗 loss 斜率（nats/1k 步）
`full-256 0.00252 / win128-256 0.00121`、`full-512 0.00769 / win256-512 0.00530`。
两点的窗口臂 loss **都比各自 full 更平**（更接近收敛）⇒ full 两臂**仍在更快下降**，
若延长训练，Δ 可能**朝更负方向走**（即快照口径下的窗口劣势是**下界**而非上界）。
⚠️ 因此「T=512 的 Δ 收窄」是**跨 T 的两点现象**，**不能**解读为「窗口劣势会随训练消失」；
两者是不同的轴（T vs 步数），本实验只描述了 T 轴。

## 3. 判据② 注意力占比：实测 vs 公式（只描述）

`attn_share(T) = 512T/(512T+786432)`（K10 公式；T=512 = **0.2500**）。

| T | 注意力孤岛 fwd+bwd (ms) | 整模型步 (ms) | **实测 占比 = 孤岛/整模型** | 公式值 | 窗口臂实测 ms | `r_time`=w/full |
|---|---|---|---|---|---|---|
| 256 | 1.756 | 32.474 | **5.41%** | 14.29% | 35.242 | 1.0852 |
| 512 | 3.205 | 29.738 | **10.78%** | 25.00% | 27.100 | 0.9113 |

- **趋势**：实测占比从 5.4% → 10.8%（涨 **1.99×**）；公式从 14.3% → 25.0%（涨 **1.75×**）。
  **趋势一致（都是随 T 近似翻倍）**；绝对值的差距来自口径：公式只数 MACs（attention vs
  qkv/proj/MLP），实测的「整模型步时」还含 embedding/读出/优化器/LayerNorm 与内核开销。
- **`r_time` 实测不可判方向**：本批两轮测量方向相反——preflight：`full 28.479 / win256 31.086`
  （**1.09×**，窗口更慢）；eval：`full 29.738 / win256 27.100`（**0.91×**，窗口更快）。
  ⇒ 如实记「**≈1，本批在共享卡的争用噪声下测不出方向**」；**不得**把 0.91× 当作窗口的墙钟收益。
- **共享卡争用声明**：步时测量期间卡上有其他 agent 的任务（load 高），T=256 同一配置两轮实测
  32.5 / 59.5 ms（近 2×）⇒ 上述步时是**争用下的上界**，方向性结论只能靠**孤岛/模型比值**（较稳）。

## 4. 判据③ 显存：未越界

| 臂 | 峰值 torch | 峰值 `nvidia-smi`（子进程） |
|---|---|---|
| full-256 | 0.911 GiB | 1.47 GB |
| win128-256 | 1.161 GiB | 1.72 GB |
| full-512 | 1.697 GiB | 2.29 GB |
| **win256-512** | **2.697 GiB** | **3.29 GB** |

**最大峰值 2.697 GiB < 5 GiB net** ⇒ **未越界**（判据③通过）。窗口掩码**增加**显存
（1.48 → 2.37 GiB，`r_mem` 1.60×），因为它物化 `[B,H,T,T]` 的 bool 掩码（与 A6 top-k 的
「更占显存」同一原因）。

## 5. 代价：双口径（等效 FLOPs + 墙钟）

- **理论（等效 FLOPs）**：窗口每 token 每层只算 `2·w·d` 的注意力 MACs（对 `2·T·d`）⇒
  注意力 MACs 降 **50%**；整模型每 token 理论降 **7.14%**（128@256）/ **12.50%**（256@512）。
  实际保留的因果对占比 **0.7490**（128@256）/ **0.7495**（256@512）——两个同刻度点的
  「可见对占比」也几乎相同（差 0.0005）。
- **实测（墙钟）**：**没有兑现节省**。窗口臂走稠密 `attn_mask`（O(T²) 照算），
  `r_time` ≈1（两轮方向相反）。这与 A6 top-k「理论省、实测涨」是同一类实现事实。
- **KV 缓存**：窗口若做流式解码可只留最近 w 个键（KV −(1−w/T) = **−50%**），
  但**本实装的训练/评测路径是稠密注意力 ⇒ KV 缓存下降 = 0%**（结构性，与 A6 top-k 同款诚实记账）。

## 6. 判据④ 交叉点首观测点

`Δ512(native) = −0.008730 ≥ −0.014` ⇒ **记「T=512 为窗口算子交叉点出现的首个观测点」**。

⚠️ **三条限制必须随结论一起说**：
1. Δ512 仍是**负的**（窗口略差），只是**落在噪声界内**——「测不出差别」≠「更好」；
2. **单点**（T=512），**禁止外推**到更大的 T（判据只描述两点形状）；
3. n=1 单 seed；且 T=512 的 full 臂本身比 T=256 差 0.049（同 token 预算下 T 越长质量越低）。

⇒ 这条腿**不能区分窗口与 full**；它**没有**支持也没有推翻「窗口伤长程」。

**诚实声明（§19 + 主 Agent 裁决第 4 条）**：距离档 >255 是**本次新配置**
（`longrange_tasks.DISTANCES` 常量上限 255），**与既往 255 上限的距离曲线不可直接比较**。
真正能判「窗口是否伤长程」的实验必须在**合成任务上训练**（如同 M1 的 2617/2618），
属**另一格/另一实验**，见 §10。

## 8. 干预活性与稳定性（§10）

- **窗口干预活着**：两窗口臂的 `window_mask_probe` = 掩码开/关同一批输入的最后一层 logits 最大差
  = **0.2340**（win256-512）/ **0.2616**（win128-256）（>0）；`window_mask_liveness` 每 200 步随日志
  落盘，`visible_frac` 0.7495/0.7490（**非 1**）。full 臂 `window_mask = null`（无干预）。
- **仪器自检**：full 两臂的「释放版 vs 显式精确因果掩码」最大 logit 差 = **0.0**（逐位一致，
  仪器等价）；窗口两臂该差 = 16.1 / 18.6（**这是掩码本身的效果，不是仪器不等价**——窗口臂的
  native 前向确实带掩码，两条路径本就不同）。
- **稳定性**：四臂 gnorm 中位 0.43–0.47、max 6.9–7.2，无 NaN，loss 单调下降（见日志）。

## 9. 三道对账（§12）

1. **算术对账**：四臂 token = 步数×bs×T = 98,304,000（逐位相等）；位置表参数增量 = 65,536
   （6,962,688 → 7,028,224）；`visible_frac` 实测 == 闭式 `Σ min(i+1,w)/(T(T+1)/2)`
   （0.749513 == 98432/131328）；占比公式 T=512 == 0.2500。全部脚本化
   （`reconcile_numbers.py`）。
2. **任务对账**：四臂**同数据切分**（enwik8 前 90M/末 10M）、**同评测流**
   （`window_seed=2`、20 批×16）、**同位置集**；native 口径 = 各臂自己的训练掩码，
   release 口径 = 全可见——两个口径都报，不用「假上下文+真目标」式对照（§13）。
3. **口径对账**：matched-token（98.3M）；Δ 用**同点自己的 full** 作基准（§17.14：基准唯一）；
   **算力账**：窗口臂推理算力理论上更低（注意力 MACs −50%）但**实测墙钟无节省**，
   该价签写进结论句（§17.14）。

**跨 run 一致性交叉检查（不是判据，只是 sanity）**：
- 本实验 `full-256` = **1.5254**，与 A6 2614 的同配置 full 基线 **1.5304** 差 0.005
  （<seed 散布 0.0138）⇒ 同分布、量级一致；
- 窗口税随窗口变窄而变大：A9 2615 的 `window32` 税 **+0.0866**（其 native 口径）、
  M3 2616 的 `window192` 税 **−0.0028**（native，`results.json::criteria.criterion_1_quality.tax_bpc_native`）；
  本实验 `window128@T256` 税 **+0.0148**（税 = −Δ）落在两者之间（窗口 128 比 32 宽、比 192 窄）
  ⇒ **方向一致（税随窗口单调下降）**；但三者的模型配方/T 不同（2616 用 d256/L12/mlp6），
  **只作定性交叉参考，不可直接并列**。

**有利数字（「T=512 不亏」）的对账**：它**通过**算术/任务/口径三道，但受 n=1、Δ 仍为负、
以及 T=512 full 本身更差三条限制——故只表述为「**噪声界内测不出窗口的额外代价**」，
不表述为「窗口在长 T 上更好」。

## 10. 失败路径与原因 / 下一步

1. **窗口 256@T=256 恒等（契约缺陷）**：`window256@T=256` 是恒等算子，不能作第二点。
   处置：补 `window128@T=256` 作真第二点（本实验已做），并立 `SCHEMA §17.16`。
2. **墙钟收益未兑现**：窗口走稠密 bool 掩码 ⇒ O(T²) 照算。**这不是实现 bug**，是「掩码 ≠ 稀疏核」
   的算法/实现事实（与 A6 top-k 2.2× 更慢同类）。要拿墙钟收益必须换真正的带状/稀疏内核。
3. **合成腿空结果**：enwik8 训练的权重在分布外合成任务上全在 chance。修法 = 在合成任务上训练
   （另一实验），本实验预算内不做。
4. **步时测量被共享卡争用污染**：同一配置两轮差近 2×。修法 = 独占卡/多次取最小值；本批只能用
   较稳的「孤岛/模型比值」下趋势结论。
5. **未测项（下一步最小实验 + 成本）**：
   - 同**步数**（12k@T=512）口径的重跑，与同 token 口径对照收敛（≈6 min）；
   - 在 **T=1024**（bs 保持 32，峰值估 ~2.9 GiB）补第三个点，看「窗口税是否继续收窄」（≈8 min）；
   - **真正的带状/稀疏注意力内核**下重测 `r_time`，验证理论 12.5% 是否兑现（工程线，非本格）；
   - **在合成长程任务上**训练「窗口 vs full」两臂，回答「窗口是否伤长程」（属 M1 格，≈20 min）。

## 11. 与 A6 / K10 的关系

- **A6 的「T=256 净亏」**（内容 top-k，k=32 Δ=−0.0166）与本实验的**位置式窗口**在 T=256 的
  Δ=−0.0148 **同量级、同方向**（都略亏）；到 T=512 窗口的 Δ 收窄到 −0.0087（带内）。
  **两种稀疏算子（内容选择 / 位置窗口）在本尺度下行为定性一致。**
- **K10 对照**：T=512 的注意力占比 = **25.0%**（本实验按此对照）；T=512 的位置表参数增量
  = **+0.94%**（+65,536）。
- **单因素/scale 声明**：本实验只描述 6.96M / 98.3M token / T∈{256,512} 两点，**不外推**。
