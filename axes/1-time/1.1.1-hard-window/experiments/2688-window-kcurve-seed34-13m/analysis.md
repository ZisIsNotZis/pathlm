# 2688 · 判读：k=128 的窗口税补到 n=5 后**判出来了**（确定越本格带、且确定小于 0.014 跨格带）；k=64 的锚点杠杆仍未判

## 0 人话摘要

- **原本以为会怎样**（契约 `README.md` §1，写下时本轮读数尚未产生）：两条都只差 `sd` 不涨。
  判据② 只要 `sd ≤ 0.005968` 就判 `above_band`；判据③ 只要 `sd ≤ 0.004148` 就判负。
  上一版把这两条不可判归因到「带的量纲」，本轮的实测**再次否掉那个归因**——判据线一格没改，
  只是多补了 seed。
- **实际怎样**：
  - **判据②（k=128 的窗口税，n=5）判出来了**：五个 seed 的税 = 0.012607 / 0.009808 / 0.002762 /
    **0.005849** / **0.010376** bpc，均值 **+0.00828**、`sd` **0.003931**、t 区间（df=4, `t=2.776`）
    **[+0.003400, +0.013161]**。下界 +0.003400 > 冻结带 0.000983 ⇒ **`above_band`**：窗口在 k=128 上
    **确实仍有税**；同时上界 +0.013161 < 0.014 ⇒ 这条税**确定落在跨格 0.014 带以内**。
  - **判据③（k=64 的锚点杠杆，n=4）仍未判**：四个 seed 的价 = −0.007652 / −0.008982 / −0.003166 /
    **+0.000478**，均值 **−0.00483**、`sd` **0.004326**、t 区间 **[−0.011713, +0.002052]** 含 0 ⇒
    `undecidable`（功效式 `n_req = 7`）。
- **为什么会这样**：
  - 判据② 的两个新 seed（0.005849 / 0.010376）落在已有三点的中间偏低处，`sd` 从 0.005073 **降到** 0.003931
    ⇒ 半宽从 0.012604 收到 0.004881，区间下界翻到带以上。**契约的预测成立**。
  - 判据③ 的 seed 3 价是 **+0.000478**（锚点臂比纯窗臂略差），四点的符号不再一致 ⇒ `sd` 从 0.003047 **升到**
    0.004326、越过契约写下的门槛 0.004148，半宽反而变大。**契约的预测不成立**，照实报 `undecidable`，
    没有剔除该 seed（`README.md` §7 预写了这条）。
- **排除了哪些别的解释**：仪器变了（否：复现门 ① 10/10 逐位相同，含 `2686` 的 10 条 checkpoint）、
  掩码/配方错了（否：判据④ 自检全过——四个新臂因果性前缀 `max|Δlogit| = 0.0`、可见对数
  `(64,0)=14368` / `(64,8)=15876` / `(128,0)=24640` 三处一致、参数量 13,536,768 逐位相同、窗口掩码与
  `recent_keep_mask` 逐位相同）、新 seed 训练异常（否：四臂 rc=0，墙钟 504 / 528 / 509 / 460 s，与 `2682` / `2686`
  同档 8–11 min/臂）、挑 seed（否：seed 3 是 `2686` 只跑到 2 之后第一个没跑过的种子，seed 4 是第二个，
  顺序固定、没有从多个里挑）。
- **结论与下一步**：k 曲线上**只剩 k=192 一档不可判**（n=2、需 n≈17 ≈135 min GPU，本格不取得）；
  k=128 的税现在有区间（**存在但 ≤0.0132**），k≤64 三档仍确定越带。判据③ 这条走完 n=4 仍不可判，
  下一档要 n≈7（≈3 个新 seed × 2 臂 = 6 臂 ≈54 min GPU），写进 `project.yaml::gaps`，本轮不做。

## 2 判据②（k=128 的窗口税，n=5）——**判出来了：`above_band`**

| 0 | `win128_s0` | 1.515296 | +0.012607 |
| 1 | `win128_s1` | 1.512497 | +0.009808 |
| 2 | `win128_s2` | 1.505451 | +0.002762 |
| 3 | `win128_s3`（**本轮**） | 1.508538 | **+0.005849** |
| 4 | `win128_s4`（**本轮**） | 1.513065 | **+0.010376** |

- 跨 seed 均值 **+0.008280**，`sd` **0.003931**（n=3 时是 0.005073），t 区间（df=4, 2.776）
  **[+0.003400, +0.013161]**；
- 按 `../2682-window-kcurve-13m/README.md` §5a 的冻结三分类 ⇒ **`above_band`**：区间下界
  +0.003400 > 冻结带 0.000983 ⇒ 税**确定越本格带**；5/5 同向为正；
- 同时上界 +0.013161 **< 0.014 跨格带** ⇒ 这条税**确定落在跨格主判的 0.014 以内**

| 2 | 1.545000 | 1.548166 | −0.003166 |

- 跨 seed 均值 **−0.00483**，`sd` **0.004326**（n=3 时是 0.003047），t 区间（df=3, 3.182）
  **[−0.011713, +0.002052]** ⇒ **含 0 ⇒ `undecidable`**，功效式给 `n_req = 7`；
- 四个 seed 里三个负、一个略正 ⇒ `same_sign = false`。这个 +0.000478 的量级本身就在带（0.000983）以内，
  但它把 `sd` 抬过门槛，于是「补 1 个 seed 即判」在这条上**第二次没成立**；

## 5 这一轮同时把「带的量纲」这个归因彻底钉死

| 事实 | 读数 |
|---|---|
| 判据线改了没有 | 没有：冻结带 0.000983、`t` 表、功效式、三分类、同 seed 配对规则一格未动（`README.md` §6 判据⑤） |
| 只补 seed 能否改判 | **能**：判据② 从 n=3 的 `undecidable` 走到 n=5 的 `above_band` |
| 判据③ 为什么没跟着改判 | 不是带的问题，是**新 seed 的真值更靠近 0**（+0.000478）⇒ `sd` 上升；换成别的带也判不出来 |
| 若按「带 = 配对差散布」改会怎样 | 功效式 `n_req = ⌈(2.9·0.005073/|0.008392−0.005073|)²⌉ = 20`（现在 5 个 seed 就判出来了）；改成点判据「mean vs 带」则直接判「税存在」、无区间 |

人话：**判据线的尺子没动，多量几次就把 k=128 量准了**——这正说明上一版「尺子错了、要换尺子」的判断是错的。
「以配对差散布替代 σ_cell」继续留在 `project.yaml::gaps` 的**口径登记项**里（它是框架性取舍），
不再是任何一条判据的收口路径。

## 6 排除了哪些别的解释

- **仪器没变**：判据① 10/10 逐位相同（`full` 1.502689、`win64_s0/s1/s2`、`win64a_s0/s1/s2`、
  `win128_s0/s1/s2` 全等）。
- **掩码与配方没变**：判据④ 全过（见 §0 第三条）。
- **训练没异常**：四臂 rc=0，墙钟 504 / 528 / 509 / 460 s（`config.json::arms` 的 `train_seconds`），
  与 `2682`（8–10 min/臂）同档；四个新臂的 bpc 都落在同族臂的散布内（同窗口臂之间的 bpc 差 ≤0.010）。
- **不是挑 seed**：seed 3 与 seed 4 是 `2686` 之后的头两个种子，按序跑、无替换。
- **不是「靠某一个点撑起来的」也不是「剔除某个点换来的」**：判据② 的五个税在 0.002762–0.012607 之间、
  没有离群点，5/5 同向为正；`above_band` 由跨 seed 区间给出，不是某个单点。同时**不得反读成「换个 n 也判得出」**：
  在 n=5 上去掉 seed 1（0.009808）或 seed 4（0.010376）中的任一个，剩下四点的区间会重新跨带
  （去掉 seed 1 ⇒ [+0.000848, +0.014948]、去掉 seed 4 ⇒ [+0.000863, +0.014651]，两个下界都 < 0.000983）
  ——所以这个判词只对「不剔除任何 seed 的 n=5」成立，这正是预登记规则要求的那一种读法。

## 7 边界（禁外推）

- 本判读只覆盖 **13M / L=12 / T=256 / enwik8 / 12k 步 / 该可见性快照**；不外推到更大规模、更长 T、别的分词口径。
- 判据② 的 k=128 只说明这一档；**不得**沿曲线外推到 k≥192（k=192 在 n=2 下仍 `undecidable`）。
  它的正确读法是「k=128 的税**存在**且**≤0.0132**」，不是「k≥128 免费」。
- 判据③ 只判「这个价在本 n 下是否非 0」；**不判**「锚点值不值得买」（买价与净算术在 `2662` / `2679` / `2682`）。
  `undecidable` 不得读成「锚点无效」，也不得读成「锚点有效」——四 seed 均值 −0.00483 仍同向偏负，
  但区间含 0。
- 四臂的训练墙钟与 rc 落在 `config.json`（`train_seconds` / `train_rc`），因为 `*.log` 是被忽略的派生物。

## 8 成本

- GPU：4 臂 × 12k 步 = **33.4 min**（504 + 528 + 509 + 460 s，含逐臂 §20 取锁；等 `1.2.2` 的 2685 训练占锁
  约 25 min 是等待，不计入本实验的 GPU 时间：`train_driver.log` 的 `wait-lock` 行可核）。评测 **25.6 s**
  （14 臂一次前向，含 10 条复现门）。
- 复现：`python3 make_config.py && python3 run.py`（权重 `*.pt` 不入库 ⇒ 别的克隆是 `rebuildable_only`，
  按 `README.md` §5 的配方重训 4 个新臂即可重算）。
