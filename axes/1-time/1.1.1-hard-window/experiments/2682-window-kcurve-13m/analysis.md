## 0 人话摘要（先看这段）

**问题**：把注意力的可见范围压成「只留最近 k 个位置」以后，质量到底掉多少？掉到多宽的窗口才算「白捡」？
还有一件更容易出错的事：**「只留最近 32」这种累计配置的代价，能不能用「删掉距离恰为 32 的那一个键」的代价
加起来估？** 本仓历史上就栽在这里——单点读数 ≤0.004 被当成收益，直接测累计是 0.212（`harness/SCHEMA.md` §17.11）。

**答案一：窗口宽度是真的单调药，但没有一档在这个样本量下被证明「税已落进噪声带以内」。**
本目录自己训了 8 条臂（k∈{32,64,128,192} × seed 0/1），加上 k=16 的 4 个种子复本，逐 seed 配对算
「窗口臂 bpc − 全因果 bpc」这把税：

| k | 税（bpc，越低越好） | 本 n 下判成什么 |
|---|---|---|
| 16 | 0.124061 | 确定越本格自测带（0.000983） |
| 32 | 0.082197 | 确定越带 |
| 64 | 0.052907 | 确定越带 |
| 128 | 0.011208 | **本 n 下不可判**（区间 [−0.006575, 0.028990] 跨带） |
| 192 | −0.000387 | **本 n 下不可判**（区间 [−0.024091, 0.023316] 跨带） |

四段方向全降（0.124 → 0.082 → 0.053 → 0.011 → −0.0004）。人话：**窗口从 16 推到 64，税从「不可用的 12%」
降到「约 5%」；推到 128 时平均税只剩 0.011、到 192 已经贴着 0 甚至略好（−0.0004 = 窗口 192 反而比全因果
好 0.04%，这在噪声量级里），但这条 0.0004 的差**不能**写成「窗口 192 免费」——k=192 的两个种子一个是
+0.001478、一个是 −0.002253，方向都不一致；k=128 同理。**按预登记的规矩，这两档只能写「本 n 下不可判」，
并给出需要多少样本**（见 §3 判据②）。

**答案二：两个数差 45 倍，单点读数不能外推成累计代价。** 在同一批权重上，`full` 臂「只留最近 32」
掉 **0.211679 bpc**；而「删掉距离恰为 32 / 64 / 128 / 255 那四个键」的代价加起来只有 **0.004720 bpc**，
比值 **44.8**。人话：**远处那些键彼此是可替代的（单独拿走一个几乎不掉），但把它们整批拿走就掉得厉害**——
拿单点读数累加会把累计代价低估四十五倍。这就是本仓把「累计预算列」与「单距离列」分开报的全部理由，
也是 `harness/SCHEMA.md` §17.11 那条入账错误在这批数据上的量化。

**答案三（顺带量出来的、比预期更扎眼的一条）：模型只在自己训练时见过的可见集上工作，把「更宽的可见集」
当成好处去读会读反。** 拿只在窗口 16 下训出来的模型去「只留最近 32」评，质量从 1.628110 崩到 3.937197
（**+2.309087 bpc**）；只在窗口 192 下训的模型「只留最近 240」反而 **−0.001662**（比它自己的释放版略好）。
人话：**给一个只看 16 个键的模型多放 16 个它从没见过的键，是重伤而不是加分。** 所以「最近 D」这一列的
每一行都必须标它相对该臂预算是什么关系（同宽 / 更窄 / 更宽），否则同一张表里会混进两种相反的读法。

**答案四（锚点杠杆在第二个 k，读数刚好处在判定的边缘）**：窗口 64 再加 8 个锚点，两个 seed 的质量都更好
（−0.007652 / −0.008982 bpc，均值 −0.008317），与 k=16 的 −0.00706 同方向同量级；但 2 个种子的 t 区间
[−0.016766, +0.000132] **含 0**，按预登记只能判「不可判」，补 1 个种子（n=3）就能判。

## 2 六问（`harness/SCHEMA.md` §25 的格式契约）

1. **它是干什么的**：让模型只看最近若干个位置也能把语言模型做好，从而让前缀能被真正丢掉、让长上下文的
   KV 与算力随序列线性而非平方增长。
2. **相对普通的 decoder-only transformer 改了什么**：只改注意力的可见掩码——每个 query 的 key 集合从
   「前面全部位置」裁成「最近 k 个位置」（锚点档再加最前面若干恒可见位置）。**不新增参数**
   （`results.json::selfchecks.*.n_params` 逐臂 13,536,768，与全因果基线逐位相同），attention 的 QKᵀ 与
   加权项由 O(T²) 降到 O(T·k)。
3. **为什么要改**：它对准的是**显存与算力**这条痛点（长 T 的 KV 缓存与二次项计算），代价是长程可达性；
   本实验要量化的是「这条代价在 k 上怎么变」，以及两条不同口径的代价能不能互相换算。
4. **怎么测的**：对照 = 同尺寸全因果 `full`（1.502689 bpc，100% 质量参照）；指标 = clean bpc（越低越好）；
   口径 = **同 step（12k）× 同 token 预算**、逐 seed 配对（同 seed 的窗口臂减同一条 `full`）；
   **禁墙钟**。判据带 = 本格冻结的自测带 0.000983（主判）+ 0.014 跨格带（只作参考，两带并列不混用）。
5. **测出来多少**：见 §0 与 §3。人话量级：窗口 16 的税 0.124061 相当于「比全因果差 8.3%」，
   窗口 64 的税 0.052907 相当于差 3.5%，窗口 192 的税已经在噪声里。
6. **结论与下一步**：结论 = **窗口宽度是单调药、k≈128 附近平均税已进 0.011 量级但本 n 判不了「是否越带」；
   两列代价不是一回事（差 45 倍），必须分开报**。下一步 = 给 k=128 / k=192 补种子（§3 判据② 给了所需 n），
   以及在更大规模上重复同一条曲线（本仓结论禁外推，见 §5）。

## 3 判据逐条（`results.json::criteria`）

### ① 复现门（仪器自检）——通过，9/9 逐位相同

用本目录 `run.py` 重评 1.1.1 目录内已有 9 条 checkpoint，clean bpc 与 `2662` / `2681` 落盘值
**逐位相等**（6 位小数）：`full` 1.502689、`win16_s0` 1.628110、`win16_s1` 1.629093、`win16_s2` 1.624611、
`win16_s3` 1.625184、`win16a_s0` 1.622527、`win16a_s1` 1.621799、`win16a_s2` 1.618953、`win16a_s3` 1.615477
（`results.json::criteria.c1_reproduction_gate.repro`，`all_equal=true`）⇒ 仪器没变，跨项复用的 4 个 k=16
种子与本目录新训的 8 条臂可以放进同一条曲线。

### ② 训练期累计预算列（主判，`criteria.c2_train_budget_column`）

逐 seed 配对的窗口税 `tax(k,s) = bpc(win-k) − bpc(full)`，跨 seed 均值 + t 区间（双侧 α=0.05，df=n−1）：

| k | n | 逐 seed 税 | 均值 | sd | t 区间 95% | 三分类 | 所需样本量 |
|---|---|---|---|---|---|---|---|
| 16 | 4 | 0.125421 / 0.126404 / 0.121922 / 0.122495 | 0.124061 | 0.002188 | [0.120579, 0.127542] | `above_band` | — |
| 32 | 2 | 0.083733 / 0.080660 | 0.082197 | 0.002173 | [0.062674, 0.101719] | `above_band` | — |
| 64 | 2 | 0.052515 / 0.053299 | 0.052907 | 0.000554 | [0.047926, 0.057888] | `above_band` | — |
| 128 | 2 | 0.012607 / 0.009808 | 0.011208 | 0.001979 | [−0.006575, 0.028990] | `undecidable` | 见下 |
| 192 | 2 | 0.001478 / −0.002253 | −0.000387 | 0.002638 | [−0.024091, 0.023316] | `undecidable` | 32 |

键路径：`criteria.c2_train_budget_column.per_k.k{16,32,64,128,192}.{per_seed,cross_seed,classification,seed_range_observed}`。

- **方向**：四对相邻 k 全部下降（`criteria.c2_train_budget_column.monotone_pairs`，4/4 `decreasing=true`）⇒
  「k 越大税越小」这条**该跌**成立，没有反例，也没有被平滑。
- **没有任何一档落进 `below_band`**：`criteria.c2_train_budget_column.band_edge.below_band_k` 为空数组。
  这就是本实验对里程碑第一条的诚实答法：**曲线画全了，但「k 到哪一档就白捡」这句话在本 n 下没有一档支持**。
- **`undecidable` 的所需样本量**（判据线规定必须给）：k=192 的预登记功效式给 **n_req = 32**
  （`per_k.k192.classification.n_req`）；k=128 的同式给 **1**
  （`per_k.k128.classification.n_req`），这个 1 是**公式本身的形态问题**而不是读数结论——预登记式
  `n_req = ceil((2.9·sd/|mean − band|)²)` 用的是正态近似（2.9 = 1.96+0.84），在 df 很小时低估样本量；
  而实际判定量是 t 区间（n=2 时 t=12.706）。按实际判定量反推（**这是推导，不是读数**）：k=128 在 **n=3**
  就可判（半宽 4.303·0.001979/√3 = 0.004917 < 0.010225），k=192 约在 **n≈17**
  （半宽 2.120·0.002638/√17 = 0.001356 < 0.001370）。两处都以「seed 间 sd 不随 n 变化」为前提；
  若 sd 随 n 上升，所需 n 更大。**判据线一个字没改，这里只是把「需要多少样本」答全。**
- **`σ_cell = 0.000983` 这根带比的是什么**（读这张表必须一起读）：它是 `2662` 上**同一条臂的两个 seed 之间
  的极差**，也就是**单臂噪声带**，不是「价格（臂间差）的散布」。价格是两个臂各自带噪声的量相减，实际散布
  会比 0.000983 大；本表仍按预登记拿它当门限（判据线不得事后调整），因此**所有 `above_band` 的结论方向不变
  但强度要打折读**，`undecidable` 的两档更不该被读成「确定免费」。本 n 的逐 k 种子极差作为描述量另报
  （`per_k.*.seed_range_observed`：0.004482 / 0.003073 / 0.000784 / 0.002799 / 0.003731），它**不回填成新带**。
- **k=16 的税为什么是 0.124061 而不是旧摘要的数**：本项的 k=16 现在是 n=4 的同配方复本（seed 0/1 来自
  1.1.4.1 的 `2634`，seed 2/3 来自本项 `2681`），而判据① 已逐位证明两者是同一仪器；旧的
  `2638` 的 k∈{17,18,24,128} 现值**不再出现在这条曲线上**，它只是被本轮读数取代的旧读数（README §2）。

### ③ 评测期累计预算列（`criteria.c3_eval_budget_column`）

`recent_keep_mask(256,D)`，D∈{16,32,64,128,192,240}，Δ = bpc_masked − bpc_该臂释放版。
按预登记每行带 `relation_to_arm_budget`（`identity` / `narrower` / `wider_than_training` / 该臂为全因果时的
`released_causal`）：

| 臂 | 释放版 bpc | D=16 | D=32 | D=64 | D=128 | D=192 | D=240 |
|---|---|---|---|---|---|---|---|
| `full`（全因果） | 1.502689 | +0.593507 | +0.211679 | +0.085327 | +0.017978 | +0.002851 | +0.000091 |
| `win16_s0` | 1.628110 | **0.000000** | +2.309087 | +2.707020 | +2.884881 | +2.924080 | +2.927818 |
| `win64_s0` | 1.555204 | +0.294957 | +0.091733 | **0.000000** | +0.063711 | +0.391113 | +0.829588 |
| `win192_s0` | 1.504167 | +0.569116 | +0.187353 | +0.069215 | +0.011306 | **0.000000** | −0.001662 |

键路径：`criteria.c3_eval_budget_column.by_arm.{full,win16_s0,win64_s0,win192_s0}.*.delta_bpc`。

- **自检通过**：三条 `identity` 行（D 等于该臂训练窗口且 anchors=0）的 Δ **逐位为 0**
  （`criteria.c3_eval_budget_column.identity_check`，3/3 `equal_zero=true`）⇒ 掩码实现与臂规格对得上。
- **`wider_than_training` 那一侧不是「好处」**：`win16_s0` 放到 D=32 是 +2.309087、D=240 是 +2.927818
  ⇒ 放出训练时从未见过的键是**重伤**。`win64_s0` 的 D=240 同样 +0.829588。这一列必须这样读，否则同一张表
  里「D 变大 ⇒ Δ 变小 ⇒ 更接近全因果 ⇒ 更好」的直觉会读反。
- **`narrower` 那一侧才与训练期税同向可比**：`win192_s0` 收到 D=128 只掉 +0.011306、`win64_s0` 收到 D=32
  掉 +0.091733 —— 与判据② 的税同量级，正是「同一件事用两种口径测」应有的样子。

### ④ 单距离列（`criteria.c4_single_distance_column`，只描述形状）

`distance_keep_mask(256,d)`，d∈{1,2,4,8,16,32,64,128,255}，Δ 同上：

| 臂 | d=1 | d=2 | d=4 | d=8 | d=16 | d=32 | d=64 | d=128 | d=255 |
|---|---|---|---|---|---|---|---|---|---|
| `full` | +3.217645 | +1.986754 | +0.750046 | +0.090254 | +0.014910 | +0.003239 | +0.001029 | +0.000452 | 0.000000 |
| `win16_s0` | +3.197320 | +2.963045 | +2.928103 | +2.928478 | +2.933579 | +2.928728 | +2.927009 | +2.927156 | +2.927460 |
| `win64_s0` | +3.171720 | +2.254698 | +1.465740 | +0.999920 | +0.907829 | +0.884383 | +0.888396 | +0.885769 | +0.879883 |
| `win192_s0` | +3.291744 | +1.942015 | +0.714311 | +0.085326 | +0.014034 | +0.001530 | −0.000719 | −0.001273 | −0.001608 |

键路径：`criteria.c4_single_distance_column.by_arm.*.rows.*.delta_bpc`。

- **形状**：`full` 上依赖随距离陡降（最近的那个键值 3.217645 bpc，d≥32 之后不到 0.0033）；
  `additivity="shape_only"` 逐臂标注齐备。
- **窗口臂上同一个「删 1 个键」是大动作**：窗口 16 的臂在 d=2 就掉 +2.963045。原因是这条曲线的分母是
  **该臂自己的可见集**——删掉 1 个键相对于 256 个可见键是 0.4%，相对于 16 个可见键是 6%。所以**这两列
  的读数不能跨臂横向比大小**，只能各自看形状；表里的 `dropped_frac` 是相对精确因果掩码的
  （`n_dropped_pairs` / `causal_pairs=32896`，d=1 时 255/32896 = 0.0077517），不是相对该臂的。
- `win192_s0` 在 d≥64 出现**负**值（−0.000719 / −0.001273 / −0.001608），即删掉一个很远的键反而略好；
  量级 0.001–0.002，与冻结带同量级，**只作形状描述，不读成收益**（判据④ 预登记就是「该跌 = 落进本格带 = 形状描述」）。

### ⑤ 两列不可互换（预登记证伪面，`criteria.c5_columns_not_interchangeable`）

只在 `full` 臂上判（窗口臂的 D=32 是「更宽」关系，不参与预测判定，见 README §5c）：
`cum = Δ_recent(32) = 0.211679`，`sum_single = Σ_{d∈{32,64,128,255}} Δ_distance(d) = 0.004720`，
比值 `44.847246`，`cum_above_frozen_band=true`，`prediction_holds=true` ⇒ **预登记预测成立**。

**为什么成立、以及它意味着什么（这条必须写清，不能只报一个比值）**：
- 「只留最近 32」一次拿走每个 query 距离 ≥32 的**全部**键（D=32 那一行 `n_dropped_pairs` 25200、
  `dropped_frac` 0.76605058，即 76.6% 的因果对）；单距离列一次只删**一个**。
- 于是这个 44.8 倍本身就是结论：**远处的键之间有强替代性**——单独拿走一个几乎不掉（0.0005–0.0032），
  整批拿走就掉 0.21。拿单点斜率先求和、再外推到别的预算，会低估累计代价约四十五倍
  （`harness/SCHEMA.md` §17.11 记的那次「单点 ≤0.004 被读成收益、实测累计 0.212」，在**同一批数据上复现**）。
- 窗口臂的比值只作描述量：`win16_s0` 0.197183、`win64_s0` 0.025925、`win192_s0` −90.508696
  （最后一个是负数，因为该臂在 d≥64 的单点 Δ 是负的）⇒ 再一次说明**跨臂横比没有意义**。

### ⑥ 锚点杠杆在第二个 k（可选臂，`criteria.c6_anchor_lever_at_k64`）

`win64a_s0/s1`（窗口 64 + 锚点 8，same 配方只多 `--train-anchors 8`）已训完，价格 = bpc(win64a) − bpc(win64)：
seed 0 **−0.007652**、seed 1 **−0.008982**（两 seed 同向 = 锚点更好），均值 **−0.008317**、sd 0.00094、
t 区间（df=1）**[−0.016766, +0.000132]** **含 0** ⇒ 按预登记判 **`undecidable`**。

- 与 k=16 的 −0.00706（`2681` 判据⑦，n=4）**同方向、同量级**，但这条只能写「不可判」，不能写「同一价格复现」。
- 区间上界 +0.000132 只差 0.00013 就越 0 ⇒ **补 1 个 seed（n=2→3）即可判**（t 区间在 n=3 的半宽
  4.303·0.00094/√3 = 0.002335 < 0.008317）。这是推导，不是读数。
- 预登记功效式给 `n_req = 1`（`criteria.c6_anchor_lever_at_k64.n_req`），与判据② 的 k=128 同一个原因：
  正态近似在 df 很小时低估所需样本量。
- **它不进判据②③④⑤ 的任何一行**（README §4b 预登记）：锚点档与纯窗档是两个不同的臂族，混进 k 曲线会把
  「窗口宽度」这个单因素搞成「窗口宽度 × 有无锚点」。

### ⑦ 自检（必须不变，`results.json::selfchecks`）

- **因果性**：只改后半段 token，前半段 logits `max|Δ| == 0`（5 条臂逐条，`selfchecks.*.causality.max_abs_logit_diff_prefix`

- **参数量**：`selfchecks.*.n_params` 逐臂 13,536,768，与纯窗臂 / 锚点臂**逐位相同** ⇒ 锚点不新增参数。

  因果掩码逐位相同）；`selfchecks.mask_matches_recent_clip` 的 k∈{16,32,64,128,192} 全 true

## 4 成本（实耗，`config.json::arms[*].train_seconds` + `results.json::cost`）

- **训练**：10 条新臂各 12k 步（8 条纯窗 + 2 条可选锚点臂），实耗
  600 / 499 / 559 / 537 / 533 / 506 / 527 / 507 / 527 / 526 s ⇒ **合计 88.7 min GPU**（8 条纯窗臂占 71.1 min）
  （README §7 的主预算 ≤110 min 不含可选 2 臂，可选臂的上限是另 ≤28 min）。逐臂 `train_rc` 全 0
  （`config.json::arms`）。
- **评测**：**79.1 s GPU**（`results.json::cost.gpu_seconds`）——19 条臂的 clean bpc + 4 条臂 × 15 个曲线点 +
  自检。README §7 的估算是 ≤12 min，实际比估算低一个数量级，原因是曲线点是纯前向的掩码重放、没有训练。
- 逐臂挂锁/等锁记录在 `train_driver.log`（`*.log` 是 git-ignored 派生物，返回码与墙钟已抄进
  `config.json::arms` 以便回溯）。

## 5 边界、禁外推与下一步

- **禁外推**：结论只适用于 enwik8 / T=256 / 13M（13,536,768 参数）/ 12k 步 / 该可见性快照，
  不外推到更大规模、更长 T、别的分词口径。
- **本实验回答不了的**：① 「锚点收益归推理期还是训练侧」（`2679` + 等键数 24 键对照臂）；
  ② 窗口代价是否随 T 消失（那是 `2636` 的同 step 子线，本实验固定在 T=256）；
  ③ `sink` 与锚点是不是两档——在本仓是同一根杠杆（`window_anchor_keep_mask` 的 anchors = 最前面 N 个恒可见），
  本实验按 `project.yaml::failure_analysis` ② 的结论处理，不另立 sink 臂。
- **判据⑥ 未判档的最小下一步**：给 `win64a` 补 **1 个 seed**（n=2→3，≈9 min GPU）即可判
  「锚点杠杆在 k=64 是不是同一方向」；补完它还要注意：锚点档与纯窗档是两个臂族，即使可判也不进 k 曲线。
- **判据② 未判档的下一步（最小实验 + 成本）**：给 k=128 补 **1 个新 seed**（n=2→3）即可按 t 区间判
  「是否越带」；给 k=192 补到 n≈17 才判得动（成本 ≈ 15 臂 × 9 min ≈ 135 min GPU）⇒ **k=192 不建议补，
  建议改用「冻结带换成本格真正需要的量」这一层去谈**（那是判据线层面的事，需用户裁决，不在本实验内）。
- **判据② 的带该怎么换**（登记，不在本轮做）：见 §3 判据② 关于 0.000983 是「单臂噪声带不是价格散布」的脚注；
  价格散布要单独量（同配方多 seed 的**配对差**的 sd），那是新契约。
