# 2682 · 窗口臂 k 全曲线自包含复算：累计预算列与单距离列分开报（WP2）

> 归属：`axes/1-time/1.1.1-hard-window`（研究项 1.1.1「hard 窗口」）的 **WP2**（`project.yaml::work_packages`）。
> 入口：`train_arms.sh`（取/放 §20 GPU 锁，逐臂；先过 `prereg_bind.py --require`）→
> `make_config.py`（训练后生成 `config.json`，落检查点 sha256）→ `run.py`（复现门 + 训练期累计预算列 +
> 评测期累计预算列 + 单距离列 + 两列不可互换的演示 + 自检）。
> 判据线与口径常数只写在**本文件与 `run.py`**（= `prereg_binding.json::contract_files`）；
> `config.json` 是训练后生成的产物（臂路径 + sha256），`run.py` 开跑前逐字段核对它。

## 1 命题（可证伪）

研究项里程碑的第一条验收是「**k 全曲线的累计预算列与单距离列分开报**」。到本轮为止：

- 窗口臂的 k 读数 k∈{16,17,18,24,32,128} **全部是复用**（`2634` / `2638`，在 **1.1.4.1** 目录下），
  本目录既没有自包含复算，`k≥17` 的档位也**没有 n≥2 复本**（`2638` 只有 seed 0）；
- 「累计预算」与「单距离」两列**从未在本目录并排出现过**，而 `harness/SCHEMA.md` §17.11 记的
  最贵一次入账错误正是把单点曲线当可加外推（本仓历史：单点 ≤0.004 被读成收益，直接测累计是 0.212）。

**本实验要判死的一句话**：*把窗口宽度 k 从 16 推到 192，质量税是不是真的单调掉下来、掉到哪一档
就落进本格噪声带以内；并且「只保留最近 k」（累计）与「删掉距离恰为 d 的键」（单点）这两列
在同一批权重上是不是**两个数**。*

- 该涨：k 越大，`tax(k) = bpc(win-k) − bpc(full)` 越接近 0（单调不增，允许噪声内起伏）；
- 该跌：单点列的 Δ 在 d ≥ 32 时落进本格带（描述形状的辅助列）；
- 必须不变：`full` 锚与全部复用臂的 clean bpc 与落盘值**逐位相同**（仪器没变）、
  因果性 `max|Δlogit_prefix| == 0`、两列各自的口径标注字段齐备。

## 2 为什么这是该做的动作

`project.yaml::milestone.acceptance` 第 1 条要的就是这两列；`project.yaml::gaps` 第 1、2 条把
「窗口臂仍为复用」「累计预算与单距离两列未拆」并列记着。本轮之前，`2662` 与本目录的 `2681` 只把
**锚点臂**做到了自包含（且只覆盖 k=16），窗口侧的 k 曲线一直是 `2634/2638` 的现值。

三件本轮必须一起做的事：

1. **自包含复算**：k∈{32,64,128,192} 各 2 seed 在**本目录**训练（同引擎、同配方、同 12k 步）。
   k=16 这一档的 4 个 seed 里，`s2`/`s3` 是**本项**（1.1.1 的 `2681`）训练的，`s0`/`s1` 是
   跨项复本（1.1.4.1 的 `2634`，同配方同引擎）——两批都由判据①的复现门逐位核到与本轮仪器同一。
   **`2638` 的 k∈{17,18,24,128} 现值不再出现在曲线里**，它只是被本轮读数取代的旧读数。
2. **两列分开**：同一批权重上分别测「只保留最近 D」(`recent_keep_mask`) 与「删掉距离恰为 d 的键」
   (`distance_keep_mask`)，各自带口径标注，**不许互相换算**。
3. **两个口径分开**：训练期窗口税 `tax(k)`（重训）与评测期丢前缀 `evaltax(D)`（0 训练 token、
   同一条 full 权重改掩码）并列成一张两列表——它们在本仓已被实测证明不是一回事，混列即错。

## 3 单因素声明与仪器不变声明

- **基底**：stock dense decoder-only trunk（d256 × 12 层 × 8 头 × mlp6 × T256），与 `2662` / `2634`/
  `2638` 逐字段同一规格；`full` 锚 = `2610` 的 `trunk.pt`（全因果，100% 质量参照）。
- **唯一新变量 = 训练期窗口宽度 k ∈ {32,64,128,192}**（锚点臂 0 个）；新臂的配方与
  `2662` 的 `win16a*` / `2634` 的 `rt_none*` **逐字段一致**，只差 `--train-window` 与 `--seed`。
- **仪器逐字不变**：bpc = `realtext_probe.win16_bpc`，96×16、`window_seed=2`
  （与 `2662` / `2681` 同一函数、同一批数、同一窗口序）。`realtext_probe.py` 是本目录副本，
  内容与 `2681` 逐字节相同。
- **掩码实现不改**：窗口臂用自己的 `window_anchor_keep_mask(256,k,0)`；两条评测期曲线用
  `tools/evalkit/retention.py` 的 `recent_keep_mask` / `distance_keep_mask`（共享底座，只读调用）。
- **不改共享文件**：`pathlm/**`、`train_depth_ar.py`、`tools/**`、`tests/**`、元级文档一律不碰。

|---|---|---|---|
| ① | **复现门（仪器自检）** | 用本目录 `run.py` 重评 1.1.1 目录内已有的 9 条 checkpoint（`win16_s0..s3`、`win16a_s0..s3`、`full`），clean bpc 与 `2662` / `2681` 落盘值**逐位相等**（6 位小数）。不等 ⇒ **本实验作废**，先修仪器，不得改判据线去凑 | **必须不变** |

| ⑤ | **两列不可互换（预登记证伪面）** | 在 D=32：`cum = Δ_recent(32)`、`sum_single = Σ_{d∈{32,64,128,255}} Δ_distance(d)`。预登记预测 `cum / sum_single > 1` 且 `cum > 冻结带`。**不成立 ⇒ 必须写清这批数据为什么不符合 §17.11，不得默默只报一条曲线** | 该涨比值 |

### 5a 判据② 的三分类与「不可判」的写法（预登记）

窗口税 `tax(k)` 是「越带 / 不越带」的二值问题，而 n=2 的区间可能两头都够不着。所以**不许把它
压成一个布尔**，一律三分类：

- `above_band`：`mean − t·sd/√n > σ_cell` ⇒ 该 k 的税**确定**越本格带（窗口在这个宽度上确实有代价）；
- `below_band`：`mean + t·sd/√n < σ_cell` ⇒ 该 k 的税**确定**不越本格带（窗口在这个宽度上不亏）；
- `undecidable`：区间跨 σ_cell ⇒ **只能写「本 n 下不可判」**，并按
  `n_req = ceil((2.9·sd/|mean − σ_cell|)²)` 给出所需样本量（1.96+0.84 的近似功效式）；
  `mean == σ_cell` 时 `n_req` 记 `null` 并注明「效应恰在带边界上，样本量不救」。
- `n < 2` ⇒ 一律 `undecidable`，`n_req` 按「先补到 n=2」记。

`σ_cell` **冻结为 0.000983**（`2662` 的两 seed 极差，`2681` 也未重算）；本实验**不重算它、不回填**
（判据线不得事后修改），本 n 的逐 k 种子极差只作描述量另报（`seed_range_observed`）。
跨格带 0.014 只作参考，两带并列报、不混用（C1 裁决）。

### 5b 判据③④ 的「两列不互相换算」纪律

- 累计预算列（`recent_keep_mask(D)`）直接测「只留最近 D」这个**累计配置**，是被许可的
  「删一段/留一段」读数；
- 单距离列（`distance_keep_mask(d)`）测「删掉距离恰为 d 的那**一个**键」，**只描述形状**，
  不得累加、不得外推到别的预算；
- 两列在 `results.json` 里各有自己的 `additivity` 字段（`direct_cumulative` / `shape_only`），
  判据⑧ 机检它们存在且取值合法。判据⑤ 把「互换会错多少」量出来。

## 6 否证条件

- 判据① 不过 ⇒ 本实验**作废**：不写判词，先查窗口序 / 掩码 / 权重 / 仪器，修完重跑。
- 判据② 的税**不单调**（k 变大反而更差）⇒ 如实报，不得平滑；并检查是否某臂训练异常（看 `train_*.log`）。
- 判据⑤ 预测不成立 ⇒ 必须写清原因（例如这批权重下距离依赖确实接近可加），**不得**改判据去凑。
- 判据③ 的自检（D ≥ 窗口时 Δ ≠ 0）不过 ⇒ 掩码实现或臂规格错，本实验作废。

## 7 成本与预算

- 训练：8 臂 × 12k 步（`2662` 实测 13.07 / 9.43 min/臂）⇒ **≤ 110 min GPU**；可选 2 臂另 ≤ 28 min。
- 评测：9 个复用臂 bpc + 8 个新臂 bpc（17 × 96×16）+ 4 臂 × 15 个曲线点 ≈ **≤ 12 min GPU**。
- **预算上限：150 min GPU / 210 min 墙钟**（可选臂不吃主预算，超时即弃并登记）。
  不够时砍什么（SCHEMA §17.7 / §20.3）：先砍单距离列的 d 档（9→5，只影响描述形状）>
  再砍曲线所覆盖的臂数（4→2：`full` + `win64_s0`）> **不砍 k 档位、不砍 seed 数（n=2 是判据② 的全部）、不砍判据线**。
- 共享机器纪律：单卡 4090 且 `local_lm_research` 优先 ⇒ **同一时刻只跑一个 GPU 作业**、
  逐臂取/放 `/tmp/pathlm_gpu.lock`、臂间 ≥61 s、单臂 `timeout 1200`（≤20 min）；
  等锁期间写文档，不空转；等锁 >40 min 则退让并如实登记。

## 9 scope 声明

只做单轴单格（1.1.1），基底恒为 stock dense；本实验不引入新机制、不改仪器、不改判据线常数。
`sink` 档**不另立臂**：在引擎里 `window_anchor_keep_mask` 的 anchors 就是「最前面 N 个位置恒可见」，
与 StreamingLLM 式 sink 是同一根杠杆（`project.yaml::failure_analysis` ② 已判），本实验用
`win16a*` / `win64a*` 承载这一档，并在结论里点明它不是独立档。
**禁外推**：结论只适用于 enwik8 / T=256 / 13M / 12k 步 / 该可见性快照上，不外推到更大规模、
更长 T、别的分词口径。本实验**不**回答「锚点收益归推理期还是训练侧」（`2679` + 等键数 24 键对照臂）。
