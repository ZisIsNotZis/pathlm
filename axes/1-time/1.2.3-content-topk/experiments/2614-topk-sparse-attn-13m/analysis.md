## 0. 人话摘要（先说人话，再上数据）

**它是干什么的。** 这个设计想让模型在读一句话时，每个词只在「内容上跟它最像的 32（或 64）
个词」之间交换信息，而不是去看前面所有 256 个位置。想法来自业界最热的省算力路线
（稀疏 / 线性注意力 / SSM / 池化），也是本仓库设计空间地图上最大的一片空白（混合算子格
`A6`，至今没有任何实验）。

**相对普通的 decoder-only transformer 改了什么。** 只改注意力算子本身，别的一律不动：

- 普通（基线）注意力：每个查询在因果掩码内（只看自己及左边）对**所有**键做 softmax 加权；
- 本实验的 top-k 版：先算出分数 `q·kᵀ`，**只保留分数最大的 k 个键**（k = 32 / 64），
  其余键置 −inf 再 softmax。选择只看内容相似度，**不看位置远近**。
- 改动量级：**参数量增量 = 0**（6,962,688 → 6,962,688，逐位相同），计算量按公式是下降的
  （见 §6），显存**不降**（原因见下）。

**为什么要改。** 全注意力的算力/缓存随上下文长度平方增长，长上下文时代这是最贵的部件；
「只跟最像的 k 个键打交道」是把它压成线性的最直接办法。先回答最核心的问题：
**能不能只让每个查询看内容上最像的 k 个键，而不掉质量？**

**怎么测的。** 同一台天平上的三个臂，唯一变量 = 注意力算子：

- 同一 stock 13M decoder-only（d=256 / 8 层 / 8 头 / seq 256 / bs 32 / tied 读出）；
- 同一数据（enwik8 前 90M 字符训练、末 10M 评测）、同 seed 0、同 12k 步（98.3M token）；
- 指标 = **clean bpc**（每字符比特数，越低越好=压得越准），口径 = matched-step 快照
  （12k 步时的质量，不是收敛值、不是墙钟）；
- **Δ = bpc_对照 − bpc_实验 = bpc_full − bpc_topk（正 = 实验更好）**；
- 判据线（预登记）：`|Δ| < 0.014` ⇒ 与全注意力同质量；`Δ ≥ +0.014` ⇒ 更好；
  `Δ ≤ −0.014` ⇒ 稀疏有害。0.014 是本项目的方差界（同尺寸同配置的种子散布 ≤0.0138）。

**测出来多少。**

| 臂 | clean bpc（越低越好） | Δ vs 全注意力 | 参照系 |
|---|---|---|---|
| 全注意力（基线） | **1.5304** | — | 同配置历史 run 1.5287（差 0.0017）；本实验重跑另一遍 1.5279（差 0.0025） |
| top-k，k=64 | 1.5399 | **−0.0095**（劣 0.6%） | 落在 `|Δ| < 0.014` 的同质量带内，但方向一致、可检出（见下） |
| top-k，k=32 | **1.5470** | **−0.0166**（劣 1.1%） | **越过 0.014 判据线 ⇒ 记为「有害」** |

用人话说：只留 64 个键，质量损失约 0.6%，在噪声带内；只留 32 个键，损失 1.1%，
恰好越过「可以忽略」的线。两个 k 的方向一致、幅度单调（k 越小越差），说明这不是抖动。
配对口径（同一批 20 个评测位置逐批相减）给出：k=32 的差是 **−0.0166 ± 0.00215**
（20/20 批方向一致，t = −7.7）；k=64 是 **−0.0095 ± 0.0023**（16/20 批方向一致，t = −4.1）；
同配置重跑散度实测 **0.0025**。所以：k=32 的劣化是真的、且越线；k=64 的劣化也是真的、
但仍在「不可排序」带内。

**成本（这一条比质量更刺眼）。** 理论上是省的，**实测是亏的**：

| 口径 | 全注意力 | top-k k=32 | top-k k=64 |
|---|---|---|---|
| 理论：保留键数占 T=256 的比例 | 100% | 12.5%（−87.5%） | 25%（−75%） |
| 理论：注意力 FLOPs（修正后，见 §6） | 100% | −43.75% | −37.5% |
| 理论：整模型每 token FLOPs | 100% | −6.25% | −5.36% |
| 理论：KV 缓存/显存 | 100% | **−0%（一点也不能省）** | **−0%** |
| **实测：整模型一步 fwd+bwd** | **24.3 ms** | **54.0 ms（×2.22）** | **54.8 ms（×2.25）** |
| **实测：峰值显存（进程）** | **1.47 GB** | **2.55 GB（×1.7）** | **2.57 GB（×1.7）** |

两个原因，都是**结构性的、不是调参能消掉的**：
① **按内容选键就必须先算出完整的 T×T 分数矩阵**（不知道分数就没法知道哪 k 个最像），
所以「省掉 QKᵀ」这条路被堵死；能省的只有后半段 `P·V` 混合。
② 因此 KV 缓存也**不能变小**——你仍然需要存下全部 K/V 才能筛选它们（这正是与
「位置窗口稀疏」的本质区别：后者才能真的把缓存砍到 k/T）。
③ 本实装为了可逐位核对的公式离开了 PyTorch 的融合注意力核（SDPA），额外付了实现代价
（§6 用同一孤岛基准把「算法本征」与「实现代价」分开测：保留 SDPA 的掩码实装 1.90×，
真稀疏 gather 参考实现 1.63×，都仍 > 1）。

**交叉点在哪。** 注意力只占 T=256 时每 token FLOPs 的 14.3%，所以「注意力省 44%」只等于
整模型省 6.25%，而墙钟还涨 2.2 倍。公式外推（**纯公式，非实测**）：T=1024 时注意力占 40%、
整模型理论省 19.4%；T=4096 时占 72.7%、理论省 36.1%。也就是说**只有到长上下文、
全注意力成为瓶颈时，内容 top-k 才可能在账面上回本**——而那时的质量税是否仍是 0.6–1.1%，
本实验（T=256）没有回答。

**结论与下一步。** 不采纳为「省算力路线」（在当前规模与实装下净亏）；
**质量上 k=32 被否证**（−0.0166 越线），k=64 记「同质量带内的小损伤」。
这不是实现 bug（5 处变异全抓红、活性量逐位对账通过、20/20 批方向一致），
所以归因落在**设计在该设定下的头寸**：13M / T=256 / 98M token 时，每个查询的注意力分布
本来就相当局部（实测被选键 77–86% 落在最近 k 个位置窗口内），砍到 32 个键等于砍掉
真正远距离的那部分信息，而正是这部分在长上下文任务里才值钱。
下一步（待主 Agent 安排）：① 在 T≥2048 复测质量是否回本；② 把「按内容选」与
「按位置窗口（最近 k 个）」在同一预算下同台对照——位置稀疏才可能真省内存；
③ 若要继续内容稀疏，必须走「自定义稀疏核」而不是「稠密打分 + 掩码」。

的设计下结构性地拿不到。**

## 4. 三道对账（SCHEMA §12）

### 4.1 算术对账

| 量 | 理论/算术 | 实测 | 是否通过 |
|---|---|---|---|
| Δ 定义 | Δ = bpc_full − bpc_topk（正 = 改善） | 1.5304 − 1.5470 = **−0.0166**；1.5304 − 1.5399 = **−0.0095** | ✓（bit 级可复算） |
| 保留键数恒等式 | `mean_i min(k, i+1)`：k=32 → (32·33/2 + 224·32)/256 = **30.0625**；k=64 → (64·65/2 + 192·64)/256 = **56.125** | 活性量实测 **30.0625 / 56.125** | ✓ 逐位一致 |
| 参数量账 | 干预不引入参数 ⇒ Δparams = 0 | 三臂均 6,962,688 | ✓ |
| bpc 下界 | bpc ≥ 0（本任务实测量级 1.5，远高于 0） | 1.53–1.55 | ✓（无越界） |
| 注意力 FLOPs 下降 | `(T−k)/(2T)`：k=32 → **0.4375**；k=64 → **0.375**（QKᵀ 全矩阵因内容选择不可省，只能省 P·V） | 实测墙钟**上升** 2.22× ⇒ 与「FLOPs 下降」不矛盾但**不能互换**（§6 明确标注） | ✓（口径已分开） |
| 配对差与噪声 | 同批配对差的 SE 必须远小于单臂 bpc 的批间散布 | SE 0.00215（k=32）/ 0.0023（k=64）；单臂批间 sd ≈0.010 | ✓ |

### 4.2 任务对账

- 三臂**同一任务定义**（char 级 AR / 下一字符）、**同一输入分布**（同一数据流与切分）、
  **同一位置集**（全序列逐位置 × depth-8 读出，`depth_curve` 同一 generator seed=2、
  同一 batch 顺序）、**同一目标定义**（tokens 自移位）、**同一评测电池**
  （`run_battery`：n_batches=20 / 同 seed / 同 batch_size）；
- 无「假上下文 + 真目标」式对照（SCHEMA §13 禁止项）：三臂都只吃真实 token，
  评测也是同一批真实位置；
- 唯一的差异通道是注意力算子，且该通道**确实被激活**（§5）。

### 4.3 口径对账

- **matched-step 快照**：三臂同为 12k 步 / 98.3M token / seed 0，**非渐近、非墙钟、非 FLOPs**；
- 质量口径（clean bpc，depth-8 读出）与成本口径（步时/显存/FLOPs 公式）**分开报**，
  全文不混用（双货币纪律：同一机制在两个口径下结论会分歧，本实验就是这种情形——
  FLOPs 口径下降、墙钟口径上升）；
- 判据阈值 0.014 = 方差界本身（`docs/methodology.md` §2），**n_seed = 1**（契约未授权补 seed），
  因此「越线/不越线」按不可排序带解读；阈值近旁的噪声已用配对评测单独量化（§7.2）。

**三道对账结论：全部通过。**

## 5. 干预活性与变异验证（SCHEMA §10 / §17.4）

### 5.1 活性量（每 200 步落盘，训练日志同行）

`<arm>-train_log.jsonl` 的每一行都带 `attn_sparse`（关闭时显式为 `null`），日志每 200 步落一行（共 61 行），活性量的层样本总数为 12,000 步 × 8 层
= 96,000（非 61 × 8）（`attn_sparse_layer_samples = 96000`）：

| 量 | top-k k=32 | top-k k=64 | 说明 |
|---|---|---|---|
| `kept_mean`（全程均值） | **30.0625** | **56.125** | **逐位等于**理论 `mean_i min(k,i+1)` ⇒ k 真的生效 |
| `kept_frac_of_T` | 0.117432 | 0.219238 | 保留键占全序列比例 |
| `sel_dist_mean`（被选键平均距离） | 24.81 | 37.95 | 训练后比随机初始化时（66.7 / 71.4）**更局部** |
| `sel_in_lastk_frac`（内容选择 ∩「最近 k 个」窗口） | 0.772 | 0.858 | ≪1 ⇒ **选择按内容、不按位置**；但同时说明注意力相当局部 |
| `params_added` | **0** | **0** | 干预不靠参数，活性只能来自掩码本身 |
| 算子输出偏差（同权重、topk→全注意力的反事实） | 层均 5.51%（最小层 0.019%） | 层均 3.67%（最小层 0.0044%） | **> 0 ⇒ 干预活着** |

**逐层看（`results.json::arms.<arm>.operator_liveness.per_layer`）**：偏差在中间层极小
（topk32 的第 3/4 层 0.02%/0.06%，因为那几层注意力本就几乎只在最近 30 个键上分配质量 ⇒
砍到 32 个键几乎不改变计算），在靠后的层变大（第 7/8 层 1.3%/1.0%）——**「稀疏在哪些层咬到」
本身就是一条可用的诊断信息**。

**一句话**：干预**是活的**，k 生效、选择按内容、每 200 步有落盘证据，与训练日志可逐点对上。

### 5.2 可失败单测（12 条，`tests/test_depth_ar.py`）

① 缺省关闭逐位还原 v1（含块类与 aux 无活性块）；② 掩码恰为「因果 ∩ 前 k 大」且每行保留数
= min(k, i+1)（与逐行排序参考实现逐位比对）；③ 选择**按内容不按位置**（把远键设成最高分，
top-2 必须选中远键、丢掉最近的非自身键）；④ 稀疏 softmax 只在被选键上有质量
（未选键权重恰为 0、行和 1、允许键 ≤ k 的行退化为全注意力）；⑤ 块公式逐位钉死
（含前 k 行 == 全注意力）与 stock 路径守卫；⑥ k ≥ T 与 stock `Block` **逐位一致**；
⑦ 参数量/初始化/键集与全注意力臂逐位相同（因果掩码是非持久 buffer，不进 state_dict）；
⑧ 守卫（非 dense / 与层间拓扑混用 / 非法 k / topk<1）；⑨ 开关必须改变前向且 k 生效
（k=1 偏差更大、k=T 回到基线逐位一致）；⑩ 位置重合度量的可解释性；⑪ `attn_sparse_probe`
在真实数据流上的口径（含探针不引入参数）；⑫ 反向可达 + **未被选键的 v 梯度恰为 0**
（「稀疏混合真的跳过了未选键」的梯度层证据）。

### 5.3 变异验证（5 处破坏全部抓红，`mutation_report.json`）

| # | 变异 | 破坏的语义 | 结果 | 抓到的测试 |
|---|---|---|---|---|
| 1 | `ignore-topk` | 块内不做选择（keep = 全因果掩码） | 红 ✓ | 块公式、开关活性 |
| 2 | `positional-select` | 改成「最近 k 个键」（位置选择） | 红 ✓ | 掩码计数、按内容选择 |
| 3 | `noncausal-leak` | 掩码改并集 ⇒ 放出未来键 | 红 ✓ | 掩码计数、稀疏 softmax |
| 4 | `unmasked-softmax` | softmax 不掩未选键 ⇒ 退化为稠密 | 红 ✓ | 块公式 |
| 5 | `k-ignored` | 建模时忽略 `attn_sparse_k` | 红 ✓ | 开关活性、探针口径 |

每次变异后都**逐字节还原**（`restored_byte_identical = true`，sha256 与 `MODEL.md` §2 一致），
还原后基线单测全绿。

## 6. 成本口径：理论 vs 实测 + 交叉点（契约 J 并列判据）

**理论（纯公式，`results.json::cost.theory` 与 `theory_scaling_vs_T`）**

| 量 | k=32 | k=64 | 公式 |
|---|---|---|---|
| 保留键数（朴素 k/T 口径） | −87.5% | −75% | `1 − k/T` |
| 注意力 FLOPs（**修正后**） | −43.75% | −37.5% | `(T − k)/(2T)`：QKᵀ 全矩阵因内容选择不可省，只省 `P·V` |
| 整模型每 token FLOPs | −6.25% | −5.36% | 注意力只占层 FLOPs 的 14.29%@T=256 |
| **KV 缓存 / 显存** | **−0%** | **−0%** | 选键需要全部 K/V ⇒ 缓存不能砍（**与位置稀疏的本质区别**） |

**实测（`results.json::cost.measured_*`，同机同时刻）**

| 口径 | 全注意力 | k=32 | k=64 | 比值 |
|---|---|---|---|---|
| 整模型一步 fwd+bwd（同进程、同 shape、同 optimizer，8 次中位） | 24.34 ms | 54.02 ms | 54.76 ms | **×2.22 / ×2.25** |
| 整模型 torch 峰值显存 | 0.807 GiB | 1.739 GiB | 1.739 GiB | **×2.15** |
| 真实训练一步墙钟（`wall/steps`，含启动开销） | 0.0300–0.0317 s | 0.0518 s | 0.0518 s | ×1.63–1.73 |
| 真实训练进程峰值显存（nvidia-smi） | 1.47 GB | 2.55 GB | 2.57 GB | ×1.7 |
| 注意力孤岛（同输入、同权重形状，B=32） | 3.70 ms | 8.30 / 8.43 ms | 8.30 / 8.43 ms | ×2.25 / ×2.28 |
| 孤岛·保留 SDPA 融合核的掩码实装（参考） | — | 7.04 ms | 7.47 ms | ×1.90 / ×2.02 |
| 孤岛·真稀疏 gather（**参考实现，B=8**） | — | 6.01 ms | 7.86 ms | ×1.63 / ×2.13 |

**读法（诚实分账）**：

1. **算法本征**：即使把实现做到「只对 k 个键做混合」（gather 参考实现），在 T=256 上
   仍然是 ×1.6–2.1 —— 因为选择本身要算全分数矩阵，而整模型的注意力占比只有 14%，
   省下的那点 FLOPs 换不回额外的选择/索引开销。**「内容 top-k 在 T=256 是净开销」是结论，
   不是实现 bug。**
2. **实现代价**：本实验为了「公式可逐位核对 + 变异可抓红」，用了显式 softmax 的稠密实装
   （×2.22–2.28），比保留 SDPA 的掩码实装（×1.90–2.02）多付约 15–20%。
3. **交叉点**：注意力占层 FLOPs 的比例随 T 线性上升（14.3%@256 → 40%@1024 → 72.7%@4096），
   理论整模型降幅 k=32 为 6.25% → 19.4% → 36.1%（**纯公式，未实测**）。
   要判断「哪一侧先回本」需要长 T 的实测（本实验预算与契约只覆盖 T=256）。

### 6.1 实测 GPU 墙钟与显存（本实验的真实账）

单卡 RTX 4090 24GB，**共享**（运行时另有 llama-server 两个进程占用 ≈3.6 + 6.3 GB，
总占用 8.2–10.7 GB，利用率 77–96%）；GPU 任务串行提交，无并行训练。

| 项 | 实测 |
|---|---|

「3 主臂 + 只重跑基线臂、评测批次保持 20、显式批准超支」。**实测落到 33.21 min
（未用满预算），因此没有触发任何砍项**；本条记录的教训是：**用别条线的步时
（6.5 min/臂）估成本会低估本干预（实际 10.35 min/臂，2.2× 步时的直接结果）。**

## 7. 收敛对账（SCHEMA §16）与重跑散度

### 7.1 同方法 loss 斜率（三臂同一窗口比例、同一最小二乘算法）

| 臂 | 末 25% 窗（step 9000→11999，16 点） | 窗内后半段 | loss（窗口起→止） |
|---|---|---|---|
| `full` | **+0.00251** nats/1k 步 | +0.02214 | 1.0501 → 1.0421 |
| `topk32` | **+0.00369** | +0.02168 | 1.0537 → 1.0520 |
| `topk64` | **+0.00308** | +0.02076 | 1.0463 → 1.0513 |

斜率 spread = **0.00118** nats/1k 步（约 0.17% 的相对差）⇒ **三臂收敛速度相同**，
Δ 是**水平差（质量）**，不是「谁收敛得更快」。训练 loss 在末尾几步几乎重合
（1.042–1.052 的批间抖动 ±0.05 覆盖了三臂差），说明 12k 步时质量差异主要体现在
**评测分布上的泛化**而不是训练 fit——这与「k=32 去掉的是远距离信息」的解释一致。

**更长训练点（2×）未做**：契约 J 的收敛对账只要求同方法斜率，预算（§8）与 12k 步的
字节对照也未包含 24k 双跑 ⇒ 本结论只能作**快照结论**，不得外推为渐近结论。

### 7.2 重跑散度（契约 J 要求）+ 阈值附近的配对噪声

| 量 | 值 | 口径 |
|---|---|---|
| 同 seed 重训基线臂（`full-r2`）bpc | 1.5279 vs 1.5304 ⇒ **0.0025** | 配对：同 20 批逐批差的均值 **+0.00253 ± 0.00252**（t = 1.0，12/20 批同向） |
| 独立交叉参考（ticket 30 E 线，同配置 d256/L8/mlp4/12k/bs32/seq256/seed0） | **0.0033** | `archive/wiki-legacy/axes/C-vertical/C3-inter-layer-topology/.../analysis.md` §1：该批新训 sequential 1.5254 vs 历史 1.5287；**跨 run + 跨代码版本**，只作量级参考，不替代本次重跑 |
| 本次三臂配对差 | k=32：−0.0166 ± 0.00215（20/20 批同向，t = −7.7）；k=64：−0.0095 ± 0.0023（16/20 批同向，t = −4.1） | 同一 20 批评测位置，配对相减 |

读法：Δ(k=32) = −0.0166 是**重跑散度（0.0025）的约 6.6 倍**，且 20/20 批方向一致 ⇒ 越线判读
可信；但它只比判据阈值 0.014 大 19% ⇒ 按失败决策树，这条结论标注为「**判据线附近的越线**：
快照口径、n=1 seed、方向与剂量单调（k 越小越差）支持真实，但复现时需要更多 seed 才能把
『越线幅度』钉死」。

## 9. 失败决策树走查（为什么归因到「设计在该设定下无头寸」而不是 bug）

| 症状 | 诊断顺序 | 本实验的排除证据 |
|---|---|---|
| 结果坏 → ① 实现 bug？ | 12 条可失败单测 + 5 处变异全部抓红并逐字节还原 + 活性量逐位对账（30.0625 / 56.125）+ 关→v1 逐位还原 + 参数量/初始化逐位相同 | **排除**（实现层没有任何未解释的偏差） |
| ② 测量问题？ | 同批配对差、配对 SE、20/20 批方向一致、重跑散度 0.0025、评测口径三臂一致 | **排除**（差异不是噪声） |
| ③ 规模问题？ | 13M / 98.3M token / T=256 是**本仓库的标准小规模位点**；此处注意力的实测「内容 ∩ 最近 k 窗口」重合度 77–86% ⇒ 注意力本来就相当局部 | **部分成立**：远距离信息在本规模/本任务上的权重本就小，砍掉它反而伤质量 ⇒ 说明「内容 top-k 的头寸在长上下文」这一假设在本实验**无法被检验**（T 太小） |
| ④ 设计问题？ | 上面的排除法把结论压到「设计在这个设定下无头寸」：k=32 越线、k=64 小损伤、成本为负 | **记为否证（在该设定下）**，并把「什么条件下才可能有效」写进 §0（长 T + 自定义稀疏核 + 与位置稀疏同台对照） |

**同时必须记录的负面结论（同等入账）**：
① 「按内容选键」**结构性地不能省 KV 缓存/显存**（要选必须先有全部 K/V）——这条会直接影响
`A9/A10/M2`（保留/压缩）三格的路线选择：想让缓存变小，必须走**位置窗口式**或**可提前丢弃**的稀疏，
而不是内容 top-k；
② 稀疏注意力对**浅层读出**的伤害（tf@4 0.4497 → 0.3299/0.3798；depth-4 bpc 3.1999 → 3.7954）
远大于对最终深度（depth-8）的伤害 ⇒ 若 RAP 的出口资产路线与稀疏注意力结合，需要单独记账。

## 10. 口径标注与未决问题（不得外推的部分）

- **口径**：全部质量数字 = matched-step 快照（12k 步 / 98.3M token / seed 0 / clean bpc，
  depth-8 读出，20 个 eval batch × 16 × 256 = 81,920 个评测 token）；成本数字分三个口径
  （整模型步时 ms、进程峰值显存 GB、FLOPs 公式）**分别标注**，互不换算；
- **n_seed = 1**（契约未授权补 seed）；重跑散度只覆盖基线臂（主 Agent 裁决，见 `README.md` §5）；
- **2× 更长训练点未做** ⇒ 不得把 Δ 当作渐近差；13M/T=256 的结论**不得外推到长上下文或更大规模**；
- 规模交叉点表是**公式外推**，不是实测；
- 本实验**没有**回答：按位置窗口稀疏 vs 按内容稀疏谁更好（本切片只测内容 top-k）；
  也没有测生成段/长上下文质量（`generation_quality` 属非 dense 形态，未在本次电池内）。
