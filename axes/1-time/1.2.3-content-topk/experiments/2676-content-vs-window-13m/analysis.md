# 2676 · 同可见键数下「按内容选」对「按位置选」：判读

## 0 人话摘要（先说结论，再上表）

**同一条 32 键的预算，「按内容挑」比「只挑最近的 32 个位置」好 0.078 bpc —— 两个种子都这么答。**

bpc（每字符比特数，越低越好）是语言模型的压缩率指标。seed 0：1.53041（全因果基线）→ 1.54704
（按内容挑 32 个键）→ 1.62503（只看最近 32 个位置）；seed 1：1.54084（按内容）→ 1.61761（最近位置）。
也就是说：

- 只看 32 个键这件事本身要付 **0.095** 的价（seed 0：1.53041 → 1.62503；seed 1 的窗口税同量级）；
- 同样只看 32 个键，**按内容挑**只付 **0.017** 的价（1.53041 → 1.54704）；
- 两者之差 **+0.07799 / +0.07677**（Δ = 位置窗口 − 内容 top-k，正 = 内容更好；seed 0 / seed 1），
  两 seed 都是 20 批评测窗口**全部同向**，t = 11.28 / 11.71，两 seed 差 **0.00122**（小于两个臂各自的
  跨 seed 散布 0.0062 / 0.00742）。k 放大到 64 时（只有 seed 0）差 **+0.03701**（t = 8.05，
  20/20 同向）——剂量一致：k 越接近全因果，两者越靠拢。

**所以旧读数「内容 top-k 净亏 0.0166」的正确读法是**：亏在「只让每个 token 看 32 个键」，
不亏在「按内容挑」——按内容挑恰恰是把 32 键预算用出最好效果的那种挑法（相对最近的 32 个位置
回收了 82% 的窗口税）。

**它买不到的东西（成本侧，如实报）**：按内容选必须先算完整 `T×T` 分数矩阵才知道哪些键最相似，
所以**每位置 KV 字节一个都省不下来（结构性 −0%）**；按位置选在结构上能省 87.5%（k=32）/75%（k=64），
但本实装是稠密 bool 掩码，这个省幅**没有兑现为实测**。两件事合起来：**内容选择是质量杠杆，不是成本杠杆。**

**证据的身份**：主判 k=32 的那一对有 **两个 seed**（seed 0 复用 `2614` 的两臂、seed 1 是本轮新训的两臂，
配方逐字段只换 `--seed`）⇒ n=2，两 seed 同向且各自越 0.014 带 5.6 / 5.5 倍，按 `README.md` §3 预登记的
升格规则，主判从「临时结果（n=1）」升为 **n=2**。`full`（基线）与 k=64 的那一对仍是 seed 0 单 run（n=1），
所以「窗口税有多大」与 k=64 的剂量点仍只作单 seed 读数。

## 1 判决回答的是哪个问题

`1.2.3` 的旧证据（`2614-topk-sparse-attn-13m`）把内容 top-k 对的是**全因果**，那条差里混了两件事：
「少看键的代价」与「按内容挑相对按位置挑的增量」。本实验只拆后者：**每行可见键数逐行相等**
（都是 `min(k, i+1)`，都含自身 `j = i`）的两臂，唯一差别 = 这些键按**内容**挑还是按**位置**挑。

**k=32 两 seed 同向且各自越带 ⇒ 主判 n=2**（`README.md` §3 的升格规则）：两 seed 差 **0.00122**，
小于两个臂各自的跨 seed 散布（0.0062 / 0.00742）⇒ 这个差不是种子噪声，也不靠单个
seed 的快照。落盘字段：`results.json::cross_seed.delta_by_seed`、`::cross_seed.same_direction = true`、
`::cross_seed.seed_spread_bpc`（两 seed 的配对检验各自在 `::cross_seed.paired_stats_by_seed`）。

剂量方向一致：k 越大两臂越接近全因果，差从 0.078 收到 0.037。**判据③（每位置缓存字节）方向相反**：
内容选择结构性 −0%、位置选择结构上 −87.5%/−75%（本实装未兑现）。

## 7 这次判决改了哪一条旧读法

`1.2.3` 的 `conclusion` 原先只写着「内容 top-k 在 T=256 上净亏」，容易被读成「内容选择没用」。
本次补上位置对照后，那句话要读成：**净亏是「每 token 只看 32 个键」的窗口税，而内容选择是同等
键数下最好的那种挑法**。阈值判读（`-0.01663` 相对 0.014 带的边缘性）不变，本实验没有改它。

## 8 边界（不能从本实验读出来的东西）

- **不能**读成「内容选择在长上下文会回本」：T 固定 256，长 T（≥2048）未测，交叉点仍只有公式外推。
- **不能**读成「内容选择能省缓存/显存」：结构性 −0%，这是本算子的定义性质（必须先算完整分数矩阵）。
- **不能**把 `+0.07799 / +0.07677` 当作跨格常数：这是 13M / L=8 / T=256 / enwik8 / 12k 步、两个 seed
  的两个配对点；n=2 只说明这个差**不依赖单个种子**，不说明它在别的尺度或别的 k 上照样成立
  （k=64 只有 seed 0，且差只有 0.037）。
- **不能**把「按内容挑」的收益读成「不连续性」带出来的：本轮**没有**做「随机选 32 个键」的毁源对照
  （`docs/methodology.md` §2 对 n=1 正结论点名的那条），所以「好过窗口」只证明内容信号胜过位置信号，
  没有排除「任何非连续掩码都更好」这一解释（缺的成本写在 `1.2.3` 的 `gaps` 里）。
- **不能**把一步耗时差当成本结论：共享卡上漂移大，只作申报。
