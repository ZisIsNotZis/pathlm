# CRITIQUE — R6-moe-scale（独立批判审计，fork=false）

## ① 是什么
MoE：用稀疏路由把"参数量"与"每 token FLOPs"解耦。本格把它登记为"同 FLOPs 更多参数"的参照线（与 `W2-expertization` 同格）。

## ② 对着什么 sota，我们偏离在哪
业界标准：Switch / GShard / Mixtral / DeepSeek-MoE / ST-MoE（`记忆·未核`）——**全部在 ≥1B 规模**。我们：**零本地实验**（`catalog.yaml:1280–1286`、`local: {}`），且 `axes/R-references/PRIOR_ART.md` §4 自认"**R6 在 13M 尺度是否有公开对照（规模远小于 MoE 典型规模）——未找到**"。

## ③ 五类问题逐条判定
- **开倒车：无。**
- **过程错误：有（制度层）。** R6 被 PRIOR_ART §2 判 `(a)` 并用 `记忆·未核` 支撑「业界结论」——同 R2 的 `SCHEMA.md §21` 违规。更要紧的是：**它想当参照线却没有可比数字**（13M 无公开对照），所以现行表述"MoE 已在 Mixtral/DeepSeek 上证明"对本项目的 W2 判据**不可用**。
- **结论错误：n/a**（无本地数字），但"用稀疏路由…是保容量减计算的成熟路线"被放在本仓的 `industry` 里，容易被读成"W2 值不值得做"的答案。13M/98M token 的 char-LM 上 MoE 是否回本，业界没有答案。
- **无意义：否——相反，这是 R 轴里最该做的一格。** 它直接决定 `W-width`（W2/W5）的判据线：如果 13M 上同 FLOPs 的 MoE ≥ dense，则"保容量减计算"是正路；否则 W 轴的稀疏方向在本尺度不成立。
- **值得做：是（立项）。**

## ④ 建议动作：立项（不要停在「业界结论」）
- 契约：13M、同 FLOPs 对照 dense、top-1 与 top-2 两档、2–4 专家（细粒度另立）；判据 = **同 FLOPs 质量**（clean bpc）+ **负载均衡**（专家使用率活性量，非零且不坍缩）+ 内存；成本按 `SCHEMA.md` 实测步时估（`tax` 字段里现写 25–40 min/臂）。
- 必须给"等参数对照"或"同 FLOPs 对照"两条之一，不得只与弱对照比（`SCHEMA.md §15`）。

## ⑤ 正确的验证方式
- **该涨**：同 FLOPs 下 MoE 的 clean bpc 应优于 dense（业界大模型上成立；13M 上**未测**）。
- **该跌**：无。
- **必须不变**：每 token FLOPs 与 dense 相等；路由不坍缩（专家使用率熵 > 0，且 top-1 路由的最差专家占比不得为 0）；同 seed / 同 token 预算。
