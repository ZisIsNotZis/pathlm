# 2621 · KV 预算图剩余缺失组合 —— 判读

> 契约：同目录 `README.md`（判据同 V1）。原始数据：`results.json`；一张总表：`table.md`；
> 图：`chart.png` / `chart.txt`；逐条对账：`reconcile_numbers.py` → `reconcile_report.json`。
> 术语（第一次出现就地解释）：
> **bpc** = 每字符比特数（语言模型的交叉熵，越低越好）；
> **KV cache** = 自回归解码时缓存的历史 K/V（访存瓶颈，也是内存大头）；
> **头共享 GQA/MQA** = 多个 query 头共用一组 K/V 头（GQA 2 组、MQA 1 组），直接按比例降 KV 字节；
> **int8 / int4** = 把每个 K/V 值分别用 1 字节 / 0.5 字节存储（相对 fp16 的 2 字节）；
> **窗口** = 每个查询只看最近 d 个位置（丢掉更远的 key）；
> **锚点（sink）** = 额外让最前几个位置恒可见；
> **chance** = 瞎猜的准确率（本题 1/64 = 0.0156）；**地板** = chance + 2σ（Wilson），≤ 它读作
> 「在该任务上不可分辨」，不是「机制无效」（SCHEMA §19）；
> **Wilson 95% CI** = 小样本比例的置信区间；两臂 CI 不重叠才算召回差异可分辨。

## 1. 人话摘要

这张图只回答一个问题：**把 KV cache 压到同样的「每位置字节数」预算，哪种压法更划算。**
上一批（`2620`）测了三种组合（GQA×int8、MQA×int8、窗口×锚点）；这一批补齐五种仍缺的优先组合
（`GQA×int4`、`MQA×int4`、`窗口×int8`、`GQA×窗口`、`锚点×int4`），并把 2619 的 14 点 + 2620 的 5 点
+ 本批 8 点**全部在同一进程、同一条评测路径上重测**，落成一张含所有已测点的总表（`table.md`）。

**一句话结论**：`int8` 叠在窗口/锚点上几乎是免费的（相对「只用窗口」的 bpc 只差 +0.0003 / +0.0001，
远在 0.014 噪声带内）；但 **`int4` 叠在头共享上是亏的**——`GQA×int4` 比单独 `GQA` 多付
**+0.096 bpc**（是单用 `int4` 的 +0.0457 的 **2.1 倍**），`MQA×int4` 多付 **+0.196 bpc**（**4.3 倍**），
且两条腿的召回也一起掉（copy 分别 −2.9pp / −7.2pp，Wilson 95% CI **不重叠**）。
在**同为 768 字节/位置**的预算上，最优解是 `MQA×int8`（bpc 1.4941、copy 0.2448），
明显优于 `GQA×int4`（bpc 1.5925、copy 0.1396）、`GQA×窗口64`（1.5591 / 0.0658）与
`窗口32×int4`（1.6435 / 0.0814）。**所以「叠加更省」这个说法只对 int8 成立，对 int4 不成立。**

## 2. 干预活性（SCHEMA §10）

本实验不训练、不改权重，只改推理期的可见集与 KV 存储精度，因此活性量量的是**推理期实际通路**：

- **KV 量化因子**：`int8`/`int4` 档的 `quant.rel_err > 0`（真改了数值），`fp32` 档恒为 0（恒等）；
- **可见性因子**：`window`/`anchor` 档 `dropped_frac > 0`（掩码真挡掉了因果对），
  锚点档 `anchor_contribution_pairs > 0`（锚点位置真的对末端查询可见）；
- **头共享因子**：`qkv_out_width != 3·d`（GQA 的 K/V 半边真的更窄）。

逐点数值见 `results.json::points[*].activity`；`reconcile_numbers.py` 的第 6 组断言全部非零/一致。
**结果：干预是活的**——两个因子的活性量在每个组合臂里都非零且与 mode 一致。

点——即被 int4 量化破坏的主要是语言的干净 bpc（依赖），而锚点通道的**召回**在这一样本量下掉幅

**不得**写成「锚点召回没受损」。反之，本批**没有**出现「bpc 近无损但召回崩」的相反不一致点。

## 4. 等字节对照（同横轴、同口径读法，判据 C1 + §17.11）

| `gqa_win64` | 头共享(2 组) × 窗口 64 | 1.559100 | 0.0658 | 0.0088 |
| `gqa_int4` | 头共享(2 组) × int4 | 1.592538 | 0.1396 | 0.1611 |

在**同一字节预算**上，`mqa_int8`（bpc 1.4941，最接近全精度 `fp16` 1.4836）**全面领先**：
它比 `gqa_int4` 好 0.098 bpc、召回高 10.5pp；比 `gqa_win64` 好 0.065 bpc、召回高 17.9pp。
⇒ **「先减 KV 头、再上 int8」比「GQA + int4」或「GQA + 窗口」更划算。**

同预算下仍是头共享族（`mqa` / `gqa_int8`）领先；窗口族即使叠 int8 也顶不上头共享。
**单点不外推（§17.11）**：`gqa_int4` / `mqa_int4` 是**单点**，只描述该点，不外推成「int4 在头共享上随规模如何」。

## 5. 与既有结论的关系

- **承接 2620**：2620 的结论「int8 叠头共享两腿近无损」在本批被**扩展**到窗口/锚点：
  `int8` 叠窗口/锚点同样近无损（增量 1e-4~3e-4）。⇒ 图上 `int8` 是一个「**通用可叠因子**」。
- **否证「组合更省」的普适说法**：int4 不是通用可叠因子——它在头共享上被放大（2.1×/4.3×），
  在锚点上也被放大（1.9×/1.2× vs 单用 int4 的 0.0457）。这与「int4 有明显质量损失」的既有读数
  （R1 `2614`：int4 +0.0457）一致，但**叠加会进一步放大**是本地新发现。
- **锚点通道不是通用召回杠杆**（A3 原结论）在本批再次成立：带锚点的点 copy@src0 明显高于
  src96/191（如 `win32_anchor32` src0 0.2471 vs src96 0.0176），锚点只救锚区内源。

## 6. 混杂与口径声明

- **参数量混杂**：GQA/MQA 参数量比 MHA 少 8.75% / 10.21%（W3 自述缺口），所有含头共享的臂
  继承该混杂——本批的 `GQA×*` 结论是「该架构 + 该压缩」的合读，**不是**「头共享净代价」。
  等参数对照臂仍未做（见 `results.json::still_missing`）。
- **口径**：横轴 = **解析字节/位置**（`2·n_layers·n_kv_heads_eff·head_dim·value_bytes·kept/T`），
  不是实测显存（判据 C2）；bpc = clean bpc（因果移位 CE token 平均，同一窗口序 `window_seed=2`）。
- **实测显存**：全臂共用一进程，评测期 GPU 峰值 **462.5 MiB**（上界，逐臂不下降——评测实现把
  K/V 立刻反量化、窗口按掩码取子集，SDPA 仍算 T×T 分数矩阵；见 `results.json::memory_convention`）。
- **跨 run 可控性**：2619 的 14 个参考臂、2620 的 5 个组合臂在本实验重测**逐位一致**
  （`max_bpc_abs_diff = 0.0`，见 `results.json::reproducibility_vs_2619` / `reproducibility_vs_2620`）。

## 7. 仍缺的组合（W1 交付项：显式列出）

以下组合**本图仍未测**（逐条来自 `results.json::still_missing`）：

1. **GQA/MQA × int4 × 窗口（三因子）**：本批只叠两个因子；三因子需单独授权。
2. **头共享 × 窗口 × 量化（`GQA×win×int8`）**：本批 `combo_mask` 的 GQA 臂只测了 fp16（纯掩码）。
3. **权重 / 激活量化**：R1 只测 KV cache；本项目零经验（先按 §21 分诊）。
4. **MLA 低秩 KV**：零经验；横轴公式需先扩展为 `2·d·r`。
5. **摘要压缩（M2 选项）**：压缩率依赖摘要器，不是单一乘式。
6. **长 T（>256）下的窗口 / 驱逐 / 量化**：本图全部点在 T=256。
7. **各臂的实测显存峰值（真 cache 实现）**：本实验只报解析列。
8. **召回腿的真实文本针（needle v3）跨族**：2615 只给了 trunk 窗口档；本批组合同样缺该第二召回腿。
9. **GQA/MQA 的等参数对照臂**：去掉参数量混杂的净代价判读仍未做。
