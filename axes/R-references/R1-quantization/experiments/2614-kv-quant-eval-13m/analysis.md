# 2614 · KV 量化参照线 —— 判读（analysis）

## 0. 人话摘要

这条研究线做的事：**把对话缓存（KV cache）里「记下来的每个位置的特征」存得更省内存
（int8 / int4），质量会掉多少？** 这是参照线——以后任何说「我能省内存 / 我能丢掉一部分
信息」的方案，都必须先跟「直接把缓存存成低精度」比一比；比不过就不算创新。

相对普通 decoder-only transformer 改了什么：**什么都不改**。权重一个不动，模型照跑，
只是在推理读注意力缓存那一步，把存进去的 K/V 从 fp16 精度压成 int8 / int4，用的时候
再还原。相当于「同一本书，把笔记抄得更潦草一些」，参数量、计算量、训练都不变。

怎么测的：同一个 13.5M 的已训练小模型、同一批 enwik8 评测窗口（每字符预测下一个字符，
越低越好，单位 bpc），只把缓存精度从 fp16 换成 int8 / int4，量 bpc 掉了多少、缓存省了多少。

测出来多少（越低越好；普通变压器同尺寸基线 bpc ≈ 1.484）：

| 缓存精度 | bpc | 相对 fp16 掉多少 | 缓存每位置省多少 |
|---|---|---|---|
| fp16（基线） | 1.483571 | — | 12288 字节 |
| int8 | 1.483721 | **+0.00015**（几乎看不出） | 6144 字节（−50%） |
| int4 | 1.529232 | **+0.0457**（明显变差） | 3072 字节（−75%） |

参照系：本项目方法学定的「噪声带」= 0.014 bpc（差得比这还小就分不出真假）。所以
**int8 缓存 = 省一半内存、几乎不损质量**（掉了 0.00015，比噪声带小 90 倍）；
**int4 缓存 = 省四分之三内存，但代价 +0.0457**（是噪声带的 3.3 倍，真掉）。

结论与下一步：int8 这条路线**近无损**，写进参照线——后续任何压缩主张，若省的内存
不如 int8 多（<50%）而质量损失更大，就没有意义；若目标是 >50% 压缩，必须打败 int4
的 +0.0457 这条线。本实验只测了「int8/int4 各自」的静态通道量化，没测 int4 加分组
（group-wise）或按 token 的方案——那是后续可选的改进方向，但本条参照线的数字已经落定。

## 1. 结果（多维指标表）

数据来源：`results.json::quant_rows` / `results.json::memory_reduction_vs_fp16`；
逐 batch 活性量在 `kv_quant_log.jsonl`（每 batch 一行）。

| 维度 | 指标 | fp16（基线） | int8 | int4 |
|---|---|---|---|---|
| 代价（质量） | clean bpc（越低越好） | 1.483571 | 1.483721 | 1.529232 |
| 代价（质量） | damage = bpc_mode − bpc_fp16 | 0.0 | **+0.000150** | **+0.045661** |
| 代价（质量） | Δ = bpc_fp16 − bpc_mode（正=改善） | 0.0 | −0.000150 | −0.045661 |
| 有效性 | vs 0.014 方差界 | — | **近无损** | **有损（3.3× 带）** |
| 收益（内存） | KV cache 每位置字节 | 12288 | 6144 | 3072 |
| 收益（内存） | 相对 fp16 下降 | — | **50.0%** | **75.0%** |
| 收益（内存） | 每位置值数（K+V，12 层×8 头×32 维×2） | 6144 | 6144 | 6144 |
| 收益（内存） | scale 总开销（per-channel，fp16 scale） | 0 | 12288 B（与序列长无关） | 12288 B |
| 可控性 | 复现性（同 seed 重跑 Δbpc 差） | — | 4.83e-07 | 2.58e-07 |
| 活性 | changed_frac（数值被改变比例） | 0.99985 | 0.99976 | 0.99988 |
| 活性 | rel_err = Σ\|err\|/Σ\|x\| | 1.76e-4 | 6.84e-3 | 1.24e-1 |
| 活性 | mean_abs_err | 2.11e-4 | 8.18e-3 | 1.49e-1 |
| 活性 | max_abs_err | 7.81e-3 | 6.67e-2 | 1.221 |
| 副产品 | clipped_frac（超出 qmax 被截） | 0 | 4.53e-5 | 0 |
| 副产品 | fp32 档 vs 释放版前向 | 逐位相等（1.483569） | — | — |

**干预是否活着**（SCHEMA §10）：**活的**。三档的 `changed_frac ≈ 1.0`、
`rel_err` 随 bit 数单调（fp16 1.76e-4 < int8 6.84e-3 < int4 1.24e-1），
且 int4 的 damage 是 int8 的 **304×**——精度真降了、且按预期排序；
单测另钉住「int4 误差 > int8 误差」「int4 改 logits」。恒等档 fp32 的
`changed_frac = 0`（数值一字未改），是活性判据的阴性对照。

**逐条判据**（`results.json::criteria`）：

- int8：|Δbpc| = 0.000150 < 0.014 ⇒ **「近无损」，写入参照线** ✓
- int4：damage = 0.045661 ≥ 0.014 ⇒ **记其代价 +0.0457 bpc** ✓
- 内存下降已给出：int8 −50%、int4 −75% ✓
- （附带）fp16 相对 fp32 的 damage = −2e-06 ⇒ fp16 基线本身近无损。

## 3. 三道对账（SCHEMA §12）

支撑假设的数字 = int8 近无损（Δ=−0.00015）、int4 有代价（damage 0.0457）、
内存下降 50%/75%。

1. **算术对账**
   - 往返误差上界：对称取整 ⇒ `max|err| ≤ 0.5·scale`。实测 int8
     `max_abs_err = 0.066712` vs `0.5·scale_max = 0.066723` —— 相等（差 1.1e-5，
     浮点舍入）；int4 `1.220645` vs `0.5·2.441447 = 1.220724` —— 相等。上界成立。
   - bpc 差：1.483721 − 1.483571 = 0.000150 ✓；1.529232 − 1.483571 = 0.045661 ✓。
   - 内存：2(K,V)×12 层×8 头×32 维×2 字节 = 12288 B/位置；÷2 = 6144、÷4 = 3072，
     下降恰为 0.500/0.750 ✓。
   - 单调性：rel_err(int4)=0.1242 > rel_err(int8)=0.00684 > rel_err(fp16)=1.76e-4 ✓。
2. **任务对账**：对照臂（fp16）与实验臂（int8/int4）是**同一模型的同一前向**，
   输入是同一批 enwik8 评测窗口（同一 `Generator(seed=2)` 与 `batch()` 顺序，
   与 2610 depth_curve 基线同序），预测同一 next-char 目标，位置集相同。
   部署对应：同一模型上线时把 KV cache 存成对应精度。三档量的是**同一件事**。
3. **口径对账**：三档 + fp32 全部 matched-step（同一 checkpoint、同一 24×16 窗口、
   1.1-epoch 快照口径）；fp32 档与释放版 dense 前向**逐位相等**（`abs_diff = 0.0`），
   释放版 bpc = 1.483569 vs 2610 记录 1.4836（差 3.1e-05）。口径一致 ✓。

**结论**：三道对账**全部通过**，无需 ERRATA。

## 4. 方差 / 噪声底（`results.json::noise_floor`）

跨评测窗口 seed（3–8，各 6 个）的配对 damage：

| 档 | 平均 damage | 跨窗口 σ | 每个 seed 的 damage |
|---|---|---|---|
| fp16 | 0.0 | 0.0 | 全 0（配对自比） |
| int8 | 0.000136 | 6.9e-05 | 1.84e-4, 2.21e-4, 1.27e-4, 1.69e-4, 7.2e-5, 4.1e-5 |
| int4 | 0.043796 | 0.001272 | 4.47e-2, 4.15e-2, 4.51e-2, 4.44e-2, 4.35e-2, 4.35e-2 |

- int8 的 damage（≈1.4e-4）落在跨窗口噪声（σ≈7e-5，2σ≈1.4e-4）量级内 ⇒
  与「零损伤」在统计上不可分 ⇒ **近无损**成立。
- int4 的 damage（0.0438）是 34σ 之外 ⇒ **真实有损**，非噪声。

## 5. 失败决策树（无效时的处置路径，按 methodology §14 顺序）

| 症状 | 诊断 | 处置 |
|---|---|---|
| fp32 档 ≠ 释放版前向 | **实现 bug** | 先修前向复刻（本实验 fp32 档逐位相等 ⇒ 该分支已排除） |
| int8 也大幅劣化（≥0.014） | 量化实现可疑 | 先查 scale/通道轴/qmax（变异 M1/M2/M4 覆盖），再看是否为该模型特性 |
| 三档 damage 全为 0 | 干预是死的 | 查 `changed_frac`（本实验 ≈1.0 ⇒ 活的）；变异 M3 覆盖「假精度」 |
| 结果不可重复 | 方差 | 同 seed 重跑差 4.8e-07 ≪ 0.005 ⇒ 已排除 |
| 数字互相矛盾 | 口径 | 三道对账；本实验已过 |

## 6. 口径标注

- **bpc**：clean bpc（越低越好），因果移位 CE 的 token 平均；**1.1-epoch 快照口径**
  （12k 步 / 98.3M tokens，未收敛），**matched-step**（同一 checkpoint、同一数据流）。
- **内存**：**解析** KV cache 占用（`per_position_bytes` = 部署关心的量）；评测期实现
  立即反量化，故 **GPU 实测峰值不随档下降**（net 132 MiB 三档相同）——这不是「实测
  内存下降」，是解析口径。
- **Δ 符号**：`Δ = bpc_对照(fp16) − bpc_实验(mode)`（正 = 改善）；damage = −Δ。
- **活跃度**：per-channel = 每 (head, head_dim) 一个 scale，沿 batch+token 取 amax
  （KIVI K 侧口径）；对称、零点 0。
