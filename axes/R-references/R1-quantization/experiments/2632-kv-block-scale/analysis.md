## 0. 人话摘要（先读这一段）

**这是干什么的。** 把 Transformer 推理时的 KV 缓存（注意力记忆）压成 int8 / int4 时，除了数值本身，
还要为每段数值存一把「标尺」（scale，用来把整数还原回实数）。**标尺存在哪、能摊多薄，决定量化到底
省不省内存。** 本实验只改这一件事，把 `2631` 的 27 点预算图在**块标尺（沿 head_dim 每 G 个值共用一把
标尺，G=32 为主）**下重测，并把字节账从「只算值」改成**部署字节（值 + 标尺）**。

**为什么重测。** `2631` 用**逐值标尺**（每个数值配一把 fp16 标尺）测出「int8 = 1 字节值 + 2 字节标尺
= 3 字节/值，比不压还费」，据此得出「量化在任何拓扑上都是内存负收益」。这是**与业界相反的结论**，
根因是标尺口径：业界标准是**按块/通道摊薄**（一块 32 个值共用一把标尺 ⇒ 每值只多 2/32 字节）。
审计指出本仓自己早就算过通道标尺的总开销与序列长度无关，是那次「因果化修复」把它降级成了逐值标尺。

**测出来两件事。**

1. **「8 位近无损且省约一半」这条参照线成立**——但要**换对摊薄轴**。沿 `head_dim`（块内 32 个值都是
   同一个 token 的，与 token 轴无关）摊薄标尺：int8 每位置 **6528 字节**（不压是 12288），**省 46.875%**，
   而 clean bpc 从 1.483571 到 **1.483672（+0.000101）**——**略差、正号**，但**远低于任何可排序线**
   （本格在力排序带 0.036324；3 个评测窗口的配对 Δ 均值 +4.1e-05、区间 [9e-06, 1.01e-04]）。关键是这个
   摊薄**不牺牲「过去的读数绝不被未来影响」**：标尺只由当前 token 自己的值决定，前缀不变性两条均 True，
   且**不需要 staging**。
2. **「省一半」只在一种实现下不成立**：逐值标尺（`2631` 的生产实现）⇒ int8 = 3 B/值 = fp16 的 **1.5×**，
   反占内存。沿 token 轴摊薄（把 32 个相邻位置合成一块，`block_tok` / KIVI 的 K 侧）也能省到 1.0625 B/值，
   但代价是**块内过去位置的读数会被同块后续位置改写**（违反前缀确定 ≤ 31 个位置）——它不是免费的另一条路。

**顺带一句 int4 与同价对手。** int4 在块标尺下省 **71.875%**（3456 字节/位置），但 4 位确实有损：
纯量化臂 Δbpc **+0.022522**；**头共享 × 4 位**两条臂换块标尺后变差（`mqa_int4` Δ=+0.054794 可排序、
`gqa_int4` Δ=+0.009642 在力带下不可排序）——**归因待核**（见 §7）。另有一条**未测**的同价对手
**fp8**：解析 1.0 B/值、无标尺、×0.50，**比 int8+块标尺更省** ⇒ 不能声称 int8+块标尺是所有 8 位方案里最优。

## 2. 正面对照：新数字 vs 旧数字

**部署口径**：`2631` 的 (a) = 逐值标尺（每值 +2 B）；本实验主臂 = 块标尺沿 `head_dim G=32`（每值 +0.0625 B）。
非量化臂两列相同。Δbpc = 本实验 block − `2631` per_value（**负 = 块标尺质量更好**）。fp16 基线 = 1.483571，
不压部署字节 = 12288；**在力排序带 = 0.036324**（> 带才可排序）。

**两个质量量不得混用**：`damage_bpc` = 本臂 − 本族基线（头共享族含**头共享本身**的开销）；
`量化增量` = 本臂 − 同拓扑 fp16 臂（**纯量化因子**）。

**读法（按在力带 0.036324 读）**：

- **纯量化与 int8 组合臂**：换块标尺后的 |Δ| 从 1.6e-05 到 2.33e-04（`win32_int8` 的**量化增量** +0.000233
  是本列最大），**全部远低于在力带 0.036324** ⇒ 这些差异**不可排序**（不做方向结论）。
  int8「近无损」的**表述按实际符号**：与 fp16 的差为 **+0.000101（正号 = 略差）**，但远低于任何可排序线。
- **纯 `int4` 臂**：块标尺 **比逐值标尺更好**（Δ = **−0.002226**），且两条腿都省内存 ⇒
  **「块标尺丢通道分辨率 ⇒ int4 变差」这个通性说法被本批数据反驳**（见 §7）。
- **头共享 × 4 位**：只有这两条臂在换块标尺后**质量变差**（`mqa_int4` +0.054794 可排序；
  `gqa_int4` +0.009642 不可排序）。它们是**不同 checkpoint**（GQA/MQA 模型），**归因待核**（§7）。
- **等字节下另一条路**：沿 token 轴分块（`block_tok G=32` / KIVI）同样是 3456 字节/位置，但 int4 质量
  更好（1.4979 / 1.4969）——代价是**违反前缀确定**（见 §5）。

## 3. 部署字节账（值 + 标尺 + staging）

**公式**：`部署字节/位置 = 2(K,V)·L·n_kv_heads_eff·head_dim·(value_bytes + scale_bytes_per_value)·(kept/T)`。

**标尺每值字节（本实验实现，与 `kv_quant.quantize_kv(scheme=...)` 一一对应；标尺个数已与量化器实际产出对账）**：

| 方案 | 标尺轴 | 每值标尺 | 前缀确定 | int8 B/值 | int4 B/值 | int8 省幅 | int4 省幅 |
|---|---|---|---|---|---|---|---|
| `per_value`（对照，2631） | token（running） | 2.0 | ✔ | 3.00 | 2.50 | **−50%（反占）** | **−25%（反占）** |
| `block` G=8 | head_dim | 0.25 | ✔ | 1.2500 | 0.7500 | 37.5% | 62.5% |
| `block` G=16 | head_dim | 0.125 | ✔ | 1.1250 | 0.6250 | 43.8% | 68.8% |
| **`block` G=32（主臂）** | head_dim | **0.0625** | ✔ | **1.0625** | **0.5625** | **46.875%** | **71.875%** |
| `block_tok` G=32 | token | 0.0625 | ✘（≤31 位置） | 1.0625 | 0.5625 | 46.875% | 71.875% |
| `kivi` G=32 | K: token / V: head_dim | 0.0625 | K✘ V✔ | 1.0625 | 0.5625 | 46.875% | 71.875% |

- **`head_dim = 32` ⇒ 沿 head_dim 的块上限 = G=32**（= per-token 标尺）。G=64 要求块跨 token，**无法同时
  保持前缀确定**：标尺一旦跨 token 就必须么（a）用整块 max（块首位置的存储值被未来改写），么（b）保持
  前缀但标尺随前缀变化（不再摊薄）。⇒ **「省 50%」的极限在 G=32 处取到 46.875%**，再往下压只能让出因果。
  在 `head_dim` 更大的模型上 G 可以更大（同一行更长）⇒ 省幅更接近 50%。
- **标尺个数对账（P2-4）**：`quantize_kv` 把实际标尺数记进活性量 `n_scales`；单测断言
  `n_scales == values/G`（block/block_tok）与 `n_scales == values/head_dim`（kivi 的 V 侧）、
  `n_scales == values`（per_value）。实测 int8 臂 `n_values=6291456`、`n_scales=196608` ⇒ 比值 32 = G。✓
- **staging（非因果方案的额外记账，两套口径不得混用）**：沿 token 分块的回填必须留住原始 fp16 值 ⇒
  **持整块（最坏）**= G=32 个位置 = **393216 B/请求**（T=256 时 1536 B/位置）；
  **平均半块**= 15.5 个位置 = **190464 B/请求**（T=256 时 744 B/位置）。与目标精度无关、int4 也要留。
  **主臂 `block` 沿 head_dim 严格因果 ⇒ 不需要 staging（0）。**
- **同价诚实对手（未测）**：**fp8**（E4M3/E5M2 式）= 1.0 B/值、无显式标尺 ⇒ **6144 B/位置 = ×0.50**，
  比 int8+块标尺（1.0625 B/值、×0.53）**更省**。fp8 质量本实验**未测** ⇒
  **不得据此断言 int8+块标尺是所有 8 位方案里最优的**（`results.json::deployment_caliber.fp8_reference`）。
- **实测显存**：评测期 GPU 峰值 **1798.6 MiB**（`torch.cuda.max_memory_allocated`）。评测实现把 K/V
  **立刻反量化** ⇒ 峰值不随档下降，**不是内存价签**（判据 C2，解析/实测分列）。

## 5. 三道对账（SCHEMA §12）

1. **算术对账**：部署字节 = 值 + 标尺，逐点对账（`scale_caliber.deployment_bytes` 内部断言与判据 C1
   的旧值字节逐位一致，对不上直接报错）。`int8` 每值 = `1 + 2/32 = 1.0625`、每位置 = 6144·1.0625 = 6528
   （不压 12288 ⇒ 省 46.875%）；`per_value` 每值 = `1 + 2 = 3`、每位置 18432（= 1.5×）。
   **标尺个数**另与量化器实际产出对账（`n_scales`，见 §3）。取整误差上界 `|x̂ − x| ≤ 0.5·块标尺`
   （单测钉住；`clipped_frac = 0.58%` 是块内 amax 位置的浮点边界，非真剪裁）。
2. **任务对账**：质量两腿与 `2631` 同任务、同数据流、同位置集（`bpc_of` 逐位复现）；**质量数字与
   `block` 价签同源**（同一 `quantize_kv(scheme="block")` 前向）；非因果方案（`block_tok`/`kivi`）的
   质量数字**单列**，不挂到 `block` 的字节上。评测峰值不随档下降已单列。
3. **口径对账**：T = 256 固定；窗口/锚点臂 `kept/T` 与 T 有关（禁外推到别的 T）；量化臂每位置字节与 T
   无关；本批是**快照口径**（冻结 checkpoint，单 seed 训练、单 T、`head_dim=32`）。

   **本格自测方差与排序带（P1-2 修正后的口径）**：
   - **标准口径**（预登记）：配对 Δ（同一对照臂对在多个评测窗口重测）的区间，**≥5 个窗口**；
   - **本批只跑了 3 个窗口（<5）⇒ 不满足标准**，故**在力排序带 = 单臂跨窗口 bpc 极差
     = 0.036324**（更保守）；
   - **不用 `max|Δ|` 当带**：主表那个窗口（seed=2）的 Δ 恰为该 3 点 max ⇒ 当带会循环、不可证伪；
   - 3 点配对量只作**描述**：`int8(block) − fp16` 逐 seed = [+0.000101, +0.000013, +0.000009]，
     **均值 = +4.1e-05**、区间 = [+9e-06, +1.01e-04]。

## 6. 干预活性、对照与可控性

## 7. 失败与局限（「以为会怎样 / 实际怎样 / 为什么 / 排除了什么」）

1. **以为**：把标尺从逐值改成块标尺，质量只会略变、字节大幅下降——两边都赚。
   **实际**：int8 与 int8 组合臂确实如此；但 **头共享 × 4 位两条臂换块标尺后质量变差**
   （`mqa_int4` Δ=+0.054794 可排序；`gqa_int4` Δ=+0.009642 不可排序）。
   **端上并列的反证**：**纯 `int4` 臂上块标尺反而比逐值标尺更好**（Δ = **−0.002226**，超过自测描述量）。
   ⇒ 因此**「块标尺丢通道分辨率 ⇒ int4 普遍变差」这个通性说法被本批数据反驳**，
   **不能作为结论**。当前**归因待核**；候选解释（**未测**）：头共享后 KV 行的动态范围更大，
   使 per-token 块标尺相对更粗。**排除的解释**：不是「实现坏了」（单测+变异抓红、误差上界恒成立）、
   不是「换了任务/模型」（非量化臂逐位不变、bpc 与仪器逐位相等）。
2. **以为**：`head_dim` 分块本应能摊到 G=64、G=128，省幅趋近 50%。
   **实际**：`head_dim = 32` ⇒ 沿 head_dim 的块**上限就是 32**；G>32 只能跨 token，不可能同时前缀确定。
   **排除的解释**：不是「做不到摊薄」，而是**可摊销的轴只有非 token 轴**，其宽度就是 `head_dim`。
3. **以为**：逐值标尺是「因果性」的必然代价。
   **实际**：沿 `head_dim` 摊薄既严格前缀确定、又摊到 `2/G` B/值 ⇒ 逐值标尺并非物理下限，
   而是一种（最贵的）实现选择。**⇒ 撤回 `2631/budget_caliber.py::mixed_axis_note` 的
   「K 侧做不到非 token 轴摊薄」：本实验证明 K 沿 head_dim 分块可摊薄且保因果**（见 §9）。
4. **局限**：① 单 seed、单规模（13.5M）、单 T（256）、`head_dim=32`、快照口径；② 质量数字只覆盖
   列出的方案（未测 fp8 标尺、旋转/投影类量化、权重/激活量化）；③ 「KIVI」为 `记忆·未核`（本机联网
   不可用，未核对原文）；④ 本实验只做**推理期存储精度**，不改权重、不改结构；⑤ 排序带用的是保守的
   单臂跨窗口口径（3 窗口，未达标准的 ≥5 窗口配对口径）。

## 8. 结论（判据 ⑤）

- **「8 位近无损且省约一半」这条参照线成立**，条件是**沿 `head_dim` 摊薄标尺**（块标尺 G=32）：
  int8 每位置 12288 → **6528 字节（省 46.875%）**，clean bpc 1.483571 → **1.483672（+0.000101）**；
  **表述为「略差、正号、远低于任何可排序线」**（在力带 0.036324；3 窗口配对 Δ 均值 +4.1e-05），
  **不说「不可分辨」**；且**前缀不变性成立**（未来 token / 同批邻居都不改过去读数）、**不需要 staging**。
- **在什么实现下不成立**：**逐值标尺**（`2631` 的生产实现）⇒ int8 = 3 B/值 = fp16 的 **1.5×**，
  反占内存。这正是本仓此前「量化在任何拓扑上都是内存负收益」的来源。
- **int4 是另一档**：块标尺省 **71.875%**；纯量化臂 Δbpc **+0.022522**（正号）；头共享 × 4 位变差
  （`mqa_int4` 可排序、`gqa_int4` 不可排序），**归因待核**。
- **不是最省**：fp8（未测质量）解析 1.0 B/值、×0.50，比 int8+块标尺更省 ⇒ 不得声称后者最优。
- **沿 token 轴分块**（`block_tok` / KIVI 的 K 侧）同样省 46.875%，但**违反前缀确定 ≤ G−1 个位置**，
  且需 staging（393216 B/请求 持整块 / 190464 B/请求 平均半块 @G=32）——不是免费的等价替代。

## 9. 撤回与下一步

**明确撤回两句**：

1. **「量化在任何拓扑上都是内存负收益」**——它是**逐值标尺实现**的产物，被本实验（块标尺 G=32，
  int8 省 46.875%、前缀不变）否证。落点：R1 格页 `tax`/`benefit` 与 `2631/analysis.md` 的读法。
2. **`2631/budget_caliber.py::mixed_axis_note` 的「K 侧做不到非 token 轴摊薄」**——被本实验否证：
   K 沿 `head_dim` 分块（`block`）就能摊薄到 `2/G` 且**保持严格因果**。（该文件是 `2631` 的冻结产物，
   本实验只在此处与 R1 格页撤回该句，不改 `2631/` 以免破坏其 `results.json::code` 的哈希绑定。）

**下一步**：

1. **[未测，最小实验 + 成本]**：`head_dim ≥ 64` 的模型上 G=32 只是行的一段（分辨率更高），块标尺与
   int4 / 头共享 × int4 的匹配是否改善——需一个更大 `head_dim` 的 13M 点（≈ 训练 15–25 min + eval 5 min）；
   这也是**头共享 × 4 位归因**的判决实验。
2. **[未测]** fp8（1 B/值、无标尺、更省）的质量：与 int8+块标尺同表比较。成本 ≈ eval 5 min。
3. **[未测]** 权重 / 激活量化是否与 KV 同口径（WI-08 的问题 3）。
4. **[口径]** 排序带若要达到标准配对口径（≥5 窗口），需把 `self_measured_seeds` 扩到 ≥5。
