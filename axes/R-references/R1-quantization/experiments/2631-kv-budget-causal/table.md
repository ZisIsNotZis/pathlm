# 2631 · 因果口径 KV 预算图 —— 一张表（27 点）

**口径**：本表是 `2621` 的 27 点预算图在 L1 修复后的**逐请求、因果/流式** KV 量化下重测的结果。除量化器 scale 约定外，checkpoint / 数据流 / 窗口序 / 任务 / 判据与 `2621` 逐字段相同；横轴公式（判据 C1）与 `2619/2620/2621` 逐字同一式：`bytes_per_position = 2 · n_layers · n_kv_heads_eff · head_dim · value_bytes · (positions_kept / T)`，T = 256。第 3 列是**值字节**（旧横轴，与 2621 逐位可比）；第 4/5 列把因果/流式量化多出的**标尺**开销算上（定义见 `budget_caliber.py`、逐臂明细见**表 5**）。

两腿全部由本实验**同进程、同一路径**重测（复用 2619 的 `bpc_of` / `synth_accuracy`）。召回地板：chance = 0.0156（1/64）、局部先验 = 0.0146（copy）。『Δbpc(新−旧)』= 本因果口径 bpc − 2621 旧口径 bpc（负 = 因果口径质量代价更小）。

**部署口径列（本表新增）：**『值字节』只是 KV 的**值**；因果/流式量化每个值还要配一个 fp16 标尺（见 `budget_caliber.py`）。『部署 (a)』= 逐值标尺（严格前缀确定，**与本实验的质量数字同源**）；『部署 (b)』= 分块标尺 + 块内回填（每 32 个连续可见位置一个标尺，**块内不再严格前缀确定**，违反距离 ≤ 31 个位置）。27 点里有 10 个量化臂受影响（值字节列把它们算便宜了），逐臂明细与省幅见**表 5**；结论与旧账推翻见同目录 `analysis.md`。

## 表 5 · 部署口径明细（值 + 标尺；两套方案）

X 轴仍用**值字节**（与 2621 逐位可比）；本表把标尺的钱算上。定义见 `budget_caliber.py`：

- **(a) 逐值标尺（严格前缀确定）**：每值 1 个 fp16 标尺 ⇒ +2 B/值。与 `tools/evalkit/kv_quant.quantize_kv` 的 `cummax` 实现**同源** ⇒ 这是本实验质量数字的价签。
- **(b) 分块标尺 + 块内回填**：每 32 个连续**可见**位置共享 1 个 fp16 标尺（块内 amax，块关闭时按最终 scale 重编码）⇒ +0.0625 B/值（名义）。三条代价：① **违反前缀确定**：块内过去值可被同块后续 **31** 个位置改写（回填后冻结）；② **staging**：块关闭前必须留着原始 fp16 值 ⇒ 平均 15.5 个位置的 fp16 缓冲 = 0.182 MiB/请求（与 T 无关：T=256 时折合 744 B/位置，T=4096 时 46.5 B/位置）；③ **重算 / 写放大**：每值 1 次编码 + 1 次延迟写（块关闭时一次性写一个块 ⇒ 突发写峰值 = 一个块）；不想留 staging 就得先按 running scale 编码、关块时重编码（每值 2 次编码 + 二次取整误差，**未测**）。分母取 `min(G, 段长)` 是**乐观上界**。
- 非量化臂（fp16 / 窗口 / 头共享）没有标尺 ⇒ 两套方案都等于值字节（见下表的 `—` 行）。

## 实测显存（与解析列分列，判据 C2）

- 本实验评测期 GPU 峰值（`torch.cuda.max_memory_allocated`）：**462.5 MiB**。
- 评测实现把 K/V 立刻反量化、按掩码取子集（SDPA 仍算 T×T 分数矩阵）⇒ 实测峰值不随档下降，故只报解析列；**实测峰值也不能当部署价签**。
- **部署口径看表 5**：严格逐 token 因果（本实验实现 = 方案 (a)）⇒ 每值 +1 个 fp16 标尺，int8 净 3 B/值、int4 净 2.5 B/值（fp16 基线 2 B/值）⇒ **旧的「int8 省一半」在因果口径下不成立**；要真省只能走 (b)（放弃块内严格前缀确定）。`kv_cache_footprint` 的 `streaming_bytes_by_seq_len` 就是 (a) 口径的总量。
