# R1-quantization · 量化

> 轴：**R 参照线（必须打败的基线）** ｜ 状态：**⬜ todo**

> **判读**：**已有**：本地已实测 KV 量化的部署口径价签与质量——**块标尺（沿 head_dim，G=32）** 下 int8 每位置 6528 B = fp16 的 ×0.53（省 46.875%）、int4 ×0.28（省 71.875%），且**严格前缀不变性成立、不需 staging**；质量：int8 Δbpc **+0.000101**（正号、远低于本格在力排序带 0.036324）、int4 **+0.022522**。**已撤回**旧「量化在任何拓扑上都是内存负收益」（那是逐值标尺实现的产物）。**尚缺**：fp8 质量、权重/激活量化、更大 head_dim 点（待补做）。

## 1. 命题

用更低比特换内存/带宽/算力——「Pro 当 Flash 用」的现成答案。

## 2. 选项枚举（本格全部可能取值）

1. `权重 int8/int4`
2. `KV cache 量化`
3. `激活量化`
4. `混合精度`

## 3. 状态（我们做了什么 / 行业做了什么）

**本地已测**：**部署口径**：KV 量化是省内存手段——**块标尺（沿 head_dim，G=32）** 下 int8 每位置 **6528 B = fp16 的 ×0.53（省 46.875%）**、int4 **3456 B（省 71.875%）**，且**严格前缀不变、不需 staging**；`head_dim` 更大时 G 可更大 ⇒ 省幅趋近 50%。**不省的是逐值标尺**实现（×1.50/×1.25，已撤回）。**同价诚实对手（未测质量）**：**fp8** 解析 1 B/值 = ×0.50，**比 int8+块标尺更省** ⇒ 不得声称 int8+块标尺是所有 8 位方案里最优。非因果的 token 轴块（`block_tok` / KIVI 的 K 侧）同省 46.875%，但违反前缀确定 ≤ G−1 个位置、需 staging（持整块 393216 B/请求 / 平均半块 190464 B/请求 @G=32）。头共享（MQA 省 87.5%）与窗口/驱逐仍是独立杠杆。**撤回 `2631/budget_caliber.py::mixed_axis_note` 的「K 侧做不到非 token 轴摊薄」**——K 沿 `head_dim` 分块可摊到 `2/G` B/值且保持严格因果。

**行业口径**：工业界标准做法；「Pro 当 Flash 用」的最强基线。任何 L1/L2 线必须打败它或与之复合。

## 4. 结论与数字

- **税**：**部署口径（源 `2632-kv-block-scale`）**：**块标尺沿 `head_dim` G=32** 下 **int8 = 1 B/值 + 2/G B 标尺 = 1.0625 B/值 ⇒ 6528 B/位置 = fp16 的 ×0.53（省 46.875%）**、**int4 = 3456 B/位置（省 71.875%）**；**严格前缀不变性成立、不需 staging**。**质量结论（块标尺）**：int8 Δbpc（vs fp16）**+0.000101**（3 窗口配对 Δ 逐 seed +0.000101/+0.000013/+0.000009，**全为正**；远低于本格在力排序带 0.036324）、int4 **+0.022522**。**旧口径（源 `2631`，逐值标尺）**：int8 = 3 B/值 = fp16 的 ×1.50、int4 ×1.25（内存负收益）——**已撤回**。fp16 基线 1.483571
- **收益**：**部署口径**：KV 量化是省内存手段——**块标尺（沿 head_dim，G=32）** 下 int8 每位置 **6528 B = fp16 的 ×0.53（省 46.875%）**、int4 **3456 B（省 71.875%）**，且**严格前缀不变、不需 staging**；`head_dim` 更大时 G 可更大 ⇒ 省幅趋近 50%。**不省的是逐值标尺**实现（×1.50/×1.25，已撤回）。**同价诚实对手（未测质量）**：**fp8** 解析 1 B/值 = ×0.50，**比 int8+块标尺更省** ⇒ 不得声称 int8+块标尺是所有 8 位方案里最优。非因果的 token 轴块（`block_tok` / KIVI 的 K 侧）同省 46.875%，但违反前缀确定 ≤ G−1 个位置、需 staging（持整块 393216 B/请求 / 平均半块 190464 B/请求 @G=32）。头共享（MQA 省 87.5%）与窗口/驱逐仍是独立杠杆。**撤回 `2631/budget_caliber.py::mixed_axis_note` 的「K 侧做不到非 token 轴摊薄」**——K 沿 `head_dim` 分块可摊到 `2/G` B/值且保持严格因果。
- **判读**：**已有**：本地已实测 KV 量化的部署口径价签与质量——**块标尺（沿 head_dim，G=32）** 下 int8 每位置 6528 B = fp16 的 ×0.53（省 46.875%）、int4 ×0.28（省 71.875%），且**严格前缀不变性成立、不需 staging**；质量：int8 Δbpc **+0.000101**（正号、远低于本格在力排序带 0.036324）、int4 **+0.022522**。**已撤回**旧「量化在任何拓扑上都是内存负收益」（那是逐值标尺实现的产物）。**尚缺**：fp8 质量、权重/激活量化、更大 head_dim 点（待补做）。

## 5. 失败路径与原因

1. **块标尺重测（`2632-kv-block-scale`，27 点同进程、非量化臂与 `2631` 逐位一致 max|Δ|=0）**：**int8 块标尺近无损且省 46.875%**（Δbpc vs fp16 **+0.000101**，3 窗口配对 Δ 全为正、远低于在力带 0.036324）；**4 位通用有损**（纯量化臂 Δbpc **+0.022522**）；**头共享 × 4 位换块标尺后变差**——`mqa_int4` Δ=+0.054794（> 在力带 0.036324 ⇒ **可排序**）、`gqa_int4` Δ=+0.009642（< 带 ⇒ **不可排序**），**归因待核**（纯 int4 臂上块标尺反而更好，Δ=−0.002226 ⇒ 「丢通道分辨率」的通性说法被自证反驳）。前缀不变性：`block` g16/g32 = True/True，`block_tok`/`kivi` 的 K 侧 = False。
2. **剩余组合与总表（ticket 38-W1，27 点同进程重测）**：**叠加更省只对 int8 成立**——int8 叠窗口/锚点几乎免费（量化增量 +0.00023/+0.00012，块标尺重测，`2632`），但**int4 叠头共享是亏的**：`GQA×int4` 比单用 GQA 多付 **+0.056801**（= 单用 int4 增量 +0.022522 的 2.5×）、`MQA×int4` 多付 **+0.148987**（6.6×），且召回同步掉。**部署字节相近的两点：`MQA×int8`（816 B/位置，bpc 1.4939 / copy 0.2448）优于 `GQA×int4`（864 B，1.5531/0.1462）、`GQA×窗口64`（768 B，1.5591/0.0658）、`窗口32×int4`（816 B，1.6956/0.0143）**（块标尺重测，`2632`）。总表含全部已测点。
3. **组合与锚点（ticket 37-V1，13 臂同进程重测）**：**`GQA×int8`（值字节口径 1536 B/位置；**部署口径（块标尺 G=32）= 1632 B/位置 = 同拓扑 `gqa` 的 ×0.13**；**撤回**旧「×1.50 ⇒ 量化在组合里是减分项」——那是逐值标尺的产物）两腿近无损**——量化增量 **+0.000116**（块标尺重测，`2632`；远低于在力排序带 0.036324）、召回 0.1683 ≥ 全量基线；同字节下碾压「窗口 32」（bpc 1.695 / 召回 0.014）；**`MQA×int8`（值字节口径 768 B/位置；部署口径（块标尺 G=32）816 B/位置）同样近无损**（+0.000170，召回 0.2448）。**锚点是靶向杠杆**：同字节下召回更好而 bpc 更差（两腿不一致，已显式标注）——它**只救锚区内的源**（src0 0.0127→0.2471），锚区外仍趴地板 ⇒ 「窗口＋锚点」不是通用的召回救援。局限：头共享族有参数量混杂（−8.75%/−10.25%）未解；「MQA 召回更高」为单 seed 不得外推；等字节 ≠ 等形状
4. **跨家族统一预算图（ticket 36-U3，块标尺重测见 `2632`）**：同一横轴「每位置 KV 字节」下的实测——**3072 B：GQA +0.0143 比 int4 **+0.022522** 便宜 ~1.6×、比窗口留 64（+0.0805）便宜 5.6×**；**6144 B：int8 **+0.000101** 优于窗口留 128（+0.0201）**；**1536 B：MQA +0.0117 优于窗口留 32（+0.2118）18×**。第二腿（合成长程召回）：**窗口 192 的 bpc 只掉 0.0042 但长程召回掉 25%** ⇒ 「低损伤 ≠ 保住了」在合成天平上复现；**int4 是唯一两腿都掉的档位，int8 是唯一两腿都近无损的点**。
5. 内存数字是**解析** KV 占用（部署口径）；评测期实现立即反量化，故 GPU 实测峰值不随档下降——已在 analysis 标注，未当作「实测内存下降」上报
