# R1-quantization · 量化

> 轴：**R 参照线（必须打败的基线）** ｜ 状态：**🏭 reference（含业界结论）**

## 1. 命题

用更低比特换内存/带宽/算力——「Pro 当 Flash 用」的现成答案。

## 2. 选项枚举（本格全部可能取值）

1. `权重 int8/int4`
2. `KV cache 量化`
3. `激活量化`
4. `混合精度`

## 3. 状态（我们做了什么 / 行业做了什么）

**本地已测**：参照线数字：**任何「省内存/丢信息」的主张，至少要打败 int8 KV 的近无损 −50%**；int4 的代价 +0.0457 是另一条可比的价签

**行业口径**：工业界标准做法；「Pro 当 Flash 用」的最强基线。任何 L1/L2 线必须打败它或与之复合。

## 4. 结论与数字

- **税**：**int8 KV：Δbpc +0.00015（近无损）**，每位置 12288 → 6144 字节（−50%）；**int4 KV：+0.0457**（3.3× 噪声带），3072 字节（−75%）；fp16 基线 1.483571
- **收益**：参照线数字：**任何「省内存/丢信息」的主张，至少要打败 int8 KV 的近无损 −50%**；int4 的代价 +0.0457 是另一条可比的价签

## 5. 失败路径与原因

1. **剩余组合与总表（ticket 38-W1，27 点同进程重测、与 2619/2620 参考臂逐位一致 max|Δ|=0）**：**叠加更省只对 int8 成立**——int8 叠窗口/锚点几乎免费（+0.0003/+0.0001），但**int4 叠头共享是亏的**：`GQA×int4` 比单用 GQA 多付 **+0.096**（= 单用 int4 的 2.1×）、`MQA×int4` 多付 **+0.196**（4.3×），且召回同步掉（−2.9pp/−7.2pp，CI 不重叠）。**同为 768 B/位置时最优是 `MQA×int8`（bpc 1.4941 / copy 0.2448）**，优于 `GQA×int4`（1.5925/0.1396）、`GQA×窗口64`（1.5591/0.0658）、`窗口32×int4`（1.6435/0.0814）。总表含全部已测点并标出仍缺 9 个组合
2. **组合与锚点（ticket 37-V1，13 臂同进程重测、参考臂与 2619 逐位一致 max|Δ|=0）**：**`GQA×int8`（1536 B/位置、省 87.5%）两腿近无损**——量化增量 **+0.000164**（噪声带的 1/85）、召回 0.1686 ≥ 全量基线 0.1413；同字节下碾压「窗口 32」（bpc 1.695 / 召回 0.014）；**`MQA×int8`（768 B/位置、省 93.75%）同样近无损**（+0.000342，召回 0.2448）。**锚点是靶向杠杆**：同字节下召回更好而 bpc 更差（两腿不一致，已显式标注）——它**只救锚区内的源**（src0 0.0127→0.2471），锚区外仍趴地板 ⇒ 「窗口＋锚点」不是通用的召回救援。局限：头共享族有参数量混杂（−8.75%/−10.25%）未解；「MQA 召回更高」为单 seed 不得外推；等字节 ≠ 等形状
3. **跨家族统一预算图（ticket 36-U3）**：同一横轴「每位置 KV 字节」下的实测——**3072 B：GQA +0.0143 比 int4 +0.0457 便宜 3.2×、比窗口留 64（+0.0805）便宜 5.6×**；**6144 B：int8 +0.00015 优于窗口留 128（+0.0201）**；**1536 B：MQA +0.0117 优于窗口留 32（+0.2118）18×**。第二腿（合成长程召回）：**窗口 192 的 bpc 只掉 0.0042（噪声带 30%）但长程召回掉 25%** ⇒ 「低损伤 ≠ 保住了」在合成天平上复现；**int4 是唯一两腿都掉的档位，int8 是唯一两腿都近无损的点**。缺失组合清单（GQA×int8 等 10 项）已交主 Agent 排批。**ERRATA（执行者自纠）**：首轮毁源对照把源区间硬编码为 [0,32)，3 档里 2 档源未被触碰、读数虚高（≈0.10），已定位（同档毁错区间 0.1562 vs 毁对区间 0.0137）并作废，未进任何结论
4. 内存数字是**解析** KV 占用（部署口径）；评测期实现立即反量化，故 GPU 实测峰值不随档下降——已在 analysis 标注，未当作「实测内存下降」上报
