# R1-quantization · 量化

> 轴：**R 参照线（必须打败的基线）** ｜ 状态：**🏭 reference**

## 1. 命题

用更低比特换内存/带宽/算力——「Pro 当 Flash 用」的现成答案。

## 2. 选项枚举（本格全部可能取值）

1. `权重 int8/int4`
2. `KV cache 量化`
3. `激活量化`
4. `混合精度`

## 3. 状态（我们做了什么 / 行业做了什么）

**本地已测**：参照线数字：**任何「省内存/丢信息」的主张，至少要打败 int8 KV 的近无损 −50%**；int4 的代价 +0.0457 是另一条可比的价签

**行业口径**：工业界标准做法；「Pro 当 Flash 用」的最强基线。任何 L1/L2 线必须打败它或与之复合。

## 4. 结论与数字

- **税**：**int8 KV：Δbpc +0.00015（近无损）**，每位置 12288 → 6144 字节（−50%）；**int4 KV：+0.0457**（3.3× 噪声带），3072 字节（−75%）；fp16 基线 1.483571
- **收益**：参照线数字：**任何「省内存/丢信息」的主张，至少要打败 int8 KV 的近无损 −50%**；int4 的代价 +0.0457 是另一条可比的价签

## 5. 失败路径与原因

1. 内存数字是**解析** KV 占用（部署口径）；评测期实现立即反量化，故 GPU 实测峰值不随档下降——已在 analysis 标注，未当作「实测内存下降」上报

## 6. 判据与判决实验设计

- **判据**：质量损失 × 内存/吞吐（双边前沿）

## 7. 成本估计
