## 0. 一句话

X1 在 **6000 步快照**上证到「λ=0.1 的**表征级去相关**真正让多路径更不相关、且净效应可排序地
成立（`l1@K8 − repr01@K8 = +0.0246 ≥ 0.014`）」，但**判据量仍在快速移动**（主判据缺口
@3000 +0.3164 → @6000 +0.1357，−0.060/1k）。本实验把**同一配置跑到 24000 步（4× token）**，
判「**机制是否熬过收敛**」：24k 时 `l1@K8 − repr01@K8` 是**保持（≥0.014）/收窄/反转**，
以及**主判据缺口**在 24k 有多大。

## 1. 命题（可证伪）

**把 X1 的 13M 两臂（`l1` 无去相关、`repr01` λ=0.1 表征级去相关）跑到 24000 步（收敛尺度）
后，机制净效应 `l1@K8 − repr01@K8` 是否仍 ≥ 0.014（可排序保持），主判据缺口
`repr01@K8 − stock@K1` 在 24k 是否仍为正？**（两者都可判定二元 + 连续量）

## 2. 干预与单因素声明（精确表述）

**唯一真变量**仍是两个键（与 X1 逐字段相同，只把 `train.steps` 由 6000 → **24000**）：

| 臂 | 相对上一级**唯一**的变化 | 隔离出的因素 |
|---|---|---|
| `stock` | —（阶梯底：单线骨干，无路径机制、无去相关压力） | — |
| `l1` | `p_skip: 0.0 → 0.1` | **路径机制**（随机丢层采样路径） |
| `repr01` | `w_repr_decorr: 0.0 → 0.1` | **表征级去相关压力**（λ=0.1） |

- `configs13m/{stock,l1,repr01}.json` 的 `model`/`train`（除 `steps`）/`path`（除上述两键）
  **逐字段相同、含 `seed=0`**；与 X1 同名臂**除 `train.steps` 外逐字段相同**。
  单测 `tests/test_mechanism_convergence.py::test_ladder_configs_differ_only_in_declared_knobs`
  与 `::test_recipe_identical_to_x1_except_steps` 钉死；变异 M1–M5 抓红且逐字节还原。
- **参数量完全相同**（去相关是**纯损失项**：不新增参数，只多一次前向）；对账机检相等。
- **调度归一的口径事实（本实验的关键前提）**：`train_m1.py` 的 cosine 学习率按**总步数**归一
  （`lambda = min((s+1)/200, 0.1 + 0.9·0.5·(1+cos(π·s/steps)))`）。因此本实验是一条 **24000 步
  cosine 的全新训练**，其 @6k 处 lr ≈ 0.868×base，而 X1 的 @6k 是 6000 步 cosine 的**末点**
  （lr → 0.1×base）⇒ **本实验 @6k 与 X1 的 6k 读数不可作逐位对照**（如实标注，见 §4.4）。
- **为什么必须重训 `stock` 到 24k（不是复用 X1 的 6k stock）**：主判据 = `repr01@K8 − stock@K1`，
  两臂必须**同一 token 预算**（§17.14）；复用 6k 的 stock 是**跨预算拼接**，会把缺口严重低估。
  （主 Agent 裁决 2026-10-06：批准 3 臂 × 24k。）
- **规模配方（如实记账）**：13M = `d256/12L/8H/T512/mlp×6`，`bs32 × 24000 步` = 每臂 **393.2M
  tokens**（4× X1 的 98.3M），同 lr（1e-3）、同 seed（0）。三个点（6k/12k/18k/24k）都在**同一条
  24k 调度**内 ⇒ 是**同方法**的收敛轨迹。

## 3. 指标表（多维，逐项）

| 维度 | 指标 | 怎么读 |
|---|---|---|
| 它解决什么问题 | K 路径集成的 bpc 增益（K1→K8） | 集成能不能替「单线」省质量 |
| 代价 | clean bpc 税（相对 `l1`、相对 `stock` 两套口径**分开报**） | 机制本身值多少钱 |
| 主判据（§4.1） | `bpc_repr01@K8 − bpc_stock@K1 < 0` | vs **同 token 预算的单线 stock**（诚实对手） |
| 机制判据（§4.2，**本实验一号问题**） | `bpc_l1@K8 − bpc_repr01@K8` 的**四点轨迹**（6k/12k/18k/24k）+ 成对 JS | 去相关**机制**能否熬过收敛 |
| 收益与用法 | K=1/2/4/8 四点曲线（终点）+ 每档相对 K=1 的 Δ | 每种 K 一行；**单点不外推**，K=8 是预登记点 |
| 可控性 | 成对 JS、确定性路径对照 | 增益是否**只**来自路径随机性 |
| 副产品 | 活性量（repr_decorr / JS / skip_frac / gnorm / gate_skips，每 200 步）、loss 斜率、峰值显存 | 干预是否活着、是否收敛、是否吃满更新 |

**算力价签（写进结论句，`§17.14` 第 4 项）**：K8 集成 = **8× 前向/token**，`stock` 单线 = 1×。

## 4. 判据线（预登记，跑之前写下，跑完不得改）

### 4.1 主判据（任务形式，**primary**）

> `bpc_repr01@K8 − bpc_stock@K1 < 0` 且配对 CI 不重叠 ⇒ **多线成立**；否则记「仍不成立」。
> 必须同时报「推理算力账」：K8 集成 ≈ 8× 前向/token vs stock 1×，价签写进结论句。

**代数对账（`§12`）**：任务形式 = `−reading_B(l1@K1, stock@K1, repr01@K8).reduced`；`run.py` 两种
写法都算并断言差 < 1e-9。

- **基准是谁**：`stock` 臂（同骨干、同 24000 步 token 预算、同 seed 的单线模型）。
- **代价项相对谁算**：`bpc_l1@K1 − bpc_stock@K1`，与基准**同一口径**。
- **CI 口径**：两臂各自 60 批**配对** bootstrap（10k 重采样，α=0.05）；同时报
  ① 配对差值 CI 不含 0（灵敏）；② 两臂各自 CI 不重叠（保守）。不一致时以保守口径为准。

### 4.2 机制判据（**本实验一号问题**：机制能否熬过收敛）

> 24k 终点 `bpc_l1@K8 − bpc_repr01@K8` 的**三态**：**保持**（≥ 0.014）/ **收窄**（0 ≤ v < 0.014，
> 落进不可排序带）/ **反转**（< 0）；并把 **6k/12k/18k/24k 四点并列**（同一条 24k 调度内的
> 收敛轨迹，**禁外推**）；配套成对 JS（`repr01` 是否仍 > `l1`）。

- **基准**：`l1` 臂（同路径机制、无去相关压力）。
- **代价项**：`bpc_repr01@K1 − bpc_l1@K1`（去相关压力的 clean 代价）。
- **两列分解（`§17.17`）**：净效应不可排序时，必须拆成 `税增量 vs 增益增量` 两列。

### 4.3 必报项

1. **`gate_skips`（须为 0）** 与**实际更新步数**（每臂）；
2. **算力账**：K8 集成 = 8× 前向/token、stock = 1×；
3. **确定性路径对照（应恰好 0）**：`stock` 臂 + `repr01` 臂（评测期强制 `p_skip=0`）；
4. **成对 JS**（路径相关度，nats + bits）三臂 K=8；
5. **税**（§4.1/§4.2 两套口径分开）；
6. **活性量每 200 步**（`repr_decorr` / `diversity_js` / `skip_frac` / `gnorm` / `n_paths`）；
7. **收敛门禁（§17.15）**：落在**决定判据的量**上——主判据缺口 `repr01@K8 − stock@K1` 与机制
   净效应 `l1@K8 − repr01@K8`，在 ckpt@6k/12k/18k 与终点**直接测**；训练总 CE 斜率仅作**并报**，
   不得代替判据量口径。

### 4.4 口径与禁令

- **口径**：matched-step **快照**（每臂 24000 步、4× token）；K 曲线用 **60-batch probe 协议**
  （与 13M 锚点同函数同 seed）；另附 200-batch battery 的 clean bpc 作参照；**24k 若仍非收敛则
  标快照**。
- **单点不得外推**：6k/12k/18k/24k 四点只描述**本调度内的**形状；不拟合、不外推到其他步数/规模。
- **不可作逐位对照的项**：本实验 @6k 与 X1 的 6k 读数（调度不同，见 §2）；
- **本实验不覆盖**：**50M 的 0.0322 缺口**（§23 第 6 问的未测项）——本实验只做 13M。
- **失败决策树**（无效时按序排除）：① 测量（probe 方法/CI）→ ② 实现（`w_repr_decorr` 是否真活着、
  `gate_skips` 是否为 0）→ ③ 规模/收敛（是否只是步数不够）→ ④ 设计（表征级去相关本身是否够了）。

## 6. 成本

```
gpu_wall_budget_min: 90        # 3 臂 × 24000 步训练 + 评测（主 Agent 2026-10-06 批准）
```

- **先实测步时再定预算（`§20.3`）**：250 步实测 `stock` 48.2 / `l1` 48.2 / `repr01` 72.3 ms/step
  ⇒ 训练 ≈ 19.3 + 19.3 + 28.9 = **67.5 min**；评测 ≈ 8 min。**注**：原 ticket 写「≈30–40 min」，
  其出处（X1 `progress.md`）把两臂的步数按平均步时只算了一遍（少算 ~2×）；已向主 Agent 报数并
  获准按 3 臂 × 24k 执行。
- **预算不够时砍什么（不砍判据线）**：① 砍 200-batch battery（改 60 批）；② 砍 K=2 档；
  ③ 砍 JS 重复批次。**禁止**砍：主判据四个读数、机制四点轨迹、确定性对照、活性量、gate 报告。
- **可中断性**：各臂独立进程，每 200 步落盘、每 6000 步存 ckpt；中断只丢当前臂。
- **峰值显存 ≤5GB net**（共享 4090）：`repr01` 每步多采样一条并行路径 ⇒ 实测 X1 同配方
  **4995.8 MB（<5GB）**；逐臂 `peak_gpu_mem_mb` 入账，跑前后各记一次 `nvidia-smi memory.free`
  （§20.2 三件套）。**不得**为好看改批大小/步数（保主判据基准同配方）。
- **外部占用降速时的处置（§20.3）**：只许**缩步数**并声明快照口径（臂间同刻度不变），
  **不许**换配方、不许砍臂；若那样会破坏「24k 收敛」前提，**先报数再决定**。

## 10. 既有做法（prior art，`SCHEMA §18`）

**检索条件**：本环境**联网检索不可用**（未注册 web / `web_search` 工具）。因此下面凡外部系统
一律标 **`记忆·未核`**，只作设计方向、**不得作判据**；本地条目标 `本地实测` 并给路径。
完整分诊见 `axes/G-policy/PRIOR_ART_DECORRELATION.md`（ticket 37 知识线）。

1. **谁做过**：**Deep Ensembles**（Lakshminarayanan et al. 2017，`记忆·未核`）；**Negative
   Correlation Learning**（Liu & Yao 1999，`记忆·未核`）；**Barlow Twins**（Zbontar et al. 2021）/
   **VICReg**（Bardes et al. 2022）（`记忆·未核`）；**Stochastic Depth**（Huang et al. 2016，`记忆·未核`）。
   本地：X1 `2622` 的 13M/50M 阶梯（`本地实测`）。
2. **为什么这么设计**：集成的误差只有在成员**误差不相关**时才被平均掉；共享主干成员天然相关
   ⇒ 要么独立训练（贵 N×），要么显式付钱买多样性。**表征级**罚则（NCL/Barlow/VICReg 一族）
   直接对「想要的性质」写损失。
3. **它的实测结果**：外部多为分类/SSL/RL，**没有可直接对照的**「共享主干 + 自回归 LM + 13M
   bpc + 收敛尺度」受控结果（`(c)`，联网不可用不能证伪其存在）；本地：X1 在 **6000 步快照**上
   判「λ=0.1 表征罚则在 13M 真去相关且净成立（+0.0246），但两档主判据都不成立、且**未收敛**」
   （`本地实测`）。
4. **我们的增量在哪**：
   - **把「快照增益」推进到「收敛尺度」**（4× token、24000 步）——正是 `SCHEMA §16` 的收敛对账义务；
   - **主判据的基准臂 stock 也重训到同预算**（避免跨预算拼接，§17.14）；
   - **判据量四点收敛轨迹**（6k/12k/18k/24k）而非单点。

## 11. 能力面 + 共享面分析（`SCHEMA §22` / `§22.8`，派发前已做）

- `grep -n "ValueError\|互斥" pathlm/depth_ar.py` 的输出里，所有互斥校验都在 **depth-AR 引擎**
  （`attn_sparse_k / train_window / attn_linear / n_kv_heads / carry_rule / topology` 两两互斥、
  block 类二选一）。**G5 多线机制不在该引擎里**——它走 loop-era 引擎 `pathlm/model.py` +
  `train_m1.py`。
- 本实验要的组合：`p_skip>0`（既有）+ `w_repr_decorr=0.1`（X1 新增）。`sample_path` 对 `p_skip`
  无互斥；`validate_pcap` 禁止 `w_diversity` 与 `w_repr_decorr` 同时开（本实验不涉及 `w_diversity`）。
- **结论：所需组合在引擎里存在，无不可组合项。** 本线**不改**任何引擎文件。

**共享面**（哪些线要改哪些文件）：本线只新增本实验目录 + `tests/test_mechanism_convergence.py`；
**不写** `train_m1.py` / `pathlm/*.py`（X1 已写过，本轮只读复用）。⇒ 与其他线**不相交**。
