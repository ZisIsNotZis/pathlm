# 2510-gap-sweep-b2-c1m · 判读

## 人话摘要

把「一次前向吐几个词」从 1 提到 2（`n_mtp=2`，多挂一个 t+2 直接头）在本项目 13M 上的**质量税**
是 **+0.041 bpc**（1.5074 → 1.5481，越低越好；0.014 以上算能排序），主干的 t+1 预测几乎没被
拖坏（命中率 0.6924 → 0.6863，−0.006）。多出来的那个 t+2 头当**草稿**用时，被主干 t+1 验证的
一致率是 **0.6582**（这就是「宽度-2 的接受率锚」，草稿用途的判据，不是对真值的命中率）。
本目录的原始 `results.json` 在，**B2 权重已不可得**（`.tmp/` 已清），因此无法重跑、只能引用原件。

术语：**bpc**（每字符比特数，越低越好）；**税**（相对同尺寸 stock 基线的质量代价 Δ）；
**草稿接受率 a₂**（草稿 argmax == 主干自身 argmax 的比例，对照物是主干不是真值，SCHEMA §11）。

## 2. 与 H1 算力账的关系

n_mtp=2 的模型在 spec 里用 `max_drafts=1`（γ=1），因此每 token 算力 `R = 2 / tokens_per_forward`
（见 `2520-spec-at-scale/analysis.md`）。本目录**没有**测 spec 吞吐，只给 γ 与草稿锚；
tokens_per_forward 由 `a₂ = 0.6582` 得 **1.658**，对应 `R = 2/1.658 = 1.206`（**>1，算力亏损**）。
即：n_mtp 1→2 用 **+0.041 bpc** 的税换来「一次前向多吐 0.66 个 token」，但**每 token 算力更贵**。

## 3. 对照与口径

- 对照 = B0（n_mtp=1，同配置、同 seed、同 token 预算）；B2fresh 是 ticket 13 的 B2 重训对照。
- 口径 = **1.1-epoch 快照**（6k 步）；所有早期税都是其**上界**（未做 2× 训练点，不在本目录 scope）。
- **D2 混杂**：C1M / C2M 臂的 `n_mtp` 未显式钉死 ⇒ 其税虚高，**不入账**（ticket 11 修正）；
  B2 不受该混杂影响（`config.path.n_mtp=2` 明写）。

## 4. 对账（SCHEMA §12）

- **算术**：税 = 1.5481 − 1.5074 = +0.0407；草稿锚 0.6582 是「草稿 vs 主干」的一致率，
  不是「vs 真值」命中（node-2 对真值命中另报 0.5597，两者分开）。
- **任务**：B2 与 B0 都是 clean enwik8 val 上的 next-token CE/命中，同任务同位置集。
- **口径**：快照 vs 快照，同 token 预算。
