# analysis · 2611 跳跃头对照臂修正 + 草稿接受率 · 13M

> 口径：char 级 enwik8（`data/enwik8_full.npz`；90M train / 10M eval，词表 206），
> 13.5M dense decoder-only 主干（d256 × 12 层 × mlp6，tied 读出、无 final LN）+ 2610
> 两个跳跃头（各 262,912 参数，seed 0/1）；**冻结、纯推理**。
> 评测位置 = eval 流的 97,536 个「t+1 与 t+2 同时可定义」的位置（行 0..T−3），
> seed 7 固定窗口，与 2610 逐位同口径。判据线来自契约 §4（预先写下，未改）。

---

## 0. 人话摘要

跳跃头想让模型在**一次前向**里就猜出「下一个字的下一个字」（t+2），省掉第二次
前向、省一半算力。做法是主干完全不动，只在一张冻结词表读出头上外挂一个 262,912
参数的小变换（约占主干 1.9%）。怎么测：找一条**诚实的、同成本的对手**——「自回归
跑两次」，第二次只把**紧邻的上一个位置**换成模型自己生成的那个字，其余保持真值
（这就是「自己循环两次」，不作弊）。测出来：诚实对手 t+2 命中 **54.89%**，跳跃头
**46.67%**，只有对手的 **85%**；纯随机猜是 0.49%。也就是说，跳跃头确实学到了 t+2
映射（远高于随机），但比「老实跑两次」低约 15%，够不上契约要求的「90%」。作为
草稿（让主干来验收），跳跃头的接受率只有 **59.98%**，远低于可用的 90%。**结论：
中性偏负**——省算力是真的（等效约 1.95×），但质量缺口让它单独不足以替代两次前向。
本实验同时**实证了 ticket 28 那条「跳跃头以半成本反超两次前向」的反向结论是错的**：
那版的对照把整段上下文都换成了自预测，量的是不可能任务（见 §3 对账）。

## 2. 对账义务（SCHEMA §12，三道）

### 2.1 算术对账

诚实 1-step AR 的 t+2 命中有**算术下界** = P(t+1 命中) × P(t+2 命中 | 真 t+1)
= `trunk_t1_hit` × `oracle_t2_hit` = 0.6934 × 0.6953 = **0.4822**。

- 实测 `ar1_deploy_t2_hit` = **0.5489 ≥ 0.4822** ✓（对账硬性条件过）。
- 上界 = min(0.6934, 0.6953) = 0.6934；0.5489 ≤ 0.6934 ✓。
- 隐含条件命中 P(第 2 步对 | 第 1 步对) = 0.5489 / 0.6934 = **0.7916**，
  ≥ 无条件 `oracle_t2_hit` = 0.6953（第 1 步对的那些位置本身更「容易」，正相关），
  方向一致，无矛盾。

**算术对账结论：通过。实现正确（若仍是整段替换，会低于下界，见 §3.2 反例）。**

### 2.2 任务对账（对照臂测的是不是同一件事）

| | 本实验 ar1 臂 | ticket 28 旧 deploy 臂（作废） |
|---|---|---|
| 输入 | 真值前缀 x[0..i] + **仅**位置 i+1 换成自身 argmax | **整段** x[1..T−1] 换成自身 argmax |
| 要预测 | 真值 x[i+2] | 真值 x[i+2] |
| 部署对应 | 真实「自回归跑两次」：第二次只吃自己刚生成的那**一个** token | **不存在**（假上下文猜真值，按构造不可完成） |
| 实测 | **0.5489**（≥ 下界 0.4822） | 0.3128（**低于**下界 0.4822 ⇒ 自证不是 AR） |

### 2.3 口径对账

同一位置集（97,536 位置，行 0..T−3）、同评测窗（seed 7，24 批 × bs16）、同主干/头、
同为「vs 真值 t+2 命中」快照口径。**交叉核验**：本次 `trunk_t1_hit` = 0.6934、
`oracle_t2_hit` = 0.6953、`jump_t2_hit` = 0.4667 与 2610 的对应值**逐位相同** ⇒
harness 一致、主臂未被改动。

### 2.4 对账总表

| 对账 | 检查 | 结果 |
|---|---|---|
| 算术 | ar1 ∈ [0.4822, 0.6934] | 0.5489 ✓ 通过 |
| 任务 | 只替换紧邻位置，其余真值 | ✓ 通过（旧 deploy 已作废） |
| 口径 | 同位置集/窗/权重/指标 | ✓ 通过（三项与 2610 逐位一致） |

| 副产品 | 旧 deploy 臂构造错误的可复现证据 | `test_ar1_prefix_keeps_ground_truth_not_whole_context`（行 0 一致、行 ≥1 必不同） | — | 证明「整段替换 ≠ 只替换紧邻位置」 |

### 3.1 与 ticket 28 的读数差

| | ticket 28（旧 deploy，作废） | 本实验（诚实 ar1） | 跳跃头 |
|---|---|---|---|
| t+2 命中 | 0.3128 | **0.5489** | **0.4667** |

旧读数 0.3128 **低于**算术下界 0.4822，是「整段替换」构造错误的铁证；修正后
真实对手是 0.5489，跳跃头 0.4667 **不再反超**对手——**ticket 28「以半成本反超
两次前向」的反向结论正式作废**（2610 ERRATA 已撤回，本实验提供修正读数与对账）。

### 3.2 反例（mutation）证据

`test_ar1_prefix_keeps_ground_truth_not_whole_context`：对同一 token 流，
行 0（只替换位置 1）快路径与旧「整段替换」**逐位一致**，行 ≥1 **必不一致** ⇒
精确复现「旧臂污染了前缀 i 之前的位置」这一缺陷。改坏 mask（把前缀也替换）
该单测必红（off-by-one / 前缀污染抓红条件）。

## 5. 对照臂可比性（SCHEMA §13，三要素）

| 臂 | 输入分布 | 预测什么 | 部署对应 |
|---|---|---|---|
| 跳跃头（主，成本 1） | **真值**前缀 x[0..i]（单次前向） | x[i+2] | 1 前向同时给 t+1（主干读出）与 t+2（跳跃头） |
| 诚实 1-step AR（对手，成本 2） | 真值前缀 x[0..i] + **仅**位置 i+1 换成本身 argmax | x[i+2] | 自回归跑两次，第二次只吃自己生成的 t+1 |
| ORACLE（上界，成本 2） | 真值前缀 x[0..i+1]（喂真 t+1） | x[i+2] | **不存在**（作弊），仅上界参考 |

三者同位置集、同目标（真值 x[i+2]）、同口径；**禁止**用 oracle 作判据 → 已遵守。

## 6. 失败决策树走查（契约 §8 / methodology §14）

| 症状 | 走查结果 |
|---|---|
| `ar1_deploy_t2_hit < 0.4822`（实现仍有问题） | **未触发**：实测 0.5489 ≥ 0.4822；且与逐行 brute-force 前向逐位一致（单测）⇒ 前缀未被污染 |
| 实现正确但比值 < 0.80（设计无效） | 未触发：比值 0.8502 ∈ 中性带 |
| 两个口径互相矛盾 | 主口径（vs 真值命中比 0.8502）与草稿口径（accept 0.5998）方向一致：都不达 90% |
| 结果不可重复（方差） | 两 seed 比值 0.8533 / 0.8469，极差 0.0064 < 0.014 ⇒ 头种子差异不可排序，结论稳 |

**归因**：测量与实现均排除（对账 + 单测通过），规模为契约设定，故结论 = **设计在该
设定下「中性」**：跳跃头以半算力达到诚实两次前向的 85%，不足以达 90%；作为草稿
接受率仅 60%。与 2610 的失败判决不冲突，而是把后者从「用错误对照得出的假失败/
假反超」修正为**带正确对照的中性读数**。

## 9. 口径局限与下一步

- **快照口径**：固定 24×16 窗口，非渐近；Δ < 0.014 不可排序。
- **接受率的读法**：契约表述「主干自身 argmax 同位置」有两种自然读法——
  (a) 对照主干自身 1-step AR 输出（无作弊，本实验采纳）：0.5998；
  (b) 对照喂真 t+1 的 oracle 输出（含作弊）：0.5337。**两种读法都 < 0.90**，
  判决不受读法影响；本实验的 `accept_jump_t2` 采用 (a)，(b) 作参考附报。
- **下一步**：跳跃头的价值在**成本**而不在**独立质量/独立草稿**。若要采纳，需在
  spec decoding 里把它当**宽草稿**、由主干验证（接受率 60% 意味着约 40% 位置需回退），
  或探索「头与主干联合训练」是否补上这 15% 缺口（2610 的联合臂因 lr 过大损坏主干，
  口径不干净，属另开实验）。

> 主 Agent 补注：正文出现 0.8501 与 0.8502 两个数，分别对应 `results.json` 的 `arms_mean`（两 seed 比值取均值）与 `criteria`（先平均分子分母再取比）；两者口径不同、数值接近，均已列出，采信以 `criteria` 为准。
