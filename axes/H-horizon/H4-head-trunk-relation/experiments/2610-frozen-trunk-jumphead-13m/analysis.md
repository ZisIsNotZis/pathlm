# analysis · 2610 冻结主干 + 只训跳跃头（H4 线 A）· 13M

> 口径：char 级 enwik8（`data/enwik8_full.npz`；90M train / 10M eval），
> 13.5M dense decoder-only 主干（d256 × 12 层 × mlp6，tied 读出、无 final LN），
> 12k 步 × bs32 × seq256 = 98.3M tokens，**冻结**后只训头。
> 评测位置 = eval 流的 97,536 个「t+1 与 t+2 同时可定义」的位置（行 0..T-3），
> seed 7 固定窗口；两 seed 头（0/1）。
> 判据线来自契约 §4（预先写下，未改）。

---

## 0. 结论（一句话）

**判据线未过 → 判「失败」：冻结主干上的跳跃头无头寸。**
跳跃头 t+2 argmax 命中 **46.67%**（宽头对照 50.81%），
低于阈值 **56.17% = 0.81 × 69.34%**（分母 = 同主干直接 t+1 命中率，实测）。
**零税成立**（挂头前后主干 clean bpc 逐位不变，Δ = 0.0000）。
等 FLOPs 口径下另有一条**反向**结论：对「真实的 2 次前向 rollout」（提交自己预测的
t+1 再前向）跳跃头以**半成本**取得更高命中（46.67% vs 31.28%）——见 §4 双口径。

## 1. 判据线（契约 §4，逐项）

| 判据 | 阈值 | 实测 | 判定 |
|---|---|---|---|
| 有效性（主） | 跳跃头 t+2 命中 ≥ 0.81 × 直接 t+1 命中 | 0.81 × 0.6934 = **0.5617** | 46.67%（默认头）/ 50.81%（宽头） | **未过** |
| 零税（代价） | \|Δ clean bpc\| < 0.014（挂头前后同主干） | Δ = **0.0000** | bpc 1.4836 → 1.4836 | **过** |
| 校准（探索性） | ECE ≤ 0.01 且分层单调 | 默认头 ECE 0.0203；宽头 **0.0064** | 两者分层均严格单调 | 默认未过 / 宽头 **过** |

- 分母锚复现良好：契约锚 0.688，实测直接 t+1 = **0.6934**（主干自身 t+1 acc 0.6979）。
- 阈值 0.5617 ≈ 回环时代 joint 直接头 t+2 锚 **55.97%** ⇒ 判据实质是
  「冻结头能否追平/超过联合训练的直接 t+2 头」，实测未追平。

## 3. 失败决策树走查（契约 §8 / methodology §14）

按「先测量 → 再实现 → 再规模 → 最后设计」顺序排除：

| 症状 | 走查结果 |
|---|---|
| 命中 ≈ 0.5（off-by-one） | **排除**：`shift_pairs` 有可失败单测（shift=2 CE≈0，shift=1 必红），且主干的 `two_forward_oracle = trunk_t1` 恒等式实测成立（0.6953 = 0.6934 同源） ⇒ shift 方向正确 |
| 主干 bpc 变了（冻结失败） | **排除**：Δbpc = 0.0000，冻结断言（requires_grad=False ∧ grad is None）通过 |
| t+1 直接头正常？ | **正常**：直接头 t+1 = 0.6951 ≈ 主干自身 0.6934 ⇒ 头的训练/映射无问题 |
| 头容量/训练不足？ | **步数排除**：头 loss 从 step 200 起即平台（3.23 → 3.00，200→2000 步无趋势）。**容量部分排除**：宽头（4d×2 block）把命中抬到 50.81%（+4.1pp）、ECE 降到 0.0064，但 loss 同样在 ~step 600 平台，仍 < 阈值 0.5617 |
| 与 joint 的 55.97% 差很多 | **保留为结论**：见 §4（信息可用性差异），不追加机制 |

**归因**：测量与实现均排除，规模为唯一设定（13M 档、契约锚同档），
故判**设计在该设定下无效**——冻结主干（表征只被 t+1 目标塑形）上，跳跃头的
t+2 映射不可达 0.81× 单跳质量；回环时代 joint 的 55.97% 更高，是**表征可用性差异**，
不是头容量差异（宽度消融只补回 4.1pp）。

## 4. 等 FLOPs 双口径（必须并报，methodology §14「口径互相矛盾 → 双报」）

| 口径 | 成本 1 臂（跳跃头，1 前向 + 头） | 成本 2 臂（2 次前向） | 比 |
|---|---|---|---|
| **契约预登记口径**（分母 = oracle 两跳 = 直接 t+1 0.6934） | t+2 = 0.4667（宽头 0.5081） | oracle t+2 = 0.6953 | 0.673（宽头 0.733）< 0.81 ⇒ **未过** |
| **真实部署口径**（对手 = deploy rollout t+2） | t+2 = 0.4667（宽头 0.5081） | deploy t+2 = **0.3128** | 跳跃头**以半成本反超**（+15.4pp / +19.5pp） |

**读法**：契约判据用的是「oracle 两跳」上界（喂真 t+1），它等价于单跳质量 0.688，
故要求冻结头几乎追平单跳——这是**严格**口径，未过。
但在真正可比成本下（2 次前向只能吃到自己预测的 t+1，命中跌到 0.3128），
跳跃头反而更好 ⇒ 「成本问题」上跳跃头有效，「质量追平 oracle 一跳」上无效。
两者不矛盾，是同一个头的两张脸；**结论以预登记口径为准（失败）**，反向结论如实记录。

## ERRATA（主 Agent 复核修正，2026-09-30）

本节修正 §4「等 FLOPs 双口径」，**原文那条反向结论作废**。

### 问题：deploy 臂的构造不成立

实现为 `xp[:, 1:] = L[:, :-1].argmax(-1)` —— 它把**整段上下文**（位置 1..T-1）替换为
模型自己的 argmax 预测，然后用**真值** `xt2` 打分。因此它量的是「在一段约 30% 字符被
替换过的假文本上预测原文下一个字」——一个按构造就不可完成的任务，**不是自回归跑两次**。

正确的 1-step AR 对照应为：只把**紧邻的前一个位置**替换为自己生成的 token，
其余上下文保持真值。

### 对账（决定性）

t+1 命中 0.6934、真上下文下 t+2 命中 0.6953 ⇒ 正确的 1-step AR 其 t+2 命中
**下界 = 0.6934 × 0.6953 = 0.4822**（t+1 错的那些位置只会往上加）。
实测 deploy 臂 0.3128 **低于该下界** ⇒ 它测的不是这件事。

### 修正后的结论

- **撤回**「跳跃头以半成本反超真实两次前向（+15.4pp）」这一说法。
- H4 判读维持「未过预登记阈值」，但**不得再引用任何 deploy 对比**。
- 判据取向按用户裁决改为：**vs 1-step AR 两次前向**（同成本诚实对手）
  + **草稿接受率 vs 主干自身输出**（SCHEMA §11）；oracle 仅作上界参考。
- 重测与正确的接受率指标见 ticket 29。
