# 2613 分析 · 自门控多跳组合（H3，契约 30-G）

## 人话摘要（先读这段）

**1）它是干什么的。** 让模型一次前向就说出「下下个字符是什么」——这是推测解码里当草稿/
加速多 token 生成要用的能力。主干（普通 12 层变压器）一点没动，只在它的输出状态外面
挂一个很小的变换头。

**2）相对普通的 decoder-only transformer 改了什么。** 主干完全冻结（拿来即用）。
外面的头把主干在第 i 个位置的状态 `h` 做一次 `h + MLP(h)`（记作 T）；
- 「直跳」臂：把 T 作用一次，再由主干自己的字表读出第 i+2 个字符；
- 「连跳」臂：把**同一个 T** 作用两次（T∘T），再读出第 i+2 个字符——参数量和直跳逐位相同；
- 「门控」臂：`h_mix = g⊙(T∘T)(h) + (1−g)⊙T(h)`，`g = sigmoid(G(h))` 逐通道，G 是一个
  d→d 的小网络——即"让模型自己决定走哪条路"。
参数量：直跳 = 连跳 = 262,912；门控 = 394,496（比它们多 131,584，即多出那个门；
相对 13.5M 主干约 +1%）。

**3）为什么要改。** 预测 t+2 有两条路：先跳 1 再跳 1（连跳），或者一步跨两步（直跳）。
用户提出的设计是让一个逐通道的门在两者间插值。本项目此前只测过「条件链 deploy 输给直接头」，
归因是草稿质量瓶颈；**组合结构本身从未测过**，所以本实验只动结构、不动别的。

**4）怎么测的。** 冻结主干 = 2610 的 13.5M dense（sha256 运行时核对，冻结断言 ok），
只训头 2000 步（4 臂 × 2 seed），在**同一批 97,536 个位置**上比 t+2 命中率
（头给出的 argmax 是否等于真正的第 i+2 个字符）。对手不是真值：契约取向（SCHEMA §11）是
**和"主干自己再跑一步"（AR-1，只把紧邻位置换成主干自己的 argmax）比**；喂真 t+1 的 oracle
只作上界参考。

**5）测出来多少（都是"越高越好"）。**

| 谁的哪个数 | 数值 | 参照系 |
|---|---|---|
| 主干读出直接当 t+2（无头） | 0.0684 | 下限锚（2610） |
| 直跳臂（T 一次） | **0.4672** | 结构基线 |
| 连跳臂（T 两次） | **0.4718** | 结构基线 |
| 门控臂（自门控混合） | **0.4738** | 比最好的固定路线高 **+0.0020** |
| 等参数但**没有门**的对照头（394,496 参数） | **0.4785** | 反而最高（比门控高 0.0047） |
| 主干自己跑两步（诚实对手 AR-1） | 0.5489 | 门控头拿到它的 **86%** |
| 喂真 t+1 的 oracle | 0.6953 | 上界，不作判据 |
| 草稿接受率（门的 argmax == 主干自己的 argmax） | **0.6113** | 契约要求 ≥ 0.90 |

判据线（契约 §4，预登记）：门控要 ≥ max(直跳, 连跳) + 0.014 = **0.4858** 才算成功；
实测 **0.4738**，差 **−0.0120**。把步数翻倍到 4000 步，差 +0.0042（0.4896 vs 0.4854），
**仍然在 0.014 的不可排序界内**。⇒ **判为中性（不采纳）**。

**6）结论与下一步。** 自门控组合**没有**拿到可排序的增益，而且它的行为不是"选择"而是"偏好"：
门开度 g 从起点的 0.5 一路涨到均值 **0.82**（96.7% 的位置偏向连跳），被压掉的那条直跳分支
在门控臂里几乎没被训练出来——它单独看只有 **0.262** 命中，而单独训的直跳臂是 0.467。
也就是说：门把两条路合成了"一条半"，结构退化成连跳 + 一点额外容量；等参数、无门的对照头
（0.4785）比门控还高，说明那 +0.0020 更应记在**参数**上，而不是门控结构（§15 归因）。
下一步若要继续，应测「约束门别坍缩（如把 g 拉回 0.5 附近的正则）」或"按位置难度选择"的判据，
而不是继续叠加结构。

## 2. 收敛对账（SCHEMA §16）

所有臂用**同一日志间隔（每 200 步）**、**同一窗口（该组步数的末 25%）**、**同一算法
（对日志点做 OLS）**。

| 组 | 窗口 | direct | composed | gated | direct_eq |
|---|---|---|---|---|---|
| 2000 步，loss 斜率 /1k 步 | 1499–1999（3 点） | +0.1619 | +0.1707 | +0.1625 | +0.1800 |
| 4000 步，loss 斜率 /1k 步 | 2999–3999（6 点） | −0.0650 | −0.0693 | −0.0690 | −0.0600 |

- 2000 步那一行**不是可用的排序证据**：窗口只有 3 个点，且每个点是**单批 8,192 token**
  的 loss（相邻两点波动 ±0.03），斜率符号被采样噪声主导。
- 4000 步那一行四臂都是 −0.06 ~ −0.07/1k（**都还在下降，速度一致**）⇒ 2000 步只是快照，
  四臂都未收敛，没有"某一臂收敛更快"的迹象。
- **2× 步数点（4000 步，seed 0，命中）**：direct 0.4788 / composed 0.4854 / gated **0.4896** /
  direct_eq 0.4882 ⇒ Δ(gated − max(direct, composed)) = **+0.0042**（2000 步时是 +0.0020），
  方向一致、幅度仍 < 0.014，且 gated 与等参数无门对照（0.4882）差 +0.0014。
- 口径：快照（2000 / 4000 头步）@ 冻结 12k 步主干；非渐近、非墙钟、非 FLOPs 归一。

## 5. 三道对账（SCHEMA §12）

**① 算术对账。** 链条：无头 naive t+2 = 0.0684（下限）→ 三臂 0.467 ~ 0.479 →
诚实 AR-1 = 0.5489 → oracle 上界 = 0.6953。门控头拿到两步法命中的 0.4738/0.5489 = **86.3%**，
位于 [naive, AR-1] 区间内，量级自洽。判据所需的门槛 = 0.4718 + 0.014 = 0.4858 高于诚实 AR-1 的
88.5%（0.4858/0.5489），即它要求的不只是"组合结构有用"，而是"接近两步法"。实测差 −0.0120。
二项标准误 sqrt(0.4738×0.5262/97536) = **0.0016**，0.014 的界约 8.8 个标准误 ⇒ 实测 Δ = +0.0020
约 1.25 SE，**不可排序**（与判决一致）。

**② 任务对账（对照臂三要素）。**

| 臂 | 输入分布 | 预测什么 | 部署中对应什么 |
|---|---|---|---|
| direct / composed / gated / direct_eq | 冻结主干在同一位置 i 的真实前缀状态 `h_i`（teacher forcing 前缀） | 真值字符 t_{i+2} 的 argmax | 一次前向后给出第 2 个草稿 token |
| ar1_deploy（诚实对手） | 真值前缀 0..i + **主干自己**在 i+1 的 argmax | 真值 t_{i+2} | 主干跑两次的第二次 |
| oracle（仅上界） | 真值前缀 + **真值** t_{i+1} | 真值 t_{i+2} | 不可能实现，仅参考 |

四臂与对手在**同一位置集**（同一 eval seed、同一批次顺序、行 i = t_{i+2}）、同一目标上打分；
接受率的分母（`ar1` 的 argmax）只算一次、四臂共用 ⇒ 不存在"假上下文 + 真目标"式的不可比对照。
注意：本实验的输入**不含** i+1 位置的信息（头只看 h_i），这是"一次前向出 t+2"的真实设定。

**③ 口径对账。** 本实验 shared 锚与 2611 逐位相同（ar1 0.5489 / oracle 0.6953 / trunk_t1 0.6934），
direct 臂与 2610 的 t2 头差 0.0005 ⇒ 口径一致。所有数字口径 = **快照**（2000 头步，另报 4000 头步），
冻结主干 12k 步，位置数 97,536；不给渐近、不做外推。

**对账结论**：通过（本实验报告的是**中性/否定**结果，仍按 §12 做满三道）。

## 7. 口径标注与已知偏差

- **口径**：快照（2000 头步 / 4000 头步收敛点）@ 冻结 12k 步主干；命中率 = argmax == 真值，
  位置数 97,536（enwik8 末 10M，24×16 窗口）；接受率 = P(头 argmax == 主干自身 AR-1 argmax)。
- **已知偏差 1（契约内不相容）**：契约写「G 单边零初始化（起步等价 direct 或 composed）」，
  但 sigmoid 门下 σ(0)=0.5，两者不能同时满足。本实验取 SCHEMA §10 的硬纪律**单边零**
  （输出侧 `fc2=0`、输入侧 `fc1~N(0,0.02)`），因此**起点是两臂的 50/50 混合**（单测钉住 g≡0.5），
  **不是** direct/composed 的逐位等价。判据线不受影响。
- **已知偏差 2（参数量≠逐位相同）**：gated 比 direct/composed 多 2d²+2d = 131,584 参数（头 +50%，
  主干 +1%）。为满足 §15 加了 `direct_eq` 等参数对照（394,496 逐位相同、无门）。
- **偏差 3**：`direct_eq` 是**本实验附加**的对照臂，不在契约 G 的判据线内；只用于归因。
- 不报渐近、不做 13M→更大规模的外推；FLOPs 未做归一（direct×1、composed×2、gated×2+门）。

## 8. 稳定性、门活性与契约缺陷

- **稳定性**：12 次头训练（3 臂 × 2 seed + 2×4000 步确认 + 等参数对照）loss 全程有限、无 NaN/Inf、单调下降；冻结主干、无优化器状态风险。
- **门活性口径**：`intervention.alive` 只断言变换 T 的非零率；**门的活性由 `gated_g_at_eval` 证明**（起点 σ(0)=0.5 → 实测均值 0.8251，96.7% 位置偏向连跳），不要把 `alive: true` 读成「门已被断言覆盖」。
- **契约缺陷**：契约要求「sigmoid 门 + 单边零初始化 + 起步等价 direct 或 composed」三者不可兼得（σ(0)=0.5）；执行者按 SCHEMA §10 取单边零、起步为 50/50 混合并显式记账。该缺陷已写入 SCHEMA §17 契约模板易错点。
