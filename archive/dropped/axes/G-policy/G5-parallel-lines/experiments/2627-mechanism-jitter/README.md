## 0. 一句话

V2（24k）测得机制净效应 `l1@K8 − repr01@K8 = +0.0144`，只比不可排序门槛 **0.014** 高

## 4. 判据线（预登记，跑之前写下，跑完不得改）

### 4.1 一号问题（抖动判决，**primary**）

> 记 run A 的净效应 `net_A = l1@K8 − repr01_A@K8`，run B 的 `net_B = l1@K8 − repr01_B@K8`
> （`l1@K8` 复用 2626 读数，两次相同 ⇒ 净效应之差 = `repr01_A@K8 − repr01_B@K8`）。
> 极差 `range = |net_A − net_B|`。按 **V2 效应本身 `effect = 0.0144`** 判三态：
> 1. **`range ≥ 0.0144`（效应本身）⇒ 机制结论降级为「不可排序」**（写进账本）；
> 2. **`range < 0.005`（≪ 效应）⇒ 机制结论升格为「稳健」**；
> 3. 其余 ⇒ **仍贴门槛 / 未决**（抖动可观但未到吞掉效应）。

- **基准是谁**：`l1_A` 臂（同 2626 曲线、同 24k 步、同 seed 的单路径机制模型）。
- **代价项相对谁算**：`repr01@K1 − l1@K1`，与基准**同一口径**。
- **primary**：本判据是 primary；主判据（多线 vs 单线缺口）不在本实验范围内（V2 已判 +0.0346 不成立）。
- **算力账**：`l1@K8` 与 `repr01@K8` 都是 8× 前向/token；两次读数的**算力相同**，故抖动是纯训练抖动。

### 4.2 §17.17 分量分解（净和不可排序时**必给**）

> 净效应 = **集成增益（K1−K8）− clean 税（vs `l1`）**。分别报 A、B 两 run 的
> `clean_tax = repr01@K1 − l1@K1` 与 `ensemble_gain = repr01@K1 − repr01@K8`，
> 并给两者之差；据此区分「机制无用」与「机制有效但代价抵消」。

### 4.3 必报项

1. **跨运行复现**：本轮重评 `l1_A`/`repr01_A` 应与 2626 记录（1.4089 / 1.3945 / 1.4389 / 1.4277）
   **逐位相同**（评测确定性；由 `run.py` 断言并入账）。
2. **配对 CI**：`repr01_B − repr01_A` 的 60 批配对 bootstrap 95% CI（`seed=21`）。
3. **200-batch battery**：A vs B 的 clean bpc 与差值（独立协议）。
4. **成对 JS**（K=8）三臂。
5. **确定性路径对照**：`repr01_B` 强制 `p_skip=0`，增益应恰好 0 且 K 条路径 logits 逐位相同。
6. **活性量每 200 步**（`repr_decorr`/`skip_frac`/`gnorm`/`n_paths`）与 `gate_skips`（须为 0）。
7. **收敛门禁（§17.15）**：落在决定判据的量上——两 run 的机制净效应在**共享的 24k 末点**直接测；
   并报两 run 的训练总 CE 末窗斜率（**并报**，不得代替判据量口径）。

### 4.4 口径与禁令

- **口径**：matched-step **快照**（每 run 24000 步、同一 24k cosine 调度、同 seed=0）；
  K 曲线用 **60-batch probe 协议**（与 13M 锚点同函数同 seed）。
- **禁外推（§17.11）**：两次读数只给出**本配置、本规模、本调度**下的抖动；**不得**外推到其他 seed、
  其他规模、其他任务。**只报极差，不报置信区间外推**（n=2 无法估分布）。
- **口径事实**：本实验**固定 `l1@K8`**（复用 2626），故极差**只**度量 `repr01` 臂的 run-to-run 抖动，
  **不**含 `l1` 臂自身的抖动 ⇒ 是**净效应抖动的下界**（如实标注）。
- **本实验不覆盖**：**50M 的 0.0322 缺口**（§23 第 6 问的未测项）——本实验只做 13M；
  主判据（多线 vs 单线）也不在本实验范围内。
- **失败决策树**（结论可疑时按序排除）：① 测量（配对 CI/复现检查）→ ② 实现（run B 是否真是同配置、
  去相关是否活着、`gate_skips` 是否为 0）→ ③ 规模/收敛（两 run 是否同轨、CE 斜率是否接近）→
  ④ 随机性本身（CUDA 非确定性 ⇒ 该点抖动就是这么大）。

## 10. 既有做法（prior art，`SCHEMA §18`）

**检索条件**：本环境**联网检索不可用**（未注册 web / `web_search` 工具）。因此外部系统一律标 **`记忆·未核`**，
只作设计方向、**不得作判据**；本地条目标 `本地实测` 并给路径。完整分诊见
`axes/G-policy/PRIOR_ART_DECORRELATION.md`（ticket 37 知识线）。

1. **谁做过**：**run-to-run 方差 / seed 敏感性**是深度学习实验的通用议题；本环境典型先例如
   `记忆·未核`（如 "Deep Reinforcement Learning that Matters" 论 seed 方差），本地先例是
   `SCHEMA §17.18` 记录的 **ticket 41-Z3 事故**：同配置两次训练读数差 **15×** ⇒ 该腿降级为辅助腿
   （`本地实测`，`SCHEMA.md §17.18`）。
2. **为什么这么设计**：`docs/methodology.md` 的不可排序门槛（Δ<0.014）是**评测/比较**的方差界；
   当一个效应的点估计**只比门槛高 ~3%** 时，「它是否真的越过门槛」取决于**训练随机性**有多大 ——
   必须先估抖动，才谈得上「稳健」。
3. **它的实测结果**：本仓库**没有**「同配置同 24k 重跑、估机制净效应抖动」的既有读数（`(c)`，
   联网不可用不能证伪其存在）；V2 自己把这条列为「未测项 #3」（2626 `analysis.md §10`）。
4. **我们的增量在哪**：
   - 把 V2 的**单点「保持」**升级为**带抖动界的「稳健 / 贴门槛 / 不可排序」**；
   - **零新配置**（逐字节同配置）⇒ 抖动是纯随机性，不掺杂配方漂移；
   - 先做跨运行复现检查（重评 2626 权重逐位相同）⇒ 抖动只来自训练、不含评测。

## 11. 能力面 + 共享面分析（`SCHEMA §22` / `§22.8`，派发前已做）

- 所有互斥校验都在 **depth-AR 引擎**（`attn_sparse_k / train_window / attn_linear / n_kv_heads /
  carry_rule / topology` 两两互斥、block 类二选一）。**G5 多线机制不在该引擎里**——它走 loop-era
  引擎 `pathlm/model.py` + `train_m1.py`。

- **结论：所需组合在引擎里存在，无不可组合项；本线不改任何引擎文件。**

**共享面**：本线只新增本实验目录 + `tests/test_mechanism_jitter.py`；**不写** `train_m1.py` / `pathlm/*.py`
