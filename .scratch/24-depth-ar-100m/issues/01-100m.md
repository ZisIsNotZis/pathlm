# 24 — 深度自适应 AR @100M：形态税的规模验证

- **Status:** in_progress（委派子代理）
- **Related:** 23 系（13M 形态验证：性质 1-4 成立，matched 税 +0.31 proj-fill
  新最优，随训练收缩）、19（100M 渐近口径与基线）
- **目标（重大节点）**：形态税是否随规模收缩（13M matched +0.31 → 100M ?）。
  ticket-19 的经验（快照税随规模与训练下降）预测收缩；若反向则缩放定律修正。

## 形态规格（= ticket 23 定案的 100M 版）

- 骨架：d=720 / L=12 / heads=12 / seq 512 / mlp_mult 6（≈102M 参数，与
  B0_100M/C1_100M 同参对照），V=205。
- 目标：纯 AR 教师强制（无 corruption/retry 站）。
- **全深度并行监督**：depth 0..L 逐深度 tied-unembed CE（depth 0 = embedding
  直连读出），fp32 头，权重均匀 + 最终深度 2×。
- **逐通道携带门**：h_{k+1} = h_k + g_k⊙Refine_k(h_k)，g 初始化偏向 carry。
- **随机退出深度 + proj-fill**：每 position 采样退出深度，KV 用退出深度表征
  填充深层（proj-fill = 恒等初始化逐层 adapter，ticket 23e 新最优）。
- 训练：24000 步 × batch 8（= B0_100M 的 1.1-epoch 口径，同 token 预算），
  lr 1e-3 cosine，bf16 autocast，seed 0。

## 实现（train_depth_ar.py 规模化，additive）

- CLI 补 mlp_mult/seq_len/batch_size/lr/cosine 全参数化；
- bf16 autocast（回环时代律：aux 损失 fp32 + 梯度范数监控）；
- PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True；
- 显存预估：batch 8 + 全深度 hook CE（205 词表 ~160MB）≈ 6-10GB，余量充足；
  若 OOM 按 playbook 降 batch（记录混杂）。
- **先 20 步冒烟再全跑**。

## 对照与判读

| 对照 | 数字 |
|---|---|
| B0_100M（无 dense，ticket 16） | clean **1.4612**（s0），渐近（96.6k）1.3411 |
| C1_100M（retry+corruption 机制） | clean 1.5871，corrupt r1 2.015 |
| 13M 形态税（matched 12k） | +0.31 |

判读：**形态税 @100M（1.1-epoch）= 本 run clean − 1.4612**。判据：
- 税 < +0.31（13M matched）且 ≤ +0.15 → 形态随规模改善，进渐近/Stage-2；
- 税 ≈ +0.3 → 规模中性（配合 ticket-19 渐近系数，渐近预期 ~+0.2，如实记录）；
- 税 > +0.5 → 规模恶化，缩放定律修正。
副测量：depth-bpc 曲线、逐深度出口 tf、门行为、（时间允许）uniform-exit
wall。**收益侧必报**：exit 资产（tf@4+）与 exits 相对 dense 的成本轴。
