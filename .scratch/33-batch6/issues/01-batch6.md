## 契约 Q：有界内存的悬崖——窗口 192 训练（M3/A9）

- 目录：`axes/M-carrier/M3-cross-step-assumption/experiments/2616-window192-trained-13m/`
- 文件所有权：可改 `pathlm/depth_ar.py`（复用既有 `--train-window/--train-anchors`，如缺评测端
  掩码对齐需补）、`train_depth_ar.py`、`tests/test_depth_ar.py`、本实验目录。
- 动机：ticket 32-O 测出「训练成只看最近 32」的税 = **+0.0866**；而同一仪器测「把全注意力模型
  限制到最近 192」的**评测期**代价只有 **+0.004**、最近 128 是 +0.020、最近 64 是 +0.081。
  于是产生一个可判定、且**不能靠外推**回答的问题：**窗口长度是不是一条带悬崖的杠杆？
  把窗口放到 192，训练税能不能压到 ≈0？**
- 干预（唯一变量 = 训练期窗口长度）：`window192`（只看最近 192 + 8 锚点）vs
  `full`（复用 2614/32-O 的全注意力基线，给配置等值性逐字段对照）。
  其余逐字段一致（`--dense`、seed=0、12k 步、bs32、seq256）。
- **判据（预登记）**：
  1. **主判据**：`window192` 的 clean bpc 相对 full 的 Δ **≤ 0.014** ⇒ 「有界内存可近零代价」成立
     （这是本批可能出现的正面结论）；Δ ≥ +0.050 ⇒ 悬崖在 192 以下，记录；
     中间值如实报。
  2. **曲线定位**：把已有的 `recent:32/64/128/192` 评测期四点与本次训练点并列成表，
     给出「训练税 vs 窗口长度」的**两个数据点**（32、192），并**明确标注不得外推内插**。
  3. 附：`window192` 的评测期依赖曲线（仪器）与窗口外针召回（检索腿），与 32 的结果对照——
     验证「窗口放宽后，窗口外的针是否仍然只是「丢了」」。
- 成本：训练 ≈7 min + 仪器 ≈5 min ⇒ ≈15–25 min。
- 交付：统一清单（本批统一清单见文末）。

## 契约 R：线性注意力 vs 全注意力（A6 混合算子续）

- 目录：`axes/A-mixing/A6-mixing-operator/experiments/2616-linear-attention-13m/`
- 文件所有权：可改 `pathlm/depth_ar.py`（新增线性注意力开关，缺省逐位还原 v1）、
  `train_depth_ar.py`、`tests/test_depth_ar.py`、本实验目录。
- 动机：ticket 31-J 已证「内容选择式 top-k」在 T=256 净亏（质量越界 + 实测 2.2× 慢、KV 不省）。
  线性注意力不同：它**不需要全分数矩阵**，理论上同时降时与降内存，是本轴上最可能「不亏」的算子。
- 干预（唯一变量 = 注意力算子）：`linear`（特征映射 φ(q)·φ(k) 的线性注意力；用 elu+1 或
  cosformer 简化形式，实现方式在 README 里写明并单测钉住）vs `full`（基线）。
  其余逐字段一致（`--dense`、seed=0、12k 步）。
- **判据（预登记）**：
  1. 质量：|Δbpc| < 0.014 ⇒ 与全注意力同质量；Δ ≥ +0.014 ⇒ 线性化在该规模有害（记录幅度）；
  2. **成本交叉点（SCHEMA §17 第 9 条）**：必须报**理论**（注意力 FLOPs、KV 内存）与**实测**
     （ms/step、峰值显存）两组数，并写出「在什么 T 上开始回本」；
  3. 附：`linear` 的评测期依赖曲线（仪器）——看线性注意力是否天然更依赖近处。
- 成本：2 臂 × ≈7–15 min + 评测 ≈20–40 min。
- 交付：统一清单。

## 契约 S：KV 头共享（GQA / MQA）——参照线补齐（W3/R1）

- 目录：`axes/W-width/W3-kv-head-sharing/experiments/2616-gqa-mqa-13m/`
- 文件所有权：可改 `pathlm/depth_ar.py`（新增 KV 头数配置，缺省逐位还原 v1）、
  `train_depth_ar.py`、`tests/test_depth_ar.py`、本实验目录。
- 动机：我们已有「KV 量化」的价签（int8 近无损、省一半内存）。工业界的另一条同分叉路线是
  **减少 KV 头数**（GQA/MQA）。地图上 W3 是空白；补上它，「省 KV 内存」的参照线才完整。
- 干预（唯一变量 = KV 头数）：`mha`（基线，8 个 KV 头）vs `gqa`（2 个 KV 头）vs
  `mqa`（1 个 KV 头）。其余逐字段一致（`--dense`、seed=0、12k 步）。
- **判据（预登记）**：给出三臂 clean bpc 与**解析** KV 内存下降（GQA −75%、MQA −87.5%）；
  若 |Δbpc| < 0.014 ⇒ 记「近无损」并写入参照线（与 int8 KV 的近无损 −50% 对照）；
  若越界 ⇒ 记其代价。必须附三臂同方法斜率与重跑散度。
- 成本：3 臂 × ≈7 min + 重跑 1 臂 ≈7 min ⇒ ≈35 min。
- 交付：统一清单。
