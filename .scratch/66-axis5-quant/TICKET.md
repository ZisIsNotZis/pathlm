## 2. 六格「想清楚」结论（人话：痛点 → 相对 SOTA 的增量）

| 格 | 痛点 | SOTA（本轮核实） | 相对 SOTA 的增量（不是「做一遍量化」） |
|---|---|---|---|
| 5.1 KV 量化 | 长上下文解码被 KV cache 的**字节数**卡住 | KIVI `2402.02750`、KVQuant `2401.18079`、Atom `2310.19102` | 机制**不是**增量（本仓 `block` ≈ 业界 per-channel/分块标尺；`block_tok`/`kivi` ≈ KIVI 的 K 侧 per-token）。增量 = ①13M 受控下「**每位置部署字节（值+标尺+staging）**→ 两腿质量」前沿（业界按比特位宽报）；②把**严格前缀不变性**当独立硬门禁（KIVI 式沿 token 分块正违反 ⇒ 须 staging）；③跨家族统一字节轴 |
| 5.2 权重量化 | 权重显存/访存 | GPTQ `2210.17323`、AWQ `2306.00978`、LLM.int8() `2208.07339` | 不重造 GPTQ/AWQ 算法。增量 = 13M 受控「每参数部署字节（含分组标尺）→ 两腿质量」前沿 + 权重/KV/激活**三类账**在同一框架下分开报 |
| 5.3 激活量化 | 激活是动态张量、体量随 batch×T 涨；离群通道 | SmoothQuant `2211.10438`、LLM.int8() `2208.07339`、Atom `2310.19102` | 不重造 SmoothQuant 的迁移算法。增量 = 小尺度受控的**含标尺激活字节账** + 把「逐层标尺 / 离群通道」做成**可失败的活性判据** |
| 5.4 低秩压缩（MLA 式） | 每头独立 K/V ⇒ 随头数×头维线性涨 | DeepSeek-V2 MLA `2405.04434`（`head_dim`=128） | 增量 = 与头共享（GQA/MQA）在**同一每位置字节轴**上比（业界缺统一字节轴，`2617` §3 记 `未找到`），并把「须从零训练 + 上投影计算」的代价入账（业界多在已训模型上 uptrain/推理包装） |
| 5.5 fp8 / 大 head_dim | int8 需分组标尺；fp8 动态范围大可能免标尺；`head_dim` 决定标尺摊薄上限 | fp8 格式 `2209.05433`、DeepSeek-V2 `2405.04434` | 增量 = 把 fp8 与 int8+块标尺放在**同一字节轴、同一 13M 设定**下比质量（补 `5.1` 的 fp8 质量缺口）+ 「`head_dim`→G→每位置字节」的解析与实测对账 |
| 5.6 组合：窗口+量化+检索 | 生产默认组合拳必须被打败 | 生产默认（`记忆·未核`）+ KIVI/KVQuant/Atom（本轮核实） | 增量 = 把三条腿（窗口保留曲线、KV 量化、检索）接到**同一字节轴 + 同一检索**上（业界各家族各报各的）；**最高风险是把兄弟线单点重绘当新发现** ⇒ 须自跑组合臂 |

共同前沿口径：纵轴两腿（clean bpc + 合成长程召回），横轴 = 每位置/每参数**解析部署字节（含标尺）**，
判据带 = 0.014（跨格统一）与本格自测带（`5.1` 的在力带 0.036324，见 `2642`）不得混用；跨口径（逐值 vs

## 6. 本轮执行的 WP：`5.1-WP2`（跨家族同字节预算重画）

- 契约（运行前写入）：`axes/5-quant/5.1-kv-quant/experiments/2642-kv-same-byte-frontier/README.md` +
  `config.json::criterion`。
- 入口：`frontier_ledger.py`（纯再分析：读 `2632` 落盘读数 + 四个 checkpoint 的参数量；**无前向、无 GPU 锁**）。
- 门禁结果（运行 `exit=0`）：
  - **G1 PASS**：独立重算的 27 臂部署字节与 `2632::deployment_caliber.per_arm[*].primary.bytes_per_position`
    `max|Δ| = 0`；同时确认 `points[*].bytes_per_position` 是**仅值口径**（int8: 6144 vs 部署 6528）
    ⇒ 两个口径不得混用。
  - **G2 PASS**：进入前沿表的量化臂全为块标尺（`scheme=block`、`G=32`）；无逐值标尺量化数字参与。
  - 输入指纹：6 个输入 sha256 与预登记一致；四个 checkpoint 的 sha256 与 `2632/MODEL.md` 逐位相同。
- 主要结论：① 跨家族**恰好同字节**的分组有 **7 个**（432/768/816/864/1536/1632/3072 B/位置），组内 bpc
  极差**全部越带**（可排序）⇒ 跨家族同字节比较在本网格上**可做、不需插值**；② 7/7 组的 bpc 最优臂都是
  头共享族，但都带参数量混杂 ⇒ 不能归因为纯机制；③ 参数混杂拆开：GQA 少 **8.75%**、MQA 少 **10.21%**
  参数（解析式 `L·(2·d_model+2)·(H−n_kv)·head_dim` 与磁盘实测**逐位一致**）；④ fp8 解析 6144 B/位置
  （×0.50）比 int8+块标尺 6528 省 384 B/位置，**fp8 质量本轴未测** ⇒ 不得称 int8 是 8 位最优；
  ⑤ 旧「同 −75% 档 GQA 便宜 3.2×」随逐值标尺口径作废，块标尺下两族不再同档（3456 vs 3072）。
- 产物：`README.md` / `config.json` / `frontier_ledger.py` / `results.json` / `table.md` / `analysis.md` /
  `MODEL.md` / `run_log.txt`（全部在 `2642-kv-same-byte-frontier/`）。
