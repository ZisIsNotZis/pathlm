## 2. MLA 实现与自检（`checks.json`，纯 CPU，全过）

- 结构：`c = wkv_down(ln1(x))`（d→d_c，无 bias）→ `k = wk_up(c)`、`v = wv_up(c)`（d_c→H·dh，无 bias）；
  `q` 与 stock `Block` 同款（d→d，带 bias）；`sdpa(is_causal=True, enable_gqa=False)`；
  残差 `x + proj(a)`、`x + mlp(ln2(x))` 与 `Block` 逐字段相同。**缓存的就是 `c`**。
- ① 参数量解析 == 实测逐位：MHA 13,536,768 / GQA2 12,352,512 / MLA_c128 13,137,408 /
  MLA_c256 14,317,056 / GQA2_eq 13,536,516。
- ② 等参数算式：Δtarget 1,184,256；逐层 FFN 斜率 2d+1 = **513**；`Δ mod 513 = 252 ≠ 0`
  ⇒ **逐位相等不可能**；最近可达 ΣΔh = 2308（`1729×4 + 1728×8`）⇒ **−252 参数（−1.86e-5）**。
  （派单的「9×193 + 3×192 ⇒ 精确相等」按 512Δh 估算，漏了 `mlp[0].bias` 的 +Δh。）
- ③ 字节轴：MLA_c128 = GQA2 = 1536 值/位置 = **3072 B/位置**（断言相等）；MLA_c256 = 6144 B/位置 = MHA 同字节。
- ④ 因果性/可见性对数不变：改未来 token ⇒ 过去位置输出 `max|Δ| = 0.0`（MLA 与 stock `Block` 对照都 0.0）。
- ⑤ 上投影参考实现（显式 `c→k,v` + 显式因果 softmax）与 SDPA 路径 `max|Δ| = 3.58e-7`；`c == wkv_down(ln1(x))` 逐位。
- ⑥ 解码期代价：MLA_c128 上投影 786,432 MACs/token = **1,572,864 FLOPs/token** = 单层 FFN 的 8.33%；
  投影 MACs 比 GQA2 每层 **+65,536**（比 MHA 反而 −32,768）。

## 3. `--mla-latent 0` 与引擎的等价性（GPU 冒烟，已跑）

| 对账 | step 0 | 末点 |
|---|---|---|
| 引擎 50 步 vs 副本 50 步（同 seed） | 5.4226 = 5.4226 | step 49：2.7002 vs 2.7000（Δ −0.0002） |
| 引擎 201 步 vs 副本 201 步 | 5.4226 = 5.4226 | step 200：2.5591 vs 2.5571（Δ −0.002） |

**不是逐位相同，但原因已核实（非猜测）**：`2616` 的 `gqa-12k-s0` 与 `gqa-12k-s0-rep` —— 同 seed、
同配方、同数据序，**两次都由未改动的引擎训练** —— 首行 loss 逐位相同（5.4463），step 200 就差
**+0.0032**，全程 `max|Δ| = 0.0112`，末值差 0.0014（`2616/stability.md` §2 已写明「初始权重逐位相同
⇒ 差异只能来自 CUDA 归约顺序」，末值 bpc 差 0.0004）。本实验的副本/引擎差（step 200：0.002）**小于**
引擎自身重训的差（0.0032），且两者 step 0 都逐位相同 ⇒ 差异属 GPU 归约序，不是 patch 的语义差异。
`mha-rep-s0`（副本、`--mla-latent 0`、12k 步）首行 loss 也是 5.4226，与 `2616::mha-12k-s0` 一致 ——
同初始化、同数据序的全长旁证。
