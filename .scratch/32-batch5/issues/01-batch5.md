## 契约 M：保留曲线补「检索腿」（仪器补全）

- 目录：`axes/M-carrier/M2-carrier-compression/experiments/2615-retention-retrieval-leg-13m/`
- 文件所有权：可扩展 `tools/evalkit/retention.py`、`tests/test_retention.py`、本实验目录。
- 动机（SCHEMA §17 第 10 条）：现有曲线量的是**依赖**；低损伤可能是「模型本来就不用」。
  必须加一条检索腿，把「不需要」与「保住了」分开。
- 方法：在 T=256 的窗口里植入 K=8 对「针」（x→y 关联，内容不在原文出现，沿用本项目
  needle v2 构造：`archive/legacy-docs/experiments.md` §needle 与
  `.scratch/05-m1-followup/evidence`），查询尾提问；
  对每个「保留配置」（全保留 / 删除最远 N / 只保留最近 d / 连续段删除）同时测
  **两条腿**：
  1. **依赖腿**（已有）：clean bpc 的 Δ；
  2. **保留腿**（新增）：针的**召回率**（以及「窗口内 / 锚区 / 窗口外」分桶，沿用历史分桶语义）。
- **判据（预登记）**：
  - 主判据：两条腿必须**给出不同信息**——存在「依赖腿几乎无伤（|Δbpc|<0.014）但保留腿崩掉
    （召回下降 > 30pp）」的配置区间 ⇒ 证明「低损伤 ≠ 保住了」，仪器成立；
  - 若两腿在所有配置下同向同幅 ⇒ 说明该模型上「依赖」可代理「保留」，也要如实记录（这本身是结论）；
  - 阈值前先报**全保留基线**的召回率（若基线 <50% 视为构造问题，先修构造再测，不得带病判读）。
- 成本：纯推理 ≈10–20 min。
- 交付：契约 README（判据逐字）/ run.py / config.json / results.json（两腿 × 各配置）/
  analysis.md / MODEL.md / 单测（≥3，含「针位置是否只被删一次」的变异验证）。

## 契约 N：三种压缩优先级的对决（A10 用户设计的前提检验）

- 目录：`axes/A-mixing/A10-compression-trigger/experiments/2615-priority-shootout-13m/`
- 文件所有权：可扩展 `tools/evalkit/retention.py`、`tests/test_retention.py`、本实验目录。
- 动机：用户提出「访问感知（LRU）压缩」——每个 token 记住自己被读过多少次，越久没被读到
  的越先压。现在我们有天平可以**直接**比较三种「先压谁」的优先级。
- 干预（唯一变量 = **记录被谁丢弃的优先级规则**，**删除预算完全相同**）：
  - `distance`：先删最远的（现基线语义）；
  - `lru`：先删「最近 k 步内被注意质量最少」的（注意质量 = 该位置收到的注意力权重之和，
    在全保留前向里统计，**评测期可观测**）；
  - `content`：先删「内容与查询最不相似」的（按 key 范数或与查询的平均相似度）。
  三者删同样数量的位置（N ∈ {8,32,64}），比较两条腿（依赖 + 保留，用契约 M 的器材）。
- **判据（预登记）**：
  - 若 `lru` 或 `content` 相对 `distance` 在**同等删除预算**下保留腿召回高 ≥10pp
    或依赖腿伤害低 ≥0.014 ⇒ 优先级规则有信息量（用户设计的前提成立，值得往下做）；
  - 若三者差异都 < 上述阈值 ⇒ **优先级规则不带来可见收益**（用户的 LRU 前提在该规模被否证）；
  - 必须报注意力质量的分布（哪些位置被读得多）与三种规则实际删掉的集合的重叠度。
- 成本：纯推理 ≈10–20 min。
- 交付：同统一清单。

## 契约 O：窗口训练后依赖是否「右移」（A3/A9 直接检验）

- 目录：`axes/A-mixing/A9-old-info-retention/experiments/2615-window-trained-retention-13m/`
- 文件所有权：可改 `pathlm/depth_ar.py`（新增训练期窗口/锚点开关，缺省逐位还原 v1）、
  `train_depth_ar.py`、`tests/test_depth_ar.py`、本实验目录。
- 动机（用户最初的设想）：若模型被训练成只用近处，它是否会把信息**往右压**（即用近处的
  状态承载远处内容），从而「前缀可丢而不掉质量」？
- 干预（唯一变量 = 训练期可见窗口）：
  - `full`（基线）：全可见（**复用契约 I 的曲线作为基线**，不重训；需给出配置等值性对照）；
  - `window32`：训练时只允许看最近 32 个位置 + 8 个锚点（评测时用同一掩码）。
  其余逐字段一致（`--dense`、seed=0、12k 步、bs32、seq256）。
- **判据（预登记）**：
  1. **质量**：`window32` 的 clean bpc 相对 `full` 的 Δ（阈值 0.014；历史 X2 曾测 +0.058~0.121）；
  2. **依赖是否右移**：用同一仪器测 `window32` 的**距离曲线**，与 `full` 比较——
     若 `window32` 在 d ∈ [8,32] 上的伤害显著**小于** `full`（依赖被压到更近），
     记「依赖右移/局部化成立」；
  3. **保留是否成立**：用契约 M 的检索腿测 `window32`——若它在窗口内能答出**原本位于
     窗口外**的针（即信息确实被搬到近处），这才是「右移」的直接证据；若只是答不出，
     则说明是「丢了」而不是「搬了」（必须区分，参照 X3 假保留陷阱）。
- 成本：训练 ≈7 min + 两条仪器 ≈15 min ⇒ ≈25 min。
- 交付：同统一清单 + 与该形态的依赖曲线对照表。
