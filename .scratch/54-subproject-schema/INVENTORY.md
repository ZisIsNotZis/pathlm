# 子项目清单与自检（出资人批注 + 我的自评）

> 用途：供出资人 review。每条：出资人批注（原话）→ 我的自评。
> **我从批注里学到的判据（本文件的自检标准）**：
> 1. **目的 vs 手段**：子项目必须写清「要解决的痛点/目的」；窗口、ALiBi、稀疏核、GQA 都是**手段**，不是目的。只列手段、没有目的 = 瞎研究。
> 2. **研究问题 + 假设**：每项必须能一句话说清「问题是什么、假设（预期创新效用）是什么、怎么端到端验证」。说不清 = 瞎研究。
> 3. **基线/参照不进列表**：基线、参照线、修饰符都是手段/工具，放 scratch 或共享底座，不占子项目。
> 4. 用出资人的词：目的叫**信息右移**（information right-shift）等，不用我自造的说法。
>
> 处置标签：`保留` / `并入 X` / `拆` / `降参照` / `删` / `移出（非子项目）`。
