## ① 这是什么
"什么时候压、先压谁"——压缩/驱逐的**触发与优先级**（固定间隔 / 距离 / 访问频率 LRU / 学习式 / 信号驱动）。

## ② 对着什么 sota，我们偏离在哪
sota：**H2O**（heavy-hitter）、Scissorhands、SnapKV、PyramidKV/Ada-KV（都是"按注意力重要性/访问频率驱逐"）、StreamingLLM、Compressive Transformer（固定压缩率）。**本格的"偏离"声明是自相矛盾的**：`catalog.yaml:415` 的 备注写"业界无人占位（访问感知压缩）"，而**同一仓的** `axes/A-mixing/PRIOR_ART.md` §A10 明确列了 H2O/Scissorhands/SnapKV/H2O-heavy-hitter 一族，并写"与业界结论不一致 ⇒ 属 (b)"。所以"无人占位"是错的；这也让"我们与 H2O 相反的负结论"缺少一个**可核的**对手。

## ③ 五类问题逐条判定
1. **开倒车：无（是"与业界冲突的负结论"，属 §21 的 (b)）**——但要小心：H2O 一类报"低预算近无损"的**基线强度争议**是业界自认的（`PRIOR_ART.md` 自己标 `不确定`）⇒ 我们的负结果**可能就是"基线更公平"的体现**，这是有价值的；但**没有可核出处**，不能当"推翻业界"。
2. **过程错误：有（中）**。
   - **判据算术不可达**：召回腿门槛"比 distance 高 ≥10pp"，而上界是全保留基线 0.6868（`2615/analysis.md` §6.1.1：781 需 ≥0.765 > 0.6868）⇒ SM 判据从设计上不可能通过，属契约缺陷（§17.1 同族问题）。
   - **口径前后不一**：契约字面裁决 `priority_rules_informative`（位置数预算）被自己的**对数重对齐** ERRATA 推翻（`2615/analysis.md` §6.4）——处理得很诚实，但说明**判据写错了**（预算定义未在契约里钉死）。
   - **统计量含未来查询**（§11 自述）：LRU/content 的统计取自全保留前向的**整窗口（含未来 query）** ⇒ 偏向 lru/content；这已被标注，但意味着"无收益"是**偏强**的负结果，**不能**说"LRU 一定无效"。
   - **被测对象 ≠ 格子命题**：格子命题/备注是"每个 token 携带自己的吸收率/剩余率"（`catalog.yaml:415`），`judge` 写"固定压缩率 ρ 下的重建质量 + ρ-质量曲线"（`catalog.yaml:405`），而**实际测的是评测期一次性删除的三种优先级**；分析自己承认用户想法的严谨对应物是**写入算子**（delta，`2615/analysis.md` §6.4/direction 与 `catalog.yaml:427`），而那个在 M1 格测的。⇒ 该格用"judged"回答了一个**不是它自己命题**的问题。
   - n=1、单模型（未重训）、单任务、单规模。
3. **结论错误：有（轻微但重要）**。**正确结论**："**在本设定**（13.5M/12k/T=256/enwik8/评测期一次性删除/统计含未来查询）下，同等**位置数**预算的三种删除优先级没有可排序的质量收益；而**同等可见性对数**预算下 lru 反而更差——这说明'删除预算'必须先定义成物理量再比较。"（这正是 §17.12 的推广，是有价值的。）**不应写成**"访问感知压缩无效"，也不应保留"业界无人占位"。
4. **无意义：部分**。已测的那问（哪个驱逐优先级更好）在 13M/256/n=1 上**不可能**改变判断；声明的那问（per-token 吸收率压缩）**根本没测**。
5. **值得做：有（中）**：① 换成**流式（只看过去）**统计重测（现在的口径偏向被比较的规则）；② 只按"可见性对数"做预算；③ 测**真压缩率** ρ 曲线（写算子：把源 token 压成 summar；不是"删多少"）；④ 与"就用个窗口"（A3）同台。
