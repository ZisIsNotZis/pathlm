## ① 这是什么
"用什么算子把被看见的信息合并起来"：softmax 注意力 vs 内容 top-k 稀疏 vs 线性注意力 vs SSM vs 卷积/池化/Fourier。

## ② 对着什么 sota，我们偏离在哪
sota：**内容选择式稀疏 = NSA / MoBA（2025）**；**线性注意力 = Katharopoulos 2020 / Performer / Linformer**；**SSM = Mamba/RWKV/RetNet/GLA**；混合架构 Jamba/Zamba 已是主流折中。偏离有三处、且**三处都让结论偏向"亏"**：
(a) 只测 **T=256**，此处注意力只占每 token MACs 的 **14.3%**（`2Td/(12d²+2Td)`，我按公式复算）⇒ 任何注意力算子改动最多只能省 6%，**结构性不可能赢**；而业界卖点全在长上下文。
(b) top-k 实装走**稠密打分 + 稠密混合**（`pathlm/depth_ar.py:377-380`：`w = scores.masked_fill(...).softmax(-1)`，`a = w @ vs`）⇒ **实装 FLOPs 节省为 0**；"注意力 FLOPs −43.75%"（`catalog.yaml:339`）是**假想内核**的数字，不是本实验的实测。
(c) 长 T 系列测的是**窗口（位置稀疏）**，不是内容 top-k——机制与格子标题不是一回事（见下）。

## ③ 五类问题逐条判定

### 开倒车：有（部分）
- "内容 top-k 在 T=256 净亏"是**算术必然**（(a)+(b)），业界从没声称它在短上下文回本；把它写成格子的首条 verdict（`catalog.yaml:335`）是打稻草人。
- 线性注意力被记为"**干预在当前实装下不可行**"（`catalog.yaml:341`），但执行者自己的二分实验在独立进程里跑通 3000 步（`2616/analysis.md` §3 行 5：chunk∈{32,64,256}×eps 全跑完，71–75 ms/step）⇒ 这是**工程债（父进程 CUDA 上下文 + 轮询组合）**，不是算子性质。写成"不可行"会污染下游判断。

### 过程错误：有（重）
1. **机制错格**：`2614`/`2616` 是内容 top-k 与线性注意力（A6 本职）；`2622–2629` 全部是 `train_window=T/2` 的**位置窗口**，属 A3 机制（`2614/analysis.md` §0 自己也说"位置窗口稀疏才能真的把缓存砍到 k/T"，与内容稀疏是**本质上不同的东西**）。A6 的 `verdict` 却用后者支撑"稀疏的收益要到长上下文才可能出现"。
2. **跨 T 趋势被步数与退火表混杂**：三点 `steps = 24000 / 12000 / 6000`（`2626/README.md` §6），lr 调度分母是 `steps`（`train_depth_ar.py:201-202`）⇒ 跨 T 同时改了**更新次数**与**退火长度**；`2629/analysis.md:279-280` 自认"两臂**都未收敛**"。而 A9 已自证"更弱的模型天然有更平的损伤曲线"（`2615/analysis.md` §8.3）⇒ **"窗口代价随 T 增大而消失"正是欠训练所预测的形状**，不是窗口机制的性质。
3. **长程腿是坏仪器**：`2626/analysis.md` §8 的合成腿（`var_recall` 三档）全在 chance，报告解释为"§19 局部先验强、模型不需要"。但本仓自己已文档化**该任务变体（查询键放在末位 T−1）是位置外推伪影**：`2623/analysis.md` §9 实测同一权重在单查询末位布局上 `full = 0.0000`，迁到训练同族多查询布局才是 0.3665。⇒ A6 的长程腿**不可能区分任何东西**，其"空结果"被错误归因；结论因此**完全没有合法的长程证据**，却在标题里下"要到长上下文才可能出现"的判断。
4. **§4 的"实测 vs 公式"单位错**：`2626/analysis.md` §4 把"注意力子层孤岛（qkv→attn→out 投影）**单层** fwd+bwd / **8 层**整模型步时"与"整模型 MAC 占比"并列，得出"公式显著高估墙钟注意力占比"。我逐点复算：实测 ≈ **(单层注意力块占比)/8**（5.6/6.6/8.5% vs 5.4/6.3/7.5%）⇒ 两条曲线差一个约 8× 的常数因子，**不可比**，"公式高估"不成立。且同一口径在两个实验里给出 10.78%@512（2622）vs 6.6%@512（2626），报告自己归因"machine/kernel 状态"⇒ 该仪器本身不可靠。
5. **n=1 + 显著性的口径**：`k=32 Δ=−0.0166` 只比 0.014 界高 **19%**；`paired_eval.json` 的 `t=−7.73` 是**同批评测位置**的配对差（20 批），度量的是"这两个已训好的模型在评测数据上的差"，**不含训练重跑方差**；而 `catalog.yaml:337` 把 `20/20 批同向，t=−7.7` 当效应真实性证据，属把相关样本当独立证据（同类问题见 49-REPORT B2，此处**未修**）。
6. **证据锚缺失**：`catalog.yaml:352` 只锚了 `2614/2616/2622` 三个 analysis.md，而 bullet 4–10 引用的 ticket 39/40/41/42/43/45/46（即 `2623–2629`）**没有任何证据锚**；`check_schema.py` 也不会发现（它只查列出的路径存在）。

### 结论错误：有（要写清"正确结论应该是什么"）
- **可留（真结论、对下游有用）**：① **内容选择式稀疏结构性地不能省 KV 缓存**（要选必须先有全部 KV）⇒ 想让缓存变小必须走位置窗/可提前丢弃；② 本实装下 T=256 步时 ×2.2、显存 ×1.7 ⇒ **"省算力"必须报成本交叉点**（§17.9）。这两条是干净的。
- **应改写**：③ `k=32 越界有害` → "Δ = −0.0166（**贴边越界 1.19×**、n=1、未过双种子；界本身是单臂估计，见 A-AUDIT）⇒ **不可排序**"。④ "窗口代价随 T 消失" → "在 13M/enwik8/**步数不等**/未收敛的三点上，Δ 从 −0.0158 变到 +0.0093；bpc 口径下窗口不再更差，**长程保留未测（合成腿是伪影）**，且未排除欠训练"。⑤ "线性注意力不可行" → "**本 harness** 下训练停摆（独立进程 3000 步正常）⇒ 工程债"。
- **应当指出的方向性错误**：A6 用 enwik8 bpc 判"稀疏在长上下文是否回本"，而 enwik8 的 bpc 差主要反映"更多上下文对本地统计是否还有用"。§19 明文要求长程结论必须在弱局部先验任务上复核，A6 试图做了却用了坏仪器 ⇒ 该结论**没有**过关。

### 无意义：边界
- "top-k 在 T=256 净亏"本身信息量低（算术必然）；**真正值得做而没做的是**：真稀疏核 + 长上下文（T≥2048）质量 + 位置稀疏/内容稀疏同预算对照。

### 值得做：有（最高优先）
1. 先修长程腿（用 `2623` 的 in-distribution 多查询布局），再判"窗口/稀疏是否丢长程"；
2. 长 T 序列改为**同 step 或同退火刻度**，并补 n≥2；
3. 真稀疏核（块稀疏）把"理论省 FLOPs"兑现，然后才是成本结论；
4. 把 `2622–2629` 迁到 A3（机制归属），A6 只留算子。
