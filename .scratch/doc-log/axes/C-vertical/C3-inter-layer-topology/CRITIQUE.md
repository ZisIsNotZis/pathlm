### ① 这个课题是什么（我自己的话）
把「层与层之间怎么接」换掉——一层内部让注意力和 MLP 同时读同一份输入（并行子层），或每层输入改成对它之前所有层输出的学习加权和——在等参数、同配方下量 clean bpc 有没有便宜可捡。

### ② 对着什么 sota，我们偏离在哪
- **并行子层**：GPT-J / PaLM 采用，**动机是吞吐**（少一次串行依赖），业界普遍承认有少量质量代价。**我们的偏离**：只量了质量与「秒/步」（`analysis.md §2`：0.0325 → 0.0300 s，−8%），没有量它真正要买的那个收益（长 T / 大 batch 的吞吐），却用「明确有害」表述（`catalog.yaml:544`）。
- **层间加权和**：对着 DenseFormer（对历史层输出做 depth-weighted average）。**我们的偏离（可核）**：本地实现把 α 初始化为「只取上一层」（`pathlm/depth_ar.py:1963-1967`），**无单纯形约束**，训练后第 1 层输入被放大到 **2.36×**（`analysis.md §3.1`）。`analysis.md §7.3/§9.3` 自己承认「严格按字面的 DenseFormer 语义…不存在」。所以这是一个**变体**，不能用来判「与业界不一致」。

### ③ 五类问题逐条判定
**1 开倒车：部分（有）。** 并行子层是业界标准件，我们用质量面（13M、短 T、bs 32——恰恰是并行最不划算的 regime）宣布「明确有害」，把业界权衡的另一半（吞吐）留在测量之外。DenseFormer 的「与业界冲突」（`catalog.yaml:549`）建立在一个语义不同的变体上。

**2 过程错误：基本没有——本格是全 C 轴方法学最干净的一格，我逐条独立核过并复算。**
- 等参数对照真实：`parallel-dual-ln` 参数量逐位相同（6,962,688），`results.json::params_delta_exact`；算术复核 6,958,592−6,962,688 = −4096 = −L·2d ✓；6,962,724−6,962,688 = +36 = L(L+1)/2 ✓（`analysis.md §6.1`）。
- Δ 复算：1.5246−1.5254 = −0.0008 ✓；1.5712−1.5254 = +0.0458 ✓；1.5656−1.5254 = +0.0402 ✓。
- 收敛对账同方法（末 25% 窗、四臂同算法），极差 0.0020 nats/1k；历史锚用当前代码逐位复现（1.5287/0.6894）。
- 变异验证 3/3 抓红并逐字节还原（`mutation_report.json`）。
- 唯一缺口：n=1 seed、24k 未跑——因本实验**没有报任何增益**，SCHEMA §16 的更长点要求不触发，这个豁免成立。

**3 结论错误：有（一处措辞）。** `catalog.yaml:549`：「密集/跨层注意（DenseFormer、Hyper-Connections）报告同规模小幅增益；本地 dense 加权和为中性」⇒ 读作「与业界冲突」。正确结论是：**「在本变体（identity 起步、α 无约束）与 13M/12k 快照下，层间加权和为中性（−0.0008，不可排序）；这不构成对 DenseFormer 原语义的否证。」** 另注：`tf@4 ≥ 0.95` 并列判据在本形态不可达（已如实报、未改判据）——属契约缺陷，不是执行缺陷。

**4 无意义：有（子项，条件性）。** 并行子层的**质量面**若不配吞吐腿，就不能改变「该路径值不值」的判断（业界要它就是为了吞吐）。要么补吞吐腿，要么把这个子项删掉。

**5 值得做：是。** (a) dense 用原语义重测（均匀起步 / 单纯形，2 臂 ≈16 min）；(b) 并行补「大 batch 或长 T 的吞吐」腿，否则删子项。

### ④ 建议动作

### ⑤ 正确的验证方式
- **该涨**：clean bpc（同参数量、同配方、同 token 预算、同深度读出）；并行的吞吐（在实际部署 regime：大 batch / 长 T 的 tok/s）。
- **该跌**：秒/步与峰值显存；dense 的「推理期需保留的层输出数」。
- **必须不变**：参数量逐位（或显式声明不等并给等参数对照）；起始步 loss/gnorm 逐位；数据切分/seed/步数/token 逐字段；收敛斜率同方法同窗口；「无增益时不做 24k 外推」。
