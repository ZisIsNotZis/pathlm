## ① 它是什么（我的理解）
本格问：把注意力的 KV 头从 8 个减到 2 个（GQA）或 1 个（MQA），能省多少解码期 KV 内存、质量掉多少；并把它放进「同一每位置字节」横轴与 KV 量化比较。

## ② 对着什么 sota / 我们偏离在哪
- **sota**（本仓 PRIOR_ART §W3，`记忆·未核`）：Shazeer 2019（MQA）、Ainslie 2023（GQA，uptraining 后近无损）、DeepSeek-V2 2024（MLA）；CLA/YOCO/MLKV 跨层共享。
- **偏离（有据、可辩护）**：业界报的是 **uptrain（从已有权重继续训练）** 的近无损；本仓是**从零训 13M**，且把 GQA/MQA 与 int8/int4 放在同一 KV 字节横轴上。这个「同字节跨家族 Pareto」确实是缺口。

## ③ 五类问题逐条
**1. 开倒车：有。** 「GQA/MQA 降 KV、质量近无损」= 业界已采纳的全行业做法；catalog `status: judged` 把它当本地发现。本格 PRIOR_ART §W3 已自判 (a)+b。

**2. 过程错误：有（对照混杂物已自报 + 跨家族比较的横轴已被本仓自己推翻）。**
- **等参数对照缺失（§15 例外未走完）**：GQA/MQA 参数 −8.75%/−10.25%（`2616/analysis.md` §6.3 与 §8.1 自报），代价里混着容量差。作者诚实列了未测项，但结论句仍以「+0.0143」记账。
- **跨家族 Pareto 的两个数已被本仓自己作废**：`catalog.yaml:815-837` 的 W3 verdict 写「同 −75% 档位下 **GQA 比 int4 KV 便宜 ≈3.2×**」，依据是 int4「−75% 内存、+0.0457 bpc」（来自 2616 §5.5 与 `2616/analysis.md` §1）。但 R1 已按因果/流式标尺改写：`catalog.yaml:1208-1211` 与 `axes/R-references/R1-quantization/README.md:9-10,46` 现在写 **int4 = 1.25× fp16 内存（负收益）**、**int4 质量代价 +0.024748（旧账 +0.0457 夸大 0.021）**。⇒ W3 的「同一 −75% 档」**在部署口径下不存在**（int4 反而多占 25% 内存），比值也从 3.2× 变 ≈1.73×。**W3 与 R1 在同仓内互相矛盾**。
- 判据贴边（0.0143 / 重跑 0.0139 跨门槛）这件事作者处理得对（按预登记规则判该臂不可判读、不写入近无损线），这点我确认无误。

**3. 结论错误：有（一句话）。** 「同 −75% 档 GQA 便宜 3.2×」应改为「GQA 相对**因果/流式口径下的 int4**（净 1.25× 内存）没有可比档位；GQA 的 +0.0143 bpc 是本仓唯一成立的读数，且其内存收益（解析 −75%）与量化不同源（头共享不涉标尺）」。
另：本格与 2616 都主张「本实验不主张任何**实测**显存收益，只报解析口径」——这是对的，但 catalog 的 `benefit` 行仍以「12288 → 3072 B/位置（−75.00%）」当收益，读者会当实测。

**4. 无意义：否。** KV 内存是长上下文部署的硬约束，本格命题有效。

**5. 值得做：是（中优先）** —— 补等参数对照与 2× 训练点；跨家族那一列按 R1 因果口径重算（或直接删掉）。
