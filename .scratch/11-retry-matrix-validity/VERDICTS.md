## 计划(按依赖排序)

```
1. [进行中→快完了] 在修复引擎上重测 retry 格
   ├─ B0 可复用(不受 D1/D3 影响)
   ├─ 用 D3 的几何重试深度(均值 0.5→1.0)训 C1/C1M_n1 各 2 种子
   ├─ 每个都用 --ckpt-every 落盘 → probe_e2e 跑 E2E(不只税)
   └─ 验收: C1M 的 r2 爆炸是否消失 = D1 的因果证据

   ├─ 选项 A: 真正交投影 E^T(EE^T)^-1E(206×206, 便宜但要缓存)
   ├─ 选项 B: 显式归一化(保输入范数)
   └─ 任一选择都使 C2/C2M 现有数字作废 → 先决策再跑, 别浪费 GPU

   ├─ 早退: E2E = 解码 tok/s @ iso-PPL(已有 decode_speed, 差每 checkpoint 版)

   └─ 产出: findings.md 重构成"每元素 = 容量税 | 推理成本 | 收益类型 | 收益值 | 缺的测量"

4. 收尾债
   ├─ findings.md ~250 行(预算 200) — 与 3 的重构合并做
   ├─ .git 1.6GB / 31 个已提交 model.pt — 历史重写, 需用户拍板
   └─ spec-decode 组合: prob0 门控重试 × 早退(77.3% 接受率已测, 没组合过) → [⬜]
```

## 一句话总结当前立场

**已证**: 打标损坏、噪声容忍、早退、prob₀ 校准、环形缓冲部署、以及"重试
在损坏输入上 E2E +1.98 bpc 而干净只付 +0.12"。
**已证伪**: shuffle(预测方向)、朴素概率复合、一致性损失、redo 的天真形式、
以及 retry 矩阵的全部排序(本轮撤回)。
**悬而未决**: 修复引擎下的 retry 全部数字、D6、规模。
