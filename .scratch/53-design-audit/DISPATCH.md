## 0. 本轮的最高指导（出资人）

**「不要最后发现其实根本没研究到点上去。」** 两种形态：

1. **显而易见的结论**——不需要实验就知道，信息量≈0；
2. **理论上「应该这么设计才可能有变化」，但我们没这么设计**——设计上就不可能有信号，于是把
   **「设计无效」误读成「机制无效」**。

**强制前门（本轮起对所有实验生效）**：契约里**必须先回答**——

> 这个机制要有变化空间，设计上必须满足哪几个条件？本实验满足了哪几条、缺哪几条？
> 缺的那几条若无法满足 ⇒ **必须写明该结论的效力边界**（「设计无效」还是「机制无效」）。

这条已并入 `SCHEMA.md` §24 第 13 类的强制动作；派发时必须逐条检查契约是否写了该节。

## 2. 五条线的契约（工具恢复后逐条发车）

### L1 · 设计有效性审计（CPU，只读+写作）
- **产出**：`.scratch/53-design-audit/DESIGN_AUDIT.md`
- **逐线**（量化 2632 / H1 2520 / H3 2631-spec-three-arms / A6 2636+2637 / R7 2623 / M1 2634 / C1 形态税）回答四问：
  1. **机制要有变化空间，设计上必须满足什么条件？**（逐条列，例如：存在超出容量的信息 / 训练信号迫使其使用 /
     有真实核兑现纸面收益 / 等参数·等深度·等算力对照 / 判据量效应超过本格噪声）
  2. **我们满足了哪几条、缺哪几条？**（逐条 yes/no + `文件:行` 证据）
  3. **结论效力三选一**：有效 ／ **设计无效** ／ **显而易见**（信息量≈0）。
  4. **若要真正回答，最小设计改动是什么**（改动 + 预算 + 预计能否产生可测效应）。
- **另加两节**：「显而易见结论」清单（建议不再投入）＋「理论上应该这么设计」清单（按投入产出比排序）。

### L2 · M1 重设计：让「信息右移通道」有机会产生质量收益（GPU ≈90 min）
- **目录**：`axes/M-carrier/M1-carrier-type/experiments/2638-carry-forced-use/`
- **干预**（唯一变量 = 是否开通道）：在**迫使使用**的设计下（窗口压到源信息不可达 / 加重建·必要性损失 /
  加高相似度干扰），测「有通道 vs 无通道」的质量差与召回差 + **毁源对照**。
- **判据**：① 分布内且信息超出窗口的任务上的召回差（若"迫使使用"仍无效 ⇒ 那才是**机制结论**）；
  ② bpc；③ 通道活性（`read_share`）；④ 与 2634 **同口径对照**（回答 0.2% 是设计问题还是机制问题）；
  ⑤ **本格自测噪声门限**；≥2 种子。

### L3 · A6 真核：把纸面省下的算力兑现成墙钟（GPU + 工程 ≈半天）
- **目录**：`axes/A-mixing/A6-mixing-operator/experiments/2639-real-sparse-window-kernel/`
- **要做**：实现**真的少算**的核（真窗口/块稀疏，或含稳定化分母的线性核——2637 已给可行配方）。
- **要求**：① 与稠密实装**逐位等价**或给出误差界；② 报实测墙钟 / 解析 FLOPs / 峰值显存三条腿；
  ③ **T=256/512/1024/2048 四点**（与 2636 同口径）；④ 同 token 预算的稠密对照臂；
  ⑤ **交叉点必须实测**（不是公式外推）。

### L4 · H1/H3 真树：按**原 cross-K 预登记判据**做完整树实验（GPU ≈2–3 h）
- **目录**：`axes/H-horizon/H3-composition/experiments/2640-spec-tree/`
- **动机**：pre-registered cross-K 判据**已触发**「树可能翻转，须做完整树实验才能定论」。
- **要做**：实现**概率多候选/树状草稿**（共享前缀、同一验证器），比 `direct`/`chain`：
  ① 平均接受长度 τ；② **每 token 等效算力 `(1+γ)/(1+τ)`**（**不得用墙钟当算力**）；③ 逐步接受率 α_i；
  ④ 真树部署收益（tok/fwd + 相对 native 的墙钟，注明外部占用）。

### L5 · 量化补齐两个诚实对手（GPU ≈30 min）
- **目录**：`axes/R-references/R1-quantization/experiments/2641-quant-opponents/`
- **要做**：实测 **fp8**（1 B/值、无标尺、理论 ×0.50）与**更大 head_dim**（G 可更大 ⇒ 趋近 50%），
  同表并列「值字节 / 部署字节 / bpc / 前缀不变性」。
- **判据**：前缀不变性；bpc 差与**本格自测噪声**比较；明确回答「8 位块标尺是否仍是最优 8 位方案」；
  若 fp8 更好 ⇒ **如实推翻 2632 的最优性表述**。

## 3. 复核线（RV，fork=false，排在全部执行之后）

逐条核：① `DESIGN_AUDIT.md` 的四问是否**真答**（条件是具体可核查、判定有证据支持）、有无漏线/漏关键前提；
② L2 的「迫使使用」是否**真的迫使**（读训练信号/窗口压力/干扰项代码）；③ L3 的核是否**真的少算**
（有没有偷偷算整矩阵）、逐位等价证据、墙钟与解析 FLOPs 是否同向；④ L4 的树是否是**概率多候选**（不是又一个 `T∘T`）、
是否按**原** cross-K 判据回答；⑤ L5 的 fp8 是否**公平**（口径与 int8 块标尺对齐）；
⑥ **所有线的契约是否都先写了「必须条件 + 满足与否」**（缺的逐条列出）；⑦ 数字与产物逐一对应（≥15）。
