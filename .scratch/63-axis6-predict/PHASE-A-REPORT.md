## 1 人话摘要（先说结论，再给数字）

**做了什么**：轴 6 的 5 个研究项（投机解码 6.2、扩散 6.3.1、一次填空 6.3.2、latent 回归 6.3.3、
训练时填充语义 6.4）逐项补上实名责任人与「想清楚」复核，然后只挑 **1 个最高价值 WP 真跑**——
6.2 的 **6.2.2 概率多候选 / 树**。出这个题的原因是：55-review 发现**出资人亲自设计的机制被砍掉了**
（原设计是「每个草稿头自带概率、预测多个候选、按路径概率加权组合」，实际只做了「单 argmax + 固定
λ=0.5 混合」，**树 / 多候选整条没测**，且预登记判据「树可能翻转排序」当时已被触发却仍写成定稿结论）。

**拿到什么**（同一批 checkpoint、冻结主干、γ=2、温度 0，只改「位置 N+2 的草稿怎么选」）：
在 13.4M×2 seed + 53.9M×1 上，把草稿从**单个 argmax** 换成**K 个自带概率的候选一起验证**
（一次前向批量验，K=2 或 4）后：

| 检查点 | 最强单候选臂的 α₁（每轮至少命中 1 个的比例） | 树臂 α₁ | 提升 | τ（每轮平均多吐几个 token）提升 |
|---|---|---|---|---|
| 13.4M seed0 | 0.8048（固定 λ 混合） | **0.8983**（取 top-2）/ **0.9317**（取 top-4） | **+0.093 / +0.127** | **+0.186 / +0.236** |
| 13.4M seed1 | 0.8453（概率加权） | **0.9200** / **0.9576** | **+0.075 / +0.112** | **+0.141 / +0.191** |
| 53.9M seed0 | 0.8439（直连头） | **0.9344**（只跑 top-2） | **+0.091** | **+0.148** |

这些差**全部**通过「按 prompt 聚类的配对 bootstrap 95% CI 不含 0」（不是「看起来更大」）；同时
**全部臂 × 3 个 checkpoint × 12 段文本的生成结果与原生逐 token 贪心逐位相同**——树只让模型更快地
吐出**同一句话**，没有改变输出（无损性门禁全过）。

**值不值**：**在有意义的方向上成立，但要付账**。抬 τ 的代价是每次前向要多算 K 个候选行：每 token
等效 FLOPs 从单候选的 1.16–1.24 倍（相对原生逐 token）涨到 **2.30 倍（K=2）/ 4.51 倍（K=4）**——
即「用约 1.9× 到 3.7× 的并行算力，换每轮少跑几次顺序前向」，而且**K 从 2 加到 4，算力翻倍而 τ 只多
约 0.05**（边际收益递减）。按本项目口径（顺序前向次数是硬指标、FLOPs 是代价轴），这就是答案的**两面**：
想让「每 token 顺序前向次数」降下来，树有效；想让「每 token 算力」降下来，树无效（投机解码本身
就是这样，不是本次的发现）。

**出资人那条「概率加权」设计呢**：**在本尺度测不出差别**（否证）。用路径概率
`w=(p₁·p(chain2))/(p(node2))` 加权与固定 λ=0.5 等权混合，α₁ 差 −0.005 / +0.004，配对 CI 含 0；
两臂逐轮选出的草稿只有约 5.7–5.8% 不同，这点差别淹没在接受率噪声里。**但**这不等于「组合无价值」——
它只说明「等权 vs 概率加权」这一处自由度在这个规模/任务上不产生可测收益（旧结论「组合无价值」是答非所问，
本报告不沿用）。

## 3 步骤 2：WP 6.2.2（本轴旗舰）——设计与结果

**实验**：`axes/6-predict/6.2-speculative-decoding/experiments/2640-tree-conf-13m/`
（预登记契约 `README.md` 先写再跑；`spec_tree.py` 臂与树验证；`run.py` 驱动；`test_spec_tree.py` 22 条单测；
`mutate.py`/`mutation_report.json` 变异；`recompute_criteria.py`/`criteria_fixed.json` 离线重算判据；
`analysis.md` 当前结论；`controls/README.md` 对照物清单）。

**单因素设计**：已提交前缀到位置 N；`v1=argmax node1`（位置 N+1，验证器自己的输出）；**唯一变量 = 位置 N+2
的草稿来源**；位置 N+3 的草稿全部臂固定 = `argmax node3`。臂：`native`（对照 = 原生逐 token 贪心）/
`direct1` / `chain1`(+1+1) / `combined_fixed`(旧 λ=0.5) / `combo_pw`(路径概率加权) / `tree_union2` /
`tree_direct_k2`（top-2 直连头，兼作与 2632 探针 recall@2 的交叉印证）/ `tree_qpw_k2` / `tree_topk4` /
`oracle_accept`（只作 τ 上界）。

**树验证怎么做的**：K 个候选**平铺成 K 行**（每行 `[v1, c_i, d3]`，共享前缀只做 KV 广播），
**一次前向**算完所有行的逐位置 logits（行内因果掩码）；接受判据 = 存在候选等于**目标模型在同一真实前缀下**
该位置的 argmax；随后只把**接受行**的 K/V 与位置写回缓存。每轮顺序前向恒为 1（`n_forward_total == n_rounds`
逐臂核对通过）。全程在实验目录内实现，`pathlm/**` 未改。

**判据结果**（判据来自离线重算 `criteria_fixed.json`；读数 = `results.json` + `cycle_log.jsonl`）：

| 判据 | 预登记内容 | 结果 |
|---|---|---|
| **P1 该涨** | 树臂 α₁ 超高最强单候选臂 > 0.014 且配对 CI 不含 0 | **成立**（9/9 个「树臂 × checkpoint」；13m_s0 +0.0618…+0.1269、13m_s1 +0.0638…+0.1123、53m_s0 +0.0905） |
| **P2 该涨** | τ / tokens-per-forward 上升且配对 CI 不含 0 | **成立**（τ +0.109…+0.236） |
| **P3 加权假设** | `combo_pw` 比 `combined_fixed` 高 > 0.014 且 CI 不含 0 | **否证**（−0.0048 / +0.0039，CI 含 0；两臂逐轮分歧率 5.66%/5.82% ⇒ 确不同但差别在噪声带内） |
| **P4 必须不变** | 全部臂 × ckpt × prompt 发出流逐位 == native 贪心 | **成立**（3 ckpt 全臂全 true；53.9M 未出现 fp 平局翻转） |
| **C1 实现有效性** | `tree_direct_k2` 的 α₁ 与 2632 探针 recall@2 同量级（不显著更低） | **过**（13m_s0 0.8983 vs 探针 0.8605；13m_s1 0.9200 vs 0.8922——实测**高于**探针，探针点未落在实测 CI 内（差 0.0086）但两 CI 重叠，已如实记录为不确定性） |
| **P5 代价轴** | 如实报 `R=K(1+γ)/(1+τ)`，**不作判据** | 单臂 1.16–1.24 → 1.73–2.36（union2/K=2）→ 4.45–4.51（K=4）；并披露「K 行平铺」是本实现口径（每轮 3K 个主干位置），节点共享树 ≈2K+1 ⇒ 表中倍数约高 1.2–1.33× |

**否证条件**（预登记 4 条）：① 无配置抬得动 α₁ ⇒ **未触发**；② 只有 oracle 抬得动 ⇒ **未触发**；
③ `combo_pw` 与 `combined_fixed` 分歧率 ≈ 0 且差 ≤0.014 ⇒ **部分触发**（差不显著，但分歧率 5.7% ≠ 0）⇒
按判据精神裁定为「该尺度下『加权 vs 等权』无信息」，不宣称任一方更优；④ C1 未过 ⇒ **未触发**。

**为什么这是真结论而不是玩具**：① 三臂的对照是同一份 checkpoint 的**同一次前向**，唯一区别是候选集大小与
选法；② 全部臂逐位无损，说明没把「偷看答案」混进来；③ 三条变异（候选集退化成 1 个 / 接受判据改无条件接受 /
加权退化成等权）**全部被抓红**且逐字节还原；④ `direct1/chain1/combined_fixed` 三臂在本实验里复现了 2631 的
原值到小数点后 4 位（例 13m_s1 direct1 α₁ 0.8370 / τ 1.5204）⇒ 评测驱动可信。

**成本（等效理论量，无墙钟判据）**：run #1 共 3 个 checkpoint × (10/10/3) 臂 × (12 prompt × 200 token)，
GPU 锁按 checkpoint 取放（§20，61 s/60 s 让出窗口），GPU 实耗 963 s（`results.json` 内无任何墙钟字段）。
