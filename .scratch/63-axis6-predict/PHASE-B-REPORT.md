## 1 人话摘要

**这轮回答了两个问题：①「一次前向多吐几个 token」的批量验证到底靠不靠得住、还能往哪挖？②「先让头去看主干未来的隐状态」有没有用？**

### 1.1 批量验证是真验证；多塞候选很快就划不来（WP 6.2.3，`experiments/2650-verify-gate-13m`）

用三类「坏候选」探门禁：

- **随机候选**：接受率 **1.85%**（≈ 瞎抽签中奖率 4/206 = 1.94%）；**概率最低的候选**：**0%**；
- **同一候选抄 4 份**、**只送 1 个候选走同一套多行机制**：逐轮结果与原来的单候选臂**逐位一模一样**；
- 这四种情况下模型吐出的文字**仍然逐位等于普通贪心解码**，且三条「故意写坏」的变异（候选↔行错位、接受行回写错位、接受判据放宽成无条件接受）**全部被测试抓红**。

⇒ **门禁是真验证，不是橡皮图章**。

再看「多验几个候选值不值」（同一候选分布族的嵌套 top-k）：

| 每次验证的候选数 K | 接受率 α₁ | 平均每轮吐几个 token τ | 每 token 等效算力（相对逐 token） | 达 τ 理论上限 |
|---|---|---|---|---|
| 1 | 0.800 | 1.432 | 1.23× | 81.1% |
| 2 | 0.867 | 1.548 | 2.36× | 87.6% |
| 4 | 0.932 | 1.659 | 4.51× | 93.9% |
| 8 | 0.979 | 1.736 | 8.77× | **98.2%** |

- **硬指标（每 token 顺序前向次数 = 1/(1+τ)）上验证不吞收益**：0.411 → 0.365（每轮恒 1 次前向，逐臂核对）。
- **算力轴上 K>4 不划算**：边际收益（每多一个候选换来的 τ）从 K=1→2 的 **0.116** 掉到 K=4→8 的 **0.019**（只剩 1/6，低于预登记阈值 0.058）。上限由**候选覆盖率**（K=4 已达 93.9%）而非验证行数决定 ⇒ 再往上要走「更好的头」，不是「更多验证行」。

### 1.2 「让头去看主干未来的隐状态」有独立增益（WP 6.3.3-WP1，`experiments/2660-latentreg-vs-disc-13m`）

在**冻结的 13M 主干**上，同参数量、同 tied 读出、同训练预算，只改监督：离散跳头（只分类）vs 加一条 **λ·MSE 把头的输出拉向主干未来真值隐状态**（latent 匹配监督）。

| 判据路径 | 数字 | 判读 |
|---|---|---|
| (i) 直接发（估计得贪心） | t+2 命中率 0.4572 → **0.4878**（种子 1：0.4573 → 0.4892；λ=0.1 时 0.4688） | Δ **+0.0313**，配对聚类 95% CI [+0.0296,+0.0330] 不含 0；13m_s1 复现 +0.0329；k=4 +0.0284 |
| (ii) 当草稿再验证（63-F4 第二臂） | 接受率 α₁ 0.642 → **0.734**（种子 1：0.668 → 0.754） | Δα₁ **+0.0916** [+0.0525,+0.1310]、Δτ **+0.1464** [+0.0971,+0.1973] |
| 参照（同一主干逐 token 的质量） | `ar_t1` = **0.6714** | 一次前向直接发 2 个位置的质量代价明码标价（0.488/0.366 vs 0.671），代价 = 每 token 主干算力 ≈ L/k |
| 硬门 | λ=0 的两臂**逐位相同**（命中率 / CE / 头权重，且重跑逐张量一致） | 冻结断言通过；读出共享 |

**必须说清的限定**：λ=0 时两臂**数学上是同一套计算**，所以差别不是「两套架构」，而是**同一参数化上的那条辅助监督**。成立的结论是「**latent 匹配监督有独立增益**」，**不等于**「回归这种产出方式优于分类」。是否据此改写 6.3.3 的描述 = 待 Main 裁决（本轴未擅改）。

## 6 上报 Main 的框架性取舍

1. **`R_K` 口径笔误的处置**：定稿口径 = `K·(1+γ)/(1+τ_K)`（= 每轮 3K 个主干位置 ÷ 每轮发出 `1+τ_K` 个 token，与 2640 逐字一致）；原 `3K·(1+γ)/(1+τ_K)` 是**出题人（我）的笔误**，由 WP worker 在开跑前发现并拒绝擅改、两套数并列上报。已在契约文件内留一行指针、经过记入工单；**判据不受影响**，故本轴直接执行并上报。
2. **是否改写 6.3.3 的机制描述**：本实验证明共享 tied 读出 + 同参数量下 λ=0 两臂**数学等价** ⇒ 独立自由度只有**监督目标**；结论只能表述为「latent 匹配监督有独立增益」。**是否把 `innovation`/`method` 从「回归产出方式」改写为「latent 匹配监督」= 待 Main 裁决**（本轴只在 `conclusion` 里写明限定与建议，未擅改）。
3. **引擎改动需求（连续两轮未动）**：① 二级条件头（N+3 候选，需重训）；② 带驱逐的树验证（`2640/spec_tree.tree_forward` 现抛 `NotImplementedError`）；③ 等 FLOPs 对照臂在本引擎 `n_mtp=3` 下不可得（63-F2 已裁决「如实注明」）。均登记在本轴工单与 gaps，**未改共享 `pathlm/**`**（如需，请指派到 `.scratch/67-engine-changes/TICKET.md` 队列）。
4. **复核者工具集问题（基础设施）**：`reviewer` 智能体上下文**没有 shell**，导致「必须执行」的验收无法由复核者独立完成（本次由 lead 自跑 + 一个带 shell 的独立执行验证者关闭）。建议 Main 决定：是否给复核者配 shell/写工具，或把「执行验证」固化成独立角色。

## 7 残余限制（不得读成更强结论）

- 绝对水平只适用于：**enwik8 char 级文本 / 温度 0 / B=1 / γ=2 / 13M 冻结主干（6.3.3）/ 13.4M 与 53.9M 已有 checkpoint（6.2.3）/ 该 prompt 集**；不外推到别的任务、规模、温度。
- 6.3.3 的增益是**同一参数化上的辅助监督**带来的（不是架构差异）；6.2.3 的代价轴是**本实现「K 行平铺」口径**（每轮 3K 个主干位置），节点共享理想树（≈2K+1）未实装。
- 全部 `R > 1` 的表述是**投机解码范式的定义性质**，不作判据；所有结论只用等效理论量（tokens-per-forward / FLOPs / 主干位置数），**无墙钟判据**。
