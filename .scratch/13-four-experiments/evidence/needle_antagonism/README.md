# needle × 损坏训练：三路尝试全部失败的记录（ticket 13 实验 2 收口）

## 结论

**损坏训练（容忍任意 token 错误）与 needle/复制任务（精确抄锚点对）在同一模型里
目标冲突，且三种解法都失败。** 这不是评测假象——已用阳性对照验证（见下）。

| run | 策略 | in_window | anchor | beyond | clean bpc |
|---|---|---|---|---|---|
| X2v2 | 无损坏（基线） | **0.8658** | **0.7637** | 0.0082 | 1.5652 |
| X2C | 损坏，无豁免 | 0.0057 | 0.0161 | 0.0050 | 1.6797 |
| X2C-v2 | 损坏 + 锚区位置豁免 | 0.0062 | 0.0327 | 0.0075 | 1.6841 |
| X2Cv3 | 损坏 + needle 批次整体豁免 | 0.0505 | 0.0354 | 0.0062 | **1.9974** |
| INT2 | 集成run（含损坏） | 0.0047 | 0.0054 | 0.0058 | 1.6548 |

- 位置豁免（v2）救回不到 4%；**任务级豁免（v3）也没救回来，且 clean bpc 从
  1.6797 恶化到 1.9974**——把任务混得更不一致，代价更糟。
- 因此"损坏鲁棒 + 精确复制"在单模型里**必须靠显式模式/通道信号**区分，不能靠
  位置或批次的损坏豁免。

## 评测协议 bug（已修，verdict-neutral）

调查中在 `needle_acc` 发现一个真 bug：它的 `eval_pc` 只清了 `corrupt_wrong`，
**漏了 `corrupt_mask`**。配置了 `corrupt_mask` 的 run（X2C / X2C-v2 / X2Cv3 /
INT2）在**复制任务评测时仍在被打 [mask]**，概念上是错的（复制内容被破坏）。

修好后重测（本目录 `reeval_fixed_protocol.txt`）：
- 各 run 数字几乎不变（X2C 0.0042→0.0057 等）→ **该 bug 对本次结论无影响**；
- **阳性对照：X2v2 复现 in_window 0.8658 / anchor 0.7637**（归档值 84.9%/76.8%）
  → 评测管线本身是好的，低分不是脚本问题。

所以 bug 是真 bug（已加可失败单测 `test_needle_acc_evaluates_with_corruption_off`
钉住，回退修复即红），但结论"损坏摧毁复制"**站得住**。
