# 实验 1 — prob0 逐位置重试门控（`retry_gate`）

## 结论（一句话）

**字面实现的 `retry_gate` 在指定的 direct 传输上是空操作：**`reentry_state`
在 r=1 就等于 `h`（direct 重入为恒等；mixture 在 r=1 只有一个累加项），
`torch.where` 无可切换。因此 12k direct checkpoint 的 eval-only 扫描里 r2
与 τ 完全无关（保留率恒为 100%，但这是空洞的）。在唯一“重入状态 ≠ h”的
linear 传输上，门控反而有害：~15% 开火时 r2 比 r1 更差（bpc 保留率
−0.15/−0.48）。6000 步 gated 训练的干净 bpc 与同引擎无门控对照无差异
（Δ=+0.0024，落在 0.0019 的同种子噪声底内），税没有缩小。

**判据（~15% 开火保留 ≥80% 的 r1→r2 收益）：不成立。** direct 上是空洞通过
（门控什么都没做），linear 上失败。

## 代码改动

- `pathlm/config.py`：新增 `retry_gate: float = 0.0`（0.0 = 关，严格等于改动前）。
- `pathlm/model.py` `forward`：r>0 的重入状态逐位置门控
  `h = torch.where(sigmoid(nodes[0]["conf"]) < τ, reentry_state, h)`（detach）。
  0.0 时走原路径（逐位一致）。
- `tests/test_m1.py`：3 个可失败单测（43 绿，原 40）——
  τ=0 不门控任何位置且仍走 transport；τ=1.0 与无门控逐位一致；
  中间 τ 下高置信位置 `h` 逐位不变、低置信位置取 transport。
- `probe_gate.py`：eval-only 阈值扫描脚本（不改 `probe_e2e.py`）。

## 训练对照（6000 步，direct + mixture，seed 0，当前引擎）

| run | retry_gate | clean bpc | next-token acc | repair r0→r1 | wall |
|---|---|---|---|---|---|
| C1MG_g90 | 0.9 | 1.6884 | 0.6601 | 0.4878→0.5160 | 7.1 min |
| C1MU（对照） | 0.0 | 1.6860 | 0.6603 | 0.4864→0.5153 | 7.9 min |

Δ(clean bpc) = **+0.0024**（gated 更差），落在同种子 nondeterminism 底
0.0019 附近；税未缩小。与“门控在 r1→r2 无作用、仅影响 25% 训练 batch 的
r≥2”一致。

## 判定与建议

字面 `torch.where` 放在重入输入上无法实现“按位置省算力”：`_run_layers`
仍对所有位置执行，且 direct 重入恒等。要保留收益必须换成**按位置跳过整段
重入计算**（或至少按位置选择重入输出而非输入），二者都超出本 ticket 的
`torch.where` 规格，未实现。
