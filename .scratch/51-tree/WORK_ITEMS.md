## 0. 通用约定（对每一项都适用，正文不重复）

**G1. 噪声门限必须逐格自测，不得套用全局数字。**
`docs/methodology.md` §2 的「Δ<0.014」其唯一来源
（`.scratch/11-retry-matrix-validity/evidence/README.md:69-71`）原话是「**seed variance is
cell-dependent (0.0001 to 0.0138)… There is no single global floor: ordering claims need
per-cell replicates**」。因此**每一项开跑前先做自测**：

- bpc 口径：在本格目标配置上做 **n≥2（推荐 n=3）独立重跑**，取同配置 bpc 极差作为本格的
  `σ_cell`；两臂之差的可排序线取 `max(√2·σ_cell, 测得的评测批内配对差)` 或直接以**区间重叠**
  判定。**不得**直接写「0.014」当本格门槛。
- 准确率口径：用二项 **Wilson 95% CI**（`docs/methodology.md` §2 明写 0.014 是 bpc 口径、
  不是准确率的 1.4pp 界），CI 重叠即不可排序。
- 阈值类判据（如「≥10pp」）：**先验算可达性**（算术上界），不可达的阈值等于零区分度
  （A10 的 10pp 门槛正是此坑）。

**G2. 规模与复现。** 每项必须给**至少两个规模点**（13M + 一个更大点，如 53.9M/100M），
或**显式声明适用范围**并写死只做 13M；**至少两次独立训练**（n≥2；n=1 的正面结论默认不可采信，
见 §2）；**禁外推**（单点/单距离/单步数不得当趋势或求和，§17.11/§17.16）。

**G3. 对照纪律。** 诚实对手按 `SCHEMA.md` §11（同成本或更低成本，**禁 oracle 当判据**）；
声称结构增益必附**等参数**对照（§15）；涉及保留/搬运/量化/压缩的必附**毁源对照**（§10）；
省内存类必给**同字节预算**对齐（§17.12）；嵌入式干预必报**活性量**（§10）。

**G4. 口径。** 每个数字带口径（快照/渐近/matched-step/墙钟/FLOPs/内存，§3）并**双货币双报**；
「省算力」类必须报**实测成本交叉点**（§17.9），不只报理论降幅。

**G5. 证据与复核。** 落盘 run 目录 + resolved config + commit（§8）；每格完成后**另派 fresh-context
只读复核者**（§14），且**复核排在执行之后**（§14b）；未过复核的结论不得计入状态灯。

**G6. GPU 串行。** 训练/评测按 `SCHEMA.md` §20 取锁串行；纯 CPU（情报/对账/分析）不取锁。
多臂驱动按臂释放锁（§20.1）。

**G7. 预算。** 下列预算为**规划估算**（含冒烟+全跑+评测），非契约数字；每个实验契约按 §8
只留**唯一一个** GPU 墙钟数字，并写明「预算不够时砍什么」。

**G8. 前置「核实出处」。** 本环境检索不可用，凡涉及业界结论的项（R1/W2/C4/A8/R7/H1/H3…），
**第一步是核实出处**（或如实标 `记忆·未核` 并降级为假设）；`记忆·未核` 不得当判据、不得当免做依据（§21）。

## 主线一 · 信息右移（把旧位置的信息搬到现在）

> 本主线 = 「右移压缩」：窗口丢掉的信息可否通过载体/通道/训练信号找回。当前正面积为零
> （见 WI-01），合格天平已建成（`tools/evalkit/longrange_tasks.py`），负结果稳定
> （「掩码逼不出搬运」窗外 494 根差恰好 0.000）。

### WI-01 · M1-carrier-type（主线落点；最高优先）
- **它是什么**：跨步信息存在哪里——本项目已首验「显式写入记忆槽 + delta 写（只搬增量）」，
  在合成关联回忆 + 窗口 16（key 全在窗外）上把召回抬到 6.08× chance。本项要把它做成**可判定的
  结论**：通道能否**跨 seed 稳健**把信息搬过窗。
- **为什么要做**：业界（delta 规则 / Gated DeltaNet，MQAR 是线性注意力标准基准）该机制在
  同任务上接近满分，本仓 13M/12k 绝对水平仅 9.5%；且我们此前的**入口结论建立在越界腿
  （距离 241–255，超训练上限 240）**上，跨 seed 已符号翻转（seed0 +6.05pp / seed1 −2.44pp）。
- **必须回答的问题**：
  1. 在**训练分布内**的多查询关联回忆腿（距离 107–240、无泄漏 Q=7）上，carry 相对 base 的召回
     增益，**三 seed 的最小值**是否显著 > 0（Wilson CI 下界 > chance 0.0156）？
  2. carry 是否**不弄坏出口资产**（tf@4/tf@6 保持）且**质量腿不超本格 σ_cell**？
  3. 若跨 seed 仍不稳健，机制上限是「任务/尺度不划算」还是「实现/训练不足」？（按 §14 决策树）
- **验证口径**：**该涨** = 分布内多查询召回（取三 seed 最小值；相对同掩码地板）；出口资产 tf@k；
  **该跌** = 无；**必须不变** = `U0≈chance`、毁源后掉回 chance、U1/U2 参数量逐位相同、
  `transport=none` clean bpc 逐位一致。
- **对照组**：诚实对手 = **同参数量无通道臂（base）**；必要对照 = **毁源臂**（打乱答案）、
  **等参数臂**（U1/U2 参数逐位相同）、**含出口资产腿**。
- **预登记判据（含噪声门限）**：先自测本格 `σ_cell`（bpc）与准确率 Wilson CI 宽度；
  主判据 = **三 seed 最小值**的分布内召回显著 > chance 且 CI 不重叠；辅助腿 = 出口资产
  Δ 落在本格 `σ_cell` 带内（此前的「−0.76pp 带内」用本格带宽复核）。越界腿永久降级为辅助腿。
- **规模与复现**：**3 臂（U0/U1/U2）× 3 seed** 为最小可判定版本；声明**只在 13M**，不外推；
  ≥2（实为 3）次独立训练。
- **预算**：≈ **150 GPU 分钟**（~9×13M 12k 训练 ×15 min + 长程评测 + 对账）。
- **依赖**：先用「分布内多查询布局」替换长程腿默认布局（禁用末位布局伪影，见 WI-02 的仪器前提）。

### WI-02 · A9-old-info-retention（主线；in-distribution 长程腿）
- **它是什么**：已读过的远距离信息留什么/丢什么/压成什么。本项把「窗口丢多少长程 + 显式通道
  救回多少」放到**同一契约同一台天平**上测。
- **为什么要做**：A 轴最有决策价值的格，但主腿在分布外、n=1、且结论靠「累计预算」（单点曲线
  外推）撑起。业界标准 = StreamingLLM（sink+滑窗）、Longformer/BigBird（global token）；
  我们的增量 = 「低损伤 ≠ 保住了」的仪器化判据 + 显式通道对照。
- **必须回答的问题**：
  1. 纯窗口在**训练分布内**的真长程任务上窗口外召回是否停在 chance（当前合成读数 win16
     0.0144 ≈ chance vs full 0.3665）？
  2. 给显式通道后，窗外召回相对**同掩码地板**提升多少？
  3. 「累计 keep-k 曲线」（keep 32/64/128/192 = +0.212/+0.081/+0.020/+0.004）在 n≥2 下是否稳定？
- **验证口径**：**该涨** = 给通道后窗外召回（相对同掩码地板）；**该跌** = 无（窗口臂窗外应停
  chance）；**必须不变** = clean bpc 对照口径、累计曲线形状；**必须报** = 同配置重跑 bpc 极差。
- **对照组**：诚实对手 = **纯窗口臂 + 同掩码无记忆地板**；必要对照 = 毁源臂、全保留上界、累计
  keep-k 各档。
- **预登记判据**：自测本格 `σ_cell`；主判据 = 窗外召回显著 > 同掩码地板（Wilson CI 不重叠）；
  **禁**单点距离曲线求和/外推（§17.11），必须同时给「按距离单点」与「按累计预算」两列。
- **规模与复现**：13M × 2 seed + 一个更大点（53.9M/100M 1 seed 或显式声明只做 13M）；
  两次独立训练。
- **预算**：≈ **150 GPU 分钟**。
- **依赖**：长程腿仪器（in-distribution 布局）先就位；与 WI-01 共用天平。

### WI-03 · A3-window-anchor（价格上界；前置）
- **它是什么**：硬窗口/锚点/sink 把「前缀可丢」变成结构事实。本项要**自包含复算**窗口与锚点，
  并把「评测期丢前缀」与「累计预算」两列拆开。
- **为什么要做**：A3 是「任何压缩/摘要必须打败的价格上界」（`catalog.yaml:268`），但头号数字
  （+0.058~0.121、needle 76.8→93.3%）只存在于一份 20 行 `.scratch` markdown，无 `results.json`/
  `run.py`；且 93.3% 实为「惩罚+驱逐」**组合**。业界标准 = StreamingLLM sink / Longformer global
  token / gist token；本仓却把它当本地发现示人。
- **必须回答的问题**：
  1. 自包含（同引擎/同数据流/n≥2）下，窗口与锚点的 tax 与 needle 召回各是多少？
  2. 「评测期丢前缀」与「累计预算」两列分别是什么（当前混列）？
- **验证口径**：**该涨** = 锚桶检索腿召回（相对同掩码地板）；**该跌** = 无；**必须不变** =
  clean bpc 的累计预算曲线（keep k 全曲线，禁单点外推）。
- **对照组**：诚实对手 = **全保留（无窗）基线**；必要对照 = 无锚窗口、锚点档、毁源臂。
- **预登记判据**：自测 `σ_cell`；主判据 = 锚桶召回 > 同掩码地板；税以本格 `σ_cell` 排序。
- **规模与复现**：13M × 2 seed（+100M 1 seed 或声明范围）；两次独立训练。
- **预算**：≈ **120 GPU 分钟**。
- **依赖**：无（本项是 WI-01/WI-02 价格基准的来源）。

### WI-04 · M2-carrier-compression（载体压缩）
- **它是什么**：载体怎么压（量化/驱逐/窗口/摘要/低秩）——内存换质量的**双边前沿**。
- **为什么要做**：驱逐已测、KV 量化价签须按 WI-08 的新口径重测；「摘要压缩 / 低秩（MLA 式）」
  本仓零经验（业界 = KIVI/KVQuant/H2O/SnapKV/Compressive Transformer/MLA，均 `记忆·未核`）。
  我们的增量 = **同字节预算下的对照 + 检索腿**。
- **必须回答的问题**：
  1. 同「每位置 KV 字节」预算下，量化 / 驱逐 / 窗口 / 摘要 的质量-召回前沿谁占优？
  2. 量化与驱逐叠加是否可加（当前 int4 叠头共享为亏）？
  3. 摘要/低秩两支是否在本尺度有头寸？
- **验证口径**：**该涨** = 相对 fp16 总字节下降（含标尺开销）；**该跌** = Δbpc 须落在本格
  `σ_cell` 带内才算无损、越界即计代价；**必须不变** = 严格因果两条测试；`2614` 补 ERRATA 指针
  （首屏仍给已撤 `d*=32`）。
- **对照组**：诚实对手 = **fp16 不压**；必要对照 = 毁源臂、检索腿、同字节各方案。
- **预登记判据**：自测本格 `σ_cell`；主判据 = 同字节下的前沿支配关系（两腿同时不劣）；
  禁「低损伤当保住」（必须并报检索腿）。
- **规模与复现**：13M × 2 seed + 一个更大点；两次独立训练；量化评测可复用权重（纯推理）。
- **预算**：≈ **120 GPU 分钟**。
- **依赖**：WI-08（R1 新口径）——否则量化列的字节与代价都站在错标尺上。

### WI-05 · F2-return-channel（回传通道）
- **它是什么**：一轮结果以什么形式回到下一轮（direct/linear/soft/hard）——决定重复能否带来
  新信息。
- **为什么要做**：D1 gauge bug 使「soft>linear>direct」排序从未在可比口径测过（它是 cap 破坏量
  的单调）；D6（linear 实为 `EᵀE`，放大 71.7×）在验收单未勾选；且 direct 实为 `f∘f≠f`
  （`pathlm/model.py:398-401`），「结构性 no-op」用词越证据。
- **必须回答的问题**：
  1. 修 D6 后，同批/同 seed/同 token 下 direct/linear/soft/hard 的真实逐轮 bpc 边际排序是什么？
  2. direct 的边际是否停在 0（须先证 `alive=true`）？
- **验证口径**：**该涨** = 能注入新信息通道的逐轮 bpc 边际；**该跌** = direct 边际停 0 且
  `alive=true`；**必须不变** = `transport=none` clean bpc 逐位一致、各档参数量逐位相同。
- **对照组**：诚实对手 = **direct（当前最优候选）**；必要对照 = `transport=none` 逐位一致、
  等参数。
- **预登记判据**：自测 `σ_cell`；主判据 = 通道边际超过本格带宽且活性非零。
- **规模与复现**：13M × 2 seed（+一个更大点或声明范围）；两次独立训练。
- **预算**：≈ **120 GPU 分钟**（含实现修复的 CPU 时间，不含 GPU）。
- **依赖**：**先修 D6（D1 已修）**——实现修复是前置。

### WI-06 · F4-training-signal（训练信号 × 显式载体）
- **它是什么**：靠什么损失让「重复/组合/摘要」真的有效（consistency / 重建-sufficiency /

- **必须回答的问题**：
  1. 把重建/充分性损失接到**显式载体**（carry/摘要槽）上，窗外可重建性/召回是否提升

  2. 有载体臂是否**优于**同任务同尺度的纯 CE 臂？
- **验证口径**：**该涨** = 有载体臂窗外可重建性/召回；**该跌** = 无；**必须不变** = λ=0 与 λ>0
  主干逐位等价（`test_recon_default_off_matches_v1_bitwise`）、fp32 头、pre-step grad-norm gate。
- **对照组**：诚实对手 = **同参数量纯 CE 臂**；必要对照 = 毁源臂、λ=0 逐位一致、等参数。
- **预登记判据**：自测 `σ_cell`；主判据 = 有载体臂召回提升显著且超本格带宽（此前预登记
  「≥+3pp 且 CI 不重叠」需按本格 CI 复核）。
- **规模与复现**：13M × 2 seed + 一个更大点或声明范围；两次独立训练。
- **预算**：≈ **100 GPU 分钟**。
- **依赖**：WI-01 的显式载体就位。

### WI-07 · A10-compression-trigger（压缩触发与优先级）
- **它是什么**：什么时候压、按什么优先级决定「谁先被压」（固定/距离/LRU/学习/信号驱动）。
- **为什么要做**：判据算术不可达（「比 distance 高 ≥10pp」而全保留上界只有 0.6868）；统计含
  **未来查询**（偏强负结果）；被测对象≠格子命题（命题是 per-token 吸收率，测的是驱逐优先级）；
  「业界无人占位」与自家 `PRIOR_ART §A10` 矛盾。业界 = H2O/Scissorhands/SnapKV/PyramidKV。
- **必须回答的问题**：
  1. 用**流式（只看过去）**统计、在**同「可见性对数」预算**下，驱逐优先级是否有可排序收益？
  2. 真 ρ 曲线（压缩率-质量）形状如何？
- **验证口径**：**该涨** = 低预算保留腿召回；**该跌** = 无（clean bpc 应最差）；**必须不变** =
  被删位置数（对照列）；**必须报** = 两条预算口径（位置数 vs 可见性对数）+ 真 ρ 曲线。
- **对照组**：诚实对手 = **距离规则（本项目 eviction）**；必要对照 = LRU/content、毁源臂、
  同可见性对数预算。
- **预登记判据**：阈值**先验算可达性**（≤ 全保留上界）；自测 `σ_cell`；主判据 = 重对齐可见性
  对数后仍有排序。
- **规模与复现**：13M × 2 seed（+明确声明只做 13M/256 或加大点）；两次独立训练。
- **预算**：≈ **120 GPU 分钟**。
- **依赖**：无（可与 WI-04 共用保留曲线天平）。

## 主线二 · 省内存（同一字节预算下的前沿）

### WI-08 · R1-quantization（坏天平；全仓省内存判据基准）
- **它是什么**：用更低比特换内存/带宽——「Pro 当 Flash 用」的现成答案。

### WI-19 · C1-layers-per-token（省延迟不省算力）
- **它是什么**：每个 token 跑几层（全深度/前缀早退/逐 token 变深度/逐通道）。
- **为什么要做**：墙钟倍率三 run 1.57/3.08/5.53×（极差 3.5×），「3.1×/1.8×」是单次抽样；
  FLOPs 净账 **+5.6%**（8.45 vs 8.00）未进结论；「最厚的资产」藏负账。本项目最厚的资产，必须
  把结论写对（省延迟、不省算力）。
- **必须回答的问题**：
  1. 100M 端到端**深度草稿**的墙钟加速（交错口径）是多少？
  2. FLOPs 净账是多少（等效 layer-position/token ≤1 才算省算力）？
- **验证口径**：**该涨** = 交错 tok/s 比值；**该跌** = 等效 layer-position/token（**≤1 才算
  省算力**）；**必须不变** = 发出流与贪心逐 token 相同（质量护栏）。
- **对照组**：诚实对手 = **普通全栈/同缓存机械**；必要对照 = `plain_cache_full`（剥离实现层
  2.02×）、同 FLOPs 的「直接退 k 层」。
- **预登记判据**：墙钟报**比值中位与极差**（交错协议 3 轮 × ≥4 prompt）；极差 > 效应则写
  「不可分辨」；FLOPs 用解析账。
- **规模与复现**：13M + 100M 两点；≥2 次独立测量；层-位置口径与墙钟口径分列；禁外推。
- **预算**：≈ **240 GPU 分钟**（100M 端到端 + 四臂墙钟重测）。
- **依赖**：WI-16（同 FLOPs 早退基线，用于说清增量）。

### WI-20 · C4-weight-sharing（参数 ↔ 循环）
- **它是什么**：深度方向是否复用同一组权重（不共享 / 全共享循环 / 每 k 层一组）。
- **为什么要做**：本轴唯一真空白，直接做「参数 ↔ 循环次数」换算，对 carry-门形态关键；本地
  零经验却被标成业界结论（`status:reference` vs 自家 `prior_art_verdict:(c)`，三处互相矛盾）。
  业界 = Universal Transformer / ALBERT（`记忆·未核`）。
- **必须回答的问题**：
  1. 深度方向权重共享是否值（同参数量质量 / 同 FLOPs 质量 / tf@k）？
- **验证口径**：**该涨** = 同参数量质量 / 同 FLOPs 质量 / tf@k；**该跌** = 参数量、每 token
  FLOPs；**必须不变** = 循环=1 与不共享臂**逐位等价**（可失败单测）。
- **对照组**：诚实对手 = **不共享（本项目）**；必要对照 = **同参数量、同 FLOPs 两腿**、
  逐位等价单测。
- **预登记判据**：自测 `σ_cell`；主判据 = 两条腿（同参数量/同 FLOPs）各自的质量差（区间）。
- **规模与复现**：13M × 2 seed + 一个更大点或声明范围；三臂（不共享/全共享/每 k 组）；
  两次独立训练。
- **预算**：≈ **180 GPU 分钟**。
- **依赖**：**引擎需实现权重共享**（当前无）——先立引擎工单。

## 主线五 · 结构税（本形态相对 stock 的税）

### WI-21 · C5-refinement-operator（门是否承载税）
- **它是什么**：每层如何把状态往前推（残差+MLP / carry 门乘 delta / 并行支路 / 条件化）。
- **为什么要做**：「门是税承载者」是链式分解的**余项**而非隔离量（0.2280），且其前提「退出+
  填充 +0.200」在 23e matched 12k 下**反号**（fill=−0.0856）；回答它的现成臂 `23d-H1-12k`
  缺 `tf@4`。
- **必须回答的问题**：
  1. 出口资产是否**必须**付门堆栈税（补 `23d-H1-12k` 的 tf@4/tf@6，纯推理 ≈5 min）？
  2. `gate-off` 臂（g≡1，保留随机退出+填充+aux）后形态税拆出多少？
- **验证口径**：**该涨** = clean bpc / tf@k / 门活性；**该跌** = gate_mean（「渐进开门」假设的
  反证点）；**必须不变** = 除门外逐字段同、`g≡1` 与 dense 等价单测。
- **对照组**：诚实对手 = **同引擎 dense（无门/退出/填充）**；必要对照 = `gate-off` 臂、
  `23d-H1-12k`（dense trunk + 全深度 aux）。
- **预登记判据**：若 tf@4(H1-12k) ≳0.9 ⇒ 出口资产不需门堆栈 ⇒「逐 token 变深度必须付 +0.44」
  要改写；自测 `σ_cell`。
- **规模与复现**：13M × 2 seed（复用已有 checkpoint 做 eval + 新增 gate-off 臂）；两次独立训练。
- **预算**：≈ **40 GPU 分钟**（eval ≈5 min + gate-off ≈10 min，×2 seed）。
- **依赖**：无（可与 WI-22 共用一次 eval）。

### WI-22 · C6-depth-supervision（同引擎税 + 出口资产）
- **它是什么**：训练期让哪些深度被监督（仅最终 / 全深度并行 / 随机退出 / 退火课程）。
- **为什么要做**：headline「出口资产只能由深度监督造出」恰是 LayerSkip 前提；0.12 vs 0.97 的
  对照是**未训练 tied 读出 proxy**（`24b-decode-wall-dense.json::tf_note` 自述）；tax 行跨引擎
  混写；+9% benefit 是墙钟噪声。
- **必须回答的问题**：
  1. 同引擎的深度监督税是多少？
  2. 出口资产是否需门堆栈（与 WI-21 共用 `23d-H1-12k` 的 tf@4）？
- **验证口径**：**该涨** = tf@k（须与**同监督量**对照比）；**该跌** = 全深度监督底座税；
  **必须不变** = 判据损失口径（若改归一化须双报两套斜率 §17.15）、w=0 时逐位回到「只监督
  最终深度」基线。
- **对照组**：诚实对手 = **只监督最终深度（stock）**；必要对照 = 深度监督剂量梯度、
  `23d-H1-12k`、同监督量对照。
- **预登记判据**：自测 `σ_cell`；主判据 = 同监督量下的 tf@k 与税；**并报**聚合损失与任务损失
  两套斜率（§17.15）。
- **规模与复现**：13M × 2 seed + 100M 1 seed（或声明范围）；两次独立训练。
- **预算**：≈ **100 GPU 分钟**。
- **依赖**：WI-21（共用 eval）。

## 主线六 · 其它

### WI-23 · G1-selector（选择器与预算分配；并入 F3）
- **它是什么**：谁决定这条路怎么走（固定 / 阈值 / prob0 门控 / 学习门 / 离线求解器）。
- **为什么要做**：「严格占优」用带内 Δ（2.0502 vs 2.0545 = 0.0043 < 带宽）；判据被事后替换
  （原判据「低置信桶 ≥ 高置信桶 2×」被改成单调下降读法）；`tax`「不加税」误导（门控开火
  τ=0.98 付 22.16% 前向）；与 F3 证据完全重合。业界 = ACT/CALM/PABEE/MoD（`记忆·未核`）。
- **必须回答的问题**：
  1. 按**原预登记判据**（分桶单调 + 低置信桶每 FLOP 收益 ≥ 高置信桶 2×，**照原样**跑）选择性
     问题是否获证？
- **验证口径**：**该涨** = 低置信分桶每 FLOP 修复收益；**该跌** = 高置信带收益 ≈0/负；
  **必须不变** = `fire split gap ≤0.004`、单轮 mixture≡overwrite 逐位一致。
- **对照组**：诚实对手 = **固定/输入无关阈值**；必要对照 = 单轮 mixture 逐位一致、校准臂。
- **预登记判据**：自测 `σ_cell`；判据线**照原样**（不得事后替换）；分桶用 Wilson CI。
- **规模与复现**：13M × 2 seed（+一个更大点或声明范围）；两次独立训练。
- **预算**：≈ **100 GPU 分钟**。
- **依赖**：无（G3/G4 校准信号已就位）。

### WI-24 · P4-normalization（QK-Norm 回填）
- **它是什么**：LayerNorm 放在哪、是否有 final norm（pre-LN / post-LN / QK-norm / RMSNorm /
  无 final LN）。
- **为什么要做**：漏记本仓已有 QK-Norm 实测（gnorm 1740.9→7.25 / 29578.6→7.58，推荐
  `qk-normfrom512`）；「无 final norm 是前提」被当结论。业界 = QK-Norm / RMSNorm（`记忆·未核`）。
- **必须回答的问题**：
  1. QK-Norm 档位回填后，长 T 稳定性如何？
  2. 有/无 final norm 的消融对「同空间」几何的影响？
- **验证口径**：**该涨** = 开 QK-Norm 后 `gnorm_max` 从 1e3–1e4 降到 <100；**该跌** = 全局档
  短 T clean bpc（T=512 +0.0314 越界）须用**长度条件档**；**必须不变** = T≤512 零 hook、
  `logits=h·Eᵀ` 同空间。
- **对照组**：诚实对手 = **无 QK-Norm（本项目）**；必要对照 = 全局档 vs 长度条件档、
  有/无 final norm。
- **预登记判据**：自测 `σ_cell`；主判据 = 稳定性（gnorm_max 阈值）+ 长度条件档下短 T 不越界。
- **规模与复现**：13M × 2 seed + 至少两个 T 档；两次独立训练。
- **预算**：≈ **100 GPU 分钟**。
- **依赖**：无（部分为已有结果回填）。
