## 0. 总原则（本轮讨论确认）

- 研究是**树**：轴（大类）→ 研究项 → 手段/子做法；每个研究项要有**目的 + 假设 + 端到端验证 + pareto 口径**。
- 目的是「用更少的计算量拿到类似效果」（序列级质量）。手段不是目的。
- 「信息右移」是**时间轴下的一个子类**，不是大类。
- 不删内容；真多余的进 **Backlog**。
- 代价口径：**等效理论时间/计算量（FLOPs / layer-passes / tokens-per-forward），考虑 pipelining；不用墙钟**。

### T · 时间轴（当前 token 往左的因果时间轴）
> 本质：**仍然做 attention，但不做全量 attention**。目的都是「更少计算、类似效果」。

| 节点 | 是什么 | 旧编号 | 处置 |
|---|---|---|---|
| **T.1 窗口化 / 衰减** | 滑动窗口、锚点槽、sink、软距离衰减（ALiBi 式） | A3 + A4 | 保留（补目的：把可见范围压到 pareto 最优）；A4 降为 T.1 的手段 |
| **T.2 稀疏 / dilated** | 内容选择稀疏、块稀疏、**dilated attention** | A6（部分）+ 已删 A5 | 保留（拆成各自独立假设）；补 dilatated |
| **T.3 attention 上限 / 预算** | 给每 token 的可见量设上限 | A3 稀疏全局 / A6 | 保留（补目的与 pareto） |
| **T.4 dynamic merging** | **越往下的层 token 越少**（合并已处理的位置） | （缺） | **缺**，要立 |
| **T.5 信息右移**（子类核心） | 把信息搬向「右」（更近），从而少 attend；极端 = **cyclic buffer** | A9 + A10 + M1 + M2 | 保留为子类；把 M1/M2/A9/A10 合进来 |

- **T.5 子节点**：
  - **T.5.1 显式记忆槽 / 线性状态载体**（写什么、何时写、更新式、读出；对照 DeltaNet/GLA/Mamba-2/MQAR）← M1

  - **T.5.3 压缩触发与优先级** ← A10
  - **T.5.4 极端边界**：左边 token 可以不 attend ⇒ **cyclic buffer**（前缀真的丢）
  - **T.5.5 implicit vs explicit**：implicit（掩码/窗口）已证退化，explicit 才是有希望的路线 ← A9
