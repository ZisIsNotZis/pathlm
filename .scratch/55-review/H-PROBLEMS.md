## 0. 先想清楚：这条线到底在干什么（不看代码时写下的第一性原理）

**痛点（问题）**：自回归逐 token 解码是**顺序 + 访存带宽受限**的——每生成 1 个 token 要跑 1 次
完整前向（= 1 次全权重访存 + 1 次顺序依赖）。N 个 token = N 次前向。要加速，就得**减少每 token
的顺序前向次数**，办法是让**一次前向的产出信息从 1 个位置「右移」到 k 个位置**——这就是出资人
说的「信息右移」在 H 轴的落点。同时质量不能崩，所以本质是 **质量-代价 pareto**。

**research topic**：**投机解码（speculative decoding）作为推理加速范式**——如何把**平均接受长度
τ** 尽量抬高、**每 token 顺序前向**尽量压低，质量代价落在 pareto 前沿上。**topic 不是「一次前向
输出几个位置」**——那只是实现这条范式的一个旋钮。

**该引入的机制**：(a) 一次前向**并行**产出多个未来位置的预测（多头 / MTP / 草稿）；
(b) 全深度 **verify** 一次验证多草稿、按拒绝点截断（无损性）；(c) **多候选/树状**草稿 + 置信度
加权组合来抬高 τ；(d) 草稿头**旁路**主干（零税）。

**代价该怎么评**：以**全量（native 贪心）标准为 100%** 画 pareto——x 轴 = 每 token 代价
（**按 regime 取相关者**：顺序前向次数 / 访存 / 墙钟 / FLOPs），y 轴 = 质量（bpc / 接受率 / τ）。
关键：spec **必然用更多 FLOPs 换更少顺序前向**，所以「FLOPs 涨」是**范式的定义性质**，不是
「亏损发现」；能当硬指标的是 **τ** 与**顺序前向次数**，FLOPs 只是 pareto 的代价轴之一。

**巨人（既有设计）**：Leviathan/Chen 2023（投机解码 + 无损性定理）、Stern 2018（blockwise）、
**Medusa 2024（冻结主干 + 多头 + 树注意力验证）**、EAGLE（特征级草稿）、Gloeckle Meta MTP、
DeepSeek-V3 MTP。

**我们是在站巨人肩上还是造轮子**：本质上是在 **重造 Medusa**（冻结主干挂多头 + 批量验证），
外加把已知结论在 13M/100M 上再量一遍。这是**造轮子**风险最高的一轴。

**几种候选哪种更可能有效**：冻结主干 + 轻头 + **树/多候选 + 置信加权**（Medusa/EAGLE 路线）
最可能抬高 τ；条件链（DeepSeek MTP）成本更高、且条件一错就级联崩。

**现有方法对不对（预判，待核对）**：大方向对，但（1）极可能把手段当 topic；（2）极可能把
「概率多候选/树/置信加权组合」简化没了；（3）极可能把「spec 必然 R>1」当发现。

## 1. 致命问题（F）

### F1 · 目的丢失：把「手段」当成了 topic
- **问题**：H1 的标题 / claim / options 就是「**每步输出位置数**」本身。
- **为什么是问题**：目的（投机解码加速推理）没写；写的是手段（一次前向输出几个位置）。
  H2/H3/H4/H5 也全是手段（填什么内容 / 怎么组合 / 头挂哪 / 怎么验证），没有一个写「目的 = 提高 τ、
  省顺序前向」。这正是出资人判据「只列手段、没有目的 = 瞎研究」的直接命中项。
- **严重度**：**致命**。
- **证据锚点**：`catalog.yaml:580-583`（id/title=每步输出位置数、claim=一次前向为几个未来位置
  产出预测、options=[1, k, 整段]）；`axes/H-horizon/README.md:8-11`；`axes/H-horizon/H1-outputs-per-pass/README.md` §1；
  自评亦承认：`.scratch/54-subproject-schema/INVENTORY.md:91`（「我把它当`输出位置数`研究，丢了目的」）。

### F2 · H3 的核心设计被简化掉了：概率多候选 / 树 / 置信加权组合 → 单 argmax + 固定 λ=0.5
- **问题**：出资人的设计是「每个 jump head 预测 n+1~n+k、**自带概率**；预测 n+2 时走直接 +2、或
  +1+1、或按路径概率加权 `(p(+1)p(+1|+1)v(+1|+1)+p(+2)v(+2))/(p(+1)p(+1|+1)+p(+2))`」。
  实际只做了：
  - 位置特化的头 `node_k = T_k(h)`——**每个头只出一个固定位置**，不是「每个头预测 n+1~n+k」；
  - 组合只测 3 臂 `chain / direct / combined`，`combined` 是**固定等权 λ=0.5** 的概率混合
    （`spec_arms.py:50` `COMBINED_LAM = 0.5`；`:74` `lam*pc+(1-lam)*pd`），**完全没有用路径概率加权**——
    引擎里明明有 conf 头（`model.py:161`）却没用；
  - **树/多候选（beam/tree）整条没测**：`catalog.yaml:647` 的 `beam 多线 + 重排`、
    `catalog.yaml:645` 的 `DP lattice 置信加权（设计 §5 已定义，从未端到端测量）` 都停在选项里；
  - **多级条件链没实装**：条件链只一级，`chain2` 复用 `T1` 而非独立条件块（2631 §7 #1；2632 §8 #2）。
- **为什么是问题**：出资人问的正是「概率路径组合」；现有的 `combined`（固定 0.5、且 chain 分支在
  deploy 条件本身差）在数学上就注定退化到 ≈direct——这不能作为「组合无价值」的证据，**答非所问**。
  删掉了出资人设计的核心自由度（**用概率加权**），把问题简化成「两条分布等权混合」，再据此下结论。
- **严重度**：**致命**。
- **证据锚点**：`.scratch/54-subproject-schema/INVENTORY.md:99-101`；`catalog.yaml:642-647`（options）、
  `catalog.yaml:651`（H3 verdict 自认「不回答用户要的概率路径组合问题」）；`2631.../spec_arms.py:50,53-74`；
  `2631.../analysis.md` §2.3；`2632.../analysis.md` §6.1；`pathlm/model.py:310-336`（`_mtp_nodes` 位置特化头 + 一级 chain）。

### F3 · H1 的主判据是数学恒真、且与「目的」无关
- **问题**：H1 花一整只实验（2520）把「每 token 算力 `R=(1+γ)/(1+τ)`」当主判据，结论是
  「**R>1 ⇒ spec 是算力亏损**」。但：
  1. **R≥1 是恒等式**：τ≤γ ⇒ 1+τ≤1+γ ⇒ R≥1，`τ=γ` 才恰好 =1。脚本自己断言
     `assert 1 ≤ R ≤ 1+γ`（`compute_ledger.py:137-140`），并把判据写成
     「`R<0.95` ⇒ 净省」（`compute_ledger.py:42`）——**这一臂按构造不可能触发**，判据不可证伪。
  2. **spec 从来不是拿来省 FLOPs 的**：它是用**更多并行算力**换**更少顺序前向 / 更少访存**。
     「FLOPs 涨」是范式定义，不是「亏损」发现。把「R>1」当头条 = **口径错 + 目的错**。
- **为什么是问题**：主判据既不可证伪、又答不到目的上；用「自己的旧口径算错」造出一整只实验
  （2520 的「符号纠正」）——这是把**自造的度量混乱**当研究产出。
- **严重度**：**致命**。
- **证据锚点**：`axes/H-horizon/H1-outputs-per-pass/experiments/2520-spec-at-scale/README.md` §5 判据1；
  `.../compute_ledger.py:42,137-140`；`.../analysis.md` §1/§7；`catalog.yaml:587`（verdict 头条「恒为算力亏损」）；
  `docs/playbook.md` 定律 11。

### F4 · 「MTP 应免费」的前提被自相矛盾地处理：H1 税的基线与 H4 的零税基线不一致
- **问题**：出资人明确「**MTP 应该是免费的（不应影响主干训练）**」。H4 实测**冻结主干挂头
  Δbpc=0.0000**（`2610.../analysis.md` §1），H 轴 README 也认「冻结主干只训头 → 零税 → 最便宜

  「n_mtp 1→2 税 +0.041」当成 MTP 的固有税（`2510.../analysis.md`；`catalog.yaml:78,587`）。
  两者正是「免费路径存在」与「你偏走了付费路径」的矛盾。
- **为什么是问题**：出资人的免费前提**已经有证据支撑**（H4），但主线结论仍用付费基线；
  没有按「冻结主干 + 多头 + 批量验证」这条免费路线去测 τ / 加速，等于**没按出资人设定做**。
- **严重度**：**致命**。
- **证据锚点**：`axes/H-horizon/README.md:20-22`；`catalog.yaml:78,88,587`；
  `axes/H-horizon/H1-outputs-per-pass/experiments/2510-gap-sweep-b2-c1m/analysis.md`；
  `axes/H-horizon/H4-head-trunk-relation/experiments/2610-frozen-trunk-jumphead-13m/analysis.md` §1。

### F5 · 树状/多候选整条缺失，结论却已定稿
- **问题**：H1/H3 的 verdict 都写「尚缺：树状草稿」（`catalog.yaml:587,651`）；
  `2632` **预登记判据已被触发**——「存在 k 使 recall@k(chain) ≥ recall@1(direct) ⇒ **树可能翻转

## 2. 重要问题（I）

### I1 · 第一硬指标 τ 几乎没有稳健性
τ 只在 **γ=2、单一小规模（13.4M/53.9M）、单任务（enwik8 char 级强局部先验）、温度 0、batch=1**
上测；**无 §19 弱局部先验对照**（随机键值回忆 / induction / 复制）、**无温度>0 拒绝采样**、
**无 batch>1**。而 τ 强依赖任务局部先验与温度。→「direct > chain」的 τ 排序受 regime 支配
（2632 自证真实文本上翻转），却按部署 regime 单点写死。
- 严重度：**重要**。
- 锚点：`2631.../analysis.md` §2/§7；`2632.../analysis.md` §5.2/§8 #6；`2520.../analysis.md` §6。

### I2 · 没有 pareto frontier
出资人要「以全量标准为 100%，质量-代价前沿长什么样」。H 轴只有**孤立点**（γ=2 的 τ、R、税），
**没有沿代价轴扫描**（γ=1/2/3…、头规模、冻结 vs 联合、树宽度）形成前沿。质量轴（bpc）与
性能轴（τ）甚至不在同一实验里对齐。
- 严重度：**重要**。
- 锚点：`catalog.yaml:588-604`（H1 metrics 列表）；`axes/H-horizon/README.md:20-22`。

### I3 · 唯一的端到端加速证据（墙钟）自我宣告不可用，却仍在头条引用
H 轴多处承认「本机外部占用下**不可稳定复现 / 禁外推**」，却又在 README/catalog 头条给
「1.68–1.90×」「1.58×」并据此称「税效比全项目最好」。⇒ **没有一条干净可用的端到端加速证据**，
「最好」缺乏可用支撑。
- 严重度：**重要**。
- 锚点：`2520.../analysis.md` §3；`2631.../analysis.md` §5；`axes/H-horizon/README.md:20-22`。

### I4 · `combined` 臂在数学上就注定 ≈direct，答不了出资人的问题
`combined = 0.5·softmax(chain2) + 0.5·softmax(node2)`，而 chain 分支在 deploy 条件本身差
（近随机 argmax）。50/50 混合一个「好分布」和一个「坏分布」，argmax 仍由好分布主导 ⇒
「combined ≈ direct」是**结构性预期**，不能证明「概率组合无价值」。出资人要的**置信加权**
恰恰是为了让坏分支自动降权——没测。
- 严重度：**重要**。
- 锚点：`2631.../spec_arms.py:50,74`；`2632.../analysis.md` §3（chain_deploy 近随机）。

### I5 · 把「已知错的方案」列成研究选项/结论
`catalog.yaml:644` 把「朴素概率乘积」列为 H3 的待研究选项，H1 verdict 又把它当「否证」写进
失败路径。但 PRIOR_ART 自认这是**数学事实**（联合≠边缘之积），非实验结论。给已知错的东西
做实验 = 无意义。
- 严重度：**重要**。
- 锚点：`catalog.yaml:644`；`catalog.yaml:587` failure 列「node-k 概率朴素复合是数学错误」；
  `axes/H-horizon/PRIOR_ART.md` §H3。

### I6 · H4/H5 是「实现选择 / 正确性不变量」，不是研究课题
- **H4**（冻结 vs 联合）就是 **Medusa-1 vs Medusa-2** 的工程选择；
- **H5**（批量验证 = 逐步贪心）是**投机解码无损性定理**（Leviathan/Chen 2023），复现它是造轮子；
  SCHEMA §21 把 H5 判 (a)（业界做透）却仍登记为 `judged`。
- 严重度：**重要**。
- 锚点：`catalog.yaml:685-732`；`axes/H-horizon/PRIOR_ART.md` §H4/§H5；`SCHEMA.md:433-448`（§21）。

### I7 · H2「训练时填空」目的不清、且与 spec 加速无关
填什么内容源于 **depth-AR/reentry（变深度）** 形态；PRIOR_ART 自认主流 MTP 不填充。
它服务的是「变深度 AR 右侧位置填充」，不是「抬高 τ」。放 H 轴 = **归属错 + 目的缺失**。
- 严重度：**重要**。
- 锚点：`axes/H-horizon/PRIOR_ART.md` §H2；`axes/H-horizon/H2-training-fill/experiments/2523e-fill-variants/README.md`；
  `catalog.yaml:609-633`。

### I8 · 「税效比全项目最好」与「R>1 净亏 + 墙钟不可复现」自相矛盾
README 既说「税效比全项目最好的一条」，又说「算力净亏、墙钟不可稳定复现」。
到底「最好」体现在哪个**可用**指标上？没有干净的端到端收益支撑「最好」这个定性。
- 严重度：**重要**。
- 锚点：`axes/H-horizon/README.md:20-22` 与 `:24`；`catalog.yaml:78-87`。

## 6. 一句话总结

**这条线把「投机解码加速推理」的研究，做成了「一次前向输出几个位置 / 组合方式 / 头挂哪 / 怎么验证」
四五个手段的扁平枚举**：目的（抬高 τ、省顺序前向）丢失；H3 的核心设计（概率多候选 + 树 + 置信
加权组合）被简化成单个 argmax + 固定 λ=0.5；主判据（R>1 算力亏损）是数学恒真且答非目的；
「MTP 免费」的前提有证据（H4 冻结零税）却被主线用付费（联合训练）基线顶掉；树/多候选整条没做
却已定稿结论。**必须重做的是：以「投机解码加速」为目的、以 τ 与顺序前向为硬指标、以
「冻结主干 + 多头 + 树/多候选 + 置信加权组合」为机制假设、以质量-代价 pareto 为验收口径。**
