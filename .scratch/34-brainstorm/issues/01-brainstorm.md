# 01 — 第七批（ticket 34）：站巨人肩膀 + 造一件「必须用长程记忆」的天平

用户 2026-10-01 指示（离场前）：
1. **先查业界**：每个设计先联想「业界有哪些已做出来的实验基于这个设计、为什么这么设计、效果如何」，
   站在巨人肩膀上，把他剥离出来再进一步。
2. **诊断「信息为什么不往右搬」**：他自己提了极端形态（只保留一个状态 ⇒ RNN/GRU/LSTM/线性注意力）
   与「每次只搬上次没搬的（LRU）」两种思路，要我方（主 Agent 编排 + 专业引擎 brainstorm）深化。
3. **线性注意力实验定位修正**：纯线性注意力业界验证基本不可行 ⇒ 我们要做的是
   **「线性注意力占比 vs 退化」的曲线**（混合层比例曲线），不是纯线性。
4. **GQA 还有没发掘的地方**，也要 brainstorm。
5. **关键洞察**：模型太小太弱 ⇒ 对远距离 context 越不敏感（靠语言先验补强，从未涌现真正长程能力）
   ⇒ 我们可能在测「模型不需要」而不是「机制做不到」。

## 契约 A：合成长程任务电池（`tools/evalkit/longrange_tasks.py`）

- 目录：`axes/M-carrier/M1-carrier-type/experiments/2617-longrange-task-battery/`
- 文件所有权：**新增** `tools/evalkit/longrange_tasks.py`、`tests/test_longrange_tasks.py`、本实验目录。
  不得修改既有 `tools/evalkit/retention.py`（只增不改），不得碰 `pathlm/`。
- 动机（SCHEMA §19）：enwik8 局部统计极强 ⇒ 长程结论会被「模型不需要」污染。必须先有不依赖
  局部先验的任务。
- 交付四个任务（每个都要：可调距离/长度、答案**不可由局部先验猜出**、随机种子可控）：
  1. **关联回忆**（associative recall）：K 对 (key, value)，随机 key/value 取自词表子集，
     末尾问 key 求 value；
  2. **Induction**：给出随机序列前缀，后面重复其中一段，要求续出下一项；
  3. **复制**（copy）：随机片段出现在远处，要求复制；
  4. **变距离回忆**：单个 (key,value) 对，距离 d ∈ {16,32,64,128,192,255}，问 value。
- 每个任务必须给出：**随机基线（chance）**、**局部先验基线（用最近 k 个 token 的 n-gram/最近邻预测）**、
  以及**距离-准确率曲线**的定义。
- **判据（预登记）**：
  - (a) 四个任务都能跑通并给出 chance 与局部先验基线；局部先验基线的准确率必须**显著低于**
    理想真值（即证明「不靠长程就答不出」）——若某任务局部先验就能答对，说明任务构造失败，
    必须重做该任务；
  - (b) 在既有 13M dense 主干（复用 `2610` 的 `trunk.pt`，断言 sha256）上测出四个任务的
    **基线准确率**（这是关键数字：**我们的模型到底有没有长程能力**）；
  - (c) 对「变距离回忆」给出与 `retention.py` 兼容的依赖曲线接口（复用其删除逻辑，不重写）。
- 成本：纯推理/合成数据，≈15–25 min。
- 交付：`tools/evalkit/longrange_tasks.py` / `tests/test_longrange_tasks.py`（≥6 可失败单测，
  含「局部先验基线确实低」与「打乱答案后准确率降到 chance」的变异验证）/ 本目录
  README/run.py/config.json/results.json/analysis.md（人话摘要在最前）/MODEL.md。

## 契约 B：情报——记忆 / 压缩 / 状态架构的既有做法（researcher，只读+写情报文件）

- 目录：`axes/M-carrier/M1-carrier-type/experiments/2617-prior-art-memory/`
- 目标产物：`PRIOR_ART.md`（本目录），回答**用户的三问**：谁做过 / 为什么这么设计 / 实测结果如何。
- 必查清单（每个都要给出处与结论，找不到就写「未找到」+检索词）：
  1. **单状态极限**：RNN / LSTM / GRU / Mamba / RWKV / RetNet / 线性注意力——
     它们把无限历史压进固定状态，**在需要长程回忆的任务上到底行不行**（如 associative recall、
     长程 copy）；固定状态容量与任务需求的**关系**（有没有「状态大小 vs 可回忆信息量」的量化结论）。
  2. **显式压缩记忆**：Compressive Transformer、Memorizing Transformer、RMT（recurrent memory
     transformer）、Unlimiformer、Block-Recurrent、DNC/NTM——压缩率、训练信号、实测质量代价。
  3. **强制搬运的训练信号**：有没有工作用**重建/充分性损失**（sufficiency / reconstruction）
     逼状态承载被丢掉的内容？效果如何？（这一条对应我们 `F4-training-signal` 的空白格）
  4. **LRU / 增量搬运**：有没有工作做「只搬上次没搬的」「按访问频率淘汰」？效果如何？
  5. **注意力 sink / StreamingLLM**：为什么前几个 token 必须留（对我们「锚点」的既有解释）。
- 输出规范（SCHEMA §18）：每条给 `来源（链接或「记忆·未核」）+ 一句话内容 + 与我们设计的关系 +
  可复现的判据建议`；**记忆类结论必须标注，不得当判据**。
- 若 web 检索不可用：如实写明，降级为记忆 + 标注，并给出「若可检索应查的关键词」。

## 契约 C：情报——混合层比例 / GQA·MLA / KV 预算 Pareto 的既有做法（researcher）

- 目录：`axes/R-references/R4-window-kv-quant-retrieval/experiments/2617-prior-art-hybrid-kv/`
- 目标产物：`PRIOR_ART.md`，专门服务用户的两点修正：
  1. **线性注意力「占比 vs 退化」曲线**：Jamba / Zamba / 混合层（每隔 n 层一个 softmax）等，
     业界用什么比例？**比例-质量曲线**长什么样？纯线性为何不可行（用户判断）？有没有公开的
     ratio sweep 数字？
  2. **GQA / MQA / MLA 的未发掘空间**：GQA 头数 vs 质量 vs KV 字节的**Pareto 曲线**有没有公开数字？
     跨层/跨深度的共享模式（不均等共享、层特异 KV 头数）有没有人做过？MLA 的低秩压缩效果？
     **我们要设计的「同 KV 字节预算下的最优分配」**有没有前例？
  3. **KV 预算的参照线**：量化 vs 头共享 vs 驱逐 vs 检索——业界有没有把它们放在**同一字节预算**
     下比较的工作？（这决定我们 W3/R1/M2 三格的判据线怎么定才公平。）
- 输出规范同契约 B。
