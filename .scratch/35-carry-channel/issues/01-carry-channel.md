# 01 — 第八批（ticket 35）：制造需求 + 提供通道——把「信息往右搬」变成可测的事

## 为什么这样设计（主 Agent 综合 ticket 34 A/B/C/D 的判断）

「往右搬」要同时成立四件事（缺一都不会自发出现）：**① 真需求**（任务必须要求事后还记得）、
**② 通道**（有地方可写）、**③ 容量压力**（状态必须比历史小）、**④ 训练信号**（要求「丢掉后还能重建」）。
ticket 34 的实测告诉我们：**①③ 从没被满足过**——enwik8 局部先验太强，模型「不需要」；
而且我们的模型连**关联回忆能力都是零**（0.0061 ≈ chance）。

所以本批**先做「①+②」两件事的对照**：
- 用**合成关联回忆任务**提供 ①（局部先验已证无效）；
- 用**训练期窗口掩码**制造「必须搬」的压力（窗口外就是看不见，但答案要求在窗口外）；
- 用**显式记忆槽 + 三种写入规则**提供 ②，并检验「只搬上次没搬的（delta 写）」是否优于「plain 累加写」。

**既有做法（SCHEMA §18，全部 `记忆·未核`，本环境联网不可用）**：
DeltaNet / Gated DeltaNet / TTT / 线性注意力家族的 delta 规则写入（`S ← S + β(v − Sk)kᵀ`）；
RMT / Block-Recurrent / Compressive Transformer 的显式记忆槽；MQAR（Zoology）作为
关联回忆的标准构造；Compressive Transformer 的 compression loss 作为 ④ 的前例。
**我们的增量**：13M + 局部先验抗性任务 + **单因素受控 + 等参数对照 + 毁源对照臂**，
**不声称**任何「无人占位」。

## 契约 U：三臂对照——无通道 / plain 写 / delta 写（唯一变量 = 写入规则与通道）

- 目录：`axes/M-carrier/M1-carrier-type/experiments/2618-carry-channel-13m/`
- 文件所有权：可改 `pathlm/depth_ar.py`、`train_depth_ar.py`、`tests/test_depth_ar.py`；
  可新增 `tools/evalkit/carry_channel.py`（如需）；本实验目录。**不得改** `tools/evalkit/retention.py`、
  `tools/evalkit/longrange_tasks.py`（只增不改；若确需扩展，只允许**新增函数**）。
- 数据：用 `tools/evalkit/longrange_tasks.py` 的**关联回忆**（主）+ **变距离回忆**（辅）生成器，
  自造训练集（**不要**用 enwik8 当主任务）。

### 三臂（每臂 13M、12k 步、seed=0、单卡共享 4090）

| 臂 | 可见性（训练+评测一致） | 写入通道 |
|---|---|---|
| `U0` 基线 | **窗口 16 + 锚点 0**（key 落在窗外 ⇒ 不搬就答不出） | 无 |
| `U1` plain 写 | 同 U0 | N 个记忆槽，逐位置累加写（`S ← S + w·v kᵀ` 的极简形式，实现写清） |
| `U2` delta 写 | 同 U0 | **同参数量/同形状**，写入改为 delta 规则 `S ← S·(I − β k kᵀ) + β v kᵀ`（「只搬上次没搬的」） |

- **U1 与 U2 必须参数量逐位相同**（同一组张量、只改更新式；SCHEMA §15）。**必须报活性量**
  （每 200 步：`S` 的 fro 范数、β 均值、写入量 `‖ΔS‖/‖S‖`），并说明干预是否活着。
- 记忆槽必须**因果可用**：位置 t 的读出只能用 `S_≤t`（单测钉住 + 变异验证）。
- 若 delta 的朴素实现步时超过基线 2.5×，允许用分块并行写法；**必须实测并报**步时倍数
  （SCHEMA §17 第 8 条不允许借用他人步时估预算）。

### 判据（预登记，一次写下不得改）

主腿在**准确率口径**（不用 bpc——训练侧 bpc 噪声 ~0.0156 已接近方差界）：

1. **U0 必须 ≈ chance**（关联回忆 chance = 1/词表子集大小）：这是「任务+窗口确实制造了需求、
   且不搬就真答不出」的**前提校验**。若 U0 显著高于 chance ⇒ 设置有问题（比如窗口没生效、
   或任务有漏洞），**先修设置再判**。
2. **主判据**：`U2`（delta 写）的关联回忆准确率 **> U0 + 5pp 且二项 95% CI 不重叠** ⇒
   「显式写入通道能让信息被搬过去」成立。
3. **并列判据（写规则优劣）**：`U2` vs `U1` 的差 **≥ 3pp 且 CI 不重叠** ⇒ delta 写优于 plain 写；
   否则记「两种写规则不可分辨」。
4. **毁源对照臂（强制）**：评测时把源片段内容毁掉（用电池的 `corrupt_span`）；
   任何一臂若在毁源后**仍**保持高准确率 ⇒ 该臂的读数不是来自「搬过去的信息」，**该臂判读作废**。
5. **辅助腿**：变距离回忆的距离曲线（U0/U1/U2 三条），报「从多远处开始能答对」。
6. 必须附：三臂**同方法** loss 斜率、训练侧重跑散度（1 臂重跑即可）、解析/实测内存分开报。

### 成本与 scope

- 每臂训练 ≈8–12 min（合成数据，T=256）；三臂 ≈30–40 min；评测与曲线 ≈10 min。
- **总预算 ≈50 min**；若 delta 实现导致单臂 >25 min，**先跑 U0+U1 两臂**并如实标
  「U2 因实现成本顺延」，**不得**削判据。
- 先 20 步冒烟（形状、因果性、步时、显存）再全跑。

## 契约 V：独立复核（fresh context，只读）

- agent：`reviewer`；对象：契约 U。
- 清单：`SCHEMA.md §14` 七项 + 本轮特别关注：
  ① **U0 ≈ chance 的前提校验**是否真的成立（它的读数是否可能就是「窗口没生效」）；
  ② **U1/U2 是否逐位等参数**（核对张量形状与数量）且**唯一变量是写入规则**；
  ③ **因果性**：位置 t 是否只用了 `S_≤t`（有没有未来信息泄漏——这是本设计最容易出的致命 bug）；
  ④ **毁源对照臂**是否真的执行且结论被正确使用；
  ⑤ 活性量（`S` 范数/β/写入量）是否每 200 步落盘且非零；
  ⑥ 有没有把 bpc 当主判据（本轮主判据必须是准确率口径）；
  ⑦ 数字与 `results.json`/日志逐一对应（含成本、次数、等式）。
- 输出：逐条 pass/fail + 可疑数字清单；`contact_supervisor` 回传，主 Agent 落盘。
