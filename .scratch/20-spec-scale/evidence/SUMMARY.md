# Ticket 20 — node-3+ spec 宽度缩放 @100M

日期：2026-09-18。INT3_100M_s0（INT_100M 协议 + n_mtp=3，104.5M 参数，
32000×6，84 min）。对照：13M B3（ticket 13：a₂=0.844，a₃|a₂=0.653，
2.40 tok/fwd，k=2 1.68× 稳态 / 1.85× random，宽度-3 前向成本 1.28×）。

## 结果

| | 13M B3 | **100M INT3** | 读法 |
|---|---|---|---|
| 宽度-3/宽度-1 前向成本 | **1.28×** | **3.4–5.3×** | launch-bound → compute-bound |
| a₂（enwik8 稳态） | 0.844 | 0.796–0.823 | 接受率近似稳定 |
| a₃\|a₂ | 0.653 | **0.767** | 条件接受率随规模**上升** |
| tok/forward（k=2） | 2.40 | **2.37–2.40** | forwards 口径不变 |
| k=2 wall speedup | 1.68×/1.85× | **1.15–1.29×** | 增益大幅收缩 |
| k=1 wall speedup | 1.42× | **0.80–0.96×（负）** | spec 单宽度亏损 |

## 判读

1. **spec 的墙钟收益是 launch-bound 小模型现象**：13M 时宽度-K 前向被固定
   开销摊销（1.28×）；100M 前向 compute-bound，宽度线性计价（≥3×）——
   批量验证不再有便宜的宽度。k=1 在 100M 是净亏损。
2. **接受级联规模稳定**：a₂ 略降（0.844→0.80），a₃|a₂ 上升（0.653→0.767），
   乘积不变（tok/fwd ≈2.4）——模型预测能力不是瓶颈，硬件计价才是。
3. **forwards 口径收益仍在**（2.37–2.40 tok/fwd）：在宽度便宜或批量与其它
   请求共享的部署里 spec 仍可用；单流 compute-bound 部署不赚。
4. **fp 平局翻转（新）**：batched SDPA 与逐位置 SDPA 的核差异在 top-2
   gap 0.008 的近平局处翻转 argmax（1 次/400 token，级联 68 token）。
   "spec==greedy 逐位相等"是 13M 规模的验证性质；100M 起记录分歧点与 gap。

## 结论

spec 杠杆的缩放定案：**接受率不随规模提升（级联稳定），墙钟收益随规模
消失（compute-bound 线性计价）**。Slider 的宽度旋钮在 100M 的部署价值
= forwards 口径优化，非墙钟加速。与 ticket 17 的"门控重试质量杠杆随规模
自衰减"合起来：**三杠杆中 retry（质量）与 spec（墙钟）在 100M 都自衰减，
存活的是 prob0 监测 + 校准框架本身**——这与"能力溢价随训练扩大"（ticket 19）
共同指向：规模下这套机制的价值在质量与可控性，不在吞吐。
